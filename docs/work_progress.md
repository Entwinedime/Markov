## 接下来仍需解决

1. **完整 E2E 的近似与误差。** source CPU 分支成本、写回阻塞和残余等待仍有沿用 base 的部分。
   partial 是限制提示，不是逐操作覆盖率。先区分 CPU 工作、依赖等待、采集扰动和未知残余，不能统一缩放 gap。
   以固定代表格检查自身回放与跨配置变化两类偏差，再决定是否修改模型。
2. **成本外推与最小补采。** 普通释放仍复用相近规模整段操作，allocator 与外围元数据成本未完全分开；
   写入/淘汰等需求识别尚不完整。单方向 DMA、部分存储增量补采和真实多缺口组仍欠完整实机证据。
   单页测量不证明跨页泛化，物理带宽不证明负载竞争已经建模。
3. **首次使用与恢复。** 验证普通 base 输入、历史无 token 输入、共享补采和中断恢复的实际体验。
   未收尾采集目前仍可能需要人工核对。现有成本收益报告缺旧资产首次取得成本及同口径实测对照，
   尚不能证明整个方法比逐个运行 target 更省。
4. **矩阵外泛化。** 09-14 的完整前缀匹配和短超时可见性问题，缺少当前执行式实现的关闭证据；
   应先复现再定修复，不能沿用旧缺陷描述断言当前代码必然相同。扩展 workload/TP 尚未按最新正常 CPU 机制统一复验。
   当前范围不证明跨 TP 扩图、多请求并发或任意后端；KTransformers 完整模型验证单列。
5. **进一步简化实现。** 围绕完整数据生产/消费链减少重复表示；独立测试已按随后要求移除，后续通过正式入口验证；
   不靠拆文件、压缩空行、删除必要能力或机械删检查减行。精度变化与纯重构分开验证。
6. **自动寻优。** 尚非已验收成果。先确认完整预测及收益排序的可信范围，再明确搜索空间、搜索与实测确认流程。

原总体及逐 base WAPE ≤3%、P90 ≤5% 的验收目标不变，争取所有格低于 6%。
看过 target 后的修复回归不是首次盲测；不以逐格参数、target-specific 模板或残差补偿兑现门槛。
