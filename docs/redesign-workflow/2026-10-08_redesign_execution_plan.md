## 1. 目标与执行顺序

用户输入一个固定模型、配置集合和 request workload 集合；系统选择代表配置及短请求，用户不指定 base。开发主线为 SGLang + Qwen3-32B，KT 预测与原生控制器留待后续。

统一流程 → 插桩采集 → 参数化子图模板 → 目标配置与请求 → 轻量控制器调用模板 → 有限变换与依赖拼接 → 给定节点耗时的动态展开 → 结构验收 → 成本模型 → 配置 × workload 探索结果。

只模拟统一流程定义的子图及必要的连接和状态。模板外工作默认排除；完整原生进程、后台调度及 HTTP 时延不成为本轮隐含目标。范围、分析粒度和支持判断的执行原则见[工程约束 §1.4](../redesign/engineering_constraints.md#14-建模范围与开发粒度)。

## 3. 下一步与阶段门槛

### 先应用约定，不新增实现任务

以下是开发时持续遵守的判断原则，不各自创建类、检查器、采集任务或待完成门槛：

- 先判断是否属于统一流程，再判断是否影响结构、控制状态或耗时；不以清空未归属事件/诊断为目标。
- 以一个完整能力为工作单位。每轮明确缺口、改动职责和停止条件，不让新发现的细节自动主导下一轮。
- 未变换的模板内容按既有合同保留；验证重点是变换部分、子图接口及状态反馈。已有证据仅在相关逻辑改变或出现具体反证时重查。
- 支持性判断来自模板合同与实际变换规则。没有匹配规则时返回该规则缺口，不额外堆积按样本、人数或采集编号编写的拒绝清单。
- 优先使用代码语义、已有采集和必要的时间上界判断影响；不要求逐细节消融。无法表达对外行为或目标成本时才细化。

### 恢复开发后的工作顺序

1. **沿用已验收的结构与公共装配。** S3/S4 主线及现有 C++ 外围适配交接已有证据；只有具体反证或必要合同变更才重开，不重新列为待完成任务。遗留问题仍须关联承诺范围内的能力，不扩大到原生所有事件。
2. **先收敛 S5 采样方法。** 以对象一致、简洁适配、跨框架共同途径、特征域构造四项约束检查现有请求采样与插桩，优先验证常驻 Engine 路径。形成最小统一接口和独立性能观测边界，用少量通用请求构造验证实际特征覆盖；具体交付与停止条件见下方 S5。
3. **完成 S5 成本覆盖与 S6 闭环。** 在合格样本上继续节点/局部子图建模和统一执行核消费，完成共享需求、多组生命周期、受影响组合重算及真实成本探索。不能以成本拟合修补结构缺口，或以每个缺失 shape 都补采的方式替代可维护模型。

上述顺序不为约定单独创建实现平台，也不要求先实现第二框架。每轮只报告关闭了什么能力缺口、证据和剩余限制，不按检查数量换算进度。

### 跨请求展开的剩余机制审阅

按需参考[模板关系](../redesign/sglang_template_relations.md)。具体问题包括请求成员循环、模型物化分支、过滤/合并、KV页与workspace状态。这是排查索引，不是要求所有分支都实现的清单。

请求池缩小的预热初值已有生产端规则及开发证据，其他配置变化不能直接继承这一资格。插入区域再次替换、更多提交线程及其他分配生命周期，只有被当前承诺的变换实际触发时才成为实现任务；不预建任意嵌套替换器。范围外后台清理不升级为 S4 门槛。

### 轻量与泛化的联合验收

- 建库围绕有限机制与可复用模板，不枚举 request 长度或每种批人数。代表短请求配方维护在[采集合同](../redesign/04_collection_templates.md#代表短请求候选与执行前门槛)。
- 同一支持域新增目标 request 应增加执行实例，不能惯性增加模板定义、规则或采集次数；真实机制差异需说明覆盖收益。
- 分开记录采集初始化/预热/观测、后处理、存储和规则规模；单次有预算不等于总体轻量。用户已授权自主采集，仍须先写目的、累计额度和停止条件。
- 固定资产及规则验证未参与修改的输入；用于修正的输入转为开发证据。未知成本与结构缺口分开报告。
- 不用只通过拒绝路径、命令 complete、字段数量或已有样例保持替代能力验收。无具体变化或反证时不反复运行同一检查。

## 4. 阶段交付与完成条件

### S0–S2：基线、输入和公共接口

历史已交付；最终输入合同后续已迁移为固定模型、configurations、request_workloads。设计分别见[用户合同](../redesign/02_user_contract.md)、[控制接口](../redesign/03_control_interface.md)。旧 base/targets 合同不恢复。

### S3：统一流程采集与参数化模板

交付统一 block 定义、公共 wrapper/extractor、适配绑定、来源 manifest、可加载模板和有限参数关系。

完成条件：

- 定义 → 插桩 → 原生证据 → 模板节点/端口可追溯；嵌套、异步关联和共享工作归属明确。Python 采集消费公共合同，C++ 仿真不依赖原生 Python 执行。
- 模板保留必要节点、依赖、资源、状态效果及参数来源，可重绑定目标身份；Prefill/Decode 按模型结构处理内部区域，语义粒度不强制等于成本粒度。
- 声明范围内的变换具有前提和真实来源，复用结构定义，不按长度或样本身份枚举。来源、实例、模板族、变体和规则数量区别报告。
- 代表性方案能解释已有资产覆盖及必要缺失，短请求、模板归并与运行/后处理/存储开销有实际证据；不能只拿到 trace 或编译成功。

当前单库为112份流程实例、3328个模型区域共享28个资产内结构定义，编译资产约112 MiB。这些分别是调用实例、区域实例和已共享定义，不是112种语义block，也不等于28个覆盖任意配置的模板族。14项配方机制均有双rank事实；是否适用于目标仍由实际实例化及变换规则判断。

初次建库实测原生约198秒、结束至后处理发布约243秒，保留原始约420 MiB、派生约1.10 GiB。该口径不包含后续假设耗时输入、诊断图及修复重提取；历史base采集没有初始化/预热分段；共享SGLangCapture新增的分段记录已在一次独立validation运行实测，不能回填为旧base测量，也不为字段单独重采。原始数据完整保留，vendor重复目录简化已真实验证，不能据此宣称开销优化全部完成。

**建库决策交接已接入单组完整生命周期**：复用实际资格结果，有资产时不因机制清点缺项重采；无来源时按声明配置组安排一次候选，失败或规则缺口不自动循环补采。Python预测编排已替换占位：根据实际缺兼容来源结果选择配置组，每组一次尝试并复用采集预算/恢复生命周期。已有库且缺成本、已声明未编译资产均证明不采集；无资产路径已完成一次真实采集，宿主中断后恢复同一attempt并导入新库。两个配置在第二轮预测返回缺成本，结束后resume不增加采集、轮次或用量。真实采集证据只覆盖一个配置组；另外三个配置组的公开输入已证明配方失败原因分别归属、已有库不受污染且不采集。已有公开开发回归证明启动失败组不污染另一个现有资产组，重复resume不增加attempt、轮次或用量；失败后继续新的采集及多个成功组尚无运行证据。确定的后处理失败已通过处理进程记录与类型化异常接入组隔离；已验证进程失败记录和成功结果复用，多组继续的运行证据仍缺，不能据此完成S6。失败未导入资产时已复用原预测，不新增轮次；自动导入后按代表配置组重算已有一次真实建库验证：第二轮仅新部署组，已有组完整结果保留，合并组计划/来源资格及重复resume通过；显式替换资产仍完整重算。原始事实已覆盖的目标不得以“没有同人数来源调用”为由补采。

配置代表选择已按最大请求池、同容量最大Prefill预算、完全相同保留声明顺序实施；公开plan与prepare-representative已验证预算较低配置先声明时仍选择预算充足的已有候选。这不证明配方在任意部署都可执行，也不生成集合之外的配置。

S3主线阶段验收通过，逐条件依据见[结构阶段验收](2026-10-13_structure_stage_acceptance.md)。稳定合同见[采集与模板](../redesign/04_collection_templates.md)。

### S4：轻量控制、有限变换与动态展开

交付使用公共控制接口的轻量控制器、模板实例化、依赖/资源执行和结构报告，接受显式给定节点耗时。

完成条件：

- 在约定范围内实现请求到达、准入/组批、prefill/decode、发布、KV状态与终止；唯一模拟时钟及端口事件影响下一次控制决策。
- 同配置及允许的配置变化可用固定模板展开多组新请求；节点参数、变换接口、关键依赖、资源和状态正确，不只比较总时长或节点数。
- 给定耗时变化能够通过实际完成事件改变调度，并完成相应结构验证；未知耗时不填零、不启动性能补采。
- 固定规则后通过范围内独立原生对照；未支持输入由同一模板/规则条件解释，不维护额外黑名单。模板外工作和成本精度不成为本阶段验收对象。

当前范围与证据分开记录，表中的条件不是新增检查或黑名单：

| 维度 | 现有规则依据 | 已验证与剩余 |
| --- | --- | --- |

Prefill预算轴已确认使用现有AdmissionWork参数域：接纳当前请求后停止，不关闭持续准入；同库公开展开成功，无须因配方未直接观察该分支而补采。独立三请求场景已核对流程、准入、kernel、通信/复制与关键发布依赖，没有修改规则或追加模板。本场景到此收口。S3/S4逐条件验收已通过，进入S5；多组生命周期及受影响组合重算仍留在S6，不转为无限结构验收任务。技术合同见[控制与语义](../redesign/05_controller_semantics.md)。

### S5：性能单元与节点成本

S3/S4主线结构验收已通过，本阶段开始实施。按实际工作选择节点或局部子图的成本单元，使用独立测量、明确特征及适用域；未变化工作也须满足成本迁移条件。

当前服务查询传递目标kernel/通信/复制描述、CPU阶段与成员工作，并保留实际节点种类。物理设备事件命令不能因缺少kernel描述而归为CPU；其服务角色和依赖保持既有结构合同。公开预测已能按显式 `assets.cost_models` 使用准入/worker/kernel 候选，并将实际节点基准与给定值分开报告；当前仍是条件运行，正式成本覆盖与资格未完成。

准入单元已有完整边界、无profiler观测以及C++ fit-costs/evaluate-costs生产评价。固定经验基线在20条独立留出上的初始化/插入MAE约9.1/6.8微秒、WAPE约17.8%/15.5%；候选保留来源条件与needs_data，不因评价完成而提升资格。该支线暂时收口，不继续预建排序/插入计数或追加字段。通信采样已补齐物理任务导出，并以旧独立采集重提取验证，没有新增采集。

暂停前的通信成本增量实现一并保留在当前提交中：物理任务样本、拟合/评价及查询入口代码已接入并通过构建；训练、留出评价和预测消费的完整运行验证尚未完成，不能计为通信模型已交付。后续从现有派生资产继续核对，不因此新增采集或回填精度结论。

一个已通过结构对照的条件场景包含162048个CPU服务节点、8918个计算节点、6256个DMA节点和7532个物理设备命令；这不是成本模型数量或时延占比。计算的265种名称/shape/dtype/格式描述中，旧独立样本精确匹配106种，尚不代表部署、数据相关特征或成本资格。CPU主要切分在execute与dispatch；旧包含式阶段样本不能逐节点分摊。规划证据见执行记录，不按剩余描述逐项补采。

#### 采样方法的近期交付

**已确定的约定：** 采样对象与模板性能单元对应，语义/性能观测独立但共享工作描述；原生状态由框架管理；不假定每个框架有静态 batch benchmark。稳定合同见[独立性能采样](../redesign/04_collection_templates.md#独立性能采样合同)，成本边界见[性能对象对应](../redesign/06_performance_execution.md#性能样本与子图工作的对应)。这些约定不各自形成状态管理器、等价检查平台或拒绝规则。

**当前实现：** CPU/device 样本仍通过常驻 `Engine.generate()`/`async_generate()` 取得，请求工作域显式提供，已有参数配方、实际批次记录和预热覆盖。device 观测仍复用语义 scope；模板参数关系只负责实际批次到节点特征，自动请求规划、完整特征覆盖评价和独立性能观测尚未完成。当前计算候选主要是精确匹配的中位数表，没有随机森林或已验证的跨 shape 泛化。独立通信设施保留，不由本次讨论推导性能资格。

恢复后按一个完整能力交付收口以下工作：

1. **对象与接口交接。** 从现有模板工作描述选择计算、attention、CPU、传输/通信的实际性能单元，明确实现、必要特征和计费范围；采样与预测消费同一含义。将需求/请求驱动、观测与资产交接按公共编排、框架适配、runtime 适配整理，不新增原生状态机。
2. **独立性能观测。** 收紧现有 observer，性能采样可取得必要归属和实际特征，无须生成新语义模板或依赖整套结构插桩。保留原生执行链及共享底层观察能力，不复制一个 observer 体系或为每个 kernel 新建执行器。
3. **有界特征范围验证。** 先复用已有样本和模板参数关系，区分固定量、请求可影响量、运行状态及实现分支。预声明少量参数化请求、覆盖目标、重复与留出、累计预算和停止条件；优先在现有 serving 入口验证实际覆盖及开销。不能只统计记录数，也不要求每次请求都形成精确指定批次。

**本项完成条件：** 从一组明确的性能特征需求到请求构造、实际样本、覆盖结果有端到端证据；未覆盖/不可达/未观测条件明确，有限预算内取得的范围与模型适用域相符；没有接管原生请求/KV 生命周期，公共合同不暴露 SGLang 类型。单次命中、同次运行重复层拆分留出或“能记录任意结果”均不足以完成。

**停止与后续边界：** 预算到限或共同参数关系无法解释时结束本次尝试并保留缺口，不反复补采至案例通过。benchmark/直接 ModelRunner 仅有源码探索证据，其输入与状态准备、外围流程及 Ascend 测量适用性尚未验证，不作为近期改造路线；独立 batch、逐算子重放、复杂反向求解器和第二框架均不预建。原生组批是否能低成本覆盖所需特征属于待验证风险，不以新增强制组批接口当作已解决。

#### 成本模型与消费的后续交付

采样合同收敛后按下列职责推进，已有合格证据和候选消费继续复用：

1. **CPU执行与提交成本。** 队列观测、分段测量及目标工作查询已接通；最新模板资产为 `data/redesign/s5-cpu-target-work`。worker 按操作×提交位置拟合，成对探针扣除后的固定留出 65250 段全匹配、MAE 1.072 微秒、WAPE 12.80%，仍保留未测边界开销及 `not_established`。测量支线收口，候选消费已接入相同执行核并保留资格，下一步完善成本适用条件，并完成主线程服务、复杂 worker 及通信逻辑根的必要工作描述。完整三段 worker 只覆盖部分 CPU 成本，缺口不直接触发补采。
2. **计算、通信/传输及设备命令模型。** 公共 kernel 拟合/评价及预测消费已接通；当前部署的一次独立训练采样以28554条计算测量形成160组候选。预测只精确匹配目标张量描述，并有条件沿用唯一观测启动变体；带额外attention/KV等语义工作时不使用该简化模型。已有局部评价不能替代完整目标成本资格，具体误差及证据用途见执行记录。下一步补齐数据相关工作与必要的启动映射，再完成通信/传输及设备命令模型，区分服务、等待和观测影响；不以形状匹配或包络时长冒充合格服务，不按每个未匹配request补采。
3. **统一成本消费。** CPU与kernel通过同一CostModel查询接入执行核，评价与预测共用特征匹配；显式候选支持加载、只读挂载和节点基准报告。配置关系由框架适配器解释，容许已支持路径中的请求池/Prefill预算变化，再按目标节点工作匹配。两档预算的公开预测已同时消费准入、worker和kernel候选，移除kernel后与原CPU结果保持一致。大量其他服务仍用显式给定值，启动变体、运行环境和服务时延迁移仍未资格化。下一步接入剩余成本类型并完成真实成本闭环，不能以混合运行成功宣称跨配置精度。

测量边界和粒度约束见[性能设计](../redesign/06_performance_execution.md#cpu-测量与执行边界的交接)。这些交付不重开已通过的结构场景，不把范围外CPU事件升级为门槛。

完成条件：计算、CPU服务、传输及通信按范围得到成本或明确缺口；合并单元不丢外部依赖、不重复计费；服务、等待与观测开销分开；独立样本验证成本模型。不得用手调倍率、残差或目标特例拟合。见[性能设计](../redesign/06_performance_execution.md)。

### S6：集合探索与真实闭环

在已有集合入口、组合隔离和恢复基础上，完成有界代表性建库、共享结构/成本需求、受影响组合重算与模型成本驱动的动态反馈。

完成条件：一个固定模型的配置 × workload 探索可从必要资产获取运行到结果；每组合报告状态、范围、指标或具体缺口；失败/预算/恢复不重复计量或污染其他组合；验证资产不进入生成或拟合。至少一个真实主线闭环得到独立证据。见[集成流程](../redesign/07_integration_workflow.md)。

**完整完成 S3–S6 后才写入 implementation_log.md 的本轮完成总结。** 不以已接入 S6 部分入口替代 S3/S4，也不因本次文档收紧而降低原承诺。
