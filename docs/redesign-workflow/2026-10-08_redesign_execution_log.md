## 历史里程碑

### 2026-10-08 至 10-10：合同与模板链

整理旧项目、恢复官方第三方源码并将必要环境适配隔离。设计收敛为统一流程、代表采集、参数化子图、轻量控制和事件反馈；S0–S2 建立集合输入与公共接口，随后接通原生事实、来源图、模板生产与条件执行。期间各版设计草案已被当前合同替代，不再作为并行方案维护。

### 2026-10-11 至 10-13：动态结构与分层

联合 serving 观测逐步补齐调度、成员、模型区域、通信和资源关系；框架与 runtime 适配拆分，workspace 初态采用统一预热。已声明规则下的请求池缩小、Prefill 预算和时间反馈取得当时的结构对照。历史模板实例数、区域数与共享定义数含义不同，不代表通用语义种类数量。

[结构阶段验收](history/2026-10-13_structure_stage_acceptance.md)记录当时 S3/S4 的通过范围。部分证据使用给定耗时；不构成性能精度验证，清空后不能从原数据复跑。模型/TP/backend 变化、KT 预测及原生控制器未因此获得支持。

### 2026-10-13 至 10-15：性能需求、采样与恢复

建立独立性能样本、统一工作特征、候选拟合和目标查询；将整体成本需求分析纳入正式流程，避免依赖开发者逐节点排查。集合编排增加共享资产、受影响组合重算和采集/拟合/预测恢复。CPU 逐段计费路线曾使模型和采集负担持续增长，后按用户确认范围删除；历史覆盖数不转成当前待办。

完整审查及整改依据保留在 [10-14 完整审查](history/2026-10-14_completed_capabilities_review.md)、[10-15 生命周期审查](history/2026-10-15_code_lifecycle_review.md)及[10-16 代码审查](history/2026-10-16_code_structure_review.md)。这些是当时快照，不替代下一轮对全部活动代码的复查。

### 2026-10-16：首次工程闭环交付

在声明范围内接通设备计算、物理通信、真实搬运及设备命令费用，目标请求可无 given 结束。此前多来源、失败隔离、局部重算和终态恢复已取得运行证据。独立端口对照出现约 −81.93% 的窗口偏差，以及预测五批、原生四批的差异；工程闭环成立不等于原生行为或性能精度合格。

交接审查删除重复费用统计、无消费者的 CPU 转存与 runtime 中的框架特判，统一传输参数前提。累计图反复重建和 RAW/MONOTONIC 跨时钟对应仍为有范围的债务。旧数据已删除，不能将当时 24 份候选或 226 个对象与下面的新运行混用。

### 2026-10-17：稳态精度归因与后续工作计划

在保持正式模板、候选和生产源码不变的情况下，先前完成两次各限 300 秒的原生开发观测，以及既有样本最小/最大值的离线敏感性分析。相同 Engine 的双请求首次窗口约 11706 ms，热态重复约 266–277 ms，中位数约 269 ms；稀疏栈定位到首次 Triton 内核编译和 host launcher 构建。原性能采样对特征点额外预热，目标验证只执行通用预热，因此原窗口不满足相同稳态条件。热态仍明显高于约 85 ms 预测，同时观察到显著 CPU 执行；尚未独立分解全部重叠、设备同范围误差和观测影响。

事实、两次观测及敏感性方法见[归因记录](../../data/20261016T233213.460800Z_accuracy-analysis/results/analysis.json)。实测 CPU 代入得到接近原生的简化估算，不算独立预测；这些输入已用于设计，后续只作为开发证据。原始正式对照不重写。
