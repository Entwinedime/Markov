# 项目主工作流

更新时间：2026-10-28。

## 项目保留的主思路

用户给出平台、模型、base、workload 和 target 集合。base trace 形成原始 DAG，
框架与目标配置规则生成目标工作和依赖，独立性能库及未变工作的源成本提供数值，执行器给出完整 HTTP 预测。
准确性实验与资源/策略搜索处于上层，共用一个预测器；它们不是普通使用的前置要求。

本轮重构解决两个相连的问题：现有实现重复组织了太多执行细节，导致预测慢、内存高且代码难维护。
新实现从合同和职责重新编写，参考旧机制与证据，不整体搬回旧目录；性能和代码规模同时评价。
同时明确具有前缀复用、容量竞争与跨层回访的负载场景，以及计入资源成本的搜索问题；
不恢复已经终止的大规模搜索任务。

## 当前判断与下一步

旧自有源码共 88,814 行、546 文件，归档并不改变这个基线，也不代表完成瘦身。
一个代表目标有约 1,223 万活跃节点和 3,343 万活跃边，同批还存在重复成本查询、无关回调与目标级源分析。
这些是静态分析与旧资产统计，尚未取得新实现的效率成绩。

全量重构已交付入口与构建底座，原始 DAG 回放、缓存 I/O、已解释计算调用的 CPU/后台/设备、阻塞通信、注意力准备及已支持的分配/内核准备已进入共用执行器；输入准备与有序流交接已生成，常规成本覆盖和完整请求控制仍未完成，正式目标预测、同输入批次提速和规模目标仍未验收。
