## 当前整体判断

已建立从输入、代表结构、分层模板、动态展开到独立成本需求、采样、拟合和结果恢复的工程链。主线为 SGLang + Qwen3-32B dense / BF16 / Ascend TP2，轻量 FCFS、统一预热、cold logical KV；prefix cache、overlap、graph、mixed/chunk 等机制没有因流程可运行而获准。KT 有原生采集，尚无模板预测资格。

稳态、分层模板与 CPU 专项已于 2026-10-20 按用户要求提前结束，未达到完整测量与精度验收条件。执行结构、单卡分片与三十轮独立全量审查现已完成声明范围交付；下一步独立完善真实成本链路，限定结构能力不授予额外模型、TP 分支或性能资格。

单卡顺序取得各逻辑角色，容量1可以从零独立建库，子图按共同接口变换与组合。旧数据清空后，新两角色模板已完成两配置×两请求集合的条件展开；只改变给定耗时仍会改变组批。输入前缀已与后续模型phase解耦，正式需求、产物、终态恢复和消费清理通过；协议推导及观察边界继续保留。

性能采集须复用同一分片执行底层，但完整成本覆盖、低扰动资格、SDK 近似、成本泛化与精度评价继续后置。已建立自动需求交接，后续仍须在预算内证明覆盖能力，不能回到逐节点人工补采或靠总残差调参。

## 2026-10-08 至 10-12：确立 redesign 路线

统一输入逐步收敛为固定模型、配置集合和 request workload 集合，用户不选 base。决定先用统一动作接口与轻量控制器，原生控制器作为后续可选能力；语义粒度与成本粒度分开，先验证给定耗时下的目标动态结构，再做真实成本。

旧代码及旧项目材料转入 deprecated，根 README 清空；third_party 框架恢复官方源码，必要构建/环境适配留在自有适配层与镜像副本，不改变主分支。Dooly 注册为参考子模块，采用轻量结构发现和参数复用的思路，没有移植其完整上下文重放系统。

逐步建立五类 serving 动作、原生语义插桩、来源图、模板、轻量控制与目标事件执行。决定跨框架差异集中到子图获取、模板生产和性能观察适配，核心不识别框架函数或重演原生状态机。

## 2026-10-12 至 10-16：打通有限工程链

适配进一步分为框架、框架内模型和 runtime；Python 负责原生观察与进程交接，C++ 负责来源解释、模板、控制、执行和成本消费。环境 patch 回归对应适配目录，统一预热成为采集与目标观察的共同起点。

独立采样、经验候选、共同成本查询、集合预算和恢复陆续接入。性能采样仍借原生请求生命周期取得实际 batch，避免自行维护 KV/worker 状态；缺失性能数据应由正式需求与覆盖流程识别，不由开发者逐个补齐。

LLMServingSim 注册为参考子模块；结合其模型层次划分重新讨论语义树、归一化和 CPU 范围。决定保留子图及动态展开，但只处理统一流程及必要因果，不追求还原全部原生 CPU 函数。

这一阶段能够在已有或给定成本下完成有限预测，原生与预测仍有显著差距。首次编译、CPU 缺失、范围及观察影响不能合并成一个残差。相关旧运行数据与详细历史已删除，以上仅为历史结论。
