# 工程与文档维护约束

本文件是自有代码、构建、配置及文档的工程规则正文。用户最新明确指令优先。规则服务于简洁、有序、可维护的实现，不据此增加检查平台或审批流程；本文不记录实施进度。

## 代码表达与规模

- 主流程自上而下表达业务步骤，同一方法保持相近抽象层次。优先显式变量、普通循环、提前返回和简单分支，减少隐式状态与跨层跳转。
- 所有 Python、Shell、C/C++ 源文件及头文件，在函数、循环和条件块内部也按逻辑成组；不同步骤之间适当留空行，紧密相关语句保持连续。独立注释上方留一行空行，不机械地逐行插空行，不用压行减少代码量。
- 命名表达业务含义，时间、字节、页数写清单位。简短注释解释身份、依赖、所有权、计费及生命周期，不复述语句；不保留注释掉的实现、无归属 TODO 或临时调试输出。
- 只为真实职责或复用提取方法、类和目录，不为几行代码增加转发层。瘦身应删除整条冗余职责链，不能通过拆文件、删必要说明或迁出统计范围凑行数。
- 同一事实只有一个所有者。删除无业务作用的重复解析、规范化、转换、拷贝、序列化、读写、图遍历及进程启动；先修所有权，再判断是否需要缓存。
- 给人看的报告、机器交接数据和可选验证明细分开。诊断在生产端按开关记录，不先完整生成再裁剪；精简不能删掉消费者必需的信息。
- 新字段、分支、依赖和抽象必须有当前消费者。不预建插件中心、万能规则语言、多套后端或未来占位功能。
- 反复增加特例、相同规则多处修改或跨层判断时，回查职责，允许联合多个文件删除重写，并完整移除旧链路。代码量下降是结果，不替代逻辑和能力验收。

## 类、组合与特化

类承载真实状态和职责；简单值合同用 struct、dataclass 或已有领域类型。不为每个字段添加 getter/setter，也不把每个代码块做成子类。

| 差异 | 实现方式 |
| --- | --- |
| 参数或绑定位置不同 | 值对象和参数，公共算法一份 |
| 多个部件协作 | 对象组合，各自持有状态 |
| 同职责的实际运行时替换 | 清晰接口或浅层继承，只替换差异步骤 |
| 同算法确实服务多个编译期类型 | 必要的 C++ 模板，明确类型要求 |
| 少量类型相关操作不同 | 重载或局部特化，不复制完整流程 |

不以闭包链、函数组合或回调管道隐藏业务生命周期，不把状态藏在全局变量或 lambda 捕获中。局部比较器、短标准算法 lambda 和无状态辅助函数可以使用。仿真事件需要的回调应有明确的拥有者和触发合同，不能成为第二套调度器。

语义子图模板与 C++ 模板是不同概念。参数差异不应生成逐长度、逐 batch 或逐来源的类与特化。

## 抽象与目录边界

- 正式 Python 流程分为输入准备、统一预测和上层应用；准确性实验与搜索并列调用预测。特定面板、案例、留出安排及跨运行汇总放在 `examples/`，不进入核心算法。
- C++ 按源观测、图与依赖、结构规则、成本、事件执行及报告组织。框架、模型、runtime 和环境差异留在适配模块；核心不按原生函数、kernel 名或实验标签增加业务分支。
- 通用采集与产物发布不导入框架私有实现；采集、成本和执行不反向导入应用或示例。环境补丁、依赖及原生观察资源有明确适配归属，不顺手修改上游工作树。
- **同职责 C++ 头文件与源文件放在同一目录**，不再新增或扩张平行 include/src 树。旧布局的迁移应作为完整职责改造，同步 include、CMake、Docker COPY 和调用方；本规则不表示现存目录已经迁移。
- include 从所属源码根开始，路径表达职责；不留下转发头兼容旧位置。普通实现放 `.cpp`，头文件只保留必要声明和模板定义，不因同目录改成全部 header-only。
- 文件移动同步 Python import、子进程模块路径、源码根定位、构建、配置和说明。跨语言合同同时修改生产者与消费者，不靠两端硬编码检查维持表面一致。
- 不预建空目录、占位类或无消费者的公共接口。活动代码不得调用 `deprecated/` 等归档实现。

## 语言、资源与边界校验

- C++23、CMake ≥3.20，关闭编译器扩展。头文件使用 `#pragma once`，直接包含所用声明，不依赖偶然传递 include，不写 `using namespace`。
- C++ 类型使用 PascalCase，函数和变量 snake_case，私有成员后缀 `_`；沿用仓库 `.clang-format`，不修改格式规则，不开展无关全仓更名或排版。
- 优先值语义、标准容器及 `unique_ptr`；真实共享所有权才用 `shared_ptr`。RAII 管理资源，指针、引用、span 和 string_view 的生命周期明确，注意扩容和异步动作造成的失效。
- 普通值对象使用编译器生成的特殊成员。不批量添加 `noexcept`、`nodiscard`、assert 或模板技巧；Release 正确性不依赖 Debug 分支。
- Python 基线为 3.10，沿用 Ruff、4 空格、双引号和 LF。修改的业务函数注明参数与返回类型，动态 JSON 在边界收窄，不逐层传不明字典或位置元组。
- 复用现有路径、JSON、进程及日志工具；模块导入不得启动服务、采集、容器或写产物。
- Shell 参数使用数组及正确引用，不用 `eval` 或拼接不可信命令。路径、设备、预算通过输入声明，不硬编码本机实验位置；不将密钥写入配置或日志。
- 外部配置、文件和适配输入在边界校验一次，内部依赖已经建立的类型与不变量。标准库能清楚报错时直接使用，仅为恢复、释放资源或必要定位捕获异常。
- 缺测、不支持、无效输入、失败预测不转成零或空成功；单位、范围和符号在边界转换，不用无符号下溢表达缺失。
- 保留输入安全、独立评价隔离、原子 DAG 修改和关键时间不变量所需检查。不要为理论上的错误堆叠存在性检查、重试、异常包装或默认值。
- 只维护当前内部合同，不新增 v1/v2、checksum、digest、指纹、冻结副本或重复读回来证明本地产物有效。真实部署版本可记录；历史数据需要时显式转换，不长期维护双格式。
- 删除功能须覆盖实现、类型、调用方、CLI、配置、分发、构建、示例及说明；只隐藏入口不算删除。用户要求保留的现行静态回放不因此移除。

## 建模与采集纪律

先解释机制、范围和变换，再获取最小必要证据。不能通过增加样本或修改成本掩盖结构问题。

- `profile_manifest.json` 是采集与建模的正式交接。原始图只来自所选 base；预测不得读取 target trace、正常真值或评分，也不得通过 target 残差调整系数。
- 三阶段分别负责原始 DAG、目标工作与依赖、成本绑定与执行。结构不读取系数，成本不生成操作或改变策略。超时、取消及完成条件由同一仿真时钟触发，不能另算理想结构后修补时间。
- base 只迁移已证明工作不变的成本；变化或新增工作使用独立数据和离线模型。数据按部署、工作变量、实现及计时口径共享，不按 C1–C5、workload 名、base 身份或矩阵格数特化。
- HiCache I/O/control、Prefill、Decode、CPU residual gap 和采集开销分别管理。完整 HTTP 不能删去难以预测的成本；不能叠加父包络墙钟与已计费子操作。
- 仿真粒度取决于外部依赖、资源竞争、状态变化及测量需求，不以还原所有 CPU 函数和后台事件为前提。未解释的成本保留来源和近似，不能假称已建模。
- 保留 SGLang 与 KTransformers 的同级接入；HiCache 只属于 SGLang，不能为 KTransformers 伪造对应能力。NodeScale 可选且默认关闭。
- 不用手调倍率、阈值、补偿表或目标身份凑成绩，挪到配置也不允许。参数必须有测量或机制依据，训练拟合成绩不能当独立预测精度。
- Python probe 默认不采 snapshot，不读取 tensor 内容或增加设备同步。设备采集严格串行；预测并发设内存上界、余量及进程树回收，不能靠 OOM 试探承载能力。
- 采样前声明问题、可复用事实、新证据、累计运行/后处理/存储预算及结束条件。失败、恢复和增加额度不清零账本；已有授权范围内自主推进，不反复要求确认同一额度。
- 初始化、预热、有效观测、后处理、导出量、保留量及峰值分别统计。固定输入验收期间不悄悄补成本或改规则；修改后的证据作为开发数据，重新安排独立验收。
- 数据按实际引用保留；base、token、CPU 配对、独立测量、正常真值和必要失败证据不能因已有汇总就删除。历史本地保留与 Git 跟踪是两件事，不为调整忽略规则删文件。

## 构建、验证与阶段交付

C++ 核心的配置、构建、格式工具和仿真使用 modeling Docker；宿主负责编辑、Git 与容器调度。受原生 SDK/ABI 约束的 hook 在对应推理 Docker 中构建，其依赖不进入纯预测核心。纯预测不需要设备或 target 真值，不能因采集与预测共用宿主就开放评分输入给预测器。

不新增或恢复独立 test 工程、CTest、测试脚本、fixture、mock 或改名的自测入口，除非用户明确要求。使用静态推导、正式构建及必要真实输入的公开入口；独立评分和有用户用途的诊断仍是产品能力。

以完整的跨文件职责链作为工作批次，不逐文件编译、记日志或提交。每个阶段及重要语义改动后做必要检查，不能把所有验证拖到整个窗口结束。没有新修改、失败或未决风险时，不扩大或重复检查；大矩阵在实现稳定后统一验收。

阶段开始核对提交基线、工作区、能力、环境、数据及遗留限制，据此调整阶段范围、依赖、任务和判据。计划可合并、重排或删除重复工作，但须说明影响，不能默默取消用户要求。首阶段明确筹备改动归属，不将以前未提交的内容算成新成果。

阶段结束沿全部差异检查生产者、消费者、调用方、配置、构建和产物，包括受影响但未改动的代码。检查职责、所有权、时序、表达和冗余，修正后复查；构建通过、行数下降及历史成绩不能代替内容审阅。

分别检查代码、文档、数据：代码做必要静态与 Docker 验证；文档核对事实、职责及状态；数据核对适用环境、依赖和保留范围。纯文档任务说明代码和数据是否受影响，不启动无关构建、采集或清理。

完成后按可独立审阅的职责分层提交并推送开发分支，提交格式为 `type(scope): English imperative summary`。核对暂存内容和远端实际提交，不强推、不直接向主分支推送，不提交运行资产。未完成交付时保留待交付状态，不开始下一阶段实现；不为日志记录自己的提交号反复补提交。

## 文档的三层职责

| 层 | 位置与职责 | 更新时机 |
| --- | --- | --- |
| 静态设计与约束 | `design/`：架构、公共合同、工程规则、机制和稳定操作说明 | 对应设计或接口真实改变时 |
| 项目主工作流 | `workflow.md`：精简里程碑、当前整体判断及优先级 | 重要进展、窗口关闭或全局取舍改变时 |
| 窗口 | `windows/YYYY-MM-DD_purpose/` 的 plan/status/log | 同一任务在原窗口持续维护 |

**跨层不引用，不复制正文。** 不写跨层链接，也不写“见某计划/设计第几节”等内容依赖；每份文档独立说明自身结论。源码、配置及实际证据可以引用，同层只做必要链接。根 README 提供导航，AGENTS 提供代理入口，不在 docs 中另建导航层、审查档案库或备份目录。

静态文档一处维护一个主题；主工作流对活动窗口只保留一句状态和项目影响，不复制阶段表、逐项待办及实验数字。字段细节已有源码或配置时，不再手抄巨量清单。

### plan、status、log

- **plan** 开头写开始日期和一句目标；正文维护范围、阶段任务、方法、交付、完成/停止条件及资源风险，不混入当前进度、结果或消耗。
- **status** 维护当前资格、基线、已验证范围、限制及下一步起点。区分待做、实施中、源码已改待验证、限定范围验证、待交付、完成、暂停；新快照替换旧状态，不复制整个计划或报告。
- **log** 按日期正序记录有意义的工作批次、失败、重要取舍和阶段交接，连续小改动合并记录，不记工具流水或常规轮询。

日志统一使用四个字段，通常各一至三句：

```markdown
## YYYY-MM-DD — 阶段或事项：本批主题

**范围：** 本批边界，阶段启动时说明提交起点。

**改动：** 实际修改、审查发现或决定及必要原因。

**验证：** 实际方法、范围、结果和必要证据位置；未运行要明确说明。

**结论与限制：** 已证明的结果、未验证范围和交付状态。
```

保留影响范围、预算或结论的失败与取舍，不能把后来成功改写为早先已通过。历史报告复核、编译、真实采集和独立验收分别表述；不粘贴整段输出。详细运行数据放在 data，不另建平行 review/evidence 文档来复制正文。

同一工作只维护一个活动窗口。窗口结束后在主工作流留下自足的日期、结果、验证和限制，再撤下已关闭窗口；未完成或暂停任务不能因整理文档被自动关闭。已有历史通过 Git 查阅，不新增归档副本。

文档交付检查目录职责、链接与锚点、事实和约束冲突、状态/计划混写及失效证据。已清理资产明确标为历史不可复现，不保留误导性的可点击链接。纯文档检查到此为止，不构建无关业务。
