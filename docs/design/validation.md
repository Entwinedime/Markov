# 验证范围与结果解释

本文规定报告和验收方式；历史结果不授予新实现的验证资格。

## 三阶段三份报告

| 报告 | 比较对象 | 能说明什么 |
| --- | --- | --- |
| 原始 DAG 回放 | 所选 base 的观测坐标与原始观测成本 | 源构图的请求、依赖和时间是否自洽，不证明正常运行精度 |
| 目标结构比较 | 预测逻辑工作与独立 target 观测 | 工作量、分支、资源和必要可达关系是否对应，不直接证明成本准确 |
| 完整性能评分 | 预测 HTTP 正式窗口与无 profiler 的正常 target 实测 | 当前部署和 workload 下的 E2E 误差，不证明整个结构已经精确 |

报告只在实验中按需生成。应用预测输出结果与局限，不读取 target 观测。
新表示压缩后不要求节点数与旧图相同；结构比较必须使用逻辑操作身份、工作量、边界和必要依赖。
操作数、字节/页、实际执行量、完成量、发布可见量、batch、existing/new、取消和后台状态分别核对。
只比较到部分结构时标明范围，不能用低 E2E 误差补充“整图正确”的结论。

## 静态诊断仍保留

源静态回放使用原始观测成本，不等同于正常 CPU 校正后的预测。
节点时间对齐分别统计服务、等待、残余和零时长边界，采集开销单列；标记点偏差不能直接解释成设备服务或 HTTP 误差。
CPU 和设备 lane 上未被事件覆盖的区间均保留为 residual gap，使显式回放不因省略设备空白而提前；设备 gap 不参与设备服务成本迁移。
每条 lane 只用一个独立起始边界保留首次观测的可用时点，避免首节点带外部依赖后丢失该约束；后续时点由成本与依赖推进，不逐节点锁定。
dependency_timing 按依赖种类及两端资源类别报告数量、时间逆序和最大反例，包含普通 flow、提交和同步。
导出的 HostToDevice flow 属于提交关系，不能把这类逆序全部称为原生 event 同步错误。
逆序只证明观测坐标不满足该先后关系；仅凭计数不能区分配对错误与跨时钟偏移，也不能据此调整时间戳或删依赖。
适配器明确观测到阶段结束前设备同步时，源图按实际提交 flow 对应的独占设备服务连接到该结束端口。
同一设备 lane 只连接已对应服务的最终前沿；缺少唯一对应的阶段单列，不用阶段墙钟反推设备服务。
这个语义同步边界不依赖原生 hook 是否采到，且不把阶段开始放到设备完成之后；KTransformers dense 的同步阶段使用此合同。
导出的提交箭头可能起于主机调用开始，不能仅凭该箭头证明内部设备命令已经发出；未解释的派发过程继续保留为限制。
显式 oracle-cost 诊断在已经得到的目标图上替换对应成本，用来区分数值与结构问题；
不读取 target 真值重新选择预测分支，不覆盖正式预测，不计作泛化精度。
沿用现行规则下的静态回放能力，历史旧执行规则只作为证据，不恢复另一套旧运行系统。
执行式预测可显式记录已完成路径，再沿同一执行器做静态回放。先用原成本核对全部操作起止和 HTTP 端口，
再做成本敏感性或已对应的真实成本替换；不能只比总时间相近就授予图正确。
回放保留资源次序和事件因果，原时间戳只作比较。固定路径不重新评估超时、取消或容量分支；替换后的结果仍须说明这一限制。

独立目标评价先按请求、生成迭代、实际参与者、区域端口及完整工作描述精确对应；没有明确身份或出现多义时不替换。
文件 worker 还核对操作结束页的完整 token 祖先关系；后台写入没有所属请求，以原生入队顺序和处理内容共同定位。
显式 record-regions 记录实际页读、复制/发布、新键/已有键写入，以及批次整理和返回，计时分段之和必须恰好覆盖原生批次。
其中分散在多次调用之间的记账余量只作为一次聚合成本，不用于证明一段连续墙钟区间的先后关系。
预测的诊断地址单独记录，不进入成本特征，也不决定结构或执行时间。阶段外控制余量只有具备相同计时边界才对应；
HiCache worker 使用同口径分段，混合等待的残余区间不能拿一个 target 包络直接填入，避免父子重复收费。
评价器检查匹配节点之间可观察的同线程先后关系；尚未覆盖的设备数据因果、缓存、内部端口与时间分支另列，不能以节点匹配率代替全部结构相似度。
所有 target 成本只用于独立静态回放，不回写模型或 readiness；未对应节点沿用原值时明确标为部分回放。
跨请求客户端间隔计入完整 HTTP 并单列；普通预测迁移 base 的独立间隔，目标评价按相同请求边界替换，不从真值中扣除以制造通过。
全部已生成成本对应后仍需核对 HTTP 边界、必要依赖及未生成工作；不能只凭全成本替换或总时间相同授予完整结构资格。

## 完整 HTTP 怎样计算

包含 HiCache I/O/control、Prefill、Decode、残余 gap 与未归属成本的影响，不从分母或时间轴删除难建模部分。
准备阶段与正式阶段连续推进缓存及异步工作，但计时只取 workload 声明的正式起止边界。
后台工作只有在因果上影响正式请求时才影响该窗口，不能等所有后台队列清空后再冒充 HTTP 完成。

```text
APE_i = abs(predicted_i - measured_mean_i) / measured_mean_i
WAPE = sum(abs(predicted_i - measured_mean_i)) / sum(measured_mean_i)
signed_error_i = predicted_i - measured_mean_i
```

P90 使用最近秩：排序后取第 ceil(0.9×有效格数) 项。缺失与失败单列，不填零、不悄悄删格求好看的覆盖率。
正常重复取算术均值，同时报告样本数和范围；有效慢样本保留，重复和失败次数事先声明并累计。
完整面板及逐 base 沿用 WAPE≤3%、P90≤5% 的评价口径，同时报告逐 workload、逐 target 和最大 APE。
cross 另与直接沿用 base 正常墙钟的参照比较；self 单列。期望单格尽量低于 6%，不以手调补偿实现。
这些是精度评价目标，本轮重构完成不以强行达标为前提；未达到如实报告模型限制。

`EXECUTED` 表示执行完成，`MODEL_LIMITATION` 表示已得到结果但精度或解释存在限制，
缺结构/成本、执行失败、评分未就绪分别列明。不能用相同英文状态覆盖所有原因。

## 新旧实现怎样比较

使用同一 manifest、请求/tokens、CPU 校正、成本依据、target 和运行条件。
先核对工作、状态转移、发布与完成顺序、资源重叠和正式边界，再比较 E2E。
数值等价是重写时的默认目标；确实修复旧机制错误造成差异时，单列旧问题、依据与影响，不静默改变基线。
压缩和缓存不能改变舍入、NodeScale、域外提示或缺失结果。诊断开关不得改变正式预测。

## 效率目标怎样验证

争取代表完整批次至少 10× 提速，必须同机、同输入、同目标、同并发、同成本与诊断设置实测。
分别记录读取/构图、源语义准备、目标规划、成本查询、执行和报告的墙钟与 CPU 用量；嵌套阶段不重复相加。
报告完整批次时间、单目标延迟、吞吐和峰值内存；源共享内存不按多个进程 RSS 重复计数。
冷、热文件条件分开，采样 profiler 的时间不能与无采样运行直接比较。
历史 96 目标约 7,975 秒只作为量级参考，不能替代新旧代码的受控基准；局部查询快十倍也不等于整批快十倍。

## 验证顺序和最终面板

各阶段交接前完成关联代码审查和必要静态检查；存在可运行增量时完成相应 Docker 构建与少量公开入口验证。
纯合同或文档阶段不启动无关运行，不为每个小补丁重复构建；完整实现后集中做 clean Release/validation 构建与最终回归。
代表覆盖 self、不变计算、变化 Prefill、页宽变化、短 timeout、best-effort、write-back 容量压力及尾部发布。
规则和公式固定后，运行原始完整 60 cross；必要 self 为参照单列，不混成 75 格的同一统计。
再恢复扩展 72 与留出 54，共 186 格，用同一结果集合独立评分；不能把重复修正后的开发格重新叫留出。
新增场景在查看 target 结果前固定选择依据，受控短 workload 的证据不自动推广到生产吞吐、P99 或任意部署。

不维护独立测试工程。使用正式入口、真实输入与必要诊断，不为验证生成另一套仿真器。
达到所需证据后停止；没有新改动、失败或风险时不扩大矩阵或重复采集。
