# 性能需求、独立测量与执行

一个性能对象由**工作定义与特征 + 适用的实测数据/模型 → 耗时估计**构成。类别数量、对象名称、特征点、重复样本和目标调用次数是不同口径。

成本提供者只回答一项工作的服务耗时与适用性。执行核依据依赖、资源和唯一时钟决定开始/完成，控制器再消费完成事件。成本层不改图、不改变业务策略、不自行启动采集。

## 工作与计费边界

| 类型 | 必要特征与测量 |
| --- | --- |
| CPU 服务 | 命名切口、线程角色、step/phase/rank 及实际批次工作；独立线程 CPU 时间 |
| 设备计算 | 完整操作/实现、张量 shape/dtype/layout、启动条件及必要操作数；原生物理工作时长 |
| 通信 | collective/物理任务、字节、rank、拓扑与 transport；可关联的多 rank 任务 |
| 传输 | 执行方式、方向、字节和部署；异步设备 DMA 或同步 host driver 本体 |
| 设备命令 | 实际任务类型与资源；不以 CPU 提交包络替代 |

attention 的 query/context、head/cache 布局属于计算特征，不按整段 Decode 长度定义成本类型。未来 CPU 专家计算也属于计算工作，不能按控制开销忽略。

一个物理服务对应一个成本查询。语义区域可包含多个服务，也可共享同一成本对象；父包络不再计费。逻辑标记只表达关系，真实等待由依赖和资源产生，不迁移 base 的等待总时间。

## 性能需求是正式流程

模板给出可能工作、参数关系和有限适用域；实际目标展开产生具体工作特征。需求分析与拟合/执行查询使用同一合同，不能由人工查看 trace、逐个补节点代替。

正式交接为：

```text
模板规则与目标状态
  → 实际 ServiceWork / CostQuery
  → 跨组合归并需求并查询已有候选
  → 缺数据工作交给采样配方
  → 真实工作核对、规范样本、拟合
  → 新资产发布后从初态重算
```

`CpuSamplingCatalog` 只提供可测命名区间及 step/phase/rank，供 CPU 插桩识别切口。各组合的 `performance_requirements.cpu_service_catalog` 引用它，实际特征和覆盖仍在目标查询中。目录项不冒充样本，也不另建全类别来源原型与规则说明库存。

`CostQuery::from_work`、模型 `estimate` 和 `CostRequirements` 共同定义需求与覆盖。CPU 目录和执行共用 `CpuServicePartition`，不各写一套区间选择。需求保留实际服务次数与必要来源示例，不复制执行层的工作状态。

覆盖须区分：合同不足、结构域外、完整工作缺成本、已有候选可查询。`candidate_available` 不代表精度资格；范围内未知成本不能填零或用给定值冒充实测覆盖。

动态调度使后续特征依赖时延。缺成本时汇总已装配前沿的全部需求，未展开路径保留未确定状态，不能声称静态库已给出所有精确特征点。新成本改变组批后可细化需求，但必须复用同一预算、去重与停止机制。

## 独立采样的四项要求

1. **对象一致。** 样本与子图实例对应相同工作、实现、特征和计时边界；同名或同 shape 不足以证明一致。
2. **适配简单。** 推理框架维护真实请求、KV、组批和 worker 状态；Markov 不为采样重写这些状态机。
3. **共同实现途径。** 公共抽象基于原生执行与观察，不假定所有框架都有 `bench_one_batch` 或可直接调用的 ModelRunner。
4. **特征可构造且有界。** 从需求构造短请求配方，再核对实际工作；构造失败与未命中明确报告。

语义插桩和性能插桩分别管理生命周期，但共享执行底层、工作描述和必要关联。同一常驻 Engine 内可运行多个采样点和重复测量，避免每点重启模型；不要求每点执行完整目标请求序列。

请求是触发手段，原生 scheduler 才决定 batch。实际覆盖须核对每 rank 的成员、完成成员、输入/context、过滤索引及必要槽位配对，不能只检查人数或提交成功。

配方合并按实际执行路径、部署及完整有序请求/释放条件去重；一个配方可服务多个需求。相同配方已尝试却仍不覆盖时，返回合同、不可达或数据问题，不无限重复采集，也不建立任意节点输入的复杂反向求解器。

独立通信采样可使用原生 collective 载体，不必加载模型，但须对应目标的物理任务和环境。CPU 路径不启用重语义 profiler；设备 profiler 的观测扰动单独核对。所有路径共用稳态协议并保留实际覆盖，不从源码入口相同推定测量等价。

## CPU：服务、等待与搬运

CPU 单元由必要执行切口之间的服务定义，不由原生调用树定义。切口保留入队、worker、提交、可观察等待、传输及 serving 端口；私有函数包络、observer 空洞或图替换接缝不自动成为新单元。

`CpuBoundary` 描述线程角色、边界类型/方向及相对队列位置。`CpuServiceWork` 带 step/phase/rank、请求数、输入/context、发布完成成员等；Schedule 另带入口运行/待合并/等待人数、准入状态、各次过滤及合并工作量。目标控制与独立采样提供相同含义，不带请求 ID 或来源时钟。

| 观测内容 | 处理 |
| --- | --- |
| 调度、准备、提交、worker、发布自身工作 | 独立线程 CPU 计时，经统一切口归一化 |
| 显式设备/线程等待 | 保留依赖，由执行时刻计算等待，不再收 CPU 墙钟费 |
| 同步 host 复制 | 独立计传输，保留完整 driver I/O 本体；不含之前的同步等待 |
| 异步 DMA | 按设备服务及依赖计费，CPU 发起不改变其身份 |
| 观察范围与时钟读取 | 记录校准事实，排除可明确计量的观察开销，不将其视为业务 |

CPU 采样保留线程时钟、标记观察区间及读取次数。通过本线程校准取得读取开销，在标准化时排除；原始计数不改写。校正后低于分辨率的观测有明确排除记录，没有有效样本的特征保留缺口。

这不能消除全部回调、缓存、调度或 profiler 扰动。测量资格需要真正无成本插桩的对照；仅停写记录而仍安装回调，不等于无插桩基线。不能把整个 run_batch 墙钟减设备时间当 CPU 标签，也不能在其上再加设备成本。

同线程原子片段可以在不跨外部接口时聚合，成员只保留追溯、不重复收费。不同 rank 的 CPU 工作可并行，CPU 与设备按各自提交和完成关系重叠，不直接相加各 rank 的总服务量。

### SDK 内部就绪近似

有些同步复制包含无法独立轻量观测的 SDK 等待。仅在生产端确认该机制时，可把周围 CPU 准备合为就绪区间，保留设备依赖，再单独计 driver 复制；就绪取 CPU 服务与前驱完成中较晚者。

该近似不恢复隐藏等待前后的精确 CPU 位置，可能包含轮询 CPU，必须单列适用性和局部验证。显式可观察等待不能随意合并，不能用补偿常数掩盖近似误差。

## 特征、拟合与查询

当前经验基线按完整工作键聚合独立样本，保存 `features / estimate_ns / count / range_ns`；估计使用实测中位数，偶数项结果按整数 ns 取整。共同分组拟合器直接消费样本，不另存重复特征副本和中间样本列表。

CPU、传输、通信和命令使用精确测量表；未建立的插值或外推不默认启用。更复杂模型需有相同范围的独立数据和收益依据，不能预设随机森林或增加特征就是进展。

计算工作还需区分真实操作数：

| 信息 | 保留原因 |
| --- | --- |
| 位置生成的扩展长度 | 相同总 shape 可能有不同逐请求循环量 |
| Logits 的有序行索引 | 行选择不能仅由总 token 与人数代表 |
| 请求池访问角色、槽位和列 | 相同形状可能访问不同位置 |
| 过滤输入数及有序保留索引 | 人数相同不表示选择工作相同 |
| attention 的实际 query/prefix/cache | 决定有效计算量和访问 |

尚未建立操作数合同的值依赖只保留 `value_dependencies` 种类进入 `unmodeled_operands`，不为每个 kernel 复制 KV 状态或派生值。只有生产端明确声明固定张量遍历、实现条件和唯一启动变体成立时，候选才允许省略对应值；其他情况保留合同缺口。核心不按 kernel 名写投影特例。

多个观测启动变体不能任挑或平均；唯一变体的消费也保留条件假设。候选携带来源、模型、框架、部署、测量边界、缺口和观察条件，跨环境共享需另有依据。

传输键区分 `asynchronous_device` 与 `synchronous_host_driver`，不能因为都在 CPU 文件中就合并计费。通信按可关联物理任务拟合，collective 父包络、启动错峰和等待不再叠加。

## 执行与独立评价

所有计费工作共用唯一事件引擎；节点服务、资源约束、必要依赖及端口共同决定完成时间。CPU 聚合保留对外接口；等待和注解不重复收费，时钟不回退。成本变化反馈到后续组批及工作量，不能固定 base 的完整执行序列。

显式给定耗时只用于结构条件分析，按来源 manifest/span 追溯。成本模型不读取该来源身份作为特征，也不从控制动作或模板生产对象中提取私有参数。

正式性能闭环要求范围内收费对象都有适用成本、脱离 given，并保留独立验证。验收先看工作与测量一致、CPU/设备重叠及主要局部误差，再看请求指标；整体时间接近可能来自错误相互抵消。

拟合与评价按运行/请求组隔离，同一次执行中的重复模型层不作为随机独立留出。结构来源、独立单元样本和 validation 数据用途分开；评价只读固定资产，不回写模型或规则。

独立请求比较对齐输入、稳态、调度就绪/发布端口和可关联时钟。范围外工作、控制近似、SDK 近似及观察扰动分别解释，不用端到端残差、手调倍率或固定 CPU gap 凑结果。端口无法对齐时报告不可比较，未通过资格时保留条件结果。
