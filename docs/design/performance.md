# 性能边界、采样与成本模型

性能层回答**一项明确工作在给定特征与运行条件下需要多少服务时间**。执行层依据服务时间、资源和依赖计算开始/完成，控制器消费完成事件；性能层不改变图或组批策略。

正式预测和结构验收共用原生控制、模板展开、资源状态、时间线及完成反馈。独立成本同时服务自主预测与固定图性能验证。给定统一耗时用于开发和程序测速。

## 与执行结构的交接

执行器向耗时提供者交付目标图中已有的工作区间、参数及资源条件，取得整数 ns 的自身服务时间；等待和纯边界由依赖推进，不另收服务成本。给定耗时使用显式假设，缺值即失败，不回退来源时长。假设改变后从初态重算，因为时延会改变后续组批。

成本查询使用实际目标工作的定义、自身服务区间、阶段、特征及角色和运行条件。结构模板的代表选择与成本适用性各自取得依据，同一共享模板可绑定不同成本。自主预测和固定图验证使用同一查询语义及范围，缺失时报告实际工作及不满足的条件。正常运行的到达取自 workload，具体工作时刻由依赖、资源和成本共同推进。

结构验收把目标案例中已核对的实际工作端点、可分离服务及外部时间条件绑定到本次展开。全节点资格逐项核对实际工作和必要端点的测量依据，纯逻辑边界由已验证的因果关系推进。宽观测窗口或后继推导的完成上界只能支持受影响部分的局部结论。设备时钟校准的不确定性与事件缺测分别报告。端点取得对应并不能单独证明每项自身服务已可分离。

语义区域与性能单元分别定义。一个区域可以包含多项 CPU、设备和搬运工作；重复模型层共享同一工作模型，调用次数独立。区间内部如需更细的性能单元，由提供者聚合为区间成本，不要求正式结构图恢复逐 kernel 节点。父区域只计自身服务，不能重复计入子区域或设备成本。模型规模、TP、dtype、backend 和运行环境的变化分别审查成本适用性，不因结构可变换就授予成本外推资格。

## 工作特征与计费边界

| 工作 | 需要保留 | 独立测量对象 |
| --- | --- | --- |
| CPU 自身服务 | 稳定起止切口、线程/角色、阶段、实际成员及工作量 | 相同切口的本线程 CPU 服务 |
| 设备计算 | 片段覆盖的计算与实现、shape、dtype、布局及影响算法的操作数 | 同一边界内的设备服务，内部细分与片段整体计费互斥 |
| 同步传输 | 方向、字节、两端条件及明确 driver 边界 | 排除之前依赖等待的传输服务 |
| 异步 DMA | 实际设备工作、字节及资源 | 设备服务，CPU 发起单独处理 |
| 通信 | 操作、数据量、参与者、拓扑及 transport | 实际通信服务；与内部物理任务分解互斥 |
| 提交和运行时命令 | 对应调用、参数及资源 | 主机自身工作，不包含等待期间墙钟 |

attention 的 query/context、heads 和 cache 布局是特征，整段 Decode 长度不是一个成本类型。相同 shape 也可能有不同索引、页布局、分支或内容相关工作；缺少必要操作数时保留合同缺口，不能按 kernel 名加补偿分支。

等待、事件和逻辑标记首先表达因果，真实服务与等待分别处理。执行器从前驱和资源就绪计算等待，不迁移来源的 CPU gap，也不把 `run_batch` 墙钟减设备总时间当成 CPU 标签。

## CPU 的两个问题

**路径如何变化。** 按提交、入队、worker、等待、结果处理和输出端口保留稳定作用。改变外部结构的循环和分支由模板与控制表达，封闭的内部循环只保留工作量特征；普通函数调用树和 observer 的碎片不自动变成新成本类别，不逐个原生 Python 函数建模。

**服务如何测量。** 性能观察使用结构已经确定的同名切口，取得自身 CPU 服务和必要工作量。父子嵌套只计自身部分，等待归依赖，复制另有边界。线程时钟读取及回调开销需独立校准并保留原始记录；低于分辨率或受首次编译影响的点不能成为有效标签。

校准不能消除全部 profiler、缓存、线程调度和 SDK 扰动。需要真正未安装对应观察器的对照，停写记录而仍执行回调不等于无插桩。若 SDK 把就绪等待与服务封装在不可分入口中，应明确局部近似和资格，不能用固定 gap、端到端残差或手调倍率掩盖。

## 采样的统一要求

1. **对象一致。** 性能与语义采集共享原生模型分片、backend 和底层执行，按真实工作与完整特征关联；同名、同 shape 或入口相同都不足以证明一致。
2. **适配简单。** 原生框架维护请求、KV、槽位和 worker；不为调用 ModelRunner 或 batch 入口复制状态机，也不假定每个框架都有 `bench_one_batch`。
3. **特征可构造。** 从目标需要的工作范围构造有限短请求或公共原语配方，再核对实际命中的成员、shape、context、实现和角色；发出请求不等于命中。
4. **开销有界。** 同一常驻原生会话运行多个点及重复观测，合并相同配方；初始化、预热、采样、后处理和保留量分别计账。相同配方没有新增证据时停止，不反复完整 serving 补点。

语义观察和性能观察分别控制生命周期，性能采样不要求携带重语义 profiler。两者共享必要的工作绑定和定位，不能各维护一套原生入口映射。辅助张量、传输替代和观察器工作不成为业务成本。

统一预热建立已加载、相关路径准备完成、逻辑 KV 清空的起点，保留明确允许的编译/分配缓存。新路径的首用开销仍须识别；不通过跑完整目标序列提前获取调度答案。

## 单卡 TP 与运行条件

单卡按原生角色执行目标 TP 的本地分片；请求长度不除以 TP，层、head、线性轴和通信接口由适配器解释。性能采样与结构来源必须使用相同分片底层，本地实测只授予实际发生的本地工作资格。

所有实际需求角色都必须能通过采样适配器到达，包括 TP4/TP8 的 rank 2 及以上。结构角色相符不自动证明服务时间相同；跨 rank 共享成本需要独立依据，不能复制普通角色样本或删除角色特征来掩盖缺口。

真实多 rank 通信、协调、争用和后台进度不能由单卡替代测得。逻辑 collective 的连接保持，成本需要真实通信数据；原生主机、worker、事件和布局工作与 transport 分开，不能叠加整体包络与内部任务。

同次通信采样按原生通道的入场次序匹配各参与者。先核对参与集合与完整操作序列，再对已配对的工作检查载荷、就绪和服务测量资格。调度同步与模型内部通信使用同一规则。

测量记录 CPU、设备及 runtime 条件。卡号和模型路径用于定位，不证明环境等价；缺失条件保持未知。跨硬件、角色或后端共享必须有依据，dummy 数据不授予数据相关分支的泛化能力。

## 需求、模型与样本隔离

完整性能流程应由目标工作自动产生需求，归并重复特征，查询已有候选，再把缺少的数据交给有限采样配方；不能依赖开发者逐节点查看 trace 补表。需求和实际查询使用一份工作合同，不从人读摘要反推机器需求。

动态调度下尚未展开的路径保持未确定，不能声称模板库已列出全部精确采样点。新模型发布后从初态重算；预算、已尝试配方和停止条件贯穿整个任务，不能形成无界“运行—发现缺口—补采”循环。

先建立有独立标签的简单基线，再按数据密度和误差来源选择插值、回归或其他模型，不预设随机森林或逐特征查表一定合适。模型参数来自数据与算法；禁止按 workload 标签、目标误差或手调阈值拟合。可查询、样本覆盖和精度通过分别报告。

结构来源、单元性能样本和独立目标验证分开。拟合与留出按运行或请求组隔离，同次运行的重复层不算独立样本。用于修正规则、接口或成本模型的案例转为开发用途。在观察合同、初态和实际工作仍匹配时，优先复用已有原生记录进行离线验证。

## 固定真实执行结构验证性能

1. **固定同一真实案例的执行。** 保留已发生的批次和工作、实参和角色、请求到达与初态、实际数据与资源次序、通信和状态交接。依赖来自经核对的因果与资源事实，独立并发保留。每项真实成本只取同一次工作中能分离的自身服务。轻量请求时延只能核对其已观测的输出，不能充当内部服务标签。
2. **用真实服务时长建立基线。** 用共同时间线从这些时长、依赖与明确的外部输入重算各事件。经核对的全图中无前驱的主机入口，由该入口的直接实测作为释放条件。工作之外独立量得的 CPU 活动、采集器开销及工作中可确认的抢占，作为对应资源步的固定时长，在各个替换场景中使用同一输入。实测内部完成时间和请求输出用作对照，内部等待随服务条件重算。基线在测量口径与校准误差范围内重现参考执行，才有资格将后续差距归于换入的成本。缺实测标签、资源顺序或必要外部条件时，先说明受影响范围并核对参考证据、执行合同和执行器。
3. **只替换服务时长。** 使用自主预测同一套成本及适用范围，仍沿同一张图推进资源和依赖。报告可比较工作及其带符号误差、未覆盖工作，以及首个显著偏离的完成边界和 TTFT、TPOT、吞吐误差。先看决定这些边界的依赖和资源链。对疑似误差来源，分别将一类 CPU、设备或传输工作恢复为实测，其余维持预测并重算。关键链可以切换，各组改善量可能重叠或抵消，逐项误差或各组改善量不能直接相加作为端到端误差。

固定图保留已配对的跨线程 SDK 入队至取队时长。上一条命令的取队区间已结束、或空队列的通知与下一条取队直接配对时，从同一 RAW 时钟量得交接时长，绑定实际的提交依赖。下一条命令已入队且提交线程在两次取队之间持续运行时，从前一条取队的结束边界计入独立测得的提交线程活动。排队仍由资源次序和依赖推进，这些固定条件用于同一真实案例的受控对照。

软件队列的取队标记结束、发布唤醒通知、等待线程恢复运行和设备同步是不同边界。取证按同一通知描述符核对读写及对应命令。写调用与线程切出重叠时，用同一读写线程间的内核唤醒确定交接。软件队列等待随其真实前驱推进。

固定图上的宿主工作可在实测队列等待处拆分。线程自身进度到达等待点、关联提交线程完成通知交接这两个条件共同决定恢复时刻，恢复后继续剩余服务。各替换场景共用这次实测的自身服务分段比例，原有工作端点用于独立核对。已单独标记的采集和输入注入区间按其实测完整时长保留为同一固定参考的外部条件。区间内可识别的抢占只计一次，自主预测的服务标签仅计实际工作。

采集器在设备流补记的入口和返回标记可以见证语义端口。经原始记录核对，标记未被原生代码读取，也没有承担计费区间边界或真实信号时，端口以必要前驱的原始时间约束判定就绪，标记提供原始上界。基线出现偏差时，另用各端点的实测前驱上界和已测服务求仍无法解释的局部等待下界，定位独立缺口及其后续传播。

宿主同步保留原生调用的入口和返回。线程全程运行且设备前驱在 SDK 实际进入同步操作前已就绪时，按 SDK 入口分开计量调用准备和就绪后的处理。固定图让设备就绪与 CPU 准备共同触发后半段。设备派发与载荷服务用同一份独立校时，从实测驱动提交、前一项设备工作完成和当前设备任务启动取证。重算时先满足提交和流次序，再计实测派发时长。前一项工作未进入参考图时，需要原始记录证明它已在提交前完成。

自主闭环使用同一正式成本，由原生控制根据模拟完成事件生成实际组批。固定图基线成立后，可把自主运行与固定图结果合看。如果固定图时序接近实测而自主误差较大，沿请求进度和因果位置找首个动作、读取或状态分歧，判断它是成本进入反馈后的放大，还是输入、结构或资源语义差异。单纯数值接近也要保留覆盖结论。

两条性能评价均按统一起点、同一请求与可关联时钟对齐，按实际观察范围区分 `ResultProcessed` 和 `RequestOutput`。缺失端口和零分母分别报告。正式自主预测的留出评分要求 TTFT、TPOT 的 MAPE 分别低于 6%，启动前固定统计粒度和排除项。固定图工作流的正确性由基线与可定位的误差证据验收，模型达标由独立评分验收。
