# 成本、迁移与独立性能数据

日期：2026-10-27。本文规定新实现的边界，模型具体形式以实际数据和机制决定；不表示现有精度已迁移。

## 语义区域的独立响应

sglang_regions 对独立 eager 请求采集输入准备与 batch 的线程 CPU、caller 返回、current-stream 区间，
另采结果线程 CPU；分别覆盖 Prefill/Decode，按实测终止 phase 导出发送前/后的 CPU，不预定模型数量。
输入准备与 batch 各自的 CPU、caller 返回从同一入口推进、取实际汇合，不串行相加；流有自己的资源和就绪端口。
batch 的 stream 区间从 worker forward 开始，包含后续 token 中继和 CPU copy 入队，不再另加一份 forward 设备成本。
流区间仍含主机发射不足和内部通信，不是裸设备服务；它从本 rank 的调用和输入端口开始，而非所有 rank 的最晚入口。
其他 rank 的必要到齐在结果消费端表达，不把同一段已测内部等待再作为整段响应的前置屏障。
调度器每轮的 CPU 请求广播由输入准备前的控制依赖表达；来源控制残余仍可能混有等待，从本地控制入口计量，与到齐重叠。
结果调用按 CPU 顺序取得调用权，在等待对应输出时持有线程；实际服务同时等待输出和本地控制区间，再付线程 CPU。
必要的下一帧提交约束调用顺序；最终发送与尾部由同一观察划分，不重复收费。
结果响应按实际 HiRadixCache/RadixCache 实现区分，不能只按相同框架名复用。

变量为 q=query_tokens、c=context_tokens、A=q×(2c−q+1)/2、batch、page、首次 phase 标记 P、
新准备规格数 N，以及本帧完成请求数 F。Prefill 准备为 T=a+bq+dA+eP+fN，batch 不含 N；
Decode 准备与 batch 为 T=a+dA+eP。结果整理为 Prefill 的 a+bq+dA+fF、Decode 的 a+dA+fF；
最终发送和尾部分别按 A 建模，不复用初始化项。
这些是小范围加性响应，系数由独立工作点中位数的非负最小二乘取得，共用缩放 QR，不手调倍率或钳制负预测。
各页大小下独立估计这些系数，合为一条系数曲线；一个页大小锚点仅支持该大小，相邻锚点之间插值。
部署、batch、页大小和特征范围单独限制覆盖；未作回归变量不意味着可以任意跨域。

N 使用输入执行配方中的有类型规格，按 caller 保留已准备集合，不再把每个新长度都当成新编译。
当前独立观察记录融合页分配的 batch 上界、页大小、extend 长度二次幂上界和 free-pages 指针对齐；
首次 phase 的准备由 P 覆盖，同次不再加 N。测量只取主机元数据，不读回设备内容或新增同步。
这仍不是完整编译状态测量：其他首次加载聚合在 P，未覆盖的内核、缓存失效和准备重叠须保留限制。
不能靠逐长度系数或 target 残差补齐这些事实。

HiCache 批量备份另用 caller 返回、完成观测及主机索引 clone 响应：caller 后接 clone，完成观测与 caller 并行推进，
全部参与者的两种端口汇合后发布；不把三者简单相加，不再添加裸 DMA。
后台备份取得共用 caller 调用权，caller 返回后释放；回载/写回淘汰保留准入调用权直到可继续。
当前 I/O 数据限定已初始化、空闲、单设备任务，完成区间含观察开销；竞争与逐层进度另列，回载不能借备份模型顶替。

回载使用自己的三项响应：load_back 的索引拼接、设备槽分配与设备索引克隆构成准备；
start_loading 的 caller 返回与完成观测从同一入口并行推进。准备按实际页数和 radix 段数，传输按页数建模，页字节数限定系数曲线。
独立采样先备好主机页，再清空设备值，回载后核对完整 K/V；预热、输入重置和结果核对均在计时外。
备份的主机索引 clone 不用于回载。剩余容量已可用、已有设备祖先前缀可读时，输入准备由各 rank 的加载发起返回端口推进，
不等待整批回载完成；GPU Prefill 仍等待全部层完成，是保守的整批数据屏障。需要回收容量或还在等待其他前缀时保留等待路径。
没有获得逐层复制/计算重叠的资格，也未细分加载首次使用和树控制 CPU，不能把完成观测当成裸 DMA。

回载两次分配失败后，框架会释放本次主机保护，沿用已有设备前缀并重新计算；这不是整个请求容量不足。
此前实际发生的备份仍保留，重新计算按完整剩余 tokens 生成工作。失败尝试不借成功传输成本：
独立小负载运行原生 init_load_back，记录线程 CPU，扣除成功子备份及其完成检查的线程 CPU；这些子工作由自己的节点计费。
剩余失败控制用非负的 a+b×pages+c×segments 表示，页大小分曲线，系数由独立点取得。
采样用两个页数和一/二段前缀构造有限容量回访，一次启动覆盖整组，不使用 target trace、HTTP 或预测残差。
阈值/配额直接跳过不是这种失败路径。曲线没有将成功子备份数量视为已验证的外推轴，部分备份时的排他 CPU 响应仍有不确定性。
profile 中的失败响应可以用于固定路径成本替换，但不用于正常成本训练或认证正常 CPU 精度。

### 文件 worker 的独立响应

文件读取使用原生 _generic_page_get，分为整批分配及循环开销、逐页 buffered read、逐页复制并发布、返回尾部。
原生实现先读完一个 batch，再逐页复制；取消发生后已经开始的读取仍须到达停止点，不能只按最终接受页数收费。
写入使用原生 _generic_page_set，整批材料化和 batch 循环开销均计费；每页再按真实状态选择新建写入或已存在键的检查/触碰。
已有键也有成本，不能跳过整批材料化或把原生 set 当作零时间。读写父包络仅用于核对区间总量，不再叠加计费。

上述八类响应共用页数 pages 和单页字节数 page_bytes：整批部分采用非负的 a+b×pages，逐页部分采用实测典型值；
不同 page_bytes 的系数按已有曲线合同选择，一个字节锚点只支持该锚点。系数来自独立重复采样，不使用 target 命中率、耗时或残差。
采样在同一原生控制器准备真实 K/V，写入新页、重写已有页，再清空目的缓冲并读回核对；初始化和数值核对在计时外。
临时页文件由采样会话持有并删除，轻量计时和预热标记进入既有性能库，不加载模型权重或采集 profiler。

该模型描述暖文件缓存下的 buffered API 响应，含轻量记录和观察开销；不代表 fsync、冷介质或 CPU/I/O 竞争。
文件查询、请求准入和轮询并未被这些 worker 成本覆盖。它们由请求执行规则和对应的控制成本表达，
不能放大文件读写系数来补齐。入队与准入检查已经分开，预取可与首轮准入前的控制残余重叠；
后者从首轮准备阶段移到请求控制阶段，只支付一次，仍是 source 残余近似。
后续进度检查由调度回合推进，不随每次 I/O 事件立即唤醒；超时只在检查时判断，预算中的命中页数在查询完成后才可见。
已观察的发起和最终检查包络由独立控制响应替代，其他未解释控制仍保留 source 残余；best_effort/timeout 的完整控制精度尚未取得资格。

### 后台预取查询

`cache.prefetch.query` 是整组后台查询从可执行入队到各 rank 完成命中数量归约的响应，不是排他 CPU 时间。
共同的 FIFO 查询 lane 与读写 worker 分开；查询阶段按文件状态确定命中前缀，再生成读取或撤销。
取消不跳过已排队查询；即使请求已经继续计算，后台仍持有尚未归还的主机缓冲。

变量为实际哈希页数 H、文件存在性检查页数 E，采用非负 `a+b×H+c×E`，page_tokens 分曲线，参与者数量限定适用域。
H 按原生批大小计入首次缺页所在批的全部哈希，E 包含首次失败的检查；多 rank 取各自工作量的最大值。
独立小负载在同一真实推理进程中交替回访两个前缀，固定使用六/七页、各四个请求，复用页文件；不随 base 大小扩大采样。
首请求预热，实际可查询长度受主机剩余容量限制；超出观测页数标为外推，不使用 target trace 或 HTTP 残差。
计时保留线程唤醒、哈希、元数据查询和 MIN 归约，从本次可执行起点扣除前序查询积压，参数由独立观测拟合。
只覆盖暖本地文件元数据、串行请求；单组 lane 近似 rank 返回偏差，查询期间并发改变文件的情况尚未认证。
外推页数明确报告，冷介质、繁忙服务及其他存储后端不由该响应覆盖。

### 前台预取控制

三段闭合响应共用 `controller_group_response`：从所有 rank 均已进入到最后返回，保留 caller 调用权，不代表排他 CPU。
`cache.prefetch.issue` 支付主机申请、必要树操作和原生发起；返回后查询才可入队。采用非负 `a+b×candidate_pages+c×allocated_pages`。
候选页数由实际剩余输入决定，实际分配页数由主机容量决定；跳过也有观测到的调用成本，不能按零处理。

`cache.prefetch.check` 只表示最终返回 ready 的一次检查中、停止之前的部分；无在途操作时就是整个短调用。
形式为非负 `a+b×operation_present+c×state_reductions`，后两者分别为是否存在操作、是否执行状态归约，均由规则取 0/1。
此前返回 pending 的检查已经包含在独立空闲回合中，不再计一次相同成本。
检查执行期间后台可以继续发布；结束后才固定各 rank 的完成前缀并停止继续发布。

`cache.prefetch.accept` 从停止到主机树更新及返回，采用非负 `a+b×pages`；pages 为各 rank 停止快照的最大本地完成页数。
缓存可见前缀仍取所有 rank 的共同部分，和该成本变量分开。停止后的已开始读取/复制继续到原生返回点，不能提前释放缓冲。
接受完成后才允许回载/重新计算准入，三段都在同一执行时钟推进。
当前停止时间取原生控制器终止调用入口；内部锁内推进及 rank 间微小偏差仍属于近似。

固定的六/七页小负载分别运行 wait_complete 与 best_effort，整组共享；独立记录按实际端口导入，查询数据也可在同次启动取得。
系数由独立观测拟合，64-token 等页几何分曲线，不读取 target trace 或 HTTP 残差。
仅在迁移成本中剥离 source 已观察的发起、完整等待回合和最终 ready 调用，原始 DAG 不改；未知外围、树规模及竞争不被吸收入这些系数。
整组响应近似 rank 内部偏差和局部/共同页数关系，复杂树、冷状态和竞争仍需额外资格；轻量观察开销也未被认证为零。

### 等待预取时的调度回合

`scheduler.idle_turn` 表示一次未完成检查开始，到下次检查开始的原生空闲循环响应。
每个参与者从自己的 caller 入口推进，保留 CPU 广播、调度工作和内部 peer 等待；所有参与者返回后才进入下一次检查。
caller 在响应期间持有调用权，较早的结果或备份调用可在两个回合之间取得 CPU；后台页读、发布和 deadline 只更新状态。
这是一项闭合响应，不宣称等于线程 CPU 自身服务，也不细分为每个 Python 函数的模型。

变量只有参与者数，约束在声明的部署和文件后端；系数是一组独立有效观察的中位数，模型为常数响应，不从 target 残差拟合。
补采使用少量交替前缀触发真实文件回访，关闭 profiler、snapshot 和原生 hook，仅保留无活动 batch 时的连续检查区间。
观察先缓存在内存中，得到 batch 后才写盘，每进程最多保存 128 个可选样本；它限制观测量，不裁剪原生执行或预测图。
`sglang_scheduler` 只训练这一类响应，不改动同次运行记录的 Prefill/Decode 模型；一组 target 共用这份数据。
采样完成后清理该任务自己生成的临时文件缓存，元数据保留删除前的字节数，原始轻量观察和预算记录仍保留。

当前只描述串行请求、原生空闲回合；忙碌服务、不同线程争用和初始化仍有不确定性，轻量时钟开销没有被当成可学习的设备服务。
零倍率若使整个轮询回合不推进时钟，明确拒绝该仿真假设，不能在同一时间戳无限生成新回合。

校准不导出 profiler trace，原始轻量观察、预热标记、选定训练来源和适用范围进入同一个 SQLite 维护流程。
不同计时口径不增加独立实验次数；同一工作点的多 worker 观测也不代表跨部署泛化。
原生端口诊断与采样能力仍保留，需要细化时再使用，不作为区域成本查询的强制前提。

正式区域预测另沿用源父区域之间的 control residual，扣除明确标识的采集开销和已有目标替代的控制区间；无法解释的工作和等待仍保留。
可替代的来源控制包括实际接受前的失败检查循环、成功的回载准备和加载发起。
区间由原生调用边界及实际返回值确定，在同一 CPU 资源上取并集后裁入残余，不按耗时阈值切分，也不修改原始 DAG 的观测成本。
没有成功接受的查询/撤销及未观察到的调用仍保留；缺少边界的旧来源不能据此获得跨策略资格。
父区域内部的等待改由目标端口表达，父墙钟不重复迁移。残余只推迟就绪，不占 CPU 服务资源；
这和下述原生诊断的逐调用校正不同，不能把未识别开销或目标控制变化视为已建模。

同 TP 的空请求广播工作不变时，base 记录各 rank 的实际调用边界及其关联 batch。
来源分为调用前、所有参与者进入后到本 rank 返回、调用后三段；目标先完成各自前置控制，再到齐并沿用后两段响应。
其中 `response_r_ns = returned_r_ns - max(entered_*_ns)`，变量均来自同一份 base 的同轮调用，没有训练系数。
这避免迁移来源已有的跨 rank 等待，无需另加成本系数或校准。它沿用的是同步响应，不能视为独占 CPU 服务；
调用内部准备与通信重叠的分布仍有近似，不覆盖不同 TP、非空消息或不同广播实现。没有相应边界时继续保留完整来源残余。
没有所有参与者共同处于调用中的区间时不作这种分段；当前真实验证范围为本机 TP2，不据此授予其他通信拓扑资格。

## KTransformers 的同步阶段响应

dense/Torch 后端把一次 Prefill 或 Decode 的 forward、可选的贪心 token 选择和完成观察作为一个封闭响应。
它只适用于显式同步执行；不能将这些耗时当作裸 NPU 服务，也不能套到有通信、CPU offload 或计算重叠的执行中。
注意力后端、是否输出 token、CPU 线程数进入实现身份，部署由共同数据合同限定；不按长度或实验格子建立模型。

变量为本步 query_tokens=q、context_tokens=c、attention_pairs=q×(2c−q+1)/2，以及首次阶段标记 P。
Prefill 使用 T=a+bq+dA+eP，Decode 使用 T=a+dA+eP；系数由显式选择的独立数据做非负拟合，未使用的项可以为零。
P 只描述该采样器观察到的首次 Prefill/Decode，不是完整的编译或缓存状态模型。
不输出 token 的中间块是不同的工作分支，没有相应数据时保持缺口；不能拿输出分支的响应直接代替。
数据进入同一 SQLite 和离线导出，保留预热/首次条件、测点及覆盖范围；域外查询返回缺失，不在预测期间拟合。
目标阶段由输入长度、固定输出数和分块配置生成，不查询 base 中是否存在同名阶段。
不同阶段按实际同步顺序进入共同执行器；独立模型不参与阶段数量和依赖的确定。

生成控制另外计量：从完整 generate 墙钟中扣除全部互不重叠的同步阶段，得到 KV 初始化、输入张量构造、
循环与结果整理的独占区间。它使用 input_tokens、prefill_steps、decode_steps 和 first_request 做非负仿射响应，
不重复收费 forward 或设备等待。记录的序列化和写盘在 HTTP 发布之后进行，轻量时钟与列表记录仍有开销。
实现条件包含 attention 后端与 CPU 线程数；数据库保留独立采集来源及覆盖范围。

当前同步入口没有阶段外的中间消费者，控制余量可合成一个前置节点，保持完整请求总和；
这不适用于异步服务、共享 KV、CPU offload 或含中间发布的执行，扩展这些行为时需增加真实端口。
HTTP 传输及 generate 外的 handler 区间沿用 source 残余，并标明 profiler、前端排队和配置变化的不确定性。
整组缺少响应时共用有限长度/输出组合采样；相同实现的分块与非分块数据参与同一模型，不按 target 身份拟合。

## 两种成本来源

**base 迁移：** 对应工作的部署、实现、shape、执行方式与必要条件已证明不变，沿用该操作的有效服务成本。
源队列等待不能作为服务迁移；未解释的源 residual gap 单独保留并标为近似，不能说已经预测了 target 的等待。

客户端入口、响应尾部和跨请求间隔直接引用所选 source 的请求及接收/发送端口，不为这些延迟先构造细图；执行时只推迟就绪，不占 CPU 服务资源。
跨请求间隔是下一请求开始减上一响应完成，只在两请求之间计费；首个正式请求前的间隔不进入正式窗口。
它保留客户端 JSON 处理、记账、写盘及未解释的停顿，假设客户端和请求序列不变，不称为稳定 CPU 服务模型。
若来源含显式后台屏障，其间隔可能混有等待，仍标为残余近似；目标 drain 与该间隔并行等待，不能重复串行累计。
当前仅假设同一请求的传输工作与前端部署保持不变；来源中混合的传输、调度和处理时间仍是残余近似。
显式生成 caller 准入等待后，来源入口中未拆开的排队时间可能重复保留；该近似须公开，不授予正常 HTTP 成本资格。
请求大小、流式响应或前端部署变化时不能据此授予外推资格。串行请求依赖前一响应；后台 I/O 清空是另一项依赖，不能用程序最终结束代替响应时刻。

### 按需原生诊断中的成本迁移

计算 probe 的 CPU 包络只用于定位提交，不作为设备成本。源设备服务沿原生提交关系绑定到独占设备区间，保留原图节点、资源与记录位置；
同一 probe 内的多个原语、重叠归属或无法匹配的设备端口不猜分配。结构侧给出的工作未变标记只是迁移依据之一，仍须核对实现、资源与依赖条件。
能够找到父调用的设备区间，不表示能将其整体作为某个子操作的成本。例如注意力调用还会写 K/V，必须按实际操作分别绑定，或保留为未能拆分的来源；不能把整段设备服务当作 score。

目标工作可携带原始操作引用，不能携带规划阶段自行算出的耗时。当前未变的单设备工作沿用已经证明的原生调用及资源顺序；
成本查询再核对完整工作描述、独占归属与目标资源，按源节点求和一次。缺少独占服务依据时仍查独立模型，不猜父包络。
迁移结果按原始操作身份缓存，不能仅按 shape 合并不同参与者的实测值；变化工作则按完整工作点复用独立响应。
这只支持原部署和资源放置下的设备服务迁移，假设该服务对新的排队位置保持稳定，不代表已验证设备竞争、频率变化或 CPU 校正。

CPU 调用区间也只在原始图的独占划分上求交，分开保留观察到的服务、等待、空白、已标识采集开销及未覆盖时间。
这些只读视图在来源准备时建立一次，不重复解析 trace，也不把父包络和子调用相加；元数据、分配等准备序列的 CPU 区间单独保留。
缓存索引值的初始复制属于元数据工作：元素数按目标页大小对齐，来源/目标元素类型与一维布局限定实现，不能与 KV 内容传输混为同一操作。
其分配使用独立 ATen 响应，从原生 CPU 包装中扣除；普通 caller/worker 和设备各自判断是否同工。空释放在返回前不访问页几何和空闲数组，可复用同 caller 的空分支成本；非空释放根据实际索引数另生成工作。
前缀匹配的索引拼接描述元素总数、输入张量段数、类型和布局；页表回写描述受保护前缀以外的元素数及转换类型。来源未观察到段数时不能证明拼接同工，相应成本需独立数据支持，不能由时间包络或源页数猜出。
释放索引读回、CPU 除法/去重及回传合为一个无中间消费者的同步响应，变量是索引数、不同页数和类型。它等待实际队列，两个同步 API 的就绪服务单独计费，不迁移源阻塞时长；剩余主机响应仍是未校正估计。内部前置 CPU 与设备的细小重叠没有逐段展开，不能将这一粗粒度近似用于有中间消费者的路径。最后的空闲页索引拼接另按现有页池长度与归还页数查询，范围不足时明确停止。
这类封闭主机响应与标量读回分别表达。标量读回仍保留等待之前的 CPU、就绪同步和返回数据成本；不能因引入整体转换而丢掉已有返回段。分配工作在每轮实际输入时绑定页池视图，准入预留不会提前改变其指针偏移或内核规格。
该视图仍是带采集的观测，已标识开销为零不代表没有 probe/profiler 开销；未完成校正前不能直接称为正常 CPU 服务，等待也不能当作服务迁移。

同源校正作为显式选择的独立输入，声明 source_manifest、basis、sources 与 intervals；区间记录资源身份、原始 begin_ns/end_ns 和估计 cost_ns。
加载时核对来源并拒绝重叠区间，逐条读取，不保留一份完整 JSON 记录树。成本按原坐标求交，分割使用累计值相减，避免多次取整破坏总量。
覆盖部分的估计值与未覆盖的原始值分开保留；已识别的等待及采集开销不套用该校正，原始图及回放不变。

从轻量配对采集中扣去 CPU 差额，再分摊到原区间，得到的是带假设的校正值，并非每个操作的独立 CPU 服务测量。
原图标作服务的区间仍可能含未识别等待，不能仅凭“已校正”授予迁移资格。
当前诊断在各请求的计算 caller 上，将已解释调用、各类准备序列、通信包络及其外部区间独占划分，另列正式请求；不相加父子包络，也不包含 worker、设备或其他线程。
结果处理另按缓存控制及最终发送边界划为独占片段；嵌套控制归最内层，原包络仅供守恒比较，不再次收费。
source 报告的 result_processing_cpu 保留服务、等待、残余、已识别采集开销和原生提交归属，同时给出处理前最近的同 caller 批次提交。
这仍是未经校正的来源观察；片段内存在原生提交时，必须生成其工作和资源交接，不能整体迁移成固定 CPU 服务。
不含原生提交的结果 caller 与发送片段可按相同批次规模、输出数量、结束状态和 caller 配方沿用源 CPU 估计，缓存/释放包络另行处理。
目标先等待对应输出事件，再支付就绪同步 API 及 caller 自身工作；event 等待与 stream 等待分别识别，不复制阻塞时长。
就绪 API 可引用同一 base、同 caller 中生产者已在入口前完成的同 API 观察，单列为未校正控制估计；没有合格样本或独立模型时仍报告缺成本。
这用于核对覆盖和后续成本归属，不直接替代目标程序已有的计费操作；正式迁移还须证明工作不变，并排除重复收费。

已知计算帧的调用顺序在来源中解释一次，包括计算、准备和通信。相邻调用间只保留独占间隔，不包含调用包络或帧前后的请求控制。
目标结构携带来源区间引用，成本层按原始图求交：服务与空白的已覆盖部分使用校正值，其余保留原始值；这些仍统一标作来源 CPU 残余近似，不能称为正常服务迁移。
近似限定同 caller、同顺序配方，未预测 host 工作随 shape 变化的部分或未知等待。它只推迟 caller 后继就绪，worker 和设备可以继续运行；不独占 CPU 服务资源。
已识别的采集开销排除，区间含尚未生成的原生提交、尚未生成依赖的已知等待或来源未覆盖时停止绑定，不能复制等待时间或静默删去。原始图与静态回放不变。

输入原生调用的 CPU 部分可以引用同一 base 内的工作估计。caller 先核对有序调用配方，再按各片段的工作量和原线程匹配；同一配方中其他片段变化，不自动否定这个片段。
worker 按自己的提交工作与资源匹配，设备仍须独立核对完整设备工作。适配器可显式声明 worker 的工作变量，不能直接把 GPU 处理的 token 数当作 CPU 提交量。
来源区间由入队、外层调用返回、后台执行和设备提交端口限定。上传 API 的完整区间已单独计费，worker 只取其两侧；caller 的 stream 同步等待由生成的依赖承担，再支付独立的就绪同步服务。
已知的其他等待或未覆盖区间不能迁移。服务与残余分别使用 CPU 校正，未覆盖校正的部分保留原值，响应标为 same_work_cpu_estimate；它不是逐操作正常服务真值，未知等待和采集开销仍可能影响估计。

首次调用的编译、加载包络没有边界时，不把它当作普通前段。已观察到相同声明规格先前提交后，后续调用可提供准备完成后的前段；其配方、工作量和 caller 也相同时，可以供本次首次调用使用，编译与加载仍由目标自己的状态另计。
该推断限定进程内规格缓存不失效的执行范围；支持中途清空或更复杂的规格条件前，需要补充相应来源事实。源排队等待和 ready 后的派发间隔不包含在这些 CPU 工作估计中。

输入派发另取入队端口与前一个 worker 返回均已满足后，到本次 worker 开始之间的源区间；前一个 worker 仍忙的部分不迁移，目标排队由依赖产生。
该区间只在完整工作配方与原资源相同时作为来源派发残余近似，不占 CPU 服务资源。它仍混有操作系统调度、发布及采集影响，不是正常环境下已校准的派发服务。

设备事件的观测必须由实际命令及其关联 ID 证明。record 可引用源标记区间，wait 只引用生产者在其开始前已完成的区间；目标 wait 仍依赖目标自己的生产者，不复制源阻塞时长。
导出标记中的零时长也保留原记录及依赖，不将其解释为精确硬件开销。其他输入设备工作只有在原生提交唯一指向完整独占服务、工作与资源未变时才能迁移。
多任务配方逐次绑定发射前 CPU 和设备服务，整个回调只收一次返回成本；原生发射 API 的入口提供 CPU 分段依据，不能把父包络分配给每个子任务。

CANN 回调的启动增量来自独立正常运行：同一新进程的首次回调响应减去稳定回调的中位响应，再跨独立进程取中位值。
计时包住同步执行的 ACLNN host 回调，设备同步、输入构造和 workspace 准备在计时外；它是 worker 被占用的响应增量，不宣称等于自身 CPU 指令时间。
有加载或符号解析的源回调不提供普通 worker 片段，普通主体引用 base 内工作相同的无加载回调，启动增量另计，避免双算。
适用域保留完整操作、dtype、索引、表几何及初始化上下文；只测过的固定几何不自动外推。当前封闭输入回调将启动增量集中到主体之前，内部启动与设备工作的重叠有近似；出现外部中间消费者或共享资源交错时须细化端口。
独立 SDK 采样目标在[原生采样目录](../../src/markov/adapters/ascend/sampling/CMakeLists.txt)构建，不进入纯 modeling 链接。
采样接收设备、表行列、稳定重复数和新的 CSV 路径，记录首次与后续回调的墙钟及线程 CPU 时间，并在计时外同步和核对全部写入结果；不加载模型、base 或 target trace。

**独立预测：** 变化或新增工作使用独立数据库和离线训练的成本模型。当前 base 不自动入库或在线拟合，
target 正常时间、trace、评分、配置名和 workload 身份不能作为参数或补偿依据。
合法零成本必须有语义或测量依据，缺数据不能填零，也不能据此删除工作。

查询和结果更新可复用相同索引操作的物理描述，但 CPU 来源仍受各自 caller 配方约束。
旧查询没有克隆尺寸或拼接段数观察时，不能仅凭 trace 中出现 clone/cat 推断完整工作并迁移成本；目标树已知的分裂工作仍须生成，再由独立响应承担。

主机上没有外部中间消费者的真实 API 可用一项 `caller_blocking_interval` 表示完整响应，保留正常测量条件，不能再加一份同 API 返回或来源父包络。该口径不宣称等于 CPU 自身服务。
主机 int64 索引克隆采用这类独立响应，变量为元素数，元素类型及 rank 限定适用域；不要求它来自当前 base，也不因所在缓存操作不同重复建模。

独立 HiCache 控制测量入口为 `python -m markov.adapters.sglang.cache_io --recipe … --output …`，在兼容 NPU 推理环境运行。
配方声明 device、geometry（layers/kv_heads/head_dim）、warmup、repeats，以及包含 page_tokens/pages 的 cases；
operations 可选择 backup、load 或两者，默认 backup；case 的可选 segments 默认为 1，表示回载索引分段数。
目前使用 BF16、kernel_ascend/page_first_direct，实际框架管理页池和复制。
测量不加载权重、不启用 profiler/probe，不读取 target；初始化、清空及物理 K/V 核对在计时外，预热记录保留。输出索引读回、controller 返回、完成同步返回、空闲同步与主机索引克隆响应。
完成同步返回包含观察 API，是设备完成的观测上界；模型对该区间的估计不保证仍为严格上界，不能直接替代裸设备服务或独占资源时间。范围目前限初始化后的空闲单设备、就绪页池，不授予并发竞争、CPU/NUMA 绑定或正常完整 HTTP 精度资格。

结果控制点和写回淘汰的备份分别查询 `cache.backup.caller` 的 `caller_blocking_interval` 与 `cache.backup.completion` 的 `completion_observation_upper_interval`。两项都从同一主机调用入口起计：前者占 caller，后者在独立备份队列上表示粗粒度完成，不能再叠加裸 DMA。随后单独计主机索引克隆，发布等待各参与者的返回和完成端口。内部 CPU 准备与 DMA 的重叠被封闭在响应里；共享资源交错尚未细化，淘汰选择、同步 API 就绪服务、ACK 和页池归还的外围控制仍缺。
每项响应采用固定项加页数乘每页系数，系数按已测 page_bytes 插值；layers 和 bytes_per_token 限定几何。模型声明允许页数外推时保留其外推身份，不把外推工作量当作新实测。参数来自独立正常控制器运行，留出采集不参加重拟合；主机克隆使用自己的元素数响应，不按 target 增加专用参数。

## 一项工作怎样查询

结构侧给出操作、真实实现、计时口径与必要工作变量。部署条件限定模型适用域。
计时口径分别表达 CPU 服务、worker 服务、设备服务、传输服务和有依据的残余区间，不能互相替代。
变量可以是 query/context tokens、M/N/K、dtype、布局、字节数、页数、层数、参与者和必要运行条件。
只用于限定覆盖的变量与进入公式的变量分别声明；同名 kernel、相同元素数或相同字节数都不保证工作等价。

模型返回耗时、来源、范围状态及近似说明，不创建节点、选择缓存策略或推进时钟。
内部相对时间及成本使用整数 ns；原始 trace 坐标、旧 us 测量和对外秒数在边界转换，保留原测量单位。
模型可声明 limitations，说明测量或独立验证中已知的限制。查询报告保留这些说明；可返回耗时只表示工作域和公式可用，不表示独立精度已经达标。

当前独立查询核心接收有类型的工作描述：操作、实现、计时口径及数值特征。选定模型按前三项建立唯一索引，
基础成本形式为常数项加各特征与系数的乘积；系数为空即为常数模型。常数项和系数统一使用 ns。
响应也可是一条系数曲线：例如不同页大小下，分别维护传输准备成本和每字节成本，再在相邻测点间线性插值。
曲线坐标必须落在已声明的测点区间内，不在区间外沿用端点；一个锚点只支持该坐标。
测点之间的插值属于模型假设，不是新增实测。
同一操作仍只有一个选定模型，不按每个页大小创建一个模型，也不让结构规则读取这些系数。
JSON 在外围装配层读取一次，图核心与成本核心不读取数据库、原生 trace 或评价结果。

独立张量校准分开采正常 C++ API/线程 CPU 与 profiler 端口。两者通过同次进程的真实线程、案例和物理工作关联，
复用 base 的原生队列及独占区间解释，不借目标 trace 补边界。正常计时减去空计时对照；worker 用量减去空同步窗口的典型线程 CPU，可能包含队列管理。
caller 总 CPU 与 wall 差额分开，caller、worker 各自按独立 profiler 的服务比例分到提交前后、发射与返回；形成训练记录时，各分段之和保持对应案例的正常 CPU 中位估计；分段仍不是正常端口实测。
dispatch 及显式 worker residual 保留独立 profiled 观察，正常线程调度空白和观察造成的比例偏差仍不确定。数据库 quantity 明示 estimate，保留两遍原始观察；不能将这些端口估计称为正常实测事实。

小型已测范围的 CPU 采用典型响应，cat 以输入段数区分；元素数只限定覆盖，不强拟合 CPU 的长度斜率。
设备仍用元素数的线性响应。离线维护因此支持 feature 为空的典型响应，以及按 curve 分组的典型值；coverage_features 仅参与范围检查，不作为系数。
HiCache 只从目标索引状态生成通用 runtime clone/cat 工作，成本库不绑定缓存配置或 base 身份。
这些响应覆盖原生 API，不能替代尚未生成和定价的查询/准入、树管理、通信等框架外围 CPU；也没有完成当前 base 的全局 CPU 开销校正。

文件后端的整体测量需要与执行边界对应。当前用已有键写入测量估计整批整理和元数据，用新键总响应的差额估计新增文件服务：
若已有键为 `a_e + b_e × bytes`、新键为 `a_n + b_n × bytes`，则先支付已有键响应，
再为含新键的批次支付 `a_n − a_e`，每个新页支付 `(b_n − b_e) × page_bytes`。
同质新键批次的总公式因而保持不变，但可以按原生顺序逐页发布；已有键跳过落盘仍需先整理数据。
这些阶段时长是根据整体测量推得，并非各阶段都已单独测量。混合批次、元数据所在位置和中途可见时间仍有近似，不应据总和一致声称阶段精度已通过。

预取的读前响应也保留原系数：页数项近似集中在准备阶段，字节项按实际读页推进，随后单独支付页复制/发布与返回响应。
这保持既有整体响应，同时允许停止后仍完成在途读取及一次被拒绝发布的复制；阶段拆分的不确定性与查询/准入 CPU 缺口单独报告。
从独立 DMA 的两个载荷档位估计启动项和每字节项，可以补充缺少的页几何；只扩大有数据依据的页档位，不改其他档位来追目标误差。

通信响应的计时边界必须与样本一致。当前 `collective_completion_interval` 表示最后一个输入就绪到参与组最晚完成的时间；
仿真先等待各输入到齐，再查询这段剩余服务。到齐前的等待不重复收费，也不能从模型返回值再减一次到达偏斜。
`arrival_span_us` 使用样本相同的整数微秒坐标：最晚到达的微秒坐标减最早到达的微秒坐标；字节量、成员数和布局另行限定工作域。
一个参与组调用只绑定一项服务，不能按成员数重复收费。该口径没有分别预测各成员的完成时间，也没有描述到齐前网络资源的占用与干扰；相应近似须随执行结果保留。

原生异步调用分开查询 caller 提交/返回、worker 逐次发射/返回和设备服务；派发延迟的起点是提交与前一后台任务均已完成，
不能从提交起算后再用 worker 排队覆盖掉这段延迟。框架准备代码不能与子调用包络重复收费。
没有对外端口的连续参数准备，归入下一次调用的 caller 前段；整段入口归入第一次调用，尾部归入最后一次返回。
输入准备按这个口径描述 caller 工作，单独保留序列入口、出口；尚未分解的 forward 入口保留框架长度上下文。页表入口按请求数构造指针数组，长度循环留在设备；批次标量上传只描述批次大小与实际元素数，token 上传和位置数组分配仍保留变化的元素数。
Triton 的运行时长度从设备张量读取时，worker 描述 grid 和 constexpr 参数，设备描述实际循环工作量；位置数组分配留在 caller，不能因发射工作不变就一起沿用。
有独立产出、等待或资源交错的 CPU 工作仍须单列。编译与加载依旧单独计费，caller 前后段的测量必须排除这些区间。
变长数组不意味着整个 caller 都按 token 数增长。对于已解释的 ATen 分配，结构单独声明 API、字节数、整数元素类型和 tensor rank；来源中匹配完整分配区间，从普通 CPU 前段扣除。剩余片段才按不变工作迁移，分配由独立响应计费，父包络与子 API 不相加。

分配响应在对应推理环境的 ATen C++ API 内测量，Python 仅初始化 runtime、声明案例和接收 CSV；张量析构及元数据核对在计时外。原始预热与空计时器对照保留，稳态估计扣除对照的典型开销。当前小型连续整数向量使用每 API 的典型固定响应，字节数限定覆盖，不强制引入线性 token 系数。它是就绪分配器的完整 API 响应，缓存压力、延迟归还和首次初始化仍有不确定性，不能视为完整 HTTP 的精度证明。
该采样桥与其他原生采样在推理 Docker 构建；提供 MARKOV_TORCH_ROOT 时按安装包的 C++ ABI 编译共享库。维护入口为 `python -m markov.adapters.ascend.tensor_allocations --recipe … --output …`，接收库路径、设备、预热/重复数和 empty/empty_strided 的整数向量案例，不依赖 base、target 或模型权重；纯 modeling 不加载 PyTorch 或原生库。

同步读回的 `post_sync_readback_interval` 只覆盖同步 API 返回后的复制与调用尾部，不包含同步本身。
执行先等待生产者，再查询相应同步 API 的空闲服务，最后支付读回尾部。底层 runtime 与外层 ACL 的测量不能直接互换。
空闲同步常数来自无待完成工作的已用 stream；它是就绪后服务的近似，没有测量繁忙环境下的唤醒延迟，不能宣称覆盖全部等待行为。

未固定主机内存的 Ascend 输入上传即使声明 non_blocking，也可能走同步主机复制。该路径先让 worker 等实际设备前沿，再支付闭合 ACL 上传 API 的 host_to_device_interval，最后让 caller 等 worker 返回并支付外层同步服务。
这个 ACL 区间已经包含内部 runtime 同步与复制，不再重复查询内部同步成本；传输区间占用 worker，不另收一份设备复制服务。包装调用的 CPU 前后段排除整个 ACL 区间。
该向量上传的 worker 两侧不遍历元素，按 dtype、rank、主机内存类型及调用方式描述；字节数仍完整进入复制 API 的独立查询，caller 也保留实际数组规模。只有适配器显式提供完整 worker 变量时，才把传输载荷与这些 CPU 片段分开；未声明时保留完整传输匹配，API 实现改变仍须拒绝迁移。
传输响应按有效字节数、主机内存类型及生产者完成条件共享，不按语义数组或 dtype 另建相同传输模型；就绪 stream 的服务测量没有覆盖繁忙环境唤醒、固定主机内存或冷缓冲区。

输入准备中的设备内核与 CPU 包装分别描述。位置生成的工作量是待计算 token 数；请求页表写入还需要已有前缀长度和表的列宽。
当前原生 Triton 实现每轮处理 512 个位置，结构侧据此给出待计算块数 Bq 和前缀块数 Bp，不读取任何耗时系数。
位置生成可用 `T = a + b × Bq`，页表写入可用 `T = c + d × Bq + e × Bp`；常数项表示内核自身的固定工作，块数项表示每轮设备读写，单位均为 ns。
相同工作量的位置生成共用响应，前缀的数值变化不另建一个模型；CPU 调用仍保留各自的语义和上下文。

这些系数来自独立运行实际内核的设备任务记录：编译、加载和输入构造先完成，重复观测按相同工作点汇总，再离线拟合。
单行、输入类型、表列宽、是否提供前缀数组及长度范围限定适用域；掩码尾块、行对齐与竞争的影响随模型限制保留。
设备任务时间不包含 CPU 准备、提交和排队，不能拿这两个内核的响应补齐那些成本。独立验证按新进程和未见工作量进行，不用验证残差改系数。

内核编译、首次加载与后续加载按各自的原生观察边界估计，不用一个平均残余表示全部准备。
这些响应是 caller 被占用的完整区间，包含其内部等待，不宣称等于 CPU 自身服务；不能再把同一准备的子区间重复相加。
常规内核调用的测量已排除这些准备区间，准备发生时才由目标规格状态增加一次对应工作。
编译和后续加载按内核规格限定覆盖；首次加载按启动器接口与 runtime_initialized 限定观察上下文。
首个接口的完整加载区间包含共享支持库初始化，后续接口仍各自支付首次加载，不再重复支付首个接口的完整区间。
这里没有把两段实测强行相减成一个通用初始化系数。接口、调用顺序或部署不在样本范围时报告域外，不能借另一个接口的时间代替。
当前分别描述融合页分配、请求页表写入、位置生成与融合 QKV 的准备；普通输入准备、传输和控制仍须有各自成本依据，不能由这些编译/加载样本推导。

已测坐标组合、范围内的新组合和明确允许的外推分别返回。逐维在范围内不等于组合已测过；
模型必须显式声明是否允许新的范围内组合，以及哪些特征允许越界。
缺模型、缺特征、范围不支持、组合不支持或公式给出无效耗时均不返回数值，不自动钳制成零。
覆盖状态只说明查询条件，不能当作模型精度或置信区间。

## 模型形式与参数来源

| 操作特点 | 首选简单形式 | 参数依据 |
| --- | --- | --- |
| 工作固定的小控制步骤 | 有明确适用域的典型响应 | 独立有效测量的稳健统计 |
| 传输或可解释规模变化 | 固定项加工作量项，或测点间插值 | 实际服务测量与覆盖范围 |
| Prefill/Decode 计算 | 按操作几何建立简单回归或插值 | 对应实现、shape、dtype/布局的独立样本 |
| 确有多变量非线性且样本足够 | 再比较必要的其他模型 | 留出验证，不因“复杂”预设更好 |

特征是目标工作的变量，系数由独立样本离线估计，模型形式说明两者如何给出响应。
整体逻辑必须能用自然语言解释；不要求每个底层细节都附会成一个独立物理系数。
父包络、子操作、设备耗时与等待不能重复计费，也不为每个原生 Python 函数或后端碎片建立一个模型。
同一模型可服务多个层、请求和配置；工作条件变化才引入必要区别，不按实验身份扩张模型数量。

计算工作由固定几何与运行变量共同描述。线性层固定 N/K 与布局，M 随参与的行数变化；RMSNorm、残差相加和门控激活使用行数与宽度。
行数按操作语义绑定：例如头归一化每个 token 有多行，而只投影最后一个 token 的词表头按 batch 取行，不能统一乘 Prefill 长度。
注意力的 context 包含 query 后缀；单请求因果注意力的有效位置对数为 `Q × (C − Q) + Q × (Q + 1) / 2`，头数、维度与布局另行限定。
这些关系只产生工作特征。耗时仍由选定成本模型给出，固定几何及行数绑定都不来自时间拟合。
输入准备、嵌入和输出处理中的张量工作可按 `固定量 + 每 query token 的元素量 × Q + 每请求的元素量 × B` 描述。
其中的元素量来自 shape、布局与原生步骤，不是拟合系数。例如输入复制可同时包含随 Q 变化的 token 数组和随 B 变化的请求数组，
词表输出与采样按 B 处理，不能随完整 prompt 长度增长。实际成本仍按这些工作特征查询独立响应。
Q/K reshape 能沿用原存储时只保留依赖端口；只有布局要求物化时才查询复制服务，不能把缺测量误认成视图。

## 数据库维护

数据库保存测量事实、工作变量、部署、计时口径、有效性与来源；离线训练声明选择样本和公式。
库中另维护各部署的一份现行离线模型选择，成功训练和导出后才发布，不按版本保存重复模型包。
直接预测可声明数据库，由准备步骤导出该选择到本任务；纯预测只读取小型模型文件。
这不把所有已导入记录自动授予训练资格，也不在成本查询时训练；未声明补采预算时，缺少部署选择明确要求维护。
声明预算后允许空库起步；自动准备只使用现行模型的合格独立来源与本任务的独立采样，不混入未知历史留出。
重复导入同一来源的同一原始记录与口径不增加权重；真实重复测量保留为不同样本，数值相同不是去重依据。
使用已有采集身份和原生记录位置定位来源，不新增文件摘要或内部版本有效性管理。
显式别名映射只处理已知来源，不能猜两个 trace 内容相同；未知部署可以保存，但不授予训练或预测资格。

已实现的最小维护入口把正常 HiCache 控制器 capture.json 与 measurements.jsonl 导入 SQLite，按规范化来源路径、原始行号和计时量去重。预热也保留，训练只选择显式列出的采集及其中非预热记录；未选中的留出不会因已经入库而参与拟合。同身份的元数据或数值冲突拒绝并回滚该次导入，不覆盖旧事实，也不用文件摘要管理版本。缺少稳定采集身份的历史文件只以原路径识别，不把复制到新路径的文件自动认作独立采集。
框架适配器解释测量单位、操作和必要环境，存储层只维护事实。当前单设备响应的环境包括平台声明、框架/runtime、PyTorch、dtype 和传输实现；模型名与全局 TP 不是其系数条件，局部层数和字节几何仍受工作域限制。平台声明不是硬件自动核验，不能据此取得新平台精度资格。
离线训练先对同一工作点取中位响应，再使用适配器声明的单变量线性形式或系数曲线。不能支持的变化变量、点数不足和混合环境明确失败，不改模型形式或添加参数凑结果。导出按操作、实现和口径替换显式选定包中的相应响应，其他模型不变；这不是全部算子、CPU 校正或自动补采已经恢复。
测量条件按同一操作/实现/口径比较，不要求不同操作的采样协议完全相同；每项响应只引用实际提供其样本的来源，不把本次选择的全部采集写进每个模型。

独立 ATen 索引操作还可通过 `python -m markov.adapters.ascend.tensor_responses` 采集，并经 ascend_tensor 适配器入库。当前提供 int32/int64、连续一维 clone/cat 的整段主机响应、主线程 CPU 时间和入口至同步返回的完成观测。三者不是可直接相加的服务分解：主线程统计不含后台工作，完成观测包含调用及同步观察，也不等于裸设备执行。
这类响应使用元素数及输入张量段数描述工作。clone 按元素数拟合；cat 在各输入段数下估计固定项和每元素系数，再按段数插值，超出测量范围不外推。后台提交、发射和返回端口不足时，这些模型不能替代现有队列配方的 CPU、worker 或设备服务；不能通过改名口径把缺口填平。启用原生观察的原始数据可保存，但未经开销处理不能用于这类正常响应训练。

采集与训练属于长期性能维护。纯预测消费已经选择和解析的只读模型，不打开大型数据库或重新训练。
模型范围与特征组合在加载时建立索引；重复的完整工作点可复用响应，但覆盖检查和报告不能因缓存消失。
同一预测会话按完整工作描述复用响应，包括缺模型和域外结果；模型只读，不在查询时训练。
逻辑查询次数和实际求值次数分别报告，每次成功绑定仍计入操作覆盖，不能把不同工作点数当作已覆盖操作数。
运行时特征如通信到达偏斜必须进入正确查询；不能只按名称缓存所有调用。

## 缺口与最小补采

先区分缺操作规则、缺工作变量、缺适用模型和模型域外。只有后两者才可能通过独立采样解决。
需求按整组目标归并，已有模型及其合法外推优先；新增测量由整组共享，并可供以后任务使用。
采样定义不读取 target 真值或误差，不逐格加专用模板、阈值和系数。
采集配方必须说明预期工作、最小请求规模、实际命中核对、预算和结束条件；失败、无效点和恢复均计入消耗。
数据不足时允许诚实停止，不能反复完整启动 serving 直到拟合好看。

当前自动配方按实际页大小和缓存实现合并区域需求，用少量独立长/短输入、重复规格及成对前缀区分工作项；
容量按这些请求的页对齐驻留上界设置，避免把内存压力混入计算响应。需要 Prefill 结束端口时再加入单输出请求。
物理备份/回载按来源 K/V 几何、实际页需求及索引段数共同采样，不加载模型权重；存储和竞争尚无自动配方。
所有性能采样共用一份累计启动、时间、请求/tokens 与存储预算，维护后处理另列并计入时间。
base 和正常评价有各自预算，不能用它们替性能采样承担消耗。中断恢复依据原容器退出状态，不依据残留输出猜成功。

## CPU、gap 与采集开销

CPU 自身服务、等待和残余空白分别保存。可解释的等待由依赖、worker 排队、设备完成及发布关系推导。
目前不能解释的 residual gap 沿明确来源迁移或标记未知，不用 I/O 或计算系数吸收它。
Python probe 默认无 snapshot；测量开销校正使用与源采集绑定的有效对照，不能用 target E2E 反推。
原始观测与校正结果同时保留，校正不能修改原始 DAG 的身份、观测坐标或重复扣费。

## 适用范围与评价

成本迁移、数据库可查询、测量覆盖和留出精度分别报告。真实模型、平台、TP 或后端变化需重新核对资格。
训练/验证按独立采集或请求组隔离，同一次运行的重复层不算大量独立样本。
评分不能触发 refit、补采或 readiness 改写；用于修正规则或参数的数据转为开发证据，不再声称首次留出。
本轮先在同一成本依据下恢复和比较行为，再单独讨论精度提升，不将重构与逐格拟合混在一起。
