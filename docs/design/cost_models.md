# 成本、迁移与独立性能数据

日期：2026-10-27。本文规定新实现的边界，模型具体形式以实际数据和机制决定；不表示现有精度已迁移。

## 两种成本来源

**base 迁移：** 对应工作的部署、实现、shape、执行方式与必要条件已证明不变，沿用该操作的有效服务成本。
源队列等待不能作为服务迁移；未解释的源 residual gap 单独保留并标为近似，不能说已经预测了 target 的等待。

客户端入口与响应尾部可以显式引用原始图区间，成本层核对其来源、资源及残余类别，执行时只推迟就绪，不占 CPU 服务资源。
当前仅假设同一请求的传输工作与前端部署保持不变；来源中混合的传输、调度和处理时间仍是残余近似。
请求大小、流式响应或前端部署变化时不能据此授予外推资格。串行请求依赖前一响应；后台 I/O 清空是另一项依赖，不能用程序最终结束代替响应时刻。

计算 probe 的 CPU 包络只用于定位提交，不作为设备成本。源设备服务沿原生提交关系绑定到独占设备区间，保留原图节点、资源与记录位置；
同一 probe 内的多个原语、重叠归属或无法匹配的设备端口不猜分配。结构侧给出的工作未变标记只是迁移依据之一，仍须核对实现、资源与依赖条件。
能够找到父调用的设备区间，不表示能将其整体作为某个子操作的成本。例如注意力调用还会写 K/V，必须按实际操作分别绑定，或保留为未能拆分的来源；不能把整段设备服务当作 score。

目标工作可携带原始操作引用，不能携带规划阶段自行算出的耗时。当前未变的单设备工作沿用已经证明的原生调用及资源顺序；
成本查询再核对完整工作描述、独占归属与目标资源，按源节点求和一次。缺少独占服务依据时仍查独立模型，不猜父包络。
迁移结果按原始操作身份缓存，不能仅按 shape 合并不同参与者的实测值；变化工作则按完整工作点复用独立响应。
这只支持原部署和资源放置下的设备服务迁移，假设该服务对新的排队位置保持稳定，不代表已验证设备竞争、频率变化或 CPU 校正。

CPU 调用区间也只在原始图的独占划分上求交，分开保留观察到的服务、等待、空白、已标识采集开销及未覆盖时间。
这些只读视图在来源准备时建立一次，不重复解析 trace，也不把父包络和子调用相加；元数据、分配等准备序列的 CPU 区间单独保留。
该视图仍是带采集的观测，已标识开销为零不代表没有 probe/profiler 开销；未完成校正前不能直接称为正常 CPU 服务，等待也不能当作服务迁移。

同源校正作为显式选择的独立输入，声明 source_manifest、basis、sources 与 intervals；区间记录资源身份、原始 begin_ns/end_ns 和估计 cost_ns。
加载时核对来源并拒绝重叠区间，逐条读取，不保留一份完整 JSON 记录树。成本按原坐标求交，分割使用累计值相减，避免多次取整破坏总量。
覆盖部分的估计值与未覆盖的原始值分开保留；已识别的等待及采集开销不套用该校正，原始图及回放不变。

从轻量配对采集中扣去 CPU 差额，再分摊到原区间，得到的是带假设的校正值，并非每个操作的独立 CPU 服务测量。
原图标作服务的区间仍可能含未识别等待，不能仅凭“已校正”授予迁移资格。
当前诊断在各请求的计算 caller 上，将已解释调用、各类准备序列、通信包络及其外部区间独占划分，另列正式请求；不相加父子包络，也不包含 worker、设备或其他线程。
这用于核对覆盖和后续成本归属，不直接替代目标程序已有的计费操作；正式迁移还须证明工作不变，并排除重复收费。

已知计算帧的调用顺序在来源中解释一次，包括计算、准备和通信。相邻调用间只保留独占间隔，不包含调用包络或帧前后的请求控制。
目标结构携带来源区间引用，成本层按原始图求交：服务与空白的已覆盖部分使用校正值，其余保留原始值；这些仍统一标作来源 CPU 残余近似，不能称为正常服务迁移。
近似限定同 caller、同顺序配方，未预测 host 工作随 shape 变化的部分或未知等待。它只推迟 caller 后继就绪，worker 和设备可以继续运行；不独占 CPU 服务资源。
已识别的采集开销排除，区间含尚未生成的原生提交、尚未生成依赖的已知等待或来源未覆盖时停止绑定，不能复制等待时间或静默删去。原始图与静态回放不变。

输入原生调用的 CPU 部分可以引用同一 base 内的工作估计。caller 按完整配方、工作量和原线程匹配，worker 按唯一相同的原生工作匹配；caller 配方变化不自动否定未变的 worker 工作。
来源区间由入队、外层调用返回、后台执行和设备提交端口限定。上传 API 的完整区间已单独计费，worker 只取其两侧；caller 的 stream 同步等待由生成的依赖承担，再支付独立的就绪同步服务。
已知的其他等待或未覆盖区间不能迁移。服务与残余分别使用 CPU 校正，未覆盖校正的部分保留原值，响应标为 same_work_cpu_estimate；它不是逐操作正常服务真值，未知等待和采集开销仍可能影响估计。

首次调用的编译、加载包络没有边界时，不把它当作普通前段。已观察到相同声明规格先前提交后，后续调用可提供准备完成后的前段；其配方、工作量和 caller 也相同时，可以供本次首次调用使用，编译与加载仍由目标自己的状态另计。
该推断限定进程内规格缓存不失效的执行范围；支持中途清空或更复杂的规格条件前，需要补充相应来源事实。源排队等待和 ready 后的派发间隔不包含在这些 CPU 工作估计中。

输入派发另取入队端口与前一个 worker 返回均已满足后，到本次 worker 开始之间的源区间；前一个 worker 仍忙的部分不迁移，目标排队由依赖产生。
该区间只在完整工作配方与原资源相同时作为来源派发残余近似，不占 CPU 服务资源。它仍混有操作系统调度、发布及采集影响，不是正常环境下已校准的派发服务。

设备事件的观测必须由实际命令及其关联 ID 证明。record 可引用源标记区间，wait 只引用生产者在其开始前已完成的区间；目标 wait 仍依赖目标自己的生产者，不复制源阻塞时长。
导出标记中的零时长也保留原记录及依赖，不将其解释为精确硬件开销。其他输入设备工作只有在原生提交唯一指向完整独占服务、工作与资源未变时才能迁移。
多任务配方逐次绑定发射前 CPU 和设备服务，整个回调只收一次返回成本；原生发射 API 的入口提供 CPU 分段依据，不能把父包络分配给每个子任务。

CANN 回调的启动增量来自独立正常运行：同一新进程的首次回调响应减去稳定回调的中位响应，再跨独立进程取中位值。
计时包住同步执行的 ACLNN host 回调，设备同步、输入构造和 workspace 准备在计时外；它是 worker 被占用的响应增量，不宣称等于自身 CPU 指令时间。
有加载或符号解析的源回调不提供普通 worker 片段，普通主体引用 base 内工作相同的无加载回调，启动增量另计，避免双算。
适用域保留完整操作、dtype、索引、表几何及初始化上下文；只测过的固定几何不自动外推。当前封闭输入回调将启动增量集中到主体之前，内部启动与设备工作的重叠有近似；出现外部中间消费者或共享资源交错时须细化端口。
独立 SDK 采样目标在[原生采样目录](../../src/markov/adapters/ascend/sampling/CMakeLists.txt)构建，不进入纯 modeling 链接。
采样接收设备、表行列、稳定重复数和新的 CSV 路径，记录首次与后续回调的墙钟及线程 CPU 时间，并在计时外同步和核对全部写入结果；不加载模型、base 或 target trace。

**独立预测：** 变化或新增工作使用独立数据库和离线训练的成本模型。当前 base 不自动入库或在线拟合，
target 正常时间、trace、评分、配置名和 workload 身份不能作为参数或补偿依据。
合法零成本必须有语义或测量依据，缺数据不能填零，也不能据此删除工作。

## 一项工作怎样查询

结构侧给出操作、真实实现、计时口径与必要工作变量。部署条件限定模型适用域。
计时口径分别表达 CPU 服务、worker 服务、设备服务、传输服务和有依据的残余区间，不能互相替代。
变量可以是 query/context tokens、M/N/K、dtype、布局、字节数、页数、层数、参与者和必要运行条件。
只用于限定覆盖的变量与进入公式的变量分别声明；同名 kernel、相同元素数或相同字节数都不保证工作等价。

模型返回耗时、来源、范围状态及近似说明，不创建节点、选择缓存策略或推进时钟。
内部相对时间及成本使用整数 ns；原始 trace 坐标、旧 us 测量和对外秒数在边界转换，保留原测量单位。
模型可声明 limitations，说明测量或独立验证中已知的限制。查询报告保留这些说明；可返回耗时只表示工作域和公式可用，不表示独立精度已经达标。

当前独立查询核心接收有类型的工作描述：操作、实现、计时口径及数值特征。选定模型按前三项建立唯一索引，
基础成本形式为常数项加各特征与系数的乘积；系数为空即为常数模型。常数项和系数统一使用 ns。
响应也可是一条系数曲线：例如不同页大小下，分别维护传输准备成本和每字节成本，再在相邻测点间线性插值。
曲线坐标必须落在已声明的测点区间内，不在区间外沿用端点；测点之间的插值属于模型假设，不是新增实测。
同一操作仍只有一个选定模型，不按每个页大小创建一个模型，也不让结构规则读取这些系数。
JSON 在外围装配层读取一次，图核心与成本核心不读取数据库、原生 trace 或评价结果。

文件后端的整体测量需要与执行边界对应。当前用已有键写入测量估计整批整理和元数据，用新键总响应的差额估计新增文件服务：
若已有键为 `a_e + b_e × bytes`、新键为 `a_n + b_n × bytes`，则先支付已有键响应，
再为含新键的批次支付 `a_n − a_e`，每个新页支付 `(b_n − b_e) × page_bytes`。
同质新键批次的总公式因而保持不变，但可以按原生顺序逐页发布；已有键跳过落盘仍需先整理数据。
这些阶段时长是根据整体测量推得，并非各阶段都已单独测量。混合批次、元数据所在位置和中途可见时间仍有近似，不应据总和一致声称阶段精度已通过。

预取的读前响应也保留原系数：页数项近似集中在准备阶段，字节项按实际读页推进，随后单独支付页复制/发布与返回响应。
这保持既有整体响应，同时允许停止后仍完成在途读取及一次被拒绝发布的复制；阶段拆分的不确定性与查询/准入 CPU 缺口单独报告。
从独立 DMA 的两个载荷档位估计启动项和每字节项，可以补充缺少的页几何；只扩大有数据依据的页档位，不改其他档位来追目标误差。

通信响应的计时边界必须与样本一致。当前 `collective_completion_interval` 表示最后一个输入就绪到参与组最晚完成的时间；
仿真先等待各输入到齐，再查询这段剩余服务。到齐前的等待不重复收费，也不能从模型返回值再减一次到达偏斜。
`arrival_span_us` 使用样本相同的整数微秒坐标：最晚到达的微秒坐标减最早到达的微秒坐标；字节量、成员数和布局另行限定工作域。
一个参与组调用只绑定一项服务，不能按成员数重复收费。该口径没有分别预测各成员的完成时间，也没有描述到齐前网络资源的占用与干扰；相应近似须随执行结果保留。

原生异步调用分开查询 caller 提交/返回、worker 逐次发射/返回和设备服务；派发延迟的起点是提交与前一后台任务均已完成，
不能从提交起算后再用 worker 排队覆盖掉这段延迟。框架准备代码不能与子调用包络重复收费。
没有对外端口的连续参数准备，归入下一次调用的 caller 前段；整段入口归入第一次调用，尾部归入最后一次返回。
输入准备按这个口径描述 caller 工作，单独保留序列入口、出口和框架上下文；worker 与设备仍使用原生工作描述，不能把框架准备重复加到它们的成本中。
有独立产出、等待或资源交错的 CPU 工作仍须单列。编译与加载依旧单独计费，caller 前后段的测量必须排除这些区间。
同步读回的 `post_sync_readback_interval` 只覆盖同步 API 返回后的复制与调用尾部，不包含同步本身。
执行先等待生产者，再查询相应同步 API 的空闲服务，最后支付读回尾部。底层 runtime 与外层 ACL 的测量不能直接互换。
空闲同步常数来自无待完成工作的已用 stream；它是就绪后服务的近似，没有测量繁忙环境下的唤醒延迟，不能宣称覆盖全部等待行为。

未固定主机内存的 Ascend 输入上传即使声明 non_blocking，也可能走同步主机复制。该路径先让 worker 等实际设备前沿，再支付闭合 ACL 上传 API 的 host_to_device_interval，最后让 caller 等 worker 返回并支付外层同步服务。
这个 ACL 区间已经包含内部 runtime 同步与复制，不再重复查询内部同步成本；传输区间占用 worker，不另收一份设备复制服务。包装调用的 CPU 前后段排除整个 ACL 区间。
传输响应按有效字节数、主机内存类型及生产者完成条件共享，不按语义数组或 dtype 另建相同传输模型；就绪 stream 的服务测量没有覆盖繁忙环境唤醒、固定主机内存或冷缓冲区。

输入准备中的设备内核与 CPU 包装分别描述。位置生成的工作量是待计算 token 数；请求页表写入还需要已有前缀长度和表的列宽。
当前原生 Triton 实现每轮处理 512 个位置，结构侧据此给出待计算块数 Bq 和前缀块数 Bp，不读取任何耗时系数。
位置生成可用 `T = a + b × Bq`，页表写入可用 `T = c + d × Bq + e × Bp`；常数项表示内核自身的固定工作，块数项表示每轮设备读写，单位均为 ns。
相同工作量的位置生成共用响应，前缀的数值变化不另建一个模型；CPU 调用仍保留各自的语义和上下文。

这些系数来自独立运行实际内核的设备任务记录：编译、加载和输入构造先完成，重复观测按相同工作点汇总，再离线拟合。
单行、输入类型、表列宽、是否提供前缀数组及长度范围限定适用域；掩码尾块、行对齐与竞争的影响随模型限制保留。
设备任务时间不包含 CPU 准备、提交和排队，不能拿这两个内核的响应补齐那些成本。独立验证按新进程和未见工作量进行，不用验证残差改系数。

内核编译、首次加载与后续加载按各自的原生观察边界估计，不用一个平均残余表示全部准备。
这些响应是 caller 被占用的完整区间，包含其内部等待，不宣称等于 CPU 自身服务；不能再把同一准备的子区间重复相加。
常规内核调用的测量已排除这些准备区间，准备发生时才由目标规格状态增加一次对应工作。
编译和后续加载按内核规格限定覆盖；首次加载按启动器接口与 runtime_initialized 限定观察上下文。
首个接口的完整加载区间包含共享支持库初始化，后续接口仍各自支付首次加载，不再重复支付首个接口的完整区间。
这里没有把两段实测强行相减成一个通用初始化系数。接口、调用顺序或部署不在样本范围时报告域外，不能借另一个接口的时间代替。
当前分别描述融合页分配、请求页表写入、位置生成与融合 QKV 的准备；普通输入准备、传输和控制仍须有各自成本依据，不能由这些编译/加载样本推导。

已测坐标组合、范围内的新组合和明确允许的外推分别返回。逐维在范围内不等于组合已测过；
模型必须显式声明是否允许新的范围内组合，以及哪些特征允许越界。
缺模型、缺特征、范围不支持、组合不支持或公式给出无效耗时均不返回数值，不自动钳制成零。
覆盖状态只说明查询条件，不能当作模型精度或置信区间。

## 模型形式与参数来源

| 操作特点 | 首选简单形式 | 参数依据 |
| --- | --- | --- |
| 工作固定的小控制步骤 | 有明确适用域的典型响应 | 独立有效测量的稳健统计 |
| 传输或可解释规模变化 | 固定项加工作量项，或测点间插值 | 实际服务测量与覆盖范围 |
| Prefill/Decode 计算 | 按操作几何建立简单回归或插值 | 对应实现、shape、dtype/布局的独立样本 |
| 确有多变量非线性且样本足够 | 再比较必要的其他模型 | 留出验证，不因“复杂”预设更好 |

特征是目标工作的变量，系数由独立样本离线估计，模型形式说明两者如何给出响应。
整体逻辑必须能用自然语言解释；不要求每个底层细节都附会成一个独立物理系数。
父包络、子操作、设备耗时与等待不能重复计费，也不为每个原生 Python 函数或后端碎片建立一个模型。
同一模型可服务多个层、请求和配置；工作条件变化才引入必要区别，不按实验身份扩张模型数量。

计算工作由固定几何与运行变量共同描述。线性层固定 N/K 与布局，M 随参与的行数变化；RMSNorm、残差相加和门控激活使用行数与宽度。
行数按操作语义绑定：例如头归一化每个 token 有多行，而只投影最后一个 token 的词表头按 batch 取行，不能统一乘 Prefill 长度。
注意力的 context 包含 query 后缀；单请求因果注意力的有效位置对数为 `Q × (C − Q) + Q × (Q + 1) / 2`，头数、维度与布局另行限定。
这些关系只产生工作特征。耗时仍由选定成本模型给出，固定几何及行数绑定都不来自时间拟合。
输入准备、嵌入和输出处理中的张量工作可按 `固定量 + 每 query token 的元素量 × Q + 每请求的元素量 × B` 描述。
其中的元素量来自 shape、布局与原生步骤，不是拟合系数。例如输入复制可同时包含随 Q 变化的 token 数组和随 B 变化的请求数组，
词表输出与采样按 B 处理，不能随完整 prompt 长度增长。实际成本仍按这些工作特征查询独立响应。
Q/K reshape 能沿用原存储时只保留依赖端口；只有布局要求物化时才查询复制服务，不能把缺测量误认成视图。

## 数据库维护

数据库保存测量事实、工作变量、部署、计时口径、有效性与来源；离线训练声明选择样本和公式。
重复导入同一来源的同一原始记录与口径不增加权重；真实重复测量保留为不同样本，数值相同不是去重依据。
使用已有采集身份和原生记录位置定位来源，不新增文件摘要或内部版本有效性管理。
显式别名映射只处理已知来源，不能猜两个 trace 内容相同；未知部署可以保存，但不授予训练或预测资格。

采集与训练属于长期性能维护。纯预测消费已经选择和解析的只读模型，不打开大型数据库或重新训练。
模型范围与特征组合在加载时建立索引；重复的完整工作点可复用响应，但覆盖检查和报告不能因缓存消失。
同一预测会话按完整工作描述复用响应，包括缺模型和域外结果；模型只读，不在查询时训练。
逻辑查询次数和实际求值次数分别报告，每次成功绑定仍计入操作覆盖，不能把不同工作点数当作已覆盖操作数。
运行时特征如通信到达偏斜必须进入正确查询；不能只按名称缓存所有调用。

## 缺口与最小补采

先区分缺操作规则、缺工作变量、缺适用模型和模型域外。只有后两者才可能通过独立采样解决。
需求按整组目标归并，已有模型及其合法外推优先；新增测量由整组共享，并可供以后任务使用。
采样定义不读取 target 真值或误差，不逐格加专用模板、阈值和系数。
采集配方必须说明预期工作、最小请求规模、实际命中核对、预算和结束条件；失败、无效点和恢复均计入消耗。
数据不足时允许诚实停止，不能反复完整启动 serving 直到拟合好看。

## CPU、gap 与采集开销

CPU 自身服务、等待和残余空白分别保存。可解释的等待由依赖、worker 排队、设备完成及发布关系推导。
目前不能解释的 residual gap 沿明确来源迁移或标记未知，不用 I/O 或计算系数吸收它。
Python probe 默认无 snapshot；测量开销校正使用与源采集绑定的有效对照，不能用 target E2E 反推。
原始观测与校正结果同时保留，校正不能修改原始 DAG 的身份、观测坐标或重复扣费。

## 适用范围与评价

成本迁移、数据库可查询、测量覆盖和留出精度分别报告。真实模型、平台、TP 或后端变化需重新核对资格。
训练/验证按独立采集或请求组隔离，同一次运行的重复层不算大量独立样本。
评分不能触发 refit、补采或 readiness 改写；用于修正规则或参数的数据转为开发证据，不再声称首次留出。
本轮先在同一成本依据下恢复和比较行为，再单独讨论精度提升，不将重构与逐格拟合混在一起。
