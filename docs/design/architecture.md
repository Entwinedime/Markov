# 项目架构与长期路线

Markov 从原生推理执行中取得必要事实，生成粗粒度执行图并提取参数化子图模板，在目标配置和请求下动态展开，再由独立成本模型预测 serving 性能。目标是用户输入简单、因果可解释、适配范围小，不重建完整推理框架。

本文定义设计和职责，不提供实现资格或实验结论。结构正确性、原生配置可运行、测量覆盖和性能精度分别取得证据。

## 输入与整体流程

输入是一个固定模型、配置集合和请求 workload 集合。模型包括实现所需配置和 dtype；请求声明长度、到达和必要内容条件，配置声明框架、并行、调度、资源和部署。系统选择代表来源，用户不指定 base。

    代表性原生执行
        → trace、流程边界、必要状态及提交事实
        → 来源粗粒度执行图
        → 子图切分、参数化和归一化
        → 模板库

    目标配置与请求
        → 原生控制决定动作
        → 模板选择、有限变换和连接
        → 目标粗粒度执行图
        → 时间与资源推进
        → 完成反馈驱动下一次原生决定

    独立目标原生执行
        → 独立真实粗图与状态事实
        → 对照预测的工作、参数、必要因果和状态变化

结构阶段先用给定耗时、实测服务时间或已核对的真实事件条件解耦成本模型。验证构图时，真实动作和批次可以作为给定输入，模板选择、参数求值及依赖仍由核心产生；验证控制器时，动作和批次必须由原生代码产生。查询等返回值如被旁路，对应模块不取得验证资格。目标图体、节点和边不能复制进来源库或预测图。性能阶段再接入特征需求、独立采样、成本拟合和精度评价。

## 三种粒度

| 对象 | 作用 |
| --- | --- |
| 流程动作 | 控制与执行之间的稳定交接，包含参数、状态效果和完成责任 |
| 粗图片段与子图 | 表达必要工作、资源和对外作用，可以层次化组合、复用和变换 |
| 性能单元 | 有明确特征和测量边界的计费对象，可比语义子图更细 |

原始 trace 是取证输入，正式图不维护其中所有 kernel、CPU 函数和 SDK 内部记录。粗图先于模板形成，不先生成完整细粒度 DAG 再把报告折叠起来。

解释先确立必要语义边界和外部作用的因果，不以所有内部命令均有唯一总序作为前提。内部工作可在资源、跨界依赖与中间消费者均已核清的封闭区域内承接；异步尾部和成本责任保持。必须外露却缺少定位依据的作用仍报告证据不足，不能由封装或时间拟合补答案。

采集与无设备控制共用本地业务窗口：首次请求开启，全部本地输入收到、原生逻辑空闲且模型发送队列已由原生循环清理后关闭。PP的proxy/output发送仍持有模型工作；空请求转发不阻止窗口关闭。控制端不能为了提前报告idle而主动清空模型发送队列。最终退出由核心在请求清理、执行图排空和控制参与者停驻后发起，适配器结束私有CPU控制等待，不向原生PP/PD消息流插入退出请求。局部窗口关闭不是组同步或协议结束；观察边界不拥有请求进度或资源状态，也不能丢弃在途工作。

无设备控制在首次请求前建立整体静止的空状态：全部原生worker初始化完成，尚未交付workload，输入所有者停在idle且其余参与者阻塞于原生控制边界。PP非输入stage可以等待下一轮metadata，不要求所有worker同时停在on_idle函数；工作到达后继续执行原生循环。该初始化与采集侧真实设备预热分别负责控制状态和运行环境。

片段内部可以隐藏实现，但其输入输出、共享状态、所用资源、CPU 返回、设备完成、中间信号和跨 rank 交互必须完整表达。跨 stream 的区域允许多个资源片段；一个服务不能被压成不符合真实行为的全局串行节点。

主机顺序与时间测量分别保存。Ascend适配器用CPU计数器连接语义区间、SDK提交和原生API，直接RAW读数作为对应边界的测量；设备顺序仍使用stream坐标及独立时钟校准。SDK导出时间需要按原生产公式还原计数器，不能用拟合偏移、邻近时间或容差猜对应。没有独立测量的内部端点保留未知，不把顺序坐标解释成耗时。

内部记录数量和名称不定义模板身份。已证明由片段承接的记录不必逐项对应算子；未能确定必要外部作用的记录仍保留具体缺口，不以底层未知总数代替流程资格判断。

## 统一 serving 流程

顶层动作包括选择工作、准备输入、模型执行、结果处理和输出；Prefill/Decode 属于模型计算主体。到达、等待和结束属于控制交互，不伪造收费工作。

| 交接 | 含义 |
| --- | --- |
| 选批完成 | 原生代码决定当前成员、阶段和 token 范围；空决定也可能有必要协调 |
| 准备与预约 | 构造必要输入并通过核心资源服务取得槽位和 KV；预约不等于设备内容已就绪 |
| 提交与计算 | CPU 提交、CPU 返回、各 stream 的工作完成分别表达，不统一排空设备 |
| 结果可读与处理 | 按实际数据和等待关系读取结果，在对应端口提交生成/结束效果 |
| 请求输出 | 输出角色向下游交出 token；独立于内部状态提交，不包含 HTTP/分词开销 |

模型结构提供 embedding、重复层、attention、MLP、归一化/残差和输出角色等语义依据。原生实现提供融合、通信、KV 与同步的实际边界。层号、调用次数和 rank 绑定不自动生成新结构种类。

张量形状规则由实际边界声明，参数身份属于声明所在调用；转发同一张量时沿显式调用参数绑定换到消费者上下文，不能按观测值相等建立关系。外层模型包装保留内部生产者的规则，PP入口读取首个本地层的原生分片方式；缺少声明或参数关系时明确报告，不以参数别名、模型名或统一除以TP度代替来源依据。

PP 保留微批次、stage 间激活、输出/token 返回环及真实等待。P/D 分离保留两个独立的槽位/KV 池，按请求连接预约、计算、KV 与 metadata 搬运、目的接入和源释放。发送入队、API 返回、数据可用及资源可释放分别处理。

chunk 的中间块只推进相应逻辑状态，不提前输出；prefix cache 命中不等于已有本次 logits。混合组批、准入、撤回及优先级使用原生策略，不能用独立启发式补齐原生决定。

## 状态与时间的唯一所有者

| 对象 | 所有者 |
| --- | --- |
| 请求进度、等待队列、组批、准入、控制分支 | 原生控制代码 |
| 槽位、KV 页、驻留、前缀引用/淘汰和就绪 | 核心资源服务 |
| 模板定义、参数关系、有限变换和绑定 | 模板与实例化对象 |
| 目标图、资源前沿、在途工作和模拟时钟 | 图装配与执行对象 |
| 工作特征、成本适用性与服务时间 | 独立性能提供者 |
| 采集时真实请求、KV 和 worker | 原生推理框架 |
| 单任务进程、预算、镜像、发布与恢复 | 外围应用 |

核心提供统一虚拟执行环境：模拟时钟、事件推进、等待唤醒及耗时/受控条件交接。原生只保留控制决定，adapter 将会影响决定的时间读取、超时、消息和完成查询接入该环境；CPU 自身工作通过显式服务时间推进，实际 Python、IPC 或进程调度快慢不决定模拟时间。虚拟化覆盖已声明的 serving 路径，任务看门狗、日志和预算的真实墙钟与之隔离。

验证旁路复用这套环境和动作接口，按本次验证责任固定已知条件，不增设回放调度器或第二份状态。真实记录按工作与因果位置对应，同刻事件保留必要因果；事实缺失或矛盾时明确受影响的结论。事实提取、案例组合及独立比较留在验证工具，核心不识别验证矩阵或框架私有函数。完整虚拟化解决输入可控性，来源完整性、模板能力、连接安全及比较独立性仍需分别取得证据。

受控验证可从共同激活点沿每个参与者的因果输入流消费记录，每步先核接口、实参和必要前置。消费游标只延续已验证历史，不替代对应依据，不跳过失配记录，也不驱动原生选择动作；比较器另行核对实际消费。普通跨运行对应仍使用其独立证据，不能因重复调用难配就退回全局次数。

原生资源对象只持有核心资源视图，不维护另一份页账或缓存树。动作交出不可变工作快照，完成事件提交对应效果；下一次预约可早于上一动作的全部异步尾部。

资源初始化由 adapter 一次声明槽位容量、请求字段和实际页复用策略，应用装配不替框架固定策略。当前 Ascend attention 的普通池将归还页放到可分配队列前部，PD 池延迟合入，原有可分配页不足时按页号排序；核心维护唯一队列并执行分配，不在 adapter 复制物理页账。逻辑复用顺序与未完成访问所需的依赖分别维护。

原生控制交接具名动作、条件、参数、工作成员和输出事实，不让核心维护一套对应框架私有方法的步骤枚举。资源 RPC 与动作执行分开：前者决定逻辑所有权，后者决定内容就绪和物理复用时机。一个池的逻辑操作由同一原生参与者顺序提出，动作保留修改前的请求绑定和返回页，不能在组装图时只读取已经改变的池后态。收到资源回复不意味着设备工作已完成；原生动作返回由对应的执行边界释放。

前缀匹配、分裂、引用和淘汰由核心索引完成；adapter 取得当前页绑定后构造原生需要的 CPU 元数据视图，不再镜像缓存树或记录 slice/clone/cat 操作列表。原生继承的请求记账逻辑继续使用这些视图，所需设备工作由采集所得动作模板承接。

动作提供者通过统一接口交付图及仍存活的数据身份；原生 batch 对象与语义端口如何绑定属于框架 adapter。共同依赖层维护已发布的张量版本、尚未完成的访问和 KV 页内区间，逻辑释放不提前抹除在途访问。执行循环按调用返回事件反馈控制，设备尾部保留在同一时间线上；下一次到达可以在设备工作完成前唤醒控制。协议消息的元数据由 adapter/broker 持有，交付可声明一组完成信号：核心仅等待实际生产者事件，完成后回复 broker，再由 broker 入队并唤醒原生接收者。该等待不阻塞发送 worker，也不在核心复制框架的协议状态机。

成功的完成读取也是控制因果。broker将完成边界随受其约束的消息交付，adapter在原生逻辑真正读取相应状态时交给共同依赖层；未采用的消息不产生当前动作前驱。依赖层保留已观察边界至下一次动作入口，再释放该引用，不回改已经返回的查询或给false读取加等待。adapter只维护当前状态的来源，不复制分配器或核心完成账本。

CPU 消息交接和目标设备通信分别表达。图使用参与者局部资源，执行层映射到统一时间线；框架声明通信参与与完成合同，共同层连接跨参与者依赖，不根据原生函数名选择协议。TP/EP/PP 的同步按实际参与组发生，不能在普通 RPC 上增加全 world 返回屏障。请求到达使用 workload 时间，控制器只读取当前可见状态。

原生“尚有未完成请求”不等于“当前有可运行工作”。适配层在原生已结束本轮必要处理的接收边界声明等待；共同控制按新请求、已入队协议消息或该实例实际查询过的完成事件唤醒。动作的产生或返回不证明逻辑取得进展。原生未声明等待的轮次照常执行，尤其不能统一跳过 PP 的转发与微批次轮转。

等待须覆盖完整原生控制轮次，PP 包含全部微批槽位。本轮运行过模型，或原生仍有待执行请求／chunk 时继续；完整无模型轮次中已检查的 PD 状态可以等待外部变化。局部握手或传输就绪不能代替 PP 全组共识；原生末级投递变化后的非空共识时唤醒入口，同一原生协商缓冲区只保存最近一次不可变载荷，不因重复发布继续唤醒。入口仍通过原生收取、等待和队列操作取得结果。唤醒保留至安全等待边界消费，不能在中间槽位的一次普通接收中丢失；资源所有者实际增加可用容量时可唤醒停驻实例，请求真正完成也属于逻辑进度。适配层不重新计算准入、不复制共识算法，也不以未分配或单个 Success 状态直接判断是否可运行。

执行器维护一个相对窗口起点的整数纳秒时钟，按数据和资源就绪推进。图实例可回收已完成历史，但保留在途引用、消息、未匹配端点和必要前沿。模拟器本身的 Python/IPC/初始化耗时不作为目标服务成本。

共同控制接口保留动作、资源和完成的边界；没有正式消费者的轻量控制、批次回放及兼容分支不保留。扩展另一控制实现时采用同一合同，不能在 adapter 内复制调度器。

## 适配与代码层次

| 层次 | 职责 |
| --- | --- |
| 框架 adapter | 流程/模型边界、批次及状态解释、原生控制接入和并行角色 |
| runtime adapter | 原生 trace、提交、队列、stream/event、资源生命周期及传输事实 |
| 共同核心 | 粗图规约、子图生产、归一化、变换、连接和资源执行 |
| 应用装配 | 选择具体适配，维护进程、文件发布和单任务生命周期 |
| example | 输入案例、实验矩阵、独立对照和错误分析 |

依赖向内，runtime 不反向依赖框架，核心不按模型名、kernel 名或私有函数增加规则。模型 metadata 能自动取得的内容不手抄；确实需要声明的模型家族/后端差异集中维护，不复制整个流程。

Python 负责原生观察、控制代理和进程装配；C++23 负责共同图、模板、资源及执行。跨语言合同由真实生产者/消费者共同维护，头源按职责同目录。验证代码不进入核心状态机。

采集与控制共同使用的框架 ABI 放在 src/adapters；例如批次阶段、成员/token 范围及参数读取只维护一份。 采集与预测的模型、实例及 workload 输入合同也由该层统一解析，入口分别维护观察策略或给定耗时等执行选项。观察插桩留在 src/collection，无设备原生控制留在 src/control；共同 ABI 不导入观察器、控制器或设备 runtime。C++ 的控制通道与资源服务分别放在 controller 和 resources，前者不复制页分配或前缀算法。

条件 EP 路由属于 workload：按逻辑请求/token 区间及实际专家层校验，采集与控制使用同一实现；框架 adapter 按原生MoE块配对路由器与专家计算模块，取得各层的top-k、层号和专家数，路由注入与控制复用同一份层几何。不从第一个router推断全模型，也不要求专家计算模块重复维护路由器的选择数。并行 rank 使用原生初始化规则，核心只传递参与者身份及角色事实。原生参数规范化改变用户请求的拓扑时，在启动 worker 前报告，不能把改写后的运行记为原配置成功。

## 来源、泛化与未来扩展

同一模型/实现域中，通过目标长度、成员、KV 范围和状态重组模板；域外模型、dtype、并行拓扑、backend、镜像和页布局分别取得来源。是否可以变换取决于实际合同，不能把未实现写成理论不可能，也不能只改配置数字声称跨域支持。

采集位置和逻辑拓扑分开。可隔离本地分片时，在一张兼容设备上依次观察代表角色；PP/EP/PD 协议需要实际参与进程时，由 adapter 运行原生组。代表采集须在采集前减少观察次数，不能用采后去重冒充节省。

等价 rank 共享结构定义，各自保持权重、KV、资源、状态和端口绑定。独立真实目标覆盖未参与建库的角色或输入。单卡分片不提供真实多卡通信时延或争用资格。

多机沿节点/设备位置和通信接口扩展；控制进程部署、网络连接及传输实现下沉到 adapter，核心处理统一依赖与资源。静态可扩展性和真实多机运行分别报告，不预建完整部署平台。

性能建设使用正式图声明的工作特征和成本责任，服务时间与等待分开、父子不重复计费。内部粗化不会自动解决通信争用、CPU 服务或成本泛化，结构通过也不等于性能精度通过。
