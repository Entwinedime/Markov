# 三阶段预测架构

本文定义三阶段预测的职责、共同合同与源码边界。

## 主流程

项目继续使用 trace 驱动的 DAG 变换路线。用户提供平台、框架、模型、base 配置、workload 和 target 配置集合。
一条主线采集并解释 base，另一条主线长期维护独立性能数据，两者在目标成本绑定时汇合。

```text
base profile → 原始 DAG 与源依据 → 目标工作、依赖和条件程序 ─┐
独立性能采集 → 测量数据库 → 离线成本模型 ─────────────────┴→ 执行 → E2E

上层：直接预测 / 准确性实验 / 配置搜索
```

实验和搜索共同消费预测接口，互不调用对方的主流程。直接使用不要求建立矩阵或取得 target trace。
三阶段是职责边界，不要求各写一份大型 JSON，也不要求三次启动进程。

### 当前正式预测如何落地

Python predict 负责准备/复用 base、导出现行模型、归并整组成本缺口并接收结果；PredictionProcess 只拥有隔离预测容器生命周期。
PerformancePreparation 用已有合格独立来源及有界采样维护模型；配方由框架适配器根据工作与来源上下文生成，不读目标真值。
DeviceTask 统一拥有设备互斥、累计用量、实际容器恢复和终态发布，base、正常测量与共享采样分别持有自己的任务预算。
这几层不实现缓存状态或仿真时钟；只有真正的成本缺口才启动性能准备，同一未解决缺口不循环补采。
文本实际 token 随采集配置交接，来源适配器核对原文与观察，不在纯预测内加载 tokenizer。
C++ 适配器核对部署、固定 workload 和支持设置，再一次提取语义观察、请求端口及区域引用。
普通预测不解析完整设备 trace，也不构造细图；manifest 仍明确声明所有来源，细图与原生因果诊断按需加载。

CacheProgram 拥有唯一的目标缓存、准入、发布和请求生命周期。它组合 RequestComputation 接口：
正式路径用 RegionCompute 表达输入准备、batch、结果处理与发送；显式原生诊断使用 ComputeProgram。
两者共享 CallerSchedule、资源前沿和 ProgramExecution，不各自维护缓存或局部时钟。

区域程序分别保留 caller CPU、caller 返回和流进度。CPU 与阻塞返回从同一入口推进、汇合后释放调用权，
输入/forward 流可继续执行；TP 输出就绪及必要的后续提交约束结果处理。最终发送、发送后 CPU 和未消费的提前计算分别保留。
后台备份也取得相同 caller 调用权，返回后让出；回载和写回淘汰在准入调用内等待，不允许同一 caller 同时执行另一条区域链。

SourceContext 的 Regions 只保存不可变观测区间及引用，不依赖细图。父区域之间的 opaque control/wait 保留为来源残余，
只扣已明确标识的采集开销；父区域内的等待由目标端口表达，不再复制整段源父耗时。
源残余不是正常 CPU 服务或已预测的 target 等待。当前细粒度 source 回放与区域预测是不同用途，不能互相替代资格。

目标帧目前沿用 base 的调度模式和固定输出次数，query 由目标缓存命中决定；尚不支持改变组批或切块方式。
区域吞吐、冷初始化和状态相关 CPU 的精度仍待验证，规则可执行不代表任意目标都有合格成本。

## 三个阶段分别负责什么

| 阶段 | 输入与输出 | 不承担的职责 |
| --- | --- | --- |
| 原始 DAG | manifest 声明的 base traces → 源 DAG、请求、资源、语义观测和原始成本依据 | 不决定 target 分支，不把 target 真值混进来源 |
| 目标结构 | 源依据、target、workload、执行规则 → 操作、工作量、依赖、资源角色和条件分支 | 不读取回归参数，不因缺成本删掉合法操作 |
| 成本与执行 | 目标工作、可迁移成本、独立模型 → 成本绑定、开始/完成时刻和 E2E | 不重新解释原生名称，不用残差修改结构规则 |

trace 中的原生名称、调用参数、模型角色和后端行为在适配层解释一次。共同图和仿真只消费已解释的身份、工作和依赖。
源信息不足时，明确缺少哪项事实及可取得它的最小观测；不能用硬词条映射推断未知框架或未知分支。

## 第二、三阶段如何交接

只保留少量具有真实所有者的共同合同，不为每个字段建立包装类：

| 概念 | 最小语义 | 所有者 |
| --- | --- | --- |
| `SourceContext` | 不可变观测、请求/帧索引与成本来源引用；细图和原生索引按需物化 | 原始 DAG 阶段，一份来源供多个 target 使用 |
| `OperationWork` | 操作、实现、shape/字节/页/参与者等工作变量，及计时口径 | 结构阶段，不携带模型参数或目标耗时 |
| `CostBinding` | 确认未变的源成本引用，或由独立模型估计的工作请求 | 结构声明类别，成本层解析数值 |
| `TargetProgram` | 目标操作、依赖、资源、必要入口/出口与条件规则 | 结构阶段，一套表示供执行和报告消费 |
| `ExecutionResult` | 完成时间、状态变化、来源与近似说明 | 执行阶段，报告不维护第二套状态 |

工作是否相同由结构语义和部署条件判断，不由“恰好能找到一个成本”决定。源成本引用不复制整份图或 trace 属性。
执行器绑定数值，不把成本系数反传给规则。框架差异集中在适配器，成本形式差异集中在提供者。

当前共同程序提交工作引用、显式零成本边界和依赖；引用只需存活到同步提交结束。
成本桥先解析完整批次，再原子提交到已有执行器。缺成本时汇总该批次的不同缺口，不提交半个批次，也不让结构规则读取数值或覆盖结果；尚未生成的后续分支不算已检查。
未变工作只向成本桥传递原始操作引用；是否有可用的独占服务及其数值由成本查询处理。各参与者保留自己的来源，不用相同 shape 覆盖不同的源耗时。
计算子集沿已证明的原生资源关系保留源队列次序；这些关系在来源准备时建立一次。
源资源放置不等于目标部署已获资格，也不能代替尚缺的跨流数据和其他业务依赖。

原生调用序列由框架适配器描述工作与调用类型，共同编排器连接 caller、worker 和设备端口。
异步提交允许 caller 返回与后台执行重叠；派发延迟从提交完成且前一后台任务返回后开始，不占 CPU 服务资源。
同步读回等待已提交的后台与设备工作，再支付同步 API 自身服务和同步后的复制/返回成本。
这些等待和延迟仍由同一执行器推进，不在结束后修补时间。准备工作与计算主体沿明确的原生端口连续编排，
普通调用之间不增加全设备完成屏障；遇到已解释的阻塞通信时才汇合并登记到达。
一次原生调用可以发射多个设备操作，提交与返回各付一次，发射与设备服务按实际操作计；纯视图仍可有 CPU 工作。
每次发射有自己的 worker 前段与设备来源引用，worker 可以继续准备下一次发射，不因上一设备任务尚未完成而等待；设备任务仍按生产者与流顺序连接。
导出箭头若落在较大的调用入口，已解释的唯一原生发射 API 可以提供更窄的分段入口；对应关系不明确时不按时间接近选择端口。
框架适配器负责这种调用组合，公共编排器不按原生函数名解释它。来源一次建立计算、准备、通信的 caller 顺序，目标复用这份有序事实，不重复排序。调用间区间按显式来源引用绑定残余近似，只推迟 caller 后继，不阻塞独立 worker 或设备。
通信包络与请求控制的 CPU 工作仍须另行归属，不能用已解释调用冒充完整计算帧。

注意力元数据、KV 分配、请求页表写入、输入构造和必要的采样位置准备统一表示为有来源区间、工作规则和资源绑定的准备序列，角色名称只用于报告，不决定执行分支。
在同一 caller/worker 上，分配可使用另一条设备流；后续 forward 保留对分配产出的依赖，不能将分配改放到计算流。
输入准备可以同时声明进入该序列的生产者流与后续计算流，框架生成记录、等待、销毁及各自工作；共同编排器保留设备前沿，记录后再让消费者流推进。
未固定主机内存的 Ascend 上传单独表达 worker 等流、同步主机复制及 caller 同步返回，不为它虚构设备复制任务。数据就绪的完成节点可以位于 CPU，数据所属设备仍单独保留，后续计算和流交接不能因此改绑到 CPU。
语义输入调用与物理传输工作分开：前者保留框架 CPU 前后段，后者以完整 ACL 上传 API 为成本边界，包含内部 runtime 同步及复制，避免重复计费。
输入准备分别声明 caller 的框架工作、worker 的提交变量和设备实际处理的长度、分块数及实现条件。没有证据分解的入口仍保留上下文，实际数组规模不因 worker 提交量不变而省去；相同设备工作可以跨请求前缀复用成本响应。
有独立 API 边界的 caller 前置工作可单独声明，例如设备张量分配。结构侧生成实际大小和有序前置节点，来源侧仅在同线程、同记录文件与明确原生调用次序下识别对应区间；成本侧从剩余 CPU 片段扣除这些区间，再分别求值。当前前置工作没有提交前的外部中间消费者；需要中间可见性时应扩展端口，不能继续使用封闭前段的串行合并。
连续参数准备并入相邻调用的 caller 前后段，不为没有对外端口的入口、prepare 和整段返回另造节点。
来源适配器按原生 correlation ID 配对入队和后台执行，保留双方资源、区间及记录；共同层核对已声明的调用序列和队列次序，不解析原生名称，也不按时间相近猜配。
这种对应关系只证明队列调用归属，尚不证明内部发射端口、正常 CPU 服务或源成本可迁移；目标的合法新分支仍由执行规则生成。
来源还可保留有端口依据的 CPU 片段及工作描述。结构侧记录可沿用的来源引用，成本侧再核对工作与资源并求值；caller 核对有序配方和各片段工作，worker 与设备分别核对自身工作，不能因一侧改变就把各侧混作同一成本。
Decode 从上一轮输出的请求池缓冲区索引输入 token，再生成位置；这次读取依赖 token 的实际发布，不能用上一轮 caller 返回代替数据可读。
来源分别保留 caller/worker 队列与单流绑定：多流序列不能要求整段只有一个设备资源，也不能仅因缺少单流绑定而猜一个设备。当前只覆盖这种有序交接，不授予任意多流执行资格。

缓存状态同时维护准入预留与实际分配：预留只保留预算，轮到输入准备时才占用物理页并推进页池视图；回载仍按实际申请占用，非空归还重置索引数组偏移。
每轮获得 caller 执行权后，控制器给出这次输入的分配快照，再展开原生工作和内核准备；通信关系提前登记，成本查询不决定分配规则，也不在事后修改已经执行的工作。
它不是物理地址。具体框架如何据此解释索引张量视图和编译规格，属于适配器；成本模型不维护第二份分配状态。

框架给原生调用附上规格描述及必要的编译、首次加载和后续加载工作。单个目标拥有自己的已计划规格缓存，按 caller 执行上下文隔离；共享来源和模型不持有这份状态。
规格命中免去重复准备，新规格在首次使用前增加相应工作，费用仍由共同成本入口绑定。各启动器接口分别记录首次加载；同一 caller 是否已有接口加载，限定共享运行环境的初始化上下文。初始缓存状态必须声明；缺少时给出输入缺口。
worker 回调的首次使用也可由配方声明，状态按目标和实际 worker 隔离。无外部中间消费者的封闭回调可在普通主体前支付一项启动增量；这是一种有说明的重叠近似，不能用于含中间发布或跨调用资源交错的任意子图。
当前 empty 对应相关内存/磁盘缓存均空，prepared 对应所需规格均已驻留；不把“磁盘已有产物但尚未加载”混入两者。
已计划缓存只用于这次目标的工作生成，成本失败后丢弃该目标，不能据此更改真实运行环境或继续复用一个半执行状态。

请求控制器拥有前缀查询及其状态变更，存储预取消费同次匹配结果，分裂产生的索引复制由请求控制器提交。
索引复制和匹配拼接复用结果更新使用的原生配方，按目标树的分段及驻留状态生成；源没有执行的分支仍可生成工作，不能由源配方条数决定目标是否合法。
查询 caller 提交后可继续后续准备，后台工作仍保留到完成，共用原生队列前沿；完整跨流数据因果仍须单独验证。

## 时间条件不能提前猜定

源请求的 token 祖先关系只建立一次，不绑定 base 的页大小。不同 target 按自己的页几何获得逻辑页，
页身份只表示 token 内容关系，不表示它已经位于设备、主机或存储，更不表示已经发布可见。
缓存状态规则在这些身份上决定实际命中、传输和计算；独立成本模型不参与页身份与合法工作量的确定。
目标前缀树按共同前缀压缩和分裂，页身份与树节点身份分开。此前请求提交过的前缀只说明内容曾被计算，
不能代替设备/主机驻留、在途传输和发布状态。客户端声明的后台工作屏障也是程序的一部分，等待由目标执行推导。

源计算帧保留参与请求、执行模式、层位置和行数绑定；固定实现、宽度和布局与 query/context 等变量分开。
目标规划重新绑定这些变量，不复制一份带源耗时的算子。组合调用按真实后端拆成操作，不能同时收费父包络与子操作。
一次原生调用对应一个有序计算配方，配方可展开为多个操作，并显式记录内部数据依赖；配方身份与工作点一起归并，不能只因当前工作量相同就丢掉不同的布局规则。
布局与行数也可能改变展开数量，例如非连续多行写入需要先连续化，单行则不需要；这类变化由工作规则决定，不通过成本倍率吸收。
纯视图变化保留依赖端口，不生成设备服务或查询零成本模型；需要复制时才生成相应工作。
嵌套 probe 不能同时拥有同一次提交。父调用内的额外操作必须由原生顺序和子调用边界限定归属，不能把父包络直接作为额外服务。

阻塞通信由适配器解释参与组、成员、调用序号、输入布局及行数绑定，计算程序据此连接各参与者的前后工作。
同一参与者的后续帧等待前一帧完成；各参与者前置计算实际完成后登记到达，全部到齐才查询一项共享通信服务，完成后释放后续计算。
到达偏斜来自同一个执行时钟，不用源等待或给定零值代替；计算、缓存和通信不各建一套调度器。
当前共同完成端口使用参与组的最晚完成时刻，忽略各成员的完成时间差；这是一项粗粒度近似。
源调用位置只用于已解释的单调用线程、阻塞通信计算子集，不能据此声称其他跨流数据依赖或目标部署已经验证。

缓存独占容量、引用和在途数据状态；分裂时保留引用保护，计算或传输的发布进度各由一个生产者维护，未就绪页不能被读取或淘汰。
备份触发条件由框架适配器声明，缓存核心不维护框架私有策略名或另一套时钟。
有限两级缓存程序组合这个状态组件与计算工作生成器。设备容量不足时选择可淘汰段，必要备份通过统一执行器完成后再释放；
回载来源在尝试设备分配前即受保护，避免为新备份腾主机空间时误删回载来源。传输所有者接管引用，发布与确认仍分开执行。
跨参与进程的计算及写回备份批次使用显式汇合边界，不能把“最后一个回调触发了下一步”当作完整 DAG 依赖。
写回式淘汰在 caller 的同步调用内等待复制批次，期间不让出调用权；等待由复制完成依赖表达，不占 CPU 服务。淘汰和结果控制点共用同一不可变备份原生配方与独立响应，各目标的缓存状态和队列前沿仍各自维护。批次已明确连接的返回与 I/O 端口无需另发无消费者的通知事件。
来源调用序列在一个索引中保留工作定义、CPU 独占区间、资源和原生关联；计算准备与结果整理共用这条绑定路径。
已建模结果 caller 等待自己的输出事件及调度提交，在同一时钟上约束后续迭代；发送与发送后的整理分开，不能因发送而删除尚未完成的工作。
结果处理中的原生调用也共用 caller、worker 和设备编排；CPU 返回释放 caller，原生工作全部完成另有端口，不能把异步控制变成 CPU 完成屏障。
结果序列在真实控制点向缓存状态取得插入的索引复制区间、匹配的索引段数及需回写的页表长度，再由适配器展开原生工作；源操作数量不限制目标合法分支。
控制点只返回有类型的工作描述及完成动作；尚需等待状态时暂停，合法空分支直接继续，不在结构回调内另计时间或提交平行 CPU 工作。备份的异步完成从对应主机调用入口发出，后续主机调用仍等待前一调用及索引克隆返回。共同编排器保留每条 I/O 队列前沿，完成动作归缓存控制器所有，不随计算程序返回而销毁；数据发布汇合各参与者的主机返回和复制完成。
重复页和未对齐尾部也由目标状态决定；Prefill 的即时释放与 Decode 的分组释放分别展开，在各参与者完成页池更新后才归还容量。Prefill 内结束的请求也有独立的即时释放，不能把同一帧的重复页与尾部操作合成一个完成计数。空源回调中的合法新工作使用该帧当前队列，不要求源中已有同名原生模板。
各参与者完成后形成显式汇合，最终发布另等待必要的 KV 输出。来源片段只提供匹配工作的成本依据，不替目标决定复制范围。
同一 caller 的一次调用占用跨越图增量和同步等待；准入遇到未就绪数据或容量不足时让出 caller，状态变化后再尝试，避免挡住归还空间的旧结果处理。
客户端响应由最终发送接出，请求程序、缓冲区和缓存引用继续保留到其后台工作完成；跨请求共用原生队列前沿，后台排空另有完成条件。
生成 KV 的内容登记与数据可读分开。目前以全部所选输出就绪作为新增页的保守发布边界，不能据此宣称逐层计算发布已还原。

文件存储按页面维护持久键和 LRU，预取进度与缓存可见性分开。查询到的页先保留在操作自己的主机缓冲区，
只有控制端接受的连续前缀才进入 radix；停止前已开始的读或复制继续到原生停止点，未接受的缓冲区到 worker 返回后才归还。
写入保持先整理整批、再逐页落盘的顺序；只有文件写完才发布对应键，不能提前将整批内容标为命中。
操作队列保留一个 worker 对当前原生操作的所有权；下一操作的片段在当前操作返回后生成，队列本身不维护服务时间或第二套时钟。
预算事件与服务完成都由同一执行器推进，不能在结束后扣一个“取消耗时”来修改路径。

预取超时、取消、容量释放和是否继续回载可能依赖实际完成时刻，因此第二阶段输出的是带条件的程序。
执行器到达必要边界时，将当前可见状态交给规则，规则生成后续工作，再由成本层估计其服务时间。
所有操作在同一仿真时钟上推进，不能先固定错误分支，再通过时长补偿修正。

执行器拥有节点执行状态、就绪队列和资源前沿；HiCache 状态组件拥有唯一的缓存、容量和发布状态。
请求进度与工作身份也只有一份权威来源。模块登记自己关心的节点动作，禁止每个节点向全部请求和模块广播。
同刻事件保持确定的因果顺序，新依赖只能指向未开始工作。

## 预测需要的细度

| 必须保留的边界 | 可采用紧凑表示的内部工作 |
| --- | --- |
| 命中、页分配/释放、传输提交、完成、发布、取消 | 状态结果相同的连续页范围和固定管理步骤 |
| CPU 提交、worker 入队/返回、设备完成、通信到齐 | 对外部交错封闭的连续服务段或局部静态子图 |
| timeout、重试、正式请求起止和其他决策点 | 不含外部消费者、资源变化或状态变化的内部细节 |

不能把 CPU、worker、设备全部串行求和，也不能因节点成本为零就删除同步或发布语义。
工作不变的区域优先引用共享定义；每个实例保留独立资源和执行状态。
静态区域只在证明无中途外部交错时压缩，保留多个必要出口；条件分支仍在运行时发生。
base trace 允许充分细致，正式源 DAG 与目标程序从构图时就按语义区域和必要端口归纳；细粒度原图按诊断需求生成，不能作为普通预测必经步骤。每次继续展开内部工作，应能说明它对配置决策、外部依赖、资源交错或必要测量的作用；原生函数层次本身不构成展开理由。
性能校准对应这些语义工作与实际工作变量，以小型共享采样提供响应；原生调用编排只在确需细化的局部使用，不要求所有区域展开成逐 API 成本。
NodeScale 关闭时不为潜在缩放强制展开全部原操作；开启时保留命中操作的成本归属，绑定后再安全汇总，不能给整个压缩段套一个只匹配部分节点的倍率。

## 建议的源码布局

以下只定义职责，不预建空目录或占位类：

```text
python/markov/              Python 正式包
  workflow/                 准备、性能维护、预测、评价与搜索的单任务流程
  instrumentation/          通用 probe、观察与原生进程生命周期
  artifacts/                manifest、workload、测量与结果合同
  adapters/                 框架、runtime、模型及部署差异
src/markov/trace_graph/     C++ 核心
  graph/ source/ planning/ cost/ simulation/
                           每个职责目录内同放 .hpp 与 .cpp
src/markov/adapters/        C++ 原生观察与框架/runtime 适配，头源同目录
scripts/                   薄入口、构建与容器调度
configs/                   少量正式示例
examples/                  矩阵复现、研究对照，不承载建模算法
docker/                    各框架与 modeling 环境
```

C++ 以 `src` 为 include 根，使用 `markov/<职责>/<文件>.hpp`，不维护平行 include 树或转发头。
依赖由外围 workflow 经 adapters 指向 core；Python 编排不实现缓存状态机或时序算法；C++ 核心不导入 Python 应用、数据库训练或 target evaluator。
SGLang 与 KTransformers 共享图、成本接口和仿真；HiCache 规则只由 SGLang 适配器启用。
框架和 runtime 使用组合，不能让共享核心反向依赖某个第三方源码树。
研究矩阵、留出划分及跨运行汇总放在 examples；正式流程只维护单任务和通用评价能力。
原生观察所需的环境补丁与依赖声明归适配器维护，third_party 工作树保持上游内容。

## 先支持什么

首轮恢复现有已验证部署的 SGLang HiCache、受控串行请求、Prefill/Decode、完整 HTTP 和原实验面板。
KTransformers 恢复正式采集适配、manifest、普通 DAG 与仿真；不伪造 HiCache。
NodeScale 保留，默认关闭；源静态回放与现行规则下的显式静态 oracle-cost 诊断保留。
跨模型、TP、平台、后端、并发组批及新的执行模式分别声明支持条件；结构可变换不自动证明成本可外推。
