# 用户输入与结果合同

用户提供平台、模型、base 配置、workload 和 target 配置集合；项目准备源输入，并使用适用的独立成本包预测各 target 的完整 HTTP 耗时。矩阵只是实验形式，不是普通预测的前提。

## 两种使用角色

| 角色 | 提供什么 | 得到什么 |
| --- | --- | --- |
| 应用用户 | base 采集配置或 manifest、workload、targets、资源环境、适用成本包 | 各 target 的预测时间、缺口、成本适用范围及近似说明 |
| 平台维护者 | 独立采样方案、资源环境、数据库、训练声明及预算 | 可跨预测组复用的成本包与测量来源、覆盖信息 |

新平台并不保证只凭一个 base 就能工作。采集适配、目标执行规则、资源描述和成本模型都需要覆盖该部署。运行观测提取和 HiCache 目标规则当前主要面向 SGLang/Ascend/Qwen3；KTransformers 共享 manifest、原始 DAG 和仿真入口，不因此获得 HiCache 或完整成本采样能力。

## Base 与 workload

首次使用在普通采集配置中声明模型、`server` 启动参数和 `bench` 工作负载；组请求用 `profile_suite` 引用它。已有采集用 `base_manifests` 明确列出 manifest，不扫描目录猜输入。

workload 的请求数量、输入长度、输出上限及准备/正式阶段由用户控制。没有固定的“必须 5×3”或代码内请求上限。减小输入前须保留想研究的缓存行为，不能把换 workload 后的速度当同工作加速。

受控 token 记录/回放固定请求顺序和实际生成工作量；它复现已经发生的内容，不预测未知 EOS 或未来内容。`max_new_tokens` 是上限，实际输出可能更少；Decode 次数也不能一律用输出数减一代替框架观测。

正式窗口来自客户端 workload 报告，准备阶段可留下缓存状态但不计正式耗时。带 profiler 的 base 用于建图，正常 target 真值只供独立评分，两者不是相同测量口径。

## 一个预测组

可从 [已有输入组示例](../../configs/modeling/hicache_group_example.json) 开始。各字段的职责如下：

| 字段 | 含义 |
| --- | --- |
| `profile_suite` / `base_manifests` | 待采集的 base 定义，或已有正式源输入 |
| `base_config`、`workload_ids` | 多候选时选择源；单 base 不要求重复声明 |
| `target_configs` | target 文件，或包含 `name` 与 `hicache` 的内联对象 |
| `cost_model` | 已训练的适用独立成本包 |
| `cost_database` + `cost_training` | 没有包时从已有库按声明离线训练 |
| `resource_environment` | 实际 device、host、storage、implementation，不是可任意覆盖的标签 |
| `output_dir` | 本组产物目录 |
| 采集预算 | 只在需要相应采集时提供，按成本来源分别累计 |

已有 `cost_model` 优先，不自动重训；新包写本组输出，不覆盖共享输入包。普通预测不自动把当前 base 加入数据库训练，也不读取 target trace 或评分。

未提供成本依据时，准备流程在采集 base 前报告 `needs_independent_cost_model`。显式 `--calibration-only` 可以只准备源输入，完成态为 `source_inputs_prepared`，不是成本齐备或预测完成。

资源适用性保留模型、TP、后端、dtype、设备、CPU 放置及实际执行条件。纯观测开关和诊断接口凭据不构成新的性能平台，但不能因此忽略真正影响执行的参数。

## 预算与缺口

| 预算 | 计量与归属 |
| --- | --- |
| `base_capture_budget` | base 的累计墙钟、启动、请求、tokens |
| `cpu_service_capture_budget` | 同源轻量配对的相同四项预算 |
| 共享补采 `budget` | 独立 runtime/control 采样，不与前两项借额度 |
| `physical_capture.budget` | 物理采样的墙钟、容器启动和逻辑 I/O 字节 |

失败启动也消耗时间及启动数；请求/token 用量不明的失败按预留量计，不当零。重试、恢复或提高上限保留历史用量。只有明确终态能证明未执行时才释放对应预留，不能删除账本重来。

共享成本补采默认关闭。显式开启 `automatic_cost_acquisition` 并提供数据库、训练声明和预算后，先从适用库刷新一次；仍缺真实测量时才选择有边界的独立采样，所得依据供整组 target 共用，再统一预测。缺结构规则、工作变量或采样定义不能靠补采解决，不从逐格误差选参数，也不无限重试同一候选。

物理页域、设备及 CPU 放置在采样声明中给出，不从 target 列表反推。独立性能入口仍需明确模型定义和采样方案，不能只填平台名就从空库自动生成全部成本。

## 输出怎么读

`group_summary.json` 给出准备状态、停止原因和 `prediction.cells`。需要复现时再读引用的 `workflow_summary.json`、`run_summary.json` 和 `runner_config.json`。成功时间为预测值，失败时间为 null，不计为零。

以下资格必须区分：

- 源输入准备好，不等于成本齐备。
- 声明的模型 ready，不等于所有 target 的工作域都被覆盖。
- `EXECUTED` 表示取得执行结果，不等于结构验证或精度达标。
- 成本范围外的可用外推必须报告来源与限制；缺模型不隐式填零。
- 预测最优配置只是模型排序；实测确认之前不能称为真实最优。

完整 HTTP 不排除 residual gap、未归属成本或计算阶段。CPU gap 是两个已观测操作间剩余的时间，可能混有排队、调度及未观测工作，不能全当某个 CPU 操作的服务成本。仍迁移的间隔与外围成本是近似，不是已经解释了成因。

## 实验与搜索的额外合同

准确性实验与搜索是统一预测器的两种上层使用方式。实验可声明多个组并独立评分；搜索从有限配置空间产生 target，期间固定成本包，缺依据后回到独立维护，开启新的比较。

完整 E2E 评分使用同工作量、关闭 profiler 及计时探针的正常测量，同时覆盖 base 和 targets。重复样本取正式窗口算术平均，保留失败及波动范围；不能挑最好的一次。所有选中预测完成后才打开真值，评分不改模型或回写准备状态。

配置选择保留预测并列项。正常样本范围重叠表示尚不能区分，不是等效证明或置信区间；缺少 base 的 self/正常对照时不伪造收益。结构比较和历史静态回放是单独诊断，不能代替正常 HTTP 评分。

应用不需要三份实验报告。只有显式实验报告开关才生成额外源回放和目标结构明细；诊断 full 不改变正式预测规则。

### 搜索输入的单位与预算

`space` 可以列出页大小、L1/L2 容量、写策略、预取策略及门槛。`page_size` 的单位为 tokens/page；容量和门槛可分别用 pages 或 tokens 表达，同一项不能两种单位并用，token 值必须能被所有所选页宽整除。当前要求 host 页数大于 device 页数，预取容量由两者差额派生；这不保证物理内存一定充足。

timeout 参数以秒为单位，只在 timeout 策略分支展开；不相关的参数差异不生成重复执行点。未搜索字段来自完整 target 模板。资源额度与 base 不同，用空间内的 `reference_config` 声明同资源参照。

`objective` 选择一个 workload，或给出非负、总和为正的 `weights`；每个正权重负载都要有 base，全部完成才能得到候选总分，失败负载不能从权重中删除。`max_predictions` 按配置×负载尝试计数，含失败与重试；self 单列，空间内相同执行点可复用。`max_wall_sec` 累计搜索墙钟，包含源准备；采集、训练和正常确认分别计量。

`confirmation.enabled` 默认 false。显式开启并给预算后，先按预测选择同资源参照与候选，筛选样本与最终重复确认样本分开，前者不混入最终均值。样本范围重叠不确认收益，失败不填零，不改写模型排名。设备启动前等待空闲不等于获得了持续独占权。
