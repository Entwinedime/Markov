# 用户输入、运行与结果合同

一次任务是**一个固定模型 × 非空配置集合 × 非空请求集合**。用户提供探索范围、采集部署及预算，系统为缺少来源的实现域选择代表配方；用户不指定 base，也不维护原生请求、KV 或 worker 状态。

本文描述正式入口的输入和产物，并单独列出已确定、尚待实现的调度、前缀缓存与 EP 输入扩展。执行结构使用给定耗时完成条件模拟；实测性能属于后续独立能力，不能从条件结果推定精度。

## 输入

完整示例见 [exploration.json](../../example/automatic_graph/exploration.json)。从仓库根运行：

```bash
example/automatic_graph/run.sh --input example/automatic_graph/exploration.json
```

| 字段 | 含义 |
| --- | --- |
| `framework` | 采集框架；正式入口提供 `sglang` / Ascend |
| `model.path / dtype` | 固定模型在推理容器中的路径及原生 dtype |
| `deployment.physical_devices` | 互异非负整数构成的采集设备列表；TP 本地分片使用一张卡，PP 需要实际原生参与者 |
| `budget` | `native_seconds`、`processing_seconds`、`temporary_bytes`、`retained_bytes` 四项累计额度，非负整数 |
| `configurations[]` | 候选配置；每项有唯一 `id`、`tp`、`attention_backend`、`max_running_requests`、`max_total_tokens`、`page_size`、`max_prefill_tokens` |
| `configurations[].pp / microbatch_requests` | 可选的 PP stage 数和每批成员上限；默认 PP=1，上限为总请求容量除以 PP 后向上取整 |
| `configurations[].placement.devices` | 可选的单机目标设备列表；按 stage 内 TP rank 排列，数量等于 TP×PP，元素是互异的非负整数 |
| `workloads[]` | 请求集合；每项有唯一 `id` 和非空 `requests` |
| `node_durations_ns` | 执行节点种类到非负整数纳秒的映射，明确给定模拟假设 |

配置和 workload 的 ID 使用字母、数字、下划线或连字符，供结果路径使用。正计数参数在有符号 64 位整数范围内，KV 容量至少容纳一页。未知字段拒绝，不静默忽略未实现的 chunk、overlap、缓存或其他选项；不保留旧字段兼容。

模型路径须在部署的原生容器中可访问，镜像及模型文件由部署准备。任务保存实际模型配置和镜像身份，恢复不重新解释镜像标签。

`placement` 声明目标绑定，和采集用的 `deployment.physical_devices` 分开；省略时按逻辑 rank 依次绑定目标设备 `0..TP×PP-1`。纯预测不据此检查现场卡数。当前正式入口采用同构单机、每个逻辑参与者独占一个设备的范围，不接收 host 列表或同卡多 rank；结果中的 topology 明确列出逻辑 rank、目标位置及参与组。

PP 的全局 rank 为 `stage×TP + TP rank`。当前 Ascend 版本不支持 PP2；PP 来源使用实际 TP×PP 参与进程取得，不能仅凭目标模板展开声称单卡可采任意流水线。微批次上限须为正且不超过总请求容量；采集配方和目标上限分别维护。

只改变这些设备绑定不会重采本地计算模板；若实际传输或局部实现改变，仍需相应来源。当前给定耗时不随设备标签变化自动产生带宽、争用或异构设备模型。

## 当前配置复用边界

| 变化 | 正式流程的处理 |
| --- | --- |
| 请求数量、输入/输出长度、到达、并发上限、KV 总容量、非 chunked Prefill 预算 | 在同一来源域内按目标参数与状态变换、重组模板；仍须满足来源规则、模型上下文和原生资源约束 |
| TP、PP、dtype、attention backend、page_size | 分别建立来源域，每域采集全部必要逻辑 rank；目前没有跨这些域的模板迁移 |
| 模型 | 每次任务固定一个模型；换模型建立相应来源，已接入家族通过同一采集流程处理，不要求用户手改模板 |
| chunk、overlap、缓存命中、speculative 等 | 需要扩展控制、状态和相应模板能力；现有合同不接受未实现的选项 |

上述分域是当前实现选择。特别是页大小固定在来源布局条件中，不能用一个页大小的库直接预测另一个；这不表示页布局原则上不能参数化。模型尺寸或 TP 的跨域迁移同样需要补充几何、角色与通信关系，不能只替换一个数字。重新采集也不授予原生后端本身不支持的配置资格。

同域复用不承诺无限形状范围或所有实现分支；实际实例化使用模板条件和已发布参数范围判断。能够展开与已通过独立原生对照分别说明，结构结论不代替成本覆盖或性能精度。

## 请求

每个请求包含唯一非空字符串 `id`、非负整数 `arrival_ns`、正整数 `prompt_tokens` 和 `output_tokens`；时间单位直接为 ns。长度及 `prompt_tokens + output_tokens - 1` 不得溢出有符号 64 位整数。

请求不用按到达排序，同刻按声明顺序处理。输入描述 token 长度和固定输出长度，不提供文本、真实 token 内容、原生 batch 或外部完成时刻。Prefill 产生第一个 token，输出 N 个 token 需要 N−1 次 Decode。内容相关路由、EOS 和缓存命中不由长度虚构。

控制基线是 FCFS、Prefill/Decode 分开。单 stage 保留一个在途批次；PP 以固定 lane 维护微批次，可在不同 stage 并发，结果回传后才提交该批请求效果。控制器为请求预留完成前的峰值页预算，实际页随驻留量分配；模型上下文上限独立于 KV 总容量。框架适配器同时检查原生单请求长度和页预留约束，原生会拒绝或缩短的请求不能作为固定输出预测。某配置无法容纳请求属于该组合的结果，不让其他合法组合因此失去来源。

`max_prefill_tokens` 是当前非分块路径的软合批预算。预算为正时接纳完整请求，再按框架给出的粒度扣除；SGLang 的固定输出、cold-cache 路径按页取整计量，实际 M 仍按原始 token 长度求和。最后一个完整请求可以超过剩余预算。采集规划据此为实际 M 确定行数上界，已有模板仍受其已发布参数域约束。

## 调度与前缀缓存输入扩展（已确定，尚未实现）

配置分别表达 chunk 上限、批次 token 预算、混合组批、Decode 优先及 prefix caching；实际字段随共同解析合同一次接入，当前正式入口尚不接受这些扩展。现有 `max_prefill_tokens` 的非分块软预算语义不静默改变；未知或原生不支持的组合不当作开关已生效。

workload 可选提供 `prefixes`，每个前缀段有唯一 ID、可选父前缀 ID 和本段 token 数；请求通过 `prefix_id` 关联完整前缀路径，累计长度不能超过 prompt 长度。该路径声明内容共享关系，不声明命中率或命中结果；实际可复用长度由驻留、就绪、页布局及实现条件决定。未声明共享的 prompt 部分和生成后缀按互异内容处理；没有共享声明时不得仅凭长度相同产生命中。原生采集按同一关系构造输入并核对，不能沿用全部相同 dummy token 来证明命中。

每个配置 × workload 从统一预热后的空逻辑前缀缓存开始，随后按请求和执行完成事件自然积累。首期仅提供设备 KV 池内的一级缓存，和活动请求共享实际容量；后续多级存储沿位置与就绪接口扩展，不预先开放 CPU/磁盘配置。

Decode 优先从已就绪成员中先分配 token 预算，再处理 Prefill chunk；混合组批另决定是否可在同一批执行两种成员。中间 chunk 不生成输出，缓存命中也不等于已有输出 logits；首 token 所需的剩余工作仍按原生规则执行。

结果区分实际计算 token、缓存命中/驻留及容量占用。请求结束释放其引用与槽位，缓存持有的页可以保留，不要求全部页返回空闲池。跨布局、拓扑或服务实例不自动共享物理 KV；EP 的给定路由也须与声明的共享前缀一致，否则不能授予该复用资格。

## EP 路由输入扩展（已确定，尚未实现）

workload 增加可选字段 `ep_routes`，按目标 **EP 拓扑 ID** 提供路由分配。配置启用某个 EP 拓扑时，与其组合的 workload 必须包含该拓扑的对应路由项；未启用 EP 时不因本条约束强制提供该字段。当前正式解析器尚未接入此扩展，不能把这里的约定当作已可运行的输入。

拓扑 ID 对应配置声明的通信组、专家分片及 expert 到逻辑 rank 的映射，不仅是 EP 数量或物理卡号。多个配置明确使用同一 EP 拓扑时可以选用同一路由项；拓扑不同则分别提供，不隐式迁移路由。配置集包含 EP 拓扑 A、B 时，同一 workload 需同时提供 A、B 两项，才能覆盖这两个预测组合。

路由以请求 ID、模型层和逻辑 token 位置定位，覆盖 Prefill token 与实际 Decode 步，并提供 token 选择的 expert（包括合法多选）。不以采集时的 batch 序号、chunk 序号或墙钟定位；控制器重新组批、切块时按实际成员取得相应路由，目的 rank 和各 expert 工作量由拓扑与路由共同推导。

在配置 × workload 装配边界一次校验拓扑匹配、必要范围覆盖及 expert 选择是否合法。缺少或不匹配时，该组合报告明确输入缺口；其他合法组合可以继续，不使用默认均匀路由、邻近拓扑或自动内容推断补齐。

结果表示**给定路由分配下的条件预测**，不声称从请求长度推导了真实文本路由。路由是工作量与连接的输入条件，不指定原生批次或完成时间，也不免除 MoE 子图和通信来源。若后端还存在 batch 相关截断或重排，需要独立的实现规则；不能把来源批次的最终分配直接外推到所有目标批次。

## 原生来源与统一起点

框架维护真实请求、组批、KV、槽位及 worker 生命周期。系统按实现域在单卡上顺序运行各逻辑 TP 角色，保留本地分片、角色职责和 collective 接口；请求长度不除以 TP。辅助数据与传输替代只服务结构观察，不提供真实通信数值或成本资格。

来源使用完整模型的 dummy 权重。统一预热后，逻辑 KV 清空，保留协议声明的编译、分配和 workspace 状态；模型加载、初始化和预热不计入目标服务时延，但计入采集费用。实际窗口中的分配、等待和搬运仍是业务工作。来源已热不证明任意新路径已热，不直接把小池 workspace 快照用于任意目标容量。

预热使用框架按页大小定义的固定五请求配方，与目标请求集合分开；实际组批仍由原生容量和调度决定。当前 Ascend dense 路径另按原生 ATB scratch 上界，在实际计算 stream 预留 workspace；上界取自硬件核数及模型原生 head 几何，不取自目标请求运行或观测拟合。该预留属于统一起点，不计入服务时延。会话摘要保存 `warmup_requests`，来源环境保存预留约定及实际窗口容量。自定义目标观察只替换 baseline/source 的请求，不把完整目标序列当作预热输入。

代表配方在采集前固定观察点和停止条件，不执行完整目标请求来获取调度答案。缺原型、缺规则、缺给定耗时分别处理；规则或耗时缺口不触发自动补采循环。声明预算为零不会免除所需工作，额度不足时停止并保留已产生的事实。

## 给定耗时与结果含义

`node_durations_ns` 直接按执行种类提供假设，如 `host`、`submit`、`device`、`transfer`、`communication`；名称与[执行种类](../../src/markov/execution/protocol.hpp)一致。每种实际遇到的工作必须有值，不能缺省补零。显式零值的等待仍保留其依赖；服务耗时与等待时间分别处理。

给定值经 `NodeDurations` 交给唯一执行器，依赖和资源决定开始/完成，端口事件反馈后续组批。它不是逐来源 span 的回放表，不读取来源墙钟作为成本，也不构成性能样本、已覆盖特征范围或精度证明。

目标结果分别报告：

- `control_status=complete`：请求在给定耗时下结束。
- `status` 和 `structure.qualification`：结构适用性及仍未证明的边界；请求完成时仍可为 `partial`。
- `first_output_ns / last_output_ns`：scheduler 向下游交出 token 的可见时刻，不包括 detokenizer、HTTP 或客户端接收。
- `state_committed_ns`：请求结束及槽位/页效果提交；不同于输出可见。
- `completed_ns`：最后一个批次的内部结果处理完成，不表示所有异步资源工作已耗尽。

ResultProcessed 推进生成进度和控制状态，RequestOutput 只记录实际输出。所有参与 rank 的内部完成与实际发送角色的输出分别连接，不能以客户端响应或单个 rank 返回替代全体控制就绪。

## 产物与输出粒度

首次运行创建一个 UTC 时间目录，恢复沿用原目录：

```text
data/<UTC时间>_automatic-graph/
├── inputs/                  任务、环境身份及逐组合输入
├── captures/<角色-尝试>/    会话摘要、操作来源及规范物理事实
├── assets/<实现域>/templates.json  共享模板目录与各逻辑 rank 的独立绑定
├── results/summary.md       人读入口、组合结果与累计费用
├── results/<配置>/         默认的逐组合精简结果，含完整请求结果
├── diagnostics/<配置>/     --details 时保存完整目标结果
├── logs/run.log            子进程命令和失败原因
├── state.json              唯一任务状态、来源引用及累计额度
└── work/                   SDK、观察库及尚未发布的角色草稿
```

结果计数中的 `batches` 表示模型迭代，`actions` 表示阶段或结果动作；PP 的一次迭代包含多个动作。明细区域按同一 batch 身份连接各 stage，动作和 lane 单独标记。

默认结果不保留完整历史图。首次运行的 `--details` 在同一业务执行中保留目标图、逐批/逐 token 记录及原始 profiler/runtime 导出；原始导出仍位于对应 capture，不复制到另一份诊断目录。正式来源和模板是机器资产，不因精简展示而裁剪。

默认执行随状态提交释放不再引用的历史，仅保留活跃端口、未完成工作和因果前沿；明细模式保留历史供核对，二者结果应相同。明细中的 `execution_timeline` 按节点列出等待、运行或完成状态，以及已发生的开始/完成时刻；运行节点的 `expected_ns` 只表示按当前给定服务时间的预计完成，不表示请求结束时该节点已完成。仅供诊断的图和记录在生产前受开关控制，不另跑一次模拟。

全部域资产发布后释放任务私有 work，即使目标结构仍为 partial。默认模式在来源成功消费后释放原始 native/runtime 导出，保留规范事实；明细模式保留它们。只清理本任务拥有的资源，不扫描其他历史目录隐式补库。

## 恢复与累计预算

```bash
example/automatic_graph/run.sh --resume data/<UTC时间>_automatic-graph
```

恢复固定原模型、配置、请求和部署；通过 `--input` 只可调整总预算或替换完整给定耗时映射。累计费用不清零，耗时改变从初态重算结果，模板继续复用，不恢复模拟器内部 checkpoint。来源已经采到而解释失败时，优先处理已有事实；已完成且产物齐全的任务重复恢复不新增原生运行。

恢复不因源码变化自动升级已发布资产。观察合同或结构规则改变时，显式建立相应新资产与验证基线；保留事实足够时可重做解释和建库，不重复采集原生执行。

同一运行根由非阻塞锁保护，不能启动两个写入者。工作进程使用单调时钟和截止时间；未确认返回的中断保守保留预占费用，明确返回后按实际耗时结算。临时峰值按运行目录采样，保留量不含 work；这两项不覆盖容器层、共享构建缓存或系统临时空间。

任务 `state.json` 的 `complete` 表示所有组合产物已发布，结构资格由组合结果单独声明；`partial`、`failed` 或 `interrupted` 保留失败及恢复信息，不解释为结构或精度通过。冻结后的独立结构验收需另有原生目标证据，给定耗时结果和明细开关都不能代替它。
