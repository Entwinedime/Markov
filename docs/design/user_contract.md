# 用户输入与结果合同

一次任务是一个固定模型、非空配置集合和非空 request workload 集合。用户提供探索范围、采集部署及累计预算，系统选择代表来源并管理原生生命周期；用户不指定 base，不维护 KV、worker 或模板。

本合同约束输入含义和结果边界，不宣称任意组合已经实现或验证。正式入口随当前工作流交付；旧细图命令、轻量控制选择和批次回放不属于现行用户接口。

## 模型、配置和部署

| 内容 | 含义 |
| --- | --- |
| framework | 原生框架及相应 adapter，SGLang/Ascend 为接入主线 |
| model.path / dtype | 模型路径和原生 dtype；任务固定一个模型及其配置/来源 |
| configurations | 唯一 ID 的配置集合，声明 backend、页布局、并行、调度和容量 |
| workloads | 唯一 ID 的请求集合，可声明共享前缀及按 EP 拓扑给定的路由条件 |
| deployment.physical_devices | 本次采集使用的互异非负物理设备；Ascend 按升序声明，映射为原生逻辑设备 0、1……；与目标逻辑拓扑分开 |
| placement | 目标逻辑 rank 到设备的位置绑定；纯预测不据此要求现场具备对应设备 |
| budget | 原生、后处理、临时和保留存储累计额度；失败及恢复不清零 |
| node_durations_ns | 结构阶段明确给定的服务时间假设，单位纳秒；不是测量或精度证明 |

控制使用原生代码，并通过共同资源和完成接口驱动展开。真实请求、KV 与 worker 在采集时归框架管理；预测时原生决定逻辑动作，核心维护资源和模拟时间。

同实例配置包含 TP、可选 PP/EP、max_running_requests、max_total_tokens、max_prefill_tokens、page_size 和 attention backend；可选择 chunked prefill、mixed 及一级 prefix cache。微批次上限与原生 PP lane 分别解释，不从总请求数直接决定实际 batch。

PD 配置分别声明 Prefill/Decode 的拓扑、槽位和 KV 容量；两池模型、dtype、backend 和页布局一致，资源独立。chunk 由 Prefill 侧推进；两池的缓存分别服从原生支持范围和各自来源实现，不共享缓存状态或隐式沿用另一池的开关。不把同实例 serving 的来源直接当作 PD 来源。

所有配置先满足原生框架与设备的真实约束。项目不 patch 上游强行运行不支持的模型/并行策略；无法运行、缺来源、缺变换、缺时间依据及尚未验证分别报告。

外部输入在边界检查一次：类型、整数范围、唯一 ID、正容量、合法请求长度及路由覆盖等必须成立。未知或未实现字段不静默忽略，不保留旧字段和控制分支兼容。

## 来源与配置变化

| 变化 | 处理原则 |
| --- | --- |
| 请求数量/长度、到达、并发和 KV 总容量 | 同域内根据模板参数、状态和有限规则变换、连接；不保证任意范围 |
| 模型、dtype、TP/PP/EP、backend、框架镜像、page_size | 规划相应新来源，模型/原生配置自动解释的部分不要求用户手改模板 |
| chunk/mixed/cache 机制 | 建立相同机制的来源，参数变化按规则展开，组合须有实际资格 |
| 仅设备位置绑定 | 不改变本地结构时复用定义；真实链路/异构成本另需依据 |
| overlap/speculative/多级实际搬运等扩展 | 需要明确控制、状态与模板能力，不因原生包含代码就自动授予支持 |

不同来源域是工程支持边界，不是理论不可能声明。粗化允许隐藏内部 kernel 差异，但不能隐藏目标变换所需参数和外部作用。能够展开、具有独立结构证据和性能可预测分别说明。

可隔离本地分片时在一张卡顺序观察代表角色；需要真实 PP/EP/PD 协议参与者时运行实际组。代表观察不减少必需协议进程，采后去重不能冒充原生采集次数减少。单卡替代不提供通信时延或争用资格。

## 请求与内容条件

每请求包含唯一非空 id、非负 arrival_ns、正整数 prompt_tokens/output_tokens，时间为整数纳秒。长度和合计不溢出有符号 64 位范围，并满足模型及原生单请求限制。

请求无需按到达排序，同刻按声明顺序处理。长度和固定输出不提供原生 batch、真实完成时间或控制答案；Prefill 产生首 token，输出 N 个 token 对应 N−1 次 Decode，具体切块和组批交给原生。

workload 可用 prefixes/prefix_id 声明内容共享关系；前缀 ID 唯一、父关系无环、累计长度不超过 prompt。声明不直接给命中结果，实际复用取决于驻留、就绪、页及实现条件。未声明共享的请求部分和生成后缀为私有内容。

采集和原生控制共用确定的合成内容，分歧处实际 token 不同，不用长度相同虚构命中。需要的词表分支超过模型词表时明确报错；合成输入和注入的固定输出不代表真实权重自然生成。

每配置×workload 从统一预热后的已声明逻辑初态开始。加载、编译、预热不属于目标服务窗口，但计入采集费用；后续窗口内真实分配、等待和搬运必须承接。workspace 热状态与逻辑 KV 冷状态分别记录。

## 调度、缓存和路由

chunk 上限与 Prefill token 预算分别声明，非分块软预算的原生语义不改变。中间 chunk 推进驻留而不提前输出。mixed 决定能否同批执行 Prefill/Decode；Decode 准入/预算优先级按原生模式解释，不增加理想化自写策略。

prefix cache 首期为设备 KV 池内一级缓存，与活动请求共享真实容量。请求结束释放槽位与引用，缓存页可继续驻留；只比较终态空闲页不足以证明引用、淘汰或背压正确。

EP 按拓扑 ID 给定路由：配置声明 ep.id/size，workload 的 ep_routes 对应每个使用的拓扑。普通 token 的专家选择可在不同拓扑相同，专家到 rank 的部署映射归 adapter；不隐式套用另一拓扑条件。

assignments 按 request、layer/token 左闭右开区间及全局专家 ID 描述，专家互异且数量符合 top-k，覆盖全部被计算逻辑位置。MoE 的 EP1 同样需要条件，dense 不接收专家路由。

padding 按拓扑给出可能补齐尾部位置的专家条件；实际批次补几行、worker 分配及附加通信由 adapter 推导，用户不维护逐 batch 状态。当前统一不自动获取真实权重补齐元数据，不混用自动/手工两种模式，不从补零默认专家。

原生和预测消费相同逻辑路由与 padding 条件，后端重排/复制/截断分别有实现依据。条件预测不声称从请求长度得到真实文本路由，dummy 权重观察不代表自然路由。

MoE 前缀共享同时核对 token 与全模型实际专家层的逐位置有序专家条件；区间覆盖普通层时，该层不参与缓存身份。PP 各 stage 使用同一份全模型专家层集合，不能仅按本地层判定共享。首次分歧后不继续共享，padding 不进入请求内容键。PD 交接和重新组批按请求逻辑位置解释，不使用来源 batch 序号。

## 时间依据与结果资格

结构阶段可提供粗图工作的给定服务时间，或显式使用固定真实案例的实测服务/事件条件进行验证；缺少依据不默认补零，零时长同步仍保留其依赖。原生控制消费核心虚拟时钟与事件，不以宿主进程的实际运行时间决定模拟结果。

旁路输入与待验证输出必须明确区分：验证构图时可输入真实动作、批次和调用参数，核心独立生成图；验证原生控制时，动作、组批及资源操作由实现产生。局部检查若给定查询或分配答案，被替代模块不取得资格。任何验证均不把目标图体或依赖复制为预测答案，也不借目标补充来源模板；验证输入不要求扩展 workload 字段。

实测时刻、可见边界区间及必要同刻顺序按其真实依据使用；区间约束采用满足依赖的最早可行时刻，报告仍区分确定时刻与区间内的一种执行。工作按请求、阶段、token 范围、rank 及必要因果位置对应；首个无法对应位置明确报告，不按第几个轮询、批次或节点硬配。

结果分别说明流程是否完成、来源是否合格、实际对照范围及结构结论。已匹配、确认差异、证据不足、原生限制、依赖阻断和工具错误分开；不把全部结果固定标为 partial，也不因内部记录未细分自动判错。

粗图对照核对工作、参数、数据/资源依赖、通信及状态和完成边界；不要求内部 task 名称/数量相同。来源或真实目标缺少必要外部作用时仍报告对应范围不足。

请求输出表示 scheduler 向下游交出 token 的可见时刻，不包括 detokenizer、HTTP 和客户端接收。内部状态提交与用户输出分开，CPU 返回与设备完成分开。给定耗时/旁路均不构成性能模型或精度结论。

## 产物、恢复与隔离

每次完整任务采用一个 UTC 时间根，分开 inputs、sources、assets、targets、results、logs、work 和可选 diagnostics。正式模板和粗图是机器资产，默认人读结果精简，不内嵌全量 trace 或完整历史展开。

原始 trace 只按构图/取证消费者生成和保留，已消费中间件及时释放。默认与明细使用同一次执行及相同业务结果，不能另跑一次模拟或只压缩 JSON 排版充当精简。

新任务只读取明确输入和本次发布的来源/资产；不搜索历史 data 自动补库，不恢复旧细图状态或旧镜像身份。来源和目标用途隔离，独立目标不能成为模板答案。

同一任务只允许一个状态写者，镜像与原生身份记录实际值。原生阶段、角色事实闭合、模板发布和任务退出分别交接；离线处理失败优先复用本次完整事实，不反复启动原生。

恢复保持模型、配置、请求、生产依据及累计费用。输入或规则改变时明确建立相应新资产与评价基线，不自动兼容旧格式；时间依据改变从合法初态重算，不续用旧预测。

失败、超时、中断和预算停止保留真实原因，不发布成功资产。临时与保留量分别核对，只清理本任务拥有的资源；结构资格、流程退出和精度不得相互代替。
