# 用户输入、运行与结果合同

本文维护稳定的产品合同，不记录实验成绩或实施进度。正式任务是一个固定模型、非空配置集合和非空请求集合；用户不指定 base，不为普通预测填写节点成本或原生批次状态。

## 项目输入

项目 JSON 的路径相对声明它的文件解析。输入边界拒绝未知字段、错误类型、重复身份、空集合和无效预算，不保留旧格式兼容。可解析不等于该实现组合能够预测。

| 字段 | 含义 |
| --- | --- |
| `model.path` | 全任务固定的模型路径；更换模型新建任务 |
| `model.tokenizer_path` | 默认与模型路径相同；token 输入无需加载 tokenizer |
| `model.configuration` | 可保存完整原生模型配置；省略时公开工作流从本地模型的 config.json 读取一次。离线复用需声明该快照 |
| `configurations[]` | 每项含唯一 `id`、`framework`、`environment`、完整配置文件 `config`，不继承其他候选 |
| `environment` | Docker runtime、启动用 service，以及非空、不重复的非负设备编号；`image_id` 可声明固定 Docker 镜像 ID，省略时公开工作流解析本地镜像 |
| `request_workloads[]` | 每项含唯一 `id` 和请求文件 `path` |
| `collection.base / performance` | 默认禁采；`allow_run` 和累计 `max_wall_time_sec`。启用时预算为正 |
| `assets.templates[]` | 显式结构 manifest，可附该来源的 `node_durations`；默认空，不重复来源 |
| `assets.performance_manifests[]` | 显式独立性能样本，由拟合进程转换为候选 |
| `assets.cost_models[]` | 显式候选成本文件，声明顺序决定重叠候选的查询顺序 |
| `output.directory / diagnostics` | 必填输出位置；默认只输出精简报告和必要机器数据，验证明细默认关闭 |

框架取 `sglang` 或 `ktransformers`，实际支持按框架/模型/后端/环境组合判断。框架配置只含 `parameters` 和可选 `model_assets`；接受的参数全部显式填写，采集还要记录原生最终生效值。

| 框架 | 参数字段 | 额外模型资产 |
| --- | --- | --- |
| SGLang | `device`、`tp_size`、`attention_backend`、`max_running_requests`、`max_total_tokens`、`chunked_prefill_size`、`max_prefill_tokens`、`schedule_policy`、`disable_radix_cache`、`disable_overlap_schedule`、`disable_cuda_graph`、`enable_mixed_chunk`、`enable_hierarchical_cache` | 无；使用固定主模型 |
| KTransformers | `backend_type`、`tp`、`max_batch_size`、`chunk_size`、`cpu_infer`、`cache_lens`、`sched_strategy`、`use_cuda_graph` | `gguf_path`、`optimize_config_path` |

字段保持原生整数、布尔和字符串类型。SGLang 的 `chunked_prefill_size` 为 −1 或正整数，其他计数为正。主模型路径不重复放入 parameters。

SGLang 普通结构及性能观察由框架适配器选择首张声明设备，使用单 worker 执行逻辑 TP 的本地分片；请求长度和 batch 不随 TP 缩小。原生多卡对照与真实通信测量仍要求每个 TP rank 有一张声明设备。局部观察本身不授予完整模型、多 rank 装配或性能资格。

`environment.measurement` 可提供 `cpu / device / runtime` 测量条件快照，未知项用 null；位置字段不能代替它。纯预测只读取声明，不临时查询硬件。未声明目标设备条件时，结构分析明确限定于来源模板硬件；声明了设备条件则需匹配来源设备及 runtime。实测成本还须匹配相应工作与测量条件，未知条件不视为相等。在线采集只回填对应配置的未知条件，不覆盖用户已声明的条件。

预测固定使用轻量控制器、`modeled` 范围和统一预热后的 cold logical KV。没有 `simulation`、`initial_state` 选择项；其他控制器、暖 KV 或 HTTP 范围需有实际能力后再建立合同。

## 请求合同

请求文件包含非空 `requests` 数组。每项有唯一非空 `id`、非负整数微秒 `arrival_offset_us`、正整数 `output_tokens`，以及 `input_tokens` / `text` 二选一。

- token 数组非空且元素为非负整数，真实运行还须满足模型词表。text 非空；分词只执行一次并保存实际 token。预测 plan 对尚未实现的 text 归一化明确返回不支持，原生采集准备可分词。
- 输入不必按到达排序；同刻按声明次序。到达偏移在边界转换成 ns，不以客户端串行请求替代开放到达。
- 输出长度是条件输入，不预测内容或 EOS。Prefill 产生第一个 token，输出数为 1 时不调用 Decode。
- 同刻原生预分词请求可以合为一条批量消息，实际 batch 由原生 scheduler 决定；整组返回不能代替逐请求 Published。
- 内容相关路由、缓存命中和专家选择不能由长度虚构。输入序列改变后新建任务，不修改已有结果的身份。

## 统一稳态起点

结构采集、独立性能采样和目标观察共用有界预热协议：引擎已准备、无在途业务请求、逻辑 KV 清空，保留协议允许的编译/分配缓存和 workspace 状态。

模型加载、运行时初始化、首次编译和预热不进入预测时延，但全部进入采集开销。一次 Prefill/Decode 不证明全部所需特征已热；预热覆盖依据有限实现条件，不能执行完整目标序列预取调度答案。

原生框架负责请求结束和 idle/清理确认。客户端收到响应不能替代确认，也不能仅凭接口名推断缓存保留效果。窗口内合法的分配、扩容和等待仍属业务工作。

记录预热输入、实际配置和初态；不同配置不直接继承同一容量快照。初始化证据缺失保留缺口，不能补造空缓存。计时窗口出现未覆盖的首次编译时，该窗口不能取得稳态精度资格，不以减常数或删除高值修正。

## 结构、成本与条件输入

模型路径、service 和卡号用于定位与启动。模板按完整原生模型配置、固定镜像身份、有效执行布局、初始化和有限变换条件复用；只换卡号不使结构失效，镜像标签不能代替固定镜像 ID。没有模型修订或内容证据时，不宣称权重内容相同，也不扫描大权重生成校验码。输入快照保留配置中的原生修订信息。

输入已保存模型配置和镜像 ID 时，离线预测不要求本地模型、原生镜像或设备。真实采集仍需本地资源；启动前核对本地模型配置，并固定镜像 ID，恢复不重新解释镜像标签。成本资格独立于结构复用，当前候选仍限已记录的测量部署，不因结构可迁移而授予跨硬件时延。

加载成功只说明资产可读，不表示目标所有阶段、rank、资源和参数均可展开。共同候选及局部供体由实际模板规则资格判断，不能按形状相近选择。

独立性能 manifest 由有锁的拟合进程消费，生成候选置于显式成本文件之后。预测只读候选，不接触原始时延样本；候选命中不自动取得精度资格。

给定耗时文件包含 `base_manifest`、`unit="ns"`、非空 `assumptions` 及 `values`，每项含 `work` 选择条件与非负整数 `duration_ns`。`work` 使用共同成本查询的字段，必须有 `kind`，可限定 `name`、`measurement_boundary` 和 `features` 等实际字段；对象按声明字段匹配，数组及标量完整相等，按声明顺序选择首个匹配项。例如 `work={"kind":"cpu"}` 明确假设该来源范围内的每个 CPU 服务区间耗时相同，不要求按动态节点填表；未命中的工作保持缺口。

给定值对应装配后的一个服务切口，CPU 分区合并后不再逐来源碎片相加；规则生成的工作使用同一查询，不需要伪造来源 span。manifest 限定假设作用域，source span 只作追溯。给定值仅用于条件结构分析，不能作为训练标签或正式精度依据；输入错误与结构来源缺失分别报告，不能因此重采结构。旧的逐 span 格式不再读取。

逻辑通信使用 `kind="collective"`、`collective_rank_device_service` 表示本 rank 的设备 transport 服务。特征包含操作、`input_shape`、`data_type`、参与 `ranks`、本地 `rank` 和 `execution="rank_device"`。原生主机调用、异步 worker、事件和布局工作保留其普通 CPU/设备查询，必要 CPU 区间携带 collective 工作上下文，不另收一次主机包络。参与组共用工作定义，各 rank 的 transport 按真实依赖并行，完成只释放本地消费者；不再额外收取一次全组设备包络，也不与物理通信任务同时计费。缺少工作描述、必要依赖或状态效果时，不能仅凭给定耗时宣称结构完整。

原生输入广播使用同一通信查询，`execution="host_synchronous"` 与设备服务分开。其条件完成包络保留本地提交、等待和普通 CPU 工作，不代表精确后台启动模型。目标消息已知但载荷字节尚未取得编码资格时，真实成本保持合同缺口；明确的 host 给定假设可以驱动条件结构。PG1 观察字节不自动迁移到目标请求，PG1 时延不进入真实多 rank 通信成本。

该包络的本地完成还受适配器声明的必要远端入口约束；给定耗时不删除这些等待关系。取得载荷字节本身不授予真实成本资格，后台进度、PG1 主机路径与目标多 rank 路径的适用性仍须分别确定。

范围内未知成本不能填零、借用来源墙钟或父包络。结构支持、样本覆盖、成本可查询与精度通过是不同结果。

## 自动运行与恢复

1. 先解析配置集合并复用显式资产。仅缺少兼容结构来源且获准采集时，才在累计 base 预算内执行代表配方；规则或成本缺口不触发结构采集。
2. 实例化产生统一工作查询，跨组合归并缺失成本。适配器构造有界采样配方，实际命中由原生工作与完整成本查询共同确认。
3. 新模板或成本资产发布后，从初态重算全部组合。没有新资产时复用已有结果，不拼接不同轮次的组合，也不恢复模拟器内部 checkpoint。
4. 不能构造、已经尝试而无新增证据、预算耗尽或合同不足时停止并保留原因，不无限循环补采。
5. `explore` 在全部预测完成后固定资产，再用独立预算取得原生验证端口；预测缺数据时不进入验证。验证只能读取，不能反哺模板、拟合和调参。

`resume` 的预算参数表示新的总额度，已用量不重置。更换模型、配置或请求须新建任务；尚未固定验证的任务可以显式替换完整资产列表。

| 情况 | 处理 |
| --- | --- |
| 预测/拟合/结构比较宿主中断而容器仍活动 | 接回已有命名进程；活动期间修订不生效，不启动替代容器 |
| 原生采集被中断 | 停止本次采集、保留消耗和交接；显式恢复按原输入及剩余预算处理 |
| 原生完成、后处理未交接 | 优先消费已有事实或继续处理，不能重复采集 |
| 确定的后处理失败 | 保留失败收据；修正原因后显式重处理，不自动重试确定失败 |
| 部分组合失败 | 保留其他组合结果和共享资产，任务总体反映未完成项 |
| 终态重复恢复 | 读取正式结果并完成必要清理，不新增预测轮次或设备运行 |

输入修订和旧结果失效一起登记，未交接完成不返回旧结果冒充新输入输出。只有正式发布并被消费确认后，才能清理本任务拥有且无活动写入者的临时产物。预测、拟合、采集各自的真实锁和预算职责保留。

## 产物合同

一次全流程使用一个 UTC 时间相关运行根，恢复沿用该根。面向读者的产物分为默认精简结果和按需验证明细；模板、样本及待消费需求是机器资产，不受展示开关裁剪。任务状态、输入快照、资产 manifest 和处理收据各有唯一写入者，不复制成多套状态。

```text
data/<时间>_<任务>/
├── run.json                       # 小型状态入口：预算、交接及产物引用
├── inputs/                        # 规范输入快照
├── assets/                        # 正式模板、成本及共享 CPU 区间目录
├── captures/
│   └── <base|performance|validation>/<采集号>/
│                                  # 轻量 manifest、必要规范事实/样本
├── results/
│   ├── summary.md                 # 人读总览：结论、限制、下一步
│   ├── prediction.json            # 每配置 × workload 的精简指标与覆盖
│   ├── requests.jsonl             # 按需读取的完整逐请求结果
│   ├── comparison.json            # 仅实际独立比较后的精简结果
│   ├── comparison-requests.jsonl   # 有实际可比请求时生成
│   └── sampling-plan.json         # 仅待处理时保留的采样计划摘要
├── work/<阶段>/<轮次>/             # 完整需求、配方等尚未消费的机器交接
├── logs/<阶段>/                   # 进程日志，不保存第二份业务报告
└── diagnostics/<阶段>/<轮次或采集号>/
                                   # 开启后保留的验证明细与原始观察导出
```

仅创建有实际产物的目录和文件；多组合明细以配置/workload 身份分组，不为每个节点或请求建立文件，不嵌套第二个运行根。`run.json` 保存状态、入口和明细是否留存，manifest 保存身份、数量与本地引用；两者不内嵌完整图、特征或样本清单。不靠扫描历史 data 隐式加载资产，外部复用资产保存显式引用而不复制。

### 精简结果与必要数据

精简结果保留组合身份、状态、预测范围与资格、聚合指标、假设引用、结构/成本覆盖数量、缺口分类和必要后续动作。例子使用固定的小展示上限并注明“展示数/总数”，不逐项内嵌节点特征、全部端口、来源链或原生配置。共同假设、来源及模型信息只保存一次。结果体积主要随组合数和缺口类别增长，不随展开节点数增长。

完整逐请求指标使用独立的行式结果，保留配置/workload/request 身份；独立比较的逐请求明细同样与汇总分开。它们是正式结果，关闭诊断不删减。不完整组合只写实际产生的结果，不补造指标。

自动采样消费完整工作需求和配方，不能反读精简报告中的例子或依赖诊断图。需求按实际特征去重，作为机器交接保存到被确认消费为止；`sampling-plan.json` 只给计划规模、原因、预算及当前交接入口。预算耗尽、失败或 `needs_data` 时仍保留恢复必需的交接；成功消费后释放临时数据并更新引用。模板、规范事实、样本和正式成本按复用需要保留，不为了缩短 JSON 删除有效数据。

未覆盖需求使用 CBOR 保存，其中的 CPU 查询包含采样需要的命名服务边界；配方中的批次来源按调用共享。采样规划消费完整需求和运行状态，报告示例不参与规划，也不另建来源区间目录。完整采样计划在 `work/planning/` 保存一份，结果摘要引用它。必要的大型机器数据采用结构格式或行式/压缩载体，manifest 引用其唯一正文；仅改压缩率或取消 JSON 缩进不算内容精简。

### 输出开关与生命周期

沿用唯一的 `output.diagnostics` 布尔开关，不增加并行的 full/verbose 开关：

| 值 | 输出行为 |
| --- | --- |
| `false`，默认 | 精简报告、完整请求结果和必要机器资产；不构造仅供排查的全量图/端口/覆盖来源明细 |
| `true` | 在相同业务流程上额外记录实际目标图、依赖/端口、完整覆盖与来源、原始观察导出等验证明细；已有资产只引用，不再复制 |

开关由入口解析一次并传给产物生产者，在记录和序列化前控制额外输出，不先写出巨量明细再裁剪。诊断按实际执行流增量落盘，不另跑一次仿真、不为记录而留住全部历史图。这里的“完整”指本任务声明流程及实际执行轮次的验证信息，不扩展到全部框架后台活动或模型张量。

验证明细用于核对结构与归属，和独立目标对照是不同职责。开启明细不自动触发采集或对照，不改变预算授权、成本查询和模拟结果，也不允许将对照数据用于拟合。失败保留简短原因与必要恢复信息，不自动升级全量输出。

默认原始导出在规范化及消费确认后释放；诊断开启时需留存的原始导出在验证目录保留唯一副本，持久引用不能依赖已清理的 work。未记录、已释放与已有明细分别说明；事后打开开关不能恢复已丢弃信息，只能从留存事实重新生成可推导部分，不静默重跑或补采。

## 状态、指标与比较

组合按配置顺序 × workload 顺序输出，含身份、`status`、`scope`、指标、缺口、假设和来源。累计采集用量在任务根共享，不按组合重复计费。

`complete` 表示条件执行完成；`needs_data` 表示缺必要数据；`unsupported` 表示范围或规则不支持；`failed` 表示执行失败。任务 `finished` 可以包含未完成组合，不能解释成精度通过。结果没有隐含 base/speedup 或综合排名。

| 指标 | 定义 |
| --- | --- |
| `window_time_ns` | 最后 Published − 最早逻辑 arrival |
| `request_latency_ns` | 请求最后 Published − scheduler_ready |
| `ttft_ns` | 请求首次 Published − scheduler_ready |
| `driver_request_latency_ns / driver_ttft_ns` | 从计划 arrival 起算的对应间隔 |
| `tpot_ns` | 首末 Published 间隔 / (输出数 − 1)；单 token 为 null |
| `output_tokens_per_sec` | 总输出 token / 窗口秒数 |

Published 指逐请求 RequestOutput 实际交出新增 token 的时刻，边界为 scheduler 向 detokenizer 交出 token 的输出服务返回，不包含下游 detokenizer、HTTP 或客户端接收。每轮内部 ResultProcessed 只推进生成/KV/控制状态，空消息或无该请求 payload 的返回不算 Published。非流式短请求可能只在终态输出，此时 TTFT 等于请求完成时延，输出数大于一时 TPOT 为零；该值不表示内部逐 token 计算没有耗时。

输出由实际发送角色决定，调度继续所需的完成参与者单独声明。其它 rank 的本地返回可以约束下一轮入口，而不改写当前输出时刻。独立端口比较按观察到的输出事件计算入口与发布时刻，全部 rank 的内部进度覆盖和入口分散另行保留。

非重叠控制路径可能在上一批返回后才接收已到达请求；逻辑到达、调度可见和执行准入是不同边界。原生比较必须对齐同一请求、端口及可关联时钟，不能从两个未关联时钟直接相减。

独立验收前固定输入、支持域与误差门槛，先核对结构、局部成本和重叠，再评价请求指标。少量样本列出逐项结果，近零值另报绝对误差，缺失或零分母不伪造比例。验证输入用于修正后转为开发证据，须另选独立输入；文件更名或重新压缩不产生独立性。
