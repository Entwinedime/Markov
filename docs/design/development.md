# 构建环境、入口与实现维护

本文维护稳定环境和操作原则。构建、安装或命令存在不表示模型、结构及性能资格通过；只使用仓库实际交付的入口，不保留旧细图 CLI、回放命令或路径别名。

## 环境

| 镜像 | 职责 |
| --- | --- |
| markov-next-modeling:ubuntu24.04 | C++23 核心构建、静态工具和纯预测 |
| markov-next-sglang-env:ubuntu22.04 | 原生推理的软件基础，不安装项目业务观察流程 |
| markov-next-sglang:ubuntu22.04 | 官方框架、当前采集包和必要原生观察资源 |
| markov-next-control:ubuntu22.04 | 无设备原生控制及元数据代理，不执行真实模型 |

标签按职责稳定命名，不含日期；实际运行记录 image ID、原生版本和模型来源。基础层可以共享，正式推理/control 包随其源码和安装资源改变后重建，不通过临时挂载旧包替换镜像内容。

Compose 位于 docker/compose/inference.yml，镜像前缀默认 markov-next。推理镜像从官方 SGLang 工作树安装框架和 wheel，control 使用同一软件来源并隔离设备发现/采集插件。必要环境补丁属于 adapter，Dockerfile 只负责组合和调用。

modeling 使用 Ubuntu 24.04、GCC 13、C++23、CMake≥3.20、Ninja 和 nlohmann-json≥3.11，关闭编译器扩展。Python 源码保持 3.10 语法基线；原生镜像的实际 Python/ABI 单独记录，不为语法形式升级推理栈。

真实 NPU 采集在匹配 PyTorch/torch_npu/CANN 和模型的推理容器中进行；采集桥在对应 SDK 环境构建，不把 SDK 链入共同核心。宿主只编辑源码、调度容器和操作 Git；核心配置、编译、静态工具和执行均在 modeling 内完成。

构建代理为宿主回环地址时，可通过 MARKOV_BUILD_NETWORK=host 选择构建网络。正式纯预测保持无设备、无网络，不加载模型权重、采集插件或目标验证数据。

## 构建与运行边界

正式 CMake target 必须对应实际交付代码，不为保留旧入口构建已经废弃的应用。删除 target 同步删除源文件、脚本、Python 导入、Docker COPY、示例和说明；新目标完整交付后再提供其公开运行命令。

程序只消费明确输入和本次发布的资产，不能搜索历史 data 自动补库。执行中的程序与重建分别持有稳定生命周期，工作进程退出前不释放其保护；新任务和恢复均由单一写者维护状态。

真实来源、离线解释、模板发布和纯预测分别交接。CPU 后处理失败优先消费已经闭合的本次事实，不重新启动原生；原生阶段成功、事实完整、资产发布及整个会话正常退出分别判断。

结果通过临时文件原子发布，输入与输出不能互相覆盖。失败不发布空成功文件，不用旧结果或累计日志误认本次通过。旧资产不自动升级格式，明确重建，不维护双格式兼容。

## 一键执行结构示例

`example/coarse_graph/run.py` 在宿主调用现有 workflow，顺序完成来源规划、有限采集及模板生产，再展开配置×workload 的全部目标。宿主只需 Python 标准库和本机 Docker CLI；协调进程使用 control 镜像的 Python，实际采集、后处理和预测仍由各自正式入口管理。运行前准备三个业务镜像及 modeling 构建的程序，模型须在本地。

默认输入 `example/coarse_graph/input.json` 为 Qwen3-8B BF16、两个 TP1 池容量配置及两个小请求集合。可复制修改模型路径、配置和 workload，并通过 `--input` 提供；默认模型位置为 `/models/Qwen3-8B`。部署文件由使用者明确提供，例如 `{"physical_devices": [4]}`，其中物理卡必须由本次任务独占；示例不会自动挑卡。PD 部署还需提供 store_url。

```bash
python3 example/coarse_graph/run.py \
  --deployment /path/to/deployment.json \
  --native-budget-seconds 900 --postprocessing-budget-seconds 600 \
  --attempt-limit 1 --storage-bytes 32212254720
```

这组额度用于默认单来源域示例，都是上限，不是实际开销承诺。增加来源域时需相应明确累计额度；不会自动放宽、重试或补采。`--timeout` 默认 900 秒，分别限制每次原生尝试和每个目标预测。程序默认 `build/coarse-graph/markov`，可用 `--binary` 指定其他 modeling 构建路径。

每次调用创建 `data/<UTC运行时间>_coarse-graph/`，不扫描或引用历史目录：

| 位置 | 内容 |
| --- | --- |
| inputs/ | 解析为绝对模型路径的探索输入、部署、三个镜像 ID 及本次程序快照 |
| plan/ | 初始来源域及代表输入、简短规划说明 |
| collection/sources/ | 各来源域的原生任务及不可替代的原始观察 |
| collection/assets/ | 各来源域的模板生产目录，包含发布模板、生产记录及必要日志 |
| targets/<序号>/ | 该目标的 input.json 和 prediction/；使用数字目录，不把用户 ID 当作路径 |
| logs/ | 每步的命令参数与外围日志，失败时定位对应子任务 |
| summary.md、result.json | 人类摘要与精简目标索引；只有全部目标成功才发布 result.json |

默认只保留生产所需的来源和正式模板，已消费的 SDK 导出、解释事实和粗图由生产入口清理；原始观察不会自动删除。`--details` 开启来源中间产物、原生资源明细及目标执行图记录，供之后独立检查。`--storage-bytes` 监测 collection/ 内的逻辑字节，**不包含目标预测文件**；详细展开可能较大，使用者应另外预留存储。

预测默认每工作给定 1 ns，可用 `--given-work-ns` 修改。结果只表示给定耗时条件下的动态展开，不是性能预测、独立结构验收或泛化覆盖证明。输入规划也不保证所有目标分支已被观察。第一处失败即停止，保留已完成任务及摘要；子任务恢复使用 logs 中记录的正式命令及原目录，不重新执行一键脚本制造新采集。此示例不增加另一套恢复状态机。

## 配置集合的来源域规划

在 modeling 环境运行 `PYTHONPATH=src/workflow:src/adapters:src/collection:src/workload python3 -m markov_workflow plan-sources --input <集合输入.json> --output <新目录>`。这一入口划分来源域，并为每域选择一个代表配置及有限 workload 组合，生成初始采集输入；不启动原生。

输入严格包含 framework（当前为 sglang）、model、configurations 和 workloads。configurations 是非空数组，每项为唯一 id 和完整 instances；instances 与单任务采集/预测的表示一致，PD 两端同属一项配置。workloads 是非空请求集合数组，每项具有唯一 id，并沿用 requests、prefixes、ep_routes 的共同合同。

规划复用预测装配的 SourceDomain 规则，将容量和 chunk 长度变化保留在同域，按模型、拓扑、页布局及机制区分来源需求。SGLang 适配层识别声明输入的流程机会（prefill/decode、后续到达、分块、多请求、共享前缀等），在每个配置与相同 EP 补齐条件组内选择提供新条件的 workload，删除已被其他选中输入覆盖的整组冗余 workload；每次选择必须增加条件，次数由有限条件集合约束。再按未包含条件、逻辑 token 总量、各组到达等待之和及 KV 容量选择初始方案；逻辑成本不是性能估计，也不声称求得全局最小集合。

选中的 workload 组成同一个 Engine 内的有限提交序列，请求/前缀 ID 编码为 `[workload ID, 原 ID]`，父前缀及路由引用同步重绑定；独立 workload 不因此意外共享内容。组内到达偏移和完整前缀树保留，只消费配置实际启用的 EP 拓扑；相同补齐条件允许记录顺序不同，不推断不同区间写法等价。不同 padding 条件分别选候选，不覆盖或混合；若无法涵盖声明条件则报告缺口。前缀树与长度关系复用共同内容解析。

输出 input.json、plan.md、每域的 sources/<域号>.json，最后发布引用这些输入的 plan.json。sources 输入可直接交给 capture；目标集合仍保留原配置/workload 两个维度。报告列出选中 workload、逻辑成本和未包含条件；共享前缀不等于实际命中，不同输出长度不等于实际发生 subset，未选中 workload 的 EP 路由变化也未获得覆盖资格。

选中请求通过 SGLang 来源适配器缩短：保留完整共享前缀、私有后缀是否存在、页与 chunk 的余数和跨界条件，以及相等/不等的输出长度分组；至少保留原有的 Prefill 完成、Decode、继续 Decode 区别。不同输出长度之间原本有中间迭代时仍保留该间隔，Decode 原本跨入新页时仍保留首次跨页。EP 路由的所有内部区间边界限制可缩短范围，只删除无新转折的尾部并平移原区间，专家选择和 padding 不变；非法路由的缺口或重叠不能被压缩掩盖。长共享前缀、晚路由转折和大 chunk 可能使长度无法缩短，报告按实际输入计量。

启用缓存且选中输入有可复用整页前缀时，追加一对连续的单请求组：前一请求完成后，再提交共享前缀的后一请求。末组已经是所选单请求时直接复用它，只追加后一组。前缀生产者可缓存完整 prompt，消费者须按原生 input_len−1 匹配上限留下执行 token。两组复用原请求的长度、前缀和 EP 路由，不构造新的专家选择；实际缓存命中仍以原生观察为准。

若上述提交序列仍没有独立的持续 Decode 请求，则再从已有请求复制至多一个具有至少三次输出的请求，单独提交。每域最多增加两个前缀请求和一个独立 Decode 请求，能合用时不重复添加。报告按最终输入计量 token 和组数，短输入可能增加成本。目标 workload 不变，选中组内不删除请求。组间保留原生缓存；缩短仍可能改变准入、组批及合并机会，这些规则不是分支覆盖证明，也不会触发自动补采。模型长度、词表及专家层合法性继续由模型适配检查。

## 有限来源集合的采集与生产

`acquire-sources` 消费 `plan-sources` 的目录，顺序复用单任务 capture 和 produce。运行前核对全部任务的域、模型路径、部署设备数和编译程序，固定输入、部署及镜像 ID；首次采集前将程序保存到集合 inputs/markov，各域只使用该副本。恢复时先按内容核对传入程序，不能混用中途重新编译的实现；单个候选仍有未包含输入条件时停止，不在执行途中生成补采请求。

```bash
PYTHONPATH=src/workflow:src/adapters:src/collection python3 -m markov_workflow acquire-sources \
  --plan <来源计划目录> --deployment <部署.json> --output <集合目录> \
  --binary <modeling构建的markov> --timeout <单次原生秒数> \
  --native-budget-seconds <原生累计秒数> --attempt-limit <原生累计尝试数> \
  --postprocessing-budget-seconds <后处理累计秒数> --storage-bytes <集合逻辑字节上限>
```

根目录 input.json 固定输入，inputs/markov 保存集合程序，status.json 提供额度和失败摘要；sources/<域号> 保存独立采集任务，assets/<域号> 保存其模板生产目录。只有全部域生产成功且域匹配，才发布 result.json 的 productions 列表；各项可交给 predict --production。该结果表示初始来源编译完成，不表示目标覆盖或独立验证通过。源 trace、SDK 临时导出和保留模板均计入集合存储，模型目录不计入；默认沿用 produce 的中间件清理规则，完整明细需显式 --keep-intermediates 或 --resource-trace。

集合持有独占锁，并直接从各子任务的原生尝试和生产记录汇总用量，不维护第二套计费账本。每次调用每个域最多新增一次原生尝试；第一处失败即停止，恢复时重新执行同一命令，可显式增加额度，不能换输入、程序或镜像。已有成功采集及完成的生产步骤复用，失败和中断预留仍计费；后处理失败不重启已成功的原生任务。不要绕过集合入口并发运行其子目录任务。

存储在新操作前和运行期间约每秒检查，是逻辑文件大小监测，不是文件系统硬配额，写入突发和清理期间可短暂超额。超额停止新操作并清理本次容器，不删除唯一来源；恢复先处理子任务中断状态，再做新操作准入。status.json 是退出时摘要，运行中的预留以子任务记录为准。

## 原生采集任务

正式外围入口在声明的设备上启动一个采集容器，模型只读挂载，输出归本次新目录；需要 Python≥3.10 和 Docker CLI。

```bash
PYTHONPATH=src/workflow:src/adapters:src/collection python3 -m markov_workflow capture \
  --input <job.json> --deployment <deployment.json> \
  --output <采集任务目录> --timeout 900 --budget-seconds 1800 --attempt-limit 2
```

采集任务可包含 `submission_groups`：非空请求 ID 数组的数组，必须恰好覆盖所有请求一次；未提供时整个 workload 是一组。规划器自动生成此采集选项，探索输入和目标 workload 不增加字段。每组内部按 arrival_ns 调度；本组所有请求完成返回且所有实例到达屏障后，使用新的共同 RAW 起点提交下一组。只有一个 Engine、预热和 profiler 窗口，原生继续维护批次与资源，组间不 flush/reset。`request-delivery.json` 保留整个观察的 origin_ns，并为每次提交记录 group、组内 arrival_ns、相对全局原点的 scheduled_ns 和实际 submitted_ns；不能把串行探针误读为原来的并发 workload。

deployment 的 physical_devices 是按使用顺序排列的不重复物理卡号；取前若干张，数量由各实例 TP×PP 之和决定。代表 worker 复用减少观察和导出，不减少运行原生并行协议所需的卡。PD 还需声明可达的 store_url，可选 transfer_protocol 默认 sdma；部署信息不进入模型或 workload 合同。Ascend adapter 提供驱动挂载、设备可见性和传输环境，外围应用不修改原生通信实现。

--resource-trace 可选，默认关闭；开启后，选定观察的 worker 额外发布 source/resources/rank-<rank>.json，记录原生槽位/页分配与释放、前缀匹配/插入/锁/淘汰接口的实际结果及当时容量。操作关联原生语义调用，包含本地单调时钟区间；页、token 位置和槽位减去 SGLang 的保留区后使用零起点，缓存节点号仍是本次原生树的局部身份。初始化保留空闲队列，窗口结束在 flush 前保存最终容量。

该开关同时在原始 rank 文档记录 `request_input_attempts`：外部入口拉取的 RAW 起止时间、进入时的原生队列快照、消息数及 workload 请求成员，包含有效观察期间的空接收。TP 广播和 PP 转发不属于这段区间；首批请求激活观察前的状态明确为未知，预热和窗口外空接收不记录。独立检查核对区间顺序及非空结果与入口记录的一致性；未启用或旧来源没有记录时明确报告未观察。这些区间既不是请求进入 socket 的时刻，也不是 CPU 成本或可直接回放的调度指令。

设备索引在 markov.observer 范围内异步复制，窗口排空后才转换为 JSON；这些复制不属于业务子图，也不能把记录的调用墙钟当作校准后的成本。该材料观察原生对象，不运行核心分配算法；与预测的 resource 记录比较时，需要按请求、作用域与资源生命周期解释接口差异，不能逐行或按节点号硬配。开关属于采集执行选项，参与恢复输入核对，不修改 workload。

bindings 在 run_batch 执行前及 PD prebuilt 准备结束时读取原生 req_to_token 表的有效序列，保留请求、实际批次槽位和所属 scope；不从最近一次缓存匹配推断请求绑定。每项从逻辑 begin 起，按顺序记录 ranges 中的 [物理页号, 页内起点, 页内终点)，相邻连续位置合并，非连续地址保持原样。预测 binding 使用相同范围表示，直接取图访问时核心解析的结果；原生是整条有效序列，预测是该图声明的访问区间，比较时按请求与逻辑区间对应。页号及 scope/事件编号都是运行内身份，不能直接当作跨运行相等条件。

--source-image 可指定镜像，启动前解析为实际 ID。input.json 保存原生任务；execution.json 保存模型挂载、部署、镜像及各次尝试的命令、期限、退出码、实际用时和计入额度。attempts/<序号>/capture.log 保存本次原生输出，attempts/<序号>/source/ 保存原始来源。只有确认原生正常退出、专属容器已清理并读取到闭合 source/capture.json，才发布 result.json；其中 source 给出 produce --capture 应使用的相对路径。

--timeout 限定一次尝试，外部协调进程和容器内的系统 timeout 同时执行该期限，避免协调进程被强杀后原生仍无限运行；--budget-seconds 和 --attempt-limit 是同一采集任务跨恢复的累计上限，可以显式提高，失败不清零。每次命令至多启动一次原生运行；重复命令先核对输入、部署和实际镜像，取得任务锁并恢复未结算尝试。正常成功且来源完整时复用已有事实；失败且仍有额度时，本次明确调用才启动下一个尝试，不在内部循环重试。

启动前预留本次允许用时，正常结束或可捕获异常按实际单调时钟用时结算，清理也计入费用。Docker 容器保留到应用主动清理，因此协调进程被强杀后可以检查其真实退出状态；已经正常退出的容器可恢复发布，不再启动 Engine。仍运行或没有正常退出证据的中断尝试只清理本任务资源，并保留预留费用；无法确认清理时保持未结算状态，不发布结果。原始来源清单本身不能替代进程正常退出证据。

此入口只负责一个原生任务的累计时间及次数；配置集合来源规划、跨任务额度和临时/保留存储限制仍需由整体任务流程完成，不能将这里的局部额度当作集合预算。

容器内 `python3 -m markov_collection capture --input <job.json> --output <新的来源目录>` 消费显式任务。顶层为 model、instances、workload、observe_all_workers；model 包含 path/dtype，workload 声明请求、可选前缀及 EP 路由。每个 instance 为 id、mode、configuration：普通 serving 使用一个 null 实例，PD 使用一对 prefill/decode 实例。两侧共享模型和 workload，分别声明并行配置与容量；PD 两侧 page_size 必须一致。入口存在不代表 PD 及全部配置已取得结构资格。

实例按列表顺序使用不重叠的连续可见设备区间及全局 rank；物理设备可见性由容器部署控制。采集以原生 Ascend transport 搬运 KV，不使用 FAKE transport；物理传输环境（包括原生依赖的 store 地址）由部署提供。两侧共同开始请求到达时钟，实际投递延迟另行记录，不改写 workload 的 arrival_ns。

单机采集的投递起点、投递偏移、入口接收、worker 接收轮次和资源操作统一使用 `CLOCK_MONOTONIC_RAW`。request-delivery 显式标明 `monotonic_raw_ns`。来源解释在入口按各自 SDK 的 collectionTimeBegin/clockMonotonicRaw 锚点还原 RAW 时间：框架/主机 API 使用 host/start_info，设备任务使用其 device 的 start_info；不能将两种导出偏移混用。显式原生 API 和传输服务已经使用 RAW，直接交接，不先加偏移再减回。stream 拓扑仍用原生顺序坐标，时间证据独立保留。

这些转换只还原导出的坐标，不校准设备计数器频率，不消除 SDK 设备/主机测量本身的因果矛盾，也不代表跨机时钟同步。校准需要独立依据，不能按目标误差、等待边或首次失败位置拟合偏移/倍率；来源冲突继续报告，不能改图或截断时间求通过。

rank 事实中的 `request_ingress` 记录首个 PP 阶段从外部取入、尚未广播的请求集合；`request_receive_rounds` 记录每个 worker 经广播或 PP 转发实际收到的请求集合；`request_receipts` 保留逐条 dispatch 入口。三者都用 `received_raw_ns`，角色由所属字段明确。请求成员保留原生 ID，经 session 声明映射到 workload ID；空轮次和采集范围外的管理请求不进入记录。这些是输入交付证据，不是执行批次，也不用于反推或强制组批。模板代表复用不允许复制代表的实测完成时间给其他 worker；需要逐参与者独立时间对照时使用已有 `observe_all_workers` 采集范围。


Ascend PD 部署必须为两侧设置同一个 `ASCEND_MF_STORE_URL=tcp://<可达地址>:<空闲端口>`；完整原生 Engine 在 Prefill 端启动配置服务，不额外启动第二份服务。Compose 将该变量传入采集容器，`ASCEND_MF_TRANSFER_PROTOCOL` 默认 sdma，其他传输方式按实际硬件配置。使用 `--device` 限定设备时，`ASCEND_RT_VISIBLE_DEVICES` 使用容器中驱动枚举的编号，例如只挂载宿主卡 4/5 时为 0/1；不能直接沿用宿主编号。开始模型采集前核对设备可见性和传输部署条件，避免以完整模型启动排查环境。单独调用传输引擎的诊断不包含 Engine 生命周期，不能据此推断正式入口缺少配置服务。

输出目录必须不存在，失败目录不自动恢复或覆盖。instances/<序号>/ 保存该 Engine 的 session、role-plan、request-delivery 和窗口关闭标记；rank-<全局rank>.json、native/rank-<全局rank>/、runtime/ 保存角色事实、原始 profiler 及原生 API/阶段记录。PD 的 kv-pools/<全局rank>.json 在统一预热排空及采集排空时发布每个真实端点的注册和布局，小型注册事实不要求该角色导出完整 trace。模型/本地池角色事实在初始化时交换，最终代表在全部实例预热排空后、profiler 启动前确定；该请求内不执行 world collective，以免阻塞 PP 请求转发。capture.json 只在所有实例正常收尾后发布，记录各实例角色及初始化/预热/采集时间；中途产生文件不等于任务完成。

## 离线模板生产入口

capture.json 发布后，外围入口按实际 observed_roles 顺序执行 SDK 导出、解释、粗图构造和模板编译。未观察的等价 worker 不重复生产库，也不从目录扫描猜测角色。

```bash
PYTHONPATH=src/workflow:src/adapters:src/collection python3 -m markov_workflow produce \
  --capture <已闭合的原始来源目录> --output <生产目录> \
  --binary <modeling构建的markov> --budget-seconds 600
```

入口需要 Python≥3.10 和 Docker CLI；可用 --source-image、--modeling-image 指定镜像。生产前固定实际 image ID，将可执行文件保存到 inputs/markov；来源只读挂载，全部后处理在相应容器执行，不挂载设备或网络。生产目录不能位于来源目录内。

SDK 的写入行为由 Ascend adapter 隔离：只复制原始 FRAMEWORK、profiler 元数据及 CANN host/device 记录到本次工作目录，不复制此前导出的 trace、数据库或分析报告。SDK 在私有副本上运行，成功后交付 trace.json 并删除副本；原始来源不被修改。离线 launcher 加载 CANN 环境，将驱动接口开发库追加到运行库搜索路径末尾，不挂载物理驱动。SDK 返回成功不代表事实完整，后续解释仍核对设备点、API/队列及 payload 依据；各步骤标准输出与错误日志保留，不自动重跑模型或悄悄复用来源目录中的旧导出。

production.json 保存输入、步骤完成情况、失败原因和累计单调时钟用时；.lock 保证单一写者。相同命令恢复时核对输入及二进制内容，已完成的步骤不重复运行。--budget-seconds 是跨恢复累计上限，可以显式提高；启动操作前预留剩余额度，正常返回或可捕获中断按实际用时结算，超时后的必要清理也计入用时；进程被强杀导致无法结算时保守计入该次预留额度。恢复清理记录的本次容器和未完成步骤产物，不触碰其他运行；Docker 失败不能被当作容器已经消失，无法确认清理时保留待恢复状态。输入、镜像或程序改变须使用新的生产目录，不把旧状态升级为新规则。

assets/<rank>.json 是代表模板；先在 work/<rank>-templates.json 编译各角色，再连接同一次采集内已声明且相容的局部实现，全部成功后发布 assets 和 result.json 索引。这只表示来源编译完成，不表示独立结构验证通过；连接不改变完整 worker 域、角色状态或原始观察。inputs/templates.json 是本次源库列表，连接步骤不查找其他生产目录。

logs 保留各步骤日志；SDK trace、事实、粗图和连接前模板在整组连接成功后默认删除。--keep-intermediates 保留这些取证材料，并在事实中附带实测边界时间、在粗图中附带事件/工作对应的原生来源；默认不生成可选证据。每个生产容器也按本步骤剩余累计额度设置内部期限，协调器中断不解除该期限；恢复仍使用已经预留的计费记录。恢复已完成连接时直接使用 assets，不要求重建已释放的中间件。SDK 私有原始副本不属于保留明细。该入口不执行原生采集或配置集合来源选择；模板合同改变后重新生产，不为旧库提供兼容读取。

单独诊断可在推理镜像中使用 `LD_PRELOAD= /opt/markov/export-profile.sh --input <来源> --rank <rank> --output <新的导出目录>`；解释入口显式传入 `python3 -m markov_collection interpret --input <来源> --rank <rank> --trace <导出目录>/trace.json --output <事实.json>`，不隐式搜索来源旁的历史 SDK 产物。解释时加 --evidence 生成 measurements；随后在 modeling 内执行 `markov project <事实.json> <粗图.json> --evidence`，生成可选 evidence。

来源证据包含观察窗口、时钟、每个粗图事件的原生 span/顺序/实测纳秒，以及各工作对应的原生 span。设备 stream 的顺序号由 runtime 映射为 SDK 实测时间；没有实体任务的逻辑等待保留 null，不借用 CPU 时间或填零。事件锚点可来自同一串行资源上的相邻片段，工作归属单独记录。证据不参与模板身份或结构选择，不能把观察窗口直接当作请求到达原点，也不能把片段墙钟自动当作成本；跨 rank 时钟及调度时间旁路需要另外核对。

## 来源证据独立检查

在 modeling 环境运行 `python3 example/coarse_graph/source_evidence.py --production <生产目录> --capture <原始采集目录> --output <新报告目录>`。生产须保留 `--keep-intermediates` 的 facts、graph 及测量证据，原始采集提供同次运行的设备校准采样；两个目录均显式指定容器内路径，不依赖生产时宿主机的绝对路径。检查器不启动采集、重建模板或修改业务资产。

报告分别说明来源映射与时间约束：核对环境、调用层级/上下文、通信声明、完整边界及其语义归属、工作/顺序区间、端口、实际张量几何、KV/槽位区间、原生依赖及测量交接。时间检查保留中点测量上的名义倒置，同时核对每个rank是否存在同一套、位于原始两端查询区间内的仿射时钟关系，能满足该图全部已测依赖；不能逐边独立放宽偏移，也不求取或回写校正时间。相容不等于精确时钟、原生关联正确或跨rank时间已校准；缺少测量仍为未知，不能填零。检查不验证符号表达式、条件或shape变换，也不能证明原生观察没有遗漏。

默认输出一份精简 Markdown 和每类名义时间问题前三个位置的 JSON；`--details` 保留全部位置。映射一致、时间全部已测且存在共同校准返回 0，其余返回 1；某个rank的材料缺失或格式错误不会阻止检查其他rank。JSON的timing分别记录校准相容状态、已测/未知约束数及首个使共同校准不可行的位置。报告不是目标执行结构的独立验收，也不授予真实时间旁路资格。

## 单任务纯预测入口

外围入口接受模型、实例配置、请求和给定耗时，依据已提供模板库自动生成 worker 环境与代表映射。预测不加载模型权重，model.path 用于核对来源模型身份。输入包含四项：

- model：path、dtype，与来源使用相同声明。
- instances：每项包含唯一 id、mode（null/prefill/decode）、configuration；配置字段与采集共用，包含拓扑、backend、页/容量及可选 chunk/mixed/prefix_cache。
- workload：requests、可选 prefixes/ep_routes 和 id；不包含原生 batch 或完成时间。
- given_work_ns：每工作给定的非负整数纳秒，仅用于结构开发，不是实测或精度结果。

一个任务为一个普通实例或一对 P/D 实例。微批次容量 microbatch_requests 可选；未指定时由原生调度器计算。该入口完成单次预测装配，配置集合的来源规划、完整任务恢复与独立评价仍在开发。

```bash
PYTHONPATH=src/workflow:src/adapters python3 -m markov_workflow predict \
  --production <已发布的生产目录> --input <prediction.json> \
  --binary <modeling构建的markov> --output <新的输出目录> --timeout 180
```

--production 可重复，用于提供不同来源域的完整生产。入口只读取明确生产目录的已发布索引，模板路径必须位于各自生产目录内。先按模型/dtype 及所有实例的 backend、TP/PP/EP、页、缓存与 chunk/mixed 机制选择唯一完整生产，再按 worker_roles 中的代表、parallel、kv_layout 及适用 expert_layers/kv_peers 装配参与者。PD 两端作为同一个来源域匹配，不能从不同采集任务拼接各自看似匹配的半边；同域有多个生产时需明确只提供本次使用的一份，不隐式合并或挑最新来源。用户不填写模板索引或逐 worker 环境。缺代表、重复代表或相互冲突的来源环境直接报错，不扫描历史 data、不拼接无授权角色。worker 可共用同一库，但资源和状态独立；容量和 chunk 长度是目标参数，同域匹配不表示任意请求和参数范围已被模板覆盖。

外围入口管理 modeling/control 两个容器，无网络、不挂载设备或模型权重。--modeling-image 和 --control-image 接受稳定标签或 ID，启动前统一解析为实际 ID；core.log/control.log 首行记录对应容器的完整命令。只给 modeling 挂载程序、模板、生成的内部任务和输出目录。输出目录必须不存在；仅两端成功退出且本次容器清理完成后发布 result.json，保留日志，删除临时内部任务和未发布结果。协调器与两个容器各自持有期限，容器使用 --init 回收子进程；超时或失败只清理本次专属容器，并回收 Docker 客户端。协调器被强杀时不保证临时任务文件被删除，但子容器仍受自身期限限制，临时文件不能视为已发布结果，不自动重跑。

predict 可选 --execution-trace，以同一次模拟增量写出 execution.jsonl；默认不序列化展开图，不保存全历史事件。精简 result.json 的业务结果不因开关变化。控制、资源与执行观察分别使用只读接口，由同一个 CLI 记录器写出；请求交付与状态查询属于控制观察，资源操作完成并交接失效信息后才记录，不增加分配账本或为记录额外查询状态。明细供工具读取，包含以下记录：

| kind | 内容 |
| --- | --- |
| resources | 各实例容量、worker 与请求输入顺序；resource 中的请求索引据此还原为用户请求身份 |
| resource | 核心资源服务实际操作、返回值、所属 worker、模拟时刻及本次失效的页/槽位；包含查询和修改，不从图推测分配 |
| binding | 图实际使用的请求 KV 映射、所属池与槽位；invocation 引用该图 call.enter 的执行事件，begin 与 ranges 表达逻辑位置到物理页的关系；相同图内跨层重复区间只保留一次 |
| graph | 实际实例化的粗图、局部事件到本次执行事件的 event_ids、各工作给定耗时及插入时刻；不重复环境大对象 |
| edge | 执行器实际连接的前驱/后继、关系及延迟，包括跨动作数据、状态复用、资源顺序、通信汇合和运行中解析的流等待 |
| completion | 事件的实际模拟完成时刻 |
| boundary_time | 具名边界的 begin_ns/end_ns 约束；相同值为确定时刻，不同值为允许区间 |
| notification_declared | 通知的参与者、名称及逻辑 work 身份和执行事件；可先于其生产者登记 |
| notification_ready | 实际完成的通知事件、身份、前驱事件和交付时刻；前驱须与实际 edge 相符 |
| completion_read | 一次实际完成状态读取的 signal、生产者 event、布尔结果和模拟时刻；boundary 明确关联所属 query 的返回事件。按读取当时顺序写出，可区分同一时刻先完成还是先读取 |
| state_query | 原生适配器返回的布尔/整数结果、worker、报告时刻及本次 completion_reads 数量；boundary 指向该 query 图已完成的 call.return 执行事件。种类和逻辑对象从该图工作上下文取得，不重复序列化 |
| end | 核心事件循环已正常结束；本身不是独立正确性结论 |

图内 scope/port/work 仍使用局部事件位置，edge/completion 使用 event_ids 或 notification_declared 声明的执行身份。这些编号只连接本次执行，独立对照必须从请求、阶段、token 范围、模型位置及 rank 等语义对应，不能跨运行按编号配对。图的环境由明确输入与模板资产提供，不在每次调用中复制。明细保留端口、shape、KV/槽位访问及依赖，但不包含完整逻辑资源状态历史，也不替代来源事实审查、真实时间旁路和独立评价。

控制侧完成通知的顶层 group 表示登记者，notification 中的 group/name/work 表示通知接收者及其逻辑身份；允许发布者为另一参与者登记通知。另声明所属请求索引，仅用于生命周期管理，不进入跨运行身份或时间匹配。一个通知及其通知前驱归属同一请求；发送者先结束时仍保留通知，待所有参与者完成该请求的原生清理、通知事件均已完成后，核心释放记录和事件保留权。最终 token 发布不代表清理完成，也不能将通知保留到整个 workload 结束。未来若需要跨请求通知，应重新定义其所有权，不能沿用本合同暗中提前回收。

查询结果在实际读取之后报告，不为记录再查一次状态；仅开启明细时返回观察凭据并进行报告交互，默认路径没有该交互。观察报告走只读交接，不消耗原生 worker 的调度轮次。boundary 只在本次执行中关联 query 图，跨运行仍使用图中的逻辑工作身份。独立工具从图的 signal 输出端口和已完成事件核对每次完成读取，再核对查询报告的读取数量；event 查询须恰好读取一个完成信号且返回相同布尔值。transport 可以使用缓存状态或短路读取多个信号，读取一致不等于协议状态组合或通知时刻已经正确。报告时刻不是原生实测时刻，也不能仅凭结果均为 Success 就认定协议时序一致。

独立 PD 对照从真实来源的 session 与末块传输确定所有必要端点及发送组，核对各端点状态更新和成功读取是否齐全；目标只从图中的 KV/元数据写作用及导出完成事件还原实际传输。每次实际完成读取核对请求与发送者，Success（含缓存返回）核对完整发送组及末块元数据已经完成。发送侧发布核对完整传输事件，接收侧可见核对实际发送组的发布事件；若启用区间旁路，还须独立核对输入区间与原始状态写入一致、实际交付在区间内。它不要求轮询次数相同，也不由必要前提一致推定精确通知到达、元数据内容或任意轮询交错已经正确。 `cross_rank_dependencies` 分别汇总已通过实际依赖边及独立原生参与者检查的通知关系、尚未验证的跨 rank 关系；后者使整体覆盖保持不完整。不能将所有非通信边都记成未检查，也不能用声明的 prerequisites 代替实际执行边。

普通 Decode 准入的独立检查连接本次接收范围内的传输读取、元数据门控、实际 MIN 输入/输出与准入；Success 且元数据未到达时输入为 Transferring。参与者来自原生 attention-TP 协调组声明，单 rank 没有集合通信切口时直接使用本轮本地门控。每轮开始清除旧结果，各 rank 的向量须对应相同顺序的请求；每次准入只能消费本轮尚未消费的成功结果。来源和目标各自核对，不跨运行按轮询次数配对，也不要求所有成功项立即准入（原生可以限定本次检查的请求）。`native_admission_operands`、`native_admission_decisions` 与 `pd_read_prerequisites` 中对应项分别报告操作数和结果消费的核对、缺观察及差异；缺结果不能当作成功。该检查不覆盖 staging 和多级缓存。 无设备控制的空闲等待也使用原生轮询归约最终结果；各 rank 的局部状态只用于其实际读取，不单独决定整组可推进。adapter 保留原生结果供等待判定，已有 broker 在预约或通知入队后唤醒；不复制准入算法。

运行中写 execution.partial.jsonl；失败保留已写部分便于诊断，不发布成功结果。核心和原生控制均正常退出、专属容器清理完成后，才发布 execution.jsonl 和 result.json。读取明细须同时确认成功结果及末尾 end，不能把中断前的记录当作完整运行。

`markov serve <templates-directory> <task.json> <result.json> [--trace <execution.jsonl>]` 是应用内部的核心入口，标准输入输出保留给控制协议。内部任务包含 settings/control、参与者环境及模板索引，模板目录按该索引放置 0.json、1.json 等库；用户通过外围入口生成，不手工维护这些重复事实。核心仍核对资产域、参与者和资源绑定。

单图实例化的 signals 按端口名绑定目标信号，pools 明确提供池绑定；动态 serving 由原生句柄维护信号代次，并将 local 绑定到当前参与者、远端绑定到相应资源所有者。独立 execute 的 initial_inputs=ready 仍是显式假设，不能作为跨动作等待正确性证据。现存旧来源缺少新机制字段时保持历史用途，不补造运行资格。

独立槽位池的可选资源观察包含 `initial.state_slots`、`state_events` 与 `state_free`，记录原生行池的容量、初始空闲集合、分配/请求绑定/归还及最终空闲集合。目标资源明细的 `state_slots` 操作来自核心资源服务，`returned_fields` 按字段记录内容失效；与请求槽位的 `returned_slots` 分开。对照按物理行别名比较生命周期，源端未记录时明确列为未观察，不能仅凭目标内部自洽授予原生对照资格。

## 原生动作的逻辑上下文

采集与原生控制共用请求进度提取：使用 workload 请求 ID、已生成 token 数、原生声明的已提交 KV 长度及 extend 区间，不以对象地址、物理槽位或本次批次编号作为跨运行身份。选择阶段保留等待、运行、上轮批次及 chunk 请求的进度快照；批次操作保留成员进度；缓存匹配优先使用实际传入的请求，没有请求参数时保留调用者已有上下文，不从相同 token 内容猜测请求。

这些事实放在工作描述的 `context` 中；CPU 片段另有 `continuation`，记录所属操作、进入和退出的具名调用边界，以及相邻子调用开始时的请求上下文。嵌套动作的 `callers` 保存各调用者的操作、请求上下文和当时的进入位置；共同调用层在挂起前取快照，不能用可变父对象或全局调用计数代替。即使多个 CPU 片段共享结构模板，继续执行的位置也不会被模板归一化抹掉。上下文只作为实际调用的证据，不进入模板条件、参数或共享定义；采集与控制分别将原生请求 ID 转换成同一 workload ID。

结构对应使用动作自身的 `context`、`continuation`，以及 `callers` 中各级 `owner` 和 `entry`；祖先的 `context`、`entry_context` 保留作诊断及时间资格检查。另一条请求留在祖先队列中，不应改变当前请求子调用的结构身份；实际跨调用因果仍由完整执行图独立检查。归并后重复的来源或目标仍无逐次配对资格，不按出现顺序兜底；不同内容和依赖也不能因身份相同而通过。结构可对应不代表可以套用来源绝对时间，同一清理操作可能发生在另一请求接收之前或之后。旧来源没有观察到的上下文不能离线补造。

## 单图给定时间与边界约束

`markov execute <coarse.json> <given-timing.json> <execution.json> [--trace <execution.jsonl>]` 执行已经选定的一张图。时间输入包含 `initial_inputs: "ready"` 和与图中工作一一对应的 `work_ns`；可选 `boundaries` 是 `{ "event": 事件编号, "time_ns": 纳秒 }` 数组，要求指定边界在共同模拟起点后的该时刻完成。其余事件仍按给定耗时和依赖推进，不隐式填入实测性能。

这里的编号仅引用当前输入图，不承担跨运行对应。真实来源必须先按请求、逻辑进度、动作和 rank 等工作身份匹配目标边界，再由调用者交付局部编号与时间；此入口本身不完成匹配，也不读取真实批次或资源分配。

时间约束不能早于调用提交，同一事件只能声明一次。执行器保留数据、资源及通信依赖；依赖导致边界晚于给定时间时直接失败，报告所需与可达时刻，不平移时间或忽略前驱。尚未到齐的通信参与者仍会阻止完成，不因提供时间而获得放行。较晚解除的外部等待不能让虚拟时钟倒退。

可选明细复用执行记录格式，`boundary_time` 记录输入约束，`completion` 记录实际完成。成功明细有末尾 `end`，失败仅保留部分记录且不发布结果；只有同时存在成功结果与 `end` 才能作为完整执行。默认 serving 使用给定工作耗时；按工作身份提供的 serving 边界时间由下述独立输入接入。

## Serving 的具名边界时间

公开 `markov_workflow predict` 可附加 `--boundary-times <times.json>`。文件为对象，可提供 `actions`、`ingress`、`notifications` 和 `input_reads`；时间约束至少包含一项实际测得的动作、通知或接收返回。`actions` 为动作记录数组，每条包含 `group`、`action`、`parameters`、`work`，以及正整数 `observed_calls` 和 `boundaries` 数组。时间对应使用完整的 `context`、`callers`、`continuation`，比结构对应多要求祖先上下文一致；这只是保守的时间候选条件，不能代替因果检查。物理页、batch 句柄、传输绑定及动作序号不参与。记录的排列顺序不影响匹配，同一身份只能有一条记录；实测边界记录只能消费一次，重复消费或实际时间冲突使预测失败；目标的新动作没有对应时间时使用给定耗时，未出现的来源动作也只记为未覆盖，时间记录不限制合法控制路径。

批次变换的上下文包含操作、左右输入请求进度及结果成员，不能只用左侧成员和右侧人数识别合并。结果快照只交给动作本身，调用前后的 CPU 片段保留进入该动作时的输入快照；不得原地修改共享上下文，将尚未发生的结果回写到前置片段。采集和原生控制共用变换声明，旧记录缺失的成员事实不能按人数或顺序补造。

每个边界是 `{ "port": "call.return", "direction": "output", "time_ns": 绝对模拟纳秒 }`。端口指向该动作图根作用域导出的具名边界，可分别提供 CPU 返回、设备完成、数据或信号时间。多个端口名若引用同一事件，只接受一致时间；没有对应端口或依赖导致迟到时不猜配、不平移。只有实际提供的端口受约束；未覆盖动作及其余内部工作使用任务显式给定的耗时。

`observed_calls` 表示同一逻辑身份在来源中实际出现的次数。非空边界要求该身份只出现一次；空边界明确表示时间未覆盖，也适用于自身唯一但处于重复父调用中的动作。目标仍执行原生代码、实例化完整图及其查询/资源作用，使用给定工作耗时，次数可以不同。时间层不判断重复动作是否纯 CPU，也不删除其作用；结构评价独立核对。结果中，新增目标身份的 observed_calls 为零，未执行的来源身份 predicted_calls 为零；它们与空边界身份均列入未覆盖，使 `timing_coverage` 为 `partial`。该状态不能取得全部反馈时间已对齐的资格，也不改变模板支持域或结构评价判据。

`ingress` 按实例 ID 提供有序接收轮次，每轮为 `{ "time_ns": 纳秒, "requests": [workload请求ID] }`。提供时必须覆盖全部实例和每个请求，成员不能重复，时间不得早于 workload 声明到达；不同实例可有独立交付时间，请求顺序可以不同于输入列表。接收轮次只控制哪些请求能在一次原生输入轮询中交付，不决定执行批次。

共同交付组件管理待交付轮次与实际已交付请求集合，资源调用和输出都按成员身份核对。默认按 workload 到达积累可用请求；提供接收记录时保留每轮成员，不把多轮合并。实际交付仍等待原生轮询，不倒退模拟时钟；可选明细以 `input_read` 记录接收前身份、请求索引和实际返回时刻，较晚交付须在独立对照中解释，不能直接宣称输入已对齐。`arrival_basis: "supplied_ingress"` 标明使用了该输入。

独立结构对照从原始 session、RAW 原点及各 rank 的 `request_ingress` 还原外部接收，不读取旁路时间文件充当真值；与目标 `input_read` 中非空返回的实际成员、轮次及时间比较，报告为 `request_ingress`。成员和轮次一致后才比较对应时刻，提前/迟到均报告差值，缺少来源不能判通过。外部接收一致不代表 worker 广播后接收、空轮询或两次接收之间的 CPU 推进已对齐，也不保证控制路径相同。

应用将文件交给 serving，不改 workload 的请求内容、声明到达或原生组批。共同层只匹配工作身份、解析当前图端口并向现有执行器提交约束，不用记录生成目标图、资源分配或原生决策。结果以 `uniform_given_work_ns_with_boundary_times` 区分于普通给定耗时，并报告 `boundary_actions`、归并后的 `boundary_events` 、`timing_coverage` 和 `unconstrained_calls` 中各未覆盖或未配对身份的来源/目标次数；后者明确保留未约束时间的范围，不能称为全部 CPU 时间已对齐。失败不发布成功结果。

局部逻辑身份在来源中唯一，只说明存在计时候选；对跨 rank 轮询归约，其他参与者的输入状态和共同结果也可能不同，不能由局部唯一性宣布时间对应已验证。partial 文件只提供诊断约束，目标迟到或控制分支变化仍需沿联合状态解释。

此入口接受明确提供的时间，不自动将其认定为原生实测。原生取证工具还须完成来源工作身份、时间单位/原点、实际到达与初态的核对，并明确覆盖的控制与资源边界。仅提供 CPU 返回时间不足以证明设备与通信完成；图内结构比较也不能由时间约束替代。

独立时间提取使用 `python3 example/coarse_graph/boundary_times.py --capture <closed-native-case> --graphs <projected-graphs> --output <new-directory>`。图目录包含经 `project --evidence` 生成的 `<rank>-graph.json`；工具只读实际采集与粗图，不读取模板或预测。请求投递与测量须采用共同 RAW 时钟，全部实际 worker 都须有记录，不能复制代表 worker 的时间。

rank 事实统一保存 `state_queries`，每项包含 `kind`（event / transport / metadata）、独立 query scope、查询前后 RAW 时间及 `result`。Event 另存生产者的 point，结果为完成布尔值；协议轮询结果为原生整数状态，逻辑请求放在该 scope 的工作上下文中；metadata gate 记录该请求的 room 字段是否非零，不用原生 room 数字作为跨运行身份。无查询时明确保存空数组，缺字段不能解释成没有发生查询。每个 query 动作必须恰有一条实际读取记录，不能把窗口根或普通 CPU 片段当作它的切口。

Event 查询除了核对返回值与本次执行的完成状态，还须核对所读对象。原生 state_queries.point 对应已导出的事件代次，目标 completion_read.signal 对应实际生产者；只有查询及生产者均有唯一调用对应时才能作跨运行比较。等待和查询共用生产者身份核对，等待另要求完成依赖，非阻塞查询不要求该边；不能因为两个不同信号都已完成就认为读取一致。缺少调用对应仍单列未覆盖，查询支持接口存在不代表当前案例实际执行了 Event.query。

协议观察的 session 使用 `protocol_requests` 保存实际提交的预约编号到 workload 请求的映射，预热编号不进入该映射。rank 记录的 `protocol_states` 保存原生状态更新前后值及 RAW 时间区间；状态由原生维护，观察无需等待 profiler 激活或元数据行分配。独立检查按原生非失败状态的单调性核对就绪和成功区间，同一次变化的重叠观察取交集；缺少就绪写入保持缺失，不由首次查询推算。旧的仅成功状态记录不自动作为当前合同输入。预约发送另保留原生目标 endpoint、拓扑对端位置及 RAW 调用区间，kv_reservation 是独立 CPU 动作，reservation.ready 导出调用入口而非发送返回；该信号仅表示因果下界。kv_ready 通知合并实际发布者的信号，对应 Prefill 的完整预约可见；Decode 自身初始化的 WaitingForInput 不生成同名远端通知。独立工具用实际传输 session 反向核对预约参与者、发送与状态写入顺序，再核对目标执行边；缺少发送记录单列为 missing_publications。

CPU 元数据集合通信的数值证据只在详细观察开启时生成：来源 `action_values` 按原始 scope 保存 `values.collective.input/output`，目标 `action_values` 按已完成的调用返回事件保存同一数值合同。广播只记录根的输入，接收端输入为空；不读取其未初始化缓冲区。快照在原生调用测量区间之外获取，不进入模板条件、工作参数或时间旁路。独立评价按每次运行自己的通道顺序和真实操作数核对广播、收集与 MIN 归约；两侧唯一调用可进一步比较输入/输出，重复调用不按序号跨运行配对。缺少详细数值继续报告未观察，不用正确的通信边代替载荷资格。

MLP 组批协调在共享 adapter 中以完整 `MLPSyncBatchInfo.all_gather` 调用切分，采集和原生控制使用相同切口。详细观察的 `action_values.values.batch_sync` 保存七项本地输入、DP/TP/CP 布局、活动标志及原生已经读回的五项输出；输出列表保留调用返回时的快照，不再次读取设备。`segments` 关联本次调用的实际片段，来源使用 scope，目标使用已完成返回事件，仅用于运行内归属。独立评价核对完整片段范围、所属通信及各参与者操作数，按原生组序计算被消费的 token 列表与控制标志；唯一可对应的调用另做跨运行数值比较。缺少观察或存在未核实的设备故障恢复掩码时保留不完整状态，不按轮询序号强配，也不把这五项输出当作 TBO 等后续机制的完整验证。

持久字段复用相同的可选动作观察通道：`values.state` 保存逻辑请求、字段、读写及实际值，不进入模板。PD 记录原生 set_buf 的首 token/缓存计数输入，以及 commit 已读出并写回请求的结果；失败提交显式记录空值，不额外读取设备张量。目标观察在对应动作返回后提交，独立评价核对本地字段访问、参与者和实际发送组，再按逻辑请求比较两侧值；room 编号仅在每次运行内部对应。不检查未使用 padding、范围外的多模态/logprob/speculative 字段，也不把缺少源端数值的目标自洽当作独立通过。

共享调用层先结束读取前的 CPU 片段，再执行 query CPU 工作，在其返回边界读取当前状态，然后恢复原生代码。读取不额外连接“被查询生产者必须完成”的等待边。原生 API 自身的工作与同步仍保留，例如 Ascend 标量读取会同步本地 stream；因此 query 可以包含多段 CPU 工作和原生等待，不能统一验证为单段纯 host。metadata 准入检查与提交之后的实际 metadata 内容读取分开。采集测量实际 API 读取区间，控制将读取线性化在 query 返回边界；这是粗粒度执行约定，不声称还原 API 内部采样时刻。结果不参与模板分类，模板只按读取种类共享结构，逻辑请求或信号生产者随实例绑定。

Event 返回 true 只说明完成不晚于查询返回，false 只说明完成不早于查询开始；检查这些界限与信号测量是否一致，不用查询时间替换设备完成时间。结构评价不将查询动作及祖先归入无状态重复 CPU，独立的前后 CPU 片段可分别检查。计时层统一保留所有重复身份的未约束范围。协议状态与 metadata 可见性不是设备完成时间；尚未提供完整跨运行状态迁移对照，不能宣称 PP/PD 协议时间已经验收。

输出 `boundary-times-report.json` 说明参与者、接收轮次及时间覆盖。提取自身和调用祖先均无重复候选的动作的 `call.return` 和导出输出信号。原生 envelope 按调用位置、参数及逻辑工作上下文归组；自身重复或处于重复 envelope 中的动作只保留实际次数，不按序号配时。父调用同一逻辑状态可能多次轮询，不能因某个成功分支只走一次就自动取得其真实时间。该判定只影响时间覆盖，不改变图切分、模板身份或原生决定。全部参与者事实有效且至少有一个唯一实测动作时发布 `boundary-times.json`：没有时间缺口则报告 extracted 并返回零，有时间缺口则报告 partial 并返回非零，时间文件仅用于部分覆盖诊断。缺少反馈测量、接收记录、查询事实或时钟不符时仅发布 unverified 报告。所有来源调用仍核对测量和查询事实，不因重复身份跳过原始证据检查。入口时间参与来源区间及 DAG 因果检查，但不作为反馈约束发布：调用返回和完成信号允许控制器继续，调用入口本身不释放结果。公开时间接口仍接受显式指定的入口约束；独立提取不要求预测按原生入口时刻构造图，也不因此宣称图内时间已对齐。

发布前沿完整 rank 内 DAG 传播已选边界时间，未测量节点不截断路径；若因果前驱晚于后继，报告两端 scope/port 和倒置量，禁止发布时间文件。该检查不要求未选设备事件均有可信时间，也不替代跨 rank 检查。提取成功只说明所选时间可交接；来源事实、内部结构、实际接收和反馈覆盖仍需独立评价。

独立动作比较在 modeling 容器内使用 `python3 example/coarse_graph/compare_actions.py --capture <closed-native-case> --graphs <projected-graphs> --execution <prediction.jsonl> --output <new-directory>`。它与时间提取共用逻辑工作身份，读取实际粗图及预测明细，不调用模板选择或实例化。 两者同时核对原始 worker 记录与粗图的环境、scope 身份、绑定声明及查询归属。原始记录必须具有统一状态查询数组，缺少记录不等于没有查询；作用或输出声明不能在图转换中丢失。每个动作按父子调用位置核对层次、参数、端口、数据张量的形状/别名/相对版本/生产者、工作种类及数量、逻辑 KV/槽位访问和通信参与者。运行地址和图事件编号不跨案例配对；元数据端口只比较布局，不把它声明成数据存储所有权。

依赖比较使用各 rank 的完整真实 DAG 和预测实际记录的边，包含后续加入的等待与状态依赖。按动作内的具名端口、等待开始、通信就绪和状态访问边界比较可达关系及共享事件；路径可以经过动作树之外的事件。工作按所在作用域、资源共享关系及前后具名边界比较，内部提交线程不必有公开端口。不比较原始事件号、边数量或测量时间，因此冗余传递边不构成差异，缺失依赖和额外串行化会分别呈现。 原生显式信号端口另按 point/producer 句柄代次映射到逻辑生产者及端口，再核对目标实际 signal 绑定和直接等待边；不以同一 stream 的其他可达路径替代正确的信号生产者。图外查询与 PD 协议就绪不由这项检查证明。

跨动作比较仍按共同工作身份和具名边界对应，核对每个边界来自其他动作的必要前驱，包含串行资源及动态等待形成的路径。来源边界分批传播有界位集合，不存储全案例的平方规模关系表；位序号只是本次比较的索引，不承担原生/预测动作配对。边界集合不同明确报告证据不足。根部自动资源入口/出口不按名字与原生配对，但其连接参与完整路径计算。

内容核对与逐次对应分开。结构键保留本地工作及调用位置、略去祖先状态，用于检查同类来源内容和依赖是否一致；一致时，每个预测副本都与共同结构比较，不按 CPU、查询或通信类型豁免。完整工作身份额外保留全部祖先上下文，两侧各出现一次才能建立调用对应；结构相同但祖先状态不同的调用仍可分别对应。已对应调用使用它自己的来源 scope，不能用结构类的首个样本代替。来源结构有变化时，仅完整身份唯一的调用可与自己的来源直接比较，其他变化保留未验证，不按与预测的相似程度选样本。重复结构报告给出结构类次数、共同内容/依赖检查数及其中已对应调用数；unpaired_calls 给出尚未对应的两侧调用总数。完整上下文仍重复时返回 incomplete，不按序号强配。

单次运行中的来源 rank/scope、目标 worker/进入事件保留每次调用、生产者、通信及物理绑定，这些编号不跨运行配对。读取完整目标后，只有两侧完整工作身份均唯一的调用建立一对一映射，再核对内部/跨动作依赖、物理绑定及查询实际返回；跨动作顺序表也使用完整工作身份，不能用结构键覆盖同类调用的边界；唯一调用的内容匹配数仍单列。缺失或重复不阻断其他调用检查，也不按出现序号补配。依赖任一端未配对时单列 unpaired，不能计作匹配或直接归咎缺边；未匹配调用的写入和动态边仍保留在完整 DAG 中。


`actions.json` 分开报告动作内容、局部依赖、跨动作次序、数据写入/输出就绪、通信参与者、请求物理绑定及有效资源操作；默认保留每类首处差异，`--details` 保留全部差异。`actions_matched` 和退出码 0 只表示报告声明的检查通过；跨 rank 因果仍限于显式通信，调用内部资源生效时刻、在途归还安全及远端池身份另取证。具名边界因果等价不单独证明原生信号句柄来源或所有未具名内部拓扑。差异先区分评价合同、记录完整性与生产实现，不直接当作核心 Bug。

资源操作比较允许两次运行的绝对页号、槽位号不同，但同一次运行中同一物理位置的身份跨释放保持不变，因而能够发现复用关系变化。内容生命周期由分配、写入、释放等操作表达，不在释放后重新命名物理位置；操作序列一致仍不单独证明在途访问安全。


`input_reads` 是外部接收返回记录数组，每项包含 `identity`、`observed_calls`、`time_ns`。身份为 `{ "instance": 实例名, "context": 接收前逻辑状态, "received": 排序且无重复的此前已交付 workload ID 数组 }`。仅唯一读取可给非负返回纳秒；重复或未资格化记录用 `null`，目标仍按原生代码及当前到达推进。结果报告 `bounded_input_reads` 和 `unconstrained_input_reads`；未覆盖不填零、重复消费或迟于已知返回进入同一读取时报错。该反馈只规定读取何时返回，成员由当时输入状态决定，不读取来源的组批结果，也不作为 CPU 性能数据。

执行明细的 `input_read` 记录身份、`time_ns` 及实际 `request_indices`，空读取也记录；其中非空记录即请求交付证据，无第二份重复交付事件。独立对照按原始接收区间及身份比较，不读取旁路文件充当真值；未知首批状态、重复及未对应读取分别保留未覆盖。

## 目录与依赖

代码按原生事实、粗图规约、模板生产、目标实例、控制、资源、执行和应用装配分层。C++ 头源同目录，使用 src 为 include 根；目录名字服从实际职责，不为保留旧文件增加包装。

框架/runtime 差异在相应 adapters，共同 instrumentation 和发布逻辑不导入具体实现。Python 应用只组织任务，不在采集侧实现预算平台，也不把模型/资源规则复制到 example。

example 承担案例、矩阵和独立评价。默认结果精简，原始 trace、完整图和状态明细按真实消费者在生产前选择；同一执行的诊断开关不改变正式行为，不另跑一次模拟生成明细。

deprecated 仅为本地参考，不进入 Git 交付、CMake、import、安装或 fallback。官方与参考子模块保持各自归属，不把临时环境修改写入上游工作树。

## 修改与验证

先静态追踪完整模块的入口、生产者、消费者、状态和资源所有权，再集中修改；可以整段删除重写，不围绕每个新错误增加分支。模块及关联调用方完成后统一编译，必要时从正式入口运行最小真实案例。

源码和构建影响相同的批次不重复验证；完整矩阵在事实生产、模板、控制和评价均收口后冻结执行。构建成功不替代代码审查，运行结果也不证明未覆盖的状态和生命周期正确。

不新增独立 test/fixture/mock 工程。使用静态推导、正式构建和必要公开入口，评价工具的受控反例留在 example，不能进入业务分支。
