# 粗粒度执行图与子图模板

正式流程先将原生 trace 与必要语义/状态事实规约成粗粒度真实图，再从粗图切分、参数化并归一化子图。模板不以逐 kernel 物理归属为前提，不把全量 trace 转成必须长期维护的细图。

本文定义资产和转换原则；实例是否可展开、原生行为是否一致、成本是否具备和精度是否达标分别报告。

框架对原生观察的动作声明解析与模板编译分开：先取得统一动作、条件、参数和状态成员绑定，再由共同编译器构造模板。原生调用输入也可交给固定来源库做独立候选选择和实例化检查；目标图只用于取得本次调用的声明及结果对照，不编译或补充来源模板。公有存储绑定若作为输入提供，检查不授予其生成过程或跨调用历史资格；局部内容对应也不代替控制轨迹与跨调用因果验证。

## 原生事实到粗图

框架提供统一流程、模型层次、批次成员及必要输入输出；runtime 提供真实提交、队列、stream/event、资源生命周期和传输事实。采集时建立能穿过异步边界的工作/资源关联，不能在事后按线程或相邻时间猜所有权。

粗图节点是一段明确职责、参数、执行资源和对外端口的工作。一个语义区域可以包含多个 CPU/设备资源片段；片段不等于一个原生函数，也不等于一个最终模板。

数据输入的端口位置表示消费边界，存储位置不决定消费者在哪种资源上执行。普通输入在调用／设备入口就绪；同步主机读取可以声明在调用返回前完成消费，来源保留进入和实际等待，将数据依赖接到该返回边界。该边界是消费已完成的保证，不声称测得内部复制的精确时刻；不能把它移到设备入口，或要求CPU进入前完成整个读取。核心从声明端口开始保护本次读取，保留至其消费结束，之前的写入和后续物理复用仍须有依赖。

提交线程只按实际设备任务和必要等待形成片段；句柄创建、销毁等管理记录用于解释资源生命周期，不因其插入位置新增业务片段。观察器自身的事件查询和释放明确排除。辅助 stream 根据 API/队列追溯到提交它的语义范围，其完成依赖使用原生事件与等待；不能只承接显式通信函数，也不能统一加上调用返回屏障。

设备记账命令由 runtime 原始元数据识别，不按通用任务名称一概删除。Ascend 的任务编号回绕须与 TS_TASK_FLIP 的 stream、任务号及 SDK 批次编号对应；仅用于编号记账的命令不成为业务工作，其他同名 placeholder 的内存或同步作用仍须承接。

| 必须保留的边界 | 原因 |
| --- | --- |
| 外部输入、输出及必要共享写入 | 决定依赖、shape、别名和后续可见内容 |
| CPU 进入/返回、必要提交及设备完成 | 决定原生控制何时继续，保持异步行为 |
| 跨 stream 信号/等待和中间数据就绪 | 避免删除依赖或增加虚假串行化 |
| collective/P2P/KV/metadata 交接 | 保留参与者、方向、数据范围和完成责任 |
| 分配、驻留、引用和释放的可见效果 | 保持资源和控制状态的正确提交 |
| 目标变换需要独立处理的内部部分 | 使成员、形状、重复和通信变化可表达 |

同步传输服务在全部内部任务完成后返回，可作为一个封闭的粗工作，拥有对外数据范围与完成端口。runtime仍以队列生命周期、实际提交及显式服务身份核对内部覆盖，要求执行落在服务区间内；线程池偶然派工及私有队列数量不进入模板结构。共享队列的跨服务顺序必须已由保留的调用线程表达，跨调用者共享或中间可见作用须先导出接口。服务整体承担内部协调与搬运，调用线程表达等待，不再同时计费内部调用。任务对应使用真实队列提交顺序，不用CPU与设备时间包含关系猜身份。

控制流程中的 CPU 张量 collective 也有跨 rank 因果。CPU/设备分类依据原生声明的进程组职责；无设备控制用 CPU 张量及 Gloo 承载设备元数据，不改变其原生执行类别，也不能因此切出额外 CPU 通信动作。共享适配切口先结束前置 CPU 片段，独立交接原生通信组、操作、元素数量及根角色；粗图以主机进入/返回作为通信就绪/完成端口，使用同一通信连接机制。原生代码与元数据 broker 唯一计算实际值，核心只推进执行边界。控制先发布输入，再提交通信图，图返回后消费结果；不能在本地图完成后才向 broker 提交输入，否则会额外等待同伴的图返回。结果保留至所有参与者消费，广播根先返回也不回收迟到接收方的数据。空 Gloo 归约和单成员组不增加汇合，广播只依赖发送根；不把元数据通信扩大成全局屏障。通信区间保留工作责任，实测阻塞墙钟包含等同伴时间，不能直接作为纯 CPU 或纯传输服务成本。

CPU 点对点元数据由原生 Gloo 或控制 broker 各自维护实际消息和 Work；观察层只记录路由、载荷布局、投递和首次成功等待返回，不另建消息队列。阻塞 send/recv 与其内部异步调用属于同一次操作。每次运行内按原生进程组、端点、tag 和该通道顺序识别消息；这份顺序不用于跨运行逐次配对。投递返回、等待完成及对端等待分别保留，不能要求双方都调用 wait 才允许一侧完成，也不能把投递当成完成。

来源清单明确全部原生参与者，记录不随设备代表筛选而省略协议端点；控制观察也先声明协议范围及全部 actor 与参与者的对应。窗口前已经投递、窗口内才等待的 Work 保留原投递身份；通道起始位置与未消费尾部明确记录。协议时间用共同主机计数器定位顺序，阻塞墙钟不直接成为服务成本。控制端按需输出 broker 已有事实，独立评价再与粗图边界连接；协议记录本身不构成新的模板或成本模型。

协议因果对照在每次运行内独立建立。来源按线程计数器的严格先后连接粗图；相同计数值不合并事件或猜顺序，必要边界发生碰撞时明确保留未验证范围。控制按实际调用返回及只读协议记录的先后连接，先确认消费前双方均已投递，再添加该协议所要求的依赖；不能用后续投递修补已经提前发生的消费。跨运行只比较已具备独立身份的动作边界，不比较消息序号。缺记录与没有执行通信分别报告。

同资源上内部封闭的连续工作可以合并；同一 stream 只是必要线索，不是合并证明。若内部信号允许外部先行，必须保留相应中间端口，不能统一推迟到片段结尾。 同一语义片段内，相邻 host stream 等待若没有新的业务提交且不跨子调用或外部端口，只保留首次等待；重复 API 的 CPU 服务开销仍归入片段。首次等待即使来源 stream 为空也保留，以等待目标运行的实际前沿；事件等待和新的 stream 前沿不按此规则删除。

归约覆盖计算、复制、通信和同步工作，没有被删除的费用责任。CPU 自身服务、排队、设备工作和等待分别表达，不叠加父调用墙钟与其内部成本。节点开始与完成由依赖及资源决定，原始事件间的时间距离不自动变成因果边。

插桩点只定位边界，不构成业务提交或完成依赖。解释器在所有端口、状态访问和同步依赖建立后，将设备区间收束到原观察范围内的真实载荷及必要原生端点：实际事件记录、等待和内部依赖继续保留，观察器的首尾标记不独立延长设备生命周期。隐式设备端口及引用该区间起止的状态/数据边界共同重绑定；内部原生坐标、CPU区间、载荷及语义归属不改变。收束成单点的区间使用boundary，不伪造设备服务；既无载荷又无显式引用的空区间和隐式端口删除，存活锚点统一重映射。缺少可定位工作而仍有外部引用时保留原范围及证据限制，不猜完成点。该规则不删除调用或CPU控制工作，不按框架函数、模型或shape判断。

CPU工作不按observer调用切碎；设备片段保留实际提交及必要就绪，原生顺序坐标不直接当作服务时长。设备开始/完成按stream内命令顺序保留，零耗时等待仍有两个逻辑边界；实测时间留在来源记录，不能因同一时间戳合并结构。等待由真实API定义，即使运行时省略物理任务仍保留逻辑作用。需外露的位置由明确提交和必要因果确定；内部变化先按资源共享、跨界依赖和中间消费者判断能否封装，不要求所有微观命令先取得唯一总序。必须外露却无法定位时保留证据缺失，不猜位置或删除作用。

时钟换算归 runtime 适配层。Ascend 在观察窗口前后分别查询设备计数器，并用主机 RAW 时钟包围实际查询；每端保留查询区间最短的样本。解释时先撤销 SDK 的导出偏移与频率换算，再按两端计数器和主机区间中点建立线性映射。原始查询区间保留为测量不确定性依据，窗口外不授予设备边界测量；该估计不提供零误差保证，也不自动放宽评价容差。校准不得读取目标结果、等待先后约束或模板选择结果，缺少校准的旧来源不自动补授新时间资格。

对已证明属于片段内部的细节，不要求逐项匹配；证实流程外的记录只作诊断。必要外部作用不明确时，保留具体区域、端口和缺失依据，不依据整个 trace 的未知总数一票否决，也不按名字默认忽略。

缓冲区的整体 shape 与实际读写区域分别表达。KV 缓冲区的层布局只作为元数据，不再要求另一份整块 storage/version 外部绑定；状态访问合同及目标资源服务唯一解释实际地址与读写。共享同一 allocation 不代表整块缓冲区都存在依赖。KV 等持久状态按 layer、请求及逻辑 token 范围声明访问，由资源所有者解释共享前缀和页映射；不因共同使用一块缓存就给无关请求增加屏障。内部张量观察如需跟踪别名和变更，只保留边界可见的版本及来源，不持久化逐操作表。

KV 访问同时声明资源池绑定、逻辑 token 范围、每 token 的逻辑载荷宽度及其中的字节切片、执行起止边界，不能只藏在可被模板整理删除的通用元数据中。来源由语义插桩点同时声明实际区间、范围规则及访问所在的执行区间，模板构造校验两者一致，不按读写类型补造 attention 专属规则。共享定义保存按批次成员求值的范围规则、来源域内固定的载荷切片及起止引用，层号保存在具体绑定中；目标实例根据自己的请求、context 和新增 token 生成区间。适配器定义逻辑载荷与真实布局的对应，当前 paged MHA 按每 token 的 K、V 顺序拼接，由实际 shape/dtype 取得宽度；核心不解析 head 或物理设备地址。布局张量的 storage/version 不替代这份范围声明，范围声明也不等于页内容已经就绪。

读开始依赖所读内容就绪，读完成后才允许覆盖或回收这段内容；写入也有开始和完成，不能把一次访问压成一个时间点。attention 声明采用所属设备区间，传输声明采用有实际完成依据的服务区间，不据提交调用返回推断设备完成；需要区间内部更早就绪时，须有独立端口证据。原生 KV 池布局保留实际层范围、head 数、存储 dtype 和 K/V token 字节宽度。模板和来源域不保存设备地址；原始注册与传输事实可保留地址，用于解释两端逻辑区域，解释后不作为跨运行身份。适配器可用独立地址坐标执行原生分片算法，再交接统一区间；传输字节数与有效 KV 内容范围分别表示。资源所有者将逻辑范围映射为实际页内字节区间，共享前缀保留相同物理页身份，不按整个页池添加依赖。多个已提交写入可以合并覆盖所需区间，但读取仍须等待相交写入的实际完成；只写入一个 head 或只有 K 时不能把整个 token 的 KV 标为已初始化。完整 token 范围保持一个连续区间，部分载荷按各 token 的切片展开。

来源粗图保留可复核的原生边界依据。原始 trace 可作为阶段性取证材料，在正式图与必要事实发布后按消费者释放；共享模板不内嵌全部原始 API/task 记录。

## 子图切分

统一流程提供选择、准备、模型执行、结果处理及输出的顶层组织。模型主体依实际结构识别 embedding、重复 decoder 层、attention、MLP、归一化/残差和输出角色，具体切点取决于复用、变换和外部可观察行为。

父区域拥有自身工作，并通过具名端口组合子调用。一个子图可以跨线程、stream 和 rank，但必须保留独立资源及对外作用；语义归属不自动产生串行 CPU 调用关系。

张量分配来源和最后写入来源分别记录。原地修改既有存储只改变写入来源；切分后分配来源在动作之外的存储由目标调用方绑定，不能因本动作写过就转为本地新分配。修改前输入和修改后输出保留相对版本关系。

数据输出端口表示该版本内容的实际就绪边界。父调用直接转交子调用已经产出的同一存储版本时，端口引用子调用的原有就绪点，不改用父调用较晚的设备结束；CPU 返回和整个调用的设备结束仍各自保留。跨兄弟调用或其他动作不借此移动端口，版本更新也重新建立生产边界。该关系在来源解释时确定，由模板的跨层事件引用保留，目标执行器不按模型或 PP 拓扑增加特例。

动作模板只保留自身事件，不复制来源中前一个或后一个动作的事件。跨动作数据由具名张量输入及版本绑定，串行资源由入口/出口交接；来源的具体生产者和后继消费者不进入模板身份。跨边界数据或信号依赖必须对应到切分后实际保留的输入端口；被切掉的父调用或相邻调用中的声明不能替代本子图的输入。未能对应的依赖不能静默丢弃。

原生控制决定调用次数的流程，按调用进入、子调用和返回切成可复用的执行片段。观察端与控制端共用调用生命周期：进入子调用前结束父片段，子调用返回后继续父片段；目标按真实控制顺序逐段实例化，不复制来源的整批子列表。包围调用的 scope 只保留层次与边界，不再重复拥有片段中的工作。独立提交的选择动作同样暂停父片段，不能既作为父片段内部工作又独立展开。片段以语义操作、是否位于调用入口/出口及实际批次变换路径选择，不以请求组合或来源出现序号选择；局部几何和必要条件从本次原生输入取得。观察端和控制端均记录原生实际执行的筛选、清空和合并，不重新实现谓词。

片段候选由适配器根据实际输入、设备、同步和状态作用分类，并保留局部参数与真实分支条件。没有更强作用合同的片段使用前后子调用边界；来源与目标由共同调用生命周期直接声明 continuation，模板生产核对所属操作及完整切口后消费该声明，不再从相邻 scope 重推。CPU 元数据投递与等待同样暂停父片段，不把阻塞时间吞进前置工作；协议所有者仍负责传输。动作时间对应保留完整 continuation，不能用模板类别或片段序号代替。

适配器可以显式声明某个调用的剩余片段仅做 CPU 控制：必要设备和状态作用已下沉到独立子调用，剩余分支和循环仍由原生代码运行。此时来源不插入设备标记，模板生产必须核对每段确实只有控制线程上的一项工作及进入/返回端口，没有子工作、等待、通信、张量或状态访问；核对失败即表示切口不完整，不能丢弃额外作用。通过核对后，同一操作的 CPU 控制片段共享结构，不再按相邻子调用的排列组合生成候选。该声明不代表不同片段耗时相同，也不是缺少候选时的 fallback；未声明的片段仍按完整条件选择。

SGLang 的固定 token 输出流程在结果处理首段由CPU读取本批token，随后按原生请求循环调用缓存、释放和发布。token消费以该首段返回为边界，来源CPU／设备存储不改变这项主机读取职责；PP显式等待、内部实际同步及生产者就绪位置继续保留。中间hidden-state proxy由模型及传输接口发布和消费，结果处理不因对象持有proxy而声明额外读取。模板选择将结果片段区分为输入消费与剩余控制，保留 phase 和状态访问条件，不枚举请求结束顺序。剩余控制片段须经同一纯 CPU 校验；采集已有的设备定位标记允许保留，但不能含实际设备工作或额外等待。生产与目标共用分类函数，不改变原图、依赖或耗时。该合同不覆盖隐藏状态、额外输出、设备卸载等未纳入当前输入范围的机制；出现新的实际作用时需完善切口，不能忽略或默认归入控制类。

片段继续使用同一种粗图、模板、资源前沿和返回反馈，CPU 返回不等待无关设备尾部。输出发布属于 publication 片段的返回，本地请求完成属于相应结果或传输收尾调用的最终返回；发布最终 token 不代替之后的资源收尾。PD 的 Prefill 响应保留为本地调用工作，用户输出由 Decode 发布；参与者独立完成及对外输出不共享一个完成标记。

stream 同步保留等待起点、被等待的 stream 和恢复端点。命令按显式 submission 链追溯到接受入队的边界，队列工作线程稍后执行 API，设备再按原依赖启动；不能等到 API 执行或设备开始才登记命令。目标等待包括起点之前已接受的命令，以及该 stream 最近的已完成命令；未入队的未来工作不加入等待。来源图保存本次实测的具体信号边，但这份动态前沿快照不固化进模板，包括源、目标都位于动作内的情况。普通图内依赖照常保留，事件句柄等待、通信和跨 rank 协议不能由 stream 同步替代。

来源中的提交证据必须与等待的层次一致。Ascend 的 SDK launch 区间可能包含内部同步，不能把整个区间返回当作设备提交：根据真实队列生命周期和驱动提交记录，在 SDK 关联的命令组上界定提交区间，再确定已提交前沿；不能从设备完成时间反推提交。一个关联包含多项工作时，不假定驱动调用与设备任务逐项一一对应；等待落在该组提交区间内部而没有更细对应证据时，明确报告前沿不确定。普通命令和传输服务复用同一队列身份解释，服务归属仍由原生调用者提供。

具名完成信号使用独立 signal 端口，不伪装成张量。来源输出指向真实 Event.record 的设备位置，输入指向实际 CPU 或 stream 等待的恢复位置，并保留两者的真实依赖；模板仅保存动作边界上的端口名和局部位置，删除原生事件身份。目标调用按端口名绑定本次运行的信号代次，执行层将输入连接到已发布的完成位置。原生句柄重新记录时使用新代次；句柄存活期间保留其完成位置，已提交的依赖独立保留，不常驻保存整个事件历史。CPU 等待约束调用返回，stream 等待约束设备继续执行，两者不能互换。

事件记录所在的stream、设备等待落入的stream属于原生操作输入。适配器从实际stream对象取得角色，来源编译和目标提交均将其作为stream条件，沿已有候选选择绑定对应队列；不能仅凭同名API或相同shape套用其他stream的实现。角色不同可以共享图定义，具体调用绑定仍须有相应来源。CPU等待不指定目标stream，其完成依赖由实际信号代次提供。流水线槽位和其他观察位置仍单独约束绝对时间，不代替操作的stream输入，也不生成新的设备图定义。

信号代次在整个 serving 会话内唯一，由生产者保存，其他参与者可通过同一身份等待或查询。回收依据所有参与者仍持有的引用，不能只看生产者本地引用；交接协议仍须保证发送方在接收方取得引用前不释放它。跨参与者不复制完成状态，所有查询仍读取同一执行时间线。

非阻塞状态读取有独立 query 动作。共同调用切分先结束前置 CPU 片段，query 承担读取的 CPU 工作，在返回边界读取当前状态，后续原生分支再继续。查询种类决定结构条件，请求或信号生产者属于调用绑定，结果和忙轮询次数不生成模板类别。查询不额外连接被查询信号的完成等待边；原生读取 API 本身的工作和同步（包括标量读取的本地 stream 同步）仍按实际图保留，不假设 query 一定是单段纯 CPU。metadata 准入门检查当前可见性，不作为必须等数据写完的普通内容读取。实际消费已准入的 metadata 仍使用原有状态访问依赖。源端保留原生读取区间和结果，API 内部的具体读取时刻没有被声称为已测得；跨运行状态对照不能用 query 图形相同或轮询次数相同替代。

异步通信的 Work 也使用这一信号合同。框架观察提交及其 Work.wait，runtime 按实际事件代次、API 与队列归属解析通信结束点；不能在提交返回时补录一个事件冒充通信完成。通信缓冲的读写持续到实际通信完成，接收输出也在该位置发布，允许调用方 stream 先返回。原生 Wait 是否阻塞 CPU，由实际等待证据及对应实现决定，不能仅凭方法名推断。

KV 读写区间可属于设备流或可并行的传输服务。区间必须处于同一执行资源，并具有从开始到结束的真实因果路径；可并行不等于没有依赖，也不应为了接受该区间而把整个服务资源改成串行。区间内的读写冲突仍由资源内容依赖连接。

通信的来源序号只表达实际通道内顺序。动作切分后将其归一为本动作内部的位置，目标跨动作序列由执行器维护；不能因为同一通信在来源里出现先后不同而生成另一类候选。原始来源图保留实际记录。

stream 完成信号可以要求切出片段终点，但不因此单独拆出其末尾内部 kernel 的开始；片段的提交由自身入口统一表达。事件句柄的记录/等待仍保留各自真实提交，不能借粗化删除必要控制关系。

选择/准备/结果中的 CPU 内部循环可以整体成为服务，前提是实际输入输出、共享状态和返回端口完整。集合变化不要求复现内部每个辅助张量操作，也不能隐藏对外独立的数据、通信或释放。

父控制调用中的批次筛选、合并通过共同批次变换边界交接，保留左右输入及结果的槽位、长度字段。输入成员数与结果成员数分别参数化，实际原生函数决定保留哪些请求；空/不变提前返回不产生虚构的设备数据访问。selection 作为控制包络，按原生调用交错提交父片段、准备、缓存匹配和变换；mix 内部的 merge 归 mix 所有，不重复提交。采集与控制共用批次 ABI，准备返回的值身份绑定到相应原生张量，后续变换通过显式输入引用连接生产者。输入在原地修改前取证，输出在调用后发布；缓存匹配保留命中/未命中的真实执行作用，不把设备拼接归为纯 CPU。内部暂存字段不因此全部变成模板端口，新增跨动作消费者时须同时补齐生产端。

批次分配通过allocation调用承接原生alloc_for_extend/alloc_for_decode，沿共同片段机制保留内部独立的释放操作，不能将淘汰组合固化为整个分配模板。准备的前置片段发布长度张量及已有槽位，分配返回缓存位置、槽位与长度，后续准备片段以这些返回值作为输入；每个片段维护自身端口，不能只在整个父调用的入口/出口交接。独立资源调用不使仍被借用的输入失效；返回值仅按显式调用合同替换后续输入，不自动上传到纯控制父调用；显式输入已经承接的生产者不重复补写端口。

原生实际分配器类型随来源实现域发布，控制端使用同一声明。adapter根据原生算法和已知请求进度确定局部实现条件，采集与控制共用；不读取额外设备内容，也不由核心猜测框架算法。分配需求上下文只服务资源调用，核心唯一维护资源状态。独立接口和算法条件不自动证明循环次数、空闲页整理或内部同步可互换，仍需各自的来源与变换依据。

原生索引helper的逐请求循环在adapter中形成独立调用片段。采集只观察该函数的循环回边与实际进入的已有页、完整新页、尾页分支，不新增设备标量读取；行位置只用于定位插桩，不进入公共图或模板条件。控制消费核心分配结果中的new_pages，以CPU视图执行同一原函数的索引计算；只提供本次实际分配的页，不复制整个空闲池或重新决定资源所有权。前置向量工作、循环间延续和返回保留在父片段，各次循环的CPU、提交和设备同步仍由原始观察解释，不压成单一CPU服务。

延迟回收页的合并/排序由核心页池在有序前缀不足时唯一执行，分配结果以members交接成员绑定，以ordering交接本次确实发生的排序及其原有序页数、待回收页数；没有排序则为null。控制视图先提交相应pages.sort调用片段，再进行索引计算，不再次查询或重建空闲池。来源直接观察原生merge_and_sort_free的数组长度及执行；该操作不依赖父批次phase。核心逻辑账本已完成排序，不代表设备索引数组已经就绪，后续执行仍须遵守来源保留的stream和完成依赖。槽位分配保持成员列表交接，不消费页排序结果。

循环每次迭代以metadata输入借用同一输出存储及版本，避免宣称读取尚未全部初始化的内容；首次调用先登记分配身份，写入仍从data输出发布新版本。父片段接回输出及已有借用输入。首次登记属于调用绑定，不进入模板选择条件；只按原生实际页处理分支选择成员模板，不以请求序号、循环总数或kernel数量划分类别；原生异常中止当前片段，不发布成功延续。Python线程trace在helper返回或异常时恢复，已有trace占用时明确报错，不覆盖其他观察者。

模型层号、请求成员和具体调用不是模板类别。不同实现确实改变对外结构时保留分支；仅内部 kernel 名称、数量或调度包不同，不新建语义模板。

## 归一化

| 内容 | 保存位置 |
| --- | --- |
| 稳定工作、参数关系、外部读写及局部端口 | 共享定义 |
| 子调用、必要顺序、端口连接及资源关系 | 共享组合 |
| 层号、权重/KV、角色、实际资源和固定实现数值 | 调用/角色绑定 |
| 请求、长度、成员、到达和动态状态 | 目标实例 |
| 原生事件号、绝对时间、地址、线程/stream 编号及内部明细 | 来源依据或可选诊断 |

共享身份保留真实语义、必要结构、类型/几何关系、状态效果和实现条件，排除捕获局部编号和动态取值。共享按确定的规范化完成，不开发任意图同构或数学等价证明平台。

跨层事件连接逐级通过子调用的导出边界交接，父调用不直接读取后代内部事件编号。接口从实际跨切口的端口、工作及依赖推导，编号按边界顺序规范化；局部事件只由本定义解释。导出仅指向局部或后代边界，不把导入再次导出形成引用环。父定义保存被调用角色、实现入口、参数集合、具名端口及导入/导出接口，具体子实现编号唯一保存在调用绑定中。接口分别保留执行资源别名、边界事件别名、端口用途与 dtype/shape 规则；不把同一 stream 上的两个不同边界视为同一个事件，也不携带子实现的内部事件编号或原生放置。每个调用绑定都需核对其实现的接口、固定参数、资源和张量绑定；父结构相同但子实现不同的来源可以共享父定义。共享父定义不代表能够任意替换或重复子调用，未观察组合仍须有条件选择、数据及状态交接依据。

事件的共享归属与依赖的实现归属分别确定。连接子图内部事件与该子图显式端口、状态访问或工作边界的依赖保存在子图中，即使共享端点本身归父层；父层继续提供该端点的真实绑定。存在互不包含的候选归属时，依赖保留在共同父层。编译不删除或改写原始依赖，只调整由哪个定义持有；具名端口先登记导入身份，避免内部实现的遍历次序改变端口含义。其余跨切口依赖及资源前沿仍须显式导出，不能因为调整归属就丢弃。

模板资产加载时核对子实现与父接口，候选分组以相同接口、常量和外部绑定为前提；动态选择只检查本次参数、guard 和子调用选择，不为每个候选重复构造接口。框架适配器只补充原生输入合同特有的要求，名称、常量值和共同参数约束由核心选择器维护。

重复层和有明确等价依据的 rank 共享定义，各自保留独立权重、KV、资源及状态绑定。输出 head、首尾 stage 或专家部署不同不能强行复制；共享结构不自动授予成本数据共享资格。 模块位置与实际路径分离，局部 KV 层位置与全局模型层号分离；跨阶段复用依据已初始化模块和池布局建立一一对应，不将层号写入共享定义。专家路由仍以实际模型层查询，模板参数使用本阶段专家层位置，避免重命名共享定义来适配另一个阶段。

代表角色的等价关系由来源初始化事实授予，目标不能自行修改环境来获得复用资格。框架适配器负责将源角色的通信组、参与者和组内根绑定为目标角色的实际关系，P2P 使用当前原生提交的完整路线；这些绑定在图实例化校验前完成。共同模板与执行算法不解析框架 rank 公式，等价声明也不能代替跨层位置或跨池传输的明确重绑定。

PD 的目的池和完成端口使用原生拓扑映射内的局部位置；真实对端只由适配器绑定。等价判定同时比较两侧池几何、元数据行宽和多源/多目的组内分片位置，不能仅因本地 shape 相同就共享不同传输职责。每个池按自己的原生层范围重绑定，远端层号不沿用本地偏移。

局部实现可以在同一采集任务的角色库之间复用，但不共享整棵动作或运行状态。适配器依据真实调用及初始化事实声明可隔离的 ABI 和局部实现域；没有对应事实时不推断资格。核心只接受无子调用、无请求状态访问及外部完成信号句柄的局部叶子，核对具名接口、张量别名与版本/写入关系、完整资源槽位及边界可达性。声明的流等待保留等待资源、开始边界和完成端口，等待开始亦参与边界因果合同；实例化仍从目标调用当时的提交前沿建立实际依赖，不搬用来源完成时间。连接时保留不同实现的实际工作及 guard，只共享定义；选择时使用调用方原有张量身份、通信组内位置和物理资源，不复制另一个角色的 frame。接口相同不能作为删除复制或资源工作的依据。

局部实现域与完整 worker 域分别校验。SGLang 的连续输入、张量返回 NPU gather 由实际 communicator、输入布局和 axis 声明；专家计算及 dispatch/combine 由已观察的模型调用角色、通信操作、专家布局和所属模块声明；跨phase保留同一初始化模块所有者，不能借整体模型配置相同就忽略层内权重/实现归属。局部环境域统一限定运行时、初始化模型配置、dtype、权重加载形式、逻辑TP/PP/EP及专家层几何；容量、PD模式和外层phase不决定局部实现域。具体接口、别名、流等待及组内职责仍由调用合同约束，同名方法或同输出shape不能跨不同模型/布局互换。完整 worker 的 Prefill/Decode 域、角色和池规则不因此放宽。每个生产任务只连接本次采集的候选，不扫描或合并历史生产。

模板数量增长须说明新的是稳定工作、对外关系还是原生实现分支。只因请求长度、来源调用、层号或内部 task 数量增加而分裂定义，属于生产/归一化问题；不设任意模板数量阈值或逐配置白名单。

原生控制结果与模板执行类别分开。框架已明确为无张量操作的提前返回分支，可以共享经来源核对的 CPU 控制结构；核对须排除设备工作、状态作用、子调用及等待/通信边界。观测用的无载荷设备标记不当作计算成本，也不据此假造设备工作。筛选前后成员等工作特征仍随目标传递，逻辑成员由原生控制维护；结构相同不授予成本数据等价资格，改变张量或资源的分支不能借此合并。

模板适用条件由局部接口决定，不能把继承的工作上下文全部作为实现条件。SGLang的请求缓存、页释放/合并及槽位释放接口不读取父批次执行模式，因此这些接口的segment不以phase区分类别；原有工作记录、参数、guard、状态访问和子调用边界仍保留。来源编译与目标动作选择共用适配器的条件规约，模型执行和批次准备等依赖执行模式的动作继续保留phase；共同模板选择器只消费规约后的条件。

显式完成句柄的等待以生产者工作、CPU/设备等待方式和目标stream表达局部工作；等待时调度器的槽位及消息现场保存在work.observation_context。结构与逻辑调用配对不以该现场划分类别，CPU返回的绝对时间旁路仍完整保留它；完成生产者的时间资格单独按逻辑工作及实际signal输出核对。实际完成依赖始终由句柄代次及signal端口连接，不能只凭生产者描述相同就认定两个调用是同一次等待；重复身份或现场不同仍报告无法逐次配对。查询及无显式生产者的stream前沿等待继续保留其完整上下文。

成功查询和完成通知的实际消费以observation关系表达调用间因果，不生成true/false模板。它表示已经读取的完成事实，signal则表示显式等待。真实图保留完成到成功读取的关系；目标由控制交出已读取的完成边界，连接下一动作入口。切模板时移除来自动作外部的observation，保留局部体及其他必要输入的严格检查；该关系由目标实际控制重新建立，不冻结来源查询结果、不回写已返回的查询，也不增加等待。

## 参数与有限变换

模型尺寸和角色优先来自原生配置、模块及实际参数；工作量来自目标批次、请求位置和资源所有者。shape 关系来自明确算子/接口或原生实现规则，不从几个观测点硬拟合公式。

变换包括目标参数求值、固定层调用的共享复用、成员访问范围展开、有限实现选择和端口/资源重绑定。通信及传输按拓扑和实际数据范围表达，不能只修改张量 shape 而遗漏参与者、等待和数据量。固定 collective 通道归所属实例；显式传输由适配器绑定完整路线，两端使用同一通道及有序参与者，不在接收后各自追加实例前缀。一个 transfer 端点声明一个有方向的载荷布局，普通张量使用 data 端口，持久状态可使用 metadata 端口并另行声明实际 KV 访问；布局相同不替代内容就绪和覆盖依赖。

同一来源域可以覆盖成员、token/context、并发和 KV 容量变化，前提是必要参数、分支和外部端口仍可确定。内部设备实现变化但对外合同保持一致时，不要求新增逐 kernel 模板。

逻辑请求 token、补齐后的模型行数及专家接收行数分别表达。采集与目标使用同一原生批次布局规则，采集端再以实际模型输入独立核对；不能在模板编译时把来源数值覆盖到参数中修正不一致。层间分片关系来自原生通信布局，条件专家负载来自 workload 路由区间；接收行数按具体 backend 的复制或去重语义计算，不能默认等于不同 token 数。 层 shape 规则与采集前代表角色判断消费同一份实际通信布局；比较分片模式、组宽、已选实现及层边界标志，排除 rank 位置和临时缓存。

每层动态特征在动作入口按逻辑层绑定，进入层模板后转换为相同的局部参数名。派发、专家计算和合并通过这些局部参数声明端口形状，避免把层号写进共享子图的参数名称。真实分支条件须对应实际原生分支；例如接收侧反置换仅在多本地专家且非空输入时执行，不能把单专家布局也强行分成两类。

模型、dtype、TP/PP/EP、backend、框架/runtime 和页布局改变时分别规划来源域。跨域迁移不是默认能力；重新采集也不授予原生不支持的配置资格。需要新的规则时补充统一机制，不按目标案例补图。

来源域由 adapter 从实际生产环境中提取，核心在选择动作前核对目标域。 缓存域记录原生实际创建的类型、生效的禁用状态和淘汰策略，调度机制记录实际启用的 chunk/mixed，不能只保存用户请求的开关；目标装配核对缓存及 P/D 模式，原生资源工厂核对所采用的缓存视图对应来源实现。物理部署位置和目标初态属于调用绑定，不混入共享定义；worker 的局部职责不能因全局 rank 更名而被忽略。域匹配只能证明已记录字段相符，不能替代框架构建身份、控制配置及来源范围的完整核对。

完整任务域仍决定worker、模型和PD对端装配。SGLang的merge与subset批次动作使用成员数组，不读取模型分片、KV几何、专家部署或PD对端；这类动作可在模型、缓存/调度机制、页布局及runtime相同的来源之间跨并行度复用。共同层仅导入无子调用、KV/槽位作用、通信信号及外部写入的闭合叶动作。适配器从接收库实际观察到的批次准备、分配及变换取得前台资源集合；共同层在该集合内按唯一资源角色重绑定，保留资源别名、全部端口、局部等待、guard和张量版本，不从整个worker的同名后台资源中任选。不能按函数同名跨模型或改变模型计算的适用域。导入候选清除接收库中不存在的观察scope，运行结果记录来源库/入口与接收库/入口；原始资产不变，重复定义和入口不增加，候选歧义仍由选择器报告。当前token-only输入下可选内部张量操作归同一粗片段，未来性能建模须另行表达其工作量差异。

候选同时使用原生控制路径和可求值的局部条件。适配器在实际子调用上声明形状/布局条件，核心逐层用来源参数核对；目标从动作参数出发，沿调用关系求出各层参数并选择本层实现。固定实现数值从本层常量绑定取得，不把观察到的动态长度固化成条件。输入/输出的实际几何仍独立保存并校验，不能由条件表达式反推真值。

张量值与存储按所有实际使用位置及写入者的最近公共作用域归属，并在该范围内编号；跨动作外部存储归动作根绑定。子树私有对象不占用其他子树的编号，跨子树共享仍归共同所有者，不能通过重命名切断别名。

选择器在初始化时按动作、控制条件、调用位置、相同的已观察父调用结构及本层绑定建立局部候选组。组内保留接口、常量、资源、张量、通信和所有跨子树的数据引用；共享数据的 shape 关系逐层代入到本层参数，版本、写入者路径和访问位置继续相同。内部私有子树不再要求整棵绑定树一致，各层根据目标参数和明确条件选择已观察实现，再沿该实现原有的子调用及连接展开。父结构、共享绑定或接口不同的来源不任意拼接，仍需对应完整调用变体；不从局部条件推导未观察的循环次数。多个可行实现报告歧义，候选与来源记录只读，生成的组合不标记为完整观察过的调用。

候选条件由适配器提供原生实际执行的有限语义路径。采集和控制共用路径读取：批次筛选记录保持/子集/清空，合并记录实际发生，不复制原生筛选谓词，不按成员数或观测序号猜选候选。路径相同仍不能唯一确定结构时继续报告歧义；路径本身不证明模板覆盖完整。

候选及其子调用在私有构造范围核对输入、条件、几何、别名和完成端口，再统一发布。失败不能污染调用者或偷偷恢复旧格式，全部候选不适用时报告具体缺口。

## 动态展开与连接

原生控制交出工作身份、成员、阶段和参数，核心资源服务提供本次槽位、页、驻留及就绪。模板不维护另一份可变请求或资源状态，也不从来源动态后态填入目标。

按请求关联的持久内容与普通批次张量分开表示。slot access 声明池、字段、读写、动态成员绑定和访问区间；来源保存实际请求集合，模板只保存成员绑定名，目标由原生 adapter 给出本次集合，再由唯一资源所有者按字段所属的资源池解析物理槽位。字段可以使用请求槽位，也可以使用具有独立容量与生命周期的行池；由 adapter 显式声明，核心不按字段名称猜测。筛选、合并或更换 batch 不改变同一请求的内容身份。槽位释放立即清除旧内容资格，在途访问仍保护复用；新请求必须先写入自己的内容才能读取。

持久槽位与 KV 的读取范围须由仍有效的历史写入，或本张图中因果上已完成的写入完整覆盖。先收齐本次访问，再沿真实依赖判断本地写入资格；不能要求初始化必然来自上一张图，也不能用事件编号推定先后或为缺失路径自动补边。历史尚未完成的访问继续通过跨调用依赖保护，多个写入片段可共同覆盖一次读取。

SGLang 的非 speculative FutureMap 使用这一合同：观察真实 stash 和 resolve 调用，读成员来自原生调用前的批次状态，写成员绑定到该 batch 的实际 req_pool_indices 对象，不回读设备索引或按张量长度猜请求。普通执行、PP 输出准备和 PD prebuilt 共用该观察。候选条件统一记录本次实际发生的字段读/写；零个成员不能悄悄绕过一个本应换实现的读写分支。

PD 首 token 元数据使用同一请求字段合同：原生 set_buf 是源端写入，实际 send_aux 服务读取源端并写入目的端，原生 get_buf 是目的端读取；get_buf 内部多个元数据张量组成一个逻辑字段，不逐标量建图。原生准入前对就绪标记的读取、接收完成后的行清零分别作为该字段的读写子调用；它们的次数由原生循环决定，不能固化在整轮队列模板中。预分配与接收处理按原生阶段分开，阶段内部仍沿真实子调用交错展开，不能让一次来源中两阶段恰好连续发生成为模板使用条件。观察同时保留双方真实缓冲注册、请求与行号预约、传输地址，用于核对请求身份及整行覆盖，地址和行号不进入模板身份。该抽象依赖原生生命周期：源端等待搬运完成后释放，目的端完成拷贝读取后回收元数据行；不能用本地 FutureMap 写入反推远端已完成，元数据行由核心的独立槽位池维护，原生决定申请和归还时机。原生构造函数提供容量，分配后在源端首次写入或目的端发布预约前绑定请求；请求槽位的释放不清除元数据行，元数据行的归还也不释放请求。物理行被归还时清除其内容有效性，尚未结束的读写继续约束下一次复用。 Decode 的预约发布自身具有调用边界，必须先让前序索引导出及必要设备同步返回，才能向 Prefill 公布可写位置；不能在父片段尚未提交时发送预约。传输完成句柄可提前提交给核心，协议通知则在全部必需完成边界就绪后才交给接收端；接收端合并实际发送组的最终通知并写入原生缓冲，仍由原生 metadata gate 决定准入。发送方保留尚未交付消费的完成引用，资源释放不额外等待接收方确认。参与者映射由原生 adapter 提供，层/head 切片由已观察域中的模板负责；目标不再重复重演一套物理地址算法。

实例端口通过真实生产/消费关系连接；CPU 返回、设备就绪、请求输出和状态提交分别交接。每次新分配的临时资源独立，外部共享资源按所有者绑定，不根据地址或整数相同推断共享。零元素张量仍交接形状和存储身份，但不产生内容读写依赖，也不要求数据生产事件；非空张量继续要求有效生产者。 模板构造核对边界 shape 后，将可变维度的零/正值条件保存在调用绑定中；目标选择保留这一来源结构边界，不凭尺寸变换补造缺失工作。该条件不证明其他原生分支在非空范围内不变。

来源观察须区分已有张量的视图和构造器交出的新存储。PyTorch 的 lift_fresh 在 dispatcher 入口接收已经物化的新张量，虽然参数与返回共享存储，仍属于当前调用的创建；不能仅按“输出存储出现在输入中”将其误记为外部来源。这个判断归 runtime 的操作语义，不能在模型或模板编译层按函数名补生产者。

原生句柄的完成查询直接读取具名 signal 在执行器中的状态，不以 CPU 占位事件的默认就绪代替设备完成。未完成查询只留下事件唤醒订阅，不复制完成账本；事件实际完成后恢复控制轮次，即使没有 CPU 调用同时返回。轮询属于原生控制循环，需返回可见接收边界，不能靠宿主忙等推进模拟时间。

原生控制需要构造后续调用的张量视图时，通过共同动作接口只读查询输出布局。查询与实例化共用候选选择、参数约束及张量形状求值，返回具名输出的 dtype/shape；不提交图、不分配目标存储、不消费资源变更，也不推进时钟。适配器据此构造原生需要的元数据对象，张量实际内容及完成依赖仍由目标图负责，不能以视图已创建代替数据就绪。

动作的 CPU 返回同时交付具名输出的目标存储身份和版本，身份直接来自该动作实例图。适配器以原生存储的弱引用关联这些值，reshape 等视图沿用同一存储身份，不把原生地址写入资产；下一动作可通过根输入端口显式传回引用，并声明仍存活的值。根端口的绑定覆盖子调用中同一存储的所有别名，核心继续检查版本、别名及读写依赖。原生对象回收后不再保留其值引用，在途依赖仍由执行器维护；拿到输出引用不表示设备数据已经完成。

原生常驻缓冲使用 adapter 声明的存储所有者名，独立于调用位置和端口名。SGLang eager 路径从已初始化的缓冲注册表读取实际字段及共享 allocation，观察其视图时保留 `buffer` 声明；临时分配和显式张量交接继续使用原有身份。模板保留该声明，目标按 worker 隔离常驻存储，并为一次调用内全部写入版本预留区间。一个常驻所有者不能对应多个 allocation，未交接也未声明所有者的外部写入不能猜成常驻缓冲。改变原生缓冲生命周期的运行机制须提供相应适配依据，不能靠当前样本地址相同或每次新建存储替代。

批次、张量和信号的存活集合统一在动作提交时读取。父调用暂停期间子调用可以产生新的对象及图绑定，父调用的工作身份可以保留，但不得保留旧的存活集合来指导回收；子调用产生的批次不能被随后提交的父片段误删。

调用前由原生分配的接收缓冲，通过具名输出端口声明目标分配绑定。新对象得到新身份，原对象复用时从上一次返回版本开始下一写入，模板内部相对版本仍由核心展开；不能按函数调用点把所有接收折叠成同一常驻缓冲。动作内部的新分配直接使用实例图生成的身份，不通过外部缓冲绑定覆盖。点对点传输按有方向的参与者和通道顺序配对，并核对两侧实际 payload 的 dtype/shape；CPU 协议消息到达不代替设备传输完成。

通信模板可在 `communication.agreements` 声明需要跨参与者一致的张量端口：`port`、`direction` 指定已有端口，`shape` 表示同时检查形状或只检查 dtype。适配器依据原生协议声明，核心在目标 shape 求值后按同一通信轮次核对，不读取框架名或 kernel 名。变长交换可只约束 dtype；约束同时进入局部模板复用合同，不能在共享实现时丢失。原始图保留观察事实，协议约束属于模板规则，独立对照仍比较真实端口几何。

没有观察到载荷端口时不从父模型形状补造。没有 agreement 表示该通信没有声明这部分核对资格，结果中的 `communication_payloads` 分别统计已核对端点、未声明端点、完整形状字段和仅 dtype 字段；未声明不能解释为载荷正确，也不改变已经取得的参与者/因果关系资格。 未声明端点不是缺少模板或需要补采的数量；是否进一步采集由该信息对外部协议、变换或后续成本特征的实际用途决定。

TP/EP 集合通信保留各参与者输入与本地完成。adapter 声明 channel、操作、成员、当前 rank 及本地完成所需的输入方；具体组与调用位置属于绑定，不进入共享定义。共同执行层按各参与者在 channel 内的协议顺序配对，保留输入就绪和完成两个端点，迟到参与者不得被当作已经完成。PP 消息保留发送、接收、等待及缓冲区生命周期；跨动作端点按工作、组、方向和字段对应，不按第几个节点硬配。

同一原生进程组的框架包装调用和直接 runtime 调用使用同一通信身份；嵌套包装只观察一次语义交接。组批阶段的设备通信也属于执行结构，不能用无设备控制进程之间的协调替代其目标依赖。

P/D 保留两个池和实际层/head/KV 范围，metadata 完成不能早于其所依赖的 KV。单边搬运用同一图声明两个池的读写，不虚构接收调用；确有双端原生操作时才配对通信端口。模板的池名是语义绑定，实例化将其替换为参与者身份；依赖构建访问实际所有者的内容状态，不另存一份跨池状态。页归还立即清除旧初始化范围，在途访问继续保护物理页复用，不能等待下一动作才失效。设备就绪后才能接入、读取或释放；不得用源端 API 返回代替所有目的端完成，也不增加协议没有的全局屏障。协议就绪依照原生通知组确定：若原生在整组传输完成后才报告成功，末块通知须保留整组及此前分块的完成依赖，直至所有接收端消费；非末块只保留各目的端自身的搬运进度，不向接收端制造原生没有的完成通知。发送调用保持非阻塞。发送侧成功发布与各接收侧可见分别使用具名完成事件：发送侧依赖完整传输组，接收侧依赖其实际需要的发送侧发布。adapter 声明参与者和逻辑工作，broker 暂存交付，核心沿共同事件时间线推进，交付后先入队再唤醒。事件可以先声明、再连接稍后提交的图信号，不能等发送调用返回后才允许后台完成；事件本身不占用额外 CPU/设备资源，也不按轮询次数复制模板。没有传播测量时不添加固定延迟，也不声称通知到达时间已与原生对齐。

执行事件使用稳定身份；所有者在动作边界交出仍引用的完成边界，执行器回收其余已完成历史，入队登记记录在生效后释放。stream 只额外保留最近一条已完成命令，后续等待仍能表达已满足的因果，不保存全部完成命令。数据层先清除已完成访问再回收事件，活跃值、资源前沿、未配对通信、在途工作和未结束调用保留。结果精简与完整诊断来自同一次执行，不改变控制或依赖。

执行器只维护事件、模拟时钟及执行资源，不决定动作或分配 KV。动作插入时由调用方绑定外部就绪依赖；串行资源分别接到自身前沿，不能统一等待前一动作的所有资源完成。入队、API 提交和设备执行沿原图关系推进，不能将整个动作插入解释为所有内部命令都已入队。

单独执行给定图时必须明确初始输入已经就绪，并为每个工作区间提供非负纳秒耗时；等待只由依赖解除，不另计固定时长。此类结果用于核对图的推进，不能代替 serving 状态绑定、真实成本或精度结论。

## 来源与评价的独立性

来源粗图和目标真实粗图使用相同表示与规约规则，但各自工作、端口、状态和依赖来自对应原生运行。真实目标不调用模板展开来补齐缺失事实，也不把最终图交给预测。

同源还原检查模板编译是否丢信息；它不证明原始规约或评价正确。独立目标对照检查工作、参数、必要因果和状态，另用直接原生边界核对共享规约可能遗漏的作用。

槽位写入可声明请求内唯一的 `publication`，表示同一字段同一版本的副本发布。只有适配器有原生协议依据确认载荷语义相同时才能声明，不能凭地址相同或时间冲突推定。核心按实际池、物理槽位、字段、请求及发布身份识别副本：同次发布的写入可并行，读者仍等待全部已提交写入；普通写入、不同发布、不同请求复用同一槽位仍保留读写依赖。该身份随模板构造和实例化传递，不是具体 rank、时间或来源事件编号。SGLang 的末块首 token 元数据采用这一声明，原生接收协议继续等待所需发送端全部完成；载荷一致性由原生控制及独立评价核对，不因此授予未观察字段的数值正确性。

异步协议的服务结束、成功状态写入和后续读取分别取证。适配器观察原生状态更新入口的实际前后值及时间区间，不额外轮询或同步；评价只判定互不重叠区间的必要先后，重叠保留未知。缺少状态写入事实不能以首次成功读取代替，也不从此推出精确通知到达或元数据载荷可见时刻。旁路可将实际写入区间交给具名完成事件；执行器选取区间内满足所有依赖的最早时刻，若依赖或登记晚于上界则失败。结果标明这是区间约束下的可行执行，不是精确测量；它不能证明区间内任意一种轮询交错都一致。

重复调用先分别确认来源内容和调用内依赖是否一致，再核对每个预测副本；依赖包括具名边界可达关系和工作位置，不能由相同内容推断。来源内部有差异时保留歧义，不按目标结果挑选来源。此类检查不建立逐次对应，跨调用生产者、通信轮次、查询结果和时间仍需独立配对。

受控时间验证可以从共同激活点逐步核对每个参与者的接口、实参及必要前置，再消费对应测量记录；消费位置只延续已验证因果，不独立定义调用身份。重复调用只有取得这份额外证据才能建立受控对应，不能从内容一致、一次同态快照或本地次数推定。该对应不改变模板定义、guard或原生决定，独立评价核对实际消费与原始事实；普通结构/稀疏时间对应保留其未验证范围，不自动降级为按序配对。

评价正常与负向输入须能分别定位真实差异、事实不足、依赖阻断和工具错误。不用总节点数、逐 kernel 名称、相同批次或总时长接近代替上述证明。粗图匹配只证明声明粒度下的结构，不能代替数值计算和性能模型验证。
