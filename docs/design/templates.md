# 结构采集、分层模板与有限变换

本文件定义从原生执行取得可展开结构的合同。结构采集回答“做了什么、依赖什么、怎样参数化”；性能样本回答相同工作的耗时。结构来源的时间戳不直接成为成本标签。

## 代表性来源与有界建库

先根据原生机制声明支持域、参数关系和有限分支，再确定最小证据。用户提供配置集和请求集，系统选择代表来源；不能先逐条运行目标请求，再把缺少的实例补成模板库。

配置分组由适配器完成。对允许请求池缩容和 Prefill 预算变化的 SGLang 路径，同部署组优先选择最大请求池，再选择同池最大 Prefill 预算，最后按输入顺序。依据是变换的方向性，不是性能评分。增加 workload 不增加结构组；分组成功不证明机制覆盖。

代表采集先消费已有兼容资产，仅实际缺来源时在授权预算内运行。一个原生进程可执行多组短请求，实际 batch、分支和清理须由观测确认。预算到限、观测失败和完成覆盖分别报告。

SGLang 的短请求配方用实际页大小 P、代表池容量 N 表达，不从目标请求抄长度：

| 组 | Prompt / 输出数 | 主要触发目的 |
| --- | --- | --- |
| 1 | P−2、P−1 / 1、1 | 双成员 Prefill、立即完成和直接释放 |
| 2 | P−1、P / 4、2 | 跨页、部分完成、过滤及单成员 Decode |
| 3 | P−2、P−1 / 2、2 | 双成员同时完成和拼接释放 |
| 4 | N+1 个 P−1；前 N−1 个输出 5，第 N 个输出 3，排队者输出 2 | 满池、排队、空位准入及合批 |

该配方的可执行域为 2≤N≤32、P≥4、Prefill 预算至少 NP，并有 4NP token 容量。上限来自已解释的原生分支与有界开销；这是配方条件，不是统一目标拒绝阈值。容量 1 或更大池仍可按已有资产与规则判断预测资格。

每组真正完成并经全部 rank 的清理确认后才提交下一组；末组保留必要清理事实再结束采集。目标仿真依然在最后 Published 结束，不计尾部轮询。配方不保证覆盖周期性输出、内存压力或全部准入分支，不能靠更换请求无限重试。

新增观测须明确缺失机制、已有事实、最短触发输入、预期字段、累计运行/后处理/存储额度和结束条件。只有新增事实有实际覆盖收益时才采集；成本缺口不重采结构，规则缺陷先修规则。

## Block、wrapper 与子图的一套合同

C++ 的公共 Block 定义拥有步骤、输入、端口和状态含义。框架绑定声明原生位置、参数来源及端口映射，Python 的通用 wrapper 消费绑定并记录身份。公共提取器通过同一身份取得对应工作，不再从函数名猜测阶段。

| 记录 | 至少表达 |
| --- | --- |
| 语义范围 | 调用身份、父子关系、步骤/区域、phase、rank、参数来源 |
| 工作关联 | 线程、队列、设备任务、stream、物理节点及必要因果 |
| 端口与效果 | 提交、设备完成、发布、状态读写及生效条件 |

wrapper 的元数据读取和记录工作属于观察开销，不能形成业务子图或被拟合为 CPU 服务。语义范围可以跨线程和异步执行；时间包络重叠不等于所有权，时间邻近不构成依赖。

SGLang 绑定围绕原生选择、准备、run_batch 和结果处理解释五类动作；模型区域绑定依据实际模块层次。框架解释业务端口，runtime 关联物理任务，公共生产只消费两者提供的合同。实现位置以 [serving 绑定](../../src/markov/src/adapters/frameworks/sglang/bindings.cpp) 和 [模型区域绑定](../../src/markov/src/adapters/frameworks/sglang/models/qwen3_regions.cpp) 为准，不复制一份函数映射表到核心。

## 来源图与依赖

来源图保留 CPU、设备计算、传输、通信和逻辑标记。关联依据包括实际调用、队列、event、task/context、stream 及 rank 身份；跨时钟时间须先建立关联，不能直接混合坐标。

必要依赖包括提交到设备、同资源先后、数据可用、等待/完成、跨 rank 通信及对外发布。可以压缩可证明冗余的传递关系，但不能按观察时间排序给独立 stream 添加因果。

来源覆盖不足保留缺口。来源无环、节点有归属、目标连接闭合是不同性质的判断；不能用其中一个替代全部原生依赖已覆盖。

只切出统一流程及必要交互。流程外节点可用边界关系投影，但不能删掉影响范围内工作的因果。源事实保持原样，目标映射、索引和变换是派生结果。

## 分层与归一化

四种对象必须分开：

| 对象 | 保存内容 | 增长原因 |
| --- | --- | --- |
| 原生观测 | 某次实际调用、节点、参数和来源身份 | 新采集和调用次数 |
| 共享结构定义 | 区域自身工作、规范拓扑、规则、接口和资源角色 | 真正不同的结构或实现条件 |
| 调用/组合绑定 | 层位置、动态值、资源别名、子区域顺序及来源映射 | 调用位置和参数差异 |
| 目标执行实例 | 新身份、目标工作、依赖及状态效果 | 请求与动态调度 |

定义只拥有自身工作，具体子定义组合放入区域树和绑定。否则同一父区域会因为子调用数量、顺序或末层身份不同而重复保存整张图。

归一化把调用 ID、层号、绝对时间、具体线程/stream 号和动态 shape 值移出结构身份；保留相对 rank、必要资源别名、固定模型属性、参数规则、端口、状态效果和规范拓扑。同名或同 shape 不足以合并，不同融合实现也不能仅为减少数量而合并。

重复模型层共享定义，仍实例化每层真实工作并重绑权重角色、KV 和外部消费者。模型树不强制 DAG 串行；跨区域融合节点保留完整工作和联合接口，不拆成虚构 kernel。

计数分别报告语义种类、共享结构、实现变体、规则、来源观测、绑定和目标实例，不相加为含混的“模板总数”。同实现域的新 request 应主要增加实例，若持续增加定义，先核对参数化或切口是否失当。

## 有限变换的合同

每条规则必须给出适用条件、参数来源及单位、实际节点/边变化、端口与资源映射、状态效果和拒绝原因。支持判断与实际变换共用同一依据，不另建一套案例黑名单。

| 工作 | 可参数化的内容 | 必须保留的条件 |
| --- | --- | --- |
| 模型计算与 attention | batch/token/context、模型固定维度、KV 布局 | 实现分支、dtype/layout、张量轴及真正的数据依赖 |
| 请求准入、过滤和合并 | 请求循环、输入/保留槽位、左右成员及共享工作 | 完整过滤序列、真实停止原因和成员顺序 |
| KV 申请/释放 | 实际页、请求成员、页内追加或跨页 | 目标 allocator 状态、分支和生效端口 |
| 请求池和派生视图 | 槽位、容量、行列布局 | 已有缩容/重绑定资格，不默认扩容 |
| 输出与发布 | 输出人数、结束成员、物化和必要搬运 | 完成/继续分支、真实发布端口 |
| 通信与传输 | 有依据的分区、数据量和物理工作 | rank、拓扑、算法、同步及执行方式 |
| Workspace | 需求量、保留容量和使用/释放关系 | 目标资源前沿与合法 allocator 分支 |

改模块参数而不改受影响的物理节点、工作量和依赖，不算完成变换。CPU 循环量首先作为工作特征或区域重复量；普通包装函数变化不新增语义类。真正改变外部状态、提交关系或实现适用性的分支才增加有限变体。

请求过滤保存输入人数及有序保留索引，全部保留、全部移除也属于真实条件。合并保存左右成员；不能由最终 batch 人数反推发生过什么。无选中批次的真实 Schedule 可以独立执行，不能合成全零批次的成本需求。

模型、TP、backend、dtype 或控制机制变化须重新判断实现资格，不能保证仅改 shape 或插入通信就覆盖。没有证据的变化返回合同或支持缺口，不选“最接近”的来源。

## 目标选择、组合与连接

1. 先判断来源身份、模型/部署、初始化、控制和容量条件。静态可用不表示全部目标工作已覆盖。
2. 每个目标 batch 联合选择覆盖各步骤及 rank 的来源批次，再按明确合同选择局部供体。禁止各阶段独立凑图后才猜测它们是否相容。
3. 对候选使用隔离的资源前沿，验证参数、分支、端口、依赖及状态，全部成立才原子提交。被拒候选不能改变真实目标状态。
4. 插入实例获得新的节点和边界身份；供体只提供工作与证据，不带入请求状态、初始容量或源绝对时间。
5. 按实际依赖连接跨模板、stream 和 rank，保留必要完成汇合。不能为替换方便添加设备服务、全局同步或错误串行边。

来源内编号必须由 manifest 限定。跨来源资源匹配须有公共角色及别名资格；原生线程号不能跨来源直接相等。成本查询使用目标工作，给定耗时单独按实际来源匹配。

固定资产的结构核对至少覆盖合法参数变化、成员变化、错峰到达、完成时间反馈，以及已承诺的页/容量转折。检查工作量、形状、关键依赖、资源和状态；总节点数或总时间相同不足以证明正确。验证中改变规则后，该输入成为开发证据。

## 编译与资产生命周期

原生捕获先规范化为有明确来源的事实。C++ `extract` 在同一进程中完成来源提取、绑定和模板生产，类型化图、调用及切口直接交接；不经 JSON 中转再解析。

正式资产为 manifest 引用的 `compiled_templates.cbor`，保存共享定义、参数规则、调用绑定、端口、资源、来源和真实缺口。预测只加载编译资产，不重新解释原始 trace，也不回调框架模板生产器。

规则表由资产拥有，使用点只读引用；序列化使用所属表的局部索引，不写内存地址。仅供生产的临时索引和无消费者描述不进入资产。`source_graph.json` 仅在显式诊断时输出，不是第二条正式生产入口。

构造规则改变后，用保留事实显式重提取，并让正式任务引用新资产；事实不足才重新采集。旧格式不兼容、缺字段不默认补齐、不新增内部版本协商或指纹系统。

原生导出在规范事实和资产成功交接后可以释放；诊断模式按需保留。manifest 中的来源定位符在原始文件释放后仍用于追溯，不能宣称可以重放原始导出。保留量、导出量、临时峰值和后处理用时分别计量。
