# 三类既有负载的全量离线搜索

开始日期：2026-11-10。

目标：复用 ShareGPT 512、BurstGPT 长度回放 256、程序生成 1,200 条请求的既有 base，按现行资源空间与报价完成全量预测，解释资源与策略的取舍，并报告实际搜索开销。

## 范围

- 请求内容、顺序、准备边界及输出设置保持原实验不变：前两组输出上限 16 tokens，程序生成固定 8 tokens，各另有 8 条准备请求。
- 使用当前 8 个资源套餐与全部 162 种策略，每组 1,296 点，三组共 3,888 点；按三级预留容量及四向带宽七项计价。
- 采用现行共享独立模型和资源实现，整轮固定选择；报价、套餐及参考带宽从实际声明读取，不按收益改值。
- 只运行 CPU 预测，不新增 base、校准、正常实测或设备任务；缺成本、不支持与不可部署保留原因。
- 与另一个长文档窗口独立输出，不修改其输入、状态、任务或结果。本轮不改 PPT。
- 采集 base 提供来源依据；费用上限使用当前空间中标记为 baseline 的配置，二者可以不同。baseline 也必须完成预测与计费，才能给出同预算排名。

## 执行步骤

### 一、检查来源与代表配置

执行前固定代码基线、必要差异、三份 manifest、请求、共享模型及实际展开的套餐和报价，使用对应构建。原始来源仅从各组所选 base 读取，预测容器不挂载正常真值。复用已有预测、枚举和资源计费入口，不建立第二套执行器或复制缓存规则。

旧 base 的复用需逐组说明以下依据：

| 核对项 | 通过条件与处理方式 |
| --- | --- |
| 部署、输入与初始条件 | 模型、runtime、精度、TP 与成本部署匹配；实际 tokens、顺序、输出、正式边界、准备后排空及内核初始状态按原实验记录核对，未记录的系统缓存等状态列为限制。变化的目标设置由受支持规则解释；存在未解释的不一致时不能直接复用。 |
| 来源与目标工作 | 语义记录足够形成当前来源；新页几何、容量淘汰、有限 SSD、四向配额及共同服务约束由现行规则在同一时钟生成工作与依赖。缺少结构依据的路径列明不支持，不从 target 真值补结构。 |
| 成本归属与适用域 | 不变工作迁移源成本；变化的计算、搬运和控制使用固定独立模型，检查实际查询的页数、分段数、context/query 等范围及外推标记。配额等待不通过缩放整段闭合响应或重复叠加源等待实现。沿用的控制残余、首次使用等近似单列。 |
| 资源与计价 | 按原生页对齐、输出预留及准入余量检查可部署性；按实际预留、每 rank/整组单位和七项单价核算。共同链路按份额计价，固定占用保持，不能按当前缓存使用量折价。 |

用输入 tokens 和已有前缀统计核对不同正文/前缀的 KV 工作集、复用上限及回访距离，说明各套餐下可能出现的容量压力。BurstGPT 保持长度回放和低复用对照定位；没有缓存机会或配置差异也保留原负载。统计表示复用潜力，不当作实际命中率，不因预测收益更换输入。

每组先从完整空间中确定不超过 24 个代表配置，包含 baseline，覆盖八套餐、三种页宽、三种写策略、等待完成、best-effort 和四档 timeout，并纳入备份/回载带宽及容量差异。选点只依据参数和输入压力，名单在预测前固定，不按收益或正常真值选择。不同负载没有触发的淘汰、失败回载或取消分支注明未触发，不另造请求凑覆盖。

代表点检查成本缺口、近似、请求工作及资源边界，同时测量来源准备、逐目标执行、完整批次墙钟、内存和输出。它们属于本轮全量集合，后续直接复用；参数值覆盖不证明所有组合和时间分支已覆盖。发现真实结构或成本缺口时先明确影响范围，不盲目派发同类批次、不自动补采；同一缺口无新事实不反复重试。输入与代表点具备依据、未决缺口已处理且开销可容纳全量后，进入第二步。

### 二、完整枚举与恢复

沿正式预测入口按每批最多 48 点、最多两个各 8 GiB 容器执行。各候选独立维护缓存状态；每次调用内共用来源和模型，记录跨批重新准备来源的实际成本。代表点和完成批次不重复计入配置数，全部实际耗时计入累计用量。

完成批次及其正式报告可恢复；重启前先核对登记进程、容器句柄和报告。任务仍活跃时等待原句柄，不能仅因日志不更新或观察超时重复启动。终止状态确认后才重试失败批次，保留原失败和耗用；OOM 时先检查容器与外层解析的占用，降低并发或缩小批次后再恢复，不删除候选。只回收本任务进程树与容器，不碰其他窗口资源。

后续组合新出现的成本缺口、不支持或执行失败分别登记。能够证明受同一缺口影响而未运行的点明确标为未运行，不算成成功或零耗时；已证明不可部署的点记录原因并计入声明清单。代码、模型或配置需要修正时另记新的运行依据，复查并重新运行受影响结果，不能把不同依据的批次混成同一完整面板。

### 三、解释结果与维护交付

按当前 baseline 的每小时费用上限，在部署合法、预测成功的同一集合中选完整正式 HTTP 最小/最大的配置；并列时优先较低费用，再按名字稳定排序，保留全部并列项。覆盖未闭合时端点只作暂定结果。相同预算上限不表示两个端点费用相同。

交付以下结果，均区分正式 HTTP、准备和窗口外后台排空：

- 每组完整候选清单、分类数量、时间—费用分布及 Pareto；每个候选保留配置、完整 HTTP、七项费用、模型域/近似和缺口。
- baseline、最好、最差的预测耗时、绝对费用、费用变化及耗时差；复用现有逐请求报告，列出实际生成的 Prefill/重算 tokens、缓存复用、备份/回载、文件读写和等待证据，解释资源与策略为何改变结果。
- 工作量明确区分提交、完成与接受，逻辑页/字节与物理流量分开；报告未提供的方向或等待分项写未观测，不填零、不新增探针。默认不导出完整细图，现有报告不足的组件归因单列限制。
- 基于所有实际批次统计墙钟、来源准备与仿真耗时、容器最大 RSS、外围进程树内存及输出保留量；采样观测最大值与资源硬上限分别报告，没有连续峰值证据时不声称测得真实峰值。预测排名与实测精度分开，不用模型关键路径解释冒充真实组件归因。

完成相关代码/入口与配置联查、文档一致性和数据来源/保留范围检查后，按本窗口实际改动分层提交推送。纯文档修订不构建或运行实验；执行阶段只做改动所需的构建与公开入口检查，不重跑无关历史矩阵。

## 资源预算与停止条件

| 项目 | 初始额度与执行方式 |
| --- | --- |
| 累计执行墙钟 | 8 小时，包含必要构建、代表点、完整扫描、失败重试及汇总；代表检查先控制在 45 分钟内，整体预留 30 分钟整理。并行区间按实际墙钟统计，中断等待另报，恢复不清零已消耗时间。 |
| 内存 | 两个预测容器各最多 8 GiB，外围编排与后处理合计预算 4 GiB；执行前落实外层限制与回收方式，不能只约束容器。分别记录容器与宿主进程树占用，避免重复求和。启动前核对其他任务，保留至少 20% 主机可用余量；压力增加时先停止派发、降为单并发或减小批次。 |
| 新增输出 | 保留量上限 16 GiB、目录瞬时占用上限 24 GiB；包含本轮必要构建、请求、失败和结果。已有 base 与共享资产只读引用并另报，不复制大数据；只解析当前批次，跨批保存候选摘要及必要报告。 |

代表点完成后，按各组实际准备开销、目标耗时及报告大小估算剩余运行时间和空间，三组分别估计，不从小负载的 54 秒或原 96 点数量直接外推。每批结束更新实际用量与剩余估计。预计超出额度时先记录原因和所需调整，不靠抽样、删难点、删必要证据或放开模型域维持旧估计；未调整额度前不派发可能超限的批次，保存可恢复状态并报告未完成。单个活跃批次触及任务资源边界时，仅终止和回收本任务对应进程树，保留诊断，不无限重试。

## 完成判据与限制

- 三组均列齐 1,296 个唯一配置，合计 3,888 点；成功、已证明不可部署、缺成本、不支持、失败、超时和未运行分别计数。清单列齐只表示声明完整；全量预测完成要求所有合法可行点成功，无未解决缺口、不支持、失败、超时或未运行。
- 来源依据、成本适用域和计价检查具有逐组证据，完整 HTTP 保留 Prefill、Decode、HiCache I/O/control、gap 及未归属成本；任一组未满足条件，就报告该组覆盖不完整和端点暂定，不用另外两组替代。
- 结果写入 `data/workload_full_scan_current_20261111/`，逐批可恢复；不覆盖旧 96 点结果，也不删除历史资产。
- 原实验的 3×96 为固定种子随机抽样。本轮空间、报价和模型均有变化，旧结果只作历史背景，不能直接用于量化同条件搜索方法收益。
- 新推荐只报告预测收益；接近的预测值不认证真实快慢顺序，增加候选还可能选到误差更乐观的点。历史正常结果仅在输入、配置、资源、部署与初始条件一致时另行评分，重复和慢样本保留；未取得对应实测时精度留空，不推广旧六个条件的误差。
- 本轮只覆盖限长串行请求、声明套餐和现行价格假设，不能据此宣称完整原始输出、高并发、长期稳态、全空间精度、实际账单节省或真实全局最优。已有 base 或固定模型不足时保留具体缺口，不扩大设备运行。
