## 联合执行与交付

本窗口作为一个联合阶段，从已交付的 56eaf5f 开始；准备请求、六次测量和结果汇总一并审查交付，不按每个点拆阶段或提交。

1. 从实际请求和排名保存六点确认清单及正式 measure 请求，复用现有 confirm.py / DeviceTask。重复数的初始值和最大值都为 1，额外条件数为 0。清单在读取本轮正常真值前保存。
2. 按 ShareGPT 最好/最差、BurstGPT 最好/最差、程序生成最好/最差串行执行。约十分钟核对一次；接近终点缩短至二至五分钟，不因观察超时重启任务。
3. 六点完成后核对配置、输入、顺序、生成数、完成原因、双 rank 配额、采集关闭、排空及完整正式 HTTP。计算每组实际跨度、两点 APE/WAPE 和排序，保留负收益、反序或超过 10% 的误差，不修正模型。
4. 将六点正常确认并入现有全量搜索报告，保持原始预测及历史证据；进行相关代码/文档/数据检查、少量分层提交推送，汇总主工作流后撤下本窗口。

完成要求是六份匹配配置的完整正常观察、可复核的工作量/边界、实际误差与跨度报告，以及维护交付。实际收益大小或误差达标不是本次采集任务的完成门槛。

预计正式 HTTP 合计约 140 分钟，加启动、准备和清理约三小时。设备严格串行；六点累计上限为 6 次启动、21,600 秒、3,984 请求、4,481,370 输入和 43,770 输出 tokens，按各点真实请求精确分配。失败、等待和处理都计入，不重置用量、不自动追加重复。必要恢复保留原状态；不能用部分请求或 profiler 时间代替完整正常观察。

每点最多保留 24 GiB 临时目录，所选 SSD 配额均为整组 16 GiB；正常记录最终新增保留目标 2 GiB。启动前核对内存与磁盘，保留宿主20%内存余量。若设备被占用，等待并记账，不干扰他人；未完成或数据不匹配时明确保持未完成。
