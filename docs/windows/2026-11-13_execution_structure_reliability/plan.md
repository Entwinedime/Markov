# 执行结构工程收口与泛化边界验证计划

开始日期：2026-11-13。按当前系统及历史经验重新规划：2026-11-15。

目标：把已有执行结构原型收口为职责清楚、行为有依据、适配范围可维护的完整流程；先通过系统开发和多场景回归解决已知机制问题，再独立检验明确的泛化主张。性能层仍后置。

计划本身不构成执行授权；goal恢复或阶段得到明确授权后，按完整维护阶段批量推进，不要求用户逐实验指挥。本文维护任务与退出条件；当前状态归status.md，历史行动和失败归log.md，[场景与证明责任](verification_matrix.md)维护覆盖明细。

## 1. 从实际系统出发

当前产品闭环是：用户提交模型、配置集合和请求集合 → 自动规划来源 → 原生观察并解释为粗图 → 层次模板和有限变换 → 原生控制提交动作 → 核心展开、连接并推进资源/时间 → 完成反馈和请求输出。独立真实目标提供对照和显式时间条件，不提供图体或控制答案。

当前已有完整流程和可复用真实事实，但最近六个Qwen8目标只证明有限范围。历史还存在来源不合格、模板歧义、原生启动/首用、SDK/测量交接和缺序报告；已有代码、过去成功和当前已获资格分别判断，不能从某个目标通过推定整个机制已完成。

这次重新规划采用以下依据：

- 层次丢失和父参数污染属于共同合同问题，首先应从代码的所有权、调用关系和消费者发现，不能依赖不断新增目标暴露。
- 场景配置覆盖不等于行为覆盖。请求输出1和输出2会走不同生命周期；缓存开关不证明命中/淘汰，容量数值不证明压力，8卡不证明所有角色和通信关系完整。
- 新模型/配置不必复用旧模板；关键是何时可以直接变换，何时自动取得新来源，何时确实需要适配。重新采集与修改代码分别统计。
- 原生事实、粗图和评价工具均需可信；自还原、给定动作展开、完整控制闭环和性能精度是不同证据，不能互相代替。
- 一次完整真实案例可以长期复用。反复重采和全量重跑不能替代根因分析，也不能用旧真值去验证另一个请求序列。

原72项清单、42/30分配和原来源组数量不再约束新计划。它们只保留为历史输入/事实索引，可经资格核对成为开发资产；不原样再跑，不为保留旧分母而保留无新增证明价值的组合。新场景从行为、实现差异和必要耦合重新选取。

## 2. 要交付的能力与维护边界

| 能力主张 | 要交付什么 | 不能混淆的边界 |
| --- | --- | --- |
| 固定库内变换 | 在明确实现域和guard/规则覆盖内，改变请求、成员、到达、容量和状态并动态展开 | 同实现域不保证一份有限来源包含全部分支；不能由shape公式发明未观察的算法结构 |
| 无代码改动的新来源流程 | 模型、dtype、拓扑、页布局或实现发生变化时，使用已有程序规划/采集/建库并预测 | 正常取得新来源不是人工适配，也不是旧库跨域变换 |
| 有边界的适配扩展 | framework/model/runtime差异在对应adapter解释，输出一致共同合同 | 优先从模块、配置、调用参数及注册布局推导；不为每型号、长度或实验维护一套实现 |
| 共同核心能力 | 正式合同能表达层次调用、条件/shape、依赖、角色、资源及完成反馈 | 共同表示不足才改核心；不把框架私有状态机或实验规则搬进去 |
| 完整执行结构 | 从输入到请求输出的内容、必要因果、通信及状态/资源关系可对照 | 粗图未保留的内部细节、数值计算、自然路由及性能精度不自动取得资格 |

用户保持现有模型/配置/request及显式路由合同，不指定base，不填写内部shape/guard，不手工拼图或维护KV、worker和批次状态。正式流程取得事实；新增适配由项目维护，不把困难转给用户。

本轮仍为单机SGLang/Ascend，最多8张物理卡，包含Dense/条件MoE、原生合法TP/PP/EP、PD、chunk/mixed和一级prefix。保留dummy权重及现有显式expert/padding路由，不新增两套路由模式。其他backend、硬件、原生版本、量化、多机、轻量控制器、overlap/speculative、多级搬运、真实权重路由和性能模型不在本轮实现范围；相关变化的接入位置可以说明，不能因此宣称已支持。

需要支持的能力不能因实现困难静默移出范围。具体模型/配置确实原生不支持时取得依据并记录；未知启动失败不自动等于不支持，也不patch框架强行运行。元数据或EntryClass存在只说明有检查入口，不能证明运行资格。

## 3. 两阶段组织

### 第一阶段：机制开发、场景回归及工程收口

开发场景由56项明确的证明责任组织，覆盖流程、合同/模板、资源、实现族、并行及调度/持续运行。它们不是56次采集或56个完整目标：一个真实案例可承接多项责任，静态推导、正式入口反例和局部展开分别标明资格。每项责任均须落实到具体输入、预期行为和实际证据，不能用标签表示已经覆盖。

阶段启动时将该组责任映射为有限真实案例：已有事实优先，必要边界采用确定性输入，内部点和无冲突组合再有界抽样。先覆盖单机制及两侧边界，再覆盖有真实数据/状态/控制耦合的组合；不做全笛卡尔积，不把大量短小变体都变成独立Engine启动。

| 阶段 | 完整维护职责 | 下一阶段的前提 |
| --- | --- | --- |
| A0 基线与证据准备 | 当前能力/遗留问题、事实资格、验证可靠性、场景和额度 | 原生/观察/核心/工具问题有归属，现有资产及待交付改动明确 |
| A1 完整闭环与图合同 | 从原始事实到模板/动作/输出，贯通层次、参数、完成及粗化依据 | 当前主线的基本合同闭合，能定位真实的首处差异 |
| A2 状态驱动的变换 | 成员、长度、到达、容量及资源生命周期共同作用 | 固定库变换的适用范围和必要分支可解释 |
| A3 多实现族与自动来源 | 多模型/布局/dtype，原生资格、有限来源与轻量适配 | 现有适配范围内的新域无需用户维护内部结构 |
| A4 多rank协作 | TP/EP角色、PP微批、PD传输与资源反馈，再组合 | rank复用、跨图/跨池及完成责任保持 |
| A5 调度与持续交互 | chunk、mixed、prefix、压力和长运行 | 实际机制发生且组合不破坏资源/因果不变量 |
| A6 工程收口与冻结 | 全链审查、精简、最终开发回归、独立场景与预算固定 | 已知关键缺陷闭合，评价及正式流程可复核 |

### 第二阶段：独立验证及结论交付

独立首批48个完整目标责任，分成四组；这是预定调查规模，不是泛化证明。来源、资格探针、补证和修正后复核另计费用。固定库、自动新来源、模型留出及组合各自承担不同主张，不能合并成一个通过率。

| 阶段 | 完整目标数 | 独立检验的主张 |
| --- | ---: | --- |
| B1 同域固定库 | 16 | 新请求/状态/参数组合能否仅靠已发布库及规则展开 |
| B2 已声明适配范围的新实现域 | 12 | 冻结代码下改变布局、dtype或拓扑，正常重新采集能否完成自动流程 |
| B3 本轮未用于开发的模型 | 8 | 两个留出模型各4种有限配置，无代码修改的适配范围究竟到哪里 |
| B4 耦合及持续运行 | 12 | 已开发机制在新组合、到达和长期状态变化下是否仍正确 |
| B5 问题处置与交付 | 不另设一套矩阵 | 解释全部结果，修正支持范围内缺陷并作受影响复核，交付能力和维护边界 |

具体48项配置、请求模式和来源角色在A6内按场景表约束确定，输入在冻结后生成并固定；不能在看到结果后挑容易项。保留所有终态、未触发及未执行原因。历史或开发输入重放只能取得重放资格，不因新目录、新采集或新seed就成为新场景泛化。

## 4. 第一阶段的实现与回归路线

### A0：将现状变成可执行的证据基线

先静态追踪当前正式入口和完整数据流：workflow的来源/预测装配，共同adapter的调用ABI，collection的framework/runtime解释，C++投影/模板/选择/实例化、原生控制和资源/执行，以及example的独立评价。实际目录和状态所有者形成一张可读流程图，不另造规则管理平台。

复核当前层级/参数修正的未提交内容及最近代码/镜像身份，处理自有待交付改动，不混入用户reference等独立工作。近期六例开发证据作为候选基线，Qwen30MoE旧派生及历史案例逐份核实原始事实是否足够；不自动选旧库、旧程序或旧镜像。

把历史来源歧义、参数越层、原生首用、SDK身份/时钟和缺序报告按共同机制归类，分清确认缺陷、解释未完成、工具问题和未覆盖。已知问题必须交给相应A阶段，不能因为某个配置预留给独立验证而推迟分析。

审查评价是否区分原生资格、来源图、模板、时间、预测和对照；错误须能定位到调用身份和责任边界。先检查现有正式反例与已保留失败是否仍能被识别，再决定需要补哪些验证材料。不得调用模板生成器制造真值，也不以修改评价掩盖结构差异。

核对已采事实的模型/配置、请求/路由、预热/初态、观察/原生身份、各rank完整性和SDK引用；只读登记路径。源和目标角色提前声明，不把失败目标偷偷转换成它自己的来源再宣布变换成功。已有数据不足时列出缺少的决定性事实，不猜默认值。

交付：能力/责任图、遗留问题及处理阶段、可复用事实清单、首批开发案例、来源作业和累计剩余额度。均放在已有结果/任务位置，状态保留恢复摘要；不新增多层账本。A0完成不等于其他能力已经验证。

### A1：先把完整闭环及基础合同做正确

保留现有Qwen8来源和六个真实目标，核对并使用当前实现贯通“事实→解释→粗图→切图/简化→依赖归属→归一化→调用绑定→匹配→展开/反馈→输出”。允许集中重写不合适的整块逻辑；不能只修报错函数。

重点清查参数实际输入/派生量/外层上下文、父子/兄弟端口、固定值/guard/shape、别名/版本及真实写入者。调用片段继承所属调用，独立子调用声明自己的合同；严格检查不放宽，未知参数不填默认值，不按名字做过滤补丁。父层组合子接口，子内部变化不应污染父定义。

观察工作按CPU服务、提交、设备计算/搬运/通信、等待及纯边界解释，说明执行/返回/可见/释放和费用责任；粗化保留真实工作和外部作用的必要因果。无法逐任务配对不构成忽略依据，也不要求回到所有底层事件逐一比对。

多stream的逻辑职责由框架声明，runtime以原始事件及等待代次绑定实际资源，核心只消费公共资源和端口。来源检查直接核对保留测量及原始有效工作覆盖；语义裁剪不要求端点等于观察器围栏，但必须在原始包络内，不用解释结果与投影彼此一致代替独立来源依据。

真实时间旁路只提供已核对身份的工作/完成/输入条件，不能提供组批、分配、查询答案或目标图体。保留原始测量、时钟域、单位及共同校准；测量范围与真正缺测分开，所选可行轨迹不冒称唯一真实时间。关键时间已采到却在解释中丢失，修交接链而非补采。

原始SDK的任务编号可能复用，运行内按真实发生实例、API关联及stream顺序核对，保留数量和原始测量；该局部坐标不用于跨运行配对。历史事实若缺少现行合同要求的原始信息，先由当时观察代码和消费者判断是否能无损离线转换；不能恢复的事实不靠默认值、字段改名或兼容分支取得资格。必要刷新须预先固定来源/目标及有限额度，仍走正式来源规划和采集，不为模板匹配失败逐次补分支。

用确定性的一请求/多请求、首token结束/一次及多轮Decode、批次部分退出和全部退出检查整个闭环。一个合法内部空集合不等于合法空workload或零长度请求；无效输入用正式边界拒绝，不启动原生验证非法请求。

退出条件：F01–F18的责任获得对应证据；主线完整案例、来源独立核对和必要合同反例符合预期。自还原和局部展开只取得其局部资格，不能代替完整控制/资源反馈。

### A2：统一处理状态、shape和结构变化

围绕请求进出、到达、资源预约/归还/重用及容量变化推导结构：哪些只改变shape/传输量，哪些改变重复次数，哪些选择已有不同实现，哪些说明来源缺少必要结构。根据真实原生分支建立有限规则，不逐长度、batch或容量添分支。

阶段开始先按资源/状态分支建立有限开发案例表，标明可复用的真实输入与确实缺少的决定性事实；参数和模板合同基线沿用已审定的正式入口。先集中完成状态、变换及交接机制，再按组运行固定案例，不从单例报错逐次扩大采集。

开发输入覆盖最小合法值、页边界两侧、非均匀成员、准入边界、初始/持续/空闲后状态，以及先逻辑释放再物理可复用。核心唯一维护资源与在途活动，原生拥有逻辑控制；adapter只能交接必要视图，不能再维护一套分配器或控制器。

显式解释Cat/列表扩展、小池与大池、分组/直接释放、批次裁剪/合并的来源和适用范围。若是真实算法切换，明确其guard和来源策略；若是表示或绑定错误，修共同机制。不能把每次模板失败都当作再补一份大容量模板的理由。

按实际实现划分取证：普通Serving和PD使用相同资源合同，但延迟归还/排序仅PD启用。A2核对共同排序算法、失效与在途保护，并取得普通Serving状态变换依据；PD排序、跨worker异步归还/再用的完整动态见证与协议在A4一起闭合，不把普通缓存压力或静态相同误报为PD资格。A4交付前这部分责任仍未完成，不能移给性能层。

不同形状/容量的有限边界检查可用已有正式展开入口；完整对照仍需对应输入的真实目标。不得把一个请求序列的真值通过改shape当成另一个目标真值。机制责任优先合并到已有真实案例，只有无法回答的变化才新跑原生。

退出条件：F19–F28及受影响F09–F18有实际依据，已声明同域变换没有未解释差异。普通支持域必要的在途归还/再用未触发时，取得有限见证或实际不可达/封闭证明；PD协议专属动态责任按上述边界在A4关闭，不能写备注后交给性能层。

### A3：围绕实现族完善自动来源与最小适配

开发模型选Qwen3-8B、Qwen3-32B、Qwen3-30B-A3B、Mistral-7B-v0.3及Mixtral-8x7B-v0.1，分别检查规模变化、Dense/MoE和不同模块/专家几何。它们是开发材料，历史失败也可用于分析；不再包装成全新模型留出。

先用元数据、已初始化模块和原生接口区分可推导事实与真正差异。按实际ModuleList、attention、head、专家与通信接口检查现有隐含假设；模型名称不能代替结构依据，不能仅靠第一个局部层代表全模型。可自动取得的信息不要求用户声明，专属解释留在相应adapter。

从单stage、最小合法拓扑核实原生资格，再检查有限来源规划、采集、图及建库，最后比较不同请求的完整预测。模型/布局/dtype等新实现域正常重新取得来源，不强求从旧图变换。已有原生失败先定位；原生不支持有依据，适配器失败修适配，不修改上游。

来源策略按真实实现域聚合，再以配置、workload及路由/padding条件预先选择有限互补作业；同域允许多个来源，但每次预测选择一份完整worker来源，局部实现只按既有合同导入，不跨采集拼接未证明的物理流。容量等参数变化的必要输入机会可由互补配置提供，不要求一个配置同时制造互斥机会；Prefill与Decode的路由机会分开，专家数量从模型元数据取得并随计划发布，纯预测不重新访问模型目录。机会标签用于有限取证和来源选择，不是原生分支证明或额外支持门槛，实际支持仍由模板合同、guard及完整回归确定。

来源策略要解释必要分支、代表角色和来源数量的由来，并在目标对照前固定。源内已有分支却选不到，应查合同；确少结构时优先修统一切口/生成或有限来源策略。禁止以目标trace逐次指导自动补采直到成功，来源增长须对应新增结构而非长度组合。

完整模型计算与控制器批次操作分别核对：普通Serving和PD均需已有合同可表达的merge/subset时，由有限局部配方提供并在发布前确认观察，不能因模型几何齐全就省略。缓存输入机会复用调用ABI的guard，保留空/非空整页和索引写入差异；实际中间chunk及状态分支仍需原生证据，机会标签不代替模板合同。

相同请求shape但expert路由不同，也可能使某角色的接收量在零/非零之间切换。来源选择与角色复用须结合已给定路由及padding条件检查这种结构机会，不能只覆盖batch大小；零分支不能由正形状模板缩放虚构，真实泛化仍由有限来源、guard及目标验证确定。

同一实现族至少有短边界与非均匀请求两类完整闭环见证。含PP/PD的新域在A4完成，A3不提前冒称支持复杂拓扑。退出条件：F29–F36及开发族单stage资格明确，原生支持域内的适配/来源缺陷闭合；人工维护范围可说明，不能把修源码统计为自动成功。

### A4：由独立角色到协作拓扑

按单worker→TP/EP组内角色→PP微批→PD预约/传输/接入/释放→必要组合推进，保留完整闭环。先解释已有实现的职责，再扩大拓扑；新域正常取得来源，相同事实不重复采集。

检查等价rank观察前复用的依据、角色非等价条件、PP局部层和全局层、expert分片及通信参与者。共享模板定义不共享运行状态，观察代表不减少必需协议worker。封闭局部实现复用须区分算法接口与调用位置，不能把来源rank常量写成算法条件；替换保留接收方的实际rank、通信、别名与资源绑定，不放宽原生角色及布局资格。目标对照覆盖所有rank；同等地位rank复用是被检验能力，不以采完去重冒称减少采集。

模型通信、CPU协议、张量依赖、stream等待、PD载荷/metadata和跨池资源前提分别交接。源/目的池有独立账本；CPU返回、入队、设备完成、内容可见及可释放不同，不按时间先后或来源节点编号造因果。同时承接F26/F27的PD延迟排序和跨worker在途归还/再用动态责任，静态算法相同或普通Serving通过不能代替实际触发与全链路对照。

传输循环的算法结构、每次调用的池/字节绑定及原生预约产生的迭代顺序分别交接。适配器取得运行状态，同一个已观测骨架绑定目标peer；不能把来源子调用位置当作目标peer身份，也不能为每种排列增加实现、guard或采集。沿采集解释、调用绑定、控制交接、模板选择、实例化及独立对照一次理顺。结构开发可显式注入实测后台调用的绑定次序，但必须独立从原生调用核对、在结果中注明条件资格；不输入目标几何/图体，不宣称已自主预测网络到达次序。对照先按实际端点和工作语义辨认服务，继续检查各自输入、必要串行关系及组完成，不能通过排序、任选候选或合并读区间消除差异。

通信组成员、每次操作的必要peer、rendezvous就绪及本地完成分别表达。按原生协议及实际收发量推导数据交换前提，metadata的全组协作单独保留；不能把含本地准备、交换和整理的包装函数默认当作全组设备栅栏，也不能因某rank接收量为零就忽略其发送或metadata参与。来源从实际原生参数/handle取得依据，目标在adapter中从已有路由与批次推导并重绑定，核心继续执行公共通信合同；独立检查核对真实收发和时间，不能复用预测答案生成真值。必要切口由实际协议决定，不以新增逐rank、路由名称或时间容差分支解决。

拓扑变化检查TP1/2/4/8、合法EP1/2/4/8、PP1/2/3/4以及满足8卡上限的组合；优先覆盖不同角色和层分配，不做全部组合。原生合法的不均匀PP层划分、微批尾部、PD非对称方向及跨池容量差异作为明确边界。 PP不能只核对单个模型批次大小，还需从实际调用/协议恢复同时驻留的微批及返回关系；请求总数或microbatch上限不代替触发证据。较大输入原生停滞时先区分原生、观察和核心责任，保留失败及未完成范围，不通过减小目标请求数回避多微批交互。

原生资格与所需机制的完整证据分别闭合。来源/目标除原生完成，还须核对实际复制的全局模型层与K/V成分；地址真实、图忠实不代表原生载荷语义正确。不等分PP与PD组合若触发原生错误地址分支，保留具体输入和原始地址依据，不修改上游、补写缺失KV或放宽读取检查。先从原生代码和注册布局选定合法代表，再取得独立来源及完整目标对照；不以新拓扑改判旧输入。普通PP仍保留不等分层责任，TP/EP/PP另承担并行组合责任，不能把48层/PP3等分误作不等分见证，也不能因某个PD实现限制整体取消不等分责任。代表选择在目标模板比较前固定，相同普通/局部输入通过正式计划精确复用，不因某个目标缺模板逐次增补。相同模型/配置的成功来源与目标预热结果不同，须分析生命周期与原生事实，不直接按配置名拒绝。

退出条件：F37–F46具名角色/协议有证据，内容、内部/跨图依赖、全rank通信、实际页/字段绑定和完成反馈对应。声明需要的关键路径仍缺证据时继续本阶段，不以大量其他成功抵消。

### A5：让调度和长期状态同时经受开发回归

先分别核对chunk、mixed、prefix，再检查它们与PP/EP/PD及资源压力的实际耦合。chunk有中间/最后块；prefix有不命中/部分/完全命中、引用和淘汰；相同长度不同内容/路由不能虚构命中。

按原生控制→成员/范围声明→请求及缓存资源→模板实例化→独立观察的方向审阅。先核对ChunkCache与RadixCache的实际选择、PrefillAdder对运行Decode的预算扣除、mixed中的逐成员phase/范围、缓存锁/分裂/淘汰及PP全模型路由身份；共同机制已正确时不重写或叠加管理层。开发回归分为无缓存chunk边界、chunk/mixed/prefix与一种合法并行职责组合、持续请求三组；既有简单prefix和淘汰事实按实际资格复用，不因进入新阶段重采。

组合中明确构造同内容同路由、同内容但仅远端PP层路由不同的请求，并保留独立padding条件；缓存内容键必须包含全模型条件、排除padding。原生准入、分块和混批始终由原生代码决定，不为验证新增组批字段或替代控制器。256/1024请求使用已有普通实现域及有限来源，核对长期身份/页/槽/缓冲复用；不同证据各自承担责任，不把短例成功或最终请求数当作持续运行证明。全部新来源、真实目标及额度在采集前固定，源码审查先于该批运行；来源机会或预算不足时先回查机制，不按目标缺口追加探针。

辅助来源与主库的装配须按共同闭合合同交接；同一完整worker实现域的实际闭合叶动作可独立导入，不要求主库重复观察同一入口。调用层次、端口/资源、guard、通信与状态所有权仍分别核对，不能因名称相同共享整棵动作。

资源控制调用按真实ABI切分：公共淘汰检查只拥有缓存对象及标量需求，不继承外层批次的张量输入；容量查询和实际释放页各自保留工作及因果，纯CPU片段按同一严格合同归一化。此边界已改变原始测量身份，旧事实不能伪造新增时间；固定一次主来源和原256/1024两个目标重新取证，辅助数组事实在输入相同且局部资格保持时显式复用。不逐缺入口补来源，也不将旧失败改判成功。

本阶段同时消除大时间输入的重复交接：外围传递独立只读文件，核心读取一次并借用actor步骤；准备和执行共用期限，失败清理临时产物。该所有权问题影响本阶段持续运行，故从A6前移，不等完成昂贵回归后再改接口。

来源独立检查对单个显式host_only片段及合并后的CPU区域使用同一原始SDK归属判据，不能只核对解释后的CPU图体。开发审查若发现检查遗漏，先统一修正评价方法；原报告保留，以现有事实在独立目录重新审定受影响资格，不重采、不改变图体。当前补充审定限主/辅来源及256目标三项，1024沿既定步骤使用同一新检查；这不属于第二阶段的冻结独立结论。

大请求输入的轻量来源必须由正式策略取得，不能靠开发者额外编一个小workload掩盖采集规模问题。用同一输入机会判据删除冗余完整请求；缓存保留完整页及共享路径，mixed保留驻留窗口和竞争输入，不只保留Prefill/Decode标签。目标不裁剪，实际分支仍由原生观察取得；删减策略、有限来源及来源资格一起审阅，再进入本批真实对照。

真实批次、命中/淘汰、背压和资源复用须从事实确认。构造输入前从原生代码推导触发条件，再选择有界请求；开关没触发时不算覆盖，不能盲目加长或加量。支持范围内可达但缺乏见证的行为不能默认后置。

覆盖短请求快速退出、长短混合、准入压力、同刻/密集/稀疏/空闲后到达，以及256和1024短请求代表中的持续身份/池复用。持续请求上限按实际原生资源条件固定；长运行不是只检查最终完成数，也不要求还原所有后台细节。

初态为统一预热后的稳态，workspace热状态与逻辑KV/cache冷/共享初态分别说明。业务时钟和事件由核心推进，宿主快慢不能改变组批/释放；未纳入的HTTP/分词等边界不临时加进图。

退出条件：F47–F56和所需耦合实际触发，完整输出与通信、状态及资源关系闭合；稳定与长运行证据分开，不将真实时间旁路结果视为成本模型精度。

### A6：把开发结论变成可冻结的工程交付

从当前入口沿生产者/消费者/所有者关联审查全部自有业务、共同adapter和评价工具，集中整理重复/零碎/过大实现，删除过渡路径、无消费者字段/输出、兼容及冗余防御；必要时跨文件重组或整块重写。不得依赖deprecated或保留能误用的旧链路，不靠压行、删注释或迁出统计瘦身。

A5已处理的大输入所有权纳入全链审查，核对准备、执行、发布及失败清理的实际消费者；保留完整工作身份和证据，不通过删队列状态、放宽对应或压缩排版缩小输入。对测量边界改变的开发资产重新审定资格，未用最终合同执行的旧成功不自动升级为当前整合资格。

资产审定分开局部结构与整轮控制合同。A5新增淘汰切口后，旧事实仍可检查未改变的模型、形状、批次数组、通信及资源子图；当前编译器消费这些声明不等于当前控制器已完成同一整轮。旧目标缺少新子调用的实测边界时，不离线补造时间或保留旧控制路径。按实际ABI兼容范围完成局部开发回归，整轮资格只由最终合同的真实来源和完整目标取得。

A6启动时优先复用A5新Dense来源及256/1024目标；再审定现有Qwen30 MoE/TP1×PP3×EP1的chunk/mixed/prefix输入，以及Mistral FP16、page32、Prefill TP1×PP4→Decode TP2输入，作为最终ABI的两组完整交互代表。初步预计每组一个新主来源及一个真实目标；辅助数组观察只有在正式重规划后输入完全相同、局部声明及来源资格保持时才显式复用。所有代码修改、统一构建及公开规划完成后，固定具体作业数和累计预算再启动；若辅助事实不适用，先修订整批清单，不等目标缺口出现再补采。两组只承担其实际角色、机制和完整交互，不能据此将其他旧模型/EP/PD案例整体升级。

验证工具按来源、图内部、跨图、控制/资源分层独立取证。反例通过已有公开入口检查缺工作/依赖、错误shape/版本/伙伴、提前消费/复用和矛盾时间；共享ABI允许共同解释，但不能共同生成真值。示例只编排实验，不复制核心图/资源逻辑。

在整批修改后统一构建，以最终实现消费完整开发责任的有效案例；原生事实仍适用时只重建派生并重跑仿真/对照。整理仅影响局部时先做受影响组，最终冻结前再做一次必要整合回归，不每次小修改重跑所有案例。

逐项审定56项覆盖责任：已满足、已证明不适用、明确原生不支持或仍未完成，并保留证明范围；支持范围内关键缺陷/未知不能靠标签过关。冻结前还须固定模型资格、正式来源策略、独立48项责任/具体配置、抽样与触发规则、实际镜像/程序及完整预算。

退出条件：完整流程和评价就绪，已知支持范围内无未关闭关键缺陷；当前能力、来源数量、模板增长与适配维护成本可解释；代码/文档/数据审查和阶段分层提交推送完成。此后才进入第二阶段，不提前给性能层开工。

## 5. 第二阶段的执行与失效处理

B1–B4每组开始固定该组完整配置和具体输入、源/目标角色、冻结基线、实际来源作业、预算与停止条件。代码、adapter、观察/解释、规则、来源策略、评价方法及镜像冻结；允许正常产品流程产生新来源，不允许根据目标结果人工补库。 固定库的原始依据合格和对目标适用是两个前提；生成目标后、目标Engine启动前，使用正式来源选择核对实际模型引用及结构合同。新颖性可以忽略目录别名，适用性必须沿正式模型身份合同，不能互相替代；不因配置字节相同就授权跨模型引用。

B3候选为Meta-Llama-3.1-8B-Instruct和GLM-4-9B-Chat；A6先取得并固定实际模型配置及必要加载元数据、下载来源和文件身份，不假设本地已有。按配置及已安装原生注册表解析LlamaForCausalLM和ChatGLMModel，不能根据商品名选择glm4实现。不得在第一阶段使用它们的结构/预测差异调规则；历史是否已参与相关适配也须如实披露，只主张“未参与本轮开发”，不保证从未见过该架构。

原生资格先于Markov自动化结论，优先复用明确同域见证；一般新域由首个正式来源任务承担必要资格判断，不再启动一次Engine做重复检查。若失败无法区分纯原生与观察适配，才做能够区分原因的最小探针。

B3的两款留出模型须在A6冻结前取得基本原生可运行依据，历史证据不足时可做一次有界纯原生资格观察，费用另计；不得消费留出图/预测差异改A阶段适配规则。只有元数据/入口不够，不能让8个名额都被已知不可运行前提占用。候选若不合格，冻结前明确修订模型选择和理由，保留原资格失败；没有合格候选就保留B3未准备好，不虚构模型泛化证据。冻结后才出现的原生限制保留原项结果，不换模型或patch上游凑通过。

具体声明保存在data/20261116T001839.770807Z_a6-engineering-freeze/inputs/independent-specification.json，人读清单在同根results/independent-matrix-declaration.md。它们只规定配置、有限候选值、确定性边界及来源角色；以A6最终远端交付提交作为抽样seed，B1先复核明确固定的来源，再抽取目标，其他组按正式用户输入规划新来源。请求模式显式保留成员/token反向对照、远端专家层差异及持续运行责任，不能仅靠随机抽样期待边界出现。

独立新作业上界为48目标、32主来源及32局部来源；普通Serving也需要局部数组来源，不能只为PD预留。实际正式规划不得超过上界，不用剩余额度补采失败目标。独立额度为100000原生秒、80000处理秒、320GiB保留；B1–B3单原生任务900秒/处理操作7200秒，B4为5400秒/10800秒。沿用累计费用，窗口原预留尝试上限272，B5的明确接口刷新按下述有限批增加至281；原生/处理各172800秒、保留768GiB及项目data 1TiB。任何任务未完成不因此改为通过。阶段开始核实实际剩余与预约，不按理论上界直接消耗。

旁路按实际身份提供实测服务/完成条件，保留共同校准和测量范围，不输入动作/组批、查询或分配答案。校准不确定性若足以改变决定性分支，限定实际结论或取得必要依据；不逐事件挑时间凑通过。没有成本模型也能检验结构，但不能借此声称真实性能或唯一轨迹复现。

### B5：问题必须有归属和处置，修正不伪装成独立成功
