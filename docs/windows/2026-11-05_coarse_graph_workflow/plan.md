# 粗粒度执行图工作流计划

开始日期：2026-11-05。

目标：从干净代码入口、空运行数据和明确镜像出发，将原生 trace 提取为保留必要因果的粗粒度图，完成模板生产、目标动态展开及可信的单机全流程验证，随后进行有界多机探索并交付。计划定义工作与判据，实施状态和实际行动分别由本目录 status.md、log.md 维护。

## 1. 范围与交付

输入保持一个固定模型、配置集合和请求集合，系统选择代表来源，用户不指定 base。原生控制后端为主线；原生维护请求逻辑，核心维护槽位、KV、前缀状态和就绪，执行器维护模拟时间及在途工作。

交付唯一的粗图工作流：采集、真实粗图、模板库、目标展开、真实对照和精简报告使用一致的表示与边界。正式执行图不以每条 kernel、SDK 内部记录或 CPU 函数为节点，也不以它们逐条归属作为普遍通过条件。

本轮保留单机 TP/PP/条件 EP、P/D 分离及组合、等价 worker 代表采集、chunked prefill、mixed、原生 Decode 准入/预算策略和一级 prefix cache 的能力目标。具体可用范围重新取得证据，不因旧实现运行过而直接认定支持。

多机只作扩展边界和最小案例探索。轻量控制器推进、真实权重自然路由、数值计算正确性、overlap/speculative 扩展、多级缓存实际搬运、性能采样/成本模型及精度验收均不属于本轮交付。已有轻量分支若不能服务当前消费者，允许完整删除；不为其兼容阻碍新合同。

## 2. 正向流程与粗图合同

    来源原生执行 → trace 与必要语义/状态事实 → 来源粗图 → 切分与归一化 → 模板库
    目标配置与请求 → 原生控制 → 模板选择、有限变换与连接 → 预测粗图 → 完成反馈
    目标原生执行 → 独立 trace 与必要事实 → 目标真实粗图 ──────────→ 同粒度对照

来源实施域同时记录原生创建出的缓存类型、生效禁用状态及淘汰策略。目标装配核对配置与来源模式，原生资源工厂核对实际视图对应的实现；用户开关或来源请求不能替代原生生效事实。缺少该事实的历史来源不补写，不为元数据单独反复采集，随下一次已规划的新来源取证。

MoE 的条件路由按显式拓扑声明交接，EP1也不能被当作dense而跳过。实际专家层从原生模块统一发现，并通过全worker事实判定模型是否需要路由；PP局部没有专家层不代表整个模型是dense。本地Standard分发的计算入口保持token行，DeepEP normal AllToAll的计算入口使用接收专家行，二者由框架adapter声明和核对，核心不按EP大小猜shape。采集、代表来源组合、缓存身份及无设备控制消费同一份路由；仅实际采用的布局取得对应来源资格。

有限采集阶段由已声明的全部请求和原生排空事实关闭：本worker接收完该阶段所有请求后，在原生整轮idle、调用栈退出且在途PP发送排空时结束观察。多个提交组之间或未来请求到达前的空闲不能关闭阶段。驱动等待全部参与者发布drained后才发送清缓存请求，随后等待原生重置和阶段完成；不由外部关闭文件或驱动管理消息决定服务窗口，不删除窗口内未知读取以消除partial。

来源粗图只描述该次真实执行，不是任意目标的全集。模板额外保存有依据的参数关系、组合和有限分支；目标组批由控制器动态产生，不能复制来源或真实目标的批次。

### 图中保留什么

| 对象 | 最少需要表达的内容 |
| --- | --- |
| 工作身份 | 请求/逻辑 token 范围、流程阶段、必要迭代、层/角色及 rank/实例；不靠跨运行节点序号对应 |
| 执行片段 | 稳定职责、使用的 CPU 线程或设备 stream/通信资源、必要参数及来源依据 |
| 数据端口 | 外部输入输出、shape/dtype、必要读写/别名和数据就绪；不保存全部内部临时张量 |
| 完成端口 | 必要的调用进入、CPU 返回、设备完成、中间信号和资源可释放边界；按实际行为选择 |
| 连接 | 数据依赖、同资源顺序、跨 stream 同步、跨 rank 通信及控制/资源效果的提交条件 |
| 模板合同 | 参数、重复/子调用、有限变换、实现域及资源绑定；来源取值不充当目标默认状态 |
| 诊断 | 粗片段到原生范围的最小取证入口；可选内部明细不进入共享身份或成功判据 |

状态访问、通信就绪至完成、非零等待区间都必须有真实因果路径；拓扑排序中的先后不能替代依赖。共用图校验在来源、切分和实例化边界执行，已验证的串行资源链直接提供路径依据，跨资源或并发服务沿实际边检查，不在各阶段重复实现规则。

持久状态初始化不依赖模板切分：读取范围可由有效历史内容与本图中因果先行的写入共同覆盖。收齐本次访问后检查完整覆盖及真实路径；局部先写后读不能误报未初始化，后写、无序写或覆盖不足不能借节点编号获得资格。历史在途访问继续保护资源复用，不为通过初始化检查自动补内部依赖。

粗图、模板及性能单元各有粒度。粗片段须覆盖内部工作的资源和成本责任，但本轮不建立真实成本；不能把被封装的工作当作零耗时。未来细化计费不要求恢复完整底层语义图。

### 规约规则

1. 先从现有原生调用/模型层次、真实提交关系和资源身份确定边界，再提取粗图；不先构建完整细粒度 DAG 再默认持久化和压缩。
2. 可合并同一串行资源上内部封闭的连续工作。对外的数据、状态、通信、中间就绪、CPU 返回及释放关系形成端口或切点；同一 stream 不能单独证明可合并。
3. 跨 stream 的区域可保留多个资源片段及连接，不压成一个全局串行节点。跨 rank/实例只连接协议实际要求的参与者，不添加整组屏障。
4. 内部 kernel 名称、数量及 SDK 实现记录不定义模板种类。必要的外部作用按实际 API、提交、队列、资源和事件生命周期承接，不用名称白名单或相邻时间猜归属。
5. 归属要求以已选流程及必要因果为范围。已证明被片段覆盖的内部细节可不逐项对应；证实流程外的记录仅作诊断；可能影响边界而无法归属的记录保留为局部证据缺失，不能静默丢弃。
6. CPU 自身工作、排队和异步设备工作分别表达。等待由依赖产生，不把整个原生调用墙钟同时算作 CPU 服务和设备成本，也不把 CPU 返回统一当作设备完成。 对同一调用片段、相同已提交 stream 前沿的重复 host 等待做统一规约；首次等待、跨子调用/外部端口和新提交形成的等待仍保留，不能按原生同步 API 次数定义模板种类。
7. 统一预热后开始观察，记录逻辑 KV/缓存初态及必要资源前沿。初始化、编译、预热和窗口外工作不进入正式图；起点不清楚时报告事实不足。

规则维护在一个正式实现中，框架/runtime 提供差异事实，不按模型、请求长度、kernel 名或目标残差增加粗化特例。未知记录的处理必须能追溯到规则和边界证据。设备记账命令须由原始 runtime 元数据证明身份后排除；同名命令可能承载实际作用，不能按通用类型名称一概忽略。

采集器插入的设备进入/完成标记只提供定位证据，不自动成为业务 stream 边界。runtime 解释完成后，按真实 payload、显式数据/状态端口、同步、通信及外部依赖决定保留范围；仅由合成标记构成、没有业务作用或外部引用的设备区间与隐式端口一并移除。存活锚点统一重映射，随后才做粗图投影、模板生产及来源对照；不能只在评价时忽略这些节点，也不能按 filter、模型或 shape 删除。CPU 调用及其逻辑状态修改仍保留。优先用现有完整原始来源重新解释，不因投影规则改变自动重采。

### 模板生产与变换

来源切分一次建立 scope 归属、目标事件入边、来源输出及资源拓扑顺序索引，各动作只遍历自身子树和相关边界。跨切口数据/信号检查以本动作实际保留的输入为依据，不接受被切掉的父调用或相邻调用代为声明；保留来源绑定顺序，不为每个小动作重新扫描整个来源。

按统一 serving 动作和模型层次切分来源粗图。Prefill/Decode 内部以 embedding、重复层、attention、MLP、归一化/残差及输出角色作为候选结构依据；不固定每个函数或每个 kernel 一类模板。

自身定义、子调用组合、目标参数和 rank/资源绑定分开。重复层、同职责 worker 共享定义，保留权重、KV、stream 和状态的独立身份；控制/输出职责不同的角色不能强行共享。代表选择发生在采集前，采后去重不冒充采集次数减少。

代表复用必须贯通生产与消费：原生初始化交换模块实现、局部张量几何/别名、角色职责和实际通信组，采集前选代表；来源保留各 worker 的等价归属、并行坐标和通信组事实。目标只能采用来源声明的等价角色，不能通过修改目标环境自行放宽实现域。collective 的分组身份由原生进程组对象确定，参与者、根和通道按实际组绑定；根采用组内位置，不按全局 rank 偏移或字符串替换推断。P2P 路线由当前原生发送/接收提交，在实例化校验前绑定。

推进顺序为同 PP 阶段内等价 TP/EP worker → 跨阶段实际模块位置/层绑定 → PD 池布局和对端重绑定。 跨阶段代表判定在原生模型和 KV 池都构造后执行，比较局部模块结构、张量几何/别名、KV 布局及首/中/尾职责。模块对应取实际模块遍历位置，KV 对应取原生池内位置；保留真实模块路径和全局层号作为目标绑定，不按路径字符串猜层号。专家工作量仍查询 workload 的实际模型层，交给模板时改用局部专家层参数位置，采集与控制共用同一映射。未接通的重绑定不允许提前省略相应来源，也不输出没有消费者的词表/层号/专家偏移表达式。每一步核对采集前选择是否真正减少观察 worker、目标是否共用定义并保持资源独立；旧来源没有角色事实时不离线猜补资格。

父调用通过直接子调用的导出边界连接，不跨层读取内部事件编号。父定义约束子调用接口，具体子实现选择归调用绑定；接口包含参数及边界资源的共享/独立关系。先完成接口、编译和实例化的一致交接，再实现子调用的独立选择、重复和组合；接口收紧不能代替动态组合的交付。资源结果处理与模型内部条件分支共用这套层次机制，不能分别增长整批组合特例。

张量句柄绑定不等于读取内容。仅将输入转交子调用、并在内部执行就绪等待的外层方法，以metadata输入传递存储/版本/形状，实际读取由子调用的data端口和原生等待约束；不能把外层进入时刻当成数据已经可读的时刻。显式输入绑定支持这两种端口，输出发布仍要求真实data端口。是否只做转交由adapter沿原生实现确认，不能只因观察到一个子调用就自动删除父层读取。

观察窗口只承载事实；供控制器调用的模板入口必须对应具名 serving 动作，显式导出跨切口的端口和依赖。目标每次只展开该次原生动作选择的入口，不能把来源窗口的调用序列整体实例化当作动态调度。调用内的逻辑别名与跨调用的持久状态分开，目标的 storage/version、资源前沿和释放条件由调用方绑定，不沿用来源运行状态作为默认值。分配来源与最后写入来源分别保留，避免把原地修改当作新分配；KV 层布局仅为元数据，实际依赖沿统一的逻辑范围/页映射处理。

shape、成员及 KV 范围关系优先来自原生模型元数据、实际调用参数、已有明确运算规则和接口合同。需要人工适配的内容限于不能自动取得的实现差异，维护一处；不从少量样本拟合 shape，不复制整套模型实现或开发通用符号推理平台。

原生布局分支由实际几何、明确 ABI 和布局运算给出条件，复用统一整数表达式。条件在局部声明，来源逐层核对条件及实际 shape，目标沿子调用参数关系求值并选择本层实现。核心不识别复制算子、模型名或具体 batch 大小，不用空缺来源的条件猜补事实。张量身份按实际共享作用域归属，外部存储归动作根，私有子树不再占用其他子树的编号。兼容候选在初始化时按相同父调用结构、调用位置、本层接口与绑定分组，并保留所有跨子树张量的别名、版本、写入者和参数关系；接口同时描述端口含义、边界别名及资源别名。目标递归选择已观察且条件成立的局部实现，保留其原有连接；内部私有结构变化不再要求整棵动作绑定树一致。父结构、共享绑定或接口变化须使用相应完整变体，不能任意重接或推导未观察循环次数。

局部 ABI 只携带本调用需要的参数，例如 gather 使用张量各维长度，父调用显式提供这些维度与 batch 参数的关系，不继承整批专家参数。局部端口表达式与父调用的张量形状记录分开维护，局部参数名不得逸出到后续调用。扩大变体共享范围前，先核对调用位置绑定、外部别名/写入者、资源映射和导出就绪点；不能仅按函数名或接口 shape 相同跨父图取候选。

**局部实现复用与粗化分开处理。** 对外端口及其可达关系相同，只证明边界因果一致，不证明内部资源工作相同。若局部复制、额外 stream 或等待产生实际资源作用，保留已观察实现及其条件；不得通过删除 guard、删除工作或添加无来源的零成本服务槽位把缺口变成通过。优先检查同一显式采集任务的其他角色是否已有相容局部实现，再决定是否存在真正的来源缺口。

局部复用按以下顺序整体实现，再进行一次必要的生产与目标展开检查：

1. **适配器声明实现依据。** 明确局部调用实际读取的参数、实现环境与通信组内职责；区分可隔离的局部 ABI 和仍依赖外部状态/调用上下文的实现。不同 Prefill/Decode 角色不能直接共用整个动作或环境域；模型、runtime、布局和通信机制的相关差异仍须约束，不靠删除域字段放宽资格。
2. **生产层分离实现与绑定。** 在同一个采集任务内核对局部接口、输入输出别名/写入关系、必要导入导出与资源共享关系。相容实现共享定义；调用方的张量身份、rank、通信组成员/根/顺序和实际资源归属保留在各自绑定中。既有绑定的具体数字相同不是复用证据，不能直接复制另一个角色的 frame。
3. **核心选择与实例化。** 只在上述合同成立时扩大局部候选范围，由目标局部参数选择已观察实现，再绑定到调用方资源。共享定义不得持有其他角色的 KV、队列或在途状态；有子调用或外部状态的复杂结构继续按完整合同处理，不为 gather 新设特殊选择分支。
4. **验证交接与隔离。** 先静态追踪生产、发布、加载、候选选择、通信重绑定和实例化，再用已有真实来源检查正向复用及不相容接口/环境/绑定的拒绝。核对没有借用另一角色的状态、修改原始事实或削弱来源评价；完成这一整条职责链后统一构建与试跑。历史不同采集任务不自动合库，也不把这项复用冒充采集前代表选择。

独立局部采样仅在确有来源缺口时另行判断；须先明确所有原生参与者的一致调用顺序、与 serving 事实的隔离及模板接入合同，不直接在 profiler 停止回调中加入 collective，也不先新增采样入口再补这些边界。

模板编译根据已核对的边界 shape 表达式，保留每个可变维度的零/正值条件。空张量可能没有数据访问或子调用，不能只改 shape 就把空来源扩为有工作结构；目标从满足条件的已观察子树中选择，仍沿该子树的原有端口连接。条件归调用绑定、同条件去重，不为具体长度新增定义。这只是空维度边界，不能代替非空范围内的原生分支条件，也不能从两棵不同绑定树任意拼接未观察组合。

为条件子树取证前，先沿原生组批、补齐、分片及模型调用条件证明目标分支在所选支持域内可达，区分模型输入行、rank 局部行和专家接收行。原生控制循环产生的调用数量由控制接口逐次展开；模型一次调用内部的组合由已观察模板及接口约束选择，两者不能混作同一证据。当前域不可达的分支不通过反复构造同类请求、修改框架或扩展未计划的配置机制来制造；相应未知资格继续明示，保留受支持域的后续泛化验证责任。

有限变换覆盖参数求值、固定层调用的共享复用、成员访问范围展开、局部实现选择和端口/资源重绑定；必要通信由对应拓扑合同连接。粗化不得隐藏需要独立变换的部分，也不因目标内部 kernel 数量变化而直接判定不支持。

重复与组合分别按所有者审查：原生控制决定动作出现次数；模型层由来源模型的实际调用树绑定，共享定义但不随请求数复制层；请求成员由本次参数、张量 shape 和 KV 范围规则展开。一次动作内部只选择已有父结构及相容子实现，不从 shape 推断未观察循环。验证内部子调用数变化时，须比较同一调用位置在不同合法输入下的实际结构；首/中/尾层固有的不同子调用数不能代替这一证据。局部选择审查覆盖参数传递、接口、跨子树别名/写入者、通信与资源绑定，不能只检查选择成功。

同来源域重点复用请求长度、成员、到达、并发及 KV 容量变化。模型、dtype、并行拓扑、backend、框架镜像及 page_size 变化分别规划新来源，不以这些变化必须沿用旧模板为目标。调度机制使用各自合法来源和控制配置。

## 3. 代码与适配职责

| 层次 | 唯一职责 |
| --- | --- |
| 框架 adapter | 流程入口、批次/模型层次、必要参数与状态事实、原生控制接入和并行角色解释 |
| runtime adapter | trace/API/队列/stream/event/传输事实的解释，实际资源和生命周期；不选择批次或实现第二份资源账 |
| 共同核心 | 粗图表示、通用规约、模板切分/归一化/变换/连接及资源执行；不识别框架私有函数和 SDK 名称 |
| 外围应用 | 单任务进程、镜像选择、累计预算、产物发布与恢复；不暗中生成模板或改变控制策略 |
| example | 代表案例、矩阵、真实独立对照和失败归因；不被 src 导入，不复制核心 shape/KV/调度算法 |

目录、类与数据交接按上述职责重排，C++ 头源同目录。先决定最清楚的组织，再判断旧模块是否有保留价值；不因现有文件名或调用关系而维持错误分层。不新增万能注册中心、双格式读取、版本分支、空适配目录或纯转发包装。

## 4. 阶段与结束条件

| 阶段 | 主要结果 | 进入下一阶段的条件 |
| --- | --- | --- |
| S0 收尾、清理与环境核对 | 干净数据起点、明确代码取舍和镜像/构建归属 | 旧输入不再可被默认找到，迁移基线和实施边界明确 |
| S1 粗图工作流构建 | 从原生事实到粗图、模板和动态展开的唯一正式链路 | 来源和评价合同齐全，旧职责链删除，完整功能静态审查及集中构建完成 |
| S2 初步验证与收口 | 代表机制的真实闭环及评价可信性证据 | 能区分来源、核心、控制和评价问题，主要机制与必要负例通过，达到冻结条件 |
| S3 全量独立验证 | 同一冻结规则下的完整结果和归因报告 | 无未关闭的关键结构缺陷，覆盖和证据边界明确 |
| S4 多机探索 | 最小证据、扩展接口及代价结论 | 探索有界结束，不改变已冻结单机实现来追求多机通过 |
| S5 最终交付 | 整理后的源码、文档、资产、公开入口和支持说明 | 审查、必要复核、数据检查和阶段提交推送完成 |

### S0：关闭旧路径的入口，建立干净起点

- 核对 Git 起点、工作区全部未提交改动和真实消费者。按保留、替换、删除确定整条职责链，未交付修复不自动成为新基线；用户无关改动单独保留。
- 只做必要归位和明确无用内容删除，不先把即将替换的细图流程大规模美化。新图表示确定后，结构性改写集中在 S1 完成。
- 核对活动任务与私有资源，结束旧窗口遗留进程后清空项目 data 下的旧运行数据，包括旧来源、模板、真实目标、预测、报告、临时文件和恢复状态。新流程不导入旧资产，也不把旧数据迁入新运行根伪装为新产物。
- 清理旧硬编码路径、默认资产选择、示例输入和文档证据链接；旧预算与失败只作为主工作流已明确范围的历史，不要求长期维护旧数据或兼容旧格式。
- 模型下载、依赖缓存、官方/参考源码及其他工作区资源不属于运行数据，不随 data 清空。不可确认归属的外部内容保持原状，并明确其不参与新流程。
- 核对 modeling、推理、control 和原生基础镜像的 ID、父镜像、软件来源及实际安装位置；检查 Compose、Docker COPY、入口、挂载和源码路径是否可能带入旧包。清除已确认本项目独占且无消费者的旧镜像/容器/编译产物，不执行全局 prune。
- 镜像稳定命名、不含日期。S0 确认软件基础与重建范围，不为即将删除的采集代码反复打包；S1 完成模块后统一重建受影响推理/control 镜像及核心程序。

结束时保留必要代码基线和本阶段实际整理记录；data 在新运行开始前为空。旧源码可供短期阅读，不能通过正式入口执行；没有经过新合同核对的镜像不安排采集。

### S1：按闭环重建，完整删除被替代实现

按“任务输入 → 采集事实 → 来源粗图 → 模板 → 原生控制 → 目标展开 → 完成反馈 → 结果”的顶层闭环实施。先定义各交接对象、状态所有者及完成条件，再向下完成每个模块；评价入口和目标真实粗图的生产同时纳入设计。

直接观察的具体输入/输出、shape 和边界与参数化规则分开交接。模板根据声明求值，真实粗图保存实际观测值，不能用同一模板求值器重建真值再自证。 子调用参数关系与 KV 范围规则在知道原生语义的插桩点声明，模板构造只核对规则与实测值；不能把全部 KV read 后补成 attention 前缀读取，也不能在离线编译时修补缺失的父子参数关系。内部 shape 传播如需观察 Torch 运算，只更新必要临时元数据，不持久化完整操作列表，也不把旧细图作为新规约的先决条件。

控制接入以具名动作及其返回为边界，资源服务独立接受原生的逻辑分配/前缀操作。动作必须保留资源变更前的必要绑定，并由执行层连接内容就绪、覆盖及复用条件；只接通 RPC 或让原生循环继续不算闭环。先建立单 worker 的这套交接，再恢复 TP/EP 参与者及 PP/PD 协议；旧的逐索引操作、框架步骤状态机和消息图装配整链删除，不包成兼容分支。PP/PD 的能力范围和全量覆盖责任保留，必须在新接口上取得证据后才能进入 S2。

控制侧安装由 worker 装配入口统一收口：原生初始化所需的资源替换先安装，serving 的流程、状态、通信与信号钩子全部注册后再一次应用，然后进入原生循环。各适配模块只声明自身钩子，不自行提前应用，避免原生注册器跳过已安装目标上的后续钩子。安装核对必须覆盖真实 worker 初始化顺序，手动组合几个 wrapper 不能代替这一交接的证据。

资源初始化时由 adapter 声明实际页复用策略，不能由应用层统一套用 PD 分配方式。沿当前 runtime 真正选择的 allocator 检查归还顺序和延迟合并条件；基类实现不能替代平台覆盖方法的依据。核心唯一维护槽位、页及前缀账本；用既有真实分配/归还记录核对具体页身份，独立区分资源选择与在途访问安全，不为此另建框架分配器副本。

资源管理的逻辑操作与其原生执行工作分别拥有边界。分配、缓存淘汰和页归还由原生代码决定何时发生，核心唯一维护资源状态；原生为维护页索引而执行的设备工作、拷贝及等待不能只混在外层preparation或结果处理模板里。先沿实际allocator/cache接口确认独立调用边界，再由采集和控制的共同adapter声明必要参数、数据及完成关系，使外层继续片段和重复维护调用按原生执行展开。不能按请求长度、是否曾见过淘汰或来源序号选择整个批次模板，也不能在核心复制原生淘汰控制器、删除真实等待或另建资源账本。统一检查初始化、普通分配、淘汰叶释放、分组归还、请求结束及PD释放路径，先完成整链设计再改代码；原始资源记录用于诊断边界，不能补造未观察到的tensor端口或把可选验证记录变成正式能力的必需输入。

可中断调用的输入在首片段记录，返回值在末片段交接；若返回张量实际由同次调用的较早片段新建，则按观察到的allocation/writer在该片段声明输出，末片段声明接收与再导出，复用目标批次的已有值绑定。保留真实写入者、版本和串行/数据依赖，不把末片段伪装成写入者，也不再执行一份完整父图。该规则只连接实际观察到的同调用片段；跨片段的已有存储变更需要写入处的显式输入/输出，不能用末尾快照反推缺失的变更边界。必要的片段身份属于正式采集合同，不依赖可选资源诊断开关。

条件路由的前缀身份与执行条件使用同一份实际专家层事实。来源复用初始化阶段已有的 worker 元数据交换取得全模型层集合，目标从装配后的全部 worker 绑定取得同一集合；PP 不只考虑本地 stage。普通层上的路由声明和等价区间拆写不改变共享资格，真实专家条件差异仍须区分；这项键语义核对不替代缓存淘汰及在途复用验证。

采集与无设备控制通过同一原生输入/空闲 hook 维护流程活动区间；非空输入激活，完整 is_fully_idle 判定结束，不使用健康检查的宽松空闲条件。原生空闲后的无工作收尾不因采集窗口仍打开而额外生成流程动作；已经提交的 PP/PD 工作、完成等待、profiler 窗口与最终排空保持各自生命周期。 入口的完整空闲等待由请求到达或最终停止释放，不能用其他worker尚未完成请求代替输入唤醒；非空闲的协议轮询仍由其实际元数据通知、已观察完成事件及原生控制进展驱动。初始化等待全部参与者各自报告空闲，最终停止另外核对全体请求清理，不能把整组收尾条件反过来施加给某个worker的局部休眠。规则在生产端生效，不对旧来源按函数名删调用或补造活动边界。

原生观察按调用范围记录 CPU 进入/返回，设备边界使用实际 stream 事件；事件必须通过原生 API 实例、队列关联及生命周期取得 trace 依据，不能按最近时间匹配，也不能用 CPU 提交时刻替代设备完成。设备事件及弱张量元数据按在途生命周期回收，不持有整个长 workload 的设备事件句柄。模型边界按当前框架 ABI 声明 token/member 维度及真实布局，未知参数保留实际形状和明确缺失，不按数值相等猜符号关系。

设备与主机时钟的对应由独立计数器查询确定：在同一观察窗口的两端记录计数器及包围查询的 RAW 区间，runtime 解释 SDK 导出坐标并校准速率。不得借用目标因果边拟合时间，也不将驱动给出的有限精度频率视为无误差真值。先完成采集、解释及来源证据的整链交接，再复核一个既有机制组合；保留查询不确定性和残余倒置，旧记录不拼接其他运行的锚点。此项只处理测量坐标，不改变图的逻辑依赖、模板条件或核心完成规则。

来源评价区分名义时间倒置、校准约束不相容和未测边界。独立检查每个rank全部已测关系是否存在共同的、落在本次两端查询区间内的仿射时钟；只判断可行性，不输出拟合时间、不回写测量，也不按倒置大小增加容差。某一条边单独可满足不代表整图可满足；缺少测量与跨rank时间关系保持各自未验证范围，校准相容不替代SDK关联及来源完整性证明。

来源等待前沿须按实际队列提交确定，SDK 的外层 launch 可能包含同步，不能以其返回过滤已经提交的任务。统一核对队列生命周期、驱动提交、SDK 关联及内部等待，命令组内没有逐项对应证据时保留提交区间的不确定性。解释规则修改后，从同一原始记录重新生成粗图与模板；粗化边界可能随正确依赖合并，不能用旧图的工作段数量约束新图，也不能继续把旧模板展开结果作为新规则的验收对象。

设备拓扑使用 stream 内的原生顺序，保留零耗时任务的开始/完成；实测时间不改变结构身份。来源解释入口按主机和设备各自的 SDK 导出锚点统一为 RAW 时钟，原生 API/传输服务直接保留 RAW，不混用偏移或往返转换；导出坐标转换与设备计时校准分别核对，不能用依赖倒置反推补偿系数。提交线程按实际设备提交和必要等待规约，句柄维护只服务生命周期解释，观察器回收不进入业务片段；不能因管理任务的插入位置新增模板或条件。通信单独声明输入就绪、本地完成及参与者，图局部资源映射到统一时间线，CPU 协调不代替设备依赖。内部布局或通信实现差异先核对是否具有对外作用；封闭细节由粗化规则承接，必要变化才采用有原生依据的有限条件，不按 batch 数量新增例外。

EP 按实际专家层及原生参与组推进：先统一采集/控制的条件路由校验和 rank 身份，再将派发、专家计算与合并的参数及通信边界接入模板。专家负载从 workload 与原生分片/补齐规则推导，接收张量的几何还须按实际 backend 的复制/去重语义核对，不能把路由次数、不同 token 数和接收行数混用。已观察通信完成不等于已具备路由变化下的模板变换；这两项分别收口后再取最小 EP 运行证据。原生会改写的非法拓扑在 worker 启动前终止，不修改框架强行支持。

PP 按原生完整轮转接入，不复制 event_loop_pp，也不把 TP/EP 的同步 collective 直接当作流水线发送。微批次容量保持原生默认计算，只有用户显式指定时才覆盖；采集与控制必须采用相同策略，不能用总请求容量代替微批次容量。实施顺序和职责如下：

PP 的跨运行工作身份由共同适配器读取实际微批槽位中的请求进度、当前批次、消息类型和字典字段；槽位只表示原生布局，不能独立充当工作身份。字段归属跟随原生字典迭代，接收读取实际消息类型而非期望类型，因此相同 shape、发送切片及暂存的异类消息不靠形状或位置猜配。异步 Work/Event 保留生产时的逻辑快照，等待另记当前工作和实际流角色；原生句柄及代次数仅在本次执行中连边，不用于跨运行匹配。所有信息只服务观察和对照，不修改线上消息或参与模板归一化；重复的相同逻辑状态仍须报告证据不足，不能追加全局次数兜底。

PP 空微批槽位检查与 PD 队列轮询共用重复查询原则：次数由原生轮转、传输进度及其他工作共同决定，状态快照不是调用发生次数的唯一身份。先区分状态推进、元数据读写与无变化查询，沿真实完成边界确定等待关系；不能要求每次重复 CPU 查询都靠追加上下文获得唯一时间记录。规约依据必须包含实际子调用、资源/张量作用、对外结果及必要因果，须审查循环计数、重试、准入预算及清理的状态变化，不能只看队列为空，也不能把一次查询强制阻塞到完成、强行返回成功或按调用次数匹配。来源和目标采用同一规则，保留原生控制执行及必要状态变化；结构对应、查询数量和真实时间覆盖分别报告，不因若干查询无法逐次对应而认定模板缺失，也不把未对应工作算作通过。实现前共同明确采集范围、模板/实例化、时间约束与独立评价的交接，不改一个比较器的过滤条件求通过。

队列级调用与普通选择共用适配层的请求进度快照，包含原生 waiting/running/previous/chunked 及对应 PD 生命周期队列；快照不成为模板类别或轮询次数编号。结构对应保留当前动作自身上下文与切分边界，祖先仅取 owner/entry 调用位置；不能将无关请求在祖先队列中的停留当成当前子调用的结构身份。祖先队列和相邻子调用快照仍保留：时间提取与核心旁路共同要求完整上下文一致，不能把结构对应自动升级为绝对时间对应。归并后的重复仍不强配，跨调用因果和数据/通信作用独立检查；缺失 CPU 时延可能改变清理与新请求到达的交错，迟到时停止并解释，不平移或删除时间以求通过。元数据传输涉及的请求归属在原生观察时记录，解释层只解析其物理布局，不补造原始 work 声明。CPU 片段复用以原生方法的完整路径审查和图内作用校验为依据：已独立提交的资源、传输和发布仍保留子调用，不能因控制循环的相邻子调用组合变化而复制同一种 CPU 结构，也不能将未检查的队列方法一律声明为纯 CPU。

PP的选批、输入读取及通信/信号使用同一原生流水线上下文：当前批次、固定槽位内的请求进度及running_batch与running_mbs的实际绑定。无批次与存在但成员为空分别表示，不能把其他槽位仍有工作的选批记成全局空闲。槽位位置来自原生固定容器，既不读取循环次数，也不推断局部变量mb_id；完整状态再次相同时仍保留重复。旧来源没有记录这些读取边界时，不能从邻近通信快照补写选批或输入读取时的状态。

组批协调的设备 all-gather 不因没有 CPU metadata 标记而脱离数值资格。采集和控制共用原生 MLPSyncBatchInfo.all_gather 的完整调用切口；详细观察只读取调用前七项 Python 标量和原生已读回的 token 数、控制标志，不额外读取设备 tensor。原生与目标的片段范围仅在各自运行内关联本次通信，不作为跨运行轮询编号。独立评价按本轮实际参与者和 DP/TP/CP 布局，核对原生实际消费的结果；重复轮次分别检查，跨运行只比较唯一调用。活动 rank 的 CPU 镜像不自动证明故障恢复中的设备 mask，缺失或非全活动证据单列未覆盖；TBO、DP/CP 扩展不能因采集到这些字段就获得运行资格。数值与片段范围不进入模板条件、工作身份或控制决策。

PD 完成反馈分别核对传输服务结束、原生 Sender/Receiver 协议状态、元数据 gate 及参与者归约。CPU 元数据集合通信通过可选详细观察保留实际调用前操作数及返回结果；来源关联原始 scope，目标关联已完成返回边界。广播非根输入缓冲不属于操作数，不能采集其未初始化内容。数值独立于模板、时间约束和调度决策；评价先按各自通道检查实际运算，再对两侧唯一调用比较操作数，重复轮次不强配，缺少证据保持未观察。原生协议状态的发布事实从实际管理器状态更新入口观察，按请求和参与者记录 Success 写入前后值及 RAW 时间区间，不用额外 poll 或设备同步取证。独立评价以实际传输及末块 metadata 确定全部必要端点，再核对状态更新及成功读取；没有读取记录的端点仍须报告缺口，不能从评价范围中消失。

发送服务、发送侧发布、接收侧状态更新和读取区间分别核对：来源与目标共用就绪/成功阈值判定：新状态读取不能整体早于状态更新，旧状态读取不能整体晚于更新。对同一端点的全部读取累积可行区间并检查状态单调顺序，不能为每次读取分别选择相互矛盾的转移时刻；重叠或同刻保持允许的不确定性。收紧区间仅用于独立一致性检查，发布的原始状态写入区间不变。缺少状态更新记录不能用首次 Success 读取补写，状态写入区间也不是 socket 到达或单一精确时刻。实现中按参与者分离传输完成与协议可见边界，不能默认一个通知的所有接收者同时就绪。adapter 解释请求、发送组及消息含义，共同执行/通知接口维护依赖、时间和交付；不在核心增加 PD 状态机，不按请求补延迟，也不让旁路指定查询结果。具名通知先登记工作身份及依赖，图信号提交后再绑定，发送调用无需等通知完成；接收侧可在预约时登记对未来发送侧发布的依赖。区间旁路采用满足依赖的最早可行时刻，依赖晚于上界直接报告矛盾，不平移区间；独立评价同时检查实际执行边、端点身份、来源区间和实际交付。

通知生命周期按请求维护：adapter 提供实际请求归属，同一通知及其通知前驱属于同一请求；核心在所有参与者完成该请求的原生清理且通知均完成后释放通知记录及时间线保留权。不能在发送者结束或最终 token 发布时提前释放，也不能让完成请求的通知随 workload 累积。逻辑身份与请求索引分工保持清楚，回收不修改通知时间、原生动作或独立评价结果。

独立时间提取按原始 session、请求和末块 metadata 关联必要发送者，检查 Success 的读取区间不得整体早于发送组服务返回；即使存在无法逐次配时的重复身份，也独立保留这项事实核对。服务返回后仍 pending 是允许的通知/轮询间隔，metadata 可见性也不能仅凭服务返回赋予精确时刻；不把必要界限检查写成完整协议证明。

原生组内轮询以共享 poll_and_all_reduce / poll_and_all_reduce_attn_cp_tp_group 为执行切口，保留读取、metadata gate、TP/CP 归约及返回；外层包络覆盖嵌套单组 helper，不重复计费，也不要求必须已经进入某个 scheduler 方法的包络。Prefill bootstrap、Decode 准入及 PP 就绪检查共用这一边界，实际 pollers 的有序请求身份进入观察和工作上下文；评价按该向量连接操作数，不能默认整个 transferring 队列就是本次操作数。轮询函数外的其他 CPU/Gloo 事务仍需各自流程依据，不能泛化为捕获全部 collective。原生轮询结果与 actor 是否可停等分别维护；停等依据已有预约/资源阶段和原生 idle 条件。独立准入检查从本次原生事实取得 TP 参与组，保存各 rank 在归约提交前的实际传输/元数据读取，再沿执行图的通信边连接输入；请求提交须满足全部参与者对同一有序请求列表已成功，且本地归约已完成。单成员组检查本地读取，不虚构 collective；不按跨运行轮询序号配对，也不由目标自己声明的参与者集合自证完整。本地 Success 不等于整组可以准入，不能令已被原生判为空闲的参与者无限轮询；由现有信号观察者、消息和到达唤醒，而不是制造另一个协议状态来驱动等待。

准入检查连接本轮读取、实际操作数、归约输出及结果消费，不能只分别证明读取合法和 MIN 算术自洽。对普通 Decode，在各次运行内部按真实请求队列顺序消费本次 decode_receive 的传输/元数据读取：Success 但元数据未到达降为 Transferring，其余状态保留。参与者从原生实际 attention-TP 协调组取得，不依赖出现集合通信动作或某个外层 scope 名称；各端操作数须对应同序请求，单 rank 使用本地门控。新接收轮次清除旧决定，每次准入只能消费当前尚未消费的成功结果；原生限定检查请求时，不要求其余成功项立即准入。来源与预测分别核对未准入轮询和实际准入，缺操作数/结果保持证据不足，不按跨运行轮询序号配对，也不向核心输入真实决策。此检查不扩展为 staging 或多级缓存状态机。

观察原生 poll 的请求归属、调用 scope、RAW 区间和返回状态，不额外轮询、同步或改变返回值，也不把查询次数变成图节点或模板条件。重复身份统一报告时间未覆盖，不因协议查询而改变计时交接规则；图外查询单独报告，传输图就绪不自动取得协议完成资格。Decode 预约中的索引导出等待仍属于必要执行关系，不能因没有设备计算工作而删除。

跨 worker 控制值通信统一检查输入发布、图提交及结果消费的顺序，覆盖 CPU 与设备进程组。来源调用入口、图提交和控制结果可用是不同边界；旁路以调用返回和导出完成信号控制推进，入口仅作为来源区间及因果证据，不强制与目标构图时刻一致。原生元数据预计算与执行图提交交错本身不判错；若结果消费早于必要执行完成，或原生值等待阻止真实返回/完成关系成立，再修正共享适配切口。保留真实计算、传输与依赖，不把设备通信改名为 CPU 服务、不平移返回时间。先整体审查原生控制用集合通信及点对点消费路径，再集中修改，必要证据一次取得。

原生 Event 的完成代次和上下文由该 Event 对象持有，重新 record 时覆盖为新代次，已提交图边保留各自的完成身份；不以对象地址或依赖 SDK 弱引用回调的外部字典维护信号身份。观察器自有定位事件不注册业务完成信号，其回收查询不生成业务动作。

完成反馈区分 CPU 阻塞返回、stream 等待和非阻塞查询：前两者保留原依赖，查询另记录实际结果、信号记录代次和调用前后时间。查询结果只提供完成时刻的界限，不能伪造精确设备时间，也不按查询次数生成模板。时间提取检查查询界限与测量一致；动作对照与时间提取共用原始查询事实检查，结构资格与逐次时间覆盖分别判断，不能给缺查询声明的旧来源补空记录；PD 预约、元数据可见和传输状态分别沿原生协议核对，不能仅凭 Event 观察声明协议覆盖。已有来源缺查询记录时保持证据限制，不补写空数组取得新资格。

1. CPU 请求及协议元数据继续经过原生 point_to_point_pyobj、字典收发和 TP 广播；无设备适配把其真实发送、接收和 Work.wait 暴露给 worker 装配层，保持异步提交、按方向/组/tag 的 FIFO、类型/形状及原生空消息。该通道只推进原生逻辑，不代替设备通信的模拟费用或完成边界。

   原生控制片段中的 CPU 张量归约、聚合和广播必须有独立执行切口：先提交调用前的 CPU 工作，向 broker 非阻塞发布输入，再通过实际 CPU 进程组和共同通信端口表达就绪与完成，图返回后消费原生元数据结果并恢复控制。不能等各端图返回后才提交值，造成隐含的第二次汇合；结果按参与者消费回收。CPU/device 组即使成员相同也不能合并身份；CPU/设备分类依据原生声明的进程组职责；无设备控制用 CPU 张量及 Gloo 承载设备元数据，不改变其原生执行类别，也不能因此切出额外 CPU 通信动作。singleton 与空 Gloo 归约不引入屏障，广播保留根依赖。沿插桩安装顺序、调用上下文所有权、来源解释、模板绑定与执行连接整体联查；旧来源缺少该切口时不补写事实。新来源验证需同时核对原始通信声明、图中端口与目标实际依赖，阻塞墙钟不当作纯服务时间。
2. 沿 _pp_launch_batch、代理张量发送/接收、输出准备/转发、结果处理和 _pp_commit_comm_work 确定动作边界。父动作内的 run_batch 只作为子调用，不能重复提交模型图；不同微批次的工作身份和缓冲绑定分别维护。
3. 区分调用返回、设备完成及后续等待。异步工作返回可引用的具名完成边界；来源记录真实事件的记录/等待位置，模板只保留 signal 端口名及局部位置，目标按原生句柄代次重绑定。CPU 等待控制调用返回，stream 等待只控制相应设备流继续；原生 Event/Work 的等待按这一语义连接核心中的对应完成位置。设备尾部可以晚于调用返回，不能把所有发送改成阻塞，也不能让 CPU 占位 Event 永远就绪。无设备后端只保留原生控制需要的元数据和视图。
4. 来源观察同时提供发送/接收参与者、消息类型及字段、实际 shape、发送缓冲与异步句柄生命周期。实际发送切片的形状在原生切分之后取得；Work.wait 通过事件代次、原生 API 和提交归属连接到对应通信结束记录，不把调用返回或新插入观察事件当作完成。缓冲读写区间持续到通信完成，接收输出在该位置发布。共同模板/执行层按端口及目标身份连接，必要的跨动作信号不能残留为来源事件编号；先补齐共同完成/依赖合同，再恢复各原生钩子，不维护第二套 PP 步骤状态机。观察包装必须保留原生方法签名及能力探测语义；代理字典中的张量字段与协议元数据分别交接，不能将消息类型当作张量端口。原生字典收发中的字段、视图及 receive 后的 TP all-gather 需要完整交接，单个 isend/irecv 可观察不等于组合收发成立。独立聚合以实际输入维度为参数，dtype、聚合轴和参与者作为候选条件；输出布局通过模板查询取得，原生接收保留最终 reshape。区分调用前已有接收缓冲与动作内部新分配，不能将内部临时分配当作外部覆盖绑定。
5. 首/中/尾 stage 的输入、输出、局部 KV 与等价 TP worker 各自绑定。非尾级的中间张量字段和形状来自模型实际输出及模板，控制端通过共同动作接口只读取得布局、构造无设备元数据视图；不按模型名猜输出，也不另写 Python 形状求值规则。查询与实际展开使用同一候选和参数约束，不消费资源变更或推进时间。动作返回交付实例图中具名输出的存储身份和版本，适配器以弱存储引用关联原生张量及其视图；下一动作显式传入根端口绑定，子调用别名由核心统一解析。返回引用与设备就绪分别处理，新接收缓冲的分配也不能误用旧批次字段或按调用点常驻复用。输出绕回首级再逐级转发、部分 prefill 跳过输出通信，以及原生微批次轮转均保留。关闭流程先排空，再让各参与者退出，不能在首级收到停止标记后留下下游阻塞接收。
6. 静态联查上述完整链路、空轮转、滞后输出、未完成传输、原生退出及有限内存后，再集中构建和取得最小 PP3 证据。之后以 TP2×PP3 等必要组合检查角色和非均匀层分配；完整范围仍在后续独立矩阵中覆盖。单独元数据通道可用不算 PP 完成。采集关闭须等待全部被采集 worker 完成原子发布，不能用入口 worker 的 stop_profile 回复代替整条流水线的 profiler 收尾。

PP 的输出交接覆盖正常 output_prepare、部分 prefill 的 output_skip，以及独立 Event.record/Event.wait/Stream.wait_stream。父动作内的等待随父模板展开，父动作外的流间等待使用实际原生 stream 职责选择模板，不能依赖 torch.cpu 的空实现。控制侧的 workload token 值只供原生请求记账；它们与接收值保留同一图引用，不能成为提前跳过设备就绪的依据。各动作自行声明候选条件，公共提交方法不累计动作名称分支。

采集与无设备控制共用 serving 活动边界：生成请求开启活动区间，原生整轮循环的完全空闲结束逻辑活动；管理命令不能重新开启区间。采集关闭请求只申请排空，在原生 on_idle 处确认通信和设备排空后关闭记录，再允许清缓存。输入分发中的 flush 就绪检查只查询已完成的排空状态，不能在 PP 微批次轮转中途截断来源；不能通过忽略目标末尾调用弥补来源窗口不完整。

采集与无设备控制共用原生调用切口：队列推进、预分配、转移提交、prebuilt 准备/首 token 结果及 Prefill inflight 收尾。共同 adapter 只组织调用边界和参数，不复制原生队列决策。内部独立选择先暂停父片段再提交，保持一次工作只展开一次；片段条件包含实际 filter/merge 路径。安装原生钩子时，同一目标的资源和语义钩子须先全部注册再应用，不能依赖原生注册表对已修改目标重复安装。Prefill 本地响应仍保留图工作，但不能重复发布 Decode 的用户输出。

选批与相邻队列按完整控制链收敛，不能每遇到一个相邻调用组合就补一个模板。实施顺序是：统一批次输出 ABI 与原生张量身份交接 → 分离实际批次变换和同步 → 核对父方法剩余作用 → 声明并证明纯 CPU 剩余片段 → 一次必要新来源。下表是职责划分，不是逐函数补采清单：

| 原生行为 | 图与控制的分工 |
| --- | --- |
| selection / prebuilt_prepare 生成批次字段 | 采集声明端口；核心返回值身份；控制绑定到真实原生张量的弱引用，供后续动作消费 |
| 父控制片段中的 filter / merge | 共用 batch_transform 合同；输入保留左右批次，输出按原生结果定形。空/不变提前返回不虚构张量读写；selection 与 PD 父片段采用相同的暂停/恢复交接，不再保留整次 selection 的第二份图工作 |
| maybe_prepare_mlp_sync_batch / prepare_mlp_sync_batch | 前者继续作原生决定，后者在分段父调用内作为 batch_sync 子调用交接；保留 collective、设备到主机读取及必要 idle batch。selection 也沿相同切口提交，不复制原生判定条件或同步工作 |
| prebuilt_admit / Decode 选批 / Prefill 选批 | 逐条核对真实分配、准备、缓存、发布和同步子调用；仅所有外部作用已独立交接后，才能共享剩余 CPU 控制结构 |
| Decode 回退恢复、Prefill chunk/bootstrap/收尾 | 恢复中的 KV 装载、chunk 的筛选/传输、失败清理和发布分别核对；不能因简单来源没有触发而将整个队列声明成纯 CPU |

selection 本身采用调用包络，选批策略继续执行原生代码；缓存匹配/请求缓存处理、批次准备、filter/merge/mix 和必要同步按实际作用交接，父方法只承接剩余工作。逐请求调用次数来自原生循环，不能将整条 selection_path 的组合枚举作为共享模板身份。batch 准备前读取旧槽位/长度身份，返回时交付新长度/位置及原地更新版本；成员、phase 和形状由对应调用的真实输入输出取得，不能把选批最终状态倒填给先前所有片段。缓存实际接口可能包含设备 cat/索引等工作，不能把“缓存由核心管理”等同于这些方法没有执行工作。先完成共同 adapter、采集、模板入口、控制交接及引用的整链修改，再取得一次有明确机制范围的新来源；旧记录仅保留历史证据，不兼容回退。

模型内部重复与上述控制重复分开：固定模型的层位置和连接来自真实模块结构，定义可以共享，权重/KV/张量绑定仍独立；若要改变子调用数量，须有明确的层/成员关系及首尾连接依据，不从观察到几个相同 child 推断任意循环。这项能力不能由选批拆分通过替代。

按变化来源分别闭合：固定模型的层循环取原生 start/end 与模块位置，目标 workload 不改变层数；逐请求资源/发布调用由原生控制在目标运行中组织；模型内部条件调用则由 adapter 声明实际分支条件，核心按条件选择具有完整端口和别名关系的子树。不得把三者混成一个按观察次数外推的 repeat 规则。先检查空输入导致的 attention 调用省略及专家接收空/非空分支，核对条件是否能从目标参数求出、是否附在拥有该分支的层、候选连接是否完整；不能只看某个叶子 kernel 缺失。固定调用树内局部选择与调用数量变化分别报告，后者未接通前不授予泛化资格。

子调用数量变化取证前，先沿原生分支确认允许的配置和请求确实改变已选语义 scope 的数量，并明确分支所有者及目标可求的条件。内部工作为空、固定层数不同和逐请求控制调用次数不同各自记录，不能代替这项证据；未找到可达分支时保留待验证状态，不靠重复采集或人为增加细分 scope 凑覆盖。

将代码交接审查与真实分支覆盖分别记录：前者检查条件生产、参数传递、候选接口、父子连接和实例化是否闭合；后者要求所选支持域内实际可达的来源。不能因尚无可达来源就反复重写已成立的公共机制，也不能用静态审查宣称取得运行资格。对已确认不触发该分支的域停止同类采集，后续选定不同合法模型或机制时再按原生代码判断是否需要这项证据。

跨调用可写缓冲区的身份须有明确来源：原生常驻字段及其别名由 adapter 声明，临时值沿实际张量存储交接，核心据此维护版本和在途依赖。动作切分前后保留判断分配归属所需的信息；调用位置和端口名不能单独证明存储常驻，也不能将所有未绑定写入都改成逐次新分配。沿原生分配、来源切分、模板绑定、目标值交接和资源回收完成整链后，再进行必要运行复核。

层 shape 关系与采集前 worker 等价判断共用原生 LayerCommunicator 描述，包括分片模式、组宽、实际选中的通信函数和影响层边界的标志。rank 位置与可变缓存不进入这份静态描述；不能仅比较模块类和权重 shape，就忽略 native 对该层选择的通信行为。该描述归框架 adapter，不给核心增加模型名或通信函数分支。


实际变换由原生函数执行，adapter 只读取前后 ABI 与实际分支。批次的槽位、长度、位置字段采用共同定义；请求持久内容仍由槽位字段管理。新切口必须同时更新来源生产、模板动作入口、控制侧值绑定和调用方；旧 trace 没有的边界不从结果倒推补写。

批次变换的来源按有限机制统一规划：筛选的 empty/unchanged/subset、两个存活批次的 merge，以及下一批准备的原地长度更新与新 KV 位置。部分筛选和合并生成新槽位/长度张量，旧 cache_locations 被清空，不能把它们当作无设备工作的成员列表修改。来源应通过正常请求生命周期形成持续运行批次、后续准入及先后完成；预先给出有限请求与采集预算，再从实际记录核对触发范围。仅有空/不变筛选的来源不证明 subset/merge；没有观察到的设备作用不能由 CPU 空片段替代，也不能为凑覆盖修改原生组批或伪造图。拆分 selection 时逐项保留变换、批次准备及同步的对外端口，不能因函数相同就直接搬用旧完整父动作。覆盖核对与实验编排放在 example/运行证据，不为某个实验增加核心分支。

必要张量的创建、原地写入和别名在 runtime 层区分，来源必须能说明每个对外值的生产者。工厂创建入口即使以别名形式通过 dispatcher，也不能被误判为调用前已经存在的输入；修正该观察语义后使用新来源，不在离线模板中猜写生产者。

动作身份、工作成员与输入参数取自对应调用；批次、值和完成信号的存活集合则在每次动作提交时统一读取。父片段暂停后，子调用可以新建或释放批次，父片段恢复不得用进入时的存活快照回收子调用已发布的绑定。使用原生弱引用和现有唯一身份所有者，不增加平行资源账本。

跨参与者完成查询和图输入必须解析到同一个生产事件，回收汇总所有参与者的存活引用；backend 负责交接期间的句柄所有权，不能让发送方释放尚未交付的完成引用。传输服务可并行，其 KV 访问仍须有明确、连通的起止区间。首 token 不止经过 metadata gate：还需跟踪原生 prebuilt 写入 FutureMap、后续 Decode 按请求槽位取出的数据关系；批次对象变化不能切断请求对应的持久内容，不能用传输成功布尔值或整批返回代替这条关系。

FutureMap 通过请求槽位字段读写承接：共用 stash/resolve 观察，绑定实际索引对象及原生请求成员；模板保留字段、访问区间与成员绑定名，核心使用既有槽位所有权连接内容依赖和复用约束。覆盖普通批次、混合组批的 Decode 子集、PP 输出准备及 PD prebuilt，不能只补 PD 特例。原生实际读/写路径同时进入候选选择和布局查询；旧来源缺该事实时不补写空访问宣称覆盖。首 token 元数据沿同一请求字段合同表达 set_buf → send_aux → get_buf，候选条件统一记录实际字段读写。物理搬运须核对双方注册的完整元数据行、实际请求/房间/行号预约和实际传输地址；不能只观察 send_aux 的返回值或给目标猜一个首 token。多份内部元数据张量作为一个逻辑内容交接，不为每个标量新增图类别。该抽象须保持原生搬运完成后源端释放、拷贝读取后接收行回收的生命周期；跨批次 slot 依赖不能替代原生 metadata gate 和无设备后端的实际内容交接。

1. **实例与请求交接。** 同一 workload 请求同时提交到 P/D 原生入口，bootstrap room 只标识本次请求，不用到达顺序配对；原生 TP/PP 局部 rank 与跨实例图参与者身份分别交接，不能把两侧的 rank0 当作同一通信端点；预热与来源使用不重叠的身份。正式采集任务统一声明 model、instances、workload 和 observe_all_workers；普通 serving 为一个 null 实例，PD 为一对 prefill/decode 实例，每项仅有 id、mode、configuration。任务按实例顺序分配全局 rank 和连续可见设备区间，各实例的采集描述只携带自己的配置，EP 路由与模型观察不解析整个 PD 拓扑。每个 Engine 在独立进程中初始化和退出，身份与共同到达时钟由任务交接；两侧请求使用相同非零 bootstrap room，预热和来源 room 不重叠。全部实例预热并 reset 后开始 profiler，全部 profiler 就绪后发布来源时钟；关闭窗口按实例隔离，不能由较快的 P 侧提前关闭仍接收请求的 D 侧。全部实例排空后关闭 profiler，全部 Engine 正常退出后发布任务结果；失败清理本次拥有的进程组。真实采集须覆盖两个实例的统一预热、逻辑 reset、profiler 全角色关闭与退出，不能只等待 Prefill 返回。
2. **原生准入和组批。** 保留 PrefillBootstrapQueue、DecodePreallocQueue、DecodeTransferQueue 及原生普通/PP 循环。Decode 的 `_pre_alloc` 在成批之前分配槽位和页，分配需求在该真实调用边界交接；不能依赖只覆盖 `alloc_for_extend/decode` 的批次包装。槽位绑定须使用该次调用的 prefix 参数，不能读尚未更新的请求字段；暂态调用参数在返回或异常时释放，不能变成第二份资源账本。Prefill 的选择、Decode 的队列推进和选择，以及传输完成后的源端收尾分别取得动作边界；它们不全部经过普通 `get_next_batch_to_run/process_batch_result`。Decode 的 prebuilt 是已接收首个 token 的准入/结果处理，不能伪造一次模型 Prefill 计算。
3. **资源内容与分片。** 核心保持两个池的独立所有权；一次传输声明源/目的实例、层、页/token 区间和必要 head/字节子范围。源读必须等待已计算的内容，目的写必须保护旧内容的在途访问，并在实际完成后供 Decode 使用。不同 TP 下一个目的页可能由多个源补齐，不能首个分片到达就把整页标为可读。原生 `CommonKVManager._resolve_rank_mapping`、`AscendKVManager.send_kvcache` 和 `MooncakeKVManager.send_kvcache_slice` 分别提供参与者、PP 层和 TP head 切片依据；采集解释把实际地址块转成统一资源区域，核心不复制这些算法，也不接受裸设备地址作为跨运行身份。目标执行只复用原生 rank 映射并核对伙伴布局与采集域一致，模板负责已捕获的层/head 切片和动态请求范围；不另运行一套地址重演来重复模板已包含的几何。原生 KV 池构造完成时记录实际层范围、head 数、KV dtype 和 K/V 每 token 字节宽度，不等 attention 执行后才获取；Decode 可能只接收首 token 而没有模型调用。控制给原生初始化提供无设备池视图；地址坐标不参与目标图身份或独立真值。来源解释合并异构 TP 的逐 token 连续片段。TP/PP 或目标池布局改变时须取得对应传输域来源，不能把这一约束藏成容量变换规则。整页传输量包含尾页未使用空间，但内容就绪约束只取请求实际有效范围，不能把 padding 当作必须先写入的逻辑 KV。原生 PP 层切片若误选 draft 分支导致跨层地址不一致，保留上游证据与不支持结论，不 clamp 地址或加模型特例。相同 page_size、KV dtype 及原生可运行拓扑是来源域条件，不能擅自支持上游拒绝的组合。
4. **传输 backend 与虚拟时间。** 无设备适配以原生 BaseKVManager/BaseKVSender/BaseKVReceiver 接口为边界；保留原生 scheduler 的 bootstrap、预分配、传输队列及首 token 准入，复用 CommonKVSender 的分块/末块规则及原生参与者映射，通过已观察传输域的模板向核心提交搬运。物理 backend 的后台线程、socket 和传输引擎不直接搬入无设备控制器；不能为保留它们而另建多线程收发、网络模拟和第二套队列状态机。按真实搬运机制决定图边界：单边写入由同一次传输声明源池读取和目的池分片写入，不能为了满足双端通道形式虚构目的端接收调用；原生确有双端提交时才使用两端通信端口。模板保存池的语义绑定名，目标调用绑定到实际资源所有者，图依赖构建直接使用这些所有者的唯一内容状态，不复制跨池账本。页归还在资源操作返回时使旧内容失效，并保留在途访问依赖，不能延迟到该池下一动作而清掉期间远端写入的新内容。通道由适配器绑定完整路线，不能在两端各自再加不同实例前缀。传输载荷可以仅提供布局元数据，实际内容依赖由显式 KV 区间承担，不能假造临时 Tensor storage 来代替 KV。原生 poll 仅翻译核心在途传输的实际状态；末块 KV、辅助元数据和参与者完成数分别满足后才报告成功。提交、调用返回、完成和轮询可见性分开，不能阻塞整个 scheduler 等传输，也不能使用 FAKE backend 的立即成功。来源须区分 scheduler 的 sender.send 入队返回与后台搬运函数返回：后者可能同步等待，不能直接替换前者作为调度动作的 call.return。后台子工作按真实入队任务归属到提交动作，保留原生入队因果及后台执行资源，不能凭时间邻近附到 scheduler，也不能为图表示方便把后台传输强行同步化。入队片段与后台服务分别记录；服务边界使用实际同步搬运 API 的起止及 SDK 时钟转换，不依赖后台线程继承 Torch profiler 回调。服务等待不再重复计入 CPU 工作。地址观察在实际 transport engine 提交点完成，覆盖直接调用引擎的异构 TP 分片；用两端真实注册缓冲及实际页列表解释逻辑区域，不能由源端猜测目的端布局。每个参与者都发布小型 KV 注册事实，与是否采集其完整计算 trace 分开，代表 worker 策略不能使远端池证据消失。模板只保留归一化区域及具名完成端口，原始地址仅用于来源解释。原生轮询通过具名完成边界读取执行器状态；未完成查询仅登记等待通知，在真实事件完成后开放原生下一轮接收，不能只靠 CPU 动作返回唤醒，也不能在虚拟时间不前进时无限空轮询。原生轮询/超时须有明确模拟时钟归属；若某项必要原生逻辑确实只能在后台执行，先补可见等待协议，不允许线程共用 WorkerPeer 或宿主线程运行快慢决定模拟结果。先接通这条职责链和退出，再启用 PD 控制入口。
5. **首 token 与资源收尾。** Decode 的资源预分配与接收处理按原生阶段分别进入共同调用切片，不能将本轮是否接收到数据绑定到预分配后的同一 continuation。接收处理中的就绪标记读取、metadata 提交和行清零分别保留原生调用及重复：观察只针对已知缓冲和实际请求行，不拦截全部标量运算，不重写原生轮询/准入谓词；采集和无设备控制共用这一语义边界。粗图中的内部 read/write 仍访问同一个请求字段，不增加逐标量模板或核心框架分支。来源没有这些切口时不能从现有等待数量猜造，先静态完成整条链再安排必要来源。原生 MetadataBuffers 交接首个 token、缓存计数和 bootstrap room；目标 metadata gate 仍由原生检查，不能只设置 KVPoll.Success 而绕过内容就绪。Decode 接收、准入后通过 prebuilt 处理首 token；Prefill 只有原生 inflight 队列确认传输完成才释放源 KV 和 metadata 槽位。区分 P/D 本地完成与对外 token 发布，避免重复首 token、提前源页复用和一侧退出留下另一侧等待。
Decode 预约发布单独进入共同调用边界：前序页索引导出及同步片段必须先返回，随后才向 Prefill 发布可写页和 metadata 行，不能在父片段尚未进入执行器时提前发送。

无设备后端以现有 worker broker 交接预约、完成句柄、元数据及消费确认；该通道只传原生协议值，不修改核心就绪。发送方在入队图已提交后发布句柄，接收方按核心完成查询处理所有必需源及分块，完成前不改写原生 MetadataBuffers。完成后仍运行原生 metadata gate、prebuilt 和后续组批。源端资源释放与句柄保留分开：发布者持有未确认的引用，接收方不再查询后确认消费，不能把等待确认额外加成 Prefill 资源释放的条件。多源向同一 metadata 行发布时，须核对内容一致性及真实写入/完成汇合关系，不能将未取证的串行假设当作已验证结构。

6. **粗图来源和评价。** 捕获真实页/层/head 范围、传输提交/完成及 metadata 因果；原生 transport 的同步调用可能包含等待，不能把整段墙钟同时记作 CPU 服务和传输成本。传输线程不在 scheduler 的 Python 父调用上下文内，必须用真实任务/请求身份和发布关系连接，不能靠最近时间嵌回父图。原生转移的首 token/元数据、源端释放和目标端首次 KV 读取构成独立对照边界；来源与目标分别生成这些事实，不用预测的地址映射反填真值。
7. **必要证据与收口。** 先收口一条 P/D 双实例的完整实现，再以一次合法最小来源检查真实 transport 事实；同一来源离线解释，不因缺字段立即补采。随后检查同/异 TP、PP×PD、EP×PD 的参与者、切片及完成计数；最终范围仍由全量矩阵独立判定。零新增 token、部分页、prefix 命中、分块发送和输出长度一的首 token 结束分别做静态链路审查，不能以 TP1 双实例运行成功替代组合交付。

同步传输以实际 engine 调用为执行边界：队列创建/释放和提交记录证明资源身份，显式服务身份穿过原生线程池；服务完成证明内部工作已结束。框架层提供源/目的数据范围，runtime 层解释私有队列，核心只消费共同工作、资源和端口。外层排队/汇合与内层实际搬运分别表达，不将整个外层墙钟和内部任务重复计费。只有已证实队列归属、调用闭合且没有外部操作穿入的工作才可封装；同队列的执行次序保留为资源约束。任务名、数量相等和时间邻近都不能替代归属证据，缺少必需原始事实时不能在旧记录中补造。

SDK 格式或设备事件对应不能从安装源码确定时，允许在采集模块静态收口并重建镜像后，取得一份有界的原生格式证据；它不属于 S2 验收，也不要求尚未接通的目标展开先完成。解释代码的修改复用同一记录，不因后处理失败重跑模型；每次尝试先声明所缺事实、范围及累计额度。

配置集合先作为固定模型、具名完整实例配置集合和具名 workload 集合解析。域划分结果保留配置→域与 workload 两个维度，避免展开重复输入文件；域划分报告不能冒充代表请求已选定或采集已排程。请求标量与未知字段在采集/预测共用输入边界核对，提交原生请求时只执行交付，不再次解释一套输入规则。配置集合规划与预测装配共用来源域规则：先区分完整 serving 拓扑与机制，再在同域内安排代表来源。PD 的两端及其远端职责来自同一次原生任务，不能先拆成局部配置再从不同任务拼回一对。模型/dtype、各端 TP/PP/EP、backend、页、缓存和 chunk/mixed 机制区分来源；容量、chunk 长度与请求条件不被当作新的域身份。同域仅表示候选来源可进入模板匹配，不宣称全部动态分支已覆盖；代表请求选择须说明实际触发机制及有限结束条件，不能凭最大长度或最多请求直接赋予覆盖资格。

代表来源规划先产出一个可执行的初始候选：SGLang 适配层从原配置/workload 识别声明输入的流程机会，在配置与兼容补齐条件组内选择提供新条件的 workload，移除条件已被保留输入覆盖的整组冗余输入，再比较逻辑 token 总量、到达等待及容量；公共规划只负责域分组、候选交接和发布。互补 workload 以同一 Engine 内的有限提交组交接，用完整命名空间重绑定请求、前缀和路由引用，保留组内到达、共享前缀和原始专家选择；探针长度与路由区间由来源适配器按明确边界转换，目标 workload 不改写。分组必须完整且不重复地覆盖源请求，PD 两端均完成本组响应后才进入下一组；源观察使用一个全局时间原点，组内计划与实际提交偏移分别记录。原生资源与缓存不在组间重置，不宣称各组从独立空态开始。该采集编排不能替代轻量探针生成或已观察机制覆盖。EP padding 不同的候选分组评估，不因先选一组而遗漏另一组可满足的组合，不覆盖冲突值或猜区间等价。

准入与合并探针按本次目标集合需要的机制设计，不为未启用机制扩大采集。SGLang 的准入同时读取微批容量、当前可用请求槽位、KV 余量、prefill/chunk 预算及实际缓存命中；ignore_eos 分支还按存活请求的剩余输出检查余量。保留到达时间或输入 token 总量不能证明这些原生状态相同，不能在外围复制 PrefillAdder 或调度器来承诺组批。实际是否出现等待准入、subset、merge、mix 和缓存命中，由已有批次变换、请求进度和资源事实分别取证；未出现时保留未观察范围，不把未包含输入条件为空视为模板覆盖完成。普通多组交接的有界运行与这些机制资格分开，公开简单示例成功不能替代联合机制及独立目标验证。

请求缩短统一按边界约束求最小长度：完整前缀和私有后缀、首次跨页/跨 chunk、页与 chunk 余数、相等和不同的长度分组、输出长度分组间的继续迭代，以及所有 EP 路由内部转折。保留原生需要的专家选择，路由只按删除的同质尾部平移；非法间隙或重叠不能被消去。不能以任意 token 上限替代这些约束，无法缩短的原长度直接计入开销。独立持续 Decode 生命周期从已有合法请求复制，不延长、不猜造路由，每域至多一组；先给出实际输入成本，不能承诺每份短输入都更便宜。

缓存复用须安排生产者完成后的消费者，不能把同批共享前缀当作命中证明。从选中输入的可复用整页前缀中安排连续单请求组，复用已有末组及独立 Decode 生命周期，最多追加两个前缀请求；消费者的可匹配长度按原生保留最后执行 token 的规则判断。沿请求交付、原生缓存返回及粗图端口核对实际命中与来源选择，配置启用、输入共享和观察命中分开表述。该有界提交安排不重置缓存、不维护另一套缓存状态，也不因此追加原生会话。

报告同时交付采集输入、成本依据和未包含条件，明确这些条件不是原生分支覆盖证明，也不是全局最小集合。删除整组冗余输入与截短单请求是不同问题：仅凭 prefill/decode 等机会标签，不能证明删掉长期存活请求后仍会发生 subset/merge，或缩短 token 后仍覆盖路由/形状分支。完整交付仍须据明确机制生成轻量探针并核对实际触发，不以任意长度上限、单请求删除或标签相同冒充完成；不能停留在选出原 workload，也不能遇到缺条件就自动追加采集。 探针设计以请求生命周期为单位，区分继续 Decode 但无请求完成、部分完成、全部完成、等待准入与存活批次合并、chunk 继续及缓存复用；这些是设计责任，不是逐操作新增采集标签。先追踪原生判断条件及共用插桩的外部作用，再同时安排有限的请求、组批压力、长度与提交关系。输入机会集合相同或合并后包含全部请求，均不能证明原工作流路径仍可达；来源输入与实际观察必须分别说明，目标输入保持原样。EP 不能凭截短或延长请求猜造新路由，PP/PD 不能用单 worker 的完成顺序替代各端行为。完成这一整条设计和代码替换后再取一次有界来源，不从单个缺候选出发逐条补 workload。

有限集合执行复用单任务采集及生产，不复制其容器、计费或恢复状态机。首次启动前核对全部来源输入、域、设备需求、模型路径与程序，固定部署和镜像；每次只运行计划内任务，第一处失败停止。总用量直接来自子任务预留及结算记录，失败、恢复和显式增加额度均不清零。恢复先清理中断操作，再为新操作检查存储，已成功的来源不因后处理失败重采；逻辑字节轮询只能作为监测上限，不宣称文件系统硬配额。全集合发布以所有域生产完成并匹配为条件，来源编译完成与实际机制覆盖仍分别记录。

一键示例只编排来源规划、有限集合和配置×workload 的目标预测，使用同一运行根、固定镜像与程序，目标匹配仍交给正式装配。默认输出简短摘要和结果索引，完整明细在生产前显式开启；只有全部目标成功才发布总结果，失败保留本次事实与子任务恢复入口，不自动重试或补采。示例真实闭环与集合真实执行合并取证，不为编排入口另增重复采集；它不承担独立评价或性能资格。

原生采集由外围应用启动单次显式任务：共同输入描述模型、实例与请求，部署 adapter 描述物理设备和传输环境；固定镜像 ID、只读模型、任务输出、累计单调额度和专属容器清理属于应用。一次明确调用最多启动一个原生尝试，原生容器自身也执行期限，不依赖协调进程存活；同任务恢复核对输入与部署，不重置已花时间及次数。协调进程中断后先检查保留容器的退出证据、清理专属资源；正常结束的完整来源直接继续发布，未知用时保守计入预留额度。成功退出并取得闭合来源后才发布结果，失败保留原始事实，不隐式循环重启 Engine。代表复用减少观察而非原生协议所需设备。配置集合规划负责把这些单次任务组织成有限来源集合，统一累计失败、重试、后处理和存储额度；不能把单次启动器当作集合规划。代表等价比较保留原生已选通信函数和其预绑定的散布模式，不能只比较函数名或按物理 rank 划分。

5. 采集阶段发布、角色事实闭合、会话管理成功和进程退出分别判断。失败不发布成功资产，已闭合事实可沿同一任务离线处理；截止和资源清理由明确所有者维护，不用隐藏重试重新运行原生。 容器自动删除与 Docker 清理失败分别处理；无法确认本次资源清理时不清空待恢复状态、不发布预测成功结果，不能忽略删除命令的错误。
6. 目标执行明细由实际实例化和执行连接点增量产出：保留子图端口/参数、局部到执行事件身份、实际依赖及完成时刻；动态资源复用、通信汇合和等待必须来自执行器实际使用的关系，不能由评价端根据模板猜补。明细默认关闭，不为取证让核心常驻全历史，失败部分与完整发布分开。执行编号只在本次运行中连接事件，不成为真实/预测跨运行匹配依据。状态操作历史与执行依赖分别取自各自实际所有者：资源服务记录操作输入、返回值及已交接的页/槽位失效；记录器只观察，不重新分配、不维护第二份常驻状态。真实侧须观察原生池和缓存操作，不能由模板或模拟器重新执行得到“真值”。观察挂接实际创建的池/缓存对象，初态在统一预热和 flush 后取得，终态在下一次 flush 前取得；仅在明确取证时保留不可变索引快照并于窗口排空后读回，不为每次资源操作同步设备。槽位/页的实际返回值、缓存匹配/插入/引用变化及请求的前缀绑定分别核对；只有容量计数一致不足以证明绑定正确。请求与物理 KV 页的关系在批次实际消费映射的共同边界读取原生表，PD 无模型调用的 prebuilt 准备结束亦保留该证据；核心从图访问时真正解析的物理范围记录，不靠“最近一次 cache match”或重新执行分配算法猜配，不为缓存内部每个分支单独补规则。两端以请求逻辑区间及有序页内范围表达，跨层重复访问只记录一份绑定；原生全序列与目标局部区间按共同工作身份比较，不能按物理页号或记录位置硬配。请求索引须有明确输入身份映射，物理页号只在本池的分配/复用生命周期内解释。真实时间旁路单独实现，操作明细存在不能代替时间对齐。
   原生控制在每个实际动作返回时通过可选明细记录请求进度与发布结果，包括空结果。独立评价用来源的实际 effects/publication 核对目标返回，检查 worker、返回事件、完成时刻和请求身份；这些结果不进入模板分类，也不由来源模板复制到预测。Prefill 传输确认与 Decode 用户输出分别解释。图内容一致不能代替控制结果一致；重复动作的结果覆盖与逐次时间对应分开报告，尚未配对的非空结果不得作为无作用轮询忽略。
   来源证据单独保留粗图事件到原生坐标、工作到原生片段的对应，由 runtime 提供实测时间；顺序号不当作纳秒，未测得的逻辑等待保留未知。源时钟证据与模板身份分开，既有因果边与实测时间矛盾时先定位原生关联、时钟及完成语义，不能平移时间、填零或删除依赖求通过。 来源独立检查放在 example：实际几何/依赖的映射一致与时间因果一致分别报告；未知时间保持未测得，单 rank 材料错误不中止其他 rank。符号表达式归一化不是该项实际证据检查的对象，模板泛化另行验证。默认精简报告，完整问题位置由明确选项输出；检查器先取得端口错接、无来源依赖和测量改写的负例证据，不能将工具未发现问题等同于全链路正确。旁路只使用已核对的决策边界时间，观察窗口不自动等于请求到达原点。 单机来源投递原点、入口与各 worker 的接收轮次使用同一 RAW 单调时钟，profiler 主机/设备测量分别按对应 SDK 导出锚点转换；逐条 dispatch 时间不能冒充接收轮次。入口在广播之前记录，各 worker 的广播/PP 转发接收另行观察，不通过入口时刻强制所有 worker 同时就绪。模板来源可代表采集，独立时间对照须取每个实际参与者，不能把代表时间复制给等价角色。

   交付层按实际请求成员维护可用性，不假设交付的是输入列表前 N 项；实测入口轮次和动作时间使用同一时间文档、分别作用于输入交付和图边界。默认到达与实测交付共用状态所有者，轮询较晚时记录实际交付，独立比较仍须核对该差异；接收成员不是执行批次。

   执行层接收已匹配调用的局部边界及绝对模拟纳秒，严格保留原依赖；前驱使边界迟于给定时刻时报告冲突，不能自动平移或删边。执行器不负责按源/目标事件编号配对。

   serving 时间输入以参与者、动作、参数及共同工作上下文匹配记录，再按当前动作根作用域的端口名定位边界；记录顺序不参与匹配。每个身份明确来源调用次数：仅动作的完整工作身份（含全部调用者上下文及继续位置）在来源唯一、且没有重复祖先调用时提供实测端口；其余显式提供空边界并保留目标实际执行和给定耗时，不按次数强配、不注入查询结果。删除仅针对纯 CPU 片段的计时特例；结构比较仍独立检查全部作用及依赖。时间输入是稀疏的性能旁路，不是控制动作白名单：未声明的目标身份正常展开、使用给定耗时，未出现的来源身份保留未配对计数，两者都标为 partial；唯一实测记录重复消费及端口别名时间冲突仍失败。完整身份在一次来源中唯一只是样本事实，不能证明可循环控制路径中的动作不可重复：不同rank在不同轮次观察到完成时，原生归约可能令条件子调用再次发生。重复祖先下的子调用保留时间未覆盖，不能把来源仅发生一次当作可消费一次绝对时刻的保证。旁路不会给未测量的CPU工作补上真实成本，因此不保证各rank在与来源相同的轮次查询；检查协议状态、归约及结构作用时须与逐次时间资格分开，不因合法轮询差异补模板、修改完成通知或强行按轮次回放。未覆盖身份按来源/目标次数单列，整体时间覆盖标为 partial；部分诊断不能作为 S1 收口或独立验收通过的证据。时间文件不改变 workload 或资源状态，内部给定耗时与原生实测资格分别说明。缺少请求、进度或续执行身份时先补公共观察合同，不按全局序号或模板种类代替。

   来源中的局部唯一身份只提供候选对应，不能独立证明跨 rank 反馈时间可用。先按原生 envelope 的调用位置、参数和逻辑上下文检查祖先重复；重复父调用中的唯一子动作不自动分配实测时间，报告父调用重复范围，不通过细分模板类别或协议名称分支处理。原生组内归约的输入状态与共同结果可能随轮询节奏变化：一个 rank 的请求进度相同，其他参与者的就绪状态可以不同。完成反馈资格须沿实际读取、参与者输入、归约与后续准入检查共同因果；联合状态不同不消费同一实测返回时间。先明确必要事实及其来源，再统一调整观察、时间交接和评价，不为每种协议状态添加延迟分支，不按轮询序号对齐，也不把 partial 诊断当作闭合。

   重复片段的因果位置单独核对：以两边唯一对应动作的进入/返回边界为锚点，沿各自完整rank内图计算重复片段进入/返回的可达前驱与后继；按完整工作上下文比较所有位置的集合，既检查缺失位置也检查多出位置，不按次数或时间选取某个来源副本。跨越未命名事件的路径仍参与计算。没有共同锚点或来源上下文时保留未知；位置集合相同只授予该项rank内关系的证据，不配对查询值、资源作用、通信轮次或耗时，也不能用它为变化中的图内容挑选来源。逐次身份歧义与结构检查分别保留，未配对次数不是缺失子图数量，不要求靠伪造身份将计数归零。

   时间对应使用的工作身份与模板结构身份分别维护；补齐请求/进度或续执行上下文不能使相同 CPU 片段按请求或轮次产生新模板。 采集与控制共用请求进度读取，原生 ID 各自映射到 workload ID；选择保留队列/上轮/chunk 上下文，缓存保留实际请求或已知调用者上下文，批次保留成员进度，片段保留具名进入/退出边界及相邻子调用的请求上下文；嵌套调用保留真实调用者链及其进入位置，由共同调用层统一维护，不按重复现象逐个添加特例。批次变换须记录所有输入侧及结果成员，而非仅记录左侧进度和右侧数量；前置片段的输入快照不能被动作完成后的更新修改。它们先作为匹配证据，而非自动生成唯一键；重复状态和独立信号仍须结合真实因果，不按来源序号兜底。

   实测边界时钟须核对 API 返回单位与时钟域；不能把设备 Event 的微秒时间直接当作 profiler 的原始 syscnt。旁路先明确哪些原生控制/资源边界需要时间，以及这些边界是否已有直接 CPU 测量，不以完成所有底层设备时间校准作为前置条件。

   **状态读取的执行切口。** 在进入 S2 前，沿共同调用切分层统一处理原生 Event.query、PD poll 以及 metadata gate：先执行读取之前的 CPU 片段，再到达明确的非阻塞读取边界，由当前执行/资源状态回答，最后继续原生分支。不能先在原片段入口时刻读取，再把整段 CPU 工作提交给执行器；也不能为了对齐把查询改成等待生产者完成。读取身份使用信号生产者或请求及协议端点，轮询次数不进入模板分类和跨运行配对键。可选目标结果观察关联实际 query 返回事件，走只读交接，不能改变 worker 的逻辑调度顺序。独立评价先检查结果与图的归属、完整性和完成先后，再判断被查询对象及原生消费者的就绪条件。实际完成读取须携带所属 query 返回事件，并记录真正读取的信号、生产者事件、结果和时刻；同一模拟时刻按实际记录顺序判断完成与读取的先后。查询报告包含实际读取数量，event 查询核对单个信号返回值，并以原生事件代次和目标实际读取信号独立核对生产者，不能只比较布尔值；等待要求完成依赖，非阻塞查询不增加这条边。transport 的缓存和多信号短路保留原生语义，不由完成读取一致推定整个协议正确；不全局合并协议枚举值，也不拿不同 workload 的查询计数作对应。传输服务完成、协议通知和组内准入分别核对，不能用其中一个时间替代全部。首次成功读取只能给状态生效时间提供上界；服务结束至该次读取的间隔还包含未轮询时间，不能作为通知开销。先用实际读取区间核对服务就绪与状态是否矛盾，再决定缺少哪一类观察；不因没有测得独立通知时刻就制造固定延迟。独立参与者核对使用真实来源的 session 和末块传输建立每个请求的发送/目标组，再用目标图的 KV/元数据写作用与导出完成事件核对实际读取；不得只解析目标 signal 字符串或复用 adapter 的决策结果作为正确性依据。同一原生传输生命周期中，Success 由 poll 缓存为终态，之后的读取不得回退为等待；来源与目标分别按实际调用顺序检查合法状态及终态保持，不通过轮询次数配对。该检查不证明 Bootstrapping/WaitingForInput 的具体变化时刻，也不把多代传输对象当作同一生命周期。Success 包括缓存返回，均须满足完整发送组和末块元数据的完成前提；满足必要前提不自动证明协议通知和组内准入。目的组及所需回复数直接使用原生拓扑声明；发送端末块发布须持有完整请求的完成依赖，直到所有通知消费者接手或消费，不能因发送者提前清理而丢失信号。通知的必要独立工作沿既有服务/消息边界表达，不逐 socket 或轮询构造节点，也不以首次成功轮询时刻冒充真实通知到达。 原生仅在末块完成后发布的通知，不得在每个分块入队时提前交给对端。adapter 提交最终通知及整个发送组的完成依赖，broker 暂存元数据且立即释放发送调用；核心在全部真实事件完成后解除交付条件，broker 先入队再唤醒。接收者按原生发送组归并最终通知，不重复轮询已经满足的完成条件。独立评价核对一次最终发布覆盖该请求所有分块及末块元数据，并验证接收端 Success 不早于发布；这不替代真实通知传播的测量。 跨 rank 依赖汇总区分已验证的通信/通知协议与仍未解释的边；通知资格同时来自实际执行边、完成先后及独立原生参与者，未验证关系不能被整体通过状态掩盖。

   PD 轮询操作数检查覆盖 Prefill 与 Decode 的共同工具入口：按实际 pollers 顺序，将每个请求的本地读取、必要元数据 gate、组内 MIN 输入/输出连成一条值来源链。后一级归约消费前一级的实际输出，不重新使用原始本地读数；参与者还须对向量中的请求顺序达成一致。来源与目标各自核对，Decode 的一次性准入继续独立检查。它证明本次决策的操作数来源，不配对跨运行的轮询次数，不替代通知时间、查询合法性或外部作用比较。

   **预约发布与远端可见。** PD 的非终态反馈须覆盖 Decode 发布资源预约到 Prefill 取得完整预约这一条反向控制消息链，不能仅限定传输 Success 的时间。该链先作为一项完整功能收口，再取得新来源；具体交接如下：

   - 框架 adapter 从实际传输组确定每个请求所需预约发布者，保留页、前缀和元数据行的原生含义。原生提交参数已明确的预约编号与请求身份随 session 交给观察器，在 worker 启动前建立关联；后台接收可以早于本地协议对象创建，不能等元数据行分配后才记录就绪变化。映射取实际提交参数，预热与 source 编号不重叠；状态观察不依赖 profiler 已激活。
   - 采集区分原生预约发布边界、对端状态写入区间和之后的查询。发布可能发生在 enclosing CPU 调用返回前，不能默认用整个 `send_metadata` 返回作所有对端可见的前驱；须定位真实发布点或明确有依据的区间，沿现有 host/service 边界和信号表达，不展开成逐 socket 工作流。
   - 预约按实际 bootstrap 对端保留一个独立 CPU 发送动作及 RAW 调用区间，导出发送入口信号作为必要因果下界；它不声称精确的 socket 入队时刻，也不以发送返回限制可能提前发生的远端写入。对端身份取原生 endpoint/session，位置只表示原生 TP 顺序及逆 PP 顺序中的拓扑位置，不充当轮询编号。
   - 控制 adapter 声明同一消息的来源、目标、载荷及发布前提，复用核心现有通知依赖与时间区间接口；broker 负责交付和唤醒，原生队列仍决定准入。消息已排队、对端已取得完整预约、后续传输完成是不同的事实，不以消息包存在就证明有实测可见时刻，不在核心新增 PD 状态机。一次远端就绪通知由一个实际发布者登记，依赖该接收端的全部真实预约发送信号；登记者与通知接收者分别表示，通知生命周期仍归同一请求。载荷可提前排队，原生发送端只有收到完整预约就绪通知后才能使用；已到达状态沿原生单调更新保留，不被之后创建的协议对象覆盖。
   - 独立评价先由原生参与者和实际传输声明确定必要对端，再检查发布、状态变化、查询与组内归约的因果。不能将全部 rank 的最后返回误作每个端点的依赖，也不能从首次 WaitingForInput 或首次 Success 的查询时间拟合通知延迟。读取提供的区间与直接状态写入测量分别标明。按原生非失败状态的单调性统一核对就绪与成功阈值；同一次状态跨越的重叠观察取交集，区间不相容或状态先后矛盾时报错，不把并发观察误作多次状态转移。缺失的事实不在旧来源补写。
   - 静态核对生产者、端口、消息所有权、消费和回收的完整实现后统一构建；先复用已有事实，确需新来源时将预约与成功两类状态观察一次取齐。是否允许消去重复空转，须另由实际作用和依赖证明；本项不以减少重复次数作为完成条件，也不取消跨 rank 反馈及有限动态组合的交付要求。

   这一项按完整链路修改：共享 adapter 定义切口，采集保留实际读取区间与结果，控制侧在同名切口请求核心状态，图及模板表达该边界的实际工作、同步、具名对象和依赖。非阻塞针对被查询对象，不表示原生 API 必然无等待；例如标量读取的本地 stream 同步必须保留，不能把所有 query 约束为单段纯 CPU。状态仍由已有执行器和资源服务维护，不增加第二份协议状态机。窗口外层的轮询同样明确是否属于规定流程；不能用 `scope=0` 的记录代替已建模动作，或因为没有父片段就漏掉必要控制边界。原生的每 rank 查询、metadata gate 和随后归约分别保留语义，局部 Success 不等于整组准入。 无设备控制在原生未选出批次时，以原生最终归约结果判断是否等待外部变化；入口 rank 的本地就绪不能代表整组就绪。保留原生后续清理和实际消息/完成唤醒，不因空轮询自己的 CPU 片段返回而视作外部进展。

   重复查询验证检查的是读取对象、允许观察到的状态与之后的实际作用，不要求真实/模拟忙轮询次数一致，也不按出现序号分配真实时间。无唯一实测对应的查询不能通过删除其作用来获得纯 CPU 豁免。查询本身的执行时刻与查询对象的完成时刻分开；需要补充的原生事实先通过上述完整设计确定，再合并到一次有限来源中。旧来源不补写切口，不为每个重复身份增加分支。整链静态审查后统一构建，先复用已保留事实做校验，正式取证与全量独立验收仍分阶段进行。

   非失败传输状态按完整单调序列检查，不能只核对就绪和完成。未测量的中间转换保留未知时间上下界，全部真实读取共同约束其可行区间；不把求得的可行区间发布为实测时间。区间重叠本身不建立读取顺序；目标同一worker的实际返回顺序则必须保持状态不倒退，即使返回时间戳相同。此检查不要求两端轮询次数相等，也不替代准入归约、载荷或逐次时间资格。

   独立时间提取只消费完整真实案例及带测量的粗图，以动作返回与对外输出信号约束目标反馈，动作入口仍检查来源区间与因果；全部 worker 按实际身份取证，不用代表时间复制。接收轮次使用共同 workload 原点，逐 worker 广播后接收另存作对照。 发布前先沿完整来源 DAG 核对所有实际动作的入口、返回及导出完成信号时间，包含重复身份的每次调用和经过未测量节点的路径；来源前驱晚于后继时禁止发布旁路输入。来源因果检查通过后才按身份唯一性筛选可交给目标的时间，不能先排除重复调用再检查来源，也不能留到预测失败后才归因。设备内部未选时间与跨 rank 因果另保留资格。缺少上下文、反馈测量或证据矛盾时仅发布缺口报告；只有身份重复而事实有效时可发布 partial 时间输入，返回非零并显式保留未约束范围，不能称为全部反馈已实测；内部依赖/形状另行比较，不能以反馈时间可提取代替结构正确。
   独立信号对照统一覆盖原生设备点、异步 Work 和显式 scope/interval/side 边界，保留各自的来源身份，不以投影后信号名反推生产者，也不跳过新类型求通过。
   独立对照须把来源的语义池绑定和目标的实际资源所有者映射到同一逻辑身份，再比较访问几何与物理绑定；本地与远端池不能混用页表，不能仅按字符串差异判错，也不能删除池字段或添加案例别名求通过。无模型计算的 prebuilt 准备也可能有请求页表快照，需区分状态观察和真实图访问；证据缺失明确报告，不为对照凭空制造 KV 工作。

   example 完成真实粗图对照，给出工作、参数、依赖、状态及完成边界的差异定位。每次真实调用先按本次运行内的独立身份保存；逻辑身份仅用于之后的跨运行对应，不能直接作为来源或目标生产者字典的唯一键。结构键只负责共同内容及内部依赖归类；逐次对应须保留完整祖先工作上下文。收齐两侧缺失与重复信息后，只对两侧均唯一的完整工作身份建立一对一映射，使用对应的实际来源 scope，继续比较其内容、依赖、绑定和查询结果。跨动作顺序及外部生产者关系沿同一映射维护，不按结构键合并边界；结构不同样本仅在其完整身份唯一时比较，不能按预测相似性选择。结构对应资格和真实时间资格分开，不能因此给重复包络的子调用补上实测时间。重复读取及未配对依赖明确单列为未完成，不因一个歧义中止整份对照，也不按调用次数强配或视作已通过。目标未匹配调用保留实际写入和完整图关系，防止后续读取被错误关联到更早的已配对生产者。合法空批次由采集/控制共用的插桩显式记录，不能由比较器把缺失上下文补成空值。删除旧逐底层配对评价和重复组装链，不保留“旧结果较好就回退”的入口。

删除范围包括被替代的整个源文件及类型、旧 CLI/配置、CMake target、Python 导入、安装资源、Docker COPY、脚本、示例和说明。确有新消费者的通用表达式、原生资源或协议能力才保留，不能勉强包一层继续使用旧流程；不移入新的活动 legacy 目录。

每轮先完成一个模块或一条完整功能链，静态核对所有调用方及跨语言合同后再集中构建、必要试跑。S1 收尾时普通入口只有新路径，旧构建/SDK/二进制已清理并重新生成；静态设计与操作说明按真实设计和实际入口对齐，不提前宣称新命令可用。

批次控制的原生分支与执行结构类别分开：请求成员和逻辑进度由原生控制维护，模板按真实设备/资源/张量作用归一化。多个提前返回分支如均只产生 CPU 工作，可在来源完整性及端口检查后共享结构，但成员变化、分支特征和耗时仍需保留；不得因缺候选直接套用另一个分支或通过扩大采集覆盖每种控制结果。 相邻调用名和逻辑进度用于动作对应，不自动等同于执行结构类别。若同一结构已在多个相邻控制位置出现而另一位置无候选，先审查原生片段的输入、设备/资源作用和出口合同，再统一调整候选分类；不能仅凭库内存在相似 CPU 图就回退选取，也不能逐标签添加入口。 固定 token 输出的结果处理以输入消费和后续控制作为作用分类：入口保留真实设备输入与等待，后续控制须通过无设备/张量/状态作用校验。生产与目标共享分类函数，完整相邻调用上下文仅用于工作对应；已有设备定位标记不当作实际设备工作；runtime 在解释结束时统一删除既无真实 payload 又无显式端口、状态或依赖引用的区间，保留真实 CPU 作用。纯 CPU 模板只要求 CPU 调用端口，不再要求观察器生成的空设备端口。重新分类优先复用本窗口实际粗图离线生产，不为标签排列补采。

PD 代表角色还须包含远端布局、元数据行宽及多源/多目的组内分片职责。目的池与完成端口按原生映射的局部位置命名，真实 rank 在装配时绑定；不按采集时间或具体 rank 字符串替换。模型/本地池等价事实在初始化阶段交换；各实例预热排空并发布真实端点后，使用已有全实例屏障确定最终代表。PP 控制请求逐阶段转发，处理该请求时不得新加 world collective。来源解释核对真实传输目的注册与声明接口，目标对每个本地/远端池分别绑定层位置。

S1 数据交接须明确区分内容就绪与包络完成：子调用输出由父调用转交时，共用原有存储版本的就绪边界；父调用返回、设备结束及后续通信完成各自保留。沿来源解释、切分、跨层事件引用、实例化和数据依赖核对整条链路，不在目标执行器按 PP 案例添加等待例外。结构评价与时间提取须共同核对原始 scope/绑定声明；重复纯 CPU 调用仅允许显式未配对范围，不删除其因果路径或据此标为完整验收。

来源覆盖按实际结构条件判断，不能用“请求长度均已采过”替代。原生异步准入可能把多个请求分开执行，目标却将其合批；即使总 token 数可参数化，布局重排也可能从视图变成设备复制。此类缺口先沿原生 ABI、局部 guard、外部别名及完成端口判断：是否已有兼容子图可复用、是否适合声明有限局部变换、或者确实缺少必要来源。检查沿已有模板条件和观察事实进行，不按模型、批次数或案例新增补采规则。必要复制及通信后的就绪依赖不能因追求粗粒度而删掉；也不能每出现一个目标缺口就追加完整 serving 采集。功能修正与独立覆盖验证仍分开推进。

独立持久字段的物理生命周期须从原生分配器确定，不能一概映射到请求槽位。adapter 声明字段使用请求槽位或独立行池，原生控制只交接申请、请求绑定和归还，核心唯一管理实际分配；模板继续声明逻辑字段与成员，实例化依赖按当前资源绑定解释。每个字段归还只清除自身内容资格，保留在途访问以保护物理复用。PD 元数据的源端写入、传输、目的端消费/清零及独立归还整链审查后统一构建；可选来源观察记录真实行池初态、分配/绑定/归还和末态，独立评价核对物理别名与生命周期。复用取证须实际出现同一物理行释放后被另一请求重新使用，并分别检查操作序列、字段载荷和执行依赖；池容量较小或最终全空本身不算复用证据，也不能用操作一致替代全部在途安全。旧来源没有这些事实时保留未观察资格，不补造行池操作，也不把请求资源一致当作元数据池一致。

持久元数据的数值对照只覆盖会被原生控制消费的字段，并与图结构验证分开。复用可选的已完成动作观察接口，源端记录原生写入输入及接收后已消费的请求值，目标沿同一原生边界记录；不为观察增加设备读取或同步，不将数值放入模板身份。独立评价先核对实际字段访问、动作完成和真实发送组，再比较请求的首 token 与缓存计数；只在各次运行内部核对原生 room，跨运行按逻辑请求对应。未使用的行 padding 不逐标量维护，失败提交及缺失/重复观察保留明确结果，不能因传输边正确就推定内容正确。

S1收尾按功能缺陷与证据覆盖分别核对，不以partial数量归零为交付门槛。读取切口缺失、状态所有权错误、错误归约/准入、必要依赖丢失或评价漏检属于S1，须完成相关职责链修正；已保留完整作用、但重复调用无法逐次配时的范围不得删除或伪装通过，交接其现有结构/协议证据及时间限制。固定案例的接口闭环不替代S2的独立目标验证。同位置子调用数变化、真实长在途条件和新配置组合按后续实际覆盖要求取得证据；若验证发现正式能力缺失，回到对应模块集中修正，不靠扩大矩阵补模板。S1仍须完成整体代码、文档、数据审查和阶段提交推送后，才能开始S2。

### S2：初步验证，先证明事实和评价可信

条件子树验证应区分整批条件变化与同批内部的独立组合：在同一来源域内让不同层或专家工作量分别变化，核对局部条件、实际端口 shape 与连接，而不只看最终请求完成。直接子调用数变化须由实际来源确有该分支的案例单独证明；空张量、内部工作变化和子调用数变化不是同一项资格，不为不可达分支盲目扩大采集。

使用新镜像、新采集和正式入口。先取得一个 Dense 单 worker 闭环，再选最少案例覆盖 TP、PP、EP、PD 及其关键组合、调度/缓存；同一案例可以覆盖多个机制，不做完整模型×配置笛卡尔积。

初步验证同时检查三件事：

- 来源粗图：从实际采集的批次/模块范围、原生端口、资源和状态核对是否漏项、重复、错窗口或增加屏障。同源实例还原只证明模板生产未丢信息，不能单独证明提取正确。
- 评价工具：核对其输入来自本次实际运行，正常匹配有具体依据；以受控的缺边、错误端口/shape、通信伙伴和缺失事实检查能否区分已确认差异、证据不足与工具报错。仅使用 example 的必要反例，不新增 test/fixture/mock 工程。
- 预测闭环：在相同到达、初态、原生策略与边界时间下，核对组批、工作、数据、资源及完成反馈。旁路只提供具名工作时间，不提供真实批次、状态分配或目标图；按工作身份对应，第一处无法对应即明确报告。

CPU 返回、设备完成、跨 rank 通信及资源释放分别检查；原始记录中的已证明内部细节不逐项计为缺口。等待和传输的长条件核对推进规模与活动状态，不把模拟器初始化/IPC 墙钟解释成目标 CPU 时间。

先从代码和完整职责链确定共因，再集中改完有关模块后进行必要复核。代表机制尚不成立、来源仍缺必要边界、评价不能定位错误时，停留 S1/S2，禁止进入全量矩阵试探缺什么。

冻结前做一次全流程审查：采集/规约/模板/变换/连接、原生控制、资源、执行、应用、桥接、例子和构建均覆盖，不只审查 diff。确认旧路径删除、引用更新、代码表达及数据/镜像一致，完成阶段维护交付。

### S3：全量独立验证，整轮收齐再处理

S2 收口后一次性确定具名矩阵、模型 revision、合法配置、workload/种子、代表来源、留出目标、预期触发机制、评价方法、镜像 ID 和累计预算。先确认原生框架可运行，再进入结构资格判断；原生不支持的组合记录原因，不 patch 框架强行扩大支持。

冻结核心、适配、规约/模板规则、评价、来源配方与输入。来源及目标都由本窗口新采集；每个目标真实案例原则上只采一次，后续仿真和离线比较复用本窗口该份事实。不得从旧 data 恢复目标、借入目标片段补模板或现场改规则。

按第 6 节覆盖完整清单。错误隔离后继续无依赖案例，依赖受阻明确记录；整轮不边验证边修复，也不以存储不足静默取消困难案例。只有资源/安全或预算不允许继续时停止，并报告覆盖未完成。

目标是一次正式全量取得通过；不能承诺零缺陷或用降低判据达成次数。若未通过，先完整报告并按共同根因集中修复，完成静态审查与受影响案例回归后才重新冻结。是否需要重做全量按真实影响决定，不自动启动下一轮、换容易输入或无限增加采集。使用过的差异转为开发证据，新独立资格明确留出边界。

全量报告先记录每例事实是否充足，再记录实际比较范围、结果、第一处差异、责任层及证据。来源失败、预测错误、评价错误、原生限制和预算停止不能混为核心不正确；内部细节未细分也不能与外部依赖未知共用一个笼统结论。

### S4：多机有界探索

在单机验证成立后，沿同一工作/资源/通信合同探索逻辑 rank 到节点/设备的映射、原生控制进程部署、跨机 collective/P2P/KV 传输与完成交接。优先选择一个最小 TP 或 PD 场景，不展开多机矩阵、部署平台或性能模型。

只采用原生框架能运行的配置。具备两机条件时取得一例真实证据；缺少条件时明确静态结论和未验证内容，本机多进程不冒充多机通过。探索性编排留在 example，必要正式接口保持在各自 adapter/核心职责中。

交付可行性、阻碍、所需修改及复杂性判断。探索不修改冻结单机资产以追求通过；必须改变共同核心的工作列为后续正式扩展，不为此重启单机全量。若发现现有单机真实缺陷，保留单机未通过状态并按影响修复，不能以“只是探索”掩盖。

### S5：整理与最终交付

沿本窗口 Git 基线审查全部业务与相关工具，检查分层、唯一状态、资源/引用生命周期、粗图与模板合同、代码风格及可删除的整条链路。无需为旧格式留兼容，不为凑行数删必要空行、注释或把业务迁出统计。

整理公开一键入口、输入例子、精简结果和支持/限制说明。只保留本窗口最终有效资产、必要新来源/真实目标、失败结论与费用；删除已消费 work、重复报告、过期镜像及编译产物。历史失败不改判，数据清理后同步撤下失效引用。

最终对照沿用 S3 的有效冻结证据；只有实际修改影响其结论时才补相关复核，不再机械复制一次同样全量。代码、文档、数据分别检查后，按职责分层提交推送开发分支，核对远端实际提交。未交付或关键结构缺口未关闭时如实保留状态，不进入性能层。

## 5. 验证可信性与错误定位

来源和目标共用事实格式、解析与规约规则，真实图的工作、参数、连接及状态必须来自各自原生运行。预测端不得调用“从目标 trace 构图”来补答案；评价可以共用基础图查询，不借模板选择/展开结果重建真值。两端共享规约可能共同遗漏的边界，须由直接原生调用/状态证据另行核对，不强制开发两套解析器。

来源投影的独立检查必须核对完整区间覆盖，而不只核对保留下来的工作是否有来源。以原始span边界、嵌套所有者和载荷区间检查每段工作恰好保留一次，等待及无载荷区间只承接顺序；粗图依赖只能来自实际依赖或资源串行顺序，不允许遗漏区间、重复计费或新增无依据的顺序边。同时核对环境、原样交接的调用层级/参数/上下文和通信声明；边界集合必须恰好来自原始区间、端口、访问及依赖，共享边界归属于两侧及相接区间的共同语义祖先。这项检查不调用核心投影实现，不声称能发现解释前已经漏采的原生事实；表达式归一化、条件与 shape 变换仍由模板合同和相应验证负责，不能因投影映射一致就取得该资格。

| 检查 | 证据与通过要求 |
| --- | --- |
| 事实与范围 | 统一预热、初态、完整角色及观察范围明确；来源闭合、目标闭合和模板发布分别成立 |
| 输入交付 | 从原始 session/RAW 时钟及入口记录核对目标实际请求成员、接收轮次和时刻；不能用旁路输入文件代替真实交付证据 |
| 粗图 | 原生工作有承接，无重复/遗漏；内部隐藏有边界依据；必要输入、输出和中间信号可定位 |
| 模板及变换 | 层/角色共享合理；改变长度、成员和容量能正确求值；分支由原生依据支持，不靠目标修图 |
| 因果与并发 | 数据就绪、CPU 返回、stream 顺序、跨 stream 等待、通信和释放完整，无额外串行化 |
| 动态控制与资源 | 同条件旁路下决策和输出进度可对应，预约/引用/回收合法，两个 PD 池保持独立 |
| 生命周期与规模 | 新任务/恢复、失败不发布成功、预算/清理、无设备纯预测和默认/明细一致，活动图不随历史无限保留 |
| 评价本身 | 正常与负向证据均能定位；工具报错不写成业务差异，证据缺失不冒充 matched |

结果至少区分已匹配、确认差异、证据不足、依赖阻断、原生不支持、工具失败及预算停止。已确认差异与证据覆盖分开交付：存在差异时总状态明确显示差异，即使另一项检查仍缺证据；各 finding 标明差异或证据缺口。覆盖状态消费已有连接、绑定、查询及数值检查中的未配对结果，不能仅看动作身份是否唯一。未配对项不视为差异，差异也不被 incomplete 总状态遮蔽。只在相关流程边界确实未知时影响对应结构资格，不能用全局未解释底层记录数一票否决，也不能把未知自动算流程外。

输入读取的缺证据也进入统一finding清单，携带进入状态、已交付请求集合、两侧次数及原因；区分身份重复、非workload消息、单侧缺记录和进入状态未观察。默认报告保留代表项，明细沿用既有开关，不复制完整trace；不能只有partial计数却没有定位入口。此诊断不改变时间配对和通过条件，也不从“最后一轮”推定读取无作用。

入口接收一致后仍须审查两次接收之间的控制推进。纯 CPU 清理可能改变原生逻辑队列及预留额度，不能仅因图中无设备任务就删除顺序差异；需要结合原生状态读写及目标资源条件判断。外部入口、worker 广播/转发后接收和空轮询分开说明，未记录的空轮询时间不得推断为已对齐。

跨动作顺序报告保留实际边的依赖类型，为差异提供有界路径证据和原生位置；计数与判据保持独立。单条路径只解释一项已存在的前驱关系，不能据此证明其他路径或原生状态影响不存在，不能将缺少 data/state 标签直接判为无害 CPU 顺序。

接收证据按原生外部拉取边界补齐起止区间、进入状态、消息数及实际成员，保留有效窗口内的空结果；沿用可选详细观察开关，不新增逐 socket 图节点或整循环 CPU 模板。独立检查先确认区间有序、非空结果与原始入口一致，再依据自身请求进度及队列状态讨论时间匹配；重复状态保持歧义，不能按轮次序号强配。首批激活前未知状态与未观察空轮询单独报告。驱动提交、socket 可用、拉取返回及广播完成互不替代，也不能用观察结果指挥原生组批。补采前须先审清输入交付、原生接收、时间反馈及评价的完整合同；已有非空记录不足以补造空接收过程。

接收前状态观察不依赖 profiler 已激活：首次 source 请求在拉取和广播之后才激活设备观察，拉取前仍须读取已初始化的原生调度状态。预热请求不使用 source 身份解释；保留范围由观测窗口维护，接收 source 请求的首轮以及窗口未排空期间的读取纳入记录，窗口外空读取不因具有上下文而进入证据。历史未知状态不得离线补为空队列。

外部接收返回与请求可交付时间分别进入控制接口。时间旁路按实例、接收前原生逻辑状态和此前已交付请求集合识别一次读取；此前交付集合由现有 delivery 所有者提供，避免把启动前和工作完成后的相同空队列混为一次。读取结果成员、轮询序号不进入身份，未知进入状态不补造。仅唯一、有原始区间且可归属于 workload 的读取提供精确返回时刻；重复身份及仅含外部控制消息的读取保持时间未覆盖。核心在该返回边界唤醒原生，再按当时输入可用性返回请求，不复制来源读结果，不规定批次。晚于实测返回才进入相同读取时直接报告矛盾，不平移时间；时钟唤醒同时包含请求到达和读取返回，不能把尚未完成的读取在收尾时丢弃。此项是开发旁路的时间反馈，不推导 CPU 成本或生成逐 socket 图。

完整目标明细统一记录接收前身份、实际返回时间及成员，包含空读取；非空成员同时作为交付证据，不再输出重复交付记录。独立评价从原始来源构造读取身份，先核对目标的历史交付集合及时间单调性，再比较两侧唯一读取的返回时间和实际成员。重复、未知及未对应项保留 partial，不因非空 cohort 一致宣称整个接收过程已对齐。功能完成后最多用一个同配置来源核对新增事实及一次预测/对照，不通过反复换请求推动此合同。

评价分开记录动作内容、内部/跨动作依赖和物理资源生命周期的资格。内容比较按实际调用树与端口核对参数、布局、数据别名/版本/生产者及逻辑状态访问；元数据端口不承担数据分配所有权。局部依赖按具名边界间的可达关系、共享事件和粗工作所处位置检查，不按事件号、原始边数或时间先后硬配；路径使用完整实际图，不能因切出子树而丢掉外部中转。内部线程可无公开端口，仍比较其资源共享与工作归属。跨 rank、跨动作、未具名内部关系及物理资源各自取得证据，不能由局部边界通过替代。串行资源的自动入口/出口在连接比较中核对。工作身份共享不意味着由模板生成真值；评价错误先按共同合同修正，不改生产资产迎合比较。

跨动作次序将已经对应的工作身份与具名边界组合成比较标签，核对来自其他动作的前驱关系。沿完整 rank 图传播，保留未命名节点中转和后来解析的动态等待；忽略不改变可达性的冗余传递边，分别报告缺失前驱和额外串行化。分批传播边界位集合，避免保存全案例的平方规模关系表；边界缺失不自动视为关系相等。该结果证明被比较边界间的因果关系，不能替代跨 rank 完整因果、信号句柄身份或调用内部资源生效时刻的证据。

资源操作比较读取每个 worker 的实际调用输入和返回值，分别规约原生记录与核心操作明细，再比较有效操作顺序和内容；顺序用于检查状态演进，不用于给节点或时间强行配对。页/槽位以释放后的使用周期标识，缓存句柄按观察到的对应关系重命名；页内偏移、请求身份、键内容、锁引用变化和释放分组仍保留。原生分组释放暂存、空释放及禁用前缀缓存的空操作不当作核心状态变更，容量查询与显式请求前缀重绑定的独立资格另外说明。不能用验证器重新执行分配或缓存策略生成真值；操作输入/结果一致也不证明调用内部生效时刻或在途安全。

资源池先按真实传输会话和注册所有者统一身份，再比较逻辑访问；不把接口名直接与实际池名比较，也不调用预测端路由规则建立真值。准备页表与消费 KV 分别统计：仅有页表快照不要求目标制造访问；有真实访问而无对应绑定证据仍报告缺口。传输使用直接记录的两端物理页及其服务窗口，释放代次来自各自所属池；metadata 槽位不等于请求槽位，未观察的字段不冒充已比较。

物理绑定独立比较以实际消费的请求页表或传输直接记录的物理页为来源，以执行器解析出的访问区间为预测；先按共同动作、所属资源池和请求身份对应，再核对逻辑覆盖、页内位置和页/槽位共享关系。不同运行允许物理编号不同；物理身份由本池编号及实际释放后的新使用周期共同解释，释放后允许重新分配，不把历史地址相同当作内容相同。原生批量释放的暂存与真正归还分开；快照没有精确时刻时，只在其所属调用窗口内相关资源未释放的条件下确认身份，否则保留证据不足。覆盖以真实粗图声明的读写区间为准，不要求消费页表中未被访问的内容；真实图有 KV 访问但没有直接物理绑定证据时，即使预测也未输出绑定，仍报告证据不足。以区间合并/交叠比较，不展开每个 token 或两两枚举所有页。绑定对应与分配/缓存操作、设备在途安全分别取得资格，不能互相替代。

预测端的KV在途安全另按实际物理绑定检查：逐次提交将逻辑访问映射到池、页、层及页内token/字节区间，完成记录移除已结束访问，逻辑归还不能移除仍在途访问。两个不同调用访问相同物理区域且至少一方写入时，若旧访问尚未完成，完整执行图必须具有旧结束到新开始的因果路径；路径包括跨rank边，不能只比较时间先后或要求某一种直接边。评价层只消费既有绑定、读写声明与执行记录，不重放分配策略，也不把检查加入核心状态机。报告分别列实际访问、待完成冲突及在途归还数量；零次触发不授予长在途复用资格。实际运行覆盖与评价器正反例检查分开，修改内存图副本或暂缓诊断侧访问回收仅用于检查评价器，不作为新的真实案例。

在途取证先沿所选原生路径确认可达性：设备工作持续较久、多个批次同时在途、归还物理页时旧访问未完成是不同条件。结果拷回、PP输出等待、PD成功通知及缓存保护引用可能使最后一种条件在正常路径不发生，不能仅增加请求或输出长度期待触发。分别核对正常完成、传输完成与资源复用的真实因果；失败、撤回、卸载及未开启机制不借正常路径结论取得资格。核心仍须保留在途访问依赖，不因某个原生案例未触发而删除通用保护；不新增强制提前释放或伪造延迟的业务开关来制造证据。

跨动作数据分别核对实际写入者和对外输出边界：子调用可以写入、父调用可以输出，不能要求写入者自身拥有数据输出端口。按原生 storage/version/写入归属确定来源，核对所有与消费有实际路径的生产动作输出；目标地址、事件号与版本起点不要求相同。通信由真实进程组、参与者和组内因果顺序确定对应轮次，再检查预测参与者就绪到完成的连接；不能仅按目标节点序号或边数配对。参与者或原生顺序缺证据时标为证据不足，不据此将目标额外边判错。同时独立核对目标自身全部通信通道，包括重复调用：按目标图实际因果顺序和声明参与者检查就绪到完成的连接是否缺失或多出，不能因来源未配对就跳过。目标协议自洽与来源对应分别报告；前者不证明载荷、跨运行轮次或声明本身正确。以上检查放在独立评价中，不把评价过程引入核心执行。

提交与等待须统一区分主机已排队、设备已提交和设备已完成。普通图内依赖在切分时保留；stream 等待观测到的具体前沿只是本次来源的动态快照，即使两端在动作内也要按目标当前命令重新绑定，不能固化某次时延下的结果。命令接受点沿明确 submission 链追溯，执行仍受原 API/设备依赖约束；不能用“等待开始时仍未完成的设备命令集合”替代原生队列语义。每条 stream 保留在途命令和最近完成边界，不无限保存完成历史。先沿采集事实、模板切分、执行前沿与回收共同明确这份合同，再整体修改相关模块；不按某个 wait 序号或某一 workload 增加补边规则。

重复调用的结构核对与逐次配对分别实现：同一来源身份的内容，以及调用内具名边界可达关系和工作位置，分别检查是否在全部实际调用中一致；一致的项逐个核对预测副本，不论哪侧重复或是否含查询/通信。不一致的项保留歧义，不能按预测结果从来源中挑一个相似实现。依赖检查保留完整图中的中间路径，不因路径暂时离开调用子树而截断。结构一致不授予查询返回、通信轮次、出现位置或外部生产者配对资格；只有两侧唯一调用参与一对一跨调用对照，重复仍标 incomplete，不按次数强配，也不保留纯 CPU 专门豁免。

对照先区分动作自身结构与控制轨迹。相同请求/队列快照不证明两次读取时的完成状态相同；给定耗时可能改变成功分支、资源提交及后续 stream 前沿。出现跨动作差异时，沿实际依赖路径和原生分支检查首次状态分歧，不能直接删串行边、添加上下文特例或过滤未配对调用。真实边界时间及通知可见性未对齐时，保留局部结构结论和未验证范围；这不豁免独立验收，也不把所有差异自动归因于耗时。

报告先给精简结论和第一处分歧，再给必要取证入口；不以节点数相同、退出码零、总时长接近或所有案例都有状态替代结构通过。

## 7. 产物、环境与采集纪律

S0 清空旧 data 后，建立一个本窗口 UTC 时间根；所有来源、目标、资产、报告及临时工作归入该根。阶段子目录不再另造大量顶层时间目录。正式默认输出精简，完整原始 trace/展开图只按必要生产或诊断用途生成和保留。

    data/<UTC>_coarse-graph/
      inputs/                 固定输入、环境/镜像依据、来源规划及矩阵
      sources/<domain>/       本窗口来源事实、来源粗图及必要采集范围
      assets/<domain>/        唯一正式模板库
      targets/<case>/         独立真实粗图、状态及必要边界时间
      results/                精简预测、逐例结论和全量报告
      logs/                   真实命令与错误
      work/                   可回收的导出、编译和解释中间件
      diagnostics/            显式需要的原始 trace 或局部明细

原始 trace 可以在 work 临时生成，粗图和必要事实发布后按消费者释放；支撑当前验证争议的原始证据保留至结论形成。不能先删除唯一证据再宣称覆盖完整，也不长期保留无消费者大 JSON。数据身份由现有输入、角色和实际生产环境交接，不新增版本平台、指纹账本或多份库存。

镜像标签保持按职责稳定命名，运行记录实际 ID。采集包、控制包、SDK 或复制资源改变后统一重建受影响镜像，验证安装路径及入口未引用旧模块；核心在 modeling 内重新构建。正式运行不临时挂载旧 Python 包覆盖镜像，也不因标签相同沿用旧资格。

采集前先静态说明问题、缺少的事实、不能靠现有代码确定的部分、运行范围及结束条件。代表来源覆盖预先声明的有限机制；每个独立目标原则上一次真实运行。正式生产和预测的子容器须有独立于协调进程的期限；预测启动前固定镜像 ID，在现有日志记录实际命令，不增加并行运行账本。解释、模板及仿真变化优先复用本窗口事实，不因 CPU 后处理失败重新启动原生。

原生、后处理、临时/保留存储和尝试数在每阶段执行前明确累计上限，失败及恢复不清零。存储按全量输入与必要原始证据规模预估，不沿用导致中途取消的过小额度；达到上限先交付实际覆盖和原因，不能偷偷扩额或换输入消耗。

## 8. 实施节奏与维护交付

每批先自顶向下追踪入口、生产者、消费者、状态所有者和生命周期，写清不变量及待删除路径，再完成整个模块或功能链。跨文件重写可以一次大范围完成；静态审查不能只查格式，运行通过也不能证明代码没有问题。

C++23、Python 3.10、面向实际职责的类与组合；必要浅层继承/模板表达差异，不堆防御分支、默认值、兼容层、异常包装或重复转换。逻辑块适当空行，身份/所有权/完成关系等重要位置写必要注释，独立注释上方留空行；不修改 .clang-format。

完成模块及相关调用方的静态检查后，统一进行受影响构建和最少正式入口运行。不每改一层就编译，不用扩大验证代替开发；没有新改动或未决问题时不重复同一验证。

每阶段启动先根据上一阶段交付和现状调整当前及后续范围；结束时核对 Git 阶段差异和全部关联代码，完成职责/正确性/风格/删除审查及文档、数据检查，再按 type(scope): summary 分层提交推送开发分支。提交集中在阶段边界，不为每次日志或局部改动单独提交。

计划只维护任务和规则，status 只维护当前状态、资格与下一步，log 按日期正序记录“范围、改动、验证、结论与限制”。不创建第二套滚动报告；全量报告作为实际结果保存在运行根，文档只保留必要摘要。阶段未通过时保留问题，不把整理、跑完矩阵或结束窗口解释为功能通过。
