# 粗粒度执行图工作流计划

开始日期：2026-11-05。

目标：从干净代码入口、空运行数据和明确镜像出发，将原生 trace 提取为保留必要因果的粗粒度图，完成模板生产、目标动态展开及可信的单机全流程验证，随后进行有界多机探索并交付。计划定义工作与判据，实施状态和实际行动分别由本目录 status.md、log.md 维护。

## 1. 范围与交付

输入保持一个固定模型、配置集合和请求集合，系统选择代表来源，用户不指定 base。原生控制后端为主线；原生维护请求逻辑，核心维护槽位、KV、前缀状态和就绪，执行器维护模拟时间及在途工作。

交付唯一的粗图工作流：采集、真实粗图、模板库、目标展开、真实对照和精简报告使用一致的表示与边界。正式执行图不以每条 kernel、SDK 内部记录或 CPU 函数为节点，也不以它们逐条归属作为普遍通过条件。

本轮保留单机 TP/PP/条件 EP、P/D 分离及组合、等价 worker 代表采集、chunked prefill、mixed、原生 Decode 准入/预算策略和一级 prefix cache 的能力目标。具体可用范围重新取得证据，不因旧实现运行过而直接认定支持。

多机只作扩展边界和最小案例探索。轻量控制器推进、真实权重自然路由、数值计算正确性、overlap/speculative 扩展、多级缓存实际搬运、性能采样/成本模型及精度验收均不属于本轮交付。已有轻量分支若不能服务当前消费者，允许完整删除；不为其兼容阻碍新合同。

## 2. 正向流程与粗图合同

    来源原生执行 → trace 与必要语义/状态事实 → 来源粗图 → 切分与归一化 → 模板库
    目标配置与请求 → 原生控制 → 模板选择、有限变换与连接 → 预测粗图 → 完成反馈
    目标原生执行 → 独立 trace 与必要事实 → 目标真实粗图 ──────────→ 同粒度对照

来源粗图只描述该次真实执行，不是任意目标的全集。模板额外保存有依据的参数关系、组合和有限分支；目标组批由控制器动态产生，不能复制来源或真实目标的批次。

### 图中保留什么

| 对象 | 最少需要表达的内容 |
| --- | --- |
| 工作身份 | 请求/逻辑 token 范围、流程阶段、必要迭代、层/角色及 rank/实例；不靠跨运行节点序号对应 |
| 执行片段 | 稳定职责、使用的 CPU 线程或设备 stream/通信资源、必要参数及来源依据 |
| 数据端口 | 外部输入输出、shape/dtype、必要读写/别名和数据就绪；不保存全部内部临时张量 |
| 完成端口 | 必要的调用进入、CPU 返回、设备完成、中间信号和资源可释放边界；按实际行为选择 |
| 连接 | 数据依赖、同资源顺序、跨 stream 同步、跨 rank 通信及控制/资源效果的提交条件 |
| 模板合同 | 参数、重复/子调用、有限变换、实现域及资源绑定；来源取值不充当目标默认状态 |
| 诊断 | 粗片段到原生范围的最小取证入口；可选内部明细不进入共享身份或成功判据 |

粗图、模板及性能单元各有粒度。粗片段须覆盖内部工作的资源和成本责任，但本轮不建立真实成本；不能把被封装的工作当作零耗时。未来细化计费不要求恢复完整底层语义图。

### 规约规则

1. 先从现有原生调用/模型层次、真实提交关系和资源身份确定边界，再提取粗图；不先构建完整细粒度 DAG 再默认持久化和压缩。
2. 可合并同一串行资源上内部封闭的连续工作。对外的数据、状态、通信、中间就绪、CPU 返回及释放关系形成端口或切点；同一 stream 不能单独证明可合并。
3. 跨 stream 的区域可保留多个资源片段及连接，不压成一个全局串行节点。跨 rank/实例只连接协议实际要求的参与者，不添加整组屏障。
4. 内部 kernel 名称、数量及 SDK 实现记录不定义模板种类。必要的外部作用按实际 API、提交、队列、资源和事件生命周期承接，不用名称白名单或相邻时间猜归属。
5. 归属要求以已选流程及必要因果为范围。已证明被片段覆盖的内部细节可不逐项对应；证实流程外的记录仅作诊断；可能影响边界而无法归属的记录保留为局部证据缺失，不能静默丢弃。
6. CPU 自身工作、排队和异步设备工作分别表达。等待由依赖产生，不把整个原生调用墙钟同时算作 CPU 服务和设备成本，也不把 CPU 返回统一当作设备完成。
7. 统一预热后开始观察，记录逻辑 KV/缓存初态及必要资源前沿。初始化、编译、预热和窗口外工作不进入正式图；起点不清楚时报告事实不足。

规则维护在一个正式实现中，框架/runtime 提供差异事实，不按模型、请求长度、kernel 名或目标残差增加粗化特例。未知记录的处理必须能追溯到规则和边界证据。

### 模板生产与变换

按统一 serving 动作和模型层次切分来源粗图。Prefill/Decode 内部以 embedding、重复层、attention、MLP、归一化/残差及输出角色作为候选结构依据；不固定每个函数或每个 kernel 一类模板。

自身定义、子调用组合、目标参数和 rank/资源绑定分开。重复层、同职责 worker 共享定义，保留权重、KV、stream 和状态的独立身份；控制/输出职责不同的角色不能强行共享。代表选择发生在采集前，采后去重不冒充采集次数减少。

shape、成员及 KV 范围关系优先来自原生模型元数据、实际调用参数、已有明确运算规则和接口合同。需要人工适配的内容限于不能自动取得的实现差异，维护一处；不从少量样本拟合 shape，不复制整套模型实现或开发通用符号推理平台。

有限变换覆盖参数求值、层/成员重复、局部实现选择和端口/资源重绑定；必要通信由对应拓扑合同连接。粗化不得隐藏需要独立变换的部分，也不因目标内部 kernel 数量变化而直接判定不支持。

同来源域重点复用请求长度、成员、到达、并发及 KV 容量变化。模型、dtype、并行拓扑、backend、框架镜像及 page_size 变化分别规划新来源，不以这些变化必须沿用旧模板为目标。调度机制使用各自合法来源和控制配置。

## 3. 代码与适配职责

| 层次 | 唯一职责 |
| --- | --- |
| 框架 adapter | 流程入口、批次/模型层次、必要参数与状态事实、原生控制接入和并行角色解释 |
| runtime adapter | trace/API/队列/stream/event/传输事实的解释，实际资源和生命周期；不选择批次或实现第二份资源账 |
| 共同核心 | 粗图表示、通用规约、模板切分/归一化/变换/连接及资源执行；不识别框架私有函数和 SDK 名称 |
| 外围应用 | 单任务进程、镜像选择、累计预算、产物发布与恢复；不暗中生成模板或改变控制策略 |
| example | 代表案例、矩阵、真实独立对照和失败归因；不被 src 导入，不复制核心 shape/KV/调度算法 |

目录、类与数据交接按上述职责重排，C++ 头源同目录。先决定最清楚的组织，再判断旧模块是否有保留价值；不因现有文件名或调用关系而维持错误分层。不新增万能注册中心、双格式读取、版本分支、空适配目录或纯转发包装。

## 4. 阶段与结束条件

| 阶段 | 主要结果 | 进入下一阶段的条件 |
| --- | --- | --- |
| S0 收尾、清理与环境核对 | 干净数据起点、明确代码取舍和镜像/构建归属 | 旧输入不再可被默认找到，迁移基线和实施边界明确 |
| S1 粗图工作流构建 | 从原生事实到粗图、模板和动态展开的唯一正式链路 | 来源和评价合同齐全，旧职责链删除，完整功能静态审查及集中构建完成 |
| S2 初步验证与收口 | 代表机制的真实闭环及评价可信性证据 | 能区分来源、核心、控制和评价问题，主要机制与必要负例通过，达到冻结条件 |
| S3 全量独立验证 | 同一冻结规则下的完整结果和归因报告 | 无未关闭的关键结构缺陷，覆盖和证据边界明确 |
| S4 多机探索 | 最小证据、扩展接口及代价结论 | 探索有界结束，不改变已冻结单机实现来追求多机通过 |
| S5 最终交付 | 整理后的源码、文档、资产、公开入口和支持说明 | 审查、必要复核、数据检查和阶段提交推送完成 |

### S0：关闭旧路径的入口，建立干净起点

- 核对 Git 起点、工作区全部未提交改动和真实消费者。按保留、替换、删除确定整条职责链，未交付修复不自动成为新基线；用户无关改动单独保留。
- 只做必要归位和明确无用内容删除，不先把即将替换的细图流程大规模美化。新图表示确定后，结构性改写集中在 S1 完成。
- 核对活动任务与私有资源，结束旧窗口遗留进程后清空项目 data 下的旧运行数据，包括旧来源、模板、真实目标、预测、报告、临时文件和恢复状态。新流程不导入旧资产，也不把旧数据迁入新运行根伪装为新产物。
- 清理旧硬编码路径、默认资产选择、示例输入和文档证据链接；旧预算与失败只作为主工作流已明确范围的历史，不要求长期维护旧数据或兼容旧格式。
- 模型下载、依赖缓存、官方/参考源码及其他工作区资源不属于运行数据，不随 data 清空。不可确认归属的外部内容保持原状，并明确其不参与新流程。
- 核对 modeling、推理、control 和原生基础镜像的 ID、父镜像、软件来源及实际安装位置；检查 Compose、Docker COPY、入口、挂载和源码路径是否可能带入旧包。清除已确认本项目独占且无消费者的旧镜像/容器/编译产物，不执行全局 prune。
- 镜像稳定命名、不含日期。S0 确认软件基础与重建范围，不为即将删除的采集代码反复打包；S1 完成模块后统一重建受影响推理/control 镜像及核心程序。

结束时保留必要代码基线和本阶段实际整理记录；data 在新运行开始前为空。旧源码可供短期阅读，不能通过正式入口执行；没有经过新合同核对的镜像不安排采集。

### S1：按闭环重建，完整删除被替代实现

按“任务输入 → 采集事实 → 来源粗图 → 模板 → 原生控制 → 目标展开 → 完成反馈 → 结果”的顶层闭环实施。先定义各交接对象、状态所有者及完成条件，再向下完成每个模块；评价入口和目标真实粗图的生产同时纳入设计。

先完成粗图合同与目录职责，再沿生产者、消费者集中重写。重点处理：

1. 采集只交付构成粗图及参数化所需的事实；保留原生关联及外部作用，删除只为逐 kernel/逐私有函数配对服务的常驻观察路径。
2. 规约在切模板前执行；原始观察范围、粗片段及对外端口有明确对应。不让粗图依赖完整细图、逐条底层归属或事后修补全局 unknown 计数。
3. 模板生产、目标绑定、通信连接和执行器共同消费新合同。源图来自真实观察，目标图来自模板与控制，二者不互相补答案。
4. 原生控制保留真实决策，资源与虚拟时钟归核心。按具体等待条件分析控制推进及跨进程交接，保留有作用的 PP 空轮转；不为加速擅自跳轮、sleep、改耗时或复制原生策略。
5. 采集阶段发布、角色事实闭合、会话管理成功和进程退出分别判断。失败不发布成功资产，已闭合事实可沿同一任务离线处理；截止和资源清理由明确所有者维护，不用隐藏重试重新运行原生。
6. example 完成真实粗图对照，给出工作、参数、依赖、状态及完成边界的差异定位。删除旧逐底层配对评价和重复组装链，不保留“旧结果较好就回退”的入口。

删除范围包括被替代的整个源文件及类型、旧 CLI/配置、CMake target、Python 导入、安装资源、Docker COPY、脚本、示例和说明。确有新消费者的通用表达式、原生资源或协议能力才保留，不能勉强包一层继续使用旧流程；不移入新的活动 legacy 目录。

每轮先完成一个模块或一条完整功能链，静态核对所有调用方及跨语言合同后再集中构建、必要试跑。S1 收尾时普通入口只有新路径，旧构建/SDK/二进制已清理并重新生成；静态设计与操作说明按真实设计和实际入口对齐，不提前宣称新命令可用。

### S2：初步验证，先证明事实和评价可信

使用新镜像、新采集和正式入口。先取得一个 Dense 单 worker 闭环，再选最少案例覆盖 TP、PP、EP、PD 及其关键组合、调度/缓存；同一案例可以覆盖多个机制，不做完整模型×配置笛卡尔积。

初步验证同时检查三件事：

- 来源粗图：从实际采集的批次/模块范围、原生端口、资源和状态核对是否漏项、重复、错窗口或增加屏障。同源实例还原只证明模板生产未丢信息，不能单独证明提取正确。
- 评价工具：核对其输入来自本次实际运行，正常匹配有具体依据；以受控的缺边、错误端口/shape、通信伙伴和缺失事实检查能否区分已确认差异、证据不足与工具报错。仅使用 example 的必要反例，不新增 test/fixture/mock 工程。
- 预测闭环：在相同到达、初态、原生策略与边界时间下，核对组批、工作、数据、资源及完成反馈。旁路只提供具名工作时间，不提供真实批次、状态分配或目标图；按工作身份对应，第一处无法对应即明确报告。

CPU 返回、设备完成、跨 rank 通信及资源释放分别检查；原始记录中的已证明内部细节不逐项计为缺口。等待和传输的长条件核对推进规模与活动状态，不把模拟器初始化/IPC 墙钟解释成目标 CPU 时间。

先从代码和完整职责链确定共因，再集中改完有关模块后进行必要复核。代表机制尚不成立、来源仍缺必要边界、评价不能定位错误时，停留 S1/S2，禁止进入全量矩阵试探缺什么。

冻结前做一次全流程审查：采集/规约/模板/变换/连接、原生控制、资源、执行、应用、桥接、例子和构建均覆盖，不只审查 diff。确认旧路径删除、引用更新、代码表达及数据/镜像一致，完成阶段维护交付。

### S3：全量独立验证，整轮收齐再处理

S2 收口后一次性确定具名矩阵、模型 revision、合法配置、workload/种子、代表来源、留出目标、预期触发机制、评价方法、镜像 ID 和累计预算。先确认原生框架可运行，再进入结构资格判断；原生不支持的组合记录原因，不 patch 框架强行扩大支持。

冻结核心、适配、规约/模板规则、评价、来源配方与输入。来源及目标都由本窗口新采集；每个目标真实案例原则上只采一次，后续仿真和离线比较复用本窗口该份事实。不得从旧 data 恢复目标、借入目标片段补模板或现场改规则。

按第 6 节覆盖完整清单。错误隔离后继续无依赖案例，依赖受阻明确记录；整轮不边验证边修复，也不以存储不足静默取消困难案例。只有资源/安全或预算不允许继续时停止，并报告覆盖未完成。

目标是一次正式全量取得通过；不能承诺零缺陷或用降低判据达成次数。若未通过，先完整报告并按共同根因集中修复，完成静态审查与受影响案例回归后才重新冻结。是否需要重做全量按真实影响决定，不自动启动下一轮、换容易输入或无限增加采集。使用过的差异转为开发证据，新独立资格明确留出边界。

全量报告先记录每例事实是否充足，再记录实际比较范围、结果、第一处差异、责任层及证据。来源失败、预测错误、评价错误、原生限制和预算停止不能混为核心不正确；内部细节未细分也不能与外部依赖未知共用一个笼统结论。

### S4：多机有界探索

在单机验证成立后，沿同一工作/资源/通信合同探索逻辑 rank 到节点/设备的映射、原生控制进程部署、跨机 collective/P2P/KV 传输与完成交接。优先选择一个最小 TP 或 PD 场景，不展开多机矩阵、部署平台或性能模型。

只采用原生框架能运行的配置。具备两机条件时取得一例真实证据；缺少条件时明确静态结论和未验证内容，本机多进程不冒充多机通过。探索性编排留在 example，必要正式接口保持在各自 adapter/核心职责中。

交付可行性、阻碍、所需修改及复杂性判断。探索不修改冻结单机资产以追求通过；必须改变共同核心的工作列为后续正式扩展，不为此重启单机全量。若发现现有单机真实缺陷，保留单机未通过状态并按影响修复，不能以“只是探索”掩盖。

### S5：整理与最终交付

沿本窗口 Git 基线审查全部业务与相关工具，检查分层、唯一状态、资源/引用生命周期、粗图与模板合同、代码风格及可删除的整条链路。无需为旧格式留兼容，不为凑行数删必要空行、注释或把业务迁出统计。

整理公开一键入口、输入例子、精简结果和支持/限制说明。只保留本窗口最终有效资产、必要新来源/真实目标、失败结论与费用；删除已消费 work、重复报告、过期镜像及编译产物。历史失败不改判，数据清理后同步撤下失效引用。

最终对照沿用 S3 的有效冻结证据；只有实际修改影响其结论时才补相关复核，不再机械复制一次同样全量。代码、文档、数据分别检查后，按职责分层提交推送开发分支，核对远端实际提交。未交付或关键结构缺口未关闭时如实保留状态，不进入性能层。

## 5. 验证可信性与错误定位

来源和目标共用事实格式、解析与规约规则，真实图的工作、参数、连接及状态必须来自各自原生运行。预测端不得调用“从目标 trace 构图”来补答案；评价可以共用基础图查询，不借模板选择/展开结果重建真值。两端共享规约可能共同遗漏的边界，须由直接原生调用/状态证据另行核对，不强制开发两套解析器。

| 检查 | 证据与通过要求 |
| --- | --- |
| 事实与范围 | 统一预热、初态、完整角色及观察范围明确；来源闭合、目标闭合和模板发布分别成立 |
| 粗图 | 原生工作有承接，无重复/遗漏；内部隐藏有边界依据；必要输入、输出和中间信号可定位 |
| 模板及变换 | 层/角色共享合理；改变长度、成员和容量能正确求值；分支由原生依据支持，不靠目标修图 |
| 因果与并发 | 数据就绪、CPU 返回、stream 顺序、跨 stream 等待、通信和释放完整，无额外串行化 |
| 动态控制与资源 | 同条件旁路下决策和输出进度可对应，预约/引用/回收合法，两个 PD 池保持独立 |
| 生命周期与规模 | 新任务/恢复、失败不发布成功、预算/清理、无设备纯预测和默认/明细一致，活动图不随历史无限保留 |
| 评价本身 | 正常与负向证据均能定位；工具报错不写成业务差异，证据缺失不冒充 matched |

结果至少区分已匹配、确认差异、证据不足、依赖阻断、原生不支持、工具失败及预算停止。只在相关流程边界确实未知时影响对应结构资格，不能用全局未解释底层记录数一票否决，也不能把未知自动算流程外。

报告先给精简结论和第一处分歧，再给必要取证入口；不以节点数相同、退出码零、总时长接近或所有案例都有状态替代结构通过。

## 6. 全量矩阵的覆盖责任

保留模型、并行、调度和请求泛化责任，按机制及重要交互选点，不照搬旧轮案例数量，也不扩成所有组合。S2 结束前固定具名案例与成本，再执行；未触发预期机制的运行不算完成该项覆盖。

| 维度 | 必须规划的范围 |
| --- | --- |
| 模型与 dtype | Qwen3-8B、Mistral-7B-v0.3、Llama-3.1-8B、GLM-4-9B-Chat、Qwen1.5-MoE-A2.7B、Qwen3-30B-A3B、OLMoE-1B-7B；至少一款 Dense 的 BF16/FP16。模型本地文件可复用，运行资产重新采集 |
| TP/PP | TP1/2/4/8、PP3/4、TP2×PP3/4；不均匀层分配、首/中/尾角色及真实等价 worker 的采集前复用 |

| P/D 组合 | 两池独立、同构/非对称 TP、EP×PD、PP×PD 及八卡内合法联合拓扑；KV 分片、metadata、背压、接入和源释放 |

| 请求与并发 | 1/2/3、31/32/33、64、101/128 成员边界；单 token、页边界和多页 prompt、输出 1/2/32/64，长上下文与实际显存/模型上限一致 |
| 到达与持续运行 | 同步/错峰/突发/空闲后再到达，64/128/256 请求混合长短序列、退出和槽位复用；核对实际形成的 batch 而非只设置容量 |

## 7. 产物、环境与采集纪律

S0 清空旧 data 后，建立一个本窗口 UTC 时间根；所有来源、目标、资产、报告及临时工作归入该根。阶段子目录不再另造大量顶层时间目录。正式默认输出精简，完整原始 trace/展开图只按必要生产或诊断用途生成和保留。

    data/<UTC>_coarse-graph/
      inputs/                 固定输入、环境/镜像依据、来源规划及矩阵
      sources/<domain>/       本窗口来源事实、来源粗图及必要采集范围
      assets/<domain>/        唯一正式模板库
      targets/<case>/         独立真实粗图、状态及必要边界时间
      results/                精简预测、逐例结论和全量报告
      logs/                   真实命令与错误
      work/                   可回收的导出、编译和解释中间件
      diagnostics/            显式需要的原始 trace 或局部明细

原始 trace 可以在 work 临时生成，粗图和必要事实发布后按消费者释放；支撑当前验证争议的原始证据保留至结论形成。不能先删除唯一证据再宣称覆盖完整，也不长期保留无消费者大 JSON。数据身份由现有输入、角色和实际生产环境交接，不新增版本平台、指纹账本或多份库存。

镜像标签保持按职责稳定命名，运行记录实际 ID。采集包、控制包、SDK 或复制资源改变后统一重建受影响镜像，验证安装路径及入口未引用旧模块；核心在 modeling 内重新构建。正式运行不临时挂载旧 Python 包覆盖镜像，也不因标签相同沿用旧资格。

采集前先静态说明问题、缺少的事实、不能靠现有代码确定的部分、运行范围及结束条件。代表来源覆盖预先声明的有限机制；每个独立目标原则上一次真实运行。解释、模板及仿真变化优先复用本窗口事实，不因 CPU 后处理失败重新启动原生。

原生、后处理、临时/保留存储和尝试数在每阶段执行前明确累计上限，失败及恢复不清零。存储按全量输入与必要原始证据规模预估，不沿用导致中途取消的过小额度；达到上限先交付实际覆盖和原因，不能偷偷扩额或换输入消耗。

## 8. 实施节奏与维护交付

每批先自顶向下追踪入口、生产者、消费者、状态所有者和生命周期，写清不变量及待删除路径，再完成整个模块或功能链。跨文件重写可以一次大范围完成；静态审查不能只查格式，运行通过也不能证明代码没有问题。

C++23、Python 3.10、面向实际职责的类与组合；必要浅层继承/模板表达差异，不堆防御分支、默认值、兼容层、异常包装或重复转换。逻辑块适当空行，身份/所有权/完成关系等重要位置写必要注释，独立注释上方留空行；不修改 .clang-format。

完成模块及相关调用方的静态检查后，统一进行受影响构建和最少正式入口运行。不每改一层就编译，不用扩大验证代替开发；没有新改动或未决问题时不重复同一验证。

每阶段启动先根据上一阶段交付和现状调整当前及后续范围；结束时核对 Git 阶段差异和全部关联代码，完成职责/正确性/风格/删除审查及文档、数据检查，再按 type(scope): summary 分层提交推送开发分支。提交集中在阶段边界，不为每次日志或局部改动单独提交。

计划只维护任务和规则，status 只维护当前状态、资格与下一步，log 按日期正序记录“范围、改动、验证、结论与限制”。不创建第二套滚动报告；全量报告作为实际结果保存在运行根，文档只保留必要摘要。阶段未通过时保留问题，不把整理、跑完矩阵或结束窗口解释为功能通过。
