# 粗粒度执行图工作流计划

开始日期：2026-11-05。

目标：从原生事实形成可信粗图和参数化模板，在目标配置与请求下动态生成执行结构，完成单机独立验证，再作有界多机探索和工程交付。本文件只维护任务、方法与判据；实际状态和行动分别记入同目录 status.md、log.md。

## 1. 范围、方法与职责

输入为固定模型、配置集合和请求 workload 集合，系统选择代表来源，用户不指定 base。原生控制维护请求逻辑、组批和准入；核心唯一维护槽位、KV、前缀状态、内容就绪、在途工作与模拟时间。

本轮交付单机 TP/PP/条件 EP、P/D 分离及合法组合、等价 worker 采集前复用、chunked prefill、mixed、原生 Decode 准入/预算和一级 prefix cache。各机制分别取得来源、结构与控制证据，已有运行成功不自动授予新规则下的资格。多机只作最小证据与扩展边界探索。

轻量控制器推进、真实权重自然路由、数值计算正确性、overlap/speculative 扩展、多级缓存实际搬运、泛化性能采样/成本模型和精度验收不属于本轮。固定真实案例的成本与事件条件可用于结构验证，不算性能层建设。

### 正向流程与规律来源

    来源原生运行 → trace、语义边界及必要状态事实 → 来源粗图 → 切分、参数化与归一化 → 模板库
    目标配置与请求 → 原生决定动作 → 模板选择、有限变换与连接 → 目标粗图 → 执行与完成反馈
    独立目标原生运行 → 各自真实事实与粗图 → 分项检查内容、连接、资源及控制交互

一次观察只证明该次执行；泛化规律须来自原生模型元数据、实际 ABI、明确代码逻辑或有限适配声明。实际观察值、参数关系和运行状态分别维护，不从少量样本拟合 shape，也不从重复次数猜任意循环。观察之外的分支必须有明确适用条件和取得实现的途径。

方法先证明四件事：真实图保留约定作用；模板能表达声明范围的变化；子图可正确连接并保护资源；独立评价能识别错误。完整虚拟化与旁路提供可控输入，不能替这四项取得资格。每项规律都要说明来源、适用范围、所有者、目标求值方法及检查依据，不能以新增案例分支代替方法收口。

| 层次 | 维护边界 |
| --- | --- |
| 框架 adapter | 原生动作、模型/批次 ABI、算法与分支依据、并行角色、控制接入和原生接口虚拟化；不复制调度器或资源账 |
| runtime adapter | API、队列、stream、事件、传输及存储事实解释；区分观测与业务作用，不选择批次 |
| 共同核心 | 图与模板、参数求值/选择/连接、唯一资源状态、模拟时钟和事件、耗时及受控输入接口；不识别框架函数、模型名或 SDK 私有名称 |
| 外围应用 | 单任务进程、部署/镜像、累计额度、发布与恢复；不暗中生成模板或决定控制策略 |
| example | 案例、矩阵、旁路事实准备、独立比较与归因；不被 src 导入，不复制核心算法或单任务生命周期 |

先按职责确定组织，再决定旧代码取舍。C++ 头源同目录；替代的类型、源文件、CLI、导入、CMake、Docker COPY、安装资源及说明整链删除，不留兼容入口、活动 legacy 目录或纯转发包装。

## 2. 阶段顺序与交付边界

S0–S2 保留原定义与历史资格。插入六个前置阶段后，原 S3 全量验证顺延为 S9，原 S4/S5 顺延为 S10/S11；原 S3.A–E 的任务按下表重新分配，旧编号只解释历史记录，不作为并行计划继续维护。

| 阶段 | 主要交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| S0 清理与环境核对 | 干净起点、代码取舍、明确镜像与数据归属 | 旧默认入口及资产引用关闭，迁移边界明确 |
| S1 粗图主链重建 | 采集、粗图、模板、原生控制、资源、展开和反馈的唯一正式链 | 完整职责链静态审查、集中构建及阶段维护交付 |
| S2 初步机制见证 | 最少代表案例与初步评价证据 | 保留已证范围和缺口，能够区分来源、核心、控制及工具责任 |
| S3 方法与验证合同 | 泛化范围、规律来源、图边界、分项证明责任和实现取舍 | 每类变化有完整推导；不能成立的假设先调整，无决定性方法问题悬置 |
| S4 真实粗图与验证基础 | 原始事实到粗图的可信链、独立来源检查及必要反例 | 保留作用、投影和测量可核对，代表边界可检查，缺事实可定位 |
| S5 核心虚拟执行环境 | 模拟时钟/事件、原生截获、实测成本与受控输入交接 | 声明路径的决定性外部输入闭合，宿主快慢不决定模拟结果 |
| S6 模板提取、归一化与有限变换 | 层次模板、参数/分支/重复合同、有限来源与选择装配 | 给定真实动作时能独立生成代表目标子图，不借目标补库 |
| S7 子图连接与资源执行 | 数据/版本、stream、通信、跨池及在途生命周期的统一连接 | 实际绑定、必要因果和复用安全成立，局部与整图证据分开 |
| S8 原生控制闭环与冻结准备 | 同条件下原生决定、资源反馈、正式入口及评价闭环 | 代表交互成立，首处分歧可归因，矩阵、环境与评价达到冻结条件 |
| S9 冻结全量独立验证 | 完整覆盖、分项资格、失败归因与报告 | 关键结构缺陷关闭，未取得资格明确，维护交付完成 |
| S10 多机有界探索 | 最小证据、可行性及扩展代价 | 有界结束，单机冻结结论不被探索改写 |
| S11 最终交付 | 全链审查、有效资产、公开入口和支持说明 | 必要复核、清理及分层提交推送完成 |

各阶段先依据代码和已有事实确定整条机制，再集中修改和做必要验证；大矩阵只属于 S9。除本阶段所需的最小见证外，不重复运行已合格机制。编号调整不抹掉原失败、未完成范围或已有证据，也不意味着所有旧模块重写或全部真值重采。

### S0–S2：保留原交付边界

- S0 核对 Git 起点与用户改动，清理本项目旧运行数据、旧默认引用及专属无消费者镜像/容器/编译产物；保留模型、依赖缓存、参考源码和其他工作区，不执行全局 prune。初始清空只属于 S0，不因后续阶段重排再次清空当前证据。
- S1 自顶向下贯通输入、采集、解释/规约、模板、原生控制、资源执行、反馈和结果，同时纳入目标真实图与评价入口。先单 worker，再 TP/EP、PP/PD；仅接通 RPC 或元数据通道不算闭环，旧逐操作调度与细图评价链删除。
- S2 用有限 Dense、调度/缓存、TP×PP、EP×PD 和缓存压力案例取得初步见证，分别检查来源、评价工具及动态交互。同源还原、初例成功、短/长给定耗时不替代泛化、真实长在途或未触发分支资格；不重新定义历史阶段为通过新的全部要求。

### S3：先说明方法怎样成立

输入为现有源码、原生框架代码、正式入口、有效事实及未解差异。先静态追踪“动作从哪里来、观测如何赋义、模板如何生成、变化如何求值、连接如何建立、何时反馈”，列清各环输入、输出、状态所有者、原生依据及 core/adapter 分工。

按变化来源区分参数变化、已有分支选择、控制器新增调用、资源/端口重绑定与必须新取来源的实现变化。特别说明固定层重复、逐请求控制循环和模型内部条件调用的不同所有者，以及同 shape 下布局、路由、索引或内容条件改变结构的情况。不能把 trace 中看见的两次执行直接推广为任意次数。

在本计划内以精简表格维护方法与范围结论，不追加源码级实施记录：每类变化有规则来源、可维护实现方式、适用/停止边界及独立检查办法；证据需求可直接指导下一阶段。若泛化仍依赖逐模型/逐目标人工补分支，先调整边界或方法，不以虚拟化、补采或修好某个 PD 案例代替论证。

结束条件是四项核心问题有具体可执行的解法和受限假设，而非声称已经验证全部模型。无法论证时明确阻断哪项能力及所缺依据，停止该项扩张；不启动原生矩阵探索答案，也不另造方法文档平台。

#### 方法依据与统一生成边界

下面按工作区源码中的实际职责明确规则来源；表格约定实现与检查边界，不授予全部输入或模型的运行资格。继承的未交付实现仍归后续阶段，不因本阶段文档交付成为合格业务基线。

| 变化或事实 | 生成依据与代码落点 | 必须保持的边界 |
| --- | --- | --- |
| serving动作及父子切口 | 原生方法实际执行，共享[调用分段](../../../src/adapters/markov_adapters/sglang/calls.py)交接进入、暂停、继续和返回 | 模板不决定下一动作；父包络不再次展开子工作，原生逻辑状态与核心资源状态各有唯一所有者 |
| 参数、shape和层间关系 | 原生ABI/模型元数据提供声明，[模块边界](../../../src/collection/markov_collection/adapters/frameworks/sglang/module_scopes.py)与[参数传递](../../../src/collection/markov_collection/instrumentation/)中的ScopeParameters维护上下文，编译核对实际值 | 一次观察核对声明，不负责自动发现任意公式；内容、布局或算法条件不能被相同shape掩盖 |
| 定义共享与调用绑定 | [模板编译](../../../src/markov/production/templates.cpp)规范化局部结构，定义与frame分别保存结构和调用绑定 | 同结构共享，不把调用次数、地址、rank或具体请求做成新定义；不以定义相同证明guard完整或目标分支已覆盖 |
| 已有局部实现间切换 | 原生依据声明guard，[选择器](../../../src/markov/templates/selection.cpp)在接口及共享绑定相容的候选中递归选择 | 空/正维度保护只是必要条件之一；保留观察到的父体，不能将缺少的循环或分支当作shape缩放；歧义须回查规则来源 |
| 执行次数变化 | 调度/逐请求次数由原生控制组织，固定模型层来自模块结构，必要索引循环通过[共同框架适配](../../../src/adapters/markov_adapters/sglang/)中的AllocationIndices复用原生helper切口 | helper的AST/局部变量识别属于具体框架实现适配，不是通用循环推断；内部重复若外露中间效果，须有明确端口与组合依据 |
| 跨子图与跨rank连接 | 目标动作绑定storage/version和资源，[依赖服务](../../../src/markov/execution/dependencies.cpp)连接数据、状态、signal及已读取完成事实 | 切分不复制来源的历史前沿；每次连接依赖目标实际所有者和生命周期，不借真实目标边作答案 |
| 服务时间与控制条件 | [serving闭环](../../../src/markov/serving/session.cpp)统一提交工作、推进时间并反馈；S5收口逐工作耗时与事件输入 | 均匀given和稀疏边界只提供局部条件，完整虚拟化还需覆盖决定性原生时间读取；不能由宿主墙钟决定分支 |
| 原生事实到粗图的核对 | [来源检查](../../../example/coarse_graph/source_evidence.py)从独立事实重建覆盖与边界约束，再比较投影 | 该项证明解释后事实到粗图的承接；解释前遗漏仍须从原生API/队列/状态独立核对，不能用同源还原代替 |

实现资格以有限原生接口及其规则为边界。新模型沿已有ABI可复用机制，新增实现差异在adapter维护；请求或容量变化本身不要求逐例适配。条件是否充分、内部变化能否封装及跨图因果是否完整，须分别沿原生实现证明，不能因选择器返回唯一候选就推定成立。

#### 变化的处理顺序

| 变化 | 采用的方法 | 适用依据与停止边界 |
| --- | --- | --- |
| 只有数值或绑定变化 | 原生元数据/调用参数形成表达式，目标求值shape和范围，重绑rank、池与存储版本 | 模型/ABI/机制域及结构条件相同；单个来源数值相等不能生成表达式 |
| 进入不同已知分支 | adapter依据原生实现声明条件，有限来源取得各实现，核心按guard与完整接口选择 | 条件须解释所有会改变保留作用的分支；仅有零/正维度保护不算完整，不能按目标标签新增变体 |
| 动作或循环次数变化 | 原生控制执行真实逻辑，逐次提交统一动作；固定层按原生模块绑定，内部重复只采用已证明的组合 | 可安全执行的纯索引helper沿真实循环切口交接；无法从目标输入确定的内部调用组合不由核心猜测 |
| 内部细节变化而接口稳定 | 在粗图合同下封装已证明封闭的工作，只保留必要资源片段、同步和外部端口 | 同边界shape/可达关系不足以封装；还须检查资源共享、跨界依赖、中间消费者、异步尾部及完整成本责任。不成立则保留切分或相应实现 |
| 实现域或接口变化 | 模型/dtype/并行/backend/页及机制域变化重新取来源；未知ABI由adapter维护一次差异 | 重新采集取得实际实现，不自动推导未知语义。不能保证任意模型零适配，但不得为每个请求/容量新增模型分支或核心代码 |

来源规划以这些有限结构条件为需求，采集前给出见证及成本，再核对实际触发。模板种类应由保留的资源/接口结构及有限条件决定，不随请求数、kernel数或目的地排列增长；若仍增长，先审查切口、封装或规则来源，不继续枚举输入补库。

#### 四项核心问题的实施解法

| 问题 | 统一处理方法 | 后续阶段必须取得的证据 |
| --- | --- | --- |
| 真实图从哪里来 | adapter先声明实际原生动作及数据/状态/同步边界，runtime关联API、队列和事件；共同投影只承接已解释事实。内部payload与公开端点分开，只有影响保留端点的顺序必须进入图 | S4从原始API/语义scope和小型状态/注册事实检查作用，再独立检查事实到粗图的完整映射；解释前遗漏与投影丢失分别定位 |
| 模板如何泛化 | 参数规则、有限条件、原生控制次数与已证明封装分别处理；固定父体中的相容子实现递归选择，定义与绑定分离 | S6核对规则来源、条件充分性、规范化与实际分支。来源取值符合公式只是必要检查，唯一候选和同源还原不证明泛化 |
| 子图如何连接 | 目标按真实生产者/版本、逻辑访问、组/端点、完成代次及资源所有者接边；控制读取通过实际已完成事实影响后续动作，资源状态由核心唯一维护 | S7分别证明跨图关系、物理绑定与在途安全，S8再核对读取/决定/反馈。真实时间可能改变合法保护边，不要求两次物理分配或所有内部边逐条相同 |
| 如何可靠验证 | 原始作用、事实投影、局部内容、整图连接和控制交互分项检查；构图时给定真实动作，控制检查时真实动作是输出，来源与目标隔离 | S4准备独立事实与必要负例，S6/S7/S8只补各自所需见证，S9冻结全量。比较器不得从预测补真值，局部通过不冒充整例通过 |

两个具体依据约束后续重构。其一，[gather布局条件](../../../src/collection/markov_collection/adapters/runtimes/pytorch/layouts.py)对应原生NPU communicator的连续输出缓冲、movedim与reshape：是否物化由组宽、轴前尺寸积、该轴长度及空维度决定，可由这一ABI推导有限条件；该结论不推广为其他函数自动具有充分guard。其二，[stream解释](../../../src/collection/markov_collection/adapters/runtimes/ascend/commands.py)须先根据实际队列提交识别同一工作的不同API观察，再确定必须保留的边界和因果，最后判断内部作用能否封装。原始SDK任务坐标保持不变；图中的命令坐标另行生成。没有直接SDK任务不等于额外一条设备命令，也不等于没有工作。必须外露而无法定位的作用仍报缺口，不能整体丢掉异步拷贝，不能仅更换时间端点就宣称方法问题解决。

完整虚拟化覆盖支持路径的决定性输入，而非全局替换Python的time模块。原生超时、会话维护和PD重试等读取须按实际配置/消费者分类，统一时间原点及单位，在读取前交出必要CPU工作；日志、进程期限、join与清理预算保留真实墙钟。当前接口之外的机制不因原生源码存在而自动纳入，但实际启用且影响决定的条件不得遗漏。

受控时间验证采用参与者各自的因果输入流：从共同激活点开始，每次先核对原生接口/继续位置、具名实参、已交付输入及必要前置事件，再消费下一份测量约束。消费位置是已验证历史的延续，不是独立匹配键；不按全局第N次调用硬配，不跳过不符记录寻找相似项，也不由提供者选择下一动作。重复查询可以据此取得受控对应，前提是原始事实足以核对这条链；事实不足仍停止相应资格。普通跨运行结构对照与旧稀疏文件保持各自规则，不能用新增计数伪造对应。

### S4：建立可信事实与检查依据

按第 3 节集中收口原生观察、API/队列解释、粗化、角色与状态事实及原始到粗图映射。优先处理会影响外部作用的遗漏、错误归属、观察标记残留和提交/完成混淆；原始事实已足够时离线重产，不为后处理失败重采。

独立检查直接读取原始 span、原生端口、资源及通信事实，核对完整覆盖、边界和必要因果；验证明细记录原生作用到保留工作/等待的对应，检查方从原始API和队列记录反查遗漏及重复，不消费生产解释器的排序结论。不能只问保留节点是否有来源，也不能调用核心投影或模板求值器重建真值。必要反例涵盖遗漏工作、重复覆盖、错端口/shape、无依据依赖、错通信伙伴和测量改写，工具报错与结构差异分开。

原生全rank、池和传输检查须可在来源侧独立运行；从既有对照链提取共同的原生事实表示和检查，不以预测执行流作为核对原生的启动前提，也不复制框架/几何规则。以最少机制案例确认检查办法和生产链：主机、设备、异步完成、跨 rank 及状态边界都有取证入口；SDK 内部未测时间与必要作用缺失分别报告。只对合同保留的作用要求完整，不扩大为每条底层事件逐次对应。

地址派生状态通过原始注册缓冲区、实际复制地址和请求页表检查：把图中逻辑访问反向映射到物理范围，与真实复制覆盖比较；共享原生布局 ABI，不调用生产端的逻辑区域生成器。调用对象以显式张量/状态端口及其所有者、版本和生命周期为边界，不为后续虚拟化预建任意原生局部变量快照。

结束条件是事实交接与评价基础可用，负例能定位，缺口能落到具体原始依据。关键边界无法解释时停止相关资格；不要求此时跑完七模型，也不把两张共享漏项的图相同视作来源正确。

### S5：实现核心虚拟化与验证旁路

沿已确定的支持路径盘清决定性外部输入，集中改造时钟、事件/消息、完成可见性、等待、超时和 CPU 服务推进。原生保留决定，adapter 截获接口，核心统一执行；不虚拟化整个操作系统，不让 Python、IPC 或宿主线程快慢决定模拟时间。

复用既有动作、耗时、通知、资源和执行接口接入固定案例的实测服务与事件条件。给定动作用于验证构图，实测成本/到达/完成条件用于验证原生控制；两者使用同一执行器，输入了哪个模块的答案就不授予该模块资格。不另建回放调度器、并行资源账或泛用注入平台，完整替换被取代的稀疏时间特例。

实施次序先收口控制器的外部读取切口，再连接 CPU 服务与模拟时钟，最后贯通受控输入和正式入口。资源容量、独立字段槽位与 Event/PD 查询先提交此前 CPU 片段，再读取当前状态；资源实现内部的检查归核心资源服务，观察器快照不生成业务查询。原始 getter 的描述、量纲、返回值和调用区间用于独立核对，不能以查询次数一致代替读取对应。

主机实际读取张量的动作独立声明：共享适配器在原生物化调用发生时切开父片段，将具名输入的完成读取归属到该调用返回；采集和控制使用同一切口。结果处理入口只登记可读取的对象，不因进入函数就认为已经消费，也不按首段或后续段位置推定是否纯CPU。输出发布与输入物化分别维护；未发生的读取不生成动作，旧观察不能补写新作用域后冒充实测。

时钟按实际消费者接入：请求超时、PD 重试/超时及其他有效控制条件使用核心时间；预算、进程存活检查和诊断墙钟独立保留。适配器替代原生设备/网络实现时，仍须保留原生状态推进与失败条件，不只复刻成功路径。通过共同服务/事件输入接口贯通 CPU 消息、Work 等待及状态可见性，同时建立有操作、对象和前置事实校验的参与者输入流；完整替换旧稀疏时间实现，不按全局调用次数强配，也不注入控制决定。

CPU 点对点协议由共同运行服务表达，不扩张语义模板：实际 post、传输就绪和 Work 消费分别交接，阻塞 API 内部的等待不重复计费。broker 只维护数值及原生通道位置，核心唯一维护完成、挂起和放行；采集保留每个参与者的实际区间与上下文，不受代表设备采集选择限制。初始化是明确的窗口外初态，排空时只可取消不再影响 serving 的私有等待。显式给定的服务时长仅为开发假设，正式受控输入仍须支持缺成本、完成条件及因果校验；独立对照检查这些服务的结构和就绪，不将它们误认成模型模板调用。

逻辑身份与传输特征分开维护：CPU操作以请求/控制上下文、通道、方向及dtype绑定，实际shape/元素数/字节数由协议descriptor保存并校验本次两端。原生请求与无设备控制对象的私有序列化长度不必相等，不能以缓冲长度取代控制语义，也不能为对应真值强改本次载荷。时间旁路验证给定条件下的控制和因果，不证明跨运行字节量或CPU性能；后续性能建模仍须明确真实服务对应的输入特征。

受控输入按全部实际参与者维护已核对前缀，每一步比较操作和完整逻辑上下文，重复读取仍保留其真实位置；不得以游标单独匹配或在记录不足时退回给定耗时。动作条件引用独立图的具名端口，内部未知工作沿真实DAG推导完成上界；不通向原语义端口的异步尾部，可使用参与者显式声明且由同步排空证明的观测窗口。窗口只约束未测完成、保留未知服务，不增加依赖或精确时刻，不以局部资源编号配对；既无因果上界也无声明窗口时仍拒绝，输入不包含目标图体。CPU传输引用已经核对的实际post位置，通知保留逻辑生产者身份，二者仍依赖真实提交/完成关系。完成时核对全部记录已消费，首处分歧优先于后续轨迹差异。

时间提取复用共同原生检查并保留测量资格：CPU直接RAW测量可给精确点；设备时间保留同一仿射校准可行区域的区间包络，须满足跨未测节点的已测因果关系，不能把名义中点当精确RAW。分开交接的包络不证明一次联合校准实现；没有测量的边界至多使用已同步排空的观测窗口，显式标为宽区间。这种partial输入可检查机制和定位不足，不能保证唯一控制轨迹；需要更窄条件时补足决定性边界事实，不按目标残差调时间。输入准备、正式执行和独立对照分别维护，不能把“满足所给条件”写成“已对应全部真实条件”。

结束条件是原生入口—adapter—核心—消费者对应清楚，最小公开流程可受控推进；加入宿主延迟或改变无关 IPC 到达先后，不改变共同虚拟输入规定的结果。无必要因果的并发按语义等价判断；缺输入、矛盾约束、未知成本及无安全等待条件均能定位。此时不要求自主成本预测。

### S6：生成可复用、可变换的模板

按第 3 节的模板与来源合同整链处理切分、声明、编译、发布、链接、选择和实例化。统一动作/模型层次，分离共享定义、子调用组合、参数与资源绑定；模型元数据、实际调用和有限原生规则提供参数关系，禁止以 batch 大小、相邻调用排列或轮询次数扩张类别。

分别收口固定层共享、局部 ABI/guard、空/非空和布局分支、父子接口及重复来源。专家局部实现以实际初始化模块结构判断等价，和采前worker角色选择共用结构读取；模块路径及真实权重/资源归属留在调用绑定，不能以具体层路径阻断等价层分支复用，也不能只因接口shape相同就混合不同内部几何。逐请求循环优先复用原生纯索引/控制 helper，采集与控制共用切口；核心不复制原函数或猜循环。已有实现先查声明和装配，再判定是否真缺来源。

来源按目标集合预先规划有限机制见证，并在采集前选择等价 worker。真实动作和调用参数可作为输入；模板选择、shape、工作及内部依赖必须从来源独立生成。核对重复层/角色共享但资源独立、跨层独立条件组合及同一调用位置的子调用数变化，不以层数不同或叶子空工作冒充后者。

当前固定输出ABI中的result由独立host_read、资源及publication动作交接实际作用，剩余CPU片段由同一adapter分类函数归类，并在来源声明时检查其封闭性；不按相邻调用的排列组合扩张候选。设备观察保留，含额外张量、状态、等待或设备工作的片段必须完善切口，不能归为CPU剩余。完整continuation仍用于工作身份及时间对应，模板结构共享不等于耗时共享。

结束条件是代表变化在明确来源域内取得局部构图证据，所有变换有依据、guard 和边界；缺来源、参数关系错误、候选歧义、装配遗漏分别定位。不可达分支保留未验证，不逐长度补库，也不将局部通过写成调度或跨图通过。

阶段按完整职责链分三批推进，不把每次试跑当成一个阶段或提交边界：

1. **整理表示和声明。** 从已交付S5基线检查切口、参数传递、共享定义、frame绑定、接口及有限实现链接。 同时核对来源与控制端的原生框架/环境身份，不能只凭framework名称认为实现域相同；身份从实际部署和上游元数据取得，不维护手写内部版本，采集插件变化与原生实现变化分开判断。 镜像构建从干净的官方工作树自动取得Git提交，来源清单/worker、模板域及控制端交接同一个上游身份，实际控制Torch亦须一致。缺失或不相容在正式启动前定位；已有事实只可在真实不可变镜像代码证明充分时显式作一次性元数据转换，不能补写事件、测量或动态读取。表达式只消去不会改变受检整数运算语义的中性项，不重排长运算、不吸收零、不从观测值造公式。独立检查只在已知表达式字段使用代数等价；请求列表、区域、别名和资源仍按真实数据核对。模块层次先由已有原生结构证明；MLP/归一化等若需独立复用或变换，再在原生模块边界补声明，不按模块数量扩张wrapper。
2. **独立生成局部目标图。** 用冻结来源、真实动作/参数及显式目标绑定调用正式选择/实例化入口；输入不给目标工作、shape答案或内部边。实验编排和独立内容/边界比较留在example，复用现有原生表示和检查，不把真实动作改成另一套调度器，不为验证扩张核心任务语言。示例可从真实粗图经adapter取得动作描述，但构图器只接收动作条件、参数和逻辑work，不能取得目标端口/工作/边或编译目标库。条件描述本身属于给定前提，不因此取得正确性资格。外部值、池和信号可用符号绑定以隔离连接/资源；内容仍核对等待合同，动态stream前沿依赖单列交给S7，不能复制目标时序边使比较通过。同源还原与留出目标分开报告。
3. **补最少机制见证并交付。** 覆盖同域shape/容量、层与等价角色绑定、空/非空与布局分支、跨层独立条件以及同位置内部子调用数量变化。先盘点有效事实和来源域；必要新证据单独说明范围/额度，不恢复旧读取规则、不以目标补库。集中修改后统一构建及最小检查，最后从Git基线做全链审查、仓库整理和分层提交推送，才进入S7。

S6联合机制见证配方合并采前worker复用和naive索引helper两项要求，避免分别扩大采集：同Qwen3-8B BF16、TP4/PP1、page16，来源先选等价角色后观察，目标观察全部worker。来源分两组：第一组prompt3201/3200且各1输出，第二组prompt17/16且输出2/3；目标一组三请求prompt1600/1601/16、输出1/2/3。来源KV16384/4槽位，目标KV32768/8槽位，max_prefill_tokens8192，均无prefix/chunk/mixed。实际NPU分配器以200新页区分Extend kernel/naive，所选来源分别覆盖401页/3页，目标202页进入naive；helper每次成员数2→3并同时保留整页/尾页两种索引分支；目标将整页成员放首位、尾页成员放次位，交换来源首/后成员的分支组合，核对存储交接不依赖该顺序，来源也有单/多成员Decode。该数值是原生分支依据，不是拟合阈值；实际是否达到对应调用、观察哪些角色仍从原生事实确认。先冻结有限配方、累计额度及源代码，再收齐目标局部结果；若未达见证条件先分析根因，不自动增加运行或把此例当全量验收。实验编排留在现有example/任务调用方，不为配方增加核心开关。

### S7：连接子图并维护唯一资源状态

按真实 storage/version、逻辑 KV/字段范围和 stream/通信合同动态连接，原生每次动作仅展开自己的入口，子图不继承来源窗口的前后序列。统一处理父子导出、原地写、数据/metadata 端口、Event/Work 代次、目标提交前沿、通信绑定及跨池访问。

资源操作仍由原生决定何时发生，核心唯一维护页、槽位、前缀和独立行池；其实际设备维护工作保留为动作。联合收口普通分配、淘汰、分组归还、请求完成、PD 预分配/传输/释放及首 token 字段，不能只验证本地页数或最终空闲量。

先用真实动作驱动整图生成，独立检查实际输出/生产者、通信端点、读写版本、物理绑定、历史在途访问及释放条件。跨运行暂时不能逐次对应时，预测自身的数据、信号、通信和物理冲突仍须完整检查。

结束条件是必要数据/通信因果和复用保护成立，无无依据屏障，活动状态随消费者回收。运行内安全、目标与真实对应、跨图完整次序分别报告；实测完成前后的合法等待差异不直接算缺陷，也不能因此豁免真正的错接。

实施按三条完整职责链收口，每批先审代码再集中修改与必要验证：

1. **存储与在途访问。** 联查动作的存储/版本和活跃绑定、依赖服务的发布与访问区间、资源归还失效及时间线回收。逻辑归还清除旧内容，不删除未完成访问；已归还且无在途访问的页/字段记录及时回收。独立运行内检查同时覆盖外部张量、KV及字段的跨调用覆盖冲突，分别报告生产者就绪和物理复用保护；不能因调用未配对而跳过。
2. **连接与整图生成。** 盘点当前可复用真实动作、资源操作及绑定事实，明确驱动正式构图/连接入口所需输入。stream提交前沿、信号代次、通信参与端点及跨池访问各有唯一所有者；真实动作可给定，真实图体和连接边只供比较。先完成所需能力，再集中核对普通、并行及PD代表事实；若既有事实不够，先说明缺什么及最少取得办法，不扩展矩阵找答案。
3. **生命周期与维护交付。** 核对归还/淘汰、请求与字段复用、未完成设备尾部、单侧传输及跨rank消费。以必要真实输入和隔离反例确认检查能定位错接/漏接/提前复用，保留未触发机制与时间限制；最后整体审查、整理仓库并完整分层提交推送，才进入S8。

连接核对优先复用正式serving与已校验的真实参与者操作流：每步先核对实际动作/实参/工作及已交付历史，再消费成本/事件条件。在该共同动作前缀内独立生成模板体、资源与连接；动作一致是本项前提，不据此另授予控制决定或唯一时序资格。前缀分歧时报告首处位置，后续连接不强配；不为验证维护另一套控制器或复制原生资源策略。

动态stream等待需记录实际接收/等待边界的激活事实及其产生的连接归属；完成记录不能反推激活。独立检查从图的提交声明和激活/完成记录重建队列，核对等待只连接当时已接收工作及已完成前沿，覆盖空队列并排除晚到提交。观察不输出队列答案，不改变执行状态；旧记录缺该事实只保留证据限制，不离线补造。

原生适配的提交与返回同样属于连接合同：已经取得完整输入/访问声明的动作，须先进入核心时间线，再等待其结果或跨参与者数值；原生返回对象须继承本次图真正发布的storage/version。数值通信沿现有异步post、图执行、Work消费的顺序，原生保持值和控制所有权。不能等一个阻塞方法全部返回后才回填已过去的入口，也不能将尚有未确定状态效果的函数直接提前完成；先沿实际原生方法核实封闭性及切口。该职责在adapter修正，不放宽测量窗口、不复制归约或按模型增加分支。

非阻塞状态读取在一个模拟时刻完成“读取工作返回→原生读取→结果交回”。核心持有本次读取边界直到结果返回，明细关闭时也执行相同交接；下一动作不能越过未交回的结果。成功读取只记录已经完成且不晚于该边界的实际原因，既连接本次返回，也保留后续工作保护；失败读取保持查询语义，不等待被查询的工作。阻塞操作用已有等待/服务表达，不能塞进非阻塞读取。独立检查核对实际读取所消费的完成或可见通知及其返回关系，不将“存在通知”“后续有保护”当作当前读取已经正确连接。

### S8：闭合原生决定、资源反馈与公开流程

在共同到达、初态、原生配置和充分的成本/事件条件下，执行单 worker → TP/EP → PP/PD 及必要组合。组批、查询、准入和资源操作必须由原生与核心产生，真实决定只作比较输出。先查首处条件分歧，再查决定、工作与连接，不逐项修复后续轨迹差异。

贯通输入/轮询、原生整轮推进、资源读取、动作、完成、可见通知、安全停驻/唤醒及最终排空；检查同刻到达、空轮转、滞后输出、缓存和长在途条件。旁路未控制的决定性因素明确保留资格缺口，不能由稀疏时间推定唯一轨迹，也不把所有差异归于时间。

正式集合规划、有限来源执行、生产、装配、一键预测及恢复共用同一单任务能力，用户无需编写内部 worker 任务。验证编排留在 example，正式能力留在 src。检查默认/明细一致、无设备预测和必要生命周期反例，不为每个编排入口另采一遍。

结束前完成全流程审查与维护交付；固定 S9 的具名案例、revision、输入/种子、来源配方、实际预期机制、原生前提、镜像/程序、评价规则和累计预算。未解决关键来源、构图、交互或评价问题时返回对应阶段，不启动大矩阵寻找缺口。

### S9：冻结并完成全量独立验证

保留七模型、40来源域、52计划来源作业、58独立目标及8项生命周期探针的覆盖责任；按第 4 节选择机制和重要交互，不扩成所有组合。数量不是新一轮原生执行指令：复用本窗口有效事实，变更配方时说明职责和覆盖映射，不能静默删掉困难项。

冻结核心、adapter、解释/规约/模板、评价、来源配方和输入。目标独立观察全部 worker；来源使用正式 plan-sources 的全部有限作业，主来源按显式目标域映射选择，辅助库按局部合同装配，不能退回每域单来源或扫描历史目录。目标真实图独立生产，不以编译目标模板为前提，也不借目标补库。

整轮只执行冻结方案，错误隔离后继续无依赖案例；原生初始化、生产、预测、工具、证据及额度失败分别记录。达到资源/安全或预算边界时交付未完成覆盖，不静默取消。中断/坏资产反例使用专门任务或副本，不能破坏独立真实目标。

报告先给事实覆盖、实际检查范围及各项资格，再给确认差异、首处可判定分歧、责任和证据。整轮收齐后按共因制定完整修复；如需改代码，结束当前冻结批次并回到对应阶段，相关最小复核后重新冻结。根据真实影响决定回归范围，不自动重采、重跑全量或更换容易输入；用于修复的目标转为开发证据，新的独立资格另行声明。

结束条件是关键结构缺陷关闭、覆盖与未取得资格完整、报告和阶段维护交付完成；跑完、退出码零或 partial 数量下降不等于通过。

### S10：多机有界探索

单机资格成立后，沿相同合同探索 rank→节点/设备映射、原生控制部署和跨机 collective/P2P/KV 完成交接。优先一个最小 TP 或 PD 场景；有两机时取一例真实证据，无条件时交付静态结论和未验证范围。本机多进程不冒充多机，不建设多机矩阵、部署平台或成本模型。

探索编排留在 example，正式差异归各自 adapter/核心。交付可行性、阻碍及复杂性判断；需要改变共同核心的内容列为后续正式扩展，不修改单机冻结资产追求多机通过。若发现真实单机缺陷，按影响处理并保留原未通过结论。

### S11：工程整理与最终交付

从窗口 Git 基线审查全业务及相关工具，覆盖未改动但受影响的模块、跨语言交接、唯一状态、资源/引用、图/模板与风格。删除过渡与冗余整链，更新 CMake、导入、安装、Docker、入口、例子和文档；不为行数挤掉必要空行/注释或把业务移出统计。

保留最终有效来源、模板、真实目标、报告、必要失败证据及费用，清理已消费 work、重复报告、过期专属镜像/编译产物并撤下失效引用。沿用 S9 有效证据，仅实际修改影响结论时补相关复核。核对公开一键入口、精简结果、支持边界与远端交付；关键结构缺口或维护交付未完成时不进入性能层。

## 3. 按职责维护的技术任务与不变量

以下要求各维护一处，阶段按职责消费，不再在每个修复位置重复追加。必须保留的是语义、所有权与证明责任；原生helper、调用分段、通知或队列表示等具体做法在S3核实，可在边界与检查不减弱的条件下整段替换，不为兼容固化已有算法。实现按完整模块或功能链集中收口，未知风险与确认缺陷分别判断。

### 3.1 原始事实、粗化与测量

- 正式图保留工作身份、CPU/设备/通信资源片段、shape/dtype 与数据/别名端口、调用进入/CPU 返回/设备完成/释放端口、必要连接和模板合同。观察诊断只保留取证入口，kernel 名称、数量、SDK 私有记录和请求序号不定义模板类别；粗图、语义模板与成本单元粒度分别维护。
- 先按原生流程/模型层次、提交和资源事实确定边界，再直接构造粗图；不持久化完整细 DAG 作为先决条件。同资源连续且内部封闭的工作可合并；外部数据、状态、通信、中间就绪及释放形成切点。跨 stream 保留多资源片段，不压成全局串行节点或添加整组屏障。同调用片段、同已提交前沿的重复 host 等待可统一规约，首次、新提交及跨子调用/外部端口的等待仍保留，不能按同步 API 次数定义类别。
- 原始到粗图映射须检查完整区间恰好承接一次、外部作用不丢、无重复计费和无依据顺序。语义/参数/guard 声明保持，仅作有依据的规范化；边界归原始端口、访问、依赖及相接区间的共同语义祖先。已证明封闭的内部细节可省，流程外只作诊断，影响边界但未解释的记录报具体缺口。来源、切分与实例化共用图校验；状态访问、非零等待及通信区间必须有真实因果路径，拓扑排序先后不能代替依赖。
- 原生 API/队列关联、driver 提交、stream 顺序及生命周期确定设备任务和逻辑命令，保留零时长命令。非零异步拷贝与等待不能因无 SDK task 消失，实体任务不得重复计入。需保留的外部作用须有明确因果位置；有证据证明区间内部封闭时可整体承接并导出必要端口。既不能定位又不能安全封装的并发提交保留证据不足，不按最近时间、父 API 返回、固定字节阈值或名称白名单猜归属。
- stream 等待保留发起/恢复及全部已提交命令前沿，包括计算、传输、事件和无计费工作；SDK 外层 launch 可能同步，不能用其返回过滤已提交任务。来源具体等待快照不能冻结为目标前沿，命令接受点沿真实 submission 链取得。
- 观察器设备标记只定位，不自动成为业务工作/边界。解释后按真实 payload、事件/等待和外部引用收束区间，重绑隐式端口、状态/数据边界及存活锚点，保留显式原生端点、CPU 范围及所有载荷。无载荷且无外部引用的区间可删，单点沿用 boundary；缺依据保留原范围，不能只在评价端忽略。
- 原生 CPU 计数器提供主机顺序，stream 序位提供设备顺序，RAW 是独立测量。窗口两端独立查询计数器及包围 RAW 区间；SDK 主机导出只还原计数器，未直接测量的 SDK 内部端点保持未知，不将 Event 微秒当 syscnt。全图已测关系须存在满足本次查询区间的共同仿射校准，只判断相容，不回写拟合时间、增加容差、借目标因果补偿或拼接其他运行锚点。
- CPU 自身服务、等待、设备及搬运费用分别承接。父服务不重复计子工作，CPU 返回不代表设备完成，封装工作不当作零成本；本轮只声明责任和固定案例条件，不拟合性能。
- 统一预热、逻辑 reset 后开始；初始化、编译和窗口外工作排除，逻辑 KV/缓存初态与必要资源前沿明确。原生缓存实现、生效禁用状态、淘汰策略和 allocator 实现均取实际创建对象，不能用配置开关或基类代替平台覆盖实现。

### 3.2 原生动作、参数与张量交接

- 采集和无设备控制共用具名动作、进入/暂停/继续/返回生命周期。独立子调用先暂停父片段，父 invocation 只提供层次；CPU 工作与资源/发布子动作按真实顺序交错，一次工作只展开一次。片段依语义操作、局部参数及真实相邻切口选择，不保存相邻调用组合枚举或整批结束标签。
- 输入在真实操作修改前读取，必要结果在实际生产片段导出、末片段接收再转交；分配者、最后写入者、版本及就绪保持。跨片段原地修改须在写入处显式声明，末尾快照不能倒推新边界。用户输出在 publication 返回发布，请求逻辑完成在最终 result 返回更新，P 侧本地响应不重复发布 D 侧 token。
- metadata 端口传存储/版本/shape，data 端口表达实际内容读取或写出；只转交句柄且在子调用等待的方法不冒充父入口读取。新建、借用、视图和原地写由 runtime 区分，dispatcher 别名工厂仍可能创建存储；调用前输入与内部新缓冲不能混用。
- 控制从同一模板候选查询输出布局并构造无设备元数据视图，不另写 Python shape 规则；查询不修改资源或时间。返回值绑定图中的真实 storage/version，以弱存储引用维持原生张量和视图，不能按调用点常驻复用临时缓冲。
- 动作成员、token 范围和调用参数取本次不可变快照；PP 共享请求对象的后来进度不能覆盖旧批次。左右批次、结果成员、原地更新前输入及接收/执行 token 均完整。每次提交重新取得真实存活集合，父继续不能用旧快照回收子调用新绑定；跨参与者汇总引用和未交付完成句柄后才能回收。
- 纯 CPU 剩余片段须有 adapter 的 host_only 声明及独立检查：单控制线程、进入/返回端口、无隐藏子调用/张量/通信/状态作用。设备输入消费及等待先单独承接；空设备观察标记不算工作。共享结构不保证 CPU 成本相同，核对失败不启用宽松选择。
- 控制安装统一由 worker 装配：初始化资源替换先安装，其余语义、状态、通信和信号 hook 全部注册后一次应用。保持原生签名/能力探测，不以手工 wrapper 组合代替真实初始化证据；各模块不自行提前应用而漏掉后续 hook。

### 3.3 层次模板、参数化与复用

- 按 serving 动作及 embedding、模型层、attention、MLP、归一化/残差、输出等实际层次切分；观察窗口不是控制入口。一次建立 scope 归属、事件入边、输出和资源拓扑索引，只遍历相关子树，不为每个小动作扫描全来源。切口实际保留的输入必须独立声明，不能由被切掉的父/邻居代为承担。通信序号在切分后按动作内各通道顺序归一化，原始来源序号不改，目标沿自身序列连接，不继承来源累计位置。
- 自身定义、子调用组合、局部参数与调用绑定分开；父层只经直接子调用导出接口连接，接口包括端口含义、参数、别名和共享/独立资源关系。共享父端点不使子实现专属提交/等待/完成依赖冻结进父定义，跨兄弟连接由共同父层拥有；导入身份不依赖内部遍历编号。
- shape、成员、KV 和父子参数关系在知道原生语义的共同插桩点声明，来源实际值独立核对。透传沿生产者关系转换，符号有明确参数作用域；局部 gather 等 ABI 只带自身维度，不继承全部 batch/expert 参数。必要 Torch 观察只保留临时元数据，不持久化第二套逐操作轨迹。
- 适用域与工作身份分开，源/目标共用参数和 guard 规则。局部参数求值选择已观察且满足条件的实现，保留父结构、原有连接及跨子树张量别名/版本/写入者。父结构或共享接口变化使用完整变体，不能任意拼接未观察组合或按函数名/输出 shape 跨父图替换。
- 空/正维度、视图/复制及原生布局分支由明确 ABI/几何条件表达；空来源不能只改 shape 变成有工作。局部端口可达相同不证明内部资源工作相同，必要复制、stream 和等待仍保留；不能删除 guard、工作或添加无来源零成本槽位。条件归调用绑定，同条件去重，不按具体长度新增定义。
- 固定模型层调用来自原生结构/start-end，定义共享但权重/KV/张量独立；逐请求资源和发布次数由原生控制执行；模型调用内部条件/重复须有已声明关系及合法来源。三者不混作观察次数外推；同位置子调用数变化须有真实可达见证，层间固有差异或空工作不替代。
- 分配循环优先复用原生纯索引 helper：核心分配页，原生以 CPU 视图决定循环/分支，采集和控制按前置、单次请求及返回切分。保留首写/续写、metadata 借用和 data 版本；首次新存储登记属于绑定，不当模板条件，未初始化整缓冲不声明读。循环回边须正确，不复制函数体、修改上游、把行号序列交给核心或扩张通用解释器。
- 局部复用先核对原生接口依赖、环境、端口、guard、别名/写入者和资源共享，再扩大候选。纯 tensor collective 与携权重模型叶子分别审查，后者保持模块实现和几何；跨 phase 不全局删条件，含等待实现须有完整等待合同。歧义不强选，已有实现未装配与真缺来源分别处理。
- 相容闭合动作可导入共享，保留来源定义与条件，各自绑定 rank、组内根、张量和前台资源。主/辅助来源只从显式任务集合读取，完整 PD 对端不能由不同任务拼成；历史任务不自动合库，不搜索最新目录补候选。生产与 serving 装配共用局部链接器，不能只链接批次数组而漏模型局部实现。

### 3.4 有限来源、代表 worker 与实现域

- 同域重点变换长度、成员、到达、并发和 KV 容量。模型/dtype、各端 TP/PP/EP、backend、框架镜像、page_size、实际缓存及 chunk/mixed 机制变化分别取得来源；容量和 chunk 长度不单独成为域身份。同域只允许候选匹配，不保证覆盖全部分支；目标不能修改环境放宽资格。
- 原生模型/池构造后交换局部模块结构、张量几何/别名、KV 布局及已选 LayerCommunicator 分片/组宽/函数/标志，按实际角色在采集前选代表。模块遍历与池内位置提供跨层对应，真实路径/层号归绑定；专家工作量查询全模型层，交给模板用局部位置。不得按字符串猜层、仅比权重 shape 或把采后去重当采集减少；代表复用减少观察，不减少原生协议所需设备。
- 代表推进顺序为同 stage TP/EP 等价 → 跨 stage 层/模块位置 → PD 对端布局。PD 还核对远端池、metadata 行宽、源/目的组分片职责，预热排空和真实端点交换后再定代表；小型远端注册及全部协议参与者事实不随计算 trace 代表筛选省略。处理请求时不另加 world collective。
- 配置→域与 workload 两维保留，公共规划只分组/交接/发布；SGLang adapter 依据原生条件选择有限输入和探针，不复制 PrefillAdder/准入控制器。显式报告输入、token/等待/容量成本、预计机会、实际观察及未覆盖条件，机会标签和静态上界不是分支证明或全局最小集合。
- 缩短保留完整前缀/私有尾部、首次跨页/chunk、余数与转折、相同/不同长度组、输出组间继续迭代和 EP 路由内部边界；固定错峰保留原长度，约束不成立保留原组。路由只缩同质尾部并平移，不造新专家选择或消除非法间隙/重叠，不以任意 token 上限替代。删整组与缩短单请求分别证明，不靠反复加长搜索覆盖。
- 互补 workload 在同 Engine 中有限分组，完整命名空间重绑定请求/前缀/路由，保留组内到达和全局原点。两端全部响应且原生队列/微批/发送排空后才换组；保留缓存、不 flush、不主动排空原生发送或强制 batch，单组目标不加此边界。EP padding 冲突候选分组评估，不覆盖冲突值或漏组。
- 覆盖明确区分 empty/unchanged/subset、存活批次 merge/mix、原地长度更新、新位置、继续 Decode/部分完成/全部完成/等待准入/chunk/缓存。多请求不等于同批多成员，同时到达不保证 PD 同时准入；微批上限沿原生默认规则，SGLang 为 max(max_running_requests//pp,1)。保留首成员后预算及页/槽位条件，ignore_eos 的剩余输出余量亦检查；不以总 token 或请求数替代可达性。
- 缓存复用安排生产者完成后的消费者，最多追加两个前缀请求；持续 Decode 复用已有合法请求，每域至多一组，不延长/猜造路由。累计页压力同时考虑缓存淘汰及 PD 无缓存的延迟回收/排序，单请求可容纳而总需求超池才有机会；Prefill/Decode 持有区间分别处理。实际未触发不追加无限采集。
- 仅 PD 的用户配置也须经正式自动规划获得必要局部实现，不要求用户另给普通库。按实际阶段合并 merge/subset 与单/多成员模型需求：全为1输出的 PD Decode 不要求模型批次，Prefill 仍需模型见证。批次数组机制可共享一个普通来源，模型几何仍按并行域取得；必要辅助配方用独立单请求组和每PP槽位两对请求，按需全部1输出或交替1/2，不扩大池或修改目标路由。
- 发布前逐代表核对真实动作/model_members 和局部几何分支，普通 run_batch 与 PP launch 用相同模型语义。主来源唯一提供完整 worker/PD 对端，辅助仅导入合同成立的局部实现；计数不代替全部 guard。独立局部采样只有真缺来源时再判断，先明确全参与者调用顺序和 serving 隔离，不在 profiler 停止回调里直接加 collective。

### 3.5 虚拟时间、控制读取与进展

- 核心唯一维护时钟、事件队列、到达、完成可见性和等待唤醒；适配器将支持路径的时间读取、sleep/超时、消息和回调接入，CPU 边界间自身工作由显式服务时间推进。任务看门狗、预算和日志使用真实墙钟并隔离；两种时间不得互相驱动。
- 原生时钟按实际策略消费者绑定，采集/控制共享切口；核心配置并公开共同正时钟原点，保留原生“0表示未设置”的约定。独立时钟读取是query，poll内部读取属于该poll的条件，不再嵌套展开一遍。源端保留实际API/消费者/读值，目标读值须由已完成的核心切口与原点得到；跨运行不能直接比较不同原点的绝对时钟值。当前输入合同不能创建session或设置forward sleep，不因此为这些路径增加每轮业务节点；扩展合同后再补实际消费者。
- 给定耗时、固定案例实测服务及必要事件条件通过同一执行接口交接，未来模型仅替换提供者。服务不含依赖等待、父子重复或整段 API 包络；无法分离时允许显式完成条件作局部约束，并排除内部成本/自主完成资格。缺测不填零、借来源时长或静默 given 回退，前驱晚于时刻/区间上界报冲突，不平移或删边。
- 实测入口与工作边界分开，workload 到达、驱动提交、入口拉取返回、worker 广播/转发接收不能互代。交付按实际成员，非输入前 N 项；接收前状态与先前交付集合由原所有者提供，成员不作为识别结果的键。首批状态在 profiler 激活前观察，预热/source 身份分开，未知不补空。
- 动作工作身份、模板结构类和时间/因果位置分别维护。请求、阶段/token、rank、必要继续位置及 caller 的真实上下文提供对应依据，物理槽位/全局编号不跨运行匹配；observation_context 只服务时间，不消除逻辑重复。真正工作锚点来自本调用 request/members/left/right 操作数，不以祖先队列中的请求冒充。
- 受控输入提供者可维护每个参与者的已核对消费位置与必要事件引用，不复制调度或资源状态。先核接口、参数/对象身份及此前因果，再返回成本/时间/事件条件；失配保留预期和实际首处，不能据预期动作改写原生决定。仅凭本地调用计数或一次同态快照不授予对应，必要原始操作/输入事实缺失也不能用游标弥补。
- CPU 控制返回需要完整读取/放置上下文；逻辑完成可在证明不依赖放置后省去祖先调度快照，仍保留自己的参数、请求、继续和 caller 入口依据。单次观察不证明动作不可重复，祖先重复下的唯一子调用也不自动取得时刻。同刻事件保留必要因果；缺激活/反馈位置报告歧义，不按轮询次数强配或无限添加字段。
- 状态读取先执行此前 CPU 片段，再在明确切口查询核心状态并继续原生分支。Event.query、PD poll、metadata gate 与资源容量分别保持对象/量纲；slots/pages/可淘汰或受保护 token 不能混用。非阻塞查询不新增等待边，其 API 内真实 stream 同步仍保留。规定流程内的外层轮询也须有实际切口，scope=0 记录不能代替建模动作；成功读取的完成事实以 observation 关系交给后续动作，不能倒填过去时间或把 false 改成等待。
- Event 自持当前 record 代次，旧图边保留旧生产者；等待使用原生句柄/代次、方式和目标 stream，现场单独用于时间，CPU 等待不补 stream。观察器自有 Event 不注册业务信号，生命周期随在途引用回收；完成查询与图输入必须解析同一生产事件。record_stream/wait_stream 来自实际对象，统一作为本层 stream 选择条件；缺候选不借同名 API 的其他队列，不能依赖 torch.cpu 空实现代替等待。
- CPU 动作提交/返回不等于外部进展。原生完成必要整轮检查后在安全边界等待，由实际到达、相关消息、完成、容量增加或请求清理唤醒；消息先入队，唤醒保留至真正解除 idle/输入停驻时消费。不能额外 poll 探测、固定轮数判定、跳过原生逻辑或手调耗时消除空转；查询记录不要求每次生成模板。
- 启动先全体 ready，再确认每实例实际 input 所有者停在 idle 且 broker 全体停驻；PP 非入口可等原生 metadata，不要求全体同一 on_idle。普通源/目标共用活动区间：首个非空输入激活，全部本地输入到达且原生/模型发送排空后关闭，等待未来请求不关闭，管理命令不激活。
- 预测保留全部 input_read 并由 adapter 标明 in_flow，首个非空交付计入；全交付历史/时间仍校验，仅共同范围逐次对照。查找时间不等于消费，实际返回才计完成，退出取消不冒充读取；范围外空读另计，不按最后输出截断。稀疏文件只能作为明确给定假设下的局部工具，不能限制完整旁路能力或证明全控制对齐。
- 最终停止需各参与者请求清理、原生调用/图/PP发送排空及 broker 停驻；新动作使旧 idle 声明失效。允许尚须清理的实例继续空轮转，不用首级停止代表整组，也不向共享 PP/PD 流注入退出请求；确认后取消本任务私有 CPU 等待并正常退出。

### 3.6 资源、并行与传输

- 核心唯一维护槽位、页、缓存引用/淘汰及独立字段行池。adapter 声明实际 allocator 及字段使用请求槽位还是独立行；资源逻辑操作与页索引、cat、排序等执行工作分开。普通池/PD池的归还和延迟合并遵从原生实现；确实合并待回收页时由操作事实触发 pages.sort，不在 adapter 再存一份队列。
- 资源初态、实际分配/归还、缓存键/锁引用与前缀绑定从原生对象直接观察；观测器只读，不重执行分配策略。可选不可变索引快照在排空后读回，不每次同步设备；请求物理页表在真实消费边界读取，PD prebuilt 无模型也可能提供快照。旧记录缺事实不补写，诊断不能替代正式数据端口。
- 内容初始化由历史有效范围与本图因果先行写入联合覆盖；完整访问收齐后检查，后写/无序写不算初始化。逻辑归还使旧内容资格失效但仍保护历史在途访问；不能拖到下一动作再清状态而删掉期间远端新写入。字段归还只清自身内容，独立池按各行全生命周期管理。
- FutureMap 的 stash/resolve、首 token 和 metadata 沿请求槽位/字段交接，覆盖普通、mixed Decode 子集、PP 输出和 PD prebuilt。set_buf→send_aux→get_buf 保留实际注册整行、索引/room、请求绑定、源释放、接收清零与行回收；不为每个标量建类别、不用传输成功布尔值代替内容链。只比较原生消费的首 token/缓存计数，room 跨运行按请求对应，padding 不逐标量维护。
- TP/EP 参与者、组内根、通道和职责取实际原生组，CPU/device 组即使成员相同也分开。EP1 同样需显式拓扑路由，专家层由全部 worker 发现，PP 局部无专家不能当 dense；采集、控制、prefix 身份共用实际专家层/路由。Standard 按 token 行、DeepEP normal 按接收专家行核对，路由次数/不同 token/接收行不混用；实际部署、分片、去重和 padding 归 adapter，不从 EP 大小猜 shape。prefix 按全模型实际专家层逐位置条件判断，普通层路由及等价区间拆分不改变身份，真实分歧后停止共享，padding 不入请求内容键。
- CPU pyobj/字典/P2P/广播沿原生接口推进，按组/方向/tag 保持 FIFO、类型/shape、空消息和真实 Work 生命周期。控制值输入在图返回前非阻塞发布，就绪/完成沿对应进程组图边表达，图返回后才消费；不制造第二次汇合，singleton/空归约不加屏障，广播非根未初始化内容不读。用 CPU/Gloo 承载设备元数据不改变原生通信类别。
- 组批 all-gather 与 CPU 数值检查分开：MLPSyncBatchInfo 切口记录调用前七项标量及原生已读回结果，不额外读取设备。按实际 DP/TP/CP 参与组检查控制输入、结果与消费；活动 CPU 镜像不证明故障设备 mask，TBO/DP/CP 扩展仍无额外资格。字段/数值只作证据，不进模板类别或驱动决定。
- PP 执行原生完整 event_loop_pp：launch、proxy 收发、output_prepare/skip、output 转发、result 和 commit 各有边界，父 run_batch 不重复提交。微批容量沿原生默认/显式配置；槽位仅指布局，不能作为工作身份。字典真实消息类型/字段、切分后 shape、receive 后 TP gather/reshape 和独立接收缓冲完整交接，相同 shape 不证明同一消息。
- PP 保留 CPU 返回、设备尾部、Event/Work、stream 等待及输出绕回首级的实际连接；控制 token 记账值不允许提前消费设备数据，异步发送不整体变阻塞。原生空轮转/共识照常执行，等待依据整轮微批、请求/chunk与传输检查，局部 Success 不代表全组；保留单调待消费唤醒，不新加 PP 屏障。停止 profiler 等全部观察 worker 原子发布，不只看入口回复。
- PD 由独立 P/D Engine、独立池及原生 bootstrap/prealloc/transfer/inflight/prebuilt 队列推进。任务声明 model、instances、workload、observe_all_workers，实例含 id/mode/configuration，普通为 null 实例；按实例分配全局身份及连续设备段，配置只交本实例。两侧同请求以共同非零 room 关联，预热/source 不重叠，全实例预热/reset和 profiler 就绪后发布共同到达原点；每实例独立排空，所有 Engine 正常退出后发布。
- PD 预分配发生在成批前，按本次 prefix 参数交接需求与必要绑定；其页索引导出/同步先返回，再发布可写预约，不提前发父片段尚未执行的结果。prebuilt 接收首 token 后准入/处理，不伪造模型 Prefill；P 本地 FINISH_LENGTH/首 token 不代表全请求结束，源页只在原生 inflight 确认完成后释放。
- KV 传输由原生 CommonKVManager/AscendKVManager/Mooncake 的映射及切片提供参与者、PP层、TP head 和字节范围。两端实际注册、页列表和实际 engine 提交地址解释为逻辑区域；原始地址仅取证，不跨运行识别，不运行第二份地址重演。池构造即记层范围、heads、KV dtype、K/V字节宽，代表筛选不丢远端注册。异构 TP 的多个源补齐后才可读；整页搬运含尾页空间，但内容就绪只要求有效逻辑范围。
- PD 传输域保持相同 page_size/KV dtype 及原生合法拓扑，TP/PP/池布局变化另取来源。原生层切片/draft 分支地址错误保留上游限制，不 clamp、patch 或用模型特例强行支持。两池所有者唯一，源读等计算、目的写保护旧访问；原生单边写用一个工作声明两端范围，确有双端提交才连接双端口。
- 无设备 backend 复用原生 BaseKVManager/Sender/Receiver 边界、CommonKVSender 分块/末块规则及原生 rank 映射，以 broker 交接预约、元数据和完成句柄。物理 socket、后台引擎不搬成第二套多线程状态机，FAKE 立即成功不作为实现；载荷布局元数据与真实 KV 访问分开，不造临时 Tensor 冒充 KV。句柄在图提交后发布，持有至消费者接手，确认回收与 P 资源释放分开。
- 后台搬运按真实入队任务/请求归属，不按最近时间嵌入 scheduler。入队返回、同步服务完成、协议可见和消费分开；服务直接记录 CPU/RAW 起止，不依赖后台 Torch 回调，等待不重算 CPU。chunk 的同步目的地组仅在载荷、私有队列、跨界作用和组间线程顺序封闭时整体规约，遍历排列不生模板；保留入队因果及整组完成，外部中间消费者/共享队列须导出接口。scope 到原观察编号显式映射，不假定数组同位。
- 多源写同字段须有请求内同一发布身份和载荷一致依据；相同发布副本可并行，读者等全必要写入，普通不同写仍保护 WAW。源/目的组按真实拓扑绑定，不能靠图插入次序串行化或整体删除写冲突。
- 预约反向消息、KV完成、metadata gate、Sender/Receiver状态及参与者归约分别表达。预约发送入口可作必要下界，远端状态写入可能早于整个调用返回；登记者与接收者、排队与完整可用分别表示。完整预约依赖所有必要发送信号，早到状态不被后来创建对象覆盖，不以最后 rank 返回或首次查询拟合延迟。
- Success 需请求全部 chunk、末块 metadata、必要发送/目标组及真实最终通知；通知只在原生末块发布，数据服务完成不直接变成协议可见。核心按依赖/区间解锁，broker 先入队再唤醒，adapter 解释消息而不在核心新增 PD 状态机。通知到原生读取的真实已完成事实交后续动作，不能无条件作为所有动作前驱；生命周期至全参与者原生清理且相关消费者完成。
- poll_and_all_reduce 及 attn_cp_tp_group 按原生公共切口包住实际读取、metadata gate、分层 MIN 与返回，嵌套 helper 不重复观察/计费；实际 pollers 的有序请求向量必须一致。后级消费前级实际输出，Decode 当轮准入只用未消费成功结果，Success 但 metadata 未到仍按原生降级；单成员本地检查，不虚构 collective，也不将 staging/多级缓存纳入本轮。
- 所有非失败传输状态按实际生命周期单调检查，Success 缓存终态不回退。直接写入区间与查询界限分别保留，同次转换的全部读取共同约束可行区间；同刻按实际返回顺序，无依据不强定序。可行区间不冒充实测，首次成功仅给上界，不把未轮询间隔当通知成本；必要通知时间缺失保留资格，不新增逐socket/逐标量图。

## 4. 验证责任、方法与覆盖

### 4.1 给定条件与独立输出

| 检查责任 | 可以提供的真实条件 | 必须独立生成并核对 |
| --- | --- | --- |
| 局部模板及整图生成 | 已声明动作/批次、调用参数、必要外部条件及实测服务 | 来源选择、参数求值、子图内容、连接及资源依赖；目标图体/边/内部shape/实现不交给构图 |
| 原生控制交互 | workload到达、共同初态、实测成本及充分事件/时间条件 | 查询、决定、组批、资源操作和反馈；不能同时输入这些待验证答案 |
| 局部模块检查 | 明确指定的其他模块返回值，必要时包括查询/分配答案 | 只授予未被替代模块资格；基本因果和资源安全仍检查 |

三类检查共用核心动作、资源和执行接口。真实决定在构图检查中是输入，在控制检查中是输出；来源模板与目标真值严格分离，不能从目标模板、节点或依赖补答案。已有局部证据保留，整例 partial 不是逐项补采清单。

给定动作的最小交接包括参与者/工作身份、原生操作与实参、具名输入对象和逻辑资源操作。输出shape、实际存储/版本、完成句柄及依赖由模板与核心生成；验证驱动使用这些返回值构造后续输入，原生对象到返回句柄只做身份翻译，不复制目标输出绑定或另存资源账。真实输出只作比较；核心返回与后续动作前提不相容时定位首处问题，不能回填真实分配/输出让流程继续。S4据此检查原始调用与对象事实是否足够，不能假定已有trace天然包含完整受控输入。

### 4.2 独立比较与必要反例

- 原始事实、映射/测量、模板内容、跨图连接、运行内资源安全及整例控制分别授予资格。解析/规约可共用，原始作用核对不调用核心投影；真值不由模板求值或分配策略重执行生成。独立检查范围不能声称发现从未观察到的事实，不为“独立”再造两套解析器。
- 每次真实调用先保留本次身份，普通跨运行对照用逻辑工作及必要上下文对应，不按事件/物理槽位/节点序号、边数或时间近邻匹配；两侧均唯一的完整工作身份可一对一比较。受控输入流另须有从共同激活点逐步校验的因果对应记录；比较器独立核对原始调用、已消费条件和实际事件，不因提供者宣称匹配就通过。两种证据分别标明，不为缺事实自动切换配对方法。其余重复项若全部原生副本内容或内部依赖一致，可逐个检查预测内容，否则保留歧义；结构类、工作对应和精确时间资格分开。
- 动作内容核对实际调用树、端口/shape、资源共享、别名/版本/写入者与状态范围；内部路径允许离开子树再返回，未命名事件仍参与。host_only 类仅在全部原声明均满足无隐藏作用时按实现/owner/参数共享，不给纯 CPU 专门豁免。未匹配目标仍保留写入者和完整关系，避免后续误连更早生产者。
- 全 rank 图同时包含模型通信、CPU协议、PD可见因果及实际跨rank信号，内容、重复位置、连接和安全共享该图；缺协议报告影响范围，不退回弱图通过。来源通信按真实组/端点/通道因果建立，目标亦独立检查全部通道和重复调用的就绪→完成连接；载荷约束按声明 dtype/shape，变长交换不强求所有行数相同。
- 次序比较在完整图保序投影具名边界，核对事件别名划分，去传递冗余后双向检查最小关系可达；缺前驱和额外串行化分别报告。最大前沿及自反前驱集合在汇合时去掉严格祖先，释放已消费前沿，分批位集避免平方全表及逐边界回溯。修改算法需独立核对可达/最小关系和原大图，不靠删检查、阈值或扩大时限。
- 重复位置用共同唯一锚点的前后可达集合比较，未命名/跨rank路径保留；缺锚点报未知，不为每个位置硬配时间。单路径和最小关系只解释现象，不能直接当独立根因；并发无唯一绝对首处，报告优先给拓扑较早的代表与有界解释路径。
- 原生资源记录与核心真实操作输入/返回分别规约，页/槽位/字段以池内释放周期解释，允许物理编号重命名及独立行操作穿插；保留请求、页内偏移、缓存内容/锁引用、释放分组和同一行顺序。暂存/空释放与禁用缓存空操作不冒充变更。容量查询须有实际读取，初末快照不能倒推读取值或时刻。
- 物理绑定从原生消费页表/传输地址与执行器实际解析范围独立取得，按动作、池、请求比覆盖、页内位置和共享关系，区间合并/交叠不逐 token 展开。释放代次须明确；无精确时刻快照只在调用窗内未释放时确认。页表准备不凭空制造 KV 访问，有访问而缺绑定即使双方都缺也报不足。
- 每个非空外部 data 输入检查实际发布根输出至消费路径；显式等待核对实际生产代次和 signal 边，query 不套等待要求。物理 KV/独立行统一检查在途重叠读写：旧访问未完成且至少一方写时需旧结束→新开始的真实路径，合法同发布副本另按合同处理；逻辑归还不删除仍在途访问，路径可跨rank。
- 长工作、多个在途批次、释放时访问未结束和实际物理复用分别取证。正常输出/传输等待和缓存引用可能使某条件不可达，不能靠更长请求期待触发；失败/撤回/卸载不能借正常路径通过。保留通用保护，不新增强制早释放或伪延迟业务开关；零次冲突/归还不是长在途资格。
- 真实与预测分别核对资源身份/范围、内容就绪和访问安全；原生已完成而模拟仍在途时，必要等待边可以不同。先根据实际绑定和完成/提交关系判断保护，再评价额外串行化；不能只凭图上某条路径缺失判错或按时间全局补边。
- CPU P2P 是所有实际worker的必要运行事实，由 NativeProfiles 在 profiler 成功后、workload 前启动，停止后原子发布全部 protocol/rank-N.json；不受代表设备采集选择或可选resource-trace影响。记录真实组/端点/tag/载荷、post、Work归属和首次成功wait，嵌套阻塞/异步不重复，窗口前Work及通道起始/尾部保留。控制记录实际 post/consumed，不增加逻辑轮次，消费不得早于双方投递；投递返回、完成和消费分别解释。
- 输入交付真值从原始 session、RAW原点、入口/worker接收取，不能读取旁路文件充真值；全请求历史和时间单调先校验，身份重复、未知首态、非workload消息、单侧缺记录及范围外空读分别定位。协议状态、全部原生组、操作数来源、分层归约和实际准入分别检查，不以 MIN 自洽或局部 Success 代替整链。
- 旁路发布前先沿完整原始 DAG 核对全部动作入口、返回和导出信号的测量因果，重复调用及经过未测节点的路径也检查；不能先筛唯一身份再校验来源。事实矛盾只发缺口报告，身份重复但事实有效可发布显式 partial，不宣称全部反馈实测；动作入口证据不强制等于目标构图时刻。
- 来源/目标映射先核完整 observed_roles、环境、原始声明和分配归属，无效映射停止相关结构比较，不能降为时间 partial 后继续；SDK内部未测时间不阻断已成立映射。每项 finding 标明确认差异或证据缺口，工具/原生/额度/依赖失败另列，已有差异不能被 incomplete 总状态遮蔽。
- 报告默认精简结论、覆盖和代表位置，details才给全部说明，不常驻完整历史或复制trace。负例只操作副本：缺工作/边、错shape/端口/别名/伙伴、无依据依赖/测量、提前消费/复用和坏资产；真实分支/长在途证据与检查器负例分别记录。

## 5. 运行、产物、环境与采集纪律

整个窗口一个UTC时间根，不按阶段创建大量顶层目录：

    data/<UTC>_coarse-graph/
      inputs/                 固定输入、环境、程序、来源规划与矩阵
      sources/<domain>/       来源原始事实、粗图和正式发布
      assets/<domain>/        正式模板库
      targets/<case>/         独立真实事实与粗图
      results/                精简预测、逐例资格与全量报告
      logs/                   命令、费用、恢复及失败依据
      work/                   可回收导出、编译和解释中间件
      diagnostics/            显式保留的原始trace或局部明细

- 正式采集、生产和预测共用模型/workload/实例配置解析，未知字段与非法组合在输入边界拒绝。worker环境、代表库及池/模块角色由来源域和worker_roles装配，不让用户编写内部任务；缺代表、重复主来源或冲突显式失败，不找历史资产。内部任务交接后释放。
- 每次显式采集最多一次原生尝试，子容器自带期限；任务固定模型只读路径、设备、输入和镜像，成功退出并取得闭合事实才发布。采集发布、全角色关闭、会话成功和进程退出分别判断；清理失败不清掉恢复状态、不发布成功，也不隐藏重启Engine。
- 初次执行核对全部域、来源、设备、模型、部署与程序，将核心二进制复制固定到本次输入后执行/恢复共用；镜像和安装路径核对实际ID。采集/控制/SDK改变后集中重建受影响镜像，核心在modeling内构建；稳定标签无日期，不挂旧包覆盖，不将标签相同当资格相同。
- source/target模型实例独立启动，统一预热、逻辑reset、profiler就绪后开放workload；完整请求已交付、原生整轮idle、调用栈退出和PP发送排空后才drained。驱动等全体drained再请求清缓存和阶段完成，不能用管理消息、客户端收齐输出或入口stop_profile提前关闭；采集保留原生有界休眠/周期唤醒。
- 原生、CPU后处理、尝试数及临时/保留存储有阶段累计上限，失败/恢复/显式扩额均不清零；按原始任务所有者预留与结算，引用历史资产不重复算新增采集。未知用时/未结算保留预留，先清中断再检查新额度；逻辑字节监测不是文件系统硬配额，存储足以支持全量，不静默删任务或暗中扩额。
- 来源集合复用单任务生命周期，每次仅执行计划作业，集合第一处失败停止并保留已成功步骤；S9矩阵则继续无依赖案例。全集发布要求有限作业全完成且装配匹配，仍单列实际机制覆盖。正式一键示例仅编排规划、来源、生产及配置×workload预测，全部目标成功才发布总结果，失败保留恢复入口，不自动补采/重试。
- 后处理复用有效原始事实；SDK可写目录由runtime私有副本提供，显式交接导出，原始记录只读，不隐式借旁边旧导出。目标只需真实粗图不生产无人消费模板。解释/模板修改不重跑模型；新边界确无事实时先说明缺什么及结果怎样影响实现，再只补受影响侧的一次有界观察，合格另一侧和原报告保留。
- 正式来源引用核对实际capture所有者、输入、成功终态与发布路径，采集镜像和当前解释镜像分别记录；缺事实不离线补写或跨环境移转资格。全体实际角色、远端小型注册及协议证据按需要保留，代表时间不复制给其他rank。每个真实目标原则上一采，后续仿真复用；不为清partial持续增加案例。
- 默认精简，完整trace/图/资源/协议历史在生产前显式开启，执行明细来自实际连接/解析点，不由评价器猜依赖。诊断只读、不保留核心全历史，部分失败与完整发布分开。临时文件按消费者释放，争议唯一原始证据保留至结论形成，清理只动本任务有明确所有权且无消费者的内容。

## 6. 实施、审查与文档维护

每批自顶向下追踪入口、生产者、消费者、状态所有者和生命周期，写清不变量、根因及删除范围，再集中完成整段职责链。连续发现或解决同类问题时先复盘逻辑覆盖与设计/推进/验证方法；方法有问题先改方法，不沿旧路径局部缝补或依赖实验逐条指导加分支。

C++23、Python3.10、按职责面向类与组合，必要浅层继承/模板表达特化；C++头源同目录。逻辑块有空行，重要身份/所有权/完成关系有适量注释，注释上方留空行，不改 .clang-format。保留真实输入/安全/原子改写/时间不变量检查，删除多余防御、默认值、兼容、包装和转换；不新增test/fixture/mock工程，不以代码量或验证量换质量。

每阶段开始根据上阶段已推送基线和当前能力调整计划，不机械沿初稿；方法或证据前提失效回到其所属阶段，只撤销受影响资格，保留有效证据和未完成责任。缺事实时给出具体影响及有界取得办法，不能以“全部partial”继续试错，也不能把证据不足统一写成核心错误。

每阶段结束从Git起点审查全部修改及未改但相关代码，检查职责、正确性、风格、可合并/删除内容及跨语言/构建/安装/入口引用。完成整块静态审查后统一构建与必要正式入口验证，不每改一层就编译，不无理由重复验证。再分别检查文档与数据，按 `type(scope): 英文祈使句` 分层提交推送并核对远端，完整纳入核心代码及关联调用方、构建入口与文档，作为下一阶段base；提交集中在阶段边界，数据和用户无关改动不纳入。仅推送文档或遗漏未跟踪业务源文件不算阶段交付。

计划维护任务与合同，status独占当前状态/资格/下一步，log按日期正序记录“范围、改动、验证、结论与限制”。技术要求在对应主题合并，不把每轮发现写回阶段正文；实验事实留实际运行报告，旧编号/失败不改写，不建立平行账本或新导航层。文档整理不自动授权恢复goal、运行、清数据或提交。
