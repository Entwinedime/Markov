## 1. 本窗口要交付什么

工作围绕三个问题展开，不能分别做成互不相通的功能库：

| 方向 | 要解决的事情 | 交付结果 |
| --- | --- | --- |
| 子图自身变换 | 同一工作在分片、层区间、成员及路由变化时如何实例化 | 有依据的参数关系、有限实现条件、可复用定义与角色绑定 |
| 子图之间连接 | 不同 rank、stage、服务实例之间如何交接数据和完成条件 | 明确通信组、发送/接收、collective、状态交接与资源依赖 |
| 控制、缓存与执行反馈 | 如何组批和复用前缀，各 rank/stage 何时交接或释放资源 | 统一动作/事件合同、轻量调度策略、具有明确所有权与就绪条件的缓存接口 |

后续主线是：**S6 真实 MoE/EP 与路由方案收口 → S7 组合拓扑与采集前代表复用 → S8 正确性与泛化里程碑 → S9 调度与一级前缀缓存 → S10 单机整合 → S11 扩展探索 → S12 最终验收**。S0–S5 保持已交付状态；后续编号不变。P/D 实例及目标 rank 仍在同一台机器；S6 已选择保留按 EP 拓扑提供路由，配置与 adapter 继续解释专家部署。

**先把组合结构和采集复用收稳，再做调度。** S6–S8 保持简单控制，完成 EP、组合拓扑、跨 rank/实例交接及代表采集的开发与固定资产验证；S8 通过后才进入 S9。CPU/设备 overlap、自适应 chunk、请求抢占、speculative、多级缓存的实际搬运与 CPU/磁盘后端均不纳入本轮；PP 流水仍可并发，不优化微批次调度启发式。

“完整闭环”指选定合法组合从用户输入、代表采集、模板生成/复用、动态决策与展开，到输出、KV/任务资源释放和独立原生结构对照全部连通，不以孤立模板示例代替。它不等于任意并行组合、所有原生启发式或内容相关路径均受支持；条件和未完成项必须公开。

对性能层的判断：**按工作种类选择模型、用节点特征预测服务时间，这个方向成立**，但结构正确不意味着性能层只剩独立查表和求和。模型还需考虑 shape、dtype、实际实现、通信参与者和拓扑；执行器要处理资源共享、等待与重叠。语义子图和成本单元不必一一对应，父子和整体/内部工作不能重复计费。本窗口仅使用给定耗时检验结构，保留后续所需特征与资源边界，不预建性能系统，也不以结构通过保证未来精度。

## 3. 正向闭环与共同合同

```text
固定模型 + 配置集合 + 请求集合
  → 解释逻辑拓扑、角色及合法组合
  → 匹配已有来源，选择必要的代表角色采集
  → 生成共享子图定义、布局、参数关系和角色绑定
  → 控制器接收到达/完成事件，作出带身份的动作
  → 实例化本地子图，连接数据、通信和状态端口
  → 执行器按给定耗时、就绪条件和资源推进模拟时间
  → 返回相应任务的进度/输出/完成事件
  → 控制器更新唯一状态并继续决策，直到请求与必要交接完成
```

### 3.1 拓扑与角色

逻辑 rank、通信组、PP stage、P/D 服务实例与物理 host/device 分开表达。TP/PP/EP 是参与关系，PD 是服务职责和 KV 交接，不能把四个参数无条件相乘生成 rank；组可以相交，成员、局部坐标和原生合法组合由 adapter 解释。

采集部署决定在哪张卡观察，目标 placement 决定模拟时哪些工作共享主机、设备或链路。本窗口正式入口只接收单机目标，逻辑 rank 不等于物理设备编号；本地部署约束由装配边界维护，图和控制算法不散布单机判断。更改 placement 不默认重建本地计算子图，但涉及 transport 或局部实现变化时，需要相应事实；跨机探索的改动应集中于拓扑/资源绑定与通信适配，不提前发布多机输入选项。

### 3.2 控制与执行接口

在已有 Batch、BatchEffects、BatchProgram、BatchExpansion 和执行端口基础上收紧合同，逐步替换单批次假设，不另造一套平行流程或万能消息总线。以下是需要表达的语义，不预先要求每一项成为一个新类：

| 交接 | 最小内容 | 所有权 |
| --- | --- | --- |
| 可见状态 | 模拟时刻、到达、可用资源、已完成的任务端口 | 执行器提供时间与完成；所选控制实现维护请求状态 |
| 工作动作 | 稳定任务身份、成员的阶段/token 范围、stage、目标角色组、输入与状态效果 | 控制器生成不可变快照，模板层消费 |
| 执行片段 | 参数化工作、依赖、资源、输出及状态提交端口 | 模板实例化与连接层；不自行决定下一批 |
| 完成事件 | 任务身份、端口、模拟时间和该端口允许提交的效果 | 执行器产生，控制器只在相应事件到达后更新状态 |

执行器拥有唯一模拟时钟；到达、控制就绪和工作完成按时间推进，同刻事件使用稳定顺序。多个任务不能继续共用无身份的 Published/Completed 和一份 BatchEffects。中间 chunk、PP 中间 stage、纯传输可以没有用户输出，发布端口不再强制每个动作都有；混合批次的输出与状态效果按成员分别提交。

请求进度、槽位和 KV 所有权只保留一份权威状态。轻量控制器维护请求，所组合的 KV 资源组件维护实际页分配、引用和驻留，缓存索引不再复制一份页账；若以后采用原生控制器，则原生实现保持权威，adapter 交出必要映射。执行器维护就绪与资源前沿，不复制请求状态机。

资源服务在就绪后才能开始。支持多任务时，不能因先装配一个未来任务，就永久预占资源或算死后来任务的时刻；先用明确资源串行规则和固定服务时间建立正确事件闭环，连续带宽争用模型留到性能阶段。图回收须保留所有在途任务、消息和状态引用，不沿用“一个批次结束就回收全部历史”的假设。

### 3.3 控制实现与未来替换边界

本窗口正式控制后端为轻量控制器，workflow 通过抽象控制接口交接动作、完成事件及结果所需状态，不依赖具体控制类的内部队列或 KV 容器。单实例、PP 微批次和 P/D 协作是当前接口的真实消费者；必要的控制差异通过组合或浅层继承实现，公共生命周期维护一份。先用简单策略核对拓扑及因果，再在 S9 扩展组批与缓存决策，不将特定顺序写进共享模板。

未来可通过 adapter 将原生调度逻辑接到同一合同，仍需解决动作交出、模拟完成注入、时钟、worker 和内容结果来源。S11 可以用最小真实适配检验其中一个闭环，不交付完整原生控制后端、虚拟 worker 平台、RPC 或配置占位项。原生 `Engine.generate()` 的真实运行继续用于采集和对照，不直接作为预测控制后端。

### 3.4 抽象对应代码层次

| 层次 | 固定职责 | 差异如何表达 |
| --- | --- | --- |
| contracts | 工作动作、端口事件、角色/组、状态效果 | 简单值类型，避免把具体控制器和框架对象带过边界 |
| controller | 根据可见状态作决定，维护请求并使用统一 KV 资源组件 | 抽象控制接口与必要的策略实现；共同状态不在多个子类复制 |
| KV / cache 组件 | 前缀索引、引用、分配与驻留的明确归属 | 逻辑匹配、替换策略和存储层通过组合协作；只有一份实际页账 |
| templates / graph | 共享定义、有限变换、实例连接 | 共用算法与角色/参数绑定，沿用 BatchExpansion 隔离装配差异 |
| execution | 时间、工作就绪、资源顺序及完成反馈 | 消费共同合同，不识别框架函数、控制器具体类或特殊 rank |
| adapters | 原生来源、实现条件、角色含义和 transport 解释 | 面向明确职责的实现，通过组合接入框架和 runtime 差异 |
| workflow | 选择并装配上述对象，维护单任务生命周期 | 具体实现的依赖集中在装配入口，不扩散到核心算法 |

需要运行时替换的职责使用抽象接口和浅层继承；同一算法确实服务多个编译期类型时使用 C++23 模板、concepts 或局部特化。仅 rank、层区间、分片大小不同则使用值与绑定；多个并行机制优先组合，不为 TP×PP×EP 的每个组合建立子类。类、目录和依赖方向共同体现这些层次。

清理被新抽象替代的旧职责链、散落的特例分支、重复状态和无消费者代码。抽象的验收是改变一种策略或装配方式时修改集中、其余层可继续复用；不以接口数量、继承深度或模板技巧衡量可扩展性，也不预建尚无用途的未来实现。

## 4. 子图如何扩展并控制数量

### 4.1 内部变换和来源

| 变化 | 优先取得的依据 | 处理方式 |
| --- | --- | --- |
| 成员、token/context、容量 | 控制快照、原生参数及 fake/meta 关系 | 求值 shape、索引、页读写、重复子调用；遇到真实实现分支选已有原型 |
| 模型分片、层区间、expert 归属 | 原生模块和并行元数据 | 实例绑定与组合；分片、复制、padding 和首尾职责保留条件 |
| 数据搬运、collective、P2P | 实际接口、参与组、端口和数据布局 | 计算传输范围，连接对应生产/消费；不从 kernel 名猜拓扑 |
| 新融合或新控制/资源行为 | 新来源及有限适配声明 | 增加确有差异的局部原型，不复制整套模型与 serving 图 |

小范围参数化成功不代表可跨任意 TP 或模型。已有分片公式、实现条件和角色映射足够时，复用可证明不变的部分；否则仍为新 TP/模型建立来源，自动归并其中相同子结构。不能把“跨 rank 共享”写成“任意 TP 无需采集”。

### 4.2 等价 rank 共享

分开共享计算叶子、共享组合布局和共享完整角色三种情况。两个 rank 可以共享 decoder layer，却因输入接收、发布、首尾 stage、KV 复制或 padding 而不能共享完整角色。

归一化沿现有确定性定义和布局机制扩展：局部值/资源重编号，物理卡号、全局 rank、层起点和消息目的地进入绑定；工作、端口、别名/读写、CPU 服务切口、实现条件及分片几何仍参与等价判断。不同实例永远有各自资源绑定，不因引用同一定义而共用 KV 存储或执行 stream。

后续采集改为：**解释目标拓扑和原生角色条件 → 在启动前分出有依据的等价角色 → 每类选择必要代表及局部实现分支 → 观察代表 → 为各目标 worker 绑定实例 → 用留出 worker 核对**。已有完整角色来源可以作为等价依据和开发证据，不要求每个新组合先采全体 worker 再去重。

等价依据由 framework/runtime adapter 提供，优先读取原生组坐标、模块分片、层/专家区间、实现分支和接口；共同模板层维护同一套绑定与连接算法。不建设第二套图等价证明器或逐 rank 例外表。须核对工作/端口、类型/布局、别名/状态效果、CPU 服务和实现条件；差异只有身份或可证明的参数映射时才复用。首/中/尾 stage、接收/发布角色及 padding 不同的 worker 不能简单并类。

派生 worker 使用代表来源和显式映射，不复制并改写原始 trace 冒充本 worker 已被观察；各实例保留独立权重、KV、stream、事件和通信端点。EP 的专家编号及路由工作量进入绑定与实例，同一角色的不同路由不是新的完整角色模板。无充分依据的角色按必要来源处理，真实新分支明确增加局部原型。

**减少观察和减少原生参与者分别计算。** 可隔离 TP 角色时，代表复用应减少模型会话；真实 PP/EP/PD 协议仍可能要求全部 peer 同时运行，此时只选择代表观察和导出，不声称只运行一个 worker 已验证多 rank 通信。验收分别记录原生会话、启动参与者、被观察角色、导出量和保留量。

验收同时报告共享定义数、布局数、角色绑定数与实际采集角色数。扩 rank 或重复层时，纯身份变化只增长绑定和实例；新增定义必须能解释为工作或条件变化。不给所有模型规定一个模板数量上限，不以隐藏差异凑少数模板。结构共享不自动授予耗时共享。

### 4.3 子图之间连接

数据端口沿生产者/消费者和存储版本连接；通信端口还需通信组、参与者、操作种类和调用身份。PP 消息、EP 交换和 PD 搬运带 stage/请求或微批次等必要身份，不能把并发调用按 trace 中的全局序号配对。

collective 保留各参与者输入就绪和本地完成；P2P 区分发送可读、发送返回、接收可用以及缓冲区何时可释放。协议确实要求哪些参与者到达，就等待哪些参与者，不为简单装配增加全 rank 全局屏障。尚未提供的合法端点属于待连接工作；完成一段可提交结构时仍缺必要端点，才报告明确缺口，不能伪造零耗时通信。

**三、必要事件归属与依赖完整性。** 对未归属的record、查询、等待和任务，先明确服务哪项工作、由谁消费、何时完成及是否允许后续动作继续，再决定所属区域与依赖端点。核对提交、设备完成、host等待、通信/KV就绪和状态提交的区别，包括跨rank、跨flow、跨实例和事件句柄复用；不能只给未知事件随意归属或增加一条全局屏障。

必要消费关系应由原生对象、协议或最小补充观察证明；仅凭事件名称、相邻时标或“没有发现wait”不能认定无影响。无关事件在取得排除依据后保留精简说明；影响不明的关键项仍未通过，不要求还原所有SDK轮询，也不把证据不足写成已确认漏边。

以接口的外部完成合同判断必要因果。已由固定实现证明成功返回前等待全部搬运完成的同步服务，可以保留为一个opaque传输节点；继续核对其输入范围、返回状态以及后续接入/释放是否依赖该完成。内部SDMA逐条归属仍单独报告partial，不再把包级一一对应当作同步合同成立的前提，也不在接口成本之外重复计费。此边界不适用于异步提交、另有外部消费者或完成语义尚未查清的事件；这些必要关系仍须明确，不用整体服务掩盖漏边。

**共同入口和来源覆盖。** 复用NativeServingSession、StructureComparison、ExecutionComparison及正式CLI；全worker观察与代表分类/派生绑定分开，比较按实例、flow、rank、阶段及成员工作配对。按请求归回KV预约/传输/确认/释放，核对Prebuilt前后free_pages与所有完成动作的效果，是否提交外部状态仍由控制合同决定。为已声明的支持范围说明固定代表配方应覆盖哪些有限实现分支及其依据，避免每发现一个目标缺口就追加请求或wrapper；新缺陷先返回机制/合同分析。

### S9：调度优化与一级前缀缓存

在 S8 完成组合结构独立验证和维护交付后实施。复用已经收稳的组合拓扑及代表采集机制，先接通单实例/TP 的四项能力，再补已验证 PP、PD、EP 组合中的必要交互；不自动授予所有开关组合。沿同一控制接口、KV 资源组件和模板装配扩展，不各写一套 serving 流程，也不以调度需求替代先前未完成的拓扑任务。

**1. Chunked prefill。** 明确每请求已处理 prompt 范围、本轮新增 token、既有 KV context 及实际页变化；按固定 chunk 上限和可用 token 预算选择工作。中间 chunk 只提交进度/KV，最后一个有效 prompt chunk 才进入首 token 发布，后续继续 Decode。原生页对齐和保留规则由 adapter 给出；现有 `max_prefill_tokens` 的非分块软预算不被静默改义。

**2. Decode 优先。** 从已就绪请求中先选 Decode，再把剩余批次 token 预算分给 Prefill chunk；同类请求沿明确的 FCFS 次序选择。预算不足的成员保留等待，不能丢失或提前推进；不抢占在途工作，不为调度加入手调成本系数或 SLO 预测器。普通基线与新策略共用状态和生命周期，只替换选择规则。

**3. 混合组批。** 同一批次的每个成员分别带阶段、context、token 范围和输出条件，不能继续用一个 batch.phase 推断全部成员。取得原生 mixed 路径对应的布局、attention 和状态接口；共享模型工作和融合节点只计一次，不能直接拼接两份完整 Prefill/Decode 图冒充混合执行。纯 Decode、纯 Prefill 是同一合同的合法退化情况；混合模式与 Decode 优先策略分别表达，但只支持明确取得来源的组合。

**4. 一级 prefix caching。** 首期实现设备 KV 池内的缓存，和活动请求共用实际容量；缓存索引、匹配、引用与淘汰是明确职责，控制器不复制其页账。workload 提供共享前缀身份、长度及父前缀关系，命中由目标运行中的驻留状态推导，不能输入一个固定命中率代替状态。

前缀按模型/实现及 KV 布局所在的复用域匹配，逻辑相同不表示不同 TP/PP 分片或 P/D 实例可以直接共用物理页。请求获得引用，写入完成后对应前缀才可发布为可复用；结束时解除请求引用，缓存持有的页继续驻留，只有无活跃引用的条目允许按单一明确策略（首期 LRU）淘汰。共享页只计一次实际容量，准入预算与既有峰值预留逻辑同步调整；可淘汰页、仍被引用的页和空闲页必须区分，尾页按原生规则处理。

命中部分不再重复生成对应模型计算，但匹配、页表准备、引用、必要复制及发布工作仍保留。全部可共享 prompt 命中也不直接产生输出：只有 KV 而没有可复用 logits 时，仍按原生规则执行必要末尾工作；[原生请求准备](../../../third_party/sglang/python/sglang/srt/managers/schedule_batch.py)和[RadixCache](../../../third_party/sglang/python/sglang/srt/mem_cache/radix_cache.py)作为实际命中、页对齐与释放规则依据。

**多级存储抽象。** 分离以下三个职责，首期仅设备层有实现，不增加空的 CPU/磁盘后端：

| 职责 | 合同与首期实现 | 后续扩展落点 |
| --- | --- | --- |
| 逻辑前缀索引 | 查找同一内容前缀，不把物理位置写进内容身份 | 多层仍共用索引，条目关联驻留位置 |
| KV 资源与驻留 | 每层实际容量、页/块分配、引用和数据就绪；设备层复用已有 KV 分配 | 加入 CPU/磁盘层实现，统一交接租用与驻留状态，不改组批算法 |
| 可用性与迁移 | 控制器取得可消费位置和就绪依赖；首期设备命中无需伪造传输 | 异层命中形成真实搬运动作，完成后消费，传输期间保护来源和目标 |

首期合同要能区分“逻辑命中”和“计算设备上已就绪”；具体跨层搬运、预取、回写和介质性能留待未来，不预建通用存储平台。PD 的 KV 交接可以复用共同传输/就绪表达，但服务之间迁移 KV 不等于共享前缀命中，不能合并两者状态机。

**采集与交互。** 现有会话固定关闭 radix cache、请求 token 全为 1；S9 必须同步更新原生会话和语义适配，按声明前缀构造共享部分与互异后缀并核对实际匹配，不能把偶然相同 dummy 输入当作业务命中。原生框架继续管理真实请求/KV；新增 match、insert、lock/unlock、evict 及 mixed 路径的必要来源，不能仅修改模拟器。统一预热后清空逻辑前缀缓存再开始每个配置 × workload，窗口内的缓存状态按执行顺序自然形成。

资产选择须区分影响执行实现的 mixed/cache 能力，不能把关闭缓存的旧库当作启用后的完整来源；仅组批次序不同则优先复用已有片段，不按每个开关组合复制整库。缓存匹配、插入和淘汰按稳定服务及必要端口/工作量参数表达，不为每个树节点或 CPU 内部函数生成模板。

chunk 与缓存组合时，已命中 context 不重复计算，未就绪 chunk 的 KV 不提前共享；mixed 的成员与输出逐项绑定；PP/TP 的缓存就绪需覆盖实际消费者所需分片。PD 首期仅在 Prefill 侧使用本地前缀缓存，Decode 侧仍按显式传输接收，不默认跨实例共享；若所选原生后端不允许此组合则明确不授予组合支持。EP 复用前缀还需给定路由与共享内容假设一致，并按逻辑 token 位置跳过已复用工作。

本阶段交付四项能力、必要模板/输入与设备一级缓存闭环。关闭新增开关时基线仍可运行，但实现共用一套；原生非法或未取得来源的交互明确列出，不通过扩大开关矩阵或永久保留旧路径解决。

### S10：单机完整闭环与扩展边界审查

从统一公开入口串联 S0–S9 的选定能力，核对单机设备组绑定、模板来源选择、组批/缓存状态、通信交接和逐请求结果。请求结束后活跃引用和槽位应释放，缓存持有的 KV 可以继续驻留；不能仍以“所有页都回到空闲池”判定完成。选择少量拓扑与调度/缓存联合场景，不把独立脚本当产品闭环，也不扩大为全部组合。

沿模块依赖与状态所有权审查代码，合并公共流程，删除旧单批次/固定 rank 特例和临时双路径。抽象必须服务本轮真实变化：PP 的 stage、PD 的两个控制实例和 TP 的角色绑定通过共同合同交互，不能分别复制 workflow、执行器或 KV 算法。

再用两种未来变化做静态扩展推演，记录预期修改落点和未解决问题，不编写未来实现：

- **未来替换为原生控制器：** 应主要新增控制接口实现及框架桥接；图定义、模板实例化和执行器继续消费相同动作/事件。原生状态、虚拟完成和内容结果如何交接仍待未来探索，不能承诺零修改接入。
- **未来扩为多机：** 应主要扩展部署/拓扑绑定、通信来源和资源解释；模板通过逻辑端口连接，不使用物理卡号充当全局 rank，也不将本机地址嵌入共享定义。真实跨机协议和运行资格留到未来取得。

若推演发现更换控制实现需要改模板算法，或增加主机需要重写请求生命周期，则本轮先修正已暴露的职责耦合。只调整实际合同和当前消费者，不新增原生后端空类、网络服务、模拟分布式平台或未来配置占位项。

### S11：多机与原生调度器的初步探索

前提是 S10 已从公开入口完成单机整合和必要开发核对。探索回答“现有抽象能否容纳下一种实现、还缺什么”，不将完整原生调度器和真实多机支持重新纳入本窗口主线。

| 路线 | 最小案例 | 要取得的结论 |
| --- | --- | --- |
| 原生调度器 | 选择一个短请求的原生调度路径，尝试取得工作动作、由模板执行器给出模拟完成，再触发原生下一步决策 | 动作/事件合同是否足够，状态由谁维护，必要适配集中在哪里 |
| 多机 | 复用已取得的本地模板，将一个通信组或 stage 连接绑定到两个逻辑主机，检查跨主机端口和资源归属 | 哪些只需更换拓扑/资源绑定，哪些必须取得新的 transport 或协议来源 |

原生案例保留原生请求/KV 生命周期；观察真实执行后重放固定批次不算完成反馈接入。若切断真实执行需要大范围模拟张量、复制状态机或重写 scheduler，就记录实际入口与阻碍并停止该路线，不以补齐所有私有对象为目标。

跨机案例先在单一模拟进程中检验连接，给定通信耗时仅为条件假设，不赋予真实网络资格。若现成硬件、网络和原生环境允许，可在同一案例预算内补一个最小跨机协议观察；资源不可用时明确缺证据，不安装或开发分布式运行平台。跨机因果依消息及完成关系确定，不能直接拼接不同主机的墙钟排序。

每条路线最多一个最小案例及一次有新依据的调整，执行前登记累计时间、会话和存储额度。编排和对照放在 example，必要的原生适配归 adapter；仅发现共同合同的具体缺陷时才修改核心。临时尝试没有后续消费者则删除，保留结论和必要证据即可。

交付按路线说明：已尝试的边界、实际结果、需要修改的模块、复杂性和未解决问题。结论可以是可接入、需要局部调整、代价过大或条件不足；后两者不自动扩大任务或阻止单机进入 S12。若发现单机共同逻辑存在缺陷，则先修正并通过必要开发核对，再冻结验收；探索成功也不宣称正式支持。

### S12：独立验证和正式交接

完成选定功能、静态审查和必要开发运行后，冻结源码规则、来源资产、预热约定、控制策略和条件输入，再执行下一节的独立验证。发生结构缺陷时返回对应阶段修正，原对照转为开发证据；重新固定受影响部分并更换或重新声明留出，不沿原冻结标签继续通过。

收口审查同时覆盖采集 → 归一化 → 变换 → 连接 → 控制 → 执行 → 输出。清除被新合同替代的单批次/固定 rank 路径、临时双格式、无消费者字段和实验适配；保留 TP1 的简洁路径。记录业务与示例代码净增减，跨源文件合并重复算法，不靠压行或搬目录减少统计。

输出一份易读的单机拓扑与调度支持结果：正式已验证组合、条件组合、未验证/缺来源组合，以及实际来源与费用。精简结果包含必要的实际计算 token、缓存复用/驻留/淘汰摘要，完整逐页记录仍由明细开关控制。多机、原生调度器及多级存储完整支持另列后续边界；性能建设继续后置，本窗口不计算 MAPE，也不提交成本模型。

## 6. 验证怎样有界而有说服力

验证编排放在 `example`，复用已有公开入口；核心只保留正式输入边界和运行不变量，不增加窗口专用检查、配置黑名单或第二套状态算法。以下维度在S8/S12独立验证前分别收成有界案例，覆盖已实现主机制及重要交互；S8同时完成广泛输入泛化、图内容/因果的深度核对与全业务实现/抽象分层审查，S12补新增调度/缓存和受影响部分，不生成全组合扫描。

| 机制 | 最小覆盖方向 | 重点观察 |
| --- | --- | --- |
| 新模型泛化 | Mistral-7B-v0.3与Qwen3-30B-A3B的完整模型来源及独立目标 | 相同流程自动发现/归一化/展开，新增适配范围明确，不逐模型复制核心或逐目标补采 |
| 原基线 | TP1/2/4/8、现有 PP 与最小 PD，必要请求/容量变化 | 既有结果、接收/发布职责、组成员和状态所有权保持 |
| 采集前代表复用 | TP peer、可等价的 PP 中间角色及 EP worker；留出未观察角色/运行 | 真实工作与独立绑定正确；区分会话、启动参与者、观察角色和导出开销 |
| 并行与 PD 组合 | TP×PP、TP/PP 与 EP、PD 两侧的多 rank，以及合法高阶/非对称候选 | 组交叠、层/expert 分片、KV 片段映射、通信配对及各自完成/释放 |
| PP | 当前原生合法的首/中/尾 stage、多个微批次；一个合法 TP×PP | P2P 配对、跨 stage 输入、输出回传和资源释放；PP2 在当前 Ascend 环境无原生资格 |
| PD | P/D 各侧的已选拓扑；多请求、短输出、目的容量压力及传输延迟变化 | 所需分片全部可见后才接入，背压、首 token、页释放和交接归属正确 |
| EP 条件结构 | 至少两个合法 EP 部署；同份workload的token/padding路由注入原生并驱动仿真；零接收、非均匀/多目标分发及缺项 | 部署映射、通信及跨 batch/chunk 定位正确，缓存假设一致；输入缺口不隐式补齐 |
| chunk 与 Decode 优先 | 短于一块、整块、多块尾块；新请求与 Decode 同时就绪、token 预算边界 | prompt/KV 进度正确，中间块不输出，Decode 先获预算，有限请求最终完成 |
| 混合组批 | 纯两阶段退化、同批混合、不同 context/成员退出 | 成员阶段与输出不串线，实际 mixed 来源匹配，无重复完整模型工作 |
| 设备前缀缓存 | 冷启动、重复/部分/全可共享前缀、页尾、并发引用、容量驱逐后再访问 | 实际命中及剩余计算量正确，无提前可见/重复分配/错误释放；缓存驻留占用真实容量 |
| 调度与拓扑交互 | 先 TP 下四项联动，再选择合法 PP、P/D、EP 交互；关闭新增开关的基线 | 分片就绪和作用域正确，P/D 不暗中共用缓存，不自动授予全部组合 |
| 必要完成反馈 | 固定简单控制规则，改变给定设备/通信服务时间及请求到达 | stage 推进、PD 背压及资源释放服从完成事件，不串任务或提前消费 |
| 单机整体闭环 | 一组合法的联合机制场景及本机设备组绑定变化 | 同一入口完整完成，跨组数据/事件不串线，任务与 KV 释放正确 |

采用三种互补证据：

1. **全业务实现、因果与所有权审查。** 沿源码目录、类、接口及跨语言交接检查抽象分层和统一/特化边界，覆盖未改动但关联的代码；每个数据消费有来源，必要通信有匹配端口，状态预约/提交/释放唯一，图无错误环、全局屏障或历史资源串接。核对对外声明与实现，清理冗余职责；源码审查不能替代独立运行。
2. **给定耗时的动态结构运行。** 任务交错和完成次序变化、同刻事件、无输出动作、活跃图回收，以及默认/明细输出的一致性。固定服务假设只检验控制反馈和结构，不冒充真实性能。
3. **有界的扩大独立单机多卡原生对照。** 比较局部工作、参数、数据/通信关系及关键状态转移，不只比节点总数。单卡分片继续用于取得可隔离的本地模板；各已选通信机制还必须有本机真实多 rank 代表观察，不能用顺序角色模拟代替协议证据。独立观察不回填冻结模板或提前提供目标调度答案；设备不足或原生组合无法运行时保留未验证项，不降低闭环完成条件。

轻量策略和原生策略不必生成完全相同批次；若声称策略等价，必须固定同一策略和输入条件。其余情况先按可关联的工作动作核对本地结构，再检验各自决策的规则与依赖，不能把组批差异都判成模板错误，也不能把它们忽略后宣称 serving 等价。

## 7. 代码、采集和产物边界

| 职责 | 落点与约束 |

| 值关系、共享定义、代表到 worker 的绑定、通信/数据连接算法 | 共同 contracts、graph、templates；不按模型名、框架私有函数或特定 rank 加分支 |

| 案例构造、受控路由对照编排、跨组合运行、独立比较和汇总 | example；不反向导入业务，不复制原生请求/KV生命周期或待验shape/通信推导规则 |

框架差异集中在有来源的角色、接口和规则，模型差异优先从真实模块/配置取得；只补无法自动获取的最小声明。SGLang 的 profiler 启停继续是采集 adapter 的局部实现，不为这件事另建一套框架层。新结构能力有实际消费者才增加接口或字段，C++ 头源同目录，保持必要空行和关键注释。

采集在启动前按“实现域 → 非等价角色/局部机制 → 有限观察点”规划；正式 workflow 消费原生参与者、观察代表及目标绑定，不按每个逻辑 rank 或请求集合逐次完整启动。统一预热后观察，加载/编译/预热计采集开销而不计模拟服务；新路径需明确是否预热。可隔离的本地事实优先单卡；真实协议所需 peer 仍按原生要求运行，代表观察与独立多 rank 验证分别安排。

首次原生运行前，在同一个运行输入中固定会话上限、原生/处理秒数、临时/保留字节和停止条件；实施阶段日志记录具体数值与累计消耗。本次尚不分配或消耗采集额度，不凭未核实的模型/设备估算任意数字。失败和重启继续计入原任务，遇到同类缺口无新依据就返回机制分析；已有自主采集授权继续有效，不逐次请求确认。

沿用一个时间运行根的 `inputs`、`captures`、`assets`、`results`、`diagnostics`、`logs`、`state.json`、`work` 职责。默认给人看简明组合结果、共享计数、来源/条件和缺口；完整图及原始明细在生产前由现有明细开关控制。共享资产保存定义和绑定，不为每 rank 或每目标复制整库；必需机器资产不因追求短 JSON 而被裁掉。不新建窗口专属产物平台，不清空已有 data。

## 8. 完成、停止与风险处理

**完成要求：** S6 取得真实 MoE/EP 结构证据，完成自动 padding 的有界评估并确定唯一正式路由合同；S7 完成所选 TP/PP/EP/PD 组合及采集前代表复用；S8作为执行结构里程碑，先统一workload路由条件并收口图内容/因果，在两个新模型及既有基线上扩大独立验证跨模型接入、请求/容量变换、并行组合与未观察worker复用，同时深入核对实现和全业务抽象分层，公开维护成本、正确性范围及实际采集节省。之后 S9 实现 chunked prefill、混合组批、Decode 优先和设备一级 prefix caching，明确多级存储边界；S10 整合，S11 形成有界探索结论，S12 完成新增能力的最终独立验收。每项区分待做、实施中、源码已改待验证、限定范围验证、待交付和完成；功能、代码/文档/数据检查及提交推送全部完成后才交付，不能只凭共享计数或条件展开授予组合资格。

若 EP、PD 或其他正式计划能力因原生后端/硬件/输入缺口无法完成，保留该项未完成与具体阻碍；可以先交付已完成子集，但不能自动把整个窗口记为完成。原生调度器和多机多卡的完整实现与支持验收仍留到未来；S11 以完成有界探索和明确结论为结束条件，不遗留占位实现。

| 主要风险 | 处置与停止边界 |
| --- | --- |
| 并行机制互相组合导致规模失控 | EP 后专门实现组合装配，以有限合法机制组合和非对称候选形成覆盖，不生成笛卡尔积或逐组合子类 |
| 等价归并误删角色、CPU 路径或布局差异 | 区分叶子/布局/完整角色复用，保留条件与绑定；缺依据就不合并 |
| 采后去重被当作采集节省 | 启动前确定代表与绑定，留出 worker 对照；分别报告原生会话、实际参与者及观察角色，不能将派生绑定记作实测 |
| 为单机或当前控制器写死共同流程 | 用实际 TP/PP/PD 差异检验接口，静态推演未来修改落点，修复跨层状态耦合 |
| 拓扑实现被调度优化分散 | S6–S8 固定简单控制，组合和代表复用验证通过后再进入 S9；新调度不能绕过未闭合的结构问题 |
| 缓存复用导致容量和状态错误 | 实际分配唯一，区分请求引用、缓存驻留与就绪；同内容不自动跨实例/布局共享 |
| 多级存储抽象变成另一套平台 | 首期仅设备层，明确位置/就绪/迁移边界，未来介质后端不预建空实现 |
| 为可扩展性增加无用接口与继承树 | 使用必要的抽象、组合和 C++ 模板；每个实现有本轮消费者，删除旧链路和空占位 |
| 初步探索扩张成第二条开发主线 | 单机整合后再开展，固定案例与额度；给出阻碍和改动范围即可收口 |
| 自动 padding 为简化输入反而引入复杂系统 | 先有界评估，找不到简单可泛化方法即保留按 EP 拓扑提供路由；不增加双合同或无界补采 |
| 给定路由与原生dummy自然选择不同 | 统一注入workload token/padding条件，核对原生行映射和真实dispatch结果；不回填目标图或注入预测split，不宣称自然路由正确 |
| 工作差异与必要因果未查清 | 完善阶段处理已确认的基线关键缺陷，明确策略差异及非阻断限制；正式冻结后记录新问题、继续其他独立案例并在整轮报告后修复，关键项未通过不授予资格或交付 |
| PD异构布局缺依据 | KV按head/层/页片段及真实协议映射，不用平均或补偿规则掩盖缺口 |
| 验证规模扩大却只检查完成或计数 | 预定机制/交互覆盖及深度判据，结合真实留出和全业务分层审查；不以大批量条件展开代替独立证据 |
| 固定耗时通过但资源竞争仍不可信 | 只报告条件结构资格，通信拓扑、成本采样与争用模型明确后置 |
| 开发被无界补采和诊断扩张拖住 | 采集前冻结问题/额度，开发与独立验收分开；只保留正式消费者所需代码 |
