## 2. 当前机制与边界

Python应用管理任务、累计费用和进程，框架/runtime提供原生事实；解释、C++模板生产和正式资产发布分别交接。C++维护共享定义、布局、执行模式与角色绑定，矩阵和独立评价留在example。原生控制唯一维护请求逻辑，核心维护槽位、页和前缀树，执行器维护时钟与在途完成。

各worker独立提交动作并取得自身CPU返回，TP/EP/PP通信按真实组连接；CPU元数据由进程broker交接，资源与时间仍归核心。发送图提交后可交出元数据，本地API返回、设备完成、发布和最终等待分别保留。

普通执行与真实时间旁路共用控制、构图、资源及完成接口。旁路只提供具名工作的边界时间，不提供批次、资源分配或目标图答案。组合工作保留实际来源引用，跨动作通信端点及活跃资源引用随生命周期维护。

同库主要复用请求、成员、到达、并发和KV容量变化。模型、TP/PP/EP、dtype、backend、page_size及机制域分别建来源；不把当前未实现的跨域变换写成理论上均不成立。EP使用给定路由/padding，一级缓存限共同实例或P侧；overlap、speculative和多机未正式支持，原生不支持的MoE mixed保持限制。没有实测成本模型、内部节点真实计时或精度结论。
