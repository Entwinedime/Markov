## 2. 当前机制与能力边界

Python应用管理任务、累计费用和进程；框架/runtime提供原生事实，解释与模板生产在独立工作区交接。C++生产共享定义、布局、执行模式和角色绑定，按目标参数展开；矩阵和评价在example。原生控制唯一维护请求逻辑，核心维护槽位、页和前缀树，执行器维护模拟时钟及在途完成。

每个原生worker独立提交动作、取得自身CPU返回并借用独立核心资源池；TP/EP/PP通信仍按真实组连接。CPU元数据集合操作由runtime交给现有进程broker，只传控制值，不管理资源或时间。发送元数据在发送图提交后交出，接收不等待发送方本地API返回；本地返回和最终wait仍分别保留。

普通执行与真实性能旁路共用控制、构图、资源及完成接口。旁路只提供具名工作的真实边界时间，不交出批次、分配或图答案。组合工作同时维护时间和实际来源引用；未匹配通信端点跨动作保留，图回收保留活跃引用。

同库主要复用请求、成员、到达、并发和KV容量变化；模型、TP/PP/EP、dtype、backend、page_size和机制域分别建来源。EP使用给定路由/padding，一级缓存目前只在共同实例或P侧启用。overlap、speculative及多机未正式支持；原生不支持的MoE mixed保持拒绝。没有实测成本模型、内部节点实际计时或精度结论。
