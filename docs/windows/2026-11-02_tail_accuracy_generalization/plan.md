# 尾部误差修复与泛化验证

开始日期：2026-11-02。

目标：先修正现有大误差的共同原因，再固定候选实现，用少量 base 和有界正常实测验证更多 HiCache 配置及新请求，为后续配置搜索明确可信范围。

## 1. 范围与基本取舍

按“修复 → 冻结 → 泛化验证”推进。固定 Qwen3-32B/BF16、Ascend 910B3、TP2、SGLang eager/FIA 和串行固定输出；本轮扩展配置及请求，不扩展硬件、模型、并发组批或冷存储。

普通预测继续从语义区域构建工作和必要端口。只有外部依赖、资源交错或配置决策确实需要时才细分，不能为降低局部误差恢复全量逐算子仿真。保留 KTransformers、可选 NodeScale、源/目标静态回放与独立评价，不恢复另一套旧运行系统。

完整 HTTP 包含 HiCache I/O/control、Prefill、Decode、gap、未归属成本及正式请求间隔。准备阶段不计入正式窗口，但其缓存和后台状态按原生逻辑连续推进。HiCache 结构、各类成本、源残余和采集开销分别归因，不互相吸收误差。

新增设备任务累计以 12 小时为上限；包含容器启动、模型加载、预热、执行、导出、占用设备的后处理及失败重试。TP2 的两个设备一起占用一小时记一小时设备组占用，另列两卡小时；排队等待和纯 CPU 后处理另报。12 小时是资源限制，不是完成全部面板的保证。

本窗口不开展配置搜索、不扩充通用实验管理功能，也不以增加模型或细化节点数量作为成果。三个阶段分别回答下面的问题：

| 阶段 | 要回答的问题 | 交付边界 |
| --- | --- | --- |
| 修复 | 大误差中哪些来自确定的机制错误，修正后哪些仍未解决？ | 同一旧面板的前后对照、原因及剩余限制 |
| 冻结 | 接下来验证的究竟是哪套实现、成本依据和输入？ | 可复现的候选及事先确定的验证安排 |
| 泛化验证 | 不再调参时，换配置组合和请求还能否准确预测，代价多大？ | 完整覆盖与缺项、正常精度、资源开销及适用范围 |

## 2. 修复：按共同原因处理大误差

### 2.1 先把需要解释的问题缩成几组

从已有全部误差大于 6% 的交叉格出发，按目标条件、base 和请求类型分组，不只修最大的一格。初始代表如下；它们是调查线索，尚不是已确认根因。

| 现象 | 优先代表 | 需要分清的原因 |
| --- | --- | --- |
| 不同 base 对同一目标共同低估 | C1/C2/C4/C5 → C3，w3 | 目标遗漏工作、成本口径、首次使用、正常真值波动 |
| 同一目标对不同 base 的偏差不同 | C1/C5 → C4，w1 | 源残余迁移、状态初值、源采集开销和依赖 |
| 同类请求在多个目标上偏低 | ShareGPT 多轮，目标 C5、紧主机写回、短 timeout | 计算与结果响应、请求间控制、容量和预取路径 |

每组保留一个大误差代表和一个工作量相近的较准对照。先检查已有正常重复、请求级误差、预测工作量、CPU/流端口、关键等待和成本来源，再决定是否补采。同一目标条件的实测由所有预测 base 共享。

解释误差时沿正式 HTTP 的因果路径核对；重叠的服务和等待不能简单相加，不能把某个组件时长差直接当成同样大小的 E2E 贡献。固定路径真实成本回放只作归因，不能证明超时、取消等分支已正确，也不覆盖正式预测。

调查结论至少区分：工作或依赖生成错误、变化工作的成本估计错误、源残余迁移不适用，以及正常测量波动或计时边界不一致。先用逐请求差异缩小范围，再检查对应工作与因果路径；证据只能排除其中一类时，就保留其他可能，不能统一归为“CPU gap”或“成本不准”。

### 2.2 补采与修正的边界

- 现有正常结果足以判断偏差时不重采。只有波动或环境可比性存疑时复测；只有结构边界不足时增加少量 target 诊断采集。
- target profile 和正常 HTTP 都只进入独立评价，不进入成本训练。新性能点必须来自独立小负载，有明确工作变量和计时边界，整组共享。
- 结构缺陷修改工作生成或依赖；成本缺陷修改测量边界、变量或独立模型。等待由依赖产生，不并入 CPU 服务或 I/O 速率。
- 不能按配置身份、workload 名或目标残差加倍率、常量、补偿表或专用模板。无法解释的源残余保留其不确定性。
- 预查新面板需要的页大小、长度、输出次数和首次使用范围；如果需要扩大独立成本覆盖，在冻结前用通用工作点处理，不能等留出误差出来后补点。

最多组织两轮机制修正，每轮联合修改有关生产者、消费者及调用方，再统一做静态检查、必要 Docker 构建和代表输入验证。不为单文件小修反复构建或运行完整矩阵。

### 2.3 修复后的核对

规则和公式稳定后，使用同一批现有 33 份 base、原正常真值，运行一次 186 cross＋33 self。只有输入或采集语义发生真实变化、旧资产已不满足合同时，才补采受影响条件，并单列可比较范围。

同时对照原来大于 6% 的整组、原来较准的对照组、逐 base、逐 workload、逐 target、self 和总体结果。修复应能由共同机制解释，不得以少数变好掩盖其他格恶化。保留修正前后值、证据和所有未解决项；已有开发结果不再称为独立留出。

交叉面板及逐 base 目标为 WAPE≤3%、P90 APE≤5%，单格争取≤6%；超过 10% 的格子逐项说明。阈值不因修复困难或正常噪声而放宽。两轮修正或本阶段预算耗尽后停止追加；未达标可作为带限制候选进入冻结，但必须写“指标未达”，不能写修复验收通过。

## 3. 冻结：固定候选实现和验证协议

冻结是本次实验的程序与数据选择固定，不增加内部版本号、hash 校验、冻结副本或新管理系统。

进入新面板前完成以下交付：

1. 完成关联代码审查、必要 Release/Debug 构建和公开入口验证；记录已解决原因、未解决误差、支持范围及代码净增减。
2. 固定 Git 提交、构建程序、现有成本库的训练选择及其模型导出。模型来源限于独立性能采样；新 base 只提供允许迁移的源成本，不导入训练库。
3. 固定配置候选及排序、请求生成规则和种子、资源预算、运行顺序、重复次数、缩减规则与评分公式。保存实际请求 tokens、会话身份及与历史输入的排除清单。
4. 完成旧面板精度核对，并以相同输入、一个 CPU、4 GiB 上限、相同文件缓存条件核对预测开销。与现有约 139 秒、137 MiB 的口径一致，采集/训练和外围准备另计；耗时或内存增加超过 20% 时解释其必要性，不能静默接受退化。
5. 以少量现有资产核对 KTransformers、NodeScale 默认关闭及显式回放能力，纯文档或无关链路不扩大运行范围。完成阶段整理、分层提交与推送后再开始新验证。

泛化预测显式使用同一份 performance.models，不提供 sampling_budget，不执行 maintain。预测只挂载本次选定 base、模型和输出，不挂载其他 base、target profile 或评分目录；即使另一个 base 恰好也是 target，也不能读取它。

新 base 可在冻结后采集，但观察不足、合法分支缺失或成本域外均如实记录；不能据此修改冻结规则、添加新系数或自动补采。若确需修正，结束该候选的验证，把已查看证据转为开发数据；后续修改另行评估，不把原验证结果改写为通过。

冻结记录同时写明本轮已经用于开发的配置、请求和诊断来源，以及新面板与它们的差别。新配置组合、新参数取值和新会话是三种不同证据；不能仅因组合未运行过，就声称成本模型完成了数值外推。参数范围内也可能缺少必要工作数据，预测时仍须报告这种缺口。

## 4. 泛化面板：增加覆盖，不增加整张全互预测矩阵

### 4.1 目标配置与 base

使用 C2、C5 两个现有配置作为 base 锚点，每组新请求各采两份。C2 为 64-token 页、选择性直写和等待预取，C5 为 128-token 页、写回和 timeout，并有不同的设备/主机容量。此前讨论的 C1/C5 均为 128-token 页，改用 C2/C5 能在不增加采集数量的情况下覆盖不同页宽的来源；32-token 页作为 base 仍不在本轮证据内。

目标集包含这两个锚点和 22 个未在此前 11 配置中出现的合法组合，共 24 配置。配置选择只依据合同与参数覆盖，不使用预测快慢、目标真值或误差。

| 变量 | 候选值 |
| --- | --- |
| 页大小，tokens | 32、64、128 |
| 设备 KV 容量，tokens | 3072、4096、6144、8192 |
| 主机容量比例 | 1.5、2、4 |
| 写入策略 | write_through、write_through_selective、write_back |
| 文件预取策略 | wait_complete、best_effort、timeout |
| 预取阈值，tokens | 128、512、1024 |
| timeout，秒，仅 timeout 策略 | 0.01、0.1、1；base=max，per_ki_token=0 |

其他设置沿用现有 eager/FIA、kernel_ascend/page_first_direct、file 后端和 max_prefill_tokens=4096。按原生合同及已有容量计算排除非法组合，不能根据仿真是否碰巧成功筛配置。

在合法候选中，用普通贪心选择每次覆盖最多尚未覆盖的参数值对的配置；条件不适用的 timeout 不算一个虚构维度。以两个锚点为起点，相同得分按规范化配置内容字典序确定，排除历史已运行配置与重复组合。保存覆盖情况及未覆盖值对，不承诺 24 个配置一定完全覆盖。新增配置的选择顺序同时作为预算缩减顺序。

### 4.2 四组未使用过的请求

继续使用现有 ShareGPT 语料解释方式，按会话身份排除历史开发、确认和独立校准已使用会话，种子固定为 20261102。保留选择规则、会话身份和实际 tokens；语料不足时报告不足，不以重复历史请求充作新请求。

| 请求组 | 正式请求安排 | 输出 tokens/请求 | 主要观察 |
| --- | --- | ---: | --- |
| 独立短输出 | 12 个独立请求，三档长度各 4 个 | 8 | 冷前缀和 Prefill 长度变化 |
| 独立较长输出 | 与短输出组使用相同 12 个输入 | 32 | 控制输入变量，观察 Decode 增加 |
| 多轮 | 3 个其他会话，各取 4 个用户回合，交错执行 | 8 | 上下文增长和前缀复用 |
| 回访 | 6 个其他长前缀，固定打乱顺序访问两遍 | 8 | 缓存容量、写回、预取和回载 |

独立输入长度按 [128,512)、[512,1536)、[1536,2049) 分层；多轮完整上下文≤2304 tokens，回访前缀为 1024–2048 tokens。多轮历史使用数据集原有回复，不用当次生成文本改写后续输入。四组除了独立短/长输出的受控配对，其余会话互不重合。

每组最多两个准备请求，使用另选的会话、不预填正式前缀；正式请求固定 12 个。含准备请求的累计输入≤32768 tokens、累计输出≤448 tokens，ignore_eos=true。超额时按固定选择顺序换候选，不截断出一份无法解释的会话。请求数和 token 预算写入实验配方，不硬编码进预测核心。

base 与正常实测使用完全相同的输入顺序、输出数量、empty 内核缓存初态及准备规则；drain_before_formal=true 只排空后台，不清除已声明缓存状态。正常重复保持独立进程/服务初始化语义；不为省启动把三次独立重复改成缓存连续累积的三个窗口。

报告实际触发的 Prefill 长度、Decode 次数、缓存复用、淘汰、回载和文件预取范围。某类请求没有触发一种路径时，不将其算作该路径的验证证据；也不为获得更漂亮的覆盖，在看过结果后更换请求。这里验证的是受控请求规模内的机制泛化，不代表完整 ShareGPT 分布或长期服务负载。

### 4.3 预测数与真实采集数

| 目标配置数 | 新 base 数 | 交叉预测 | Self | 正常条件 | 三次成功窗口 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 24，完整目标 | 8 | 184 | 8 | 96 | 288 |
| 18，第一缩减档 | 8 | 136 | 8 | 72 | 216 |
| 12，第二缩减档 | 8 | 88 | 8 | 48 | 144 |

计算方式为四组请求×两个 base×目标配置数，self 单列。完整档中的 176 个 cross 是两个 base 对 22 个新配置的预测，另 8 个 cross 是两个锚点互预测。新配置组合与新请求的联合泛化是主要新证据，不能把 184 格当成 184 份独立真实采集。

只采 8 份 base；同一“目标配置＋请求序列”的三次正常真值给两个 base 共享。默认不为新目标另采 profiler trace，也不打开全图输出。先对完整 24 配置做无设备预测，之后按预算决定实测档位；未实测配置只能报告预测与覆盖情况，不能计入精度验证。

## 5. 时间、启动和空间预算

| 用途 | 设备组占用安排 | 优先级与停止规则 |
| --- | ---: | --- |
| 修复诊断、必要正常复测、独立补采 | 2 小时 | 先复用资产；先验证能区分共同原因的证据 |
| 泛化 8 份 base | 2 小时 | 从代表来源估算；不足时停止新增来源，不悄悄丢一种 base |
| 泛化正常实测 | 6 小时 | 按预注册顺序选择 24/18/12 档 |
| 失败恢复、波动确认与超出估计的余量 | 2 小时 | 累计全窗口用量，失败不清零 |

未消耗额度可以在用途间转移，说明收益及影响即可，不逐次询问确认；累计不得自行超过本窗口 12 小时。编译、CPU 仿真和无设备后处理单列，不混入 HTTP 或设备占用。正式任务仍使用已有启动、请求、tokens、wall_sec 和 retained_mib 预算；全窗口累计从现有任务状态核算，不建设新的预算平台。

冻结后先执行固定试运行：C2 的独立短输出 base，以及 C2/C5、独立短输出/回访四个正常条件各一次，再运行 C2 的独立长输出正常条件一次，避免只用短输出估计长输出成本。五个正常窗口计入最终资产和预算，不额外增加正式重复；回访及长输出条件可在相应 base 采集前正常运行，但不提前评分。

用试运行与同环境历史启动记录估算剩余全部 base、正常启动/预热/执行/导出、三次成功窗口及恢复余量。按同类任务较慢的完整时长估算，未在试运行出现的页大小、大容量和长输出不能直接套用最快任务。不能用几十秒的 HTTP 时间代替一次完整模型加载成本，也不能假设 288 窗口只需 96 次启动。正常运行按当前公开入口实际执行；若需调整跨条件/跨重复运行顺序，只修改 example 编排，不建立另一个采集入口。

选档时给出可复核的估算：已用设备组时间＋剩余 base 任务估算＋剩余正常任务估算＋恢复余量≤12 小时；已完成的试运行从剩余任务中扣除。每次新设备任务启动前核对剩余额度，任务自身的 wall_sec 上限也不得超过剩余额度。单任务预算不能代替全窗口上限；沿现有任务状态累计，不清零重算。

在查看新面板精度前，选能装入剩余额度的最大档位：24 → 18 → 12。始终保留两个锚点、四类请求、两个 base 和三次成功窗口；新增配置取原选择序列的前缀。先执行各条件第一遍，再以固定种子打乱、反向次序交错后续重复，减少时间漂移和同一条件连续运行的影响。

启动失败最多按同条件重试一次，额度不足即停止；不能更改配置后沿用原条件身份。后续若真实用量继续超出估计，停止剩余任务并报告已选面板缺项，不能根据已看到的误差再次删格改分母。已完成的最低档面板可以单列，但必须同时保留原定规模与缺项。

正常三次样本若变异系数超过 3%，允许按固定条件排序最多选 8 个条件追加至五次，使用恢复余量；均值使用所有有效样本，慢样本不剔除。无额度时保留波动与精度判断限制，不放宽门槛，也不只重测预测不准的条件。

窗口新增资产保留量先按 80 GiB、在途临时额外空间按 32 GiB 安排；单份新 base 导出上限初设 8 GiB，小型独立采样保留上限 1 GiB。冻结前用既有来源的规模估计确认请求/输出上限，冻结后的试运行再核对实际峰值与预计保留量。超额时先按预定档位缩减目标实测，仍不够则停止并报告资源限制；不能边测边改变 workload，也不能只保留较小或较准的来源。

普通实测的 HiCache 临时页文件按单任务空间限制控制，只清理本任务已确认无后继用途的缓存页；trace、来源、原始正常窗口、预算与失败证据保留。不预先分配“288×单任务上限”的空间，也不删除现有正式资产腾位置。达到存储上限时停止并说明缺项，不靠删测量证据冒充小开销。

## 6. 独立评价与为搜索保留的结论

每格与该条件所有有效正常窗口的算术均值比较，完整保留样本数、范围、标准差和失败。APE 为绝对预测差/正常均值；WAPE 为绝对差之和/正常均值之和；P90 取排序后第 ceil(0.9×格数) 项。缺项不填零，未完成面板的子集分数不能标成完整 WAPE。

报告总体、两个 base、四类请求、配置维度和新配置/锚点分组，列出最大误差、超过 6%/10% 的格、误差方向、域内/插值/外推和源残余占比。两个 base 共用真值，重复窗口也不是新的独立配置证据；不把格数扩张解释成同等数量的独立样本。

Cross 另与“直接沿用对应 base 的正常耗时”比较，使用同一已实测子集计算两者误差，说明预测是否比不处理配置变化更有用。这个参照只在独立评分中计算，不成为预测输入。Self 用于核对来源到正常运行的偏差，不与 cross 混合稀释泛化误差。完整交叉面板及逐 base 仍按 WAPE≤3%、P90≤5% 评价，单格争取≤6%，超过 10% 明确列出；缺结构、缺成本和未实测分别报告，不能只统计成功且较准的格。

为后续搜索另报每类请求下候选相对锚点的真实收益与预测收益、候选排序及两种 base 的排序差异。正常样本范围重叠的候选标为暂无法区分，不强行判定谁更优。有限候选和串行小请求只能证明本轮范围，不认证全空间最优、吞吐或 P99。

正式结果放在本窗口对应的 data 目录，复用现有报告格式。保留修复前后对照、冻结时选择、全部泛化预测、正常原始窗口、失败、来源和资源用量；不给每轮建立一套平行文档。

## 7. 实施边界、交付与关闭

本次文档建立后再开始实现；不把计划中的数量写成已经完成。业务修正留在框架适配器或共同图/成本/执行职责内，实验选择、输入规模、批量次序和覆盖汇总留在 examples。优先扩展现有 HiCache example 和正式公开入口，不新增独立 test 工程、另一套模拟器或通用实验管理平台。

三个阶段分别在相关修改基本齐备后统一审查、必要验证、整理并分层提交推送；不按单个误差格、小文件或每次采集收尾。status 只写当前资格、基线与恢复起点；log 原则上每阶段交接一条，影响预算、判断或数据有效性的独立失败与取舍另记，日常采集细节留在 data。

收口需要交付修复原因与结果、固定候选依据、泛化覆盖与完整误差，以及真实采集/实测/预测的时间和空间开销。达到预定证据或资源停止条件后结束本窗口；后者标明提前结束及未完成项目，不能称精度全部通过。

时间和空间至少分为 base 采集、独立性能数据准备、已准备输入的批量预测、正常实测四项；同时给出一次新使用的前期开销和增加一个 target 的边际开销。保留可复用的输入与执行命令，使后续搜索能直接使用已明确的范围和成本依据，不必重新拼装本轮实验。
