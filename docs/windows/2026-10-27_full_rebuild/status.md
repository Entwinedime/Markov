## 目标工作与共同执行

### 已解释的计算调用

188 个源计算帧含 134,044 次已解释调用、74 种配方，展开为 191,760 个设备操作和 57,716 条配方内部依赖。源变量重绑定无差异，全部调用获得原生规则及唯一 caller/worker/device 关联。
线性、归一化、激活、注意力、输入复制、嵌入及掩码、Q/K reshape、位置编码、输出裁剪/转换与贪心采样均已进入共同调用过程。

框架适配器生成准备代码、原生提交及设备工作，共同编排器维护 caller、worker、设备的连续依赖；注意力准备后不再强制等全部设备工作结束才进入计算主体。
一次调用的多次设备发射共享一次提交和返回，例如采样的归约与类型转换；纯视图仍支付自己的 CPU 工作。派发延迟从提交与前一后台任务均完成后起算，不占服务资源。
同步读回先等生产者，再支付 API 自身服务及读回尾部，没有用父包络或设备墙钟补 CPU。

最终三种页大小各完成 188 帧、134,044 次计算调用、191,760 个计算设备服务、188 次 metadata、各 94 次 Prefill/Decode 分配和 12,220 次共享通信。
三种几何共有 2,545,344/2,545,352/2,545,348 个原生计费操作，其中 metadata 为 13,348 个、Decode 分配为 16,262 个、Prefill 分配为 9,788/9,796/9,792 个，派发延迟均为 187,624 个。计费操作数包含 CPU 服务及残余区间，不等于原生调用数或设备操作数。
计算与缓存联合运行各完成 47 请求，I/O 最终空闲，设备、主机和文件容量未越界。
本批两个最终进程约 119/100 秒、峰值约 2.45/2.33 GiB，每个进程只准备一次来源；前者含三个缓存目标，后者为额外页几何计算子集，两者均含读入、构图、回放及校正核对，不是完整预测时间或 10× 成绩。

注意力准备与分配现在共用准备序列合同、CPU 区间及资源索引和编排路径，角色只用于报告。分配与计算 caller/worker 相同，设备流不同；目标保留分配流，并在有序生产者链上交接到 forward，不把分配放到计算流。
单 token Decode 分配按目标长度和页大小生成页内/新页分支，使用已有独立模型；当前限未排序 NPU 页池、int64 序列与 int32 位置。32/64/128 几何各有 94 次新页分配，额外 96-token 几何的 94 次页内分配生成 7,802 个计费操作，均完成全部已知计算。
96-token 只验证组件几何与工作生成，没有真实部署或完整 HTTP 资格。排序/合并池、记录/等待 API 及其余跨流执行仍未接通。

Prefill 分配在未排序 NPU 页池、int64 输入/位置、单请求及 task queue 下生成新页计数、同步读回、少于 200 个新页的融合内核和输出转换。分配索引视图来自目标自身的申请/归还轨迹；普通帧变量与分配输入共用 FrameInput，不抄 source 的偏移或编译次数。
每个目标显式选择 kernel_cache_initial_state 为 empty 或 prepared，维护自己的规格缓存。空缓存三种几何分别准备 6/10/8 个规格，各计划两次首次加载；按请求工作独立计算的唯一规格数与节点数吻合。已准备分支不再加入准备，缺少初始状态时在首个计算片段前停止。计划计数不表示一个未完成目标已实际执行这些工作。
编译、首次加载、后续加载均来自独立校准，作为 caller 阻塞区间单独绑定。首次加载按固定启动器接口解释共享初始化，编译与后续加载仍保留规格覆盖；当前只支持每个 caller 一个启动器接口，不能推广为任意内核或磁盘缓存状态。空缓存首次响应与已准备分支的差额恰等于独立编译及首次加载成本之和，但这只是依赖与计费检查，不是精度。
新增 Prefill 区间从 source 调用外部分划出，原图、回放、既有 CPU 角色及总覆盖均未变。此前 1-token 几何的零计算执行属于旧子集边界；现行融合分配不支持该规模，未复验，不能套用旧成功/停止位置。

原生审查补上旋转位置编码表在多行时的两次连续化复制，并限制未解释的多 tensor 混合 dtype 复制与直接 Triton 发射。当前真实来源没有覆盖这些额外分支；它们只有静态机制与构建依据。
目前验证范围仍为既有资源放置、Ascend eager、单请求和已解释的阻塞通信路径；不包含 speculative/SWA/MLA、任意部署或跨流执行。

### 缓存、文件服务和通信

源 token 祖先关系含 26,133 个前缀；32/64/128-token 页各形成 47 请求和 34 个非根 radix 分段，全量前缀需 816/408/204 页。页身份与实际驻留、在途复制、发布状态分开。

Ascend kernel_ascend/page_first_direct 在第 0 层传完整批所有层，不按层均摊虚构提前发布。

文件服务按整批整理、逐页读写/复制/发布、控制接受和 worker 返回执行；超时与取消使用同一时钟，停止后保留在途读取及一次被拒绝发布的复制，缓冲区到实际返回才归还。
前批三种页大小分别运行 wait_complete、best_effort 和 75 ms timeout，共九个联合情形；全部完成 47 请求，容量有界且 I/O 最终空闲。本批增加 Prefill/Decode 分配及准备后复验三个 timeout 目标，仍全部完成且容量有界、I/O 空闲。
等待完成没有拒绝发布，超时及 best_effort 都保留在途读取与拒绝发布的复制。查询/准入暂为逻辑即时动作，因此 best_effort 的即时停止还不代表完整原生行为；文件阶段成本也不是逐段独立实测。

外部请求端口已接入共同执行：开始、接收、响应开始与响应完成分别记录；下个请求依赖前一响应，后台 I/O 可继续运行。显式 drain 屏障额外依赖复制、存储读返回、写完成及控制接受的实际前沿。
入口与响应尾部只沿用同一请求、同一前端部署的源残余间隔，不占 CPU 服务资源，也未迁移客户端间隔或诊断 checkpoint。
每种目标绑定 94 段残余，三个目标共用 94 个来源求值；全部端口顺序和间隔与声明一致。timeout 三个目标最后响应后还有约 40.9/29.6/17.8 ms 后台工作，响应与子集清空时刻已分开。

24,440 次参与者调用归并为 12,220 次共享通信，实际输入完成后登记到达，到齐后绑定一次服务，再释放后续工作。
