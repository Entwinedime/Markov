### 计算配方与页几何

188 个计算帧中，108,664 次已解释原生调用归并为 40 种配方，展开为 162,808 个操作、54,144 条配方内部依赖；源变量重绑定全部一致，无缺失行数绑定。
覆盖线性、RMSNorm、相加、激活，以及受支持 FIA 分支的 K/V 写入、非连续值连续化和 score；其他计算、通信及 CPU 仍未完整解释。
一次调用可产生多个操作，不能继续把调用数与操作数混为一谈；内部依赖不等于完整目标图。

源 token 祖先关系共 26,133 个前缀。32/64/128-token 页各生成 47 请求、34 个非根 radix 分段，完整保留前缀需要 816/408/204 页。
三组均生成上述计算子集；客户端 drain_hicache 屏障位于第 35 个请求之后，不迁移源等待或 checkpoint 断言。
这是不淘汰、无 padding 的内容集合与工作量检查，不代表真实目标驻留、峰值容量或最终命中。

Cache 集中维护分段容量、引用、复制、发布和确认，分裂保留保护。有限两级缓存程序已按容量和写策略主动生成备份、回载及相应计算工作，成本缺口不改变合法动作。
此前 128-token 页的 D2H 域外已用独立测量补齐，write_back 三组页几何均完成 47 请求，证据在 data/rebuild/finite_cache_dma_covered/；其余旧两级结果保留在历史日志。
计算参与进程和写回备份批次以显式边汇合；回载在设备分配前保护主机来源，传输接管保护直至确认，后台工作不强制在每次请求末清空。
文件存储现可按声明容量淘汰键，先整理整批再逐页发布文件；查询按实际主机锚点和跳过设备前缀后的 token 链解析，而非默认完整 prompt 键。
预取分别维护读、复制、发布、控制接受与 worker 返回；停止后仍执行原生要求的一次被拒绝发布复制，缓冲区到实际返回后才归还。
wait_complete、best_effort、150 ms timeout 及补充的 75 ms timeout 各运行三种页几何，共 12 个组件情形均完成 47 请求并清空 I/O 队列；设备/主机/文件容量峰值未越界。
75 ms 情形中，64/128 页各先接受 4 页再停止；best_effort 在当前即时准入假设下接受零页，并保留后续读和被拒绝的复制。
证据在 data/rebuild/storage_wait/、storage_timeout/、storage_best_effort/、storage_partial/；每进程约 80 秒、峰值约 2.21 GiB，各仅准备一次来源。
这些是对称参与进程、空初始文件存储和部分成本下的仿真。查询/准入及其他 CPU、通信、完整跨流依赖和完整原生批次仍未验证，不输出 HTTP 耗时，也未独立对照 target 结构。
