## 已有组件及边界

缓存维护目标自身的容量、前缀、驻留、引用、回写、回载和确认。文件服务逐页读写/复制/发布、取消与缓冲区归还在同一时钟推进；后台不在响应后强制清空。
Ascend kernel_ascend/page_first_direct 按整批跨层 DMA 发布；查询/准入仍为即时逻辑，best_effort 与 timeout 尚非完整原生行为。

计算使用框架描述的原生调用，共同编排 caller、worker、设备、派发和同步读回。阻塞通信等待实际到齐后查询一次服务；参与者暂共享最晚完成时刻。
前批已核对 188 帧、134,044 次已解释调用、191,760 个设备操作及 12,220 次共享通信，新增区间没有改变这些来源事实。
未变设备迁移只限独占关联、完整工作及原资源相同的服务；变化或归属不明的工作查独立模型，不迁移源排队等待。

注意力元数据、未排序 NPU 页池的融合 Prefill 分配及单 token Decode 分配共用准备序列。
目前限 int64 Prefill、少于 200 个新页和 int32 Decode 位置；分配与计算同 caller/worker，保留各自设备流及有序生产者交接。
每目标显式选择 empty/prepared 内核初始状态并维护规格缓存；现行首次加载模型只覆盖一个已解释启动器接口，不能套到新发现的内核族。
选定独立模型仍为 1,720 项；编译/首次加载/后续加载的独立依据保存在 costs/preparation_import/。96-token 只有组件几何证据，没有真实部署资格。

入口与响应尾部引用同一请求/前端的来源残余，不占 CPU 服务资源。串行请求依赖前一响应，drain 另等真实后台完成。
响应仍接在选定计算全部完成之后；原生重叠提交、结果可读与返回之间的交接未完整表达，也未覆盖完整请求控制和跨流依赖。
调用间 CPU 只在无未建模提交、无未表达等待、来源完整且同 caller 配方的区间保留残余近似；覆盖部分用校正，未覆盖部分保留原值，不能授予任意 shape 的 CPU 精度。
