## 当前可以怎样运行

正式 predict 接受 deployment、workload、base、targets 和独立性能来源；准备或复用 base，按整组缺口准备成本，再批量预测。
普通预测解释源语义区域，不建源细图、不读大型设备 trace；同次会话共享来源和模型，每个 target 独立维护状态。
预测容器仅挂载程序、所选 base、只读模型、准备输入和输出，使用 runc，无设备、数据库或 target/正常评分挂载。
结构由执行规则生成，变化工作使用独立成本，已证明不变的成本才迁移；完整正式 HTTP 不扣 gap、未归属控制或 Prefill/Decode。

SGLang 当前范围是 Qwen3-32B/BF16/TP2、Ascend 910B3、eager/FIA、串行固定输出，支持有限容量、三种写策略、回载失败、文件预取及取消。
CPU 返回、流进度、结果可读和缓存发布分开；workload 可声明正式窗口前排空后台，不读 tensor/cache snapshot。
KTransformers 已用 Llama-2-7B/float16、单 NPU、Torch/dense 实跑 self、分块 Prefill 与 SDPA；仅 empty 初始化，没有 HiCache。
NodeScale 默认关闭；显式源/目标固定路径回放保留归属和依赖，不重新选择时间分支。
镜像是 markov-modeling:ubuntu24.04、markov-sglang:ubuntu22.04、markov-ktransformers:ubuntu22.04。

独立校准表明，同一请求中首个热 Decode 的 caller 可约 0.67 秒、后续约 0.14 秒，CPU 各约 0.17/0.14 秒；其设备区间却都约 0.15 秒。
变化发生在 worker forward 内。实际镜像的 AscendAttnBackend.init_forward_metadata 用设备 seq_lens.max() 作为主机切片上界，存在需要验证的同步读取边界。
这支持先检查前序设备等待的归属，不直接加历史特征或调整倍率；需轻量边界观察确认并让规则表达必要依赖，再估计同步之外的响应。
