# 稳态、分层模板与 CPU 建模计划

开始：2026-10-17。更新：2026-10-20。状态：**进行中；逻辑审查与限定域交接已完成，完整测量和性能资格未完成。** 此窗口继续保留，不因文档整理或业务审查结束而关闭。

## 目标与范围

在声明域内，用少量分层、参数化模板和可测 CPU/设备成本预测预热后 serving。当前推进重点仍是逻辑、边界和必要交接；暂不启动请求精度验收。

四个难点分别处理：

| 问题 | 方法 | 判断依据 |
| --- | --- | --- |
| CPU 路径导致子图膨胀 | 包装函数留在适配端；循环量参数化；真实分支才形成变体 | 新请求不逐调用增加语义定义，接口与状态仍成立 |
| CPU 如何测量和建模 | 独立线程服务切口，排除明确观察工作；等待走依赖、传输单独收费 | 样本与目标同特征同切口，扰动和重叠有证据 |
| 模板如何分层 | 五类顶层动作，模型/serving 内部区域；父自身工作与子组合分开 | 每项工作唯一归属，无虚构同步或重复计费 |
| 模板如何归一化 | 定义、来源、绑定和目标实例分开，规则按实际语义共享 | 同结构调用复用；未合并差异有机制依据 |

验证域固定为 SGLang + Qwen3-32B dense、BF16、Ascend TP2、ascend attention 及同一软件部署；FCFS，无 prefix cache/overlap/graph/mixed/chunk。请求池容量 1/2、总 token 容量 16384；单请求 Prefill 2–128 token、输出 1–5 token，考察成员、排队、错峰、页边界及已有资格的 Prefill 预算变化。

这些数字界定本窗口证据，不新增按数字硬拒绝的通用规则，也不撤销其他规则的条件能力。更换模型、TP、backend、dtype、并行或控制机制不在本窗口自动取得资格。

起点为预热完成、无在途请求、cold logical KV，保留协议允许的缓存和 workspace；不从繁忙服务中途截取。模型加载、首次编译、预热和 HTTP/tokenization 排除，窗口内业务分配/扩容仍保留。

## 剩余工作的顺序

### 1. 收清测量资格与结构边界

复核 CPU 记录开关对照中仍安装的回调及线程校准，区分已排除观察量和未证实的运行扰动。需要新增证据时，选择真正不安装成本插桩的稳态对照；不按整体差值写补偿系数。

核对 SDK 内部就绪聚合是否跨过必要接口，以及其与设备等待、driver 复制的重叠。优先静态推导和已有事实，仅以能区分近似的少量实际批次取证，不恢复逐 API 建模。

来源依赖仍有 partial 项。先判断是否影响已承诺目标的必要因果；会影响则修生产/连接合同，不影响则明确适用范围。未覆盖的容量转折和优化机制不得顺带纳入；也不能把保留限制当作已完成承诺。

### 2. 完成必要成本覆盖

使用正式目标查询合并 CPU、计算、通信、传输及命令需求，先复用已有样本，再安排可构造、有收益的独立采样。配方由原生请求生命周期执行，框架管理 KV/worker；实际特征决定覆盖。

成本不足不重采结构；新增候选后从初态重算全部组合，检查新的时间反馈是否产生新需求。配方重复而无新增证据、合同不足、不可达或预算耗尽时停止，不用零值推进，不建立另一套补采循环。

先保持有依据的测量查询。只有独立误差和样本覆盖表明必要时再引入复杂回归，不把模型复杂度作为阶段目标。

### 3. 条件满足后再做独立验收

进入条件是：当前模板与规则已正式消费，目标必要关系核对完成，CPU 测量及近似适用性明确，范围内所有收费对象有真实成本。用户要求的“先理清逻辑”未完成时，不启动 P7。

验收按结构 → 固定实际工作下的局部成本/重叠 → 请求指标进行。新输入在运行前确定，覆盖双请求同时到达、三请求排队以及页边界/错峰；配置取已声明容量与 Prefill 预算变化。用于修正的输入转开发用途，另选独立输入。

保留已确定门槛：同范围请求完成时延、TTFT、每请求平均输出间隔的相对误差中位数≤20%、P90≤30%；总窗口和吞吐相对误差≤20%。分并发和请求类别报告，少样本列全量，单输出无平均输出间隔，近零项另报绝对误差。门槛不因成绩修改。

最后沿公开示例从空资产检查建库、成本、预测及独立对照，并检查重建、缺数据继续与终态恢复。全部产物归于单个时间根，验证数据不挂入预测或拟合。

## 资源与实施纪律

优先沿完整生产/消费链静态审查，必要时整段删除重写。公共合同、生产解释、模板、控制、成本、执行和外围编排各自拥有数据，框架/runtime 差异不进入核心。不改 `.clang-format`，不新增 test 工程、兼容层、硬编码拟合或治理平台。

每批新增采集前在执行记录明确问题、复用事实、最短触发、累计原生/后处理/存储额度及停止条件；自主采集授权继续有效，无须逐次确认。初始化、预热、失败和恢复均计入实际开销，不以新请求重置预算。

只做与修改相关的 Docker C++23 构建和公开入口验证。结构定义、规则、样本、产物及代码规模分别观察；数量增长先查必要性，不以压行或删重要信息达成数字目标。
