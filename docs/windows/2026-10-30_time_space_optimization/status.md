## 已确定的边界

- 允许同步粗化：每格相对细粒度 E2E 偏移 ≤2%，同真值总体 WAPE 增量 ≤1 个百分点。
- 新性能采集成功提取、入库并核对后默认保留小证据；base trace 和现有资产不自动删除。
- 时间首要目标已按用户补充调整为：完整单目标预测比相同 workload 的 base 正常真机运行快至少 10 倍；另列源 DAG 复用时间及旧模拟器对照。内存降至原来的 30% 以下、空间减少 90% 以上仍为目标，均未达验收。
- 完整 HTTP 保留 gap、未归属成本与 Prefill/Decode，不为速度调参、删工作或排除失败格。
- 仅操作本仓库；不改另外两个项目，不恢复数据传输或 archive 符号链接，不续跑已终止研究。

## 阶段 A 结果与交付

- 起点为已推送的 `933318a`，开发分支 `perf/time-space-optimization`。计量实现未改变模型公式、策略或依赖；Release 完成统一构建，补齐头文件依赖后增量构建10项通过。Python Ruff、C++格式和差异检查通过，调用方/生产者/消费者已关联审查。
- 四类输入各三次，完整单目标墙钟中位数为 599.76 / 165.47 / 134.60 / 142.13 秒。3次同源四目标组为 418.15 / 422.79 / 423.79 秒，每组只准备一次源；另做1次查询诊断。25次目标HTTP与5项图规模计数均等于旧同输入结果，不是新的准确性验收。
- 查询诊断为556,428次调用、2,361个模型工作点，查询计时2.21秒、缓存命中0。30秒 perf 样本支持边哈希与索引为热点，但部分共享库符号未解析，不能当作全作业的函数占比。
- 主要耗时是源区域替换/结构准备。大图首次为354.45秒，动态执行87.38秒；成本包加载只约0.51秒。源CPU校正文件约99–462 MiB，C++仍整体解析JSON，Python元信息读取已轻量化。PSS快照开销也已单列，后续比较要保持相同观测条件。
- 协议、逐次结果与汇总分别在 `data/modeling_runs/time-space-20261030/baseline_protocol.json`、`baseline_measurements.json`、`baseline_analysis.json`，`protocol_complete=true`。输入只引用原资产，新目录未拷贝/清理旧数据。
- 全部预测结束后复核已有正常base报告，每类5次均值为41.416 / 4.817 / 9.400 / 18.724秒；10倍目标对应4.142 / 0.482 / 0.940 / 1.872秒。来源及范围在同目录 `real_machine_reference.json`。完整预测是否作为主计时范围暂按包含读取/构图执行，两个口径都会保留。
