# Markov 仿真时间与空间开销优化计划

开始日期：2026-10-30。目标：在保留完整预测语义和明确误差边界的前提下，大幅降低预测及性能维护的时间、内存和空间开销。时间的主要验收目标是预测比相同 workload 的 base 正常真机运行快至少 10 倍，具体计时范围见 6.2；相对旧模拟器的加速另报。

本窗口针对 `/home/markov` 的现行老项目。恢复工作先读 [status](status.md)，再读本计划；
实际行动与证据只记在 [log](log.md)。计划中的目标不代表已经实现，阶段进度不在本文重复维护。

## 1. 目标和已确认的取舍

base trace 可以保持必要规模；性能采集、性能库和一次预测不能继续承担同样大的时间与空间成本。
本轮沿现有三阶段建模流程优化，不重建另一套预测器，也不恢复已终止的自动寻优研究。

用户已确认两项取舍：

- 允许同步推进粗粒度仿真，不要求等所有结果等价的优化完成后才开始。每格完整 E2E 相对现行细粒度
  预测的偏移不超过 **2%**，相同真实测量下总体 WAPE 的增量不超过 **1 个百分点**。
- 新增性能采集在成功提取、入库并检查来源和覆盖后，默认保留小型测量证据，完整 trace 可以清理；
  完整保留作为显式选项。这不授权删除现有数据，也不适用于 base trace。

时间的首要参照是真机：相同 workload 下，预测应比 base 的正常真实运行快 10 倍以上，而不只是比旧模拟器快 10 倍。base 实测采用同 token 工作量、关闭 profiler 和计时探针的正常 HTTP 正式窗口；不拿带采集墙钟充当分母。

最终需要同时交付：达到真机对比目标的预测、更小的运行与维护资产、可解释的粒度边界，以及公开入口下可复现的结果。
不能通过缩减验证面板、漏掉成本或提高并发来替代算法优化。

## 2. 范围与调查方法

围绕两条现有输入主线修改：base 采集、CPU 校正、原始构图与目标执行；独立性能采集、观测提取、SQLite、训练与成本包交接。公开预测、实验和搜索继续使用同一个预测器，不引入另一套业务流程。

优先核对重复的所有权和工作，再决定压缩表示或缓存：

| 调查范围 | 主要代码入口 | 需要分清的问题 |
| --- | --- | --- |
| 成本输入与目标配置 | Python `modeling/execution/model_executor.py`、`runner_adapter.py`；C++ `cli/prediction_batch.cpp` | 哪些包可共享，哪些派生值与统计属于 target |
| 源与目标图 | C++ `cli/workflow.cpp`、`source_dag/index.cpp`、`core/dag_mutation.cpp` | 原始证据、只读索引、可变状态及失效节点分别由谁持有 |
| 展开与调度 | C++ `modules/hicache/runtime/tensor_program.cpp`、`window.cpp`、`simulation/topological_simulator.cpp` | 必需执行边界与无外部作用的内部步骤如何区分 |
| 成本查询 | C++ `cost/operator_model.cpp` | 数值计算、字符串处理、覆盖查询与统计各自的开销 |
| 性能维护 | Python `preparation/performance.py`、`modeling/source_dag/observations.py`、`modeling/cost/` | 必要原始证据、重复观测、大中间对象和长期存储的区别 |

上述 Python 路径相对 `scripts/internal/markov_internal/`，C++ 路径相对 `src/modeling/trace_graph/src/`。实现已经具备的同批源共享、紧凑邻接和延迟解析应先复用，不重新包装成新功能。历史报告只用于选代表输入；实际时间占比、内存和优化收益在新基线中测量。

## 3. 改造后的职责与粒度

### 3.1 原始证据、执行表示和报告分开

大 trace 用于理解原始执行，预测运行使用必要的执行信息，性能维护保存可复用的测量依据。

| 层次 | 内容 | 生命周期 |
| --- | --- | --- |
| 原始采集证据 | base trace、原始时间、事件关联、manifest | 按资产要求保留，允许较大 |
| 源执行信息 | 请求、操作、资源、外部依赖、可迁移成本、HiCache 状态事实 | 同一个 base 在一次预测会话内共享 |
| 目标执行状态 | 新增工作、变化依赖、队列和执行时间 | 每个 target 独立，结束后释放 |
| 性能数据库 | 工作点、测量分布、适用环境、来源 | 跨预测组维护 |
| 成本包 | 公式、系数、覆盖范围和必要来源引用 | 整组 target 共享 |
| 预测结果 | 完整 E2E、状态、缺口、近似说明、输入引用 | 默认紧凑保存 |
| 实验诊断 | 原始回放、结构比较、展开图及细节 | 显式开启，独立保存 |

保持三个建模阶段：原始 DAG；目标工作及依赖；成本绑定及同钟执行。
结构不读成本系数，成本提供者不创建操作或改变策略，时间条件仍在同一个仿真时钟触发。

### 3.2 必须保留的边界

- CPU 提交、worker 接收、设备完成之间的异步关系。
- 资源切换、队列竞争、跨 rank 通信及同步。
- HiCache 容量变化、逐批发布、取消、超时和接纳重试。
- 请求开始结束、正式窗口与准备窗口的边界。
- 有外部消费者的中间结果，以及会被其他规则观察的执行时刻。
- HiCache I/O/control、Prefill、Decode、residual gap、未归属成本及采集开销各自的归属。

### 3.3 可以合并的内部工作

- 同一资源上、无外部消费者、无状态变化的连续串行工作。
- 不影响其他操作启动的内部零成本连接节点。
- 具有相同依赖和发布时刻的连续页范围。
- 已证明只贡献总服务时间的内部计算链。

不能把 CPU 提交、设备执行和 CPU 返回直接相加成一个串行时长；跨资源区域先压缩表示，保留必要端点。
合并条件按依赖、资源和语义定义，不按 C1–C5、workload 名、层数或 cell 身份硬编码。
未知区域保留细粒度；不能因为缺少数据而删工作或填零。

## 4. 分阶段修改

### A. 建立能解释开销的基线

目的：确认当前代码的时间和内存分布，避免凭静态猜测安排全部优化。

在已有摘要中增加少量阶段计时与统计，不另建监控系统：

- 配置与成本包加载；trace 读取、关联和原始构图；CPU 校正加载、源操作识别和索引准备。
- 目标区域替换及结构准备；成本查询、执行调度和结果输出。
- 原始、有效、失效、合成节点和边；成本总查询、不同工作点与缓存命中数。
- 批次墙钟、CPU 时间、进程组峰值内存、新增落盘量。

不在每个节点打印日志。普通运行只输出阶段摘要，细粒度计数可关闭。
嵌套阶段注明包含关系；并行 target 的时间和共享准备时间不能直接相加冒充批次墙钟。
内存区分共享页、目标私有内存和进程组/容器峰值，不能将多个进程 RSS 简单相加。

代表输入选用已有数据：

1. ShareGPT 回访大图：C5 → `tight_host_writeback`。
2. `w3_prefetch_admission_ladder_and_survival`：C5 → C4 best-effort。
3. `w2_writeback_dual_tier_cascade`：C4 → C3 write-back/wait。
4. `confirmation_sharegpt_independent`：C5 → `wide_device_wait`。

另选上述同源输入的完整 target 组，测量共享准备和批量收益。这些名字只用于实验选择。
用单并发测算法成本，用固定相同并发比较批量效果；冷启动与同会话后续预测分开。
代表集各运行三次报告中位数与范围，不清理宿主机全局页缓存或挤占他人资源。

完成判据：有当前代码的新基线、输入和执行参数记录；能区分性能维护、预测和正常实测成本。
不重采整套矩阵，不恢复已终止的搜索。

### B. 消除重复成本包和重复查询

范围：Python 预测编排、离线成本包导出、C++ 配置加载、成本提供者、结果输入引用。

- 成本包按会话加载一次。target 只保存策略和共享成本包引用，移除逐格嵌入的完整 `operator_models`。
  页大小派生量在执行边界计算，各 target 引用同一只读模型集合，查询计数独立。
- 成本包的来源集中保存，各模型保留自己的来源引用，不能用整包来源集合替代每个模型的来源关系。
  联合工作点使用明确特征序列对应的数值坐标；回归变量与覆盖变量仍分开，保留所有坐标、联合覆盖和外推标记，
  相同工作点集合只保存一次，模型记录引用，不能只剩各变量最小值、最大值。
  离线导出与全部消费者一起改，历史包显式转换，不长期维护两套运行格式。
- 模型身份提前解析为内部编号；已测组合建立查询索引；纯数值响应按模型及完整输入变量复用。
  依赖队列、缓存状态或执行时钟的结果不缓存成静态成本。
- 缓存命中仍按真实使用次数累计查询和外推统计；不能因复用隐藏未见工作。
- 每个 target 保存紧凑结果、配置引用和必要缺口。资源细计的采集开销单列，详细内存快照与查询计时在生产端按开关启用，比较时保持相同观测条件。展开图仍显式开启。
  单格复现能够读取共享引用，不要求复制整包。

共享实验源回放文件的落盘位置及引用随 C 的 PreparedSource 所有权一起调整，避免在两个阶段重复改报告接口；默认关闭的行为不变。

完成判据：同参数代表格的预测值、执行决策一致；target 增加不增加共享成本文件副本；
186 格默认预测产物争取减少 90% 以上。更换成本包开启新会话，不增加版本、SHA 或冻结副本系统。

### C. 同一 base 真正只准备一次

范围：源索引、各模块源观测、图所有权及批次生命周期。

- 扩展现有 `PreparedSource`，集中保存只读邻接、资源、操作观测、CPU 队列、请求锚点、HiCache 事实和可迁移成本。
- 实验源回放按 base 保存一次，各目标引用同一报告；同步独立评分消费者，不复制逐格回放。
- 只依赖 base 的识别工作移到 target 执行前；target 容量、页几何和策略仍由目标结构阶段处理。
  原图索引不能直接用于已经变更的目标图。
- CPU 校正区间同样归源输入管理。消除逐区间重复线程身份、整份 JSON 中间树及无必要的区间复制，保留原始整数坐标、累计取整、区间拆分、来源绑定和重叠检查；不能以压缩或预绑定为由再次扣减采集开销。
- 取消每个 target 的完整源图复制。原始证据和源执行信息共享，target 只拥有保留工作的运行状态与新结构。
  诊断通过来源引用访问原始事件；预测必需字段提前解析，避免目标进程修改源侧延迟缓存。
- 若源区域替换仍逐 target 重复，将只依赖 base 的分割、删除计划、原始 host 程序和资源关系编译一次。
  共享描述只保存源事实及绑定位置；target 状态、接纳判断、回调和成本提供者仍独立建立。
  不能把第一个 target 的模块对象直接当作缓存，也不能把改变后的图继续套用原图索引。
- 联合检查源读取、通道关联与构图的重复扫描和缓冲区生命周期。提前筛选必须保留跨窗口因果尾部、
  初始化事实和参数上下文；原始 trace 不修改。读取和编译仍计入首次完整预测，不通过前移准备来改计时口径。
  分片预扫描、参数遍历和文件所有权一起处理，保留验证事件过滤、来源及整数时间精度，不能靠关闭过滤或改用浮点时间换速度。
- 在执行入口压实目标的邻接和调度状态，只为仍需执行的节点分配运行时编号。请求锚点、回调及来源继续使用稳定图身份，通过统一映射衔接；保留的证据记录不进入调度。结构存储的进一步缩减与 D 的少展开共同处理，避免压缩后再逐模块修补身份。
- 源索引共用，mutation 使用受影响节点和边的邻接信息。具有顺序依赖的修改分批提交，不为省扫描随意交换顺序。
- 收敛每次 mutation 的整图 prospective copy、拓扑扫描和 effect-edge 哈希重建；利用已经建立的 DAG 不变量及受影响区域验证修改。环路、引用、组件归属、原子修改和边重复语义仍须保证，不能仅关闭校验换取速度；Debug 保留完整诊断核对。

完成判据：只读源观测和索引每会话建立一次，target 不增加完整源图副本，源数据不被目标修改；
不改变结构规则和公式时预测结果一致。

### D. 减少目标节点和调度事件

范围：张量操作程序、CPU/设备任务表示、HiCache 回调和仿真器。与 C 同步设计，使用统一源信息和节点身份。

控制点直接插入也要延续已证明的拓扑顺序：收集新增或改向的边，批量判断局部插入能否成立，不能因每个控制点编辑就退回整图验证。无法证明时仍走完整校验；开始事件执行后释放这份准备期证明，避免为动态节点维护无用记录。

- 结构生成时合并符合条件的串行内部链，不先生成数百万节点再清理。
  合并由依赖和资源决定，成本来自原有模型，gap、服务、等待仍分开归属。
- 异步操作保留提交完成、worker 释放、设备完成等端点；无外部作用的内部步骤用紧凑程序表示。
  timeout 或其他模块观察到的中间边界不能消失。
  优先处理连续 K/V 页提交与拷贝：结构记录重复次数、首个提交、末次提交和完成端点，成本阶段仍使用原来的单次服务与整段传输估计，在同一时钟计算两条流水线的重叠。保留原来按累计字节分摊的整数耗时，不能直接用“大块拷贝耗时”替换一系列有提交间隔的拷贝；存在逐页发布或外部消费者的区域不按整段合并。
- 资源和操作模型沿用既有内部身份，同一调用的不可变描述共享；避免逐节点复制来源、名称和 shape。成本来源继续使用现有绑定合同，不为编号另建一套登记表。实验需要的原始步骤映射保留合并前后的对应，不以减少节点丢弃来源。
- NodeScale 在合并前作用于对应工作；无法保留名称匹配和执行成本语义的区域保持细粒度。
- 构建时登记边界需要的回调，普通计算节点不再询问所有 HiCache 模块。保持同刻事件的优先级与处理顺序。
  已执行状态复用仿真器数组，减少独立集合。
- 细粒度和合并表示使用同一个执行器、时钟、成本及状态规则。细粒度保留为验证选项，不发展成另一套算法。
  不满足条件的区域自然保留原粒度并报告原因。
- 若紧凑程序仍把每个内部步骤物化成 DAG 节点，继续收敛为程序内部的紧凑指令和必要执行端点。
  内部步骤仍按原成本参与资源竞争与同刻排序；存在外部消费者、共享资源竞争或规则观察的位置必须能让出执行，
  无法证明可合并就保留原粒度。不能另建一套分析时钟来修补结果。
- 执行中的内部编号、成本、前驱和资源使用紧凑数据，避免为每次内部推进重新分配字符串、属性表和树集合。
  成本来源、覆盖次数和原步骤映射保留；NodeScale及实验展开仍能访问必要的细粒度信息，不保留两套正式执行规则。
- 实验结构报告与执行表示同步收敛，只保存评分消费的工作、边界及必要依赖投影，完整图继续使用现有显式诊断入口。
  折叠未归属中间步骤时保留已比较操作之间的可达性、资源关系、来源和未覆盖项；同步评分消费者并核对比较结果与覆盖计数，
  不能把原有差异改成未比较，也不能为每个target重复保存相同的源描述。

完成判据：依赖、资源竞争、发布和取消行为正确；完整 E2E 满足 2% / 1 个百分点边界；
同时报告节点、事件、时间和内存变化。不能用缺失成本、遗漏 gap 或改变正式窗口换取速度。
超限时按操作类别停用或修正合并规则，不能按 cell 增加例外。

### E. 将性能维护改成小规模、可持续的数据链路

范围：独立采集、观测提取、SQLite、训练和产物生命周期。

#### E1. 按工作覆盖安排采集

- 按操作、shape、实现、计时口径和运行状态定义需求；已有适用数据先复用，缺失项才进入采样计划。
- 请求数、输入长度、输出 tokens 和重复次数由采样配置控制，不硬编码截断。
- I/O 原语沿用小型独立测量；复杂控制与异步行为用必要的短运行片段。CPU、worker、device 与 residual 不混用。
- 冷启动、编译、首次加载和后续加载分开。服务实例仅在状态能恢复、测量口径一致时复用；必要时仍重新启动。
- 重复样本数量和停止条件在采集前声明，不根据 target 误差选择追加样本，不把重复层数当作变量覆盖。

#### E2. 减少提取和导入的中间副本

- C++ 分批输出标准操作观测，Python 流式消费；不整体载入巨型 JSON 再跨 capture 累积全部行。
- CPU 校正、控制与张量观测共用一次必要的关联和索引。确需完整因果关联时仍复用现有构图能力，
  不另写一套简化归属规则。
- 每个 capture 处理后及时释放；SQLite 批量写入、采集级事务，保留重导入去重、冲突检查和失败回滚。

#### E3. 数据库保存工作点和测量分布

继续使用 SQLite，不引入数据库服务。

- 环境、操作、实现、特征和来源集中登记，同一完整工作点只存一份特征描述。
- 按 capture 和工作点保存样本数、耗时分布和变异信息；原位置及来源映射采用紧凑证据表示，减少长字符串重复。
- 不混并不同 capture、运行状态和实现；重导入冲突不能被聚合隐藏。
- 现有数据转换优先保留精确耗时分布。训练按 capture 和回归坐标聚合，保持独立采集权重；
  不能用若干中位数的中位数替代原分布的中位数。
- 覆盖坐标和回归变量继续分开，压缩数据库不能悄悄改变拟合含义或丢掉未进入回归的覆盖条件。
- 显式转换到新输出，检查成功后再切换引用；旧库和已发布成本包保持可用，不原地覆盖。

#### E4. 产物保留

- base trace 保留；新性能采集的完整 trace 默认是临时输入。
- 提取、入库、来源与覆盖检查成功后，默认保留测量、分布、必要片段及配置，完整采集可显式保留。
- 失败或提取不完整时不自动清理原始输入；清理不得早于所有声明消费者完成提取。
- 原始 trace 删除后，已有测量必须仍能独立训练。需要新增未提取特征时，明确报告重新采集需求。
- 现存采集目录和旧数据库不自动删除；先列引用和可清理资产，再单独处理历史空间。
- 长期空间计入时序日志、CPU 校正、测量、数据库和必要配置，不能只报操作测量文件的压缩率。
  必要证据优先无损压缩；采用紧凑存储时同步修改生产者、所有消费者和引用，验证后再切换新资产，不能直接改扩展名。

完成判据：新链路能完成采集、提取、去重入库、训练和缺口报告；迁移已有数据时响应与覆盖语义保持一致。
新小型采样另验覆盖与 E2E，不把旧数据转换成功当作采集缩减成功。
设备、导出、入库、训练时间及临时峰值、长期保留空间分别报告。

### F. 批量预测与搜索共用会话

## 6. 验证指标和效率目标

### 6.1 精度与语义

记同一格的细粒度预测为 `P_fine`，优化后预测为 `P_new`，正常 HTTP 实测为 `T`。

- 粗化偏移：`abs(P_new - P_fine) / P_fine <= 0.02`。仅对成功且基准时间为正的预测计算，失败不填零。
- 总体误差：`WAPE = sum(abs(P - T)) / sum(T)`；要求 `WAPE_new - WAPE_fine <= 0.01`，即增量不超过 1 个百分点。
- 两侧使用同一面板、同一正式窗口和同一正常测量。未完成格不得静默排除后宣称整板通过。
- 同时报告各面板、逐 base 的 WAPE、P90、最大误差和失败项，避免总体均值掩盖退步。
- 结果等价的共享、索引、存储优化不使用粗化容差掩盖错误，预测值和执行决策应保持一致。
- 粗化容差不是置信区间，也不是实际推荐收益的保证；收益接近数值变化幅度时，不宣称可靠排序改进。
- 不能排除 gap、未归属成本或 Prefill/Decode 后仍称完整 E2E。成本维护的新采样结果与结构优化对照分开报告。

### 6.2 时间和空间

| 指标 | 优化目标与统计口径 |
| --- | --- |
| 相对真机的完整单目标预测 | 首要目标：`T_base_normal / T_predict_wall >= 10`；从已有 base manifest 和成本包进入预测，到结果返回，包含源读取/构图、结构准备、执行及输出 |
| 同源后续 target 预测时间 | 另报复用 base DAG 后的 `T_base_normal / T_target_wall`，并与旧模拟器同输入、同成本、同并发比较；不得代替完整预测指标 |
| 包含源准备的整组时间 | 报整组墙钟、每目标摊销及一次性准备；不能用摊销或并发掩盖单目标未达标 |
| 单目标峰值内存 | 争取降到原来的 30% 以下，共享源和目标私有内存分开统计 |
| 默认预测落盘空间 | 争取降低 90% 以上，共享输入不逐格复制 |
| 性能维护长期空间 | 争取降低 90% 以上，同时报告覆盖是否相同 |
| 性能采集开销 | 分别计启动、设备运行、导出与处理，不把少存文件等同于少采集 |

计时范围目前暂按包含源读取与构图的完整预测作为主指标；用户若明确选择 DAG 准备后的预测为主，则调整主次，两个口径的证据仍同时保留，不修改已测耗时。

按需启动 modeling 环境时，将启动开销与预测计算分别记录；未明确采用就绪环境验收前，主墙钟不扣除启动。
即使用户选择已启动环境，仍计入成本包加载、base 读取与构图、目标变换和执行，并保留完整首次公开入口墙钟。

`T_base_normal` 是所选 base 在相同 workload 的正常正式窗口，多次测量取均值；target 真值仍只在预测完成后独立评分时读取。采集和离线性能维护不计入每次预测，但其取得成本单独报告。若将准备前移到显式可复用资产，必须同时列出取得和加载成本，不能改名后从主指标消失。

以上资源数值是优化目标，不是静态分析已经证明的成绩；阶段 A 的新基线用于量化每阶段贡献。相对旧实现的 10 倍不能替代相对真机的 10 倍，未达真机目标须明确报告差距。
不能把局部加速比相乘，也不能通过缩小 workload、减少 target、关闭必要语义或把资产移到其他目录达标。
对旧数据转换与重新设计的小型采样，分别比较，不能用数据覆盖变化伪装压缩率。

### 6.3 必要场景与验证节奏

覆盖同源多 target、分批提交、成本包切换、冷启动与复用；覆盖 wait-complete、best-effort、timeout、
写回与选择性写入、页大小和容量变化、接纳重试、ShareGPT 独立与回访。
重点核对 CPU/设备重叠、通信等待、逐批发布、取消，以及缺成本、范围外、采集不全、重导入冲突、
中断恢复、内存保护和 NodeScale。

不新增独立测试工程或测试文件。通过正式入口、既有真实输入、必要产品不变量和静态检查验证。
以跨文件的完整职责改造为批次，批次中做静态审查，在阶段必要边界统一检查构建；不是逐文件编译，
也不是所有阶段结束前不检查。C++ 编译和格式检查在 modeling Docker 中完成。
开发期以代表格为主，没有新风险不扩大检查；完整 186 格在实现稳定后统一执行，不因每个小改动重采或重训。
