# HiCache 数值模型

本文说明 HiCache I/O 与控制开销、以及 Prefill/Decode cost model。执行流程见
`docs/modeling_development.md`，实测结果见 `docs/validation/hicache_validation.md`。

## 三阶段重构中的成本接口

当前统一成本包已离线发布 1,689 项声明，来自 32 个训练来源、63 份来源 manifest；
当前 base 不在线拟合，target 评分也不回写模型。ShareGPT 新留出 54 格使用同一包，全部完成完整 HTTP 评分，
没有新增校准或重训；原 72/60 格最终代码回归及独立评分也已完成，
全 186 格低于 10%，但两批回归的严格门槛未通过。结果与来源清单见 [工作进展](work_progress.md)。
模型声明就绪不等于所有变量组合实测或成本覆盖完整，也不证明 target 结构完全正确。
下文说明成本的来源、形式和适用限制；局部训练误差不代表目标精度。

10-10 的共享包中，独立操作查询的范围与 I/O 参数覆盖要分开看。预取的正常运行修正倍率
只来自一份 page32 独立配对、四次操作；用于 page64/page128 时沿用端点倍率，属于未验证外推。
回载的 setup/带宽只在 page32/page64 识别出合法参数；page128 的测量未能同时给出非负 setup 和正带宽，
当前沿用 page64 端点，不能称作 page128 已测覆盖。page32 的每调用拟合锚点为 4–248 MiB，
page64 为 24–216 MiB；超出调用大小范围也只是按服务公式外推。
D2H 的三个页宽均有运行修正锚点，已有存储键的 H2S 修正倍率却只有 page128 锚点，较小页宽沿用它。
新键 H2S 沿用三个页宽的物理公式，推理时争用未单独验证。以上都不证明全部 batch 或资源状态有覆盖；
证据在当轮 `independent_calibration/io_domain_review.json`，评分中的 `by_cost_query_domain` 只分类独立操作查询，
不能用“没有域外操作查询”代表整个 I/O 模型没有外推。

普通单请求 Prefill 的最后一行选择单独建模，不混入输出投影。长度处理是一个 int32 元素
提升为 int64 后求和、减一；选行从 `[input_rows, width]` 中读取一行，输出 `[1, width]`。
当前独立观测的 width 固定为 5,120，长度处理元素数固定为一，因此各服务先用常数近似；
`input_rows`、`width`、`selected_rows` 用于限定选行适用域，不按全部输入行数线性放大传输量。
CPU 提交、worker、设备和各残余间隔分别训练；没有 CPU leaf 的外层间隔仍作为 residual，
不是宣布 Python 代码没有耗时。每类 14 条独立采集内观测按既有工作点聚合，
其中 cumsum 设备服务在 82–208 微秒之间，波动明显，不能把常数近似称为精确物理规律。
41 项声明已完成离线训练，尚未作为跨页大小目标预测的精度证据。

Q/K reshape 先由目标张量布局决定是否复制；一行输入的视图分支只调整元数据，不生成 clone 设备节点。
这个分支的 CPU 服务和残余间隔分别采用常数模型，行数、头数、头宽、元素数及原始行步长限定适用域。
10-10 已有 page32/page64 两份独立完整/轻量配对，各口径共 768 条观测；样本已入库但原训练声明遗漏该分支，
因此补充声明而不重复采集。不能用多行 clone 的入口开销、其他 view 操作或缺失值零填充替代这项测量。
两项模型已离线发布并用于换 base 预测；同一采集内重复层调用不等于多个独立负载样本，
正式目标精度以独立评分为准，不由这 768 条观测推断。

eager 输入准备按实际缓冲区注册信息分组：同一源/目标 dtype 的张量一起复制，token 轴
随输入行数变化，请求轴在当前单请求范围内保持一。设备复制以组内元素总数为变量，
Prefill 使用带截距的线性模型，固定单行 Decode 使用常数；张量数与 dtype 限定适用范围。
入口整理复制列表、后续组间推进和末尾主机复制/视图整理是三个不同的主机操作，各用常数近似，
CPU 服务与残余间隔分开。没有 CPU leaf 的组间片段仍保留残余时间，不宣称 Python 循环免费。
新增 page32 独立配对后，样本覆盖 32–2,944 行 Prefill 和单行 Decode，组内布局固定；不据此支持
任意批量、自定义 buffer 回调或域外形状。52 类计时项已训练，两个复制模型各有七个采集/工作点、
两个参数。int32→int64 与四张量 int64 复制的训练内 WAPE 约 2.08%/10.33%；后者跨采集波动明显，
不把局部线性模型称为精确带宽规律，也不把训练内误差当成目标精度。

`prefetch.check.best_effort_to_stop` 表示 best-effort 分支从执行检查到进入停止调用前的控制区间，
不是存储传输或等待设备完成的时间。独立存储恢复负载已获得四条双 rank 观测（59–88 微秒）；
与其他检查片段一样使用有范围限制的常数声明，`participants`、`rank` 只限定测量条件，不作为配置专用系数。
这几条数据只补充该合法分支的成本依据，不证明其他页大小、全部时序分支或目标 E2E 精度。

页表索引的设备工作拆成非连续视图整理和行索引。整理量由请求表行数与上下文长度决定，
索引量由选出的 token 数决定；表行数、原始列宽及批量限定布局。页大小只用于随后的页号除法，
不作为前面索引成本的适用条件。两个设备段分别估计，worker 启动与返回单独测量，不再叠加父设备总耗时。
page32/page64 独立数据已验证两段可测，但单行表、完整列宽及更大工作量仍没有相同强度的实测覆盖。

页号除法前的非连续视图整理还区分 Slice 和 AsStrided：完整页可走 Slice，末页不满时按 CANN 的边界规则
走 AsStrided；这个选择由结构层决定，不由哪种成本样本更齐全决定。AsStrided 设备成本声明为
“固定启动成本 + 每个选中页索引的增量成本”，两个系数仅从独立操作测量拟合；worker CPU 和残余启动间隔
分别使用常数，不计入设备时间。页大小、输入元素数、选中元素数及 batch 限定设备模型的适用范围，
不启用域外外推。page32 的共享部分页采集已提取三个口径各 14 条样本、七个工作点，page64 各 12 条；
page128 的完整/轻量配对和独立入库也已完成。三项模型已完成独立训练并纳入统一成本包；
重复 rank 测量不等于独立重复采集，也不能证明各页大小之间可任意插值。

页表整理的 Prefill/Decode 标签不另定义两种底层工作：`ascend_page_table_division` 对两阶段使用
同一 int32 输入视图、页步长与上下文整除规则，生成相同 Slice/AsStrided 子启动。
因此，这个操作族的设备服务、worker 启动服务和启动残余间隔显式合并两阶段的独立观测，
仍按实际实现与计时口径分别训练，原始标签与来源保留。外层调用、准备、派发和返回不因此合并。
这依赖当前部署下相同子启动的成本不由阶段标签决定的近似，不证明所有主机调度环境都相同；
页大小、工作量及 batch 的原有适用范围不变，也不开放域外外推。缺某阶段标签不必重复采集
同一个底层操作，但缺少实现或必要几何仍需要独立数据，不能借其他张量的同名 Slice 补齐。

词嵌入掩码的三个整数乘法先将布尔 mask 提升为 int64，再执行乘法。结构与测量共用这两次启动规则。
Prefill 的设备段按元素数做局部线性估计，固定单元素 Decode 用常数；主机与 worker 各段分别估计。
page32 独立数据各计时口径已有 14 条观测，重训和两个代表格复验已越过该缺口；单次采集内的重复调用不是多个独立工作负载，
不能据此宣布精度或泛化通过。

缓存写入需要区分连续数据与行间带间隔的视图。Qwen3 普通 Prefill 的 V 来自合并 Q/K/V 投影的 split，
而 K 经归一化和 RoPE 后使用新输出；Decode 的融合 QKV 则有自己的输出布局。
结构侧使用实际 K/V 元数据，或按同轮同层的生产者观测还原布局，不从设备启动次数反推生成规则。
当前接入 bfloat16、头维度连续、token 行之间有间隔时的 Slice→Scatter；一行或连续更新不生成 Slice。
两个设备段分别按元素数建模，行步长与行数限制适用域；CPU/worker 启动及返回仍各自计费，不叠加整段设备成本。
Release/validation 及独立提取已通过，两个设备段和相应 worker 口径各有 896 条观测。
每段只有一份独立采集、四个聚合工作点：整理与写入的训练内 WAPE 分别为 1.57%/7.53%，不是目标精度。
共享包已完成重训，测量覆盖 32–2,944 行、每行 512 元素、源行步长 5,120；不允许范围外外推。
dtype 转换后的布局及其他存储格式不冒充已支持。

连续 K/V 更新都调用同一 `npu_scatter_nd_update_`，当前 Qwen3 部署的元素类型与每行大小相同。
本轮训练声明让连续 V 写入的设备服务、worker 启动服务和启动残余间隔显式复用连续 K/V 的独立观测；
仍按元素数和行数限定范围，外层 CPU、派发及返回不合并。带间隔的 V 仍使用上述 Slice→Scatter 两段，
不能借连续 K 的测量省掉整理。该声明已纳入统一包并用于本轮预测，模型发布本身不是精度结论。

回载准入的准备段位于首次设备分配之前，负责遍历 host 节点、保护祖先并拼接 CPU token 索引。
当前 CPU 服务沿用 `固定开销 + 每个 requested_token 的增量开销`，残余间隔另用常数近似；
参数只来自独立完整/轻量配对。token 总量、页宽和参与拼接的节点数限制适用域，
`pages = requested_tokens / page_size_tokens` 不另设独立范围门：这里复制的是 token 索引，不是按页复制 KV。
各坐标在范围内仍不证明其联合工作点已测过；节点遍历与祖先锁的差异尚未单独参数化。
这项去重不放宽后续设备索引、DMA 或存储服务的工作量检查，不允许成本缺口改变回载结构。

Ascend 设备事件记录和事件等待使用共享的原语描述 `device.event.record/wait`，
层等待、通信、加载和写回只共享这项设备服务，不合并调用者 CPU、worker、派发或返回开销。
设备服务回答的是“一条事件指令本身花多久”，不是“等前面的工作结束花多久”；后者由依赖和同一执行时钟产生。
样本来自同部署独立 trace 中的原始 EVENT_RECORD/EVENT_WAIT，每个原始设备事件只进入共享族一次。
等待样本必须具有唯一已完成的同步前驱，合成等待和包含实际等待的区间不参与这项训练。
单条指令首轮使用常数模型：每次采集先取中位数，再按独立采集等权估计；没有 target 或调用位置专用系数。
这是指定硬件/runtime 下的近似，不证明所有流争用和事件模式都具有相同开销；数据范围、波动和整数微秒仿真精度仍需说明。
没有合格设备样本时报告缺成本，不拿主机返回时间、同步归一值或其他组件残差补齐。

贪心采样在已确认的 Ascend 910B、连续单行 float32 logits 路径下，分为求最大值索引和
int32→int64 索引转换。前者的工作量是词表宽度，后者只转换输出行数个索引，不能按词表大小
计算转换量。两步共用一次任务提交，但有各自的设备服务和 worker 启动段；成本导出不再同时
保留父操作设备总量来重复计费。规则来自 [CANN ArgMaxV2 实现](https://gitcode.com/cann/ops-math/blob/master/math/arg_max_v2/op_api/argmax_v2.cpp)
及 [aclnn 调用链](https://gitcode.com/cann/ops-math/blob/master/math/arg_max_v2/op_api/aclnn_argmax.cpp)，
并由本次独立 trace 的 ArgMaxV2→Cast 顺序交叉核对。它不是其他硬件、dtype 或布局的通用规则；
新分段样本已在本次独立采集上提取：28 次采样共导出 364 条分口径观测，包含两次启动的
worker 与设备成本，不再导出父调用设备总成本。相关模型已纳入统一成本包。

同步读回先等待设备结果，再复制到 CPU。调用和依赖可以证明这项工作存在，但只有主机/设备
时间顺序自洽，才能从原始区间扣除设备等待并导出 `blocking_readback_interval`。
时间矛盾不再导致结构操作消失；它只使这项返回成本不可用，等待前的独立 CPU 准备观测仍可提取。
本轮 trace 已发现设备完成晚于同步返回的情况，尚未校正。
[CANN 时间线说明](https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/920beta1/devaids/Profiling/atlasprofiling_16_0059.html)
也说明频率换算和 Host/Device 同步可能造成错位；这只是已知风险依据，不证明本次偏差的具体成因，
更不能据此按 target 误差平移时间轴。
随后在同一设备做了不加载模型的原生事件诊断：九次成功同步中，后七次 profiler 设备完成时间晚于
主机返回；首末 profiler 间隔也超出主机包围区间。该证据排除了本项目图变换造成这次异常的可能，
但没有给出历史 trace 的精确校正参数。下一步需取得同次采集的独立时钟依据及误差界，不能将诊断中
约 20 ppm 的设备 API/profiler 增量差直接硬编码到所有 profile。诊断资产和数值见工作进展。

读回返回现在另导出 `post_sync_readback_interval`：从实际同步调用返回到外层读回结束，
两个端点都来自主机，包含同步复制和调用尾部，不包含同步 API 自身。独立前缀采集已得到四类操作
各 14 条这类观测。它不能单独替代完整返回成本。
`calibrate-hicache idle-sync` 单独测量 SGLang hook 实际拦截的 `rtStreamSynchronize` 和
`rtStreamSynchronizeWithTimeout`，而非仅凭 trace 的 ACL 名称选取外层 API。
先完成一个设备事件，再以原生循环批量测量空闲流同步，超时接口使用 -1。
这提供已就绪情况下的开销近似，不测量争用或从阻塞中唤醒的额外延迟；这些限制不能因数值很小而省略。
当前成本提供者已将返回估计改为两项之和：独立原语的空闲同步常数，加对应读回操作的
`post_sync_readback_interval`。普通同步和无限超时同步作为同一 runtime 空闲服务族估计，
实际 API、rank 和重复次数保留在观测位置中，不增加接口或 rank 专用拟合系数。
页式加载和写回提交也使用这一空闲同步原语：同步前准备单独测量，同步返回后的间隔单独测量，
同步服务绑定在设备完成依赖之后，不再把阻塞同步墙钟混入准备成本。定位服务在等待之后是一项近似，
并未测得阻塞调用内部等待前后的完整 CPU 分解；沿用下述唤醒/争用限制，不据此声称已建模全部同步成本。
这只适用于当前支持的普通/无限等待路径，不推广到有限超时、不同 stream flag 或阻塞唤醒策略。
本次原语常数为 1.738865 微秒；仿真按现有整数微秒规则绑定。四类读回尾部常数为
25、27、41、29.5 微秒，分别对应 Prefill 上下文、Decode 上下文、Prefill 扩展长度和 allocator 页数。
尾部首轮仅支持单请求、单元素读回；总时间不再叠加原先受时钟偏差影响的完整返回测量。
这些是各自独立测量的中位数，不是目标精度成绩，单采集/工作点的零训练残差也不证明泛化。

正式流程为“原始 DAG → 目标操作及依赖 → 成本绑定与执行”。后文历史实验成绩不能作为本轮验收结果，
成本包声明就绪和 60 格执行成功也不证明全部成本归属或预测精度已经达标。

成本数据库只接纳显式选择的独立测量，离线训练成本包；当前预测 base 不自动入库或参与拟合。
按原采集与操作位置去重，不按特征相同合并不同真实测量。重复导入时新增的声明路径、
完整/轻量配对来源仍保留，用于训练留出，并随参数包导出，避免换路径后绕过 base/评分数据隔离。
采集别名与测量依赖分开：留出任一已知别名会排除同一次采集及依赖它的测量，
连续导入形成的同源别名链也会完整展开；配对来源只用于排除依赖测量，不沿依赖反向扩展别名。
因此不会仅因两份测量共享轻量参考，就把它们认作同一次采集。
这些关系只描述来源，不使用文件摘要或内部版本号；新增来源声明后须重新离线导出成本包。
计算工作量由共享 shape 合同定义，历史测量导出和目标查询使用同一套单位与公式。

普通 all-reduce 的新口径是 `collective_completion_interval`，回答“所有 rank 输入就绪以后，
整组还要多久才能全部完成”，不是通信带宽。独立源 trace 中用各通信节点原始前驱的完成时间确定
输入就绪；最晚就绪到最后一个通信完成的区间作为一个组样本，不将同组各 rank 重复计为独立测量。
缺前驱观测、存在合成前驱、前驱时间与设备开始时间矛盾或协议有多个通信节点时，当前不导出该样本。
它依赖同机已对齐的时间坐标，不借此支持未知跨机时钟。

载荷变量是 token 行数、hidden width、元素字节数、逻辑张量字节数和参与者数；它们不是全部都要拟合的
独立变量。另有动态变量 `arrival_span_us`，表示各 rank 输入就绪时间的差距，预测从生成的就绪点计算，
不读取 target trace。该差距可能影响最后就绪后剩余的协议工作，因此不能默认为任意到达模式都可共享同一成本。
提取时先把每个输入就绪时刻投到整数微秒坐标，再计算到达差，与执行器的输入精度一致；
完成区间本身仍用原始纳秒时间差保存小数微秒。不把 0.226 微秒的原始到达差下限直接用于拒绝同一 tick 到达的预测，
也不通过扩大训练范围或修改服务测量解决这个单位精度问题。旧派生观测需要显式重提取并重训。
训练仍使用显式声明的常数或线性模型及适用范围，系数只来自独立采集；没有足够变量变化时报告缺数据，
不增加逐配置系数，不能把查询成功当作模型精度证据。

本轮独立数据已为普通双 rank eager 通信训练首批模型：调用者每个准备/提交/返回片段、
worker 启动/返回及事件操作使用各自的常数，限制在已测张量数量、rank 数和工作范围内；
不是把整个通信调用压成一个 CPU 常数。Prefill all-reduce 的完成区间使用
`截距 + 字节系数 × logical_tensor_bytes + 到达差系数 × arrival_span_us`。
Decode all-reduce 的实测载荷固定，因此只估计截距和到达差系数，不从单一字节量臆造带宽。
本轮 Prefill 完成区间的训练声明同时接纳同实现、dtype、hidden width 和双 rank 的 Decode 观测：
底层归约根据载荷与就绪条件工作，不根据阶段标签选择成本。沿用上述线性形式和实测范围；
较大的 Decode 到达差与较大的 Prefill 载荷若未共同出现，仍标为未见组合，不宣称联合覆盖。
调用者与 worker 模型保持分阶段；这项声明还需统一重训和复验，不复制 Decode 系数或放宽外推开关。
普通 logits all-gather 在 Prefill/Decode 中调用同一个 `all_gather_into_tensor`，当前观测的 dtype、
载荷和双 rank 实现相同，原始 trace 显示同一 BFP16、MESH-RING-NHR 路径；阶段名称不是设备成本变量。
因此完成区间使用一个 `collective.all_gather` 常数模型，显式合并两种调用上下文的独立测量，
CPU 调用者/worker 仍保留各自的模型。已有小/大到达差的服务分布相近，分采集斜率正负不稳定，
不继续拟合其局部斜率。10-10 泛化实验的 370 项独立测量来自 17 份采集，
到达差 0–100、500–1000、1000–2000 微秒的服务中位数分别约 17.86、17.54、16.33 微秒；
最大到达差 3070 微秒仅有一次测量，完成区间为 25.54 微秒。
当前对相同载荷和实现允许仅 `arrival_span_us` 外推，保留全部实测范围与超范围查询标记；
其他变量仍严格限制到实测范围。这是固定小载荷服务近似，不是任意错峰协议的已验证模型，
没有获得域外误差界，也不允许将实际等候时间并入服务或因此声称成本覆盖完整。
训练声明可用 `observation_operations` 列出有机制依据的等价观测操作；默认只用同名操作。
同一原测量不复制成新的采集，原始操作名与 provenance 保留；此选项不是任意合并不同实现或计时口径的许可。
到达差影响的是全部输入就绪后剩下的协议工作，实际等待仍由依赖计算，不能把它重复当作排队时间相加。
这些模型来自两份独立运行中的多个通信调用，不把调用数当成独立采集次数；训练内残差不是跨配置精度。
当前矩阵已完整执行，仍未验证更大载荷、多请求或新的到达模式。

普通计算的首轮主机成本按固定调用路径估计：Linear、归一化、门控激活、Embedding、位置编码、
Attention 准备、logits 和采样分别保留调用者、派发、worker 启动与返回口径。
这些主机片段先用独立采集的常数，不把设备上的矩阵元素数直接乘成 CPU 计算时间；
设备服务另用其工作量模型。所有已观测几何字段用于限制适用范围，不自动增加回归系数。
常数只是已测固定路径的基线，不能证明几何范围内完全不随工作量变化；派发及残余间隔还保留测量时的调度条件。
当前训练先按同次采集的回归坐标取中位数：常数模型可能把多个实际 shape 汇成一个点。
因此其低训练残差不能证明各 shape 的精度，须结合原始耗时范围、被合并工作组和最终运行报告判断，
不得以此省略缺少设备模型或未测实现的报告，也不据 target 残差反向调整常数。

离线算子模型现在附带 `training_fit`，报告同次采集/同工作点中位数上的拟合误差、参数数和剩余自由度。
这些是训练内诊断，不是留出精度；工作点数等于参数数时，近零残差仍可能只是恰好定参。
局部线性回归的截距或系数可能为负，不应逐项解释为物理服务时间或带宽；总响应为负时仍作为成本缺口，
不截断为零，也不根据 target 分数自动调整公式。本轮十项设备模型与 I/O 的具体训练范围见工作进展，
这些模型已纳入统一成本包；未被统计的节点和保留残余等待仍使整体成本覆盖为 partial。

I/O 报告区分成功参数来源与仅被考察的数据；失败拟合可能影响物理公式的选择，
后者仍保留在成本包的数据隔离来源中。缺少声明需要的 I/O 成本时，包标为缺数据。
取消、发布和资源选择不是成本公式的一部分，规则侧读取执行完成坐标，而不读取 I/O 回归系数。
Prefill 的 `attention_token_pairs` 是 `n × (context + n/2)` 的二次工作量代理，
不是精确的因果注意力配对数；Decode 第 `i` 个零起始轮次的 attention 上下文是 `prompt + i + 1`。
缓存页数按目标页大小向上取整，不等同于 kernel 内部 tile 数。结构账本保留基本工作量，
不另存可由这些量推导的模型变量。这份 shape 合同本身不决定后端算子布局，也不证明布局已生成。
base 成本仅用于对应、未改变操作的迁移。目标新增或改变的操作按工作量查询成本包，
CPU service、CPU 残余区间、worker service、派发间隔和设备 service 分别管理，缺测不填零。
预测不读取数据库原始 trace，也不读取 target 真值；成本模型不能决定操作数量或依赖关系。

成本声明区分拟合变量 `features` 和可选的范围变量 `coverage_features`。后者只记录样本所覆盖的
工作条件，不增加回归系数；常数模型因此也可以限制到已测工作范围，而不是默认适用于任意大小。
训练要求两类变量都有测量依据，预测要求目标描述提供同口径变量；外推仍由显式选项决定。
每个操作、实现与计时口径只能对应一项训练声明，通配声明不作为具体声明的隐式备用项。
补采前若发现声明重叠、目标描述缺少变量或模型产生无效耗时，整组先报告需要修正的原因，
不继续为其他缺口采集后再尝试训练；这些问题不能靠重复采集解决。
变量各自的最小/最大范围不能证明多变量组合覆盖，未见组合仍需在结果中说明。
这不自动选择变量或改变已有模型形式，也不因矩阵成功便宣布未见变量组合已验证。

加载提交、加载准入和逐层等待不再使用 `load_submission_calibration`、`load_index_calibration`、
`layer_wait_calibration` 原生字段。独立导出的 `operator_observations` 进入数据库，保留各次调用的
工作点与测量来源；不以按 rank 汇总的均值选择目标程序，也不按 base 中的近邻片段决定页数。
这些控制族的实际数据覆盖、完整执行分支和外推范围仍待收口与运行验证。

写入提交的独立观测也由普通 profile 入库提取，前提是该采集已有同源 CPU 配对校正。
它与专门的写入导出共用布局识别及测量口径，不另造一套拟合数据；CPU、残余、worker、派发和事件服务分开入库。
这些观测只提供成本证据，不能决定目标执行结构，也不包含另由 I/O 服务计量的传输载荷耗时。

加载索引的设备工作量应按实际张量操作区分：页号乘法处理 `pages` 个元素，
`arange` 只生成 `page_size_tokens` 个偏移，广播加法及索引复制处理相应 token 数。
不能因为申请 token 数变大，就把固定页大小的 `arange` 也按申请长度放大。
首批声明仅在独立采集的范围内使用常数或带截距的线性近似；CPU 提交、worker、派发和残余间隔
分别估计，不吸收进设备服务。仅两个尺寸的训练不能证明泛化，也不支持未测的多节点拼接分支。
设备观测保留原始小数微秒；DAG 仿真的整数时间粒度不是训练数据的测量精度，
不得将小于一微秒的复制或拼接截断为零后入库。

前缀拼接另有一个执行条件：输入中是否已有非空的设备前缀。独立回放确认单非空输入的设备服务
约为 0.5–0.6 微秒，两个非空输入约为 7.6–8.8 微秒，不能仅扩大长度范围后混成同一种固定开销。
当前声明用输出 token 数表达数据量，用 `nonempty_inputs` 区分已测的一/两段输入；CPU 提交和 worker
启动也按这一分支分别估计，残余与派发仍单列。系数只由独立测量训练，不从代表格误差修正。
此处仅支持已有测量范围，未测的多输入、尺寸组合及跨设备泛化不因这次补采而得到证明。

同步读回还存在单独的测量缺口：设备完成时间与主机 API 返回时间属于不同的时钟映射，
当前独立采集未得到可接纳的 `blocking_readback_interval`，不能把缺失当成零或直接放宽先后检查。
观测提取现另保留 `post_sync_readback_interval`，从主机同步 API 返回计到读回调用结束，
包括同步复制及调用尾部，但不包括同步 API 自身，也不包括等待前序计算的时间。
这段只使用主机时钟，不能单独满足完整读回成本请求；当前与上文独立测得的空闲同步服务组合。
前序设备等待仍由 DAG 依赖承担，不重复计入成本；阻塞唤醒等额外开销仍没有独立解释。

正式操作查询由本次执行的成本提供者统一接收，结构模块只提供工作描述。结果中的
`independent_operator_queries` 按操作、实现和计时口径列出查询、允许外推及未测组合次数。
一次查询可以服务多个重复节点，因此查询次数不是节点数，返回耗时之和也不是执行服务量或 E2E。
phase 的迁移/预测节点统计另列；payload I/O、保留 gap 和完整成本归属尚未由这份查询摘要覆盖。

同一种操作可以使用多次独立采集的观测共同训练。已迁入算子模型的加载、逐层等待、预取查询和等待控制，
原始校准文档只作为数据库证据保存，不再重复合并进预测包；两次采集的数值不同不应因此产生文档冲突。
调用链核对确认写回、释放和确认也已使用算子模型，旧的三个校准路径仅剩配置转发，并无执行消费方。
这条转发已删除：预测包不再携带控制观测文档，不按 target 页大小选择邻近校准文件，也不在每次预测时重新生成它们。
`control_calibrations` 仅用于显式导入或补采所得测量的声明，历史观测、导出及静态回放能力保留。

`executed_cost_sources` 另外统计实际执行且仍有效的节点。阶段成本即使预测数值与原值相同，
也按绑定依据区分源成本迁移与独立模型；生成的 attention/allocator 张量、页优先传输及提交、
分页释放节点在成本绑定后标记来源。其余节点暂列 `unclassified`，包括尚未接入归属统计的
存储 I/O、其他控制、保留片段和零耗时边界，
不能据此判断它们没有成本模型，也不能把它们自动算成已证明可迁移的 base 成本。
统计包含后台工作，记录最终数值变换后的节点耗时，并单列顺序 gap 和 ready delay；
worker 节点耗时可能包含独立预测的残余区间。因此这些和数既不是纯服务总量，也不是 HTTP E2E 或关键路径时间。
gap 与 ready delay 是这些节点关联的延迟，不表示延迟也来自同一个模型；例如阶段节点改用独立计算成本，
其源 CPU gap 仍可能保留。
这项统计已随当前矩阵输出；全图来源归属仍不完整，不能将 partial 改称全部覆盖。

H2D/D2H 页优先传输的执行入口只接受已经绑定成本的计划。传输字节数、提交、事件与依赖先由结构规则生成，
控制成本和 payload 成本随后分别填入；payload 按累计字节权重分配整数微秒，保持总传输服务耗时不变。
插入 DAG 时不再重新分配成本，也不复制整份节点计划来改数值。该路径已用于本轮统一预测。

阻塞写回检查分开查询以下 CPU/residual 工作，不再接受 `empty_write_check_us` 覆盖：

- `write.completion_entry`：空调用使用 `blocking_empty`，包含整个空分支；非空调用使用 `blocking`，仅到首次同步入口。
- `write.completion_poll`：`blocking_storage` 描述一次同步入口到对应确认函数返回，变量是备份 token 数和发布的 radix 节点数。
- `write.completion_advance`：两次确认之间推进循环，到下一次同步入口为止；该工作在等待下一笔 DMA 之前执行。
- `write.completion.release_first/release_next/return`：最后一次确认之后，按框架的队列和局部变量生命周期
  释放事件并返回；首次释放携带确认数量，其余按逐次操作计费，不再查询聚合的 `completion_cleanup`。

非空导出要求实际队列是一批次一操作、完整清空，并有逐笔 ack 边界与对应同步；不由总时长猜次数。
轮询样本只接受设备在同步 API 进入前已完成的区间，真实设备等待不作为 CPU 成本。
嵌套设备提交、不可归属时间或不支持的批次形态保持缺测；入口、循环推进和清理可分别提取。
运行时按目标 radix 当前拆分计算发布节点数，逐笔确认后即可提交 H2S，不等末尾队列清理；
容量释放仍等待整个检查返回。10-04 已按独立配对观测训练这些口径，仍不能保证所有形状或唤醒状态覆盖。
`completion_advance` 是每推进一次循环的常数成本，次数由结构决定，不拿 target 总时长拟合。
`complete_control_cost_package.json` 中 CPU 和残余口径各有 44 条观测、来自五次独立完整采集；
CPU 配对结果均为零，残余实测 63–498 微秒，模型常数为 112.5 微秒。零是该校正口径的测量结果，
不是缺测默认值，也不证明真实 Python 指令没有成本；残余离散程度仍随模型报告，不能当成精度保证。
已为 `_finish_write_through_ack` 增加独立调用边界与工作量观测，导出为 `write.acknowledgement`。
它描述同步之后的发布、可选存储提交和解锁工作；只在整个区间可独立测量时导出 CPU/residual。
备份 token 数、发布节点数、存储与解锁开关是工作特征，ack ID 仅用于观测定位，不参与训练。
该函数体样本不单独加到 `write.completion_poll` 或非阻塞确认尾部上，避免包含关系导致重复收费。
当前统一包的 acknowledgement 两个口径各有 142 条独立观测并已训练；这不证明任意阻塞状态都可测。
非阻塞确认尾段也使用同一套严格区间提取：不能把 DAG 归一化后的同步返回常数当成实测 CPU 成本。
只有已知单资源同步且设备在 API 进入前完成时，才读取保留的原始区间；其他同步等待保持缺测。
观测位置身份未改变，旧数据库中相同样本若数值不同会报重导冲突；统一验证时应从保留原始资产重建独立库，
不能把重新提取的同一次采集作为额外样本叠加；本轮已重提取并重建独立库。

张量阻塞返回新增独立口径 `blocking_return_interval`：起点为最后提交结束与本操作设备完成的较晚者，
终点为调用包络返回。设备完成按纳秒校核，并向上取到微秒，避免把最后不足一微秒的设备等待算入返回间隔。
只接受同一串行设备链末端的明确单次同步，且返回区间无额外提交；未知或多个等待不生成此类样本。
此值是扣除已表达设备等待后的主机返回包络，可能含调度与唤醒延迟，不是纯 CPU 服务，也不证明 residual gap 已建模。
有配对校正时应用现有同源开销修正；没有校正则导出 `profiled_blocking_return_interval`，两者不混用。

不能用 60 格执行完成证明这一可选口径已经覆盖；实际遇到相应需求时仍须有独立测量依据。

和[同步主机拷贝实现](https://github.com/Ascend/pytorch/blob/94f8a8e6b523d7ba553e1b80d5b5248478391526/torch_npu/csrc/aten/ops/op_api/CopyKernelOpApi.cpp)
改为：调用前段 → 等计算流 → 调用线程同步读回 → 返回，不生成 worker。
该规则同时适用于当前 allocator 生成的 int64 和 bool 标量读回；布尔分支判断不能误走异步算子的成本提取。
独立观测须看到明确的流同步与随后同步 memcpy；`blocking_readback_interval` 从同步入口和前序设备完成的较晚者算到调用返回，
包含同步拷贝与主机响应，不称为纯 CPU 或纯 DMA，也不再额外叠加设备服务。其前段仍单独测量 CPU/residual。
这一表示占用调用线程、保留前序计算依赖，暂未单独表达读回与其他传输争用拷贝引擎；报告不声称 native 资源覆盖完整。
缺少这些边界、出现额外提交或多个未知等待时保持缺测。当前独立采集没有可接纳的上述跨时钟区间，
正式成本绑定使用空闲同步服务加 `post_sync_readback_interval`，不直接查询 `blocking_readback_interval`。
统一包已有四项读回返回模型，共 696 条观测，已随 60 格预测运行；这不证明跨时钟测量问题已消失，
也不单独证明读回成本精度。当前计费细节见前文读回成本说明。

预取查询也使用这条统一成本接口。第二阶段按 SGLang 规则生成采样、跨 rank MIN 和应用结果，
参与者取自执行组；第三阶段查询四个独立模型口径：采样前区间、采样到 MIN 区间、MIN 后应用区间，
以及全组到齐后的通信包络余量。它们仍是粗粒度墙钟证据，不是四项纯 CPU 服务。
独立导出保存实际查询观测位置，显式入库与离线训练后才能用于预测；正式执行不读取查询校准文档。
首轮同 TP 常数响应尚不解释查询长度变化和局部调度差异，不能据此扩大泛化或采集开销剥离的结论。
该路径已用于本轮统一预测，具体精度须由独立评分判断。

预取检查的本地区间也使用独立操作模型，操作名为 `prefetch.check.<区间角色>`，
实现为 `sglang.prefetch_check`，口径为 `control_interval`。目标实际执行到哪个分支才查询哪个区间，
不会为未执行的停止或重试分支提前要求成本。仅同一请求中已观测的本地提前返回可以直接迁移 base 耗时，
不再从另一份校准文档中直接挑选返回耗时。独立配对导出保留各次调用的真实观测位置，入库后离线训练。
这些区间包含残余等待，不能称为纯 CPU 服务；当前特征仅有 rank 和参与者数，尚未解释数据规模与调度变化。
通信和 scheduler 循环同样使用下文的独立操作模型，不再消费嵌入的等待文档数值。
等待文档不再输出或消费旧的本地 `cpu` 汇总，也不再将这些汇总字段齐全作为通信成本可用的前提。
新导出的本地区间只保存在逐调用的 `operator_observations` 中；旧文档需要重新导出这些观测才能训练相应模型。

`prefetch.collective.completion_min`，实现为 `gloo.all_reduce.int32`，消息分别为 8 和 4 字节。
提交前区间、提交服务、派发间隔、全组到齐后的 worker 余量、join 后区间分别建模；
组依赖由执行规则生成，不从独立测量读取。派发和余量仍含运行时波动，不是纯通信带宽。
只有确实进入重试循环时才查询 scheduler 成本；通信与 scheduler 模型均纳入统一训练及预测。

调度循环也已迁入统一操作查询，正式路径不再消费等待文档；上述嵌入 scheduler 的过渡接口已删除。
`prefetch.scheduler.<动作>.<before/after/collective>` 与 `prefetch.scheduler.tail` 描述一轮工作，
CPU、残余区间和通信各计时口径分开训练，不从成本数据决定动作或重试次数。

## 独立测量的提取与开销修正

下面说明独立完整/轻量测量怎样提取成本，以及仍然存在的计时限制。
导出的测量须显式入库并离线训练，不直接充当目标执行模板；旧控制和阶段聚合规则另列在第 6–7 节。

### 共享 CPU 操作校准的采集开销

共享校准也必须区分采集耗时和正常执行成本。先对同一份独立 workload 做完整采集与轻量采集，
再用 `scripts/model.sh prepare-cpu-service --correct-recorder` 生成绑定到完整采集的 CPU 修正数据。
`scripts/model.sh export-hicache-operation-costs` 将该修正应用到校准 DAG，再导出 load index、
load submission 和 layer wait 的共享操作成本；不能将原始 profiler 间隔直接作为正常执行成本。
需要预取等待/停止依据时使用 `--operation prefetch_wait`；策略读取所选源配置，不由 target 指定。
它复用执行器的分支观测，按源时间顺序选择第一个完整的活跃请求，目标重试次数仍由预测状态决定。
同时保留每个 rank 首次观察到的本地提前返回成本；这条分支在策略判断之前执行，不能借活跃等待成本代替。
缺少预取查询依据时，可用 `--operation prefetch_query` 从独立 trace 导出窗口内所有完整查询组，
保留原始观测身份，供整组导入和离线训练，不挑第一组或按 target 误差选样本。
测量提取属于 source_dag，不由目标执行器提供模板。局部区间只在已有 CPU 校正跨度内应用修正，
其他调度/残余时间仍保留；MIN 仅测最后一个 rank 进入后的返回区间，前面的同行等待由依赖表达。
不能把配对修正文件存在等同于全部开销已分离。
只有执行事实中存在预取候选时才要求查询模型；最终命中为空也需要查询，没有候选时不查询成本或触发补采。
缺少独立查询模型时报告可补采的操作需求。先从组内已声明、经环境准入且有配对 CPU 修正的
预取等待校准来源重新导出查询成本；无此来源再使用共享三阶段实验。导出失败不发布索引，也不静默启动
新采集绕过错误。成功后才重建组模型，一次准备不会反复重采同一需求。已有来源的真实数据复用已验证，
无来源时的新增设备补采分支尚待验收。
独立操作成本默认使用正式 workload 窗口；只有配对 CPU 校正明确覆盖全部受控请求时，才扩展到准备请求，仍不包含服务器启动。
这是校准取数范围，不改变 base 预测或 target 评分的正式窗口；缺少本地返回成本时，执行报告对应补采需求。
可重复 `--operation` 只导出所缺操作；不指定时保持 load index、load submission、layer wait 三类。
多操作导出共用一次 trace 读取、构图及 CPU 修正加载；各操作在独立图副本上提取，不共享边界修改。
后续操作失败时，前面已完整提取并通过整理的成本文件仍保留，失败操作不发布最终文件。
导出器构建目标为 `hicache_calibration_export`，默认读取 Release 构建目录，也可用 `--exporter` 指定路径。
命令参数见 `--help`。

开启 `--diagnostics full` 时，load index 与 load submission 的中间审计文件共用 `nodes`/`edges` 表示。
节点 `id` 是当前数组下标，`service_us` 是 CPU 或设备的执行成本，`residual_us` 是 CPU 残余间隔，
`dispatch_us` 是已观测的 worker 派发延迟；`submission` 与边保留任务关联。
同一任务的多个 worker 片段由 `task_predecessor` 连接，只有首片段带派发延迟。
保留源工作时按片段迁移依赖：中途可以启动设备，worker 队列仍等最后片段结束才释放。
加载索引、页式释放、传输提交与普通异步张量调用共用单启动点的两段 worker 规则：启动段结束允许设备执行，
返回段与设备并行，但仍占用同一 FIFO 任务。独立观测按唯一关联启动节点分出
`worker_launch_service`、`worker_launch_residual_interval`、`worker_return_service` 和
`worker_return_residual_interval`，不使用总耗时比例；无返回工作时，完整任务观测可证明该段为零。
多次独立提交或多个启动点不提供这四类样本，不将它们压成一个启动点。
这些字段需要对应离线模型定义和重新导出的独立测量；旧 worker 总耗时模型不作为回退。
HiCache 逐层等待也使用这四类分段成本，无论作为独立检查还是在 attention 内生成，
都由同一个目标等待规则产生 worker 启动、返回和设备等待节点。
两者共用原始任务的测量提取：必须确认完整任务、唯一设备启动点且没有混入设备等待。
审计可保留 worker 总耗时，但分段不可测时明确标注，不能把总耗时用于替代缺失的分段模型。
加载索引的 Python 汇总读取导出器按真实任务启动点提取的 `worker_costs`，不从片段数量推导比例。
分段不可测时只将该次观测列为不可用，不将整个采集的其他有效样本一并丢弃。
分段观测与模型已用于本轮统一预测；多启动点仍按各自规则处理，不能从单启动证据推断其覆盖。
这只是导出器与汇总器之间的诊断格式，最终共享成本文件及其模型接口不变。
历史审计文件保留作排查资料，不要求新汇总器兼容旧中间字段；需要重新汇总时从原 manifest 和 CPU 修正文件重新导出。

这一步只修正有配对测量依据的 CPU 区间。未测量的间隔、工作线程派发和设备成本仍保留，
不是将 residual gap 清零，也不依据 target 的 E2E 误差调整参数。区间内的开销分摊不是逐条指令的归因；
超出校准所覆盖的操作规模仍属于外推，应单独记录不确定性。

等待预取时的空选择循环另按单轮比较，而不强行配对循环序号：只接纳单请求、已发起且尚未完成的预取，
并要求完整/轻量采集的等待调用序列相同、没有另行归属的子操作或设备同步。
同 rank、同调用序列两组线程 CPU 中位数之差作为单轮采集增量；从源各轮扣除同一增量，保留源轮次间差异。
两次采集的轮数可以不同，不能相减总时长。无法匹配、缺计时、或扣减后出现负成本的轮次保留原值；
估计值和实际应用次数写入 CPU 配对摘要。已有写出校正不重复扣除这些源区间。
这是同一 base 上的重复测量近似，不保证相同调用序列内部的所有工作量和资源状态相同；
没有 target 参数或逐格补偿。已完成同源 CPU 准备、构模和两格验证：跨配置时间减少 5.883 毫秒，
自身增加 15.022 毫秒，未获得一致精度收益；不能把累计 CPU 扣减量当作 E2E 改善。

可选 hook 写出测量的实现正在验证：完整源采集声明 `HOOK_EMISSION_TIMING=1` 时，
`--correct-recorder` 还读取原始 hook 事件携带的上一条同线程日志写出测量。
仅在未与既有 CPU 修正重叠的源区间绑定实测线程 CPU 扣减，保留未测量、亚微秒及重叠部分；
这些区间可覆盖 worker，不依赖 target。节点、普通间隔和 worker 就绪延迟读取同一成本表示，
生成操作的导出成本也沿用该口径，不二次扣减。区间内分摊仍是均匀近似，不能从局部墙钟
分割精确还原 CPU 执行位置。报告的 `bound_reduction_us` 是绑定预算，不是 E2E 改善量。
已完成 C3/W3 真实配对及同源开关对照：原始 DAG、自身预测分别减少 55/232 微秒，C3→C2 不变。
该结果支持保留可选测量，不支持把 worker 日志累计时间当主要 E2E 误差或要求所有 base 重采。
首批测量有未覆盖写出；随后调整了时钟采样顺序，其覆盖改善尚未重新采集确认。旧资产不补造测量。

CPU 配对先在原始采集输入处检查请求/rank 覆盖、步骤编号和时钟，再比较两次采集的实际工作。
内部 forward、input、layer 和 scheduler 处理复用这份已建立的合同，不逐层重新检查同一身份；
两次采集的同步次数、子操作、层工作或边界不同，仍不能直接配对或用零补齐。

分配器首次准备成本由实际特化参数、内存/磁盘缓存状态及 base 的 prepare/load 观测决定。
将准备工作从源 CPU 间隔搬到合成节点时，准备区间并集及剩余间隔都沿用同源 CPU 校正；
外推样本也使用同一成本口径，合成节点不再次扣减。校正可以增加或减少成本，不按目标误差决定方向。
本次口径修复已通过构建及完整 60 格运行；总体精度仍未达标，不能据此宣称准备成本已准确或全部采集开销已去除。

## 1. 模型回答什么

给定一个 base profile 和一个只含 HiCache 配置的 target，C++ 先由 source facts 与 target policy 产生 I/O 机会和需求，
再用同一份 service cost 推进完成、timeout、可见性与资源顺序，在共享执行时钟上生成 Prefill/Decode 工作量和 DAG 变换：

```text
source DAG + target config
  -> target effect/demand plan
  -> HiCache I/O/control cost + completion/resource schedule
  -> executed/visible work plan
  -> Prefill/Decode cost
  -> DAG dependencies and costs
  -> full HTTP request-chain simulation
  -> independent normal-runtime scoring
```

cost model 不根据 target 标签选择节点或工作量，也不从 target 残差反推结构；但 service duration 是 deadline、完成批次和发布页数的
真实因果输入，因此会影响时间相关的可见性与依赖。target profile、target E2E 和 target 分项 cost 只在预测全部完成后用于评分。

当前组件为：

- HiCache I/O/control（内部 scope ID 为 `hicache_direct`）：Prefetch、Load、device-to-host（D2H）、host-to-storage（H2S）及其固有 control；
- `prefill` 和 `decode`：由 target cache reuse 改变的计算工作；
- residual CPU gap：不作为 I/O/计算拟合参数；当前完整预测仍保留部分 source 等待，尚未准确描述它随 target 配置变化的规律。完整 E2E 真值不剔除这些耗时。

## 2. 三类数据

| 数据 | 提供什么 | 不提供什么 |
| --- | --- | --- |
| 当前 base profile | 原始 DAG、请求和工作描述、明确未变化操作的迁移成本 | 变化操作的在线拟合参数 |
| 独立 runtime 测量 | 指定部署下逐操作的工作量和分口径耗时 | 当前 base/评分采集的隐式副本、逐格误差补偿 |
| 独立物理测量 | KV 字节几何、DMA/存储基础服务曲线及测量条件 | 完整推理负载下的资源争用、CPU 控制或计算成本 |

独立观测必须显式入库，训练前选择同模型、TP、后端和资源环境，并排除当前整轮 base 与评分采集。
同配置的其他历史采集可在满足部署条件时使用，但应说明配置重合；这不等于验证了未见配置泛化。
不同 base 共用同一份适用成本包，不能各自拿当前 profile 再拟合一套参数。
完整/轻量配对的两侧都属于测量来源，不能仅留出完整侧或通过更换路径绕过隔离。

I/O 回归也使用数据库选出的独立证据，不再采用旧的 base 优先选择。
纯新页写入需要不同调用规模来区分启动开销和字节成本；混合新旧页不能在覆盖写依据缺失时硬拆分。
独立运行证据不足、而适用物理报告已包含该服务时，可使用基础物理公式，
但应明确未测得运行时竞争影响。倍率 1 表示未追加修正，不是负载成本恰好等于物理成本的实验证明。
物理几何与测量分开：部署描述或空服务表不能提供耗时，缺失也不等于零。

## 3. 按缺口选择共享实验

默认只使用已提供的成本包。显式开启自动补库后，先从已有独立数据库重训一次，
仍缺可采集观测才选择整组共享实验；不先把当前 base 放进训练库。
缺模型声明、缺工作特征、未知结构分支或无效模型响应，应修正相应输入/实现，不能靠重复采集解决。
具体入口、预算及已验证范围见建模说明第 5–6 节。

控制实验使用已声明的平台几何、合法 token 和有限的框架路径。预取控制通常经过 token 记录、
完整回放、轻量回放、同源 CPU 校正及导出；token 记录本身不是成本样本，三次运行和失败重试均计入预算。
同一次组运行不因不同 target 重复执行相同实验，也不因一次成功就保证所有需求已覆盖。
普通释放、活跃预取和写回等只支持已有生成器表达的分支，未知需求明确保留。

物理 I/O 缺口可按具体服务和方向采样，不为两个写入系数强制运行完整推理 workload。
已有服务曲线保留；补测的来源与费用累积，不把旧资产取得成本记为零。
采样使用模型的 KV dtype、page-first 布局和框架文件后端；每个 rank 只管理自己的临时存储键。
逻辑传输字节数、各 rank 服务时间之和与整次墙钟分别保存，不能混用。
设备 profiling 始终串行，模型侧的并行构图不改变这一要求。

## 4. 变量、参数与模型形式

变量描述目标要做的工作，由结构规则生成；系数描述这些工作在指定环境中通常需要的时间，由独立测量估计。
操作名、实现、部署与计时口径决定选哪个模型，不把配置名、workload 名或单格误差当变量。

| 成本族 | 典型变量 | 模型与系数来源 |
| --- | --- | --- |
| 固定主机/worker 片段 | 已确认的调用路径；另保留 shape、rank 等适用条件 | 独立分段测量的常数响应，CPU 与 residual 分开 |
| 设备张量工作 | 元素数、M/N/K、MAC 数等有机制依据的工作量 | 常数、线性或单变量分段线性；不再按阶段 token 比例分摊 |
| 普通双 rank all-reduce | 逻辑载荷、各 rank 输入就绪差 | 独立通信完成区间回归；实际等待由 DAG 依赖承担 |
| DMA、存储 I/O | 页数、每页字节数、调用次数、新旧页与实际 batch | 基础服务公式或独立调用规模曲线，详见第 5 节 |
| 未变化操作 | 对应源身份及工作、实现、资源等迁移条件 | 直接迁移对应成本，不训练新的系数 |

常数形式为 `t = a`；线性形式为 `t = a + Σ(b_i × x_i)`；分段线性在已声明的单变量锚点之间插值。
是否估计截距由声明决定。CPU 固定路径不因为设备元素数增加就自动乘以元素数；相关变量也不全塞进回归。
先在每次独立采集、同一拟合工作点内取中位数，再估计参数；常数使用这些值的中位数。
重复层调用不会单凭样本数量压过其他独立采集。线性回归仍按实际聚合工作点估计，不宣称每种采集无条件等权。

`features` 参与公式，`coverage_features` 仅限定适用范围、不增加系数。
常数模型也需要说明测过哪些工作条件；各变量分别落在范围内，不代表组合已测过。
模型保存原观测范围、被合并的不同工作组、训练误差及来源；训练误差不是留出精度，
观测波动也不是 E2E 置信区间。缺特征、缺计时口径、超出禁止外推的范围或负响应均报告成本缺口。

现行预取状态检查、scheduler、加载和写回控制查询操作模型，不消费旧的聚合控制文档。
`control_models` 中的旧标量与第 7 节的阶段聚合模型只用于历史静态诊断，不能替代当前独立成本包。

## 5. HiCache I/O service 公式

以下时间单位为微秒，`B` 为 byte 数，`P` 为 page 数，`G` 为每 token 每 rank 的 KV bytes。

### 5.1 Prefetch

```text
page_bytes = target_page_size * G
physical = P * (before_copy_per_page + page_bytes * before_copy_per_byte)
         + copied_pages * (copy_publish_per_page + page_bytes * copy_publish_per_byte)
         + service_calls * return_per_operation + P * return_per_page
predicted = physical * runtime_scale(page_bytes)
```

`P` 是实际执行读取的页数，`copied_pages` 是实际拷贝页数，不能用最终可见或完成的 token 数代替；取消预取也可能已做了这些工作。
`service_calls` 来自 storage batches。各阶段系数来自平台测量，runtime scale 来自显式选择的独立运行观测。
正式构模要求分阶段测量，不再回退到总耗时公式；旧报告若只有总耗时，会报告阶段证据缺口。
正式模型加载也只接受 `stages` 与运行倍率，不再接受旧总带宽形式或忽略模型中的冗余总成本字段。
Python 构模和 C++ 直接配置入口执行相同规则；带 stages 又附带旧总成本字段的混合输入也会拒绝。
I/O 观测范围统一保存在 `model_build_summary.json` 的 `io_coverage` 中，由所选观测生成，
不由倍率端点补造。它是范围说明，不参与参数选择或预测，因此不再复制进数值模型并作为加载门槛。
只有独立物理参数、没有所选 workload I/O 观测时，`io_coverage.page_bytes` 为 null，调用范围为空；
物理测量来源另列在 `platform_measurement` 中，不把单位倍率当作负载下覆盖证据。
单独使用模型文件不意味着已取得观测范围证明；需要查看来源和限制时，应同时保留构模摘要。
原测量缺少分阶段信息仍须补充证据，不能靠移除报告字段绕过参数缺口。历史静态回放及其数据保留。
物理采集同样只保留分阶段预取测量，已删除会被覆盖的独立整段暖读测速及 `--isolated-repeats` 参数。
分阶段实验自身需要的缓存预热仍保留；旧原始测量和已生成报告不因此删除。
完整存储采集和只补预取阶段共用一个入口，按计划中的非空任务执行；一次采集中每 rank 只建立一个工作进程。
各实验清理自己的存储键，完成的测量在进入下一阶段前保存；失败时关闭整组工作进程，不发布完整报告。
阶段模型只保存六个阶段系数，不再附加另一套总启动开销、总每页开销和总带宽。
只有一个页大小时，测量只能确定该大小下的每页响应，不能分别证明固定项和字节项；字节项为零不是零成本，也不代表其他页大小不影响耗时。
因此跨页使用仍是未验证的外推。原始测量先于参数估计保存，拟合失败不发布完整报告，但保留测量供排查与重建。
物理采集入口在启动测量前检查输出覆盖权限与补采来源；内部发布层使用已准入的几何和观测，
不重复维护覆盖开关或用零代替缺失几何。阶段测量是否足以估计参数仍由估计器判断。

### 5.2 Load 与 D2H

独立运行测量在同一页大小下有两个不同的每次调用字节规模时，可直接估计：

```text
predicted = operations * setup_per_operation + B * 1e6 / bandwidth
```

估计方法与纯新页写入共用：按调用数归一化，每份 profile 对相同规模取中位数，再由两端规模确定直线。
负启动成本、非正带宽或只有一种规模都不算辨识成功，不裁剪系数来强行接纳观测。
该路径不需要独立 DMA 曲线，写入模型的 runtime_scale 为 1，仅用于沿用统一执行公式。
在未观测页大小或调用规模上的外推仍须说明不确定性。

已选独立运行观测不能辨识时，使用适用的独立物理曲线与有测量依据的运行时倍率；
没有运行时依据时明确保留基础物理近似，不能用当前 base 或 target 误差补出倍率：

```text
physical = B * 1e6 / physical_bandwidth(page_bytes)
         + operations * setup_per_operation(page_bytes)
predicted = physical * runtime_scale(page_bytes)
```

Load 和 D2H 分别有自己的物理 bandwidth 曲线和 runtime-scale 曲线，不共享 target 修正项。

### 5.3 H2S existing

已有 storage key 的读取/覆盖响应与单次 batch 深度有关：

```text
predicted_existing = sum_over_batches(
    existing_pages * page_bytes * 1e6
    / physical_existing_bandwidth(page_bytes, batch_pages)
) * existing_runtime_scale(page_bytes)
```

### 5.4 H2S new

创建新 storage operation 有一次 setup，再传输该 batch 的 bytes：

```text
predicted_new = sum_over_new_batches(
    setup_per_new_operation(page_bytes)
    + new_pages * page_bytes * 1e6 / new_bandwidth(page_bytes)
)
```

setup 和 bandwidth 来自独立运行的不同调用规模，或已声明的适用物理测量。
不要求固定 workload 或两个页大小端点，不混入当前 base，也不按 target 残差再乘倍率。

端点间以 page bytes 的对数坐标插值；超出已声明物理域时使用最近端点并在 coverage 中显式暴露，而不是外推新的经验曲线。

## 6. 历史控制成本与开销修正记录

本节保留 09 月旧模型的选择规则与实验解释；其中 base 优先、整段复用和阶段外推均不是当前合同。
现行操作模型、同步等待和资源规则见本文开头及第 2–4 节，旧结果不追溯改写。

### 预取服务的轻量配对依据

同一 base 的轻量回放可同时记录存储读、复制和发布阶段。组准备生成的轻量配置开启
`SGLANG_HICACHE_IO_TIMING`，不额外启动一次采集。配对先核对配置、forced tokens 和计算工作，
然后把已完成的预取服务及其测量 manifest 放入成本文件的 `reference_io`；CPU 仿真不消费这部分元数据。
仅在轻量运行未启用 Torch profiler/Python probe，且对应 source 请求的页宽、批次页数、实际复制页数一致时，
这些服务成本才可用于构模。复制与最终发布分别记录，未发布不能冒充未执行。

该比例规则是历史流程。现行独立数据库路径中，预取墙钟倍率只接纳工作量匹配的轻量测量；
不能用带 profiler 的函数墙钟放大无 profiler 的独立服务。没有适用轻量证据时使用已测的独立
分阶段预取公式，不添加经验倍率；推理期间的资源争用仍未验证，不能声称已消除这项误差。
DMA 的设备时钟测量和存储写入的既有选择规则不受本项修改影响。
没有按 target 选值；测量 manifest 和可用范围进入参数来源。
不匹配的轻量操作不补造测量，也不改变目标工作量。轻量墙钟仍含计时和资源波动，
不能声称是完全无观测开销的正常值。该链路已完成 Release/Debug 构建、正式配对与构模，
并在固定 CPU 成本的自身/cross 对照中执行通过。采用当前规则的完整 60 格已执行并独立评分，
该轮 WAPE 3.342%、P90 7.023%；后续成本搬移及共享等待校正后为 3.273%/6.977%，
整体仍未达到精度门槛。两轮改动及证据不同，具体来源差异与限制见工作进展。

现行执行式路径生成目标 CPU 操作和依赖，再从适用 base 或共享校准取得操作成本。
查询、加载提交、层等待、写入和释放并非统一的一个常数；普通释放的近邻规模片段仍有外推限制。
是否执行由 target 状态和规则决定，缺成本不会改成不执行，也不能计零。

历史预取等待实现的 scheduler 循环采用一个完整 base 样本：按 HTTP 顺序选首个可用的活跃请求，
取其前两次进度检查之间的本地工作和通信步骤。节点及间隔经过同源 CPU 校正后，
按 target 执行状态所需的轮数重复；没有适用 base 时才读取独立等待校准。
这是“单轮成本近似不变”的假设，不是把整个 base 等待时长原样加给 target。
单个样本中的偶发间隔可能被重复放大；目前没有逐轮资源状态模型，不能把这些间隔都当成纯 CPU 工作或直接删除。
现行独立成本导出改为收集各请求的全部可归属 retry 间隔，按共享进度通信身份对齐 rank；
CPU、本地残余间隔、通信提交、dispatch 和 worker 分项仍分别保存。训练按采集平衡，
目标需要多少轮仍由执行状态决定，扩大取样不意味着等待模型已经精确。

具有原生 worker 观测的集合通信分开保存调用线程的提交前、提交和返回工作，以及跨线程 dispatch、
各 rank 到齐后的 worker 剩余时间。前三项读取同源 CPU 校正后再用于生成节点；生成节点不重复校正。
dispatch 和 worker 等待不套用调用线程的校正。仅有调用包络的粗粒度通信证据仍保留未拆分成本限制。
此项成本搬移修复通过 Release/Debug 构建，原来源校准重新导出后完成 60/60：
完整 E2E WAPE 3.230%、P90 6.717%，53/60 低于 6%，仍未达标。
受支持的未校正静态对照与 A–F 逐字段一致；重建 gap 缺源坐标的静态输入仍不能叠加 CPU 校正。

本轮重构中，base 的加载收尾若能明确识别为同一计算流上的异步 InplaceCopy 序列，
会拆成逐节点 clone 和一次性 CPU 收尾。单次 clone 的主线程工作、残余间隔、worker 服务、
dispatch 和设备服务分别取这份 source 内各次调用的均值，并按各自微秒精度取整；
目标状态中的被提升节点数决定执行次数，不再照搬 source 后缀中的 clone 总数。
这是基于 base 的常数单次成本外推，没有拟合 target，也没有证明不同节点长度下 clone 成本不变。
不能确认唯一提交/worker/设备归属、clone 与其他操作交错或存在额外等待时，不做这种拆分，仍保留聚合观测限制。
外层分支在 clone 后的拼接及 CPU 收尾保留原有操作和依赖，只执行一次，不混入可重复的 clone 成本。
09-28 的统一验收及去掉独立 load-index 校准的检查均执行成功；但这只证明该输入能够预测，
后续诊断确认，外层拼接曾使拆分器拒绝全部代表样本；保留该一次性后缀的修正尚待运行验证，
不能据此前的成功执行宣称分解或跨规模精度已通过。
随后降误差阶段修正加载准入的成本选择：独立校准不再阻止提取 base 样本。
目标无需淘汰、重试或 allocator sort，且 base 中有同线程、同页大小及 token 规模、可拆分 clone 的直接成功样本时，
优先使用该 base 操作成本；其他情况仍优先使用已声明的独立原语，未声明时保留原 base 外推路径及其限制。
资源连接同时绑定可选成本程序的资源角色，不用成本样本决定目标分支。此项选择修正正在验证，
09-28 的 60 格成绩是修正前的固定基线，不能作为修正后的结果。

加载提交的生成执行路径也开始优先使用 base：把同线程的完整提交分成索引同步前 CPU 工作、
起始 record、wait、首个/后续 K/V copy、首个/后续 layer record 和收尾。每项分别保存主线程服务、
残余间隔、worker 服务、派发延迟及设备服务；同源可拆分样本取均值，重复操作的均值按微秒取整。
目标页数决定 copy 次数，模型层数决定 layer record 次数，成本来源不改变这些数量或依赖。
base 不具备完整可拆分布局时保留共享成本；没有声明提交校准的旧 base-only 路径本次未更换。
这是一种固定单次操作成本外推，尚未证明其适用于所有页宽、队列压力或线程资源状态。
运行摘要的 `load_submission_base_cost_batches` / `load_submission_shared_cost_batches` 记录实际生成批次的成本来源，
不是精度或外推可靠性标记。本项已完成完整 60 格复验；总体 WAPE 从 3.897% 小幅降到 3.843%，
C3 组略退步，仍未达到精度门槛，不能把来源更清楚等同于成本已准确。

base 提取和独立校准导出使用同一个 C++ 提交拆分函数，Python 不再重复实现提交分段。
新导出的操作均值在 C++ 内按微秒取整，再由 Python 合并同 rank 样本；既有校准文件不被改写。

以下标量规则仅用于保留的静态诊断，不是现行执行式 CPU 成本模型：

- Prefetch 始终支付一次 terminal commit；`wait_complete` 和 `timeout` 另支付一次 state check，`best_effort` 不支付；
- Load 支付一次 admission 固定成本；
- 静态 D2H/H2S 没有单列 owner control；该字段为 0 不表示执行式写入/释放没有 CPU 成本；
- 零载荷 Prefetch 只落 control，不伪造 service bytes；
- page/operation 计数仍由结构模型决定，control 系数不吸收 service 或 gap。

两条路径都用 resource lane 和 DAG dependency 表达 I/O 并发，不把各 operation wall time直接相加：storage read/write、H2D、D2H 按平台声明决定
是共享 lane 还是每 rank lane。状态回放和最终 DAG 都调用同一个 service 估计；不存在另一套 planning bandwidth。

Prefetch 另外区分三个时间概念：

- 实际执行的 service：决定设备成本和资源占用，即使最终 0 页可见也保留；
- 发布的完整 batch：决定哪些页能进入 host cache；
- 前台等待：`wait_complete` 依赖完整 service，`best_effort` 不等待，未完成的 `timeout` 只依赖从 enqueue 到 deadline 的策略门。

因此 timeout 后未完成的 I/O 可以继续占用后台资源，但不能把完整 service 时长强加给当前请求。策略门没有拟合系数，持续时间直接来自 target
配置的 timeout 规则。

### 6.1 淘汰时跳过锁定候选的 CPU 成本

淘汰循环可能弹出一个仍被请求占用的节点，检查锁后跳过它，继续找下一个候选。没有传输也仍有 CPU 工作。
操作模型为 `cost_us = a * pop_count + b * sum_log2_heap`。训练输入是一整批跳过操作：
`pop_count` 是弹出次数，`sum_log2_heap` 是每次弹出前堆大小的 log2 之和。
预测一次跳过时查询 `(1, log2(H))`，H 来自预测缓存状态，不是目标 trace。
a 表示每次检查的固定开销，b 表示随堆高度增长的操作开销；没有额外截距，零次操作对应零工作。
同一部署共享模型，不按配置身份、页大小或策略调系数；缺少模型仍报告成本缺口，不默认填零。

参数来自独立运行框架原始淘汰循环的 CPU 批量测量，使用真实节点对象。
基线使用相同候选集合但请求释放 0 token，只建堆而不遍历；活跃测量请求释放 1 token，遍历并跳过全部锁定候选。
两者线程 CPU 时间之差用于估计循环增量；每个绑核范围、堆大小保留原始配对测量，
其中位数作为一条整批观测入库。当前声明使用无截距线性模型，不把整批平均值伪装成某一次弹出的测量。
从整批推导单次操作依赖可加性假设，即使查询落在特征取值范围内，也不等于单次成本已实测验证。
训练内残差不作为留出精度。历史固定字段和两端点求系数方法不再描述当前独立数据库路径。

10-04 已按当前两个 rank 的绑核范围测量 1、8、64 个候选，共六条整批观测并入库。
首轮训练得到 a≈0.2533 微秒/次、b≈0.04034 微秒/log2 工作单位；采集内同工作点聚合后只有三个点、两个参数，
并不是六个独立配置。整批拟合误差小也不能证明单次弹出准确。模型已让 C4 越过原语缺项，尚无该格完整预测。
原始资产为 `data/modeling_runs/three_stage_refactor_20261003/locked_candidate_cpu`。
历史测量使用更宽的共同 CPU 集合，未改写其环境声明来冒充本次数据。

这仍是待完整验收的近似：空闲 CPU 原语测量不证明带负载时完全一致，源控制模板也可能已包含部分跳过工作，
需要核查实际选中的模板，避免重复计入。运行通过或单个原语留出误差小，都不能替代整行、其他 base 和完整矩阵验证。

## 7. 历史 Prefill/Decode 聚合模型

以下描述历史实验及保留的静态回放输入，不是本轮执行式预测的训练接口。
本轮已移除通用阶段曲线兜底，变化的计算使用操作级工作描述和独立模型；接口见本文开头及建模说明。
历史 Phase 与 HiCache I/O/control 分开估计，但保存在同一个模型 JSON 中。

### 7.1 Prefill

```text
common kernel      = measured curve(new_tokens)
collective         = measured curve(new_tokens)
prefix attention   = a + b * new_tokens
                       + c * new_tokens * (context_tokens + new_tokens / 2)
```

曲线在相同 new-token 点先对样本取中位数。测量噪声造成后一个锚点更低时，只向前做单调夹取，不增加自由参数；锚点间线性插值。
`a/b/c` 用非负最小二乘求解，允许不需要的项自然为 0。

### 7.2 Decode

```text
effective_pages = ceil(context_tokens / min(target_page_size, base_kernel_page_tokens))
paged attention per iteration = a + b * context_tokens + c * effective_pages
collective per iteration      = observed median
```

target 的 decode iteration 数沿用 source 请求语义；非 paged kernel cost 和 CPU submit 保留 source 模板。CPU submit 单独诊断，不允许它吸收
HiCache I/O/control 或 residual gap。

执行式 Prefill/Decode 的设备成本会随目标工作量变化，但普通提交 CPU 和未被其他模块接管的源间隔仍沿用 base。
因此设备成本变化不一定带来相同比例的 HTTP 变化：若 CPU 提交链更慢，设备变化可能被重叠掩盖。
这是模型近似及关键路径关系，不证明真实 target 也受 CPU 限制；不能靠统一缩放 CPU/gap 来补齐误差。

若本组选定的 base workload 明确没有 Decode 迭代，不为不存在的工作补采 Decode 参数：
`decode_paged_attention`、`decode_collective` 和 Decode context 覆盖上下限保存为 `null`，不是零成本。
实际预测没有 Decode 时跳过对应成本投影；若执行需要 Decode 而模型没有参数，则报告 `phase/decode` 成本缺口。
有 Decode 迭代却缺少 kernel 测量仍是数据缺失，不能按“未执行”处理。

独立校准中具有相同请求、rank、token 和页大小工作量的重复测量先折叠成逻辑实验，避免重复次数改变权重。
参数优先来自所选 base；一个组有多少份 workload profile 不由矩阵实验计数限定，target profile 不参与估计。

## 8. “训练”和预测分别做什么

训练在数据库侧离线完成：选择部署与留出 → 选择独立观测 → 按声明形式估计参数 → 导出成本包。
同一输入与声明产生确定的参数，但模型形式不自动搜索，评分也不触发重训。
包记录来源、单位、变量范围、样本数和训练内诊断；重复导入按原始测量身份去重，
不同真实采集中的同工作点仍保留。提取规则修正后显式重导，已有包不会悄悄改写。

预测不打开数据库或训练 trace：根据 target 配置、workload 和执行规则生成操作，
查询已训练模型或迁移明确未变的源成本，再沿 DAG 的共同资源与依赖执行。
动态完成事件可以触发下一条结构规则，但成本模型不能自己增加操作或改缓存策略。
同一组 target 共享成本包和额外采集，不按格子选择专用系数。

应用默认不需要 target 真值；实验完成预测后再独立生成源回放、结构比较和完整 E2E 报告。
数据库声明 ready、预测 EXECUTED、结构比较完成和精度达标是四件不同的事。
当前 60 格已完整执行，但成本归属仍为 partial；本轮结果与来源资产见工作进展。

## 9. 计时与验收边界

**当前完整 E2E** 对比预测 HTTP 请求链和独立正常运行的正式窗口；评分不剔除 gap、未归属成本、Prefill 或 Decode。
同 base 的 profile/light 测量只校正采集开销，不从 target 真值中扣除误差。`EXECUTED` 只说明流程运行完成，
成本覆盖标记和精度验收须另行检查。

以下 gap-excluded scope 是历史组件实验和分项诊断口径，不是当前完整 E2E 的验收分母。

HiCache I/O/control 标签计 operation 自身的 service 和明确归属的 control CPU：

- DMA 使用 device-transfer 时钟；storage 当前使用函数墙钟代理，其中可能仍含函数内部调度等待，不能宣称为完全纯净的设备时间；
- 函数外已识别的 residual CPU gap、完整请求 wall time和随机到达空白不进入 HiCache I/O/control 参数；
- Prefill/Decode compute 分项计已归属 device compute/collective；组合 scope 还保留对应 submit CPU；
- gap-excluded scope 组合 HiCache I/O/control + Prefill + Decode 在预测 DAG 上的关键路径，保留必要因果/资源边；
- 未归入上述组件的 wrapper/probe 成本与 residual gap 被排除，不等于完整应用墙钟只减去所有 CPU 空白；
- formal window 由 workload 的语义起止点决定，不按 config/cell 写死时间边界。

默认评分只保存紧凑指标。oracle-cost replay 只有显式开启时才用 target observation 替换预测 cost，用于诊断操作级绑定和 cost
sensitivity；它不是完整 target 时序同构证明，不是预测成绩，也不能回写参数。
回放前先检查相同预测成本注入恒等性；control 输入是明确观测的 CPU 工作，不是轮询等待。
控制操作边界独立于 duration 数值存在，不能因 oracle control 为零而删除依赖节点。

09-12 之前的旧 60-cross 只作修复前参照，其结构检查范围较窄。09-12 严格评分的 HiCache I/O/控制
WAPE/p90/delta 为 5.186%/32.518%/8.121%，严格 gate 未通过。09-14 又完成新 workload、新配置及
TP=4 的十二格泛化实验；两批结果、严格结构口径和不抵消分项统一见
[验证与当前限制](validation/hicache_validation.md)，不能把旧 60 格当作新面板成绩。
这些历史结果暴露完整前缀匹配边界、短超时等待/可见性投影及成本泛化限制；尚缺当前实现上的关闭证据。
不能把旧缺陷描述直接当作当前代码结论，也不能根据 target 分数追加参数。
