# 性能模型与执行引擎

本文统一维护现行成本范围、需求、测量与执行合同。首个真实性能闭环保留采集子图、有限变换、轻量控制和动态展开，排除 host 控制类 CPU 服务时延，计算、通信、搬运和物理设备命令仍须有真实成本；详细边界见[CPU 时间如何处理](#4-cpu-时间如何处理)。消费[模板工作](05_controller_semantics.md)，遵守[控制接口](03_control_interface.md)和[工程约束](engineering_constraints.md)。

当前实现已删除 host CPU 收费、逐类采样、拟合及申采链；计算、通信、传输和设备命令沿统一成本路径。最新完成状态与测量资格只在[实施计划](../redesign-workflow/2026-10-08_redesign_execution_plan.md)维护，本文不重复逐轮进度。历史资产与结果保留原范围，不回填新口径。

上述 CPU 排除规则描述 2026-10-16 交付实现及其历史结果。后续目标是稳态统一流程内必要 CPU/设备联合预测，方法、阶段与退出条件只见[当前专项](../redesign-workflow/2026-10-17_steady_state_template_cpu_plan.md)；CPU 模型尚未实现。专项先修正稳态口径和模板结构，再更新本合同及成本链，不恢复旧微观 CPU 采样或用实测残差补偿。

## 1. 两个职责

成本提供者回答范围内一项明确工作在声明条件下需要多少服务；执行引擎根据依赖、资源和并发关系决定何时开始、何时完成。控制器消费完成事件和状态，继续生成工作。性能层不能修改业务策略或用低成本替代缺失语义。

执行引擎的依赖、资源、唯一时钟和端口反馈先在 S4 用给定节点耗时验证，本阶段为同一机制提供范围内的真实成本。运行时的设备完成和传输进展仍影响控制与动态展开；目标 DAG 是执行产物，不是先生成固定图再统一填总时长。显式给定值只用于结构验收和条件分析，不作为性能样本、拟合常量或精度证明。

源 DAG 可以保留 CPU、设备、通信、传输和标记；原始事件、必要因果和收费对象分别确定。保留一个 CPU 观察点不要求为它建立成本模型，排除 CPU 服务时延也不允许删除实际提交、同步、数据可用及发布依赖。

### 参数化模板与成本资产

性能粒度按实际工作、可测边界和必要依赖选择，可以是节点或局部子图，与五类 block 和整个 decode 长度无须一一对应。重复模型区域共享参数化结构，目标工作量由请求、KV 和配置状态产生；不同目标仍须满足模板与有限规则的适用条件。采样遵守[独立性能采样合同](04_collection_templates.md#独立性能采样合同)，不为每个节点重建一套重放系统。

成本身份包含必要实现、模型固定参数、dtype/layout、硬件和适用条件；token、request、KV 等量作为动态特征。来源 span、请求身份及采样序号只作追溯。相同名称、shape 或节点数不证明等价；跨配置共享须有适用条件或明确迁移依据。

结构覆盖和成本覆盖分别报告。合并性能单元必须保留外部依赖与可观察的中间完成时刻，父子工作只计一次。包含设备等待的原生调用包络不能直接作为可迁移服务；不能用父时长、比例分摊或目标残差补齐内部成本。

## 2. 本阶段收费对象

| 类型 | 查询特征 | 数据来源与限制 |
| --- | --- | --- |
| 模型计算节点/局部子图 | 操作与实现、shape、dtype、layout、部署 | 以主线实际设备计算为对象；未来 CPU 专家计算也是计算工作，须单独建立支持资格，不能按 host 控制排除规则忽略 |
| attention 工作 | 实现、各序列 query/context、head/cache 布局、dtype、部署 | 长度属于具体工作特征，不定义整个 decode 的成本类型 |
| 搬运/存储 | 执行方式、方向、字节、介质和并发条件 | 异步 DMA 与同步 host driver I/O 均按真实工作计时，CPU 发起不改变其传输身份 |
| 通信 | collective/物理任务、字节量、rank、拓扑与 transport | 明确计费层次，物理任务和父 collective 包络不能重复计费 |
| 物理设备命令 | 任务类型、runtime、实际设备工作与资源 | 设备事件/通知命令保留真实服务角色，不能混同逻辑注释 |

host 调度、准备、提交、worker 控制及完成处理的 CPU 服务不属于本阶段收费对象。逻辑标记不产生服务费；真实等待由依赖和资源状态产生，不迁移 base 的等待总时长。若 I/O 隐藏在 CPU 注释或调用包络中，必须按实际传输工作识别，不能随 CPU 服务一并排除。

实现先保持少量成本类别，算法可用有独立数据支持的精确匹配、查表、插值或公式。参数由数据和算法产生，不以 workload 名、实验标签、手调倍率、补偿阈值或残差表凑精度；把常数移入配置也不改变这一约束。新增算法不改控制器。

## 3. 成本来源与映射

未变化的对应工作只有在实现、工作量、部署和测量边界适用时才能复用成本。变化或新增工作使用适用的独立数据；结构来源不自动成为拟合数据。每个性能单元说明覆盖节点、入口/出口、资源及成本来源，测量载体可以不同，但须对应同一实际执行工作。

### 性能需求推导与覆盖分析

查询合同的完整性与某份候选能否估价分开：物理 kernel 描述缺失仍是合同缺口；存在物理描述但没有匹配样本时为 `needs_data`。需要投影的值操作数继续随查询保留，只有实际候选的策略能够允许忽略它们；候选拒绝投影时才报告相应合同不足。查询可构造不代表已具备成本或允许扩大采样域。

正式链路为：**参数化模板与目标范围 → 范围内性能对象及特征需求 → 模型/数据覆盖 → 有界采样与建模 → 目标预测与独立评价**。开发者看 trace 或分析脚本可以帮助建立合同，不能代替正式需求交接；减少某个案例的缺失节点数不能证明闭环完成。

需求输入是模板、有限变换、目标配置与 request workload 集合及支持条件。静态 base DAG 只是已观察实例；模板中的参数关系解释目标工作怎样改变特征。每个对象明确：

| 内容 | 含义 |
| --- | --- |
| 名称与实现身份 | 具体计算、通信、搬运或物理命令；类别不代替对象定义 |
| 计时与计费边界 | 真实测量端点、包含的工作、排除的等待/探针及覆盖节点 |
| 特征与参数关系 | 必要输入、单位、固定/动态量，以及从模板和目标状态取得它们的方法 |
| 范围与适用条件 | 特征点、关系、实现分支、部署和必要状态；未确定部分保留限制 |

来源原型、潜在参数关系和实际目标点分别表达。规范化、拟合、覆盖分析和预测查询复用同一工作合同与适用性，不另建宽松覆盖规则。`CostQuery::from_work`、模型 `estimate`、`PerformanceRequirementsPlan` 与 `CostRequirements` 承担公共职责；当前已排除纯 CPU 服务需求，不再把其未定义计时边界列为首个闭环阻塞。

覆盖区分候选可用、对象完整但缺数据/有效模型、边界或特征合同不足、目标超出支持域。`candidate_available` 只表示可查询，不授予精度资格；合同不足或结构不支持不能靠增加同类采集掩盖。明确排除的 CPU 服务属于阶段范围，不创建 0 ns 样本、候选或 givens，也不计作实测覆盖。结构、关联或 I/O 工作仍有缺口时照常报告。

动态调度使最终批次、实例和部分特征依赖时延。运行前生成可确定的对象、关系和范围；实例化后汇总实际工作点及全部当前缺口，尚未展开的路径保留未确定状态。给定耗时推导的路径不证明真实调度下的全域覆盖。

执行图唯一维护实际计费节点，需求层只统计实际查询和测量来源，不再次选择区域。当前每个物理服务单独查询，模型命中后不重复申采；没有 CPU 成本区域或替代边界选区。`measurement_required` 交给公共采样规划，首次实际 `measurement_origin/measurement_example` 提供载体；来源不进入成本键。首个来源不可构造时报告未解，不搜索其他来源或反推任意节点输入。

跨组合按对象、计时边界、特征与部署合并需求。先复用或重处理已有事实，必要时一次原生运行测量多个对象；配方可构造不保证原生批次或命名对象必然命中。实际覆盖由同一查询确认，不按每个缺失 shape 启动完整流程。

防重采只读取独立 manifest 的工作域、准备输入和必要观测事实；无候选的真实采集也保留历史。沿用执行路径、部署和物理容量约束，完成域同时比较全体成员及实际完成成员的工作特征多重集。只有完成数量的旧记录不证明异质部分完成。

数据相关 kernel 的 `observed_kernel_operand_fields`、同步搬运的 `observed_transfer_executions` 只证明各 rank 在相应工作域取得了必要事实，不证明具体对象已有成本。历史未观测所需字段时不冒充覆盖；同域及所需事实已观察、对象仍无成本时返回 `observed_domain_without_required_measurement`。已失败、无候选或未命中的同配方返回 `previous_sampling_attempt_without_new_trigger`；不能将 `[A,B]` 缩为 `[B]` 重采。同域停止不把对象变成已覆盖。

公开流程保存逐轮采样计划，复用父任务累计预算、attempt、处理、拟合与恢复交接；只有新候选才重算受影响组合。不可达、合同不足、预算耗尽或无新增证据均保留原因，不循环补采。原生请求、KV 和组批状态由框架维护。

### 性能样本与子图工作的对应

语义和性能观测独立，但共享实现、实际工作及必要关联。来源引用用于追溯和同源隔离，相同函数名、kernel 或 shape 不能单独证明等价。

| 工作 | 测量来源与边界 |
| --- | --- |
| 模型计算 | 原生实际 forward 的计算节点或切口合格局部子图；前向总时长不分摊为节点样本 |
| 异步搬运 | 原生关联的物理 DMA 工作，保留字节、方向及实际执行方式 |
| 同步 host I/O | 原生完整 driver 搬运叶子的成功起止；保留 I/O 停顿，排除此前设备同步等待及包围它的控制 CPU 开销 |
| 通信及设备命令 | 真实多 rank 物理任务/命令，保留实际工作和依赖；父包络不再收费 |

同步 host I/O 可以使用现有 CPU 观测文件作为测量载体，文件名或 CPU lane 不决定成本归属。没有可分离的实际传输量、执行方式或完整边界时保留传输合同缺口，不能直接排除或把整个 runtime 调用作为 I/O 样本。

统一预热不等于所有缓存、workspace 和并发状态相同。只解释实际需要的适用条件，不维护自己的原生状态机。设备时长可能含竞争和内部停顿，不能用经验常数剥离；未支持的资源竞争明确列为近似或不支持。

### 经验候选的生产

`CostFittingWorkflow` 在输入边界校验独立资产，转为 `MeasuredCostSample<Features>`；`MeasuredCostFitter` 共用按特征分组的中位数拟合和固定候选评价。条目保存 `features/estimate_ns/count/range_ns`；偶数样本中位数按整数 ns 向下取整，不移除高值或自动校正时钟。

候选保存来源 manifest、原始范围、测量缺口、假设及 `observed_context` 中的模型、框架、部署和 runtime。它们是观测条件，不自动证明跨部署可迁移。显式导入后按同一目标查询消费，不修改 givens 或提升资格。固定评价共用样本读取和工作键，不调用拟合、不外推、不填零；拟合与评价样本不得直接重叠，文件名不同不证明独立。

物理计算通过 `kernel_work` 交接公共工作；`KernelCostFeatures` 处理完整名称、操作、输入输出 shape/dtype/format、实际启动规模、attention 和已定义的 `operand_work`。目标与样本复用特征合同，完整键须匹配唯一观测启动变体；多变体不能挑选或平均。唯一变体的采用仍是条件假设。

相同 shape 不代表相同工作：

| `operand_work` 字段 | 成本含义 |
| --- | --- |
| `position_lengths` | 有序实际扩展长度，表达逐请求循环量；prefix 改变生成数值，不作为该循环的长度特征 |
| `logits_rows` | 有序实际 hidden-state 行索引，不按总 token 数和 batch 人数合并不同索引 |
| `request_pool` | `RequestPoolWork.role` 区分访问：`prefix_extend_write` 保存 `slot/prefix_tokens/input_tokens`；`token_read/token_write` 保存 `slot/column`；`row_read/relay_read/relay_write` 保存 `slots`，列范围由张量描述表达 |
| `batch_filter` | 共用`BatchFilter`的`input_count/retained_indices`，保留索引顺序；不把transition/running角色、请求身份或前驱prompt混入物理选择工作的键 |

请求池角色由框架生产端解释签名和分支，目标坐标由已有目标状态派生，实测坐标读取原生状态。历史缺失字段不从 shape、排列或实现推断后回填；已保存事实足够时才重处理。

过滤Index由原生过滤调用的独立性能scope读取实际成员选择，张量尾维、dtype及唯一launch继续按真实描述匹配；同一选择不按四种物理描述分别维护语义规则。覆盖报告单列`observed_batch_filter_work`，只有实际kernel提供typed字段后才证明相应观测已发生。缺少该事实的旧同形状Index样本不替代完整键，也不因观察过相同人数的模型批次而阻止必要的新合同观测。

请求域或字段名已观测不等于必要特征值已覆盖。例如相同单请求Decode可落在不同原生池槽位，不能因此把槽位2的样本当作槽位3。采样域的`pool_slots`由typed池访问需求提取，不按角色各建一份配方；它表达所需预留位置，不替代成本中的role/column/slots与张量键。覆盖与历史判断将工作特征和实际槽位成对比较，无槽位约束的域仍按自身特征判断，历史缺槽位事实不补造。原生触发及可达边界见[采样合同](04_collection_templates.md#从请求构造到特征覆盖)；不可达时保留具体缺口，不重复相同域或放松成本键。

语义参数不必全部进入成本键。生产端以 `tensor_traversal` 声明固定遍历假设；当前 Ascend 仅对已识别的 Cast、Add/Sub、Clip、ReduceMax/Sum 和 Concat 家族同时核对操作及完整后缀。核心消费该属性，不识别名称。只有已有明确遍历声明、张量描述、适用条件及唯一启动相符时，才允许候选省略相应语义值；逐请求循环和索引访问保留必要字段，缺失时不能借用纯 shape 样本。该投影不证明数值、缓存或观测影响已排除。

传输共用 `TransferCostFeatures`、拟合与查询，`execution` 必须区分 `asynchronous_device` 和 `synchronous_host_driver`，并保留方向与字节。前者读取关联 DMA，后者读取成功完整 driver 叶子的实际 I/O 墙钟；二者不能混键或与外部设备等待重复计费。现有来源和执行方式不自动建立 host 内存属性、并发及部署迁移资格。当前同步 I/O 载体延用 `measurement_kind=native_serving_timing`，仅拟合 `transfer_units`；sample 类型为 `transfer`。新两参数 queue ABI 必须与 torch_npu 队列观察头文件成套重编译，旧镜像不能直接用于新 transfer 采样，详见[部署限制](development.md#队列-abi-与镜像)。

### 通信采样与节点工作的交接

独立通信观测保留 collective 包络和逐 rank 记录，并输出 `task_samples`。Ascend 适配端以原生 rank、stream/task/context 身份连接唯一物理任务，保留操作、字节、dtype、transport、源/目标 rank、硬件起止及证据引用；不按时间接近或包络比例分摊。物理等待、数据任务和命令分别处理，未知归属或歧义保留缺口。

`DeviceCommandWork` 交接真实任务类型，event/task 编号只作依赖和追溯。现有 Ascend EVENT_RECORD 候选仅消费模板中相应物理命令，不代替 CPU 提交或通信任务；profiler 分辨率、内部停顿和部署资格仍须解释。

### 当前给定耗时执行与后续成本模型

`NodeDurations` 继续用于显式条件输入：来源 manifest、局部 source_span、ns 单位和假设必须明确，跨来源不能借用同号节点。目标工作交给 `ServiceWork`/`CostQuery`，来源给定值单独交给 `NodeCosts`；成本模型不读取控制动作、模板参数化对象或来源身份作为特征。

workflow 装配模型/框架/部署条件，节点模型解释工作特征，调度器不读取框架字段。当前 SGLang 路径共享只允许既定请求池容量和 Prefill 预算变化，相同执行路径不自动授予耗时迁移资格。未知范围内成本保留缺口；成本函数不启动采集。

本阶段完成要求范围内收费对象全部脱离 given。当前执行不再查询纯 host CPU 给定值；历史包含 CPU 费用的条件运行仍按原口径报告，不能改标签当作当前范围通过。真实成本与运行验证以实施计划为准。

## 4. CPU 时间如何处理

首个真实闭环明确排除 **host 调度、准入、KV/输入准备、入队、worker 控制、CPU 提交和发布处理的服务时延**。控制器、模板、请求/KV/workspace 状态及动态展开继续保留；计算、通信、真实传输和物理设备命令仍按模型推进时间。排除依据是工作职责，不能据 CPU 线程或 `CpuControl` 节点种类顺带排除同步 I/O 或未来 CPU 专家计算。当前主线仍为 SGLang + Qwen3-32B，未因此增加 KT 支持。

| 内容 | 阶段约定 |
| --- | --- |
| host CPU 服务 | 不建立、采样或查询预测服务成本，不作为首个闭环的待补节点清单 |
| 必要提交和跨线程交接 | 保留原生关联、先后顺序与设备启动条件；不增加未建模的 CPU 执行延迟 |
| 设备、通信和 I/O 等待 | 保留所等对象及完成依赖，等待由目标工作计算；不搬用 base 等待墙钟 |
| 发布与状态生效 | 仍等待约定结果，按端口更新 token、KV、资源及后续控制；不能提前发布 |
| 原始 CPU 观察与诊断 | 可保留来源和结构事实，不因存在事件就要求独立计时 |

这是明确接受的性能近似，可能低估窗口时间、改变并发及后续组批。不能宣称 host CPU 实际免费、完整 serving/HTTP 已被建模，或把该范围决策写成缺数据时填零。必要行为或依赖仍未知时继续报告结构不支持。

`CpuCostModel`、CPU 成本单元及独立 CPU 服务采样/拟合/申采链已删除，不保留可选 CPU 模式。`ServiceWork` 只交接节点种类、kernel、communication、transfer 和 device_command；纯 host CPU 节点在目标图中保留为注解，必要边界、因果及发布语义仍在。同步 host I/O 使用独立 transfer 载体，不因来自 CPU lane 而排除；历史资产不改写。

### CPU 测量与执行边界的交接

本阶段不继续补齐 before/call/after、函数 gap、成员体或同步两侧的 CPU 计时。未来只有独立证据表明省略 CPU 服务影响所需结果时，才重新选择少数完整、可观测且保留必要外部端口的区域，建立相应范围和评价依据；不默认恢复逐操作微观重建，也不预建接口、时钟锚点平台或新采样体系。

统一预热不能证明所有 executor/tiling 缓存分支相同。影响真实设备工作、依赖、分配效果或传输量的差异仍由模板和有限变换解释；仅改变已排除 host CPU 服务时延的内部差异不自动增加语义模板或目标状态。

## 5. 单一事件引擎

执行核维护唯一模拟时钟、就绪工作、完成事件和资源状态，请求到达与范围内工作完成共享时间轴。设备按实际提交和数据依赖启动，设备完成与发布状态分别表达；跨 rank 端口在所需 rank 完成后生效。

CPU lane/worker 保留必要顺序与交接，本阶段不预测 CPU 服务容量、抢占或执行延迟。设备 stream 不等于设备全局串行；链路、存储等共享资源按实际支持的竞争模型处理，不给所有并发传输无条件分配完整带宽。未支持的竞争明确列为近似或不支持。

排队与依赖等待由执行核产生，不在服务成本中重复计入。当前每个范围内物理服务节点只查询并收费一次；不再拼接 CPU 联合成本单元。目标工作与候选在组合内不可变，替换成本资产后从初态重算，不跨运行复用旧时钟或节点估计。

`release_ns` 是工作提交到执行图的时刻，不代表所有前置条件已满足；实际先后看 `completion_ns` 和依赖。不能用前驱端口晚于后继 release 判定违规。

## 6. 输出与误差

窗口时间由明确的起止事件计算，不能相加全部节点成本。请求 TTFT、完成时延和吞吐只有相应端口与时钟定义存在时才报告，明示 modeled 范围及省略的 host CPU 服务；不能标作完整 HTTP 指标。

独立评价对相同请求、相同起止端口及可关联时钟的原生观测，直接报告预测与原生端口间隔的偏差。该偏差同时包含省略 CPU、范围外工作、观测影响及其他模型误差，不能称为纯设备同范围真值或精度资格通过；不要求先还原或剥离全部 CPU 时间。缺实际原点或端口时报告不可比较，不伪造数值。

`observe-target --purpose ports`是默认时延观察：沿相同Engine、统一预热和目标到达序列，只记录原生`run_batch`与`process_batch_result`成功返回后的Submitted/Published。先读时钟，再读取请求进度和写记录；前者不是device_done，后者不使用整组Engine响应时间替代。单机worker与请求驱动器共用实际`perf_counter_ns`时钟及实现，端口事实保留rank、批次和成员进度。末尾控制RPC仅用于越过最终发布并确认记录交接，端口完整性由各rank的真实记录判断；RPC完成时刻不定义预测窗口，也不从端口间隔中扣除其耗时。此路径不启动完整profiler、AST或原生API journal，不输出可构图或可拟合的资产。

`--purpose structure`保留内部结构与依赖的完整profiler/语义观察。已有模板中的ScopeReturn以profiler marker末端表达，包含观察后处理；轻量路径的直接原方法返回与它不是同一物理取时点，不对历史数据减常数、换字段或回填时间。两种用途沿用同一validation角色、累计预算及恢复流程；目的在新任务准备时固定。轻量hook、标量读取和时钟本身仍可能影响后续批次，不宣称完全无扰动。时序变化造成实际组批不同也须报告，不强行套用预测的批次路径。

请求驱动器使用`perf_counter_ns`，profiler导出偏移关联到`CLOCK_MONOTONIC_RAW`，两者不能直接相减。采集在原到达原点位置按RAW-before → perf-counter原点 → RAW-after读取，并在`native_environment.request_timing`保存`origin_ns/clock_implementation/raw_clock/raw_before_ns/raw_after_ns`。评价保留真实原点在RAW中的区间，不用中点、历史wall差值或拟合偏移冒充精确关联；字段是否齐备以对应观测为准，transfer采样不经过这条Capture路径，旧观测不回填。原点区间不同时约束厂商时间戳精度、漂移或观测开销。无法关联到达时钟时，仅报告有共同端口与时钟的间隔，相关到达指标保持缺失。

评价不回写模板、成本或请求规则，不用目标残差补 CPU 时间，也不减去残差制造一致；局部正负误差抵消不能证明各项准确。结构、成本、控制近似和范围取舍分别说明。

## 7. 交付边界

真实成本闭环要求范围内工作由适用实测候选提供耗时，无 given、无缺口兜底且不重复计费；沿同一执行核保留动态反馈，再以独立原生端口报告偏差及比较限制。传输观察使用匹配 ABI 的成套部署，不能扩大已有样本适用域。

候选驱动执行完成不代替单元留出、独立对照或精度资格，也不授予跨框架与完整 serving 预测能力。实际状态、证据、预算和后续任务只在[主计划](../redesign-workflow/2026-10-08_redesign_execution_plan.md)及其专项维护。
