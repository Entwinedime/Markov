## 当前验收口径

正式精度对照是完整 HTTP 正式窗口：预测与 target 正常运行的客户端测量比较，
不排除 residual gap、未归属成本、HiCache I/O/control、Prefill 或 Decode。
目标 DAG 的仿真耗时不是正常 HTTP 真值。内部 `hicache_direct` 只表示 HiCache I/O 与相关控制开销。

总面板及逐 base 都要求：

- 全部选中格完成预测，且 source/target 的有效正式 HTTP 窗口齐备；
- WAPE ≤ 3%，单格 APE 的 P90 ≤ 5%；
- cross 的绝对误差总和小于直接沿用 base 正常墙钟的参照。

self 单列，不要求优于自身零误差参照。逐 workload、逐 target 的分数也独立列出：
总体及逐 base PASS 不代表这些分组全部 PASS，更不证明成本或结构覆盖完整。
单格小于 6% 或 10% 是附加观察，不替代上述门槛。

`EXECUTED` 只表示预测执行完整；`PASS` 只表示上述完整 HTTP 验收通过；
`MODEL_LIMITATION` 表示门槛未通过，不是命令崩溃。缺测、失败和无效窗口不记为零。

### 误差怎么算

设第 i 格预测时间为 p_i、正常实测均值为 t_i：

```text
APE_i = |p_i - t_i| / t_i
WAPE = Σ|p_i - t_i| / Σt_i
带符号误差 = p_i - t_i       # 正值表示预测偏慢
```

P90 使用最近秩：将单格 APE 从小到大排序，取第 ceil(0.9 × 格数) 项。
不能对各分组 WAPE 再求简单平均。缺失窗口计入覆盖失败，不从分母中悄悄删格。

正常重复测量取算术均值，同时保留每次样本、样本数和范围；base 墙钟参照也来自正常运行。
有效慢样本不能为了分数好看而删除。重复次数及波动追加规则应在读取结果前声明，
“针对均值准确”不等于“每次运行都准确”。原 60 cross 复用 15 个配置/workload 的真值，
不是 60 个独立新场景；两次重复也不足以确定完整波动分布。

### 评分与预测隔离

`evaluate` 先检查全部选中预测。存在未完成格时返回 NOT_READY、非零退出状态并列出原因，
不打开 target、不计算精度，也不读取失败格的旧结果。
显式 retry 只能替换未完成格，保持其 source 和 target；不能用重跑覆盖已完成格来选择好成绩。
旧 48 格中有 16 格未完成的拒绝证据位于
`three_stage_refactor_20261003/incomplete_cross_evaluation/gate_summary.json`。

全部预测完成后才读取独立评分输入；评分不训练、不补采、不回写模型或 readiness。
训练隔离审计检查实际选中的 bases、正常性能测量和结构采集的声明来源，包含配对两侧；
它不是隐藏复制数据或语义近重复的自动证明。
目标构图和 CPU 密集比较受现有 jobs 上限约束，默认一，不是并行设备 profiling。

## 三份报告分别证明什么

| 报告 | 对照与结论 | 不能证明什么 |
| --- | --- | --- |
| 源回放 | 在私有源图副本上，用构图器归一化等待后的源成本，对照同次 profile 的窗口及逐请求延迟 | 不是正常 HTTP 精度；小时间误差不证明全部记录、时钟或依赖正确 |
| 目标结构 | 对比实际展开的工作、语义身份、资源分组和完成点可达关系 | partial 不等于整图一致；额外可达端点对不是错误边数 |
| 性能 | 对比预测和正常 HTTP，报告 APE/WAPE/P90/最大值、偏慢或偏快及简单基线 | 精度好不证明组件成本都准；服务时长总和不是关键路径 |

源报告的事件覆盖从通道合并后开始，窗口过滤、因果尾部和上下文另列，
不能以图节点数冒充原始 JSON 记录覆盖率。逐请求延迟不含请求间停顿，不能替代整段 HTTP。
源回放在 CPU 开销校正、目标变换、独立成本绑定和 NodeScale 之前执行。

结构对应以各自的逻辑输入、请求、阶段和轮次建立，不比较跨 trace 的局部节点编号。
原生 worker 按唯一提交关联对应，D2H 提交、设备完成和缓存发布分别比较。
HTTP 结束前已准入调用的因果尾部可以参与结构比较，但不延长 HTTP 窗口。
未对应的通信内部操作、重复调用身份和目标构图缺少的 CPU 跨 rank 关系仍是覆盖限制。

实验可只采少量代表 target 的结构 trace，但必须报告已比较格数与未评价格数。
`--diagnostics full` 只增加差异明细，不改变比较范围或门槛；详细关系示例的截断不减少完整差异计数。
正常 HTTP 评分依旧要求全部选中格的真值，不用代表格代替全矩阵精度。

成本覆盖另外报告。独立查询的测量点、范围内未见组合和域外查询不包含载荷 I/O、迁移成本或保留 gap，
不能当作全 DAG 成本覆盖率或置信度。采集用量也不等于经济收益：旧资产首次取得成本与同口径实测
对照不完整时，收益仍为 `INCOMPLETE_COST_EVIDENCE`，不能因为本轮没有重采就声称首次使用很便宜。

## 静态 oracle-cost 诊断

保留的是现行执行规则下的显式静态回放，不恢复旧运行规则。
它先生成静态对照，再将同一结构中的操作成本替换为目标观测：
相同成本填回必须复现时间、图规模和 ownership 汇总，随后才运行五种真实成本变体。
I/O service 与 intrinsic control 都保留，不能因 duration 为零而移除控制边界。

它只诊断结构固定后的成本绑定及敏感性，不计入预测精度、不回写参数，
也不证明完整 target 图同构。普通执行式预测缺少这套完整操作映射，
不能仅打开 diagnostics full 就获得静态 oracle 能力。
已有报告不足时说明 NOT_RUN，不自动重跑预测补诊断输入。

包含无源坐标重建 gap 的静态图仍不能叠加源 CPU 校正。
未校正诊断必须始终使用同一未校正对照，不能中途删校正项来通过恒等检查，
更不能当作正常 HTTP 预测。命令退出 0 但内部 patch blocked 不算通过。

## 历史实验怎样解读

### 09-12：排除 gap 的原 60 cross

五个配置轮流作为 base，各用自己的三个 workload 预测其余配置。
当时 base 拟合 Prefill/Decode，另共用平台物理校准和 page32/128 各两次固定输入；
这不是现在的“base 只迁移未变成本、变化工作查独立包”流程。

主指标是三组件归属的组合关键路径，排除 residual gap 和未归属成本，不是完整 HTTP 只减 CPU 空白。
总面板及五个 base 的组合 scope 门槛通过，但所有 base 的 HiCache I/O/control 全 gate 均未通过。

| 分项 | WAPE | P90 | delta | 当时结论 |
| --- | ---: | ---: | ---: | --- |
| Gap-excluded scope | 0.921% | 1.981% | — | PASS；最大单格 2.712% |
| Prefill | 0.808% | 3.436% | — | P90 未通过 |
| Decode | 0.302% | 0.976% | — | PASS |
| Prefill + Decode | 0.694% | 2.316% | 1.383% | PASS；54 个大变化方向正确 |
| HiCache I/O/control 总量 | 5.186% | 32.518% | 8.121% | FAIL |
| HiCache I/O/control 不抵消分项 | 5.995% | 32.518% | — | FAIL |

历史 gate：scope WAPE ≤3%、P90 ≤5%；phase WAPE ≤1.5%、request/rank 二级 P90 ≤3%；
phase delta weighted L1 ≤2%，大变化方向全部正确；HiCache 总量及不抵消分项 WAPE ≤3%、
P90 ≤5%、delta ≤3%。phase P90 先在每格内取 request/rank 的 P90，再对这些值取 P90；
delta 的分母是实际变化量绝对值之和。“不抵消”先算四类 I/O 各自的绝对误差再相加。
当前普通 evaluator 不再生成这些细分 gate，停止输出不表示它们已经通过。

当时 15 份 target 重新提取后，60 格的 effect 工作量及所比较依赖投影一致。
旧 40 格的 1,376 项差异来自 visibility 页数漏填，不能当作到达或调度错误。
这是局部工作/依赖证据，不是完整 target DAG 同构；capacity-gate 的 required/partial 分支没有真实矩阵覆盖。

Prefetch/Load/D2H/H2S 的 WAPE 为 6.372%/6.684%/8.949%/5.409%。
校准重复波动小于 4.3% 不证明真实负载、缓存冷热或竞争已覆盖。
09-10 旧口径排除了已执行但零可见的预取，Prefetch 总量由 65.258 秒变为 77.532 秒；
其 2.971% I/O WAPE 不能与新口径当作纯精度退化比较。

五个代表格完成 5 次恒等和 25 次真实成本替换。
完整真实成本回放 scope APE 为 0.0053%、0.0075%、0.0092%、1.2717%、0.0059%；
C4/W2→C3 仍有 60,758 微秒残差，未单独归因。
旧约 13% 的 oracle 偏差受到清零终止控制和错误连边污染，不能作为真实调度误差。
target 成本按语义填入，不是复制 target 图，也没有据残差增加参数。
历史根目录为 `hicache_gap_excluded_causal_20260912`，旧报告可能已清理。

### 09-14：新负载、新配置和同 TP 扩展

C5 base 在 TP=2 与 TP=4 各预测两种新 workload、三个新配置，共十二格。
配置覆盖 page32/64/128、写策略与 10 ms 短超时；两负载分别含混合上下文回访和较长 Decode。
预测完成后才独立评分，没有用新 workload 或 target 真值拟合参数。
这只检验同 TP 的单 base、串行受控请求，不是 TP=2→TP=4 扩图或并发泛化。

| 项目 | 当时结果 |
| --- | --- |
| 组合 scope | WAPE 0.317%，P90 0.935%，最大 1.453%；所有组通过 |
| Prefill / Decode | WAPE 1.662% / 0.151%，P90 8.634% / 0.476% |
| combined compute | WAPE 0.446%，P90 2.688%；通过 |

| 结构 | HiCache 8/12、phase 10/12，两者同时一致 6/12 |

总体仍为 MODEL_LIMITATION，小 scope 误差不能掩盖后台 I/O 的大偏差。
Prefetch 和 H2S 占 I/O 不抵消误差约 97.4%。两个 G2/W4 完整前缀命中预测 Prefill 为零，
实测每 rank 128 tokens；原因是当时缺少 input_len−1 后再按页对齐的匹配边界。
G3 四格的短超时等待与零可见页投影未对齐；不能说模型没有 10 ms 等待，也不能删除比较字段宣称 exact。
这些是旧实现的发现，缺少当前执行式实现上的逐项关闭证据，不能自动断言仍有同样缺陷或已经解决。
