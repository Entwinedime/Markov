## 重构后应当怎样理解项目

正式入口维持四个脚本：profile、model、run、build。用户提供 base 和 targets 后，流程是：

1. 采集或读取 base manifest，准备同源采集开销校正。
2. 提取源事实、源资源角色和成本样本。源观测不负责决定目标分支。
3. 从 target 配置、workload 和执行规则产生操作；执行时间影响完成、超时和发布状态。
4. 用 base、可解释外推或适用共享测量赋予成本。缺失明确报告，不改变合法执行规则。
5. 将操作接到资源和因果依赖上，执行完整 HTTP 窗口。
6. 如有独立真实结果，再评分。评分不驱动构模、补采或参数修正。

这不是强求所有操作共用一个万能类。不同业务确有不同语义时保留差别；统一的是信息归属、
执行规则和资源接入方式，不是把差别藏进开关、字符串和大字典。

## 必须保留的边界

- SGLang、KTransformers 同级采集与通用 DAG 能力；HiCache 仅属 SGLang；NodeScale 可选且默认关闭。
- 现行规则下的显式静态 oracle-cost 回放。历史结果作为证据，不恢复历史执行规则。
- source DAG 只来自 source profile；manifest 是采集与建模交接面。
- predictor 不读 target trace、score 或 oracle；独立校准面向整组，不逐格调参。
- HiCache I/O/control、Prefill/Decode、CPU residual gap、probe overhead 各有边界，不互相吸收误差。
- 完整 E2E 不排除 gap、未归属成本或计算。失败格为缺失，不填零。
- 数据资产、原始校准、正常 HTTP 真值和既有稳定对照不删除。
- 输入边界、内存资源安全、关键 DAG 不变量保留；不批量删除异常来掩盖合同破坏。
- 不引入内部版本、SHA、冻结副本或多套正式入口；不新增独立测试文件。
- C++ 头文件统一在 include，实现放 src。代码块内按逻辑留白，保留必要解释。

## A. 源证据、加载和释放：统一目标操作路径

重点联合处理 runtime/load_admission、load_capacity、write_calls、write_host、write_expansion、
eviction_replacement 及对应头文件，沿调用关系扩展，不以单文件为窗口。

现在同时有完整 source 模板与独立成本生成的加载路径，资源重绑定和返回处理要兼容两套对象。
目标是让分配、失败、释放、重试、clone、返回的执行语义只有一处；样本读取只提供成本和资源依据。

- 先明确两条路径的真实差别，包括 prefix/suffix、clone 次数、失败分配 CPU、retry 和返回时刻。
- 把样本差异转为操作成本依据，不用“有无校准”选择不同的目标执行算法。
- base-only 的有效能力不能靠强制新增独立校准来替代；无法拆分的源整段成本明确标注适用范围。
- 源中没有的合法分支由规则生成，缺成本报告具体操作；不引入矩阵身份分支。
- 删除被替代的路径、状态容器、回调和仅为兼容两套路径存在的资源修补。

完成依据：同一加载状态转换只保留一处执行规则，成本依据与操作生成分开；不只是函数改名。

## B. 写入、预取、层等待与资源连接

联合处理 writes、write_lifecycle、write_capacity、write_confirmations、load_submission、layer_calls、
prefetch_queries/waits、window 及 source_dag_index、host removal/insertion。

- 源图观测与目标修改分阶段组织，保留稳定操作身份、边界和资源角色。
- 减少“修改图—其他模块重新找节点—修补引用”的隐式调用顺序。
- 一个相关操作组先构造完整 mutation 再应用；动态图仍可按实际执行事件逐组展开。
- 索引能复用时复用，但不得跨图修改盲目缓存会失效的节点与队列位置。
- 统一提交、等待、返回与资源插入原语；CPU、worker、设备、残余等待仍分别表达。
- 保留逐页发布、取消、超时、写回和淘汰的必要状态，不用总量近似替代因果关系。

完成依据：资源连接不再各业务维护重复规则；状态所有者清楚，清除可替代的重复绑定代码。

## C. 通用 DAG、输入解释、仿真与静态回放

覆盖 core、io、frontend、simulation、cli、hicache/patch 和诊断链。

- 核对事件规范化、时钟、关联、同步、mutation、仿真的职责；删除重复中间表示和无人消费字段。
- 正式执行与静态回放尽量共享操作、成本及底层落图规则，不把静态回放强行变成完整运行时。
- 已共享的 service cost 不再另造公式层；source fact、目标工作与成本记录只合并真正重复的字段。
- 诊断明细按开关构造，不在默认流程准备随后丢弃的大量报告。
- 清除独立测试删除后遗留的 friend、测试专用接口和不可达分支，保留正式安全检查。

完成依据：完整调用链的生产者和消费者对应清楚；静态回放与通用框架能力仍有正式入口。

## D. 成本表示与 Python 工作流

覆盖 modeling、modeling_workflow 的 group/prepare、observations、io_model/build、calibration、
physical/control acquisition、execution/prediction/evaluation。

- 明确模型表示与 target 投影的唯一所有者，减少字段搬运、重新解析和重复合同检查。
- 本阶段保持成本公式及参数选择含义；发现数值问题记入后续误差清单，不混入逐格修正。
- 采集沿用现有 recorded_capture，理清预算、尝试状态、产物准入和恢复，不新增通用流程引擎。
- 汇总多类缺口后串行共享补采，再统一更新模型。避免同一逻辑在前置准备与执行补采各写一遍。
- 评估按成本依赖减少不受影响的重复预测；只有能证明模型更新不影响该任务时才保留本次结果。
  若需要复杂缓存或另一套状态账本才能实现，则优先保持简单整组重跑，记录实际取舍。
- HTTP 评分与可选回放分别组织；不能为代码复用让 predictor 导入 evaluator。

完成依据：主流程能自上而下读懂，模型输入与运行配置不会多次无意义往返，采集与预算只有一套事实来源。

实施取舍：当前补采会重新选择共享参数，参数变化还可能通过 I/O 完成与 deadline 改变后续工作量。
仅凭“这一格之前没缺成本”不能证明它不受影响。本轮保留整组重跑，不增加参数依赖账本或缓存系统。
组级数值模型是长期输入，target 执行配置是一次派生结果；两者不强行合成一种 JSON。
Python 负责校准适用性选择与 target 投影，C++ 独立 CLI 保留执行输入校验，公式仍只在所属成本实现中维护。

## E. Profiling、公开入口、配置和文档收口

覆盖 profiling runner/executor、probe/hook、workload、manifest、Shell、docker 与 configs。

- 沿实际入口检查重复调度、配置展开和无消费者选项，不凭名称删除真实 workload 或框架能力。
- probe 保持轻量、默认 snapshot-free；不把 CPU 时间、墙钟和采集扰动合并。
- Shell 保持薄封装，Python 组织业务，C++ 负责 DAG 与执行；消除为了内部层对齐产生的重复参数。
- 删除被替代实现、无用导出与空目录；不重写第三方，不清理运行数据。
- 主文档对齐唯一现行流程，记录限制和最终结构；临时文档不成为第二套长期使用说明。
- 再按原口径统计行数、文件数和增删，解释新增抽象是否真正替换了旧实现。

完成依据：A–E 每项有实施结论和剩余项，调用链不存在“新实现已写、旧路径仍并存”的未收尾状态。

## G. 重构验收后再启动降误差

只有 F 完成后，才基于新结果另建误差改进 plan/log，不能把历史归因原样当作当前结论。

- 选不同误差机制的代表格，分别检查 CPU 工作、依赖等待、I/O、Prefill/Decode 与未知残余。
- 优先修复可定位的工作量、重复计费或依赖错误，再改善参数来源和外推范围。
- 使用 base 和少量共享独立校准，不以 target 残差、配置名、workload 名增加参数。
- 保持完整 HTTP 分母，目标仍为总体及逐 base WAPE ≤3%、P90 ≤5%，争取所有格低于 6%。
- 参数含义与来源能整体解释，不要求每个实现细节对应一句自然语言。
- 公式稳定后再统一运行 60 cross；已看过的矩阵为修复回归，不能声称盲测泛化。

完成目标需要重构、统一正确性验收和后续误差改进的实际证据；计划写完或行数下降都不代表 goal 完成。
