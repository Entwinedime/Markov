# 三阶段建模重构计划

## 目标与已确认取舍

本轮将正式建模流程分成三个有明确输入、输出和修改边界的阶段，而不是只移动目录：

```text
base trace → 原始 DAG → target 结构计划 → 成本绑定与执行 → 完整 HTTP E2E
                            ↑                 ↑
                target / workload / 执行规则   独立数据库成本模型
```

- 第二阶段允许条件结构计划；超时、逐页发布、取消和重复操作仍按执行规则展开。
- 当前 base 仅提供原始图和可直接迁移的成本，不自动入库或用于临时拟合。
- 历史采集显式入库、离线训练；首轮只支持同模型、同 TP，其他部署分别保存与选用。
- 留出实际评分采集，允许同配置其他历史采集；报告区分已覆盖配置预测与未见配置泛化。
- 首批保留常数、分段线性、线性和物理公式；不在本轮加入随机森林或算法搜索。
- 历史数据优先复用，必要时最小补采；自动补库默认关闭，显式开启并有预算才执行。
- 本轮完成标准是三阶段真正解耦、数据库及工作流可用、60-cross 得到预测和三类可信报告。
  不把所有格低于 6% 设为完成条件，也不隐藏精度退步。

这次重构首先解决“结构怎么生成、成本从哪里来、结果怎么判断”三个问题，不以换目录或加入数据库作为完成标志。
也不借这次机会扩大配置支持范围、重新设计采集系统，或做模型算法搜索。

### 与现有主文档的关系

最新验收以本文“最终验收清单（10-04）”及 `docs/work_progress.md` 为准：
本轮 A–E 已按下方验收清单完成。设备流切口修正后的 60 格预测及独立评分已经完成，
结构差异、覆盖不足及精度退步如实交付，不将这些限制改写为通过。
本节不再保留迁移初期的“尚未构建/运行”流水；具体历史过程见实施日志和本文后部记录。

主文档维护当前接口、模型原理与限制，计划负责约束验收，不能互相复制逐轮状态。
收口时仍需核对以下要求，不能因主流程跑通而省略：

- 成本覆盖分别报告模型查询、节点绑定及实际执行；未归属节点保持未知。
  全图服务量不是 HTTP 关键路径贡献，查询成功数也不是覆盖率。
- I/O payload、提交/释放控制和存储批次分别生成、绑定；确认位置与资源依赖由结构规则决定。
  阻塞检查逐笔确认、发布并允许后续 DMA 与 H2S 重叠，容量不能提前释放，也不能重复确认。
- 独立控制观测只用于显式入库和训练，不回到原始校准文档的预测旁路。
  重提取同一采集不算新样本；缺模型声明不启动无效补采，缺测不能按零处理。
- 张量、allocator 和主机操作的工作描述不携带 DAG 槽位或模型参数。
  同步读回不伪造 worker，不重复计设备等待；跨时钟、多 worker 和唤醒延迟的证据不足单列。
- 现行静态回放保留，与执行式预测使用不同的职责入口；旧成功记录不代替当前工作树验证。
  当前源码与训练输入变化不追溯改写历史实验成绩。

### 首轮支持范围与输入条件

首轮以现有 SGLang 执行路径和部署为准，覆盖现有实验涉及的 HiCache 页大小、缓存容量、
写回/预取策略及其组合。阶段 A 从配置解析和框架源码列出实际支持项及组合限制，不能把 C1–C5 名称当作支持范围。
模型、TP、dtype、设备和执行实现保持在已声明的适用域内；数据库能存其他部署，不等于预测支持部署切换。
工作量或页大小改变可能改变算子实现，不能仅因模型和 TP 相同就宣布成本可迁移。

workload 是应用输入，包括请求到达顺序、输入 token、生成长度或停止规则，以及必要的复用关系。
当前矩阵使用已有 forced-token 资产明确这些条件，不从 target profile 补取生成长度、命中结果或实际调度。
仅给自然语言请求、未给生成长度分布时，不能声称已经预测未知输出长度下的完整 E2E；这属于另外的工作量问题。
本轮先保证已知 workload 条件下的配置预测，不新增请求内容或输出长度预测模型。

配置不支持、观测不足和成本缺失分别报告。合法结构缺成本不能报成配置不支持；
框架没有该执行机制，也不能用数据库里同名成本强行补成支持。

## 一、三个阶段及衔接

### 原始 DAG

只通过 profile_manifest 读取源 trace，合并通道及 rank，构建操作、依赖、请求和资源语义。
源测量与源坐标保持原样，采集开销校正作为另外的成本依据保存，不覆盖原观测。
不应用 target、HiCache 预测、NodeScale 或数据库模型。后续在独立工作图上操作。

第一阶段输出不只是节点和边，还须保留后续所需的源身份、资源关联、请求顺序、阶段观测和测量口径。
源回放保留现有构图器的同步/队列等待归一规则：等待由依赖表达，部分节点不再使用原始墙钟耗时。
报告须明确这一口径并记录被改写耗时的原始事件节点数量，不能称为完全未调整的原始耗时回放。
没有获得 HTTP 回放值的源报告应列为不可用，文件存在不等于第一阶段已完整报告。
已存在的 CPU 开销校正属于第三阶段可选择的成本视图，不影响第一阶段对原始观测的保存。
源图可以使用只读共享存储、独立工作副本或已有的安全 mutation 机制隔离；不要求在每个 cell 同时复制两份庞大图。
实验源回放本身也会写入队列顺序、ready delay 和模拟时刻，因此在独立副本上执行，
报告完成后释放副本；不能让开启实验报告改变正式预测的源图。
无论采用哪种实现，后续变换都不能覆盖用于源回放、成本迁移和来源核对的原始观测。

### 目标结构计划

结构模块决定操作、工作量、shape、依赖、资源角色和条件分支；不能读取数据库、参数或 target trace。
HiCache 状态规则、Prefill/Decode 工作生成与框架适配分别拥有自己的结构职责。
成本缺失不能让合法分支消失，也不能用源模板是否存在决定目标是否执行。

时间相关结构使用声明的分支与循环规则；执行器提供完成事件，结构模块据此展开操作。
实际结构可能随成本而改变，但规则始终属于第二阶段，不允许成本提供者修改 DAG。

因此，三个阶段是职责和数据边界，不是要求先算出一张与耗时无关的完整 target 图。
第二阶段先交出确定工作及条件执行规则，第三阶段绑定成本并推进时钟；条件成立时，
仍由第二阶段的规则生成后续操作。最终展开的图才用于结构报告，未展开计划不能冒充完整目标图。
无需为做到这种分离另写一套仿真器，也不允许状态机和 DAG 各自计算一份服务完成时间。

操作描述包含语义身份、所属组件、工作量/shape、资源和依赖，以及成本绑定方式：
未变化操作引用源测量，变化或新增操作描述成本需求。动态特征在状态确定时补全。
操作描述不得携带回归系数、训练算法、数据库表名或校准路径。

### 第二、三阶段的衔接合同

两阶段共享的是“需要执行什么”，而不是某一种成本模型的输入格式。操作描述至少表达以下语义：

| 内容 | 负责提供的一方 | 约束 |
| --- | --- | --- |
| 操作身份、组件、请求及阶段位置 | 结构模块 | 不以跨 trace 的局部节点编号作为语义身份 |
| 工作量、必要 shape、实现选择和资源需求 | 结构模块 | 明确单位；动态值在操作准入时补全 |
| 前驱、资源顺序、发布/完成点、条件分支 | 结构模块 | 不读取回归参数，不因缺少成本而删掉合法工作 |
| 源成本引用或需要预测的操作描述 | 结构模块 | 说明迁移依据，而不只给一个“沿用”布尔值 |
| 服务耗时、来源、覆盖范围和不确定性 | 成本提供者 | 不能增加操作、修改工作量或决定缓存策略 |
| 排队、重叠和实际完成事件 | 执行器 | 使用同一个 DAG 时钟反馈给结构规则 |

接口采用少量明确的领域对象，不为每个字段建立包装类，不要求所有组件具有相同的特征集合。
shape 和特征选择需要区分：结构模块描述实际工作，成本模型从中选取自己的变量；
不能为方便某个回归公式而修改实际工作量，或把公式系数塞回结构对象。

源节点引用只用于同一 source 图中的成本对应与来源追溯，不能要求新增操作也必须找到源节点。
工作描述不能依赖源节点持有的耗时；一个没有源成本引用的新操作，仍必须能完整描述其语义、工作和依赖。
迁移判定记录本操作需要核对的条件，不把所有组件压成一套固定 shape 字段或硬编码事件白名单。

以预取为例：第二阶段规定读哪些页、在哪些位置检查取消、何时发布，以及超时后如何处理；
第三阶段提供读、复制和返回的耗时；执行器到达对应完成点后通知状态机。
不能由成本模块判断“这个预取不值得做”并删掉它，也不能把数据库曲线直接暴露给缓存状态规则。
缺成本时，可以报告已经确定的工作及尚未展开的条件规则，但不能把它们当作已完成目标 DAG 或有效 E2E。

### 阶段交接的最小产物

| 阶段 | 交出的内容 | 后续允许做什么 |
| --- | --- | --- |
| 原始 DAG | 源图、原观测、请求/资源关联与源操作索引 | 读取与引用；target 变换在工作视图中进行 |
| 结构计划 | 确定操作、条件规则、依赖、工作描述及迁移依据 | 成本提供者读取工作描述；执行器反馈完成事件 |
| 成本与执行 | 每项绑定的来源及耗时、实际展开图、请求完成时间和局限 | 独立评价读取；不反向修改训练和执行规则 |

这些是内存与数据合同，不要求每个阶段默认导出完整 DAG 或重新解析大型 JSON。
普通应用保持紧凑输出；实验显式保留比较所需的操作和依赖明细。
源引用在本次 source 图生命周期内稳定，新增操作使用自身语义身份，不能为了获得节点编号而借用源模板。
迁移记录说明哪些相关条件未变；成本模型记录为什么适用。两者各有职责，不互相重复做整份配置校验。

阶段边界按调用和数据流落实，不只按目录落实：结构规则不得调用模型选择或读取成本文件；
执行器可以把结构规则和成本提供者组合起来，但不得另写一套隐藏的缓存决策。
时间触发的结构差异由同一时钟解释，不能再维护一套只供报告使用的“理想 target 图”。

### 成本与执行

只迁移工作量、实现及适用资源未变化的成本；其他成本由独立模型预测。
无执行工作的语义边界允许为零，测量缺失不能记零。
CPU 服务、设备、通信、I/O、residual gap 和 probe overhead 独立管理。
等待与排队通过依赖、资源和仿真产生，不把整段等待当固有服务重复计费。
尚无模型的源 residual gap 可暂时保留，但明确标为近似而非已证明不变。

### 哪些成本可以沿用

迁移是对具体操作的判断，不是对整段 Prefill、Decode 或整条 CPU 分支的判断。
只有影响该操作耗时的工作量、实现及资源条件未改变，才能直接引用源测量；
新增调用即使名称相同，也不能默认按源调用平均耗时填入。

- Prefill 不能只看新 token 数，还要核对相关上下文、batch、算子实现及必要 shape。
- Decode 不能只看总轮数；需要区分逐轮上下文、缓存页与 kernel 内部分块，不能将三者混为同一个变量。
- I/O 按实际传输字节、调用/batch、existing/new 和后端区分；可见页数不能替代已执行传输量。
- CPU 提交和控制成本核对实际调用序列与工作规模；不能用整段墙钟等待作为单次固有服务成本。
- 对未建模的 residual gap 和其他未归属时间，保留源近似时单独标注，不能宣称已证明可迁移。

显式区分源成本迁移、模型预测、无实际工作的语义边界，以及保留但未建模的间隔。
零耗时只用于已知没有服务工作的情况，不能用于成本缺失。
完整 E2E 仍包含这些间隔；不以隔离、置零或跨组件补偿获得本轮精度成绩。

## 二、成本数据库与训练

SQLite 保存部署、采集来源、操作观测和训练参数；原始 trace 留在现有资产目录。
runtime trace 和独立校准均通过显式入库进入数据库，不要求来自 base。
逐操作样本用于逐操作模型；汇总只能用于相同语义的聚合操作，不能按 base 耗时比例分配目标成本。
缺 shape、工作量或计时归属的旧样本标明不可用，不猜测补齐。

### 数据怎么进入数据库

入库是独立、显式的动作，预测不扫描历史目录、不自动把本次 base 变成训练样本。
已有 runtime profile 从 manifest 提取操作观测；独立物理测量和 CPU 操作校准保留其测量来源和计时范围。
已有训练参数可以迁移为参数产物，但不能反过来伪装成原始测量，增加训练样本数。
不同模型或配置的历史采集可以存入同一数据库，是否能够参与某个模型训练由适用条件决定。

数据库按模型、硬件、TP、dtype、操作实现、I/O 后端、布局和计时类型区分适用性。
首轮计算/控制按相同部署训练；物理 I/O 按设备、布局及后端选择，不能因入同一库就混用。

采集开关、导出目录和实验名称是来源信息，不应使同一部署被错误拆成不同资源环境。
硬件、实现和线程/资源设置则不能为了合并样本而忽略。旧资产缺少这些信息时，
只能在有证据的前提下显式补充部署声明；无法确认的样本保留但不参与相应训练。

同一采集/操作重复导入去重；相同特征的不同真实运行保留，用于测量波动。
采用原采集身份、manifest 和源操作位置，不使用 SHA、冻结副本或内部版本号。
重复导入不增加样本权重，但保留新声明的来源路径及完整/轻量配对成员。
训练留出和导出的成本包都使用这些来源关系，不能只保留首次入库的路径；
同一次采集的别名与配对测量依赖分别记录。按已知采集 ID 留出时覆盖它的全部声明别名，
并排除依赖这些采集的测量；不会把该测量的其他独立输入也自动视为同一次采集。
预测仍不访问数据库。已导出的成本包不会因后来增加别名而自动更新，使用新声明前须重新离线导出。
复制资产显式声明原采集身份；来源不能确定时不能当新测量增加训练权重。

同一来源重复导入应不增加样本；同一身份内容冲突要报告，而不是覆盖旧观测或同时计权。
不同运行的同特征样本不去重为一条，它们用于说明测量波动。
训练时说明重复层、重复调用和独立采集的权重，不让某次 trace 因事件特别多而主导参数。
首轮以单次采集内同工作点的代表值、再结合不同采集建模；不根据 target 误差挑选样本。

Python 离线训练并导出紧凑参数，C++ 本地提供成本，不逐节点调用 Python 或查询 SQLite。
模型保存特征、单位、来源、覆盖范围和外推限制。不同操作族使用不同模型，接口不依赖 HiCache 身份。
删除 base 优先、当前组临时估计和阶段总量按源耗时份额投影的正式路径。

### 首批成本模型的具体要求

迁移初期发现的计算模型问题是：通用 Prefill/Decode 算子观测和目标请求
只使用 `PrefillShape` / `DecodeShape` 的阶段级变量，没有逐 MatMul 的矩阵维度。
独立历史采集 `hicache_calibration_cpu_correction_20260923` 的
`20260923_030441_base_cpu_profiled` 配置明确为 `record_shapes: false`；抽查其 rank 0 的
`aclnnMatmulBatchInvariant_MatMulV3BatchInvariantCommon_MatMulV3BatchInvariant` 原始设备事件，
只有任务/流/关联信息，没有矩阵 shape。该证据只说明这份采集及抽查事件，不能推断所有历史 trace 均不可用。

这部分按以下顺序收口，不通过增加同名样本替代工作描述：先确认同名实现是否包含不同矩阵工作，
再从有 shape 的 CPU 算子包络及提交关联提取实际工作；缺信息时在必要的独立采集中显式开启
shape 记录，并检查采集开销。目标端根据模型执行规则与目标 token/batch 推导对应形状，
不能只在训练样本中增加预测端无法提供的变量，也不能从 target trace 补取。已有 Attention/allocator
专用描述与这项通用计算缺口分别处理。阶段级代理变量可以作为明确说明局限的近似，
不能写成已获得完整算子几何或已证明同名操作成本可共享；完成情况须在 C/E 收口时给出实际证据。

当前源观测保留 shape、stride、提交关联及未解析项；源进程 ID 不当作逻辑 rank。
`structure/phase_shape` 已按实际矩阵工作生成 M/N/K、元素数和乘加量，独立成本包中的
`prefill.linear` / `decode.linear` 使用这些几何变量约束适用范围，并已用于本轮矩阵。
这取代了仅有阶段变量的旧前提；不表示所有历史 trace 都可恢复几何，也不表示常数模型已解释
任意矩阵大小的成本变化。具体后端、布局和模型形式仍按主建模文档与成本包限定。

每个操作族需要给出一段能读懂的说明：执行的工作是什么，使用哪些变量，系数来源是什么，
公式怎样训练和预测，以及什么输入暂时不支持。无需为每个代码细节逐句配自然语言。

常数模型只用于明确不随所支持工作量变化的原语；线性模型要说明截距与各变量的含义；
分段线性模型使用真实工作点；物理 I/O 模型区分调用启动、字节传输和发布/返回等工作。
不为了补齐某个 cell 偷换公式、隐藏截断负值、增加专用倍率，或把阶段汇总重新按源耗时比例摊回节点。
无法辨识系数时报告缺少哪些工作点；调整变量或模型形式必须有执行机制依据，不能由评分自动选择。

CPU 服务、通信、设备计算和测量墙钟不能混训。未做开销校正的 CPU 样本可以保留作原始观测，
不能默认当作正常运行服务成本；必要的独立校准使用自身 full/light 配对，不能借用 base 的时间坐标修正。
同步读回若因主机/设备时钟映射不能测得完整返回区间，应按执行语义拆分：同步返回后的复制/调用尾部
用同一主机时钟测量，同步 API 的非等待服务另由已空闲设备流的独立原语测量提供，等待前序计算由依赖表达。
两段齐备前不得用其中一段替代完整读回成本；不硬改时钟频率，不把同步调用的阻塞墙钟重复叠加到设备等待。
首次编译/准备和稳定运行的成本也要区分，不把偶发首次开销吸收到普通计算系数中。

训练输出是可直接用于预测的紧凑成本包，包含适用部署、逐操作模型、I/O 参数、必要的独立控制成本、
来源与缺口。预测只读这个包，不在线训练、不逐节点查数据库，也不隐式读取训练用的原始 trace。
数据库的当前模型可被显式重新训练替换，不引入内部版本号、冻结副本或摘要校验。

缺口区分操作/分支缺失、部署不适用、必要特征缺失、特征不可辨识及域外未验证。
有依据的线性或物理外推可以返回结果并报告限制；分段曲线域外或缺必要证据不能伪造结果。

覆盖查询应回答“这个操作及这份工作是否有依据”，而不只是“数据库里有没有同名函数”。
预测结果需要说明迁移、域内预测、显式允许的外推和未建模近似分别在哪里使用。
不能仅凭操作成功返回一个数值就标为完整成本覆盖。

### 训练、覆盖和应用的先后关系

先确定测量来源及部署，再提取观测、选择有机制依据的变量、训练并导出成本包。
预测使用操作描述查询这个包：工作未变化时迁移明确对应的源成本，否则选择适用模型。
特征范围只描述已有证据，不能把“各变量分别在范围内”当作其组合一定有观测支持；
线性模型还须满足变量可辨识，分段模型须有适用工作点，未见组合或外推单独说明。

数据库去重与模型适用性是两件事：同一采集重复导入只计一次，但多个相似函数名不能因此合并成一个原语。
离线训练可以从同一库中按声明的部署和操作条件选样本；应用只携带成本包，不要求同时携带 SQLite 或原始校准目录。
包内控制成本应包含实际执行需要的数值与语义来源，而不是要求预测时重新打开 trace 提取控制程序。
来源路径用于追溯，不作为运行时必须可访问的依赖。

成本包不能把历史测量中的节点数组和依赖片段直接当作目标程序。
若某服务必须整体测量，可以保留聚合耗时及其适用工作描述，但其调用位置、重复次数和同步关系仍由结构规则决定。
同一操作有多份适用独立测量时，由离线训练按明确口径合并或显式选用；不在预测时以文件加载顺序覆盖参数。
同名模型具有重叠适用域时，须明确选择依据，不能默默使用列表中的第一项。

不足以支持预测时，缺口至少说明操作、部署、必要工作量/单位、已有证据和拒绝原因。
不承诺在证据不足时输出统计置信区间；首轮的不确定性来自测量波动、覆盖范围、外推假设及未建模项。

### 各成本族的责任清单

阶段 A–C 联合完成下表对应的实际操作清单。表中是职责，不是要求为每行新增一套模型框架。

| 成本族 | 主要工作描述 | 需要特别分清的内容 |
| --- | --- | --- |
| HiCache I/O | 方向、实际字节、页布局、batch、后端、existing/new | 执行量与可见量；服务与排队；取消前已执行的工作 |
| CPU 控制 | 原语、分支、处理规模、线程角色、实现 | 固有服务与等待；失败/重试/排序与成功调用不能互代 |
| allocator preparation | 特化形状、准备路径、首次及缓存状态 | 编译/加载与普通分配；目标未出现过的合法特化 |
| Prefill/Decode | 算子、必要 shape、逐轮上下文、batch、实现 | 缓存页与 kernel 分块；计算、提交和通信的不同计时口径 |
| 通信与同步 | 集合通信类型、数据量、rank/资源、实际等待对象 | 通信服务与依赖等待；不得同时收取墙钟包络和内部服务 |
| residual gap 与未归属时间 | 源关联、保留位置、时间口径 | 只作明确近似；被替换操作的源等待不能无条件再复制一遍 |

每族说明变量、单位、系数来源、公式、训练选择和适用范围；不强求全部使用同一公式或相同特征数量。
probe overhead 是测量修正依据，不是可迁移的正常执行工作；已修正成本不能再次扣减。
完整 E2E 需要保留相关间隔，但“保留”不等于重复收费：替换源片段时同步核对间隔与依赖的归属。

## 三、显式自动补库

默认只报告缺口。显式开启且有累计预算时，汇总整个 target 组需求，按部署、操作和特征去重，
复用现有采集器补库；不得依据 target E2E 或评分误差选实验。
采集严格串行，失败/重试计入累计预算。统一入库训练后，用同一模型重新预测整组，不逐格拟合。
动态分支中的新需求走相同路径；同一未解决需求在一次调用中不重复采集。
预算耗尽和不支持的采集明确报告；评分开始后不得再训练或补采。

缺口识别先来自已知操作需求和模型覆盖，运行时才显露的需求再补充到同一组计划。
补采选择依据操作、必要变量及缺失分支，不依据 cell 名称或哪个格误差最大。
同类需求尽量合并成少量实验；不能一遇到域外就跑对应 target 的完整 workload 来获取答案。
现有采集器不支持某项需求时直接列出限制，不承诺本轮能自动解决所有成本缺口。
工作描述缺少模型必需变量、或模型给出无效耗时，不是可直接补采的测量缺口；
组摘要单列这两类修正需求，不原样重复实验。其他确实缺少操作测量或变量覆盖的需求仍按组补采。
运行时与离线查询应给出已有计时口径、缺失变量或已测范围，避免将接口问题误诊为数据不足。

一次补采后的数据显式入库并重新训练，再用同一个成本包重跑整组。
失败、重试及各阶段启动仍进入已有累计预算；不重置历史耗用，不另建一套平行账本。
一次调用不反复采同一个未解决需求；后续需要继续采集时须保留缺口、尝试和剩余预算。

## 四、代码与公开入口

Python 建模按 source_dag、structure、cost、execution、evaluation 分工，数据库及训练属于 cost。
C++ 保留共享 graph/I/O/simulation，分开源图构建、结构模块与成本提供者；头文件仍与实现分置。
拆分实际职责，不创建转发包装层，不为尚不存在的插件引入动态注册框架。

公开入口继续使用 scripts/model.sh：build-dag、predict、cost-db import/train/inspect、evaluate。
predict 串联三阶段，默认使用已训练模型；显式自动补库才进入采集准备。
迁移现有调用方与配置后删除旧正式流程，不同时维护两套准备/训练/预测路径。
SGLang、KTransformers、现行静态回放和默认关闭的 NodeScale 全部保留。
NodeScale 属于显式成本变换，不混进原始构图或 HiCache 结构规则。

### 子模块及迁移边界

结构子模块负责状态、合法工作和依赖规则；成本子模块负责操作描述到成本的映射。
二者可以服务同一个功能，例如 HiCache，但不合成一个同时读取样本、决定策略和修改图的大模块。
按实际调用链迁移，包括调用方、配置解析、导出器及文档；不只在新目录写接口而让旧主流程继续绕过它。

独立控制校准中若同时包含程序片段和成本，需要拆开处理：合法调用序列、资源角色和重复次数由执行规则定义；
校准只提供适用原语的成本。不能让成本包中的样本片段变成决定目标合法分支是否存在的模板库。
已有源片段可用于对齐源资源和可迁移工作，不能作为生成 target 新分支的唯一条件。

迁移期间不保留两条长期正式流程。旧路径在替代路径及调用方完整接通后移除，
不能先删除仍被使用的入口，再把运行失败当作重构已完成。静态成本回放单独保留，
其诊断性成本注入与正式数据库预测清楚区分，不将历史回放接口重新包装为在线拟合路径。

普通 build-dag 保持框架无关；KTransformers 不接受伪造的 HiCache 参数。
本轮只为已存在的组件建立清楚的接入边界，不新增插件注册平台或无实际调用的扩展框架。

### 按实际职责链联合迁移

下表是实施分块，不是新增六套接口或永久子系统。每块同时整理生产者、消费者和配置，
共享的操作描述及资源合同先明确，再处理各组件；不要一边保留旧表示，一边另建长期并行表示。

| 分块 | 需要一起处理的逻辑 | 完成后应消除的问题 |
| --- | --- | --- |
| 源图与观测 | manifest 构图、原测量、CPU 校正视图、源回放 | 原图被变换覆盖；校正数值冒充原观测 |
| HiCache 状态与 I/O | 策略、容量、页状态、batch、取消、发布、资源 lane、服务完成反馈 | 状态机持有带宽参数；规划与执行重复计时 |
| CPU 控制 | 查询、scheduler、加载准入/提交、层等待、写确认、释放及 allocator preparation | 从 base 求均值外推新增调用；校准片段决定合法分支 |
| Prefill/Decode | 目标阶段工作、算子布局、逐轮上下文、源对应、逐操作成本绑定 | 只按 token 判断迁移；阶段总量按源耗时比例摊回 |
| 数据与成本 | 原观测入库、部署适用性、去重、训练、参数包、覆盖与组补库 | 预测在线拟合当前 base；原始测量和旧参数混为样本 |
| 编排与实验 | 用户入口、串行采集与预算、执行结果、三报告、旧入口及文档 | 多套正式流程；应用读 target；评分触发训练 |

这些混合职责是迁移核查重点，不意味着所有旧分支都应无条件删除。
源自身的可迁移成本、正式资源与依赖安全检查、显式静态回放仍保留；删除的是重复路径和不符合新合同的预测依据。

## 五、实验报告

- 第一阶段：源观测成本静态回放，对照同次采集正式窗口；报告时序误差、覆盖与依赖问题。
  校正成本另列；时序还原不能单独证明每条依赖正确，不以正常 HTTP 替代 profile 真值。
- 第二阶段：独立提取 target 图，比较操作、工作量、shape、分支、资源与语义依赖。
  覆盖完整可比较图并分组件；不比较局部节点 ID，不要求时间戳相同。
  未观测、无法对应和调度敏感差异单列，不悄悄排除后宣布 exact。
- 第三阶段：预测与正常 HTTP 完整 E2E 对比，报告 APE/WAPE/P90/最大误差及成本覆盖。
  不排除 gap、未归属成本和 Prefill/Decode。

三类评分只在实验模式运行。target 仅由独立 evaluator 读取；报告不训练、补采或回写模型。
target 结构提取与成本样本导出分开：评分器请求结构时不提取训练成本，
不以成本样本是否可测决定结构证据是否可用。独立成本导入仍走完整测量提取路径。
实验训练留出本轮全部评分采集，同配置历史数据参与与否明确披露。
应用路径仅保留紧凑预测结果、必要来源与缺口，不执行实验评价。

### 三份报告分别证明什么

第一份报告回答“源观测能否由原始 DAG 正确回放”。使用未变换、未替换成本的源图，
对照同次 profile 的正式窗口，报告有符号时间差、绝对误差、事件/请求覆盖和已发现的依赖问题。
源 CPU 校正后的结果另列，不能替代原始回放。该报告不等于 source→target 的 oracle-cost 诊断。

第二份报告回答“配置变化后的工作与依赖生成得怎样”。按请求、rank、操作语义及资源角色建立对应，
比较操作增删、工作量/shape、I/O batch 和实际执行/发布量、阶段工作，以及必要的依赖与资源顺序。
图中冗余边可按相同可达性解释，但不能把缺少真正同步的情况算成一致。
只有节点数或按类别汇总相同，不能宣布结构 exact；只完成汇总比较时，必须明确其证明范围。
时间敏感分支不同仍记为结构差异，同时说明其可能与成本时钟有关，不能直接全部归为结构规则错误。

第三份报告回答“用户实际等待的时间预测得怎样”。正常 HTTP 重复测量采用预先确定的样本集合与汇总方式，
保留重复次数和范围；不事后选最接近预测的一次。
单格 APE 为绝对时间差除以真实时间；WAPE 为全部格子的绝对时间差之和除以真实时间之和；
P90 使用最近秩。报告总体、逐 base、逐 workload、最大误差及有符号偏差，失败格不记为零。

实验需要两类独立 target 输入：带 trace 的采集供结构比较，正常 HTTP 采集供完整 E2E 评分。
实际用于这两类评价的采集都从训练中留出；配置相同但另一次历史采集可以参与训练并披露。
第一阶段的 base profile 用于源回放，不因此自动成为训练输入。

三份报告使用同一轮明确选择的输入和当前代码结果，不用旧成绩拼成一次完整验收。
评价器不得修改预测文件、成本包或训练状态；应用流程不要求任何 target 实测存在。
结构和分项诊断中的未知、未覆盖、无法对应应给出数量与原因，不隐藏在“通过”字样中。

报告采用以下最小判断口径，不再增加一套逐文件证明或冻结机制：

- 源回放覆盖：列明输入中应进入正式窗口的可建模事件、已建图事件及未支持事件；
  过滤范围单列，不用图内节点数充当事件覆盖率。依赖审计说明查了哪些同步/资源关系及发现的问题。
- 结构比较：先建立语义对应，再比较工作和必要关系。未匹配操作及不可比较关系进入报告，
  即使时间误差很小也不算结构正确；观测不到的依赖不能宣布已经证明。
- 成本覆盖：按操作计数和服务量分别说明迁移、模型预测、允许外推及未建模近似；
  服务量统计不是关键路径贡献，各节点耗时不能相加当成 E2E。
- 失败结果：列明未完成格及原因；可另列已完成子集指标，但不能把子集指标写成完整 60 格成绩。

阶段报告默认保留摘要和问题清单，完整匹配/依赖明细由实验诊断开关控制。
“执行完成”“结构比较完成”“成本覆盖充分”“精度达标”是不同事实，不合成一个 PASS 掩盖未知项。

结构报告分开给出操作对应覆盖、工作量/shape 差异及语义依赖差异，不合成一个看似精确的万能相似度。
资源共享关系比较须覆盖双方的全部匹配操作；未归属资源的操作单列，两侧同为空不能当作资源一致。
第二阶段比较的是正式预测实际展开的图，不能先填入 target 真实成本，再把得到的结构一致性作为正式成绩。
如需成本替换诊断，放在单独诊断项中，并说明它只帮助区分时钟敏感性与规则问题。

## 六、实施阶段与验收

### A：边界与数据合同

核查调用链，确定源图、结构规则、成本与执行所有者，建立操作描述和绑定合同。
先明确真实时间相关行为，再迁移实现；不能把成本/资源决定混成结构规则。

收口条件：列清仍混合结构与成本的调用链；确定操作描述、迁移依据、缺口和完成事件的接口；
为各现行成本族明确样本粒度及计时范围。发现尚不能说明的机制先写清问题，不用接口名字掩盖它。

### B：源图与结构模块
