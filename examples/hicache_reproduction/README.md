# 从空数据重建 HiCache 实验

这是一个独立的复现实例，不是 Markov 新增的正式工作流。它只通过仓库现有的
`scripts/build.sh`、`run.sh`、`profile.sh` 和 `model.sh` 组织实验，不导入内部 Python 模块，
不改预测、采集或成本模型实现。删除本目录不影响项目的正式功能。

## 怎么运行

在宿主机运行，不要在 modeling 容器里运行：

```bash
# 先展开实验范围，不下载、不构建、不启动容器或使用 NPU。
examples/hicache_reproduction/run.sh --dry-run

# 从空 data/ 和 build/modeling/ 开始执行。
examples/hicache_reproduction/run.sh

# 已有本地 ShareGPT 时，不必重新下载。
examples/hicache_reproduction/run.sh --dataset /path/to/ShareGPT.json

# 已有适用的独立成本包时，直接复用，不重新采集和训练。
examples/hicache_reproduction/run.sh --skip-build --cost-model data/reproductions/hicache/costs/prepared/cost_model.json

# 预测已经全部成功，仅正常对照/评分中断时，从该阶段继续。
examples/hicache_reproduction/run.sh --resume-normal --cost-model data/reproductions/hicache/costs/prediction_cost_model.json
```

先检查同目录的 `recipe.json`。默认示例是 Qwen3-32B、TP=2、NPU 0/1、NUMA 6，
两组 CPU 分别为 144–155 和 156–167；这些是实验部署，不是通用平台默认值。
设备必须空闲，CPU/NUMA 要与当前分配相符。更换放置时同时调整设备、NUMA 映射及 CPU 集合。
本例只覆盖两张连续编号 Ascend 卡的 TP=2 部署，不代表任意模型、平台都已适配。

需要预先提供 Docker/Compose、Ascend 驱动及模型权重；模型默认在 `/models/Qwen3-32B`，
也可传 `--model-path`，路径须在宿主机和 SGLang 容器里都可见。
脚本不安装驱动、不下载模型权重、不停止其他人的任务。
缺失的镜像通过现有构建入口准备，再编译 hook 与 Release 建模程序。
ShareGPT 默认从配方声明的公开地址下载，约 673 MB；离线时用 `--dataset`。

本目录也可以复制到仓库外，显式指定要调用的仓库：

```bash
/path/to/hicache_reproduction/run.sh --repo /home/markov --dry-run
```

复制时保留整个目录。Python 只使用标准库；正式命令所需的依赖仍由项目容器提供。
输出必须放在被 Docker 挂载的仓库内；默认是 `data/reproductions/hicache/`。
更换配方、语料或部署时，用新的 `--output-dir`，不要混用不同实验的产物。

## 186 格是什么

原问题中的“184”已确认按历史 186 格恢复，不包含 self prediction。

| 面板 | 组成 | cross 格数 |
| --- | --- | ---: |
| 原矩阵 | 5 个 base 分别预测其余 4 个配置，使用 3 个手工 workload | 60 |
| 开发扩展 | C5 到 6 个新增配置的手工负载，以及 C5/C1/C2 的 ShareGPT 扩展 | 72 |
| 留出确认 | C5/C1/C2 使用另一组、不重叠的 ShareGPT 会话 | 54 |

准确的 base、target 和负载分组都列在 `recipe.json`，dry-run 后也写入
`experiment_plan.json`。不是 11 个配置和所有负载的全排列。

## 实际执行顺序

1. 选择开发、留出确认和独立采样用的 ShareGPT 会话，各组不重叠。原三个手工负载不截断。
2. 在独立采样配置下记录 token、采集完整 profile 和同源轻量 CPU 配对；再采物理 I/O、
   空闲同步及淘汰原语，建立一个共享性能库和成本包。采样长度、页大小和模型形式由配方事先声明。
3. 每个实验 workload 只记录一次生成 token；33 个 base 条件以及后续正常测量共享这些 token，
   完成 base profile 和 CPU 配对。
4. 通过现有预测入口依次完成十二组、共 186 格预测。此时不读取 target 正常测量或评分。
5. 全部预测成功后，才开始正常 HTTP 测量：99 个配置/负载条件，每个默认五次，
   共 495 次正常服务启动。关闭 profiler 与计时探针，采集严格串行。
6. 三个面板分别独立评分，生成 `results.md` 和 `run_summary.json`。
   完整 HTTP 正式窗口不排除 gap、未归属成本或 Prefill/Decode，评分不触发调参或补采。

CPU 配对调用 `prepare-hicache --calibration-only`；其输入合同要求一个 target，
所以填入同配置的声明，但该步骤在预测前就结束，不产生额外 self 格。
源回放和预测执行结构报告通过 `--experiment-reports` 保留；没有另采完整 target 结构，
不能把性能评分通过当成整张目标 DAG 的结构验证。

这不是小任务：除 495 次正常测量外，还包括 token 记录、base、独立样本及轻量配对。
`--dry-run` 只核对计划，不能用它估算精确耗时或证明设备流程成功。

## 结果、失败和继续执行

- `experiment_plan.json`：实验组成及本次部署、采样配方。
- `costs/`：独立采样、性能数据库、训练声明、共享成本包。
- `tokens/`、`bases/`、`normal/`：token、base 和正常实测；以各采集结果声明的 manifest 为准。
- `predictions/`：十二组预测；`evaluation/`：与预测隔离的评分。
- 默认只生成完整 HTTP 预测和必要摘要；`--experiment-reports` 可额外生成逐格源回放与结构诊断，运行更慢。
- `results.md`：完成后的三面板误差表；`run_summary.json`：完成状态或停止步骤。
- `logs/`：失败及非零退出命令的输出；退出 0 的外层日志删除，正式命令自己的必要记录仍保留。

相同输入可重跑同一命令。只复用已完成、非 dry-run 的采集结果，失败尝试保留并新开目录；
未结算的 running 状态会停止，需先确认旧进程已退出并处理原状态，避免重叠采集。
CPU 配对和物理采样沿用正式入口的累计预算；原语完成后复用。
同一实验恢复时，已经完成入库的独立测量直接复用，不重复提取全部大图；模型训练仍重新执行。
完整事实和覆盖清单均已准备好时，恢复直接进入训练，不再导入同一批控制行或重新汇总全库。
控制测量也按其 source manifest 和 CPU 配对来源复用；更换来源会重新导出，不按旧文件名混用测量。
物理采样只用一个已配对、同部署的普通释放 profile 说明平台环境，全部已入库事实仍供成本模型使用。
物理事实已经生成后，恢复时直接通过正式入口导入这份事实，不再次解析平台锚点的大图。
如果改变测量提取语义，也应使用新的输出目录，不能把旧测量解释成新程序的提取结果。
预测和评分用当前程序重跑，不把旧状态当成新代码验证。
`--skip-build` 只适用于镜像、hook 和建模程序已经构建的情况。
`--resume-normal` 是同一次实验的阶段恢复：预测程序、成本包、部署、配方及 token 输入必须保持不变。
它检查原有预测是否完整覆盖声明的 source/target/workload，且全部执行成功、指向所选成本包，
然后只恢复正常对照和评分，不构建、不拟合、不重跑预测。该检查不证明代码或参数未被修改；
修改预测逻辑或成本后应使用完整命令重新预测，不用此开关代替当前程序验证。
已完成的正常对照复用，失败尝试仍保留，新尝试使用独立运行目录；真实服务 OOM 不计成有效测量。

全部评分通过退出 0；完整评分结束但存在 `MODEL_LIMITATION` 退出 2；
构建、预测缺口或输入错误会停止并保留原因。正常对照的服务命令失败则保留该次记录，继续串行采集其余条件；
本轮结束仍有缺测时停止，不生成完整矩阵评分，使用 `--resume-normal` 集中恢复失败样本。
不跳过最终缺格、不填零，也不自动更换公式来追求通过；正常运行的失败次数和成功耗时须分别说明。

## 和历史结果的区别

2026-10-18 的历史数据及 `build/modeling/` 曾被清空。本例恢复的是实验组成和执行顺序，
不是恢复已删除的历史 token、成本参数或分数。
`costs.py` 将配方中的操作/变量规则展开为正式训练请求，不另实现拟合器、数据库或仿真算法。
规则可按实际实现区分模型形式：单请求、无输入 logprobs 时，词表投影只处理最后一个 token，
其矩阵形状不随 Prefill 长度变化，使用固定形状下的常数响应；普通投影仍按工作量拟合。
固定形状仍保留全部测量范围条件，不据此支持批量或其他 shape 的外推。
词表 all-gather 的实际后端操作在 Prefill/Decode 间相同，`shared_response_models` 显式声明
使用两阶段的独立观测训练共同完成响应；阶段归属及调用端 CPU 模型仍分开，不改写原始测量。
页表的 AsStrided 物化同样由共同的后端程序生成：对相同 dtype、页宽及工作量域，
其设备和 worker-launch 成本可使用两阶段的独立测量，阶段入口 CPU 成本不共享。
页宽整除时使用的 Slice 采用相同的共享原则；声明的共享响应替代同身份的单阶段声明，不重复注册模型。
未排序分页分配器的容量不足分支只做页数计算和容量比较，随后在张量操作前返回；
其失败返回使用已测线程 CPU 常数响应，并允许请求 token 数外推。页宽及实现约束仍保留，
不把成功分配、队列合并/排序或设备工作包含进这个常数。
`control_sampling` 另声明一组小容量缓存、非整页请求的独立采样，
用于覆盖只淘汰已备份页时的空写回检查，并保留小计算形状；它不是 target 性能实验。
该组用 `cost_operations` 只导出所需的写回控制测量，不要求它再次覆盖其他组已测过的控制操作。
`write_sampling` 使用三个页宽的独立 write-through 负载，补充该策略的写回提交成本。
普通释放样本使用 selective 策略，不保证触发写回，不能替代这些测量；不借用实验 base 或 target 的成本。
`path_sampling` 用较大的 host 池保留一条有多处分叉的缓存路径，并在正式阶段先发送一组未预热的小请求。
这样既能观测跨多个树节点的加载，也能在之后的大请求中形成集中写回；仍是一组所有 target 共享的独立采样。
`branch_parts` 控制分叉深度，`cold_requests` 声明只在正式阶段发送的请求数量与长度，默认不启用。
加载准备使用实测典型 CPU 响应，树节点数和请求 token 数用于约束适用范围，残余区间仍单独估计。
当前小路径测量不能辨识有物理意义的线性增量，不强行拟合负系数，也不把常数响应外推到未测过的更深路径。
阻塞写回清理已在结构中展开每个确认及事件销毁，`release_first` 只表示第一步清理的固定前缀，
不会再按整批数量重复收费。因此只允许这一步的 `confirmed_operations` 上下文外推，其他范围检查仍保留。
大批量写回可能合并事件，原始批量数不直接当作逐事件清理测量；不满足提取合同的样本不强行入库。
独立采样配方已实际完成设备采集与 CPU 配对；本轮 186 格已经完成预测与评分，但不证明支持范围外的执行分支或变量组合。
独立 timeout 样本使用配方中的 `paired_timeout_sec`（2 秒），以减少 profiler 改变缓存读回量、
造成完整/轻量运行计算量不同的风险；原 10 毫秒样本已实际出现这类差异，不能用于 CPU 相减。
这只调整独立性能采样，不改变实验 target 的超时配置；是否可配对仍由正式入口核对，不强行准入。
best-effort 控制只在 `best_effort_page_token_sizes` 声明的页宽采样：当前操作描述仅含 rank 和参与者数，
不以页大小为变量，因此使用已合法配对的 page32 样本共享控制测量。各页宽的传输和阶段计算仍由
其他独立采样覆盖，正式成本覆盖检查仍须通过；未准入的历史采样不删除、不入库。
独立非释放采样当前每请求生成 2 个 token，包含 Prefill 和一个 Decode 步；这不改变实验负载的输出数量。
此前 8-token 采样的原始 Torch CPU 记录在 1,048,575 条时已提前结束，后段通信无可用提交记录。
现在先完成严格的控制观测导出，再进行耗时的批量入库；没有采用忽略不完整请求来发布成本包。
`sampling.measurement_scope` 将这组独立输入及成本库放到 `complete_cpu` 数据目录，旧采样及旧库保留为失败证据。
缺口由正式成本准备或预测命令报告，不通过 target 真值、当前 base 拟合或逐格专用参数补洞。
连续行的 K/V 写入调用同一个 ScatterNdUpdate 后端，行宽和 dtype 在当前部署中相同。
因此三项内核/worker 响应按元素数、位置数共享独立 Prefill 的 K/V 观测；调用端 CPU 仍各自建模。
这不包含需先物化的跨步 V 视图；物化与后续 scatter 仍分别计费。共享只扩大已有实测形状范围，不允许范围外外推。

2026-10-22 已完成 33 份实验 base 与 CPU 配对、独立成本准备、186 格预测，以及 99 条件各五次的 495 个有效正常样本和三面板评分。
全体 WAPE 2.826%，最大误差 18.785%，185/186 格低于 10%；总状态为 `completed_with_model_limitations`，不是全部精度通过。
正常对照另有七次失败尝试，均保留；成功运行的均值不代表零失败保证。
本轮有修复、补充独立测量和显式成本包续跑，不是全空目录一次无人干预运行的证明。
完整结论与限制见 [项目工作流与进展](../../docs/workflow.md)。
